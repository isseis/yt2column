# Package Reference

This document lists the packages under `cmd/` and `internal/`, plus the
`prompts` package at the repository root, with the responsibility of each.
Update it in the same commit that adds, removes, or changes the responsibility
of a package.

The planned layout and the responsibility of each not-yet-created package are
described in [project_overview.md](../project_overview.md) ("想定ディレクトリ構成" and
"パイプライン").

| Package | Responsibility |
|---|---|
| `cmd/mergepr` | Entry point of the `/mergepr` developer tool: prepares a PR for message drafting, then merges and cleans up after the user approves the message |
| `cmd/yt2column` | Entry point of the CLI (`yt2column [flags] <video URL>`): `main` runs `run` under `internal/signalrun`, which subscribes to SIGTERM, and to SIGINT and SIGHUP unless each was ignored at startup (so a background job or `nohup` keeps its ignore), drops the subscription on the first signal before canceling the context, so a second signal terminates the process (one that arrives while the first is handled is raised again once the default disposition is restored); `main` passes `os.LookupEnv` (the package's only environment access) to `run`. `run` parses the flags, validates the video URL, chooses exactly one destination from which of `--out` (a file) and `--slack` (the Slack-compatible Incoming Webhook, e.g. Mattermost) appear on the command line, never from their values (`--slack=false` and an empty `--out` are rejected), rejects `--review-log` with `--no-review`, with an empty path, or naming the same file as `--out`, loads `internal/config` (with `--slack`, `SLACK_WEBHOOK_URL` must be set), refuses an `--out` or a `--review-log` inside the cache directory, and builds the stages before any side effect (exit code `2`); the shorten and review steps are enabled by default and disabled by `--no-shorten`/`--no-review`, and the review LLM client is built only when the review step runs. It then calls `internal/job` with `job.FileOutput` or `job.RemoteOutput` (exit code `1` on failure, `0` on success, warnings included), writes one summary line per step that ran and the review log path when one was written, and, on failure, names the failing step and the matching hint (a review-log write failure after the publish is reported on its own, without the run-failed line). Every line written to standard error goes through `internal/redact` (`Line`), which escapes it and redacts the configured secrets and their last eight characters (`SecretStrings` adds the `slackwebhook.SensitiveParts` of `SLACK_WEBHOOK_URL`), so a fragment such as its path alone is hidden too; standard output only receives the `-h`/`--help` usage |
| `cmd/yt2column-server` | Entry point of the localhost server (`yt2column-server`, no arguments): `main` runs `run` under `internal/signalrun` and passes `os.LookupEnv` (the package's only environment access). `run` loads `config.LoadServer` (each rejected variable on its own line, exit code `2`), loads or creates the shared token with `internal/authtoken` (a rejected file exits with `2` and is left unchanged; a created token is written to standard output once, before listening, and nowhere else), builds the LLM clients, the `writer.ArticleWriter` (the shorten and review steps enabled and the built-in templates, as a CLI run with no step flags), the `SlackWebhookPublisher`, the `SlackFailureNotifier`, and the `internal/server` server with the API keys, the Webhook URL, and the token as the redacted secrets (a construction failure exits with `2`), listens on both loopback addresses (a failure exits with `1`), logs the endpoint URLs, and serves until the first signal; it then waits for the in-flight jobs and failure notices, saying that a second signal exits at once, and exits with `0` (a listener that fails while serving exits with `1` after the same wait). Standard error carries every line except the created token, through `internal/redact` |
| `internal/mergepr` | Implements the `/mergepr` mechanics: prepares the drafting material after CI passes, squash-merges with `--match-head-commit`, and updates the local base and deletes the local head branch only while it still points at the merged head |
| `internal/secret` | Holds a secret (API key, Webhook URL) and guarantees it never appears in `fmt`, `log/slog`, or JSON output |
| `internal/strictjson` | Extracts values from JSON documents that passed strict checks: rejects the byte sequences and structural shapes `encoding/json` would silently repair (invalid UTF-8, unpaired surrogate escapes, trailing data, duplicate or `null` consumed members). `Object.CollectOnly` accepts only the named keys, rejecting an unknown or a duplicated key without naming it, and `Value.AsBool` accepts only `true`/`false`. Shared by `internal/transcript`, `internal/llm/deepseek`, `internal/llm/claude`, `internal/publisher`, `internal/writer`, and `internal/artifact` |
| `internal/nilcheck` | Reports whether a value is nil, including a typed nil held in an interface (`IsNil`). Used by `internal/pipeline` to reject unset stages and by `internal/writer` to reject a missing `LLMClient` |
| `internal/slackwebhook` | The rule a Slack-compatible Incoming Webhook URL (Mattermost or Slack) must meet (`ValidURL`: `net/url` parses it, its scheme is `https`, its host is not empty) and the parts of such a URL that must never appear in output (`SensitiveParts`: the URL, its path, query, and userinfo both as given and as `net/url` writes them, the last path segment, and the last eight characters). Depends on the standard library only; shared by `internal/config`, `internal/publisher`, `internal/redact`, and the integration tests (including `cmd/yt2column`'s) |
| `internal/config` | Reads and validates the process configuration through a `LookupFunc`. The generation and review LLM settings live in `LLMConfig` (the provider (`Provider`: `deepseek` or `claude`) and model of the generation, the review step's `ReviewProvider`/`ReviewModel` (each defaulting to the generation's; a set review provider requires a set review model), and the own variables of every provider the generation or review step uses (the DeepSeek or Anthropic API key held as `secret.Secret`, the Claude effort via `claudeparam.ParseEffort` and the Anthropic workspace ID via `claudeparam.ParseWorkspaceID`)); `Config` reads them, the Slack Webhook URL (held as `secret.Secret`, validated with `slackwebhook.ValidURL`), the absolute cache directory (with an OS-specific default derived from `HOME`/`XDG_CACHE_HOME`), the `yt-dlp` path, and whether `GODEBUG` enables HTTP/2 logging (`HTTP2DebugEnabledIn`), and exposes the LLM settings through `LLM()`. `ServerConfig` and `LoadServer` validate the same LLM settings, a required Webhook URL, the listening port `YT2COLUMN_SERVER_PORT` (default `8765`, `1024` through `65535`), and the shared token file's path under the configuration directory (an OS-specific default derived from `HOME`/`XDG_CONFIG_HOME`, sharing the cache directory's OS rules), reading none of the cache or `yt-dlp` variables. `RequireSlackWebhookURL` returns the Webhook URL or a `*VarError` naming the variable when none is configured. `Load` and `LoadServer` report every rejected variable with a fixed, value-free reason (`VarError`, `ErrMissing`/`ErrInvalid`) and return a zero value on any error. `internal/config/envaccess_test.go` enforces that only the allowed places read the process environment or name the secret variables. `Need` (`Generation`, `Review`) and `LoadFor` read and validate only the variables the run's stages need, so a resumed run does not require a skipped stage's settings; `Load` is `LoadFor` with both needs set |
| `internal/authtoken` | Holds the shared token that authenticates the extension and reads or creates the file that stores it. `Token` keeps the value as a `secret.Secret`, so printing it never shows the value, and the zero `Token` matches nothing; `LoadOrCreate` returns the token of the file at the caller's path, or, when it is missing, generates 32 crypto-random bytes as 64 lowercase hexadecimal characters and publishes them under the final name atomically (a `0600` temporary file in the same directory, written and synced, then `link(2)`; an existing name is read instead of overwritten, so a concurrent first start shares one token). Reading opens with `O_NOFOLLOW` and `O_NONBLOCK` and requires a regular file, no `0077` permission bits, the current user as owner, and exactly 64 lowercase hexadecimal characters with no trailing byte; any other file is a `*FileError` naming the path and a fixed reason and wrapping `ErrInvalidTokenFile`, holds none of the content, and is never repaired or regenerated. `Matches` compares with `crypto/subtle.ConstantTimeCompare` and is false for the zero `Token` and for an empty value. Built only on Unix |
| `internal/server` | The localhost HTTP server the browser extension posts to. `New` validates `Options` (a `writer.ArticleWriter`, a `publisher.Publisher`, a `failure.Notifier`, a non-zero `authtoken.Token`, a non-zero port, and a log output; a nil or typed-nil collaborator is rejected) and builds the `slog` logger and the `http.Server` `ErrorLog` over `redact.Writer`, so no log path can bypass the redaction. `ArticlesPath` is the one endpoint's request target. `Listen` binds `127.0.0.1` and `::1` only, on the configured port. A request is checked in a fixed order that reads no body until the header checks pass: `Host` (`127.0.0.1:<port>`, `[::1]:<port>`, or `localhost:<port>`), the `/articles` target, `POST`, exactly one `Content-Type: application/json`, the fixed extension `Origin`, and `Authorization: Bearer <token>` compared in constant time; then a slot is taken (at most two authenticated requests in flight, no queue), the body is read under a 4 MiB cap and checked with `strictjson` and `transcript.ValidateVideoURL`/`NewCopiedSource`, and the response is a fixed JSON object (`status`, `reason`, `requestId`) that carries no request value and no secret. An accepted request starts a job (the pipeline) that generates and posts the article, recovers its own panics, and reports a failure as a `failure.Notice` while holding its slot; a rejection after the slot is taken is also notified. `Serve` stops on cancellation or a listener failure, waits for in-flight jobs and notices without canceling them (logging how many), and returns |
| `internal/transcript` | Defines the transcript stage (`Transcript`/`Segment`, `TranscriptSource`) and provides its `YtDlpSource` implementation: video URL validation (`ValidateVideoURL` returns the video ID and normalized URL of a URL, and `NormalizedVideoURL` validates a video ID and builds the normalized URL from it), strict json3 and info.json parsers, the `yt-dlp` execution boundary (a shell-free command executor with a fixed environment allowlist and a capped, drained standard error output, files the caller passes down to the child process through `Options.InheritedFiles`, and a child started in its own process group that is killed as a group when the context ends), the per-video cache (`Fetch`, `RemoveCache`, `PruneCache`; `SeedCacheForTest` places a valid cache for tests and is built only with `-tags test` or `-tags integration`), and the stage's sentinel errors. `CopiedSource` builds a `Transcript` from the copied transcript text a user takes from YouTube's transcript panel: `NewCopiedSource` validates the video ID and parses `Raw` eagerly (a bad format wraps `ErrCopiedTranscriptFormat`), and `Fetch` serves the parsed `Transcript` only for its normalized URL |
| `internal/llm` | Defines the provider-independent `LLMClient` interface and its `GenerateRequest`/`GenerateResponse` types, the provider-common sentinel errors (`ErrInvalidRequest`/`ErrTruncated`/`ErrUnexpectedFinishReason`/`ErrEmptyResponse`), and `GenerateRequest.Validate` |
| `internal/llm/claudeparam` | The Claude adapter's parameter types: `Effort` (the `output_config.effort` value, one of "low", "medium", "high", "xhigh", "max"; `ParseEffort`, `String`, and `Valid`, with the zero `EffortUnset` outside the accepted set) and `WorkspaceID` (the zero value means none; a non-zero value can only come from `ParseWorkspaceID`, which accepts a non-empty string of printable ASCII other than space, 0x21-0x7E) |
| `internal/llm/claude` | Implements `llm.LLMClient` against the Anthropic Messages API: construction validation (API key shape, model, `claudeparam.Effort`, `claudeparam.WorkspaceID`, positive timeout), a fixed production endpoint (with `-tags test`, other packages can point a client at a loopback URL through `NewForLoopbackTest`), a request body of only `model`/`system`/`messages`/`max_tokens`/`output_config.effort` with `x-api-key` and `anthropic-version` headers (and `anthropic-workspace-id` only when a workspace ID was specified), its HTTP send path taken from `internal/llm/llmhttp` (so it never follows a redirect and reads the body under `llmhttp.MaxResponseBytes`), and strict validation of the response body before anything is returned (exactly one `text` block, `stop_reason` `end_turn`, an unknown content block type rejected, thinking blocks ignored), reporting an HTTP-status, invalid-response, or transport failure with its own sentinels |
| `internal/llm/deepseek` | Implements `llm.LLMClient` against the DeepSeek Chat Completions API: construction validation, a fixed production endpoint (with `-tags test`, other packages can also point a client at a loopback URL through `NewForLoopbackTest`), the exported `ErrPaddedModel` for a model name with surrounding whitespace, its HTTP send path taken from `internal/llm/llmhttp` (so it never follows a redirect and reads the body under `llmhttp.MaxResponseBytes`), and strict validation of the response body before anything is returned |
| `internal/llm/llmhttp` | Performs one HTTP POST for an LLM adapter: applies the adapter's timeout over the caller's context, never follows a redirect whatever `http.Client` it is given, returns the body of a `200` response under the `MaxResponseBytes` cap without reading the body of a non-`200` response, and classifies a send or read failure into `context.DeadlineExceeded`/`context.Canceled` or one of the adapter's own sentinels (`Errors`). `NewClient` returns a client that never redirects and leaves `Transport` nil, so the proxy environment variables apply. Defines no sentinel of its own |
| `internal/llm/llmhttp/llmhttptest` | The test servers and loopback listeners shared by `internal/llm/llmhttp` and the LLM adapters' tests: a request recorder, fixed-response and stalling servers, a first-request gate, a listener that truncates a response, and a blackhole proxy for the proxy environment variables. Deliberately does not import `llmhttp`, so a same-package test can use it. Built only with `-tags test` |
| `internal/llm/provider` | Builds the `llm.LLMClient` a `config.LLMConfig` selects: `New` uses the generation `Provider`/`Model` and `NewReview` the review `ReviewProvider`/`ReviewModel`, both through the shared `newClient(provider, model, cfg, build)`. `config.ProviderDeepSeek` maps to the DeepSeek adapter (configured API key and model) and `config.ProviderClaude` to the Claude adapter (configured API key, model, effort, and workspace ID), both with the fixed `LLMTimeout` (15 minutes); an unknown provider is rejected with an unexported sentinel instead of defaulting to one. The adapter constructors are a seam (`builders`; a package test substitutes loopback constructors or spies), and construction errors are wrapped with `%w` so `deepseek.ErrPaddedModel` stays detectable with `errors.Is` |
| `internal/artifact` | Persists the article writer's intermediate artifacts: one JSON file per video ID and stage under a directory the caller names. `Parse`/`Marshal` define the single on-disk format (a `writer.StageRecord` plus the identifier computed from its content); `NewStore` opens the directory once and rejects a missing path, a non-directory, and a symbolic link with `ErrMissing` without creating it; `Save` writes a temporary file (mode `0o600`) and renames it over the fixed `<videoID>.<stage>.json` name; `Load` verifies the chain from the requested stage back to generation against the current material, rejecting an absent, broken, or mismatched artifact (`ErrMissing`/`ErrMalformed`/`ErrMismatch`), and reads each artifact only after `os.Root.Lstat` confirms a regular file and `os.SameFile` confirms the opened descriptor is that file. Implements `writer.ArtifactStore`; depends on `internal/writer`, `internal/strictjson`, and `internal/transcript` |
| `internal/writer` | Defines the article-writing stage: `Article` and the `ArticleWriter` interface, and implements it. `New` rejects a nil or typed-nil `LLMClient` and the step combinations it must not accept (an enabled review step without a client, a client set while the step is disabled, a template path for a disabled step), takes optional per-template override paths in `Options` for the generation, shorten, and review template pairs, reads each override file once (following symbolic links, refusing non-regular files without blocking, capped in size), and checks the embedded and override templates of every enabled step alike: size, UTF-8, not blank, parses, no `define`/`block`, and only allowlisted syntax (the fields of that pair's own data type — `templateData`, `shortenTemplateData`, or `reviewTemplateData` — and the builtin functions that cannot grow a string, each called with an accepted number of arguments; a review template embeds the generation data type, so `.Title` and the other material fields stay available). `Write` validates the `Transcript` (video ID, normalized URL, segments, UTF-8), expands the generation templates into buffers capped at 1 MiB, calls the generation `LLMClient` once, and validates the generated text, `Model`, and `ModelVersion` without repairing them apart from normalizing the body part's line endings to `\n` and dropping its leading BOM (rejecting raw HTML and an unclosed code fence in the body part, judged in linear time and leaning to rejection where the judgment is simpler than CommonMark). Then, unless `Options` disables them, it runs the shorten step (when the body is over 4,000 characters, a second generation call toward a 3,600-character target, failing with `ErrTooLong` if the result is still over the limit) and the review step (one call on `ReviewOptions.Client` returning a JSON list of corrections, which `Write` checks for size, item count, unknown and duplicate keys, value types, UTF-8, and control characters, applies to the text, and re-checks), and rejects a body still over the limit after the review step with `ErrTooLong`; every step failure is a `*StepError`. It appends a source block built from the validated video ID. `Article.CheckPublishable` is the check a publisher applies before output (required fields, the step model lines, `ReviewResult.Check`, no control characters; wraps `ErrInvalidArticle`, never a field value). `Options.Artifacts` (`Store`, `Resume`) saves each completed stage's artifact through a `writer.ArtifactStore` before publication and resumes from a saved chain, so the reused stages' model provenance reaches the output; `Write` derives the stages it runs from `Resume` and the enabled steps, and `New` rejects an enabled step without a client, a client set for a step that does not run, and a template path for a step that does not run |
| `prompts` | Embeds the default prompt templates and returns them: the generation pair with `System` and `User`, and the shorten and review pairs with `ShortenSystem`/`ShortenUser` and `ReviewSystem`/`ReviewUser`; `README.md` documents the template contract and the values each pair may reference |
| `internal/publisher` | Defines the publishing stage: the `Publisher` interface, and `FilePublisher`, which writes one article to one local file and never overwrites: it checks the article with `CheckPublishable`, writes and syncs a temporary file (`.yt2column-*.tmp`, mode `0o644`) in the output directory, and gives it the output name with `link(2)`, so the output path only ever names a complete file. A link failure keeps the temporary file and returns `*KeptFileError` wrapping `ErrOutputExists`, `ErrNoHardLink`, or the original cause. `ReviewLogWriter` writes an article's review list to one new file with the same `atomicFile` procedure, without overwriting and removing the temporary file on a link failure; it checks the article with `CheckPublishable` (including `ReviewResult.Check`) and rejects a nil `Review`. `SlackWebhookPublisher` posts an article to a Slack-compatible Incoming Webhook (Mattermost is the verified target) as one or more messages: it holds the URL only as a `secret.Secret`, rejects mention syntax and syntax the server would rewrite before sending anything, splits the article into messages of at most 16,383 code points (at most 10 messages), posts them with `silent` set, without following redirects, and under a 30-second per-message timeout (`SlackPostTimeout`), keeps the Webhook URL and its parts out of every error, and reports a post failure as a `*SlackPostError` naming how many messages were posted; `SlackMessageCount` returns the same message count without sending. With `-tags test`, `NewSlackWebhookPublisherForLoopbackTest` builds one that posts to a loopback URL, `SlackMessagesForTest` returns the prepared message texts, and `SlackMaxMessageRunesForTest`, `SlackMaxMessagesForTest`, and `SlackPublishMaxDurationForTest` expose the limits and the longest a post of a given number of messages can take, for tests in other packages |
| `internal/cachelock` | Serializes the runs that share one cache directory: `Acquire` creates the directory (mode `0o700`) when missing, opens the fixed `.yt2column.lock` without following symbolic links or blocking on a named pipe, rejects a non-regular file, and takes a non-blocking `flock` exclusive lock. A held lock returns a `*LockedError` that carries the lock path and wraps `ErrLocked`; any other failure does not wrap it. `File()` exposes the descriptor so a child process inherits the lock, and `Close` releases this process's reference. Built only on Unix (`//go:build unix`) |
| `internal/job` | Runs one job end to end: `Run` validates the request (the target is `Output`, built by `FileOutput` (a path and a `Publisher`) or `RemoteOutput` (a `Publisher`); the zero value is rejected), pre-checks a file output's path and, when set, the review log path before any side effect (an existing path becomes a publish-stage error wrapping `publisher.ErrOutputExists` for `--out`, and a fixed message naming no stage for the review log; an unusable parent is a publish-stage error that does not wrap it for `--out`, and the same fixed stage-less message for the review log; a remote output has no local check), takes the `cachelock` for the cache directory, prunes dangling entries, runs the `pipeline` with the lock file inherited by `yt-dlp`, removes the video's cache unless `KeepCache` is set, and then writes the review log when `Request.ReviewLog` is set. A prune or removal failure is reported in `Result.Warnings` and does not fail the run; a nil error means the article was published and the review log, when requested, was written, while a `*ReviewLogError` means the article was published and only writing the review log failed |
| `internal/pipeline` | Runs the three stages in order: `Pipeline`, `Stage`, `StageError`, `ErrNilStage` |
| `internal/loopbacktest` | The rule a test endpoint must meet so a loopback constructor cannot be pointed at an external host (`ValidateURL`: `net/url` parses it, its host is not empty, and the host is a loopback IP address). Built only with `-tags test`; used by the test-only construction of `internal/llm/deepseek` and `internal/publisher` |
| `internal/maketestutil` | Checks make targets that run charged integration tests: runs a target with `GOTEST` replaced by a stub (`RunTarget`, returning the recorded arguments and variables), checks a charged target's charge notice, `go test` arguments, `-timeout` bound, opt-in, and variable defaults (`CheckChargedTarget`), concatenates recorded variable names without duplicates (`RecordedNames`, which also rejects any name that is not a plain shell variable name, since the stub embeds the names in shell text), and checks a file's first line (`FirstLineIs`). The provider-specific names, defaults, and notices are the caller's. Built only with `-tags test` |
| `internal/transcript/testutil` | Test fixtures the other packages share: the test double (`FakeTranscriptSource`) for `transcript.TranscriptSource`, fake `yt-dlp` scripts (a tripwire, a fake that stops and records descriptor 3 and its PIDs, a standard-error failure, and one that writes a valid cache), and a directory listing. `mocks.go`/`mocks_test.go` are built only with `-tags test`; `helpers.go` is also built with `-tags integration` |
| `internal/llm/testutil` | Test doubles for `llm.LLMClient`: `FakeLLMClient` returns one fixed result, and a scripted client returns prepared results or errors in call order and fails the test through an `ErrorReporter` when called more often than the script provides; built only with `-tags test` |
| `internal/llm/deepseek/testutil` | What the integration tests that call the real DeepSeek API share: `SettingsFrom` decides from the environment whether such a test runs, skips, or fails (each test names its own opt-in variable, make target, and whether a missing test API key skips or fails), and `RunMakeTarget`/`CheckChargedTarget`/`FirstLineIs` are thin wrappers over `internal/maketestutil` that check the make targets and build tags keeping those tests out of `make test` (the wrapper records this package's two opt-ins and model name, plus any variables the caller names, such as the webhook opt-ins of `internal/publisher/testutil`, and checks the DeepSeek charge notice). `integration.go` is also built with `-tags integration`; `make.go` is built only with `-tags test` |
| `internal/llm/claude/testutil` | What the integration test that calls the real Anthropic Messages API needs: `SettingsFrom` decides from the environment (read through an `os.LookupEnv`-shaped function, so an unset and an empty variable differ) whether the test runs, skips, or fails. The opt-in is exactly `1`; a missing `YT2COLUMN_TEST_ANTHROPIC_API_KEY` skips (`ANTHROPIC_API_KEY` is never read); a missing model name or a missing or unknown effort (`claudeparam.ParseEffort`) fails; an empty or malformed `YT2COLUMN_TEST_ANTHROPIC_WORKSPACE_ID` (`claudeparam.ParseWorkspaceID`) fails while an unset one specifies none (`ANTHROPIC_WORKSPACE_ID` is never read); an HTTP/2 debug `GODEBUG` (`config.HTTP2DebugEnabledIn`) fails. The reason never holds the API key. `integration.go` is also built with `-tags integration` |
| `internal/writer/testutil` | Test double (`FakeArticleWriter`) for `writer.ArticleWriter`, and `DefaultOptions`, the `writer.Options` of a run with every step at its default, which the tests of `cmd/yt2column` (no step flags) and `cmd/yt2column-server` both compare their options with; built only with `-tags test` |
| `internal/publisher/testutil` | Test double (`FakePublisher`) for `publisher.Publisher`, and what the webhook integration tests share: `SettingsFrom` decides from the environment whether a test that posts to the real test Webhook runs, skips, or fails (the opt-in is exactly `1`, the URL is read only from `YT2COLUMN_TEST_SLACK_WEBHOOK_URL` and must satisfy `slackwebhook.ValidURL`, and an HTTP/2 debug `GODEBUG` fails; the reason never holds the URL), `SlackIntegrationOptions`/`CLISlackIntegrationOptions` name each test's opt-in and make target, and `IntegrationArticles` builds the two fixed articles the publisher integration test posts (one of exactly one message's limit, one split into several, each titled with a run marker). `mocks.go`/`mocks_test.go` are built only with `-tags test`; `integration.go` is also built with `-tags integration` |
| `internal/failure` | The contract for reporting a failed authenticated request: the `Kind` that classifies it (zero value `KindUnknown`), the `Notice` a report may carry (`RequestID`, `VideoID`, `Kind` — chosen or generated by the server, never copied from the request), and the `Notifier` interface (`Notify(context.Context, Notice) error`) |
| `internal/failure/testutil` | Test double (`FakeNotifier`) for `failure.Notifier`; built only with `-tags test` |
| `internal/redact` | Keeps secret values out of output: `Line` renders one line for a terminal (escaping non-printables as `strconv.Quote` does, then replacing every secret, its trailing eight characters, and the escaped spelling of both with a collision-free marker), `Writer` redacts each write for output already formatted by `log/slog` without escaping it again, and `SecretStrings` builds the string list from `secret.Secret` values (the Webhook URL also contributes its `slackwebhook.SensitiveParts`; a zero secret contributes nothing). Depends on `internal/secret` and `internal/slackwebhook`, not on `internal/config`; moved from `cmd/yt2column` |
| `internal/signalrun` | `Run` calls a program's main function under a context that the first subscribed signal cancels: SIGTERM always, and SIGINT and SIGHUP unless each was ignored at startup (so a background job or `nohup` keeps its ignore); the subscription is dropped on that first signal before cancellation, so a second signal terminates the process. Moved from `cmd/yt2column` |
