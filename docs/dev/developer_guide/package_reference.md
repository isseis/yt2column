# Package Reference

This document lists the packages under `cmd/` and `internal/`, plus the
`prompts` package at the repository root, with the responsibility of each.
Update it in the same commit that adds, removes, or changes the responsibility
of a package.

The planned layout and the responsibility of each not-yet-created package are
described in [project_overview.md](../project_overview.md) ("想定ディレクトリ構成" and
"パイプライン").

| Package | Responsibility |
|---|---|
| `cmd/mergepr` | Entry point of the `/mergepr` developer tool: prepares a PR for message drafting, then merges and cleans up after the user approves the message |
| `cmd/yt2column` | Entry point of the CLI (`yt2column [flags] <video URL>`): `main` subscribes to SIGTERM, and to SIGINT and SIGHUP unless each was ignored at startup (so a background job or `nohup` keeps its ignore), drops the subscription on the first signal before canceling the context, so a second signal terminates the process (one that arrives while the first is handled is raised again once the default disposition is restored), and passes `os.LookupEnv` (the package's only environment access) to `run`. `run` parses the flags, validates the video URL, loads `internal/config`, refuses an `--out` inside the cache directory, and builds the stages before any side effect (exit code `2`), then calls `internal/job` (exit code `1` on failure, `0` on success, warnings included). Every line written to standard error is escaped and has the configured secrets and their last eight characters redacted; standard output only receives the `-h`/`--help` usage |
| `internal/mergepr` | Implements the `/mergepr` mechanics: prepares the drafting material after CI passes, squash-merges with `--match-head-commit`, and updates the local base and deletes the local head branch only while it still points at the merged head |
| `internal/secret` | Holds a secret (API key, Webhook URL) and guarantees it never appears in `fmt`, `log/slog`, or JSON output |
| `internal/strictjson` | Extracts values from JSON documents that passed strict checks: rejects the byte sequences and structural shapes `encoding/json` would silently repair (invalid UTF-8, unpaired surrogate escapes, trailing data, duplicate or `null` consumed members). Shared by `internal/transcript` and `internal/llm/deepseek` |
| `internal/nilcheck` | Reports whether a value is nil, including a typed nil held in an interface (`IsNil`). Used by `internal/pipeline` to reject unset stages and by `internal/writer` to reject a missing `LLMClient` |
| `internal/slackwebhook` | The rule a Slack-compatible Incoming Webhook URL (Mattermost or Slack) must meet (`ValidURL`: `net/url` parses it, its scheme is `https`, its host is not empty) and the parts of such a URL that must never appear in output (`SensitiveParts`: the URL, its path, query, and userinfo both as given and as `net/url` writes them, the last path segment, and the last eight characters). Depends on the standard library only; shared by `internal/config`, `internal/publisher`, `cmd/yt2column`, and the integration tests |
| `internal/config` | Reads and validates the process configuration through a `LookupFunc`: the provider (`Provider`), model, DeepSeek API key and Slack Webhook URL (both held as `secret.Secret`, the latter validated with `slackwebhook.ValidURL`), the absolute cache directory (with an OS-specific default derived from `HOME`/`XDG_CACHE_HOME`), the `yt-dlp` path, and whether `GODEBUG` enables HTTP/2 logging (`HTTP2DebugEnabledIn`). `RequireSlackWebhookURL` returns the Webhook URL or a `*VarError` naming the variable when none is configured. `Load` reports every rejected variable with a fixed, value-free reason (`VarError`, `ErrMissing`/`ErrInvalid`) and returns a zero `Config` on any error. `internal/config/envaccess_test.go` enforces that only the allowed places read the process environment or name the secret variables |
| `internal/transcript` | Defines the transcript stage (`Transcript`/`Segment`, `TranscriptSource`) and provides its `YtDlpSource` implementation: video URL validation (`ValidateVideoURL` returns the video ID and normalized URL of a URL, and `NormalizedVideoURL` validates a video ID and builds the normalized URL from it), strict json3 and info.json parsers, the `yt-dlp` execution boundary (a shell-free command executor with a fixed environment allowlist and a capped, drained standard error output, files the caller passes down to the child process through `Options.InheritedFiles`, and a child started in its own process group that is killed as a group when the context ends), the per-video cache (`Fetch`, `RemoveCache`, `PruneCache`; `SeedCacheForTest` places a valid cache for tests and is built only with `-tags test` or `-tags integration`), and the stage's sentinel errors |
| `internal/llm` | Defines the provider-independent `LLMClient` interface and its `GenerateRequest`/`GenerateResponse` types, the provider-common sentinel errors (`ErrInvalidRequest`/`ErrTruncated`/`ErrUnexpectedFinishReason`/`ErrEmptyResponse`), and `GenerateRequest.Validate` |
| `internal/llm/deepseek` | Implements `llm.LLMClient` against the DeepSeek Chat Completions API: construction validation, a fixed production endpoint (with `-tags test`, other packages can also point a client at a loopback URL through `NewForLoopbackTest`), the exported `ErrPaddedModel` for a model name with surrounding whitespace, redirects not followed, and strict validation of the response body before anything is returned |
| `internal/llm/provider` | Builds the `llm.LLMClient` selected by a `config.Config`: `New` maps `config.ProviderDeepSeek` to the DeepSeek adapter with the configured API key and model and the fixed `LLMTimeout` (15 minutes), and rejects an unknown provider with an unexported sentinel instead of defaulting to one. The adapter constructor is a seam (a package test substitutes the loopback constructor), and construction errors are wrapped with `%w` so `deepseek.ErrPaddedModel` stays detectable with `errors.Is` |
| `internal/writer` | Defines the article-writing stage: `Article` and the `ArticleWriter` interface, and implements it. `New` rejects a nil or typed-nil `LLMClient`, takes optional per-template override paths in `Options`, reads each override file once (following symbolic links, refusing non-regular files without blocking, capped in size), and checks the embedded and override templates alike: size, UTF-8, not blank, parses, no `define`/`block`, and only allowlisted syntax (the four template data fields and the builtin functions that cannot grow a string, each called with an accepted number of arguments). `Write` validates the `Transcript` (video ID, normalized URL, segments, UTF-8), expands both templates into buffers capped at 1 MiB, calls the `LLMClient` once, validates the generated text, `Model`, and `ModelVersion` without repairing them apart from normalizing the body part's line endings to `\n` and dropping its leading BOM (rejecting raw HTML and an unclosed code fence in the body part, judged in linear time and leaning to rejection where the judgment is simpler than CommonMark), and appends a source block built from the validated video ID. `Article.CheckPublishable` is the check a publisher applies before output (required fields, no control characters; wraps `ErrInvalidArticle`, never a field value) |
| `prompts` | Embeds the default system and user prompt templates and returns them with `System` and `User`; `README.md` documents the template contract for override-file authors |
| `internal/publisher` | Defines the publishing stage: the `Publisher` interface, and `FilePublisher`, which writes one article to one local file and never overwrites: it checks the article with `CheckPublishable`, writes and syncs a temporary file (`.yt2column-*.tmp`, mode `0o644`) in the output directory, and gives it the output name with `link(2)`, so the output path only ever names a complete file. A link failure keeps the temporary file and returns `*KeptFileError` wrapping `ErrOutputExists`, `ErrNoHardLink`, or the original cause. `SlackWebhookPublisher` posts an article to a Slack-compatible Incoming Webhook (Mattermost is the verified target) as one or more messages: it holds the URL only as a `secret.Secret`, rejects mention syntax and syntax the server would rewrite before sending anything, splits the article into messages of at most 16,383 code points (at most 10 messages), posts them with `silent` set, without following redirects, and under a 30-second per-message timeout (`SlackPostTimeout`), keeps the Webhook URL and its parts out of every error, and reports a post failure as a `*SlackPostError` naming how many messages were posted; `SlackMessageCount` returns the same message count without sending. With `-tags test`, `NewSlackWebhookPublisherForLoopbackTest` builds one that posts to a loopback URL, and `SlackMessagesForTest` returns the prepared message texts |
| `internal/cachelock` | Serializes the runs that share one cache directory: `Acquire` creates the directory (mode `0o700`) when missing, opens the fixed `.yt2column.lock` without following symbolic links or blocking on a named pipe, rejects a non-regular file, and takes a non-blocking `flock` exclusive lock. A held lock returns a `*LockedError` that carries the lock path and wraps `ErrLocked`; any other failure does not wrap it. `File()` exposes the descriptor so a child process inherits the lock, and `Close` releases this process's reference. Built only on Unix (`//go:build unix`) |
| `internal/job` | Runs one job end to end: `Run` validates the request (the target is `Output`, built by `FileOutput` (a path and a `Publisher`) or `RemoteOutput` (a `Publisher`); the zero value is rejected), pre-checks a file output's path before any side effect (an existing path becomes a publish-stage error wrapping `publisher.ErrOutputExists`; an unusable parent a publish-stage error that does not wrap it; a remote output has no local check), takes the `cachelock` for the cache directory, prunes dangling entries, runs the `pipeline` with the lock file inherited by `yt-dlp`, and removes the video's cache unless `KeepCache` is set. A prune or removal failure is reported in `Result.Warnings` and does not fail the run; a nil error means the article was published |
| `internal/pipeline` | Runs the three stages in order: `Pipeline`, `Stage`, `StageError`, `ErrNilStage` |
| `internal/loopbacktest` | The rule a test endpoint must meet so a loopback constructor cannot be pointed at an external host (`ValidateURL`: `net/url` parses it, its host is not empty, and the host is a loopback IP address). Built only with `-tags test`; used by the test-only construction of `internal/llm/deepseek` and `internal/publisher` |
| `internal/transcript/testutil` | Test fixtures the other packages share: the test double (`FakeTranscriptSource`) for `transcript.TranscriptSource`, fake `yt-dlp` scripts (a tripwire, a fake that stops and records descriptor 3 and its PIDs, a standard-error failure, and one that writes a valid cache), and a directory listing. `mocks.go`/`mocks_test.go` are built only with `-tags test`; `helpers.go` is also built with `-tags integration` |
| `internal/llm/testutil` | Test double (`FakeLLMClient`) for `llm.LLMClient`; built only with `-tags test` |
| `internal/llm/deepseek/testutil` | What the integration tests that call the real DeepSeek API share: `SettingsFrom` decides from the environment whether such a test runs, skips, or fails (each test names its own opt-in variable, make target, and whether a missing test API key skips or fails), and `RunMakeTarget`/`FirstLineIs` check the make targets and build tags that keep those tests out of `make test`. `integration.go` is also built with `-tags integration`; `make.go` is built only with `-tags test` |
| `internal/writer/testutil` | Test double (`FakeArticleWriter`) for `writer.ArticleWriter`; built only with `-tags test` |
| `internal/publisher/testutil` | Test double (`FakePublisher`) for `publisher.Publisher`; built only with `-tags test` |
