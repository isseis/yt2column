# セキュリティ考慮事項

yt2column の設計・実装・レビューで確認するセキュリティ上の観点をまとめる。`mkarch` / `weakreview` などのコマンドは、機能が `.claude/commands/_context.md` の "Conditional-guide trigger" に該当するとき本書を参照する。

yt2column はローカルで実行する。主経路では、利用者がブラウザ拡張からコピーした字幕（と動画の URL・メタ情報）を与え、CLI では動画 URL を与える。字幕・動画タイトル・概要欄・LLM の応答・外部サーバーのレスポンスは**信頼できない入力**として扱う。

## 1. 外部コマンド（yt-dlp）の起動

- `exec.CommandContext` に引数を配列で渡す。シェル（`sh -c`）を経由しない。
- 子プロセスへ渡す環境変数は allowlist に限定し、設定されている変数のみを渡す（例: `PATH`・`HOME`・`TMPDIR`・`XDG_CONFIG_HOME`・`XDG_CACHE_HOME`・proxy 関連・locale・`SSL_CERT_FILE` / `SSL_CERT_DIR`）。`exec.Cmd.Env` を nil のままにせず、API キーなどの秘密情報を子プロセスへ引き継がない。ブロックリスト（既知の秘密情報だけを除く）ではなく allowlist にして、秘密情報を追加したときに漏れないようにする。
- URL は引数として渡す前に検証する。YouTube の動画 URL 形式から動画 ID を取り出し、yt-dlp には正規化した URL を渡す。`-` で始まる値がオプションとして解釈されないよう、URL の直前に `--` を置く。
- 出力先のディレクトリは `-P`（`--paths`）の値として渡し、`-o` の出力テンプレートは動画 ID のフィールド（`%(id)s`）に基づく固定の文字列とする。yt-dlp は `-o` の値をテンプレートとして展開するため、`%` を含むキャッシュディレクトリのパスなど、呼び出し元が与えたパスを `-o` に含めない。動画 ID は `[A-Za-z0-9_-]{11}` に一致することを確認し、パス区切りや `..` を含む値を拒否する。
- `context` によるタイムアウトを設定する。
- yt-dlp の標準エラー出力をエラーメッセージに含める場合は長さを制限する。

## 2. 秘密情報（API キー）

- `DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` などの API キーは、CLI では環境変数からのみ読み込み、localhost サーバではモード `0600` の設定ファイル（`$HOME/.config/yt2column/config.env`。§8.2）からのみ読み込む。リポジトリ内のファイルに書かない（`.envrc` / `.env` は `.gitignore` 済みで、サーバの設定ファイルはリポジトリの外にある）。サーバは環境変数の値を読まない。
- テストでは、本番の API キー（`DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` に設定するもの）を使わない。ただし、実 API を呼ぶ統合テストに限り、本番とは別に用意した**テスト用の API キー**を使う例外を設ける（`docs/tasks/0003_deepseek_llm_client/02_architecture.md` §5.2）。テスト用の API キーは、DeepSeek API・Anthropic API・OpenAI API に実際に通る有効なキーであり、使えば料金が発生する。
  - ユニットテストは、本番のキーもテスト用の API キーも使わない。偽の値だけを使う。どのテストも API キーをコードやテストデータに書かない。
  - テスト用の API キーは、テスト専用の環境変数 `YT2COLUMN_TEST_DEEPSEEK_API_KEY` からだけ読む。統合テストは、本番の `DEEPSEEK_API_KEY` を、設定されていても読まない。テスト用の API キーには、本番と別のキー（利用上限を設けたものなど）を割り当てる。
  - Claude の統合テストも同じ方針で、テスト専用の `YT2COLUMN_TEST_ANTHROPIC_API_KEY` からだけ API キーを読み、本番の `ANTHROPIC_API_KEY` は設定されていても読まない。ワークスペース ID もテスト専用の `YT2COLUMN_TEST_ANTHROPIC_WORKSPACE_ID` からだけ読み、本番の `ANTHROPIC_WORKSPACE_ID` は読まない。テスト用の API キーには、利用上限を設けたワークスペースのものを割り当てる。
  - OpenAI の統合テストも同じ方針で、テスト専用の `YT2COLUMN_TEST_OPENAI_API_KEY` からだけ API キーを読み、本番の `OPENAI_API_KEY` は設定されていても読まない。テスト用の API キーには、本番と別の、利用上限を設けたプロジェクトのキーを割り当てる。
  - テスト用の API キーを使うのは、`//go:build integration` の次の 4 つの統合テストだけである。どれも、対応する make のターゲットだけがエクスポートするオプトインの変数の値がちょうど `1` でなければスキップする。各ターゲットは自分のオプトインだけをエクスポートし、他のオプトインはエクスポートしない。テスト用の API キーが `.envrc` などで常にエクスポートされていても、`go test -tags integration ./...` や IDE からの実行で料金が発生しない。

    | 統合テスト | make のターゲット | オプトインの変数 | テスト用の API キーがない場合 |
    |---|---|---|---|
    | `internal/llm/deepseek/integration_test.go`（DeepSeek のアダプタ） | `make test-integration-deepseek` | `YT2COLUMN_DEEPSEEK_INTEGRATION=1` | スキップする |
    | `internal/llm/claude/integration_test.go`（Claude のアダプタ） | `make test-integration-claude` | `YT2COLUMN_CLAUDE_INTEGRATION=1` | スキップする |
    | `internal/llm/openai/integration_test.go`（OpenAI のアダプタ） | `make test-integration-openai` | `YT2COLUMN_OPENAI_INTEGRATION=1` | スキップする |
    | `cmd/yt2column/integration_test.go`（CLI の組み立てで testdata の字幕からファイル出力まで） | `make test-integration-cli` | `YT2COLUMN_CLI_INTEGRATION=1` | 失敗する（本番の `DEEPSEEK_API_KEY` だけがある場合も、それを代わりに使わない） |

  - 実行するかどうかの判定とテスト用の API キーの読み込みは、DeepSeek の 2 つのテストが `internal/llm/deepseek/testutil` の `SettingsFrom` で、Claude のテストが `internal/llm/claude/testutil` の `SettingsFrom` で、OpenAI のテストが `internal/llm/openai/testutil` の `SettingsFrom` で行う。
  - CLI は API キーを `DEEPSEEK_API_KEY` という名前で受け取るので、CLI の統合テストは、読み込んだテスト用の API キーを、テストが組み立てて CLI に与える環境の中で `DEEPSEEK_API_KEY` という名前で渡す。プロセスの環境変数は変えない。名前は本番と同じだが、値はテスト用の API キーである。
  - テストの出力（ログ・失敗メッセージ・スキップの理由）に API キーもその一部も書かない。
- `GODEBUG` に `http2debug=1` または `http2debug=2` を含めると、Go の HTTP/2 の Transport は送信するリクエストヘッダーを値ごと標準エラー出力に記録する。`Authorization`・`x-api-key` などの API キーのヘッダーもそのまま出力される。この設定で通信を調査するときは、無効な API キー（本番のキーでもテスト用のキーでもないもの）を使う。`GODEBUG` はプロセスの開始時に一度だけ読まれ、実行中に取り除いても効かないため、統合テストは、API を呼ぶものも、送信の前にこの設定を検出して失敗する。
- 本番の CLI は `GODEBUG` の `http2debug` を拒否せずに読み込み、利用者が明示的に指定したものとしてデバッグを優先する。その代わり、LLM API を呼ぶ前に、`http2debug` により API キーが標準エラー出力に書かれうることを警告する（F-001・F-007・F-008）。警告はこの 1 つだけである。

## 3. ネットワーク通信

- HTTP クライアントにはタイムアウトを設定する（`http.DefaultClient` をそのまま使わない）。
- **レスポンスサイズの上限**: 外部サーバーのレスポンスを読むときは `io.LimitReader` などで上限を設ける。上限なしの `io.ReadAll` / `json.Decoder.Decode` は指摘対象とする。
- リトライする場合は回数または経過時間の上限を設ける。
- **応答から取り出すものを限定する**: `200` 以外の応答からは、エラーの識別子（`id`・`request_id`）だけを取り出し、`message` などの自由文は読まない・表示しない。
- **モデル ID は要求本文にだけ入れる**: モデル ID（`YT2COLUMN_LLM`・`YT2COLUMN_REVIEW_LLM` の最初の `/` より後ろ。そこに `+` があれば `+` より前）は、`/` を含んだまま、要求本文（JSON）の値としてだけ送り、要求の URL には入れない。今の 3 つのアダプタは、モデルを要求本文の `model` の値としてだけ送る。URL のパスにモデルを入れる API のプロバイダを加えるときは、モデル ID の中の `/` や `..` がパスを変えないようにする。

## 4. LLM プロバイダへ送るデータ

- DeepSeek の API への入力は中国で処理・保存され、プライバシーポリシー上はデフォルトでモデルの学習に使われる（オプトアウトあり）。運用開始前にオプトアウトの設定を確認する。
- Anthropic の Messages API へ送る入力と出力は、商用製品の既定では Anthropic のモデルの学習に使われない（利用者がフィードバックを明示的に送った場合や、利用者が許可した場合を除く）。Anthropic API の入力と出力は、受け取りまたは生成から 30 日以内にバックエンドから自動的に削除される。利用者側で保持期間を延ばす機能を使う場合、別途合意した場合（ゼロデータ保持など）、利用ポリシー違反の調査、法令上の保持は例外である。出典: Anthropic Privacy Center [「Is my data used for model training?」](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)・[「How long do you store my organization's data?」](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)（2026-10-12 確認）。
- OpenAI の Responses API（`POST https://api.openai.com/v1/responses`）へ送るデータは、ほかのプロバイダと同じである（この節の最後の 2 項目）。アダプタは要求に `store: false` を常に付け、変える設定はない。出典: OpenAI [Data controls in the OpenAI platform](https://developers.openai.com/api/docs/guides/your-data)・[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)（2026-11-11 確認）。
  - API へ送った入力と出力は、既定では OpenAI のモデルの学習・改善に使われない（利用者が明示的にオプトインした場合を除く）。
  - `store: false` は、応答を後から API で取り出すための保存（既定や `store: true` では 30 日）を止めるだけである。下のプロンプトキャッシュの状態は止めない。不正利用の監視ログは `store` の値にかかわらず既定で作られ、通常は最大 30 日保持されうる（法令上の必要や、サービス・第三者を害から守るために長く保持する場合を除く）。監視ログから内容を除くのは、承認を受けた利用者の Modified Abuse Monitoring やゼロデータ保持であり、`store: false` はそれに当たらない。本ツールの要求をゼロデータ保持と説明しない。
  - プロンプトキャッシュは、`store` とは別に、暗号化したキーと値のテンソル（KV テンソル）をアプリケーションの状態として保持しうる。要求が指定する 30 分（`prompt_cache_options.ttl`）は最低保持期間であり、OpenAI はそれより長く保持しうる。30 分後の削除は保証されない。公式の文書は、プロンプトキャッシュの保持の上限を 24 時間としている。
  - これらは設計時（2026-11-10）と実装時（2026-11-11）に確認した公式の文書の記述であり、外部の仕様は変わりうる。設計の判断は [ADR-0041](adr/0041-openai-api.md) にある。
- 字数の調整の工程は生成した文面（タイトルと本文）も LLM に送る。検証・推敲の工程は、生成した文面に加えて素材（字幕・概要欄・動画タイトル・チャンネル名）も送る。検証・推敲のプロバイダを生成と別にする（`YT2COLUMN_REVIEW_LLM`）と、送り先の事業者が増える。
- LLM に送るのは、生成では公開動画の字幕・メタ情報、字数の調整では生成した文面、検証・推敲では生成した文面と素材、そしていずれの工程でもプロンプトテンプレートだけにする。API キー、ローカルのファイルパス、利用者の個人情報をプロンプトに含めない。

## 5. キャッシュディレクトリ

- ディレクトリは `0o700`、ファイルは `0o600` で作成する。
- キャッシュの読み込み時も、ファイル名を動画 ID から組み立てる（ディレクトリ内の任意のファイル名を信用しない）。
- ディレクトリを列挙する必要がある場合（dangling なエントリの掃除など）は、自分の命名規則に完全に一致し、動画 ID の検証を通った名前だけを扱う。操作するパスは検証済みの動画 ID から組み立て直し、シンボリックリンクを辿らない。
- 中間生成物（`--artifacts` の成果物）も `0o600` で作り、キャッシュの外の利用者が指定したディレクトリに置く（CLI はディレクトリを作らない）。名前は検証済みの動画 ID と固定の工程名から組み立てる。読み書きは `os.Root` のハンドルを基準に行い、読み込みでは `Lstat` で通常のファイルに限ることを確かめ、開いた記述子が同じファイルであること（`os.SameFile`）と大きさの上限を確かめてから読む。シンボリックリンク（ルート内を指す相対のものを含む）と FIFO は拒否し、`--artifacts` がキャッシュディレクトリの中にある場合は拒否する。

## 6. 信頼できないテキストの取り扱い

- 字幕・タイトル・概要欄はプロンプトに埋め込まれる。プロンプトインジェクションによって生成記事の内容が操作されうることを前提とし、生成結果を他のコマンドやコードとして実行しない。
- **出典リンクは、LLM の出力ではなくコードで付ける。** URL は検証済みの動画 ID から組み立て、生成したテキストの URL は使わない。出典リンクは、生成に成功した記事の本文の一部である。記事の出力は、`--out` のファイルへの保存と、ビューアでの表示・コピーの 2 つで、どれもこの本文から作るので、どの出力にも出典リンクが付く。
- LLM の空応答・途中打ち切り（`finish_reason` が `stop` 以外）はエラーとして扱い、不完全な記事を `done` にしない。
- 推論モデルの推論過程（DeepSeek の `reasoning_content`）は記事に含めない。
- **表示とコピーで、記事によるメンションの通知を抑止する。** サーバは、状態の取得の `done` の応答の `markdown` に、表示用の Markdown の対象の `@` を無効化した文字列を入れ、ビューアはそれをそのまま描画し、コピーする。表示した記事の全体を選択してブラウザでコピーしたときも、同じ位置で無効化した文字が貼り付けられる（Markdown の記号は描画で除かれる）（F-002・F-003、[ADR-0043](adr/0043-copy-mention-neutralization.md)）。
  - **対象の `@`:** `@` のうち、先頭にあるもの、または直前が文字でも数字でもないものである。`＠` などの見た目の似た文字と、`@` を表しうる文字参照（`@` を表す数値の文字参照と、すべての名前付きの文字参照）を含む。直後の文字は問わない（`@**channel**`・`@ `・末尾の `@` も対象になる）。語の途中の `@`（`Tech@Work`、`user@example.com`）は対象の `@` ではない。
  - **無効化:** 対象の `@` の直後（文字参照が表す `@` では、その `;` の直後）に U+200B を 1 つ入れることである。`@` そのものと、記事のほかの文字は変えない。入れるのは 1 つの `@` の単位に 1 つだけである。
  - **変えない `@`:** URL のパスの `/@`（Mattermost が自動リンクにしてメンションとして扱わない形）は変えない。条件は、`@` が文字参照でなく直前が `/`、`@` より前の同じ行に小文字の `http://` か `https://` があり、その直前が行頭か空白か ASCII でない文字か `(`（またはそれらの後ろの `<`）、ホストが文字・数字・`.`・`-` だけで先頭が文字か数字で直後が `/`、URL の始まりから `@` までに空白・`<`・`>`・`?`・`#`・`` ` `` がなく、表示用の Markdown の URL の始まりより前に `[` がない、の 5 つである。URL の中でも、これらに当たらない `@`（`https://@channel`、`https://example.com/?@here`）は無効化する。
  - **見出し:** ビューアの記事の上の見出し（動画のタイトルとチャンネル名）は、サーバが無効化した値を表示する。見出しでは、URL のパスの `/@` も含めてすべての対象の `@` を無効化する。記事が完了する前の見出しと、生成の開始が動画のタイトルを送らなかったときの見出しのタイトルは、拡張が読んだ値のままで、無効化しない。
  - **コードの中:** コードスパンとフェンス付きコードブロックの中の `@` も無効化する。ビューアは記号を除いて描画するので、選択によるコピーではコードの `@` がコードの外の `@` として貼り付くためである。
  - **変えない出力:** `Article` の値と、`--out` と「.md で保存する」のファイルの中身は変えない。
  - **拒否しない:** コピーは記事の内容によって拒否しない。以前の投稿が拒否した並び（コードの中の対象の `@`、直前が `/` の対象の `@`、`<!`・`<@`、文字参照、`<a|b>` の形）を含む記事もコピーでき、それらの並びは、上の規則で対象の `@` に U+200B を入れるほかは変わらない。URL のパスの `/@` は変えず、ほかの直前が `/` の対象の `@` は無効化する。
  - **通知:** 無効化したかどうかは、サーバの無効化の部品が値として返し、応答の `mentionsNeutralized` にする。ビューアは、それが真のときだけ、コピーの通知で無効化したことを示す（数を示さない）。表示した記事を選択してブラウザでコピーしたときは通知を出さない。
  - **置き場所と時間:** 規則はサーバの `internal/publisher` の 1 か所にあり、入力の長さに比例する時間で終わる。ビューアは受け取った文字列を加工しない。拡張だけの構成へ移った後も、同じ部品を WASM の中で使う。
  - **根拠:** この規則は、Mattermost の `master`（コミット `d504067`）と `v11.11.3` のソースの読解と、Mattermost サーバ 11.11.3 の実機の確認に基づく。読解していない版では保証しない。
- **表示とコピーに残るリスク（許容する）。** (1) Slack では確かめていない。(2) `.md` で保存したファイルや `--out` のファイルの中身を貼り付けた場合は無効化されない。(3) `<https://…|表示>` の形は Mattermost でリンクになる（行き先は `about:blank#blocked` で、メンションにはならない）。(4) Mattermost が文字参照とエスケープを解く規則が変わり、こちらの判定が想定しない形で `@` を作ると、その `@` がメンションになりうる。(5) こちらが URL のパスの `/@` と判定するのに Mattermost が自動リンクにしない並びでは、その `@` がメンションになりうる。逆に、Mattermost が自動リンクにする URL のうち、こちらの定義より広い形（ポート付きのホスト、`_` を含むホスト、大文字のスキームなど）では、U+200B が入って URL が壊れる。(6) 表示した記事を選択してコピーしたときは、無効化したことの通知は出ない。(7) 記事の一部を選択するか分けて貼り付けるとき、変えなかった `@` の直前で切ると、その `@` がメンションになりうる。(8) Mattermost は、利用者が設定したキーワードや名前を、`@` がなくても通知する。(9) 記事が完了する前の見出しと、生成の開始が動画のタイトルを送らなかったときの見出しのタイトルは無効化しない。
- **チャンネル名は、タイトルと同じく外部由来の表示用の文字列として扱う。** 拡張が YouTube のページから読む値（localhost サーバ）、または `yt-dlp` が出す値（CLI）で、信頼しない。同じ規則（有効な UTF-8、空白だけでない、制御文字なし、双方向の制御文字 U+202A〜U+202E・U+2066〜U+2069 なし、200 コードポイント以下。空文字は「チャンネル名なし」）を 3 か所で適用する。要求の入口（`parseRequest`。違反は `invalid_body`）、LLM を呼ぶ前（`validateTranscript`）、公開の直前（`CheckPublishable`）である。拒否のエラーは規則の名前だけを示し、値を含めない。表示とコピーの無効化の対象になり、見出しでは URL のパスの `/@` も無効化する。
- **`--out` のファイルのフロントマターの値は、すべて二重引用符の文字列にする。** 値の書き出しは `strconv.Quote` とし、引用符・バックスラッシュ・`:`・`#`・`---` を含む値でもフロントマターの行数とキーの並びは変わらない。値は検査済み（有効な UTF-8、制御文字なし）のものだけを渡し、変換で黙って値を変えない（制御文字の除去などをしない）。`CheckPublishable` が引用符で囲む値（チャンネル名・モデル名・モデルの版・出典 URL）の UTF-8 を検査する。見出しの下のチャンネル名の行は、行頭がブロックの記法になる場合に限り、行頭にバックスラッシュを 1 つ入れる（番号付きリストの記号は数字の後ろ）。行頭の空白は落とす。残るリスクとして、タイトルとモデル名の書式制御文字は拒否せず、チャンネル名の行の途中の記法（`*強調*`・自動リンク・インライン HTML）は描画するビューアで有効になる。拡張のビューアは記事を描画するので（§8.1）、チャンネル名の行の途中の `**…**`・`*…*` は強調に、`` `…` `` はコードになり、リンクの条件を満たす `<https://…>` はリンクになる。インライン HTML は文字のまま表示する。行の途中の ASCII の区切り文字の前の `\` は表示されない。
- **検証・推敲の応答を信頼しない。** 応答は LLM が書いた JSON であり、信頼できない入力として扱う。応答全体の大きさ（1 MiB）と項目の数（256）に上限を設け、正しい UTF-8・対になっていないサロゲート・末尾に続くデータ・未知のキーと重複したキー・値の型・制御文字（タブ以外を拒否し、`before`・`after` は改行 `\n` も拒否、`evidence` の `\n` だけを認める）を検査し、規則に反する応答は補正・部分受理せずに拒否する。直す前と直した後の記述は、記事の中にちょうど 1 回だけ現れ、範囲が重ならず、見出しの構成を変えないことを確かめてから当てはめる。拒否のエラーには応答の値を含めない。
- **LLM の応答の `usage` を信頼しない。** 応答の `usage` もネットワークから受け取る信頼できない入力である。規則に合わない値（要素の不在・重複、値が負でない整数でない：負数・`-0`・小数・指数・`int64` を超える数・文字列・真偽値・`null`・配列・オブジェクト）は受理せず、その呼び出しのトークン数を「不明」とする。`usage` の不正で応答を拒否せず、記事の生成も失敗させない（副次的な情報のために本来の機能を失わない）。不明の理由は壊れた規則と要素の名前（アダプタの定数）だけから作り、応答のテキストと `usage` の値を含めない。トークン数の行は `redact.Line` を通る。ただし Claude の `cache_read_input_tokens`・`cache_creation_input_tokens` の `null` だけは、文書化された値として 0 とする（プロンプトキャッシュを指定していないため）。
- **一覧のファイル（`--review-log`）に入る値**は、記事の値と検証・推敲の応答の値だけから作り、設定の値（API キー）を含めない。検証・推敲の応答から来る値は Markdown の引用ブロックの中に置き、値の中の見出し記号などがファイルの見出しの構造を壊さないようにする。記事のタイトルとモデル名・モデルの版は制御文字と改行を拒否する検査を通り、出典 URL は検証済みの動画 ID から組み立てるので、箇条書きの行も見出しの構造を変えない。公開の直前と同じく、書き出す前に記事の値を `CheckPublishable` で検査する。
- **中間生成物（`--artifacts`）に入る値**は、工程の出力（記事のタイトルと本文、検証・推敲の一覧）と来歴（工程・モデル名とモデルの版・トークン数・呼び出しの時刻・テンプレートの内容のダイジェスト・入力の識別子）だけとし、API キー・上書きテンプレートのローカルのパス・設定の値を含めない。読み込みは信頼できない入力として境界で検査し、未知のキー・重複したキー・末尾の内容・上限（ファイル 4 MiB・文面 1 MiB・一覧 256 項目）の超過・本文の先頭の U+FEFF を拒否し、入力の識別子を生成の出力まで順にたどって照合する。`usage` 要素も検査し、4 つの区分のオブジェクトか不明を表す `null` だけを受理し、宣言していない要素・要素の欠け・重複・負数や範囲外の数は拒否する。トークン数と呼び出しの時刻は来歴の一部として `id` の計算に含め、書き換えたファイルを拒否する。呼び出しの時刻（`call_time`）は `YYYY-MM-DDTHH:MM:SSZ` の 20 バイトの文字列だけを受理し、`time.Parse` の後に同じ書式で書き直した文字列とのバイト単位の一致でほかの書き方を拒否する。ゼロの時刻と UTC でない時刻も拒否する（`TestParseRecordRejectsCallTime`）。ただし `id` は秘密の鍵を使わない識別子なので、トークン数や呼び出しの時刻を書き換えたうえで `id` を計算し直したファイルは検出できない（残余のリスクであり、改ざんの影響は、再利用した工程のトークン数の表示と、料金の行の適用した単価・`at=` の時刻・推定コストを誤らせることに限られる）。壊れた入力は補正も部分受理もしない。拒否のエラーには成果物の値を含めない。

## 7. リポジトリに保存する実データ

テスト用に実際の取得結果（`yt-dlp` の出力、YouTube のページの HTML など）を `testdata/` に保存するときは、次を守る。個々のファイルの出典・加工内容・作り直し方は [testdata/README.md](../../testdata/README.md) に記録する。

- 保存してよいのは、再配布が許諾されたライセンス（CC BY など）の動画から取得したものだけにする。出典とライセンスを `testdata/README.md` に明記する。
- 取得者を特定できる情報は、コミットする前に取り除く。`yt-dlp` の info.json は署名付き URL に取得者の IP アドレスを埋め込むので、該当する値を置き換える。ブラウザで保存したページの HTML は、ログインした状態で保存するとアカウントの情報（アバター、登録チャンネルの一覧、視聴履歴に基づくおすすめなど）を含む。ログインしていない状態で保存し、さらに必要な要素だけを切り出す。
- ページ全体のスナップショットはコミットしない。YouTube 自身のマークアップ・スクリプト、他チャンネルの動画の情報を含み、ログインした状態で保存した場合はアカウントの情報も含むためである。スナップショットは、どの worktree からも参照できるように、リポジトリの外の `${YT2COLUMN_SNAPSHOT_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/yt2column/snapshots}` に置く。`.envrc` は worktree に複製されないので、この環境変数は任意とし、設定しなければ既定のパスを使う。テストはこのディレクトリを参照しない。

## 8. ブラウザ拡張と localhost サーバ（#43）

ブラウザ拡張（#110・#111）は、収集した字幕と動画ページの URL を、利用者のマシンで動く localhost のサーバ（#104・#109）へ送る。#170 から、動画ページの DOM から読んだ動画タイトル・チャンネル名・概要欄も任意のメンバとして送る（§8.1）。タブのタイトルは送らない。#272 から、サーバは TCP を待ち受けず、Unix ドメインソケット（UDS）だけを待ち受ける。拡張からの送信は、ブラウザが起動する Native Messaging のホストが UDS へ中継する。

- **同一ユーザーのフル権限プロセスは信頼する。** サーバや拡張と同じ OS ユーザーとして動き、ファイルの読み書きとプロセスの起動ができるプロセス（AI Agent を含む）は、`.envrc` と API キーを読め、サーバを経由せずに LLM API を直接使える。サーバの入口をどう限定しても、これらの資産は守れないので、この相手は排除しない。
- **動画単位で記事の有無とキーを返す照会を受け入れる。** 照会付きの生成の開始（生成の開始の本文の `mode` が `inquiry`）は、検査を通る本文（字幕は形が通れば中身を問わない）を送れば、その動画の記事があるかどうかを、記事の入力（字幕の中身と動画メタデータ）を知らずに知る手段になる。今の入力のキーの記録が処理中か完了なら、今と同じく `202` の受け付けの応答でそのキーを返す。そうではなく、同じ動画（動画 ID が同じ）の別のキーの記事が処理中か完了なら、生成を始めず、LLM を呼ばず、キャッシュの記録を加えも捨てもせずに、その記事のうち受け付けた時点が最も新しい 1 件のキーを、`200` と `{"status":"same_video","key":"…","requestId":"…"}` で返す。どちらでもなければ、照会なしの生成の開始と同じく生成を始め（生成の枠を取り、記事のキャッシュが上限に達していれば完了か失敗の古い記録を捨てる）、生成の枠か件数の上限で `too_many_requests` になることもある。返すのは、照会した動画のその 1 件のキーだけで、ほかの動画の記事の有無も、記事の一覧も返さない。`0044` の設計書 §3.2 と脅威 T-10 は、生成を始めずに記事の有無を知る手段を作らないことを、キーの計算に秘密を使う理由の 1 つとした。この照会による記事の有無の判定は、排除する脅威ではなく、信頼の境界の内側で受け入れるリスクとして再評価する。T-10 の攻撃者は、ソケットに接続できる同じ利用者の権限のプロセスであり、`0044` の T-07 のとおり信頼する。そのプロセスは今も、生成の開始でキーを得て（T-10 の残るリスク）、そのキーで記事の状態を読み、`.envrc` を読んで LLM API を直接使え、ブラウザの履歴も読める。記事の有無を動画単位で知る手段は増えるが、照会を送れるのはソケットに接続できる同じ利用者の権限のプロセスと拡張だけで、守る資産は変えない。他ユーザーのプロセスは UDS の権限で、ウェブページはサーバが TCP を待ち受けないことで、今と同じく排除する（§8）。承認済みの `0044` の設計書は当時の決定の記録として変えず、この再評価は本書に書く。
- **キーを秘密から計算する理由は、この再評価の後も残る。** キーは今と同じく、サーバのプロセスごとの秘密を鍵とする HMAC-SHA256 で計算する。同じ動画の判定に使う動画 ID は、キーの計算に入れない。`0044` が挙げた、生成を始めずにキーを計算されることの防御は、ソケットに接続できる同じ利用者の権限のプロセスを信頼した後は当てにしない。秘密を使う目的は、公開しないキーの計算方法に利用者と拡張を依存させないこと（Hyrum's Law）である。同じ入力のキーは、生成の開始か照会を送らなければ得られない。
- **排除する相手ごとに根拠が異なる。** 混同しない。
  - 他ユーザーのプロセス: ソケットのディレクトリの `0700`（主な防御）とソケットの `0600`（2 つ目の防御）、ディレクトリとソケットの所有者の検査で排除する（§8.2）。
  - ウェブページ: サーバは TCP を待ち受けないので、ページからサーバへ届く経路がない。ブラウザには、ページから UDS へ接続する手段がない。DNS rebinding や preflight の不要な `POST` でページが loopback のサーバへ届く問題（以前の TCP のサーバの前提）は、待ち受けそのものがなくなったことで生じない。
  - サンドボックス化された Agent: 排除しているのはサンドボックスのポリシーであり、UDS の権限ではない。ファイルのモードは同じ uid のプロセスを区別しないので、ポリシーが Unix ソケットへの接続を許可していれば、Agent はサーバに到達できる。UDS への移行によって、この点が後退することはない。
- **UDS の権限は同じ uid のプロセスを区別しない。** ソケットに接続できる相手は、同一ユーザーのどのプロセスでもありうる。サーバは、この相手が付けられる `Host`・`Origin`・`Content-Type`・`Authorization` のヘッダを検査しない（誰でも偽れるので、検査しても排除できる相手がいない）。検査するのはパスとメソッドだけである。
- **共有トークンを削除した理由。** 以前の共有トークンは拡張の認証ではなく、トークンのファイルを読める相手だけが示せる秘密の値で、ファイルを読めない相手を排除するものだった。同一ユーザーのフル権限プロセスはトークンのファイルも `.envrc` も読めるので、トークンを残してもこの相手は防げない。他ユーザーとウェブページは上のとおり UDS で排除できるので、トークンが排除する相手は残らない。そのため削除した。

### 8.1. ブラウザ拡張（#110）

本タスクの拡張（#110）は、開発環境と、選択範囲・タブの URL・タブのタイトルの収集と表示、および選択範囲と URL のサーバへの送信を行う。#170 で、動画ページの DOM から動画タイトル・チャンネル名・概要欄（以下、動画メタデータ）を読み、表示し、本文に加えて送るようになった。#272 で、送信を Native Messaging のホストを通す形に改め、共有トークンとポートの設定を削除した。#503 で、送信をサーバのジョブの API に移し、Service Worker と、記事を表示する拡張のページ（ビューア）を加えた。ポップアップの主ボタンで Service Worker が照会付きの生成の開始を送り、同じ動画の記事があれば、ポップアップは「既存の記事を表示する」か「現在の選択範囲で生成する」（照会なしの生成の開始）かを選ばせ、ビューアは既存の記事を表示する。ポップアップとビューアは記事のキーで状態の取得を繰り返し、ビューアは記事を表示し、保存とコピーを行う。

- **要求する権限**（`docs/tasks/0026_native_messaging_relay` の設計書 3.7.1 の manifest）: `activeTab`（利用者が起動したタブに限り、そのタブの URL・タイトルを読み、スクリプトを注入することを許す）、`scripting`（起動したタブに、選択範囲と動画メタデータを読む関数を注入する）、`nativeMessaging`（固定のホスト名 `io.github.isseis.yt2column` のホストを起動し、1 つのメッセージを送って 1 つの応答を受け取る）。閲覧内容全般に及ぶ権限（すべてのサイトへのホストの権限、`tabs`、`history`、`cookies`、`webRequest` など）と、`host_permissions`・`storage` の権限は要求しない。
- **送る相手は固定のホストだけ。** 拡張は `chrome.runtime.sendNativeMessage` で固定のホスト名にだけ送り、ホスト名を変える設定を持たない。ネットワークへの要求（`fetch`・`XMLHttpRequest`・`WebSocket`・`EventSource`）を持たず、接続を開いたままにする `connectNative` も使わない。操作は新しい形のメッセージの `op`（`start`・`status`）で指定し、パスもメソッドも指定しない。1 回のやり取りでホストを 1 回起動し、1 つのメッセージを送って 1 つの応答で終わる。状態の取得はポーリングとして繰り返すので、1 回の送信の後にも、ポップアップと開いている各ビューアがホストを繰り返し起動する。1 つのページが同時に送る状態の取得は 1 つまでで、繰り返しても結果の変わらない応答では止める。ホストを起動できる拡張は、ホストの manifest の `allowed_origins` が固定の拡張 ID に限る（§8.2）。
- **権限を広げずに、ビューアを開き、保存し、コピーする。** ビューアのタブは `chrome.tabs` の権限の要らない操作（作成・選択・削除・取得）で開き、`chrome.windows.update` で前面に出す。同じ記事のビューアは `BroadcastChannel` で探す。このチャンネルは拡張自身のオリジンの文脈の間でだけ届き、ウェブページや注入したスクリプトは送れない。記事の保存は拡張のページからの Blob のダウンロードで、コピーは利用者の操作の中のクリップボードへの書き込みで行う。`tabs`・`downloads`・`clipboardWrite`・`storage` の権限を要求しない。ビューアは `web_accessible_resources` に含めないので、ウェブページはビューアを開くことも埋め込むこともできない。
- **生成の開始は、拡張自身のポップアップからだけ受け付ける。** 生成の開始は料金がかかるので、Service Worker は、送り手が自分の拡張で、タブを持たず（注入したスクリプトとタブの拡張のページはタブを持つ）、URL がポップアップのページと完全に一致する求めだけを受け付け、ほかの求めには何も送らず、タブも開かない。`onMessageExternal` と `externally_connectable` を使わない。
- **設定を保存しない。** 拡張は `chrome.storage` を使わず、トークン・ポート・ほかの設定を持たない。送信ごとの値は、ビューアの URL と各ページのメモリにだけある。ビューアの URL は、見出し・チャンネル名・動画タイトル・動画の URL・送信の時刻と、受け付けた後は記事のキーを持ち、既存の記事のビューアは既存の記事を表示していることを示す値（`e=1`）も持つ。これらはブラウザの履歴に残る。`history.replaceState` で URL を書き換える前と後の URL が、それぞれ履歴の項目になりうる。Chrome の同期で履歴がほかの端末に渡りうるし、`tabs` や `history` の権限を持つほかの拡張はこれらの URL を読める。これらは受け入れる。コピーした字幕と概要欄は URL に入れない。`e` は、そのビューアが既存の記事を表示していることだけを表し、入力や既存の記事の値を含まない。動画の URL とタイトルは、動画のページを開いた時点ですでに履歴に残る値である。キーはサーバのプロセスごとの秘密を鍵とする値で、サーバの再起動の後は使えない。0020 の版が `chrome.storage.local` に保存した共有トークンとポート（キー `sharedToken`・`serverPort`）は、拡張を更新しても残りうる。拡張は `storage` の権限を持たないので、これを読むことも削除することもできない。新しいサーバはトークンを読まないので、残った値が通用する相手はない。値はプロファイルのディレクトリにあり、読めるのは同一ユーザーのプロセスだけで、以前の版と同じ信頼の範囲である。消したい場合は、`chrome://extensions/` で拡張を一度削除してから読み込み直す（拡張 ID は manifest の `key` で決まるので変わらず、ホストを install し直す必要はない）。
- **API キーを持たない。** 拡張はこれを保持も入力も保存も表示もしない。
- **送れなかった場合と結果が分からない場合を分け、自動で再送しない。** サーバに届いていないと確定する場合（未送信。ホストが返す `server_unavailable`・`message_too_large`）と、応答がない場合（`server_timeout`）、ホストの失敗（ホストを起動できない、応答の前に終了した）、想定外の応答（まとめて結果不明）を分ける。生成の開始は、どの結果でも自動では再送しない。生成の開始の結果不明では、同じ入力を送り直しても、その記事が処理中か完了していれば二重には生成されない（サーバは同じ入力に同じキーを返し、LLM を呼ばない）ことを示す。自動で繰り返すのは、生成を始めない状態の取得だけである。
- **ホストの失敗をブラウザの文字列で分けない。** ブラウザはホストの失敗を `chrome.runtime.lastError` の文字列だけで伝える。この文字列は Chromium の内部の定数で、版によって変わりうるので、拡張はどの文字列もホストの失敗（結果不明）として扱い、表示にも分類にも使わない。開発者向けのログにだけ記録する。
- **応答を受理する形で検査し、記事のほかの文字列を表示しない。** ホストの応答は信頼できない入力として扱う。版（`v`）・形（`kind`）・メンバの集合・型を確かめ、合わなければ想定外の応答とする。ホストが包んだサーバの応答の本文（標準の base64）は、正規の形のものだけを復号し、ホストが中継する上限（§8.2）までに限る。本文は厳格な JSON として解析し（BOM・不正な UTF-8・メンバの重複・対になっていないサロゲートのエスケープ・後続のデータを拒否する）、操作と状態ごとのメンバの集合、コードの閉じた集合、数値の表記、状態コードと `status`・`reason` の組が合わなければ想定外の応答とする。表示に使う応答の文字列は、記事（無効化した表示用の Markdown とファイルの中身）と、無効化した動画のタイトル・チャンネル名と、形を検査した推定の料金の金額だけである。コードは固定の文言に、`requestId` は 16 進 16 文字に限る。
- **記事を untrusted テキストとして描画する。** 記事は LLM の出力で、字幕とメタデータへのプロンプトインジェクションで操作されうる。ビューアは、表示用の Markdown を、タスク 0063 の要件（`docs/tasks/0063_viewer_markdown/01_requirements.md` §3.2）が定める少ない規則だけで解釈し（ADR-0017）、見出し・段落・リスト・強調・コード・リンクに描画する。HTML は解釈しない。解釈の関数（`parseArticleMarkdown`）が記事の木を作り、組み立ての関数（`buildArticleBody`）は記事の木の種類だけで要素を選んで、要素の生成と文字のノードだけで DOM を作る。作る要素と属性は固定の一覧に限り、記事の内容から値を決める属性は、リンク先と番号付きリストの開始番号だけである。リンクにするのは `https` の自動リンク（`<https://…>`）のうち、URL として解釈でき、ホストを持ち、ユーザー名とパスワードを持たず、直列化と 1 文字も違わないものだけで、表示する文字列とリンク先は同じ URL の文字列である。リンクは新しいタブで、参照元を送らず、開いたページに `window.opener` を与えない形（`rel="noopener noreferrer"`）で開き、周りの文字の方向から分離して左から右に表示する。`[文字](URL)` の形のリンク、HTML のタグ、文字参照は、文字のまま表示する。HTML を解釈する API は lint で禁止し、リンク先の型 `LinkUrl` を作れるファイルも lint で解釈の関数のファイルに限る。拡張のページの既定の Content Security Policy を緩めない。ビューアは `nativeMessaging` を呼べるページなので、記事からスクリプトが動けば、ホストへの任意の送信につながるためである。保存とコピーは描画の結果を使わず、状態の取得が返す文字列を変えずに使う。残余のリスクとして、次を許容する。(1) 記事が `https` の自動リンクで任意のサイトを指すことは防がない。利用者が押せば、そのサイトが開く。リンクの表示は URL そのもので、プロンプトは本文に URL を書かせないので、出典の行のほかの自動リンクはプロンプトインジェクションの疑いが強い。(2) リンク先には `https://localhost/`・`https://127.0.0.1:8443/`・LAN のアドレスも入りうる。押すと、そのアドレスへ GET のリクエストが 1 回送られる。(3) チャンネル名の行の途中の記法は、本文と同じに描画される（§6）。動画の持ち主は、LLM を介さずにリンクと強調を作れる。(4) ビューアの URL は記事のキーを持つので、リンクの `rel` から `noreferrer` を外す変更は、キーをリンク先に渡しうる。(5) 同じ行の右から左への上書き（U+202E など）で、リンクの前後の文字の並びが変わり、リンクの隣に見える文字が変わりうる。リンクの中の文字の順と、ほかの行の表示は変わらない。元の動画へのリンクは、収集と同じ検査を通った動画ページの URL だけを、参照元を送らない形で表示する。ビューアの URL の値は信頼できない入力として検査し、合わなければ記事を表示せず何も送らない。開いただけで送るのは状態の取得だけである。記事が完了する前の見出しと、生成の開始が動画のタイトルを送らなかったときの見出しのタイトルは URL の値なので、細工した URL は利用者を誤解させる見出しを表示しうる（README に書く）。

  残余のリスク（許容する）: 利用者が、リンクにならなかった記事の中の URL の文字列をコピーして開くことは防げない。ビューアを多く開くと、その数だけホストが起動し、止まったサーバに対して状態の取得を続けるビューアを開いたままにすると、ホストの起動を続ける（隠れたタブではブラウザが間引く）。
- **開発者向けのログに値を出さない。** Service Worker・ポップアップ・ビューアのログは、固定のラベル、結果と検査の種類、数、経過時間、状態コード、`requestId`、ホストの失敗のときのブラウザのエラーの文字列だけを書き、字幕・記事・動画メタデータの値・キー・URL の値を書かない。
- **利用者が起動するまでページを読まない。** `content_scripts` を宣言せず、ページの読み込み時に自動で実行されるコードを持たない。起動で読むのは起動したタブだけである（`activeTab`）。選択範囲はページの DOM の構造に依存せず、ブラウザの選択の API（`window.getSelection()`）で取得する。
- **動画メタデータは DOM から読むだけで、ページを操作しない。** 動画タイトル・チャンネル名・概要欄は、収集が成功したときだけ、起動したタブの動画ページの DOM から読む。新しい権限を加えず、既存の `scripting` の注入で DOM を読むだけで、クリック・フォーカス・入力などページを操作するコードを持たない（概要欄の「…もっと見る」も開かない）。読む時点のページの URL が収集した URL と一致しない場合は、別の動画の値を混ぜないよう 3 つの値をすべて省略する。DOM の構造は YouTube が独自に定義したもので変わりうるため、取得に失敗しても起動を失敗させず、拒否の理由にもしない（値を省略して選択範囲と URL を送る）。開発者向けのログにはフィールドの名前・省略の理由・失敗した検査の種類・折りたたみの状態だけを残し、読み取った値は残さない。
- **動画メタデータを untrusted テキストとして扱う。** 読み取った結果は信頼できない入力であり、受理する形（決めたメンバと値の型）に合うものだけを受け入れる。値は HTML として解釈せず `textContent` だけで表示し、双方向の制御文字で表示順が変わらないよう `dir="auto"` と `unicode-bidi: plaintext` で分離する。本文へは JSON の文字列として入れる。値の大きさは本文の上限（4 MiB）の判定に含める。
- **読み取った文字列をテキストとして表示する。** 選択範囲とタブのタイトルは信頼できない入力であり、HTML やほかのマークアップとして解釈せず、`textContent` だけで表示する。`eval`・`new Function` と HTML を解釈する API は lint で禁止し、Manifest V3 の既定の Content Security Policy を緩めない（lint とは独立した 2 つ目の防御）。
- **秘密鍵をリポジトリに含めない。** 拡張 ID の固定には manifest の `key`（公開鍵）だけを使い、生成した RSA の秘密鍵は生成直後に削除する。固定した拡張 ID は `clfmbbcdpnjcefbdihdoahomaifbabkk`。拡張 ID は秘密ではなく、`key` は公開情報なので誰でも同じ ID の拡張を読み込んで名乗れる。したがって拡張 ID（ホストの `allowed_origins` と、ホストが受け取る呼び出し元のオリジン）は送り元の認証にならない（§8.2 の残余のリスク）。
- **依存パッケージは lockfile で版を固定し、開発用に限る。** 拡張の実行時に読み込む npm の依存パッケージはなく、`dist/` に含まれるのは本リポジトリで書いたコードだけである。インストールは `npm ci --ignore-scripts` で行い、依存パッケージのインストール時のスクリプト（`postinstall` など）を実行しない。

### 8.2. localhost サーバ（#109）

サーバ（`cmd/yt2column-server`・`internal/server`・`internal/articlecache`・`internal/serversock`）は、拡張から送られた字幕をもとに記事を生成し、メモリに保持して、求めに応じて返す。§8 の方針に加え、次を守る。

- **設定ファイル。** サーバは、API キー・LLM の設定を、`HOME` だけから導出したパスの設定ファイル（`$HOME/.config/yt2column/config.env`。macOS とほかの Unix で同じ。`XDG_CONFIG_HOME` は読まない）からだけ読む（`internal/config`・`internal/privatefile`。[ADR-0018](adr/0018-server-config-file.md)）。サーバのコードがプロセスの環境から読むのは `HOME` と `GODEBUG` だけで、環境の 6 つのキーは読まない。
  - **検査してから、検査した記述子から読む。** `O_NOFOLLOW`・`O_NONBLOCK` で開いた記述子の `fstat` で、通常のファイルであること・所有者が実効ユーザーであること・モードがちょうど `0600`（setuid・setgid・sticky のビットもなし）であることを確かめ、同じ記述子から読む。パスの `Lstat` は拒否にだけ使う。検査の後にパスのファイルを入れ替えられても、検査していないファイルの中身は使わない。シンボリックリンク・通常のファイルでないもの（FIFO は書き手を待たない）・他人の所有のファイル・モードの違うファイルは、何も直さずに起動を中止する（終了コード `2`）。親のディレクトリは検査しない。サーバは設定ファイルの親に何も作らないので、親を検査して守るものがない。
  - **シェルとして実行せず、直さずに拒否する。** 書式は 1 行に 1 つの `KEY=VALUE` で、値を変換しない。変数の展開・コマンドの置換・引用符の解釈をしない。受理する形に合わない行、制御文字・CR・DEL・U+FEFF、UTF-8 として正しくないバイト列、64 KiB を超える大きさは、ファイル全体を拒否し、一部の行だけを使って起動しない（大きさは全体を読まずに拒否する）。
  - **拒否の文に値と中身を出さない。** 拒否は、パス・行番号・固定の理由と、6 つのキーの名前だけを示す。値・行の文字列・未知のキーの文字列は示さない。起動の後のログは今までどおり `redact` を通し、ファイルから読んだ秘密の値を伏せ字にする。
  - **雛形に秘密を入れない。** `yt2column-server config init` は `HOME` だけを読み、コメントの行と空行だけの雛形を、同じディレクトリの一時ファイルに書いて `link` で置く。モードは umask によらず `0600` で、既存のものは上書きしない。ない親（`.config`・`yt2column`）は umask によらず `0700` で作り、既存の親は変えない。
- **UDS だけを待ち受ける。** ソケットのパスは `HOME` だけから導出する（macOS は `$HOME/Library/Application Support/yt2column/run/server.sock`、他の Unix は `$HOME/.local/state/yt2column/run/server.sock`）。`XDG_*`・`TMPDIR` などほかの変数は読まない。ブラウザが起動するホストは利用者のシェルの環境変数を引き継がないので、ほかの変数を読むと、サーバとホストが別のパスを導出しうるためである。導出したパスが OS の上限（Linux は 107 バイト、macOS と他の Unix は 103 バイト）を超えれば、値を含めずに `HOME` を名指して起動を中止する（終了コード `2`）。
- **ソケットのディレクトリ（`run`）は `0700`、ソケットは `0600`。** 他ユーザーを排除する主な防御は、ディレクトリの `0700` である。起動時に、ディレクトリの親が symlink でないディレクトリで、所有者が自分で、グループとその他の書き込みのビット（`0022`）が立っていないことを確かめる（親に他人が書き込めると、検査の後に `run` の名前を入れ替えられる）。`run` がなければ `0700` で作り、symlink でないディレクトリで、所有者が自分で、権限がちょうど `0700`（setuid・setgid・sticky のビットもなし）であることを確かめる。bind の直後、ソケットは umask に従う広い権限で存在しうるが、その間も他ユーザーはディレクトリを検索できない。bind の後に `chmod` で `0600` にし、`Lstat` でソケットであること・所有者が自分であること・権限がちょうど `0600` であることを確かめ直す（2 つ目の防御）。プロセス全体の umask は変えない。
- **修復せずに拒否する。** ディレクトリ・親・ソケットのパスが受理する形でなければ、権限を変えず、何も削除せずに起動を中止する（終了コード `1`）。エラーはパスと固定の理由を示し、利用者が手で直す（CLAUDE.md「Reject, don't normalize」）。
- **起動のロック。** ディレクトリの検査の後、ソケットのディレクトリのロックのファイル（`.yt2column.lock`。`internal/cachelock` を使う）に、待たずに排他の `flock` を取る。stale の判定・`unlink`・bind をサーバの間で直列化し、2 つのサーバが互いのソケットを消し合わないようにするためである。取れなければ、別のサーバが動いているとして起動を中止する（終了コード `1`）。サーバは、`Serve` が返る（シャットダウン中のジョブの完了を待つ）までロックを持ち続けるので、シャットダウン中に起動した次のサーバも中止する。2 つのサーバが同時にジョブを処理し、同時実行の枠の上限がサーバ全体で効かなくなることはない。ロックはプロセスの終了（`SIGKILL` を含む）で解放され、ロックのファイルは削除しない。
- **stale の判定。** ソケットのパスに既にある名前は、自分の所有のソケットで、接続が拒否される（`ECONNREFUSED`）場合だけ、異常終了したサーバが残した stale なソケットとして削除し、bind し直す。接続できるソケット（ロックを取らずに待ち受ける別のプロセス）は削除せずに中止する。他人の所有のソケット、接続の試みがほかの理由で失敗するソケット、通常ファイル・ディレクトリ・symlink・FIFO も、削除せずに中止する。正常に終了すると、リスナーを閉じたときにソケットを削除する。
- **ヘッダの検査はパスとメソッドだけ。** リクエストは、パス（`/jobs`・`/jobs/{key}`）とメソッドを先に検査し、どちらかが合わなければ（`not_found`・`method_not_allowed`）本文を 1 バイトも読まず、枠を取らず、記事を生成しない。HTTP として読めないバイト列には `net/http` が自分で `400` を返し、ハンドラは呼ばれない。生成の開始は本文を読む前に読み込みの枠（`2`）を取り、超えていれば本文を読まずに `too_many_requests` で拒否する。同時に読む本文は最大 2 つである。生成の枠（`2`）を数えるのはジョブの API の生成のジョブだけである。本文を読んだ後でも、生成の枠に空きがない場合と、記事のキャッシュが上限で埋まっていて捨てられる記録がない場合は、生成を始めずに `too_many_requests` で拒否する。未完了のリクエストの資源消費は、本文を読まないこと、枠を取らないこと、`Connection: close`、ヘッダの大きさとタイムアウトの上限で抑える。
- **受け取る入力の境界。** 生成の開始の本文は 4 MiB を上限とし、`Content-Length` の事前検査と `http.MaxBytesReader` で読む。`Content-Length` が上限を超えれば本文を読まずに `body_too_large` で拒否するので、`Expect: 100-continue` を付けたクライアントは本文を送らずに拒否の応答を受け取る。本文全体の UTF-8・対になっていないサロゲート・1 つのオブジェクト・末尾の余分な値・宣言したメンバの重複を厳格に検査し（`internal/strictjson`）、`mode` は必須のメンバとして `inquiry` と `plain` だけを受理し（ほかの値・欠け・重複は、どちらかに補わずに `invalid_body` で拒否し、生成を始めない）、`videoUrl` は `transcript.ValidateVideoURL` で、`transcript` は `transcript.NewCopiedSource` で検査する。合わない入力は補正せず拒否する。状態の取得は本文を取らず、`Content-Length` が 0 でない要求と `Transfer-Encoding` を持つ要求を、本文を読まずに `invalid_body` で拒否する。クエリを付けたターゲットは `not_found` にする。キーはデコードする前のターゲットの 1 つのパスの部分として照合し、64 文字の小文字の 16 進だけを受理する（`%`・大文字・前後の空白・長さの違いは `invalid_key`）。サーバはキーを、キャッシュを引く値・ログの属性・受け付けの応答・同じ動画の応答にだけ使い、ファイルのパスやログの書式に埋め込まない。ホストも、キーの長さや文字の種類を検査せず、`url.PathEscape` で 1 つのパスの部分としてエスケープしてから送る（キーがパスやクエリを作らない）。
- **メモリに持つ記事。** 記事のキャッシュはサーバのプロセスの中だけにあり、ディスクに書かない。持つのは、キー・ジョブと工程の状態・完了した記事（検証・推敲の訂正の一覧を除く）・失敗の理由・時刻である。記録は、同じ動画の判定のために動画 ID も持つ。キーと動画 ID は、どちらも検査を通った同じ入力から決まる。記録の動画 ID は比較にだけ使い、応答にも `Snapshot` にも出さない。動画 ID の値そのものは、今と同じく生成の開始と生成のジョブのログの行の `videoId` に出て、完了した記事の出典の URL（状態の取得の応答と、保存したファイルの中身）に含まれる。記録の動画 ID は、記録が捨てられるかサーバが再起動すると消える。コピーした字幕そのもの（`transcript` の文字列と解析したセグメント）は、生成が終わった後に持たない。件数の上限は 100 件で、超えるときは完了または失敗した時刻の古い記録から捨てる（処理中の記録は捨てない）。サーバの再起動で、記事はすべて失われる。
- **返す記事は untrusted なテキスト。** 状態の取得が返す無効化した表示用の Markdown・無効化した動画のタイトルとチャンネル名・ファイルの中身は、LLM が生成した文章か外部由来の値で、コピーした字幕とメタデータへのプロンプトインジェクションで操作されうる（§6）。サーバは、公開できる形かを確かめ、表示用の Markdown・動画のタイトル・チャンネル名には無効化の U+200B を入れるほかは記事を変えずに返す。拡張のビューアは、記事を HTML として解釈せず、§8.1 の規則で Markdown を描画する。リンク・HTML・スクリプトの扱いは §8.1 による。
- **秘密と字幕の本文を出力に流さない。** API キーは `secret.Secret` で持つ。応答は、完了した記事の文字列（無効化した表示用の Markdown・無効化した動画のタイトルとチャンネル名・ファイルの中身）を除き、拒否の理由・コード・数値・真偽値という固定の値と、サーバが生成した識別子（キー・リクエスト ID）だけで組み立てる。ログは `redact.Writer` を必ず通し、`redact.SecretStrings` が返す文字列を伏せ字にする。キーは、受理する形を通ったものだけをログの属性に出す（中身を復元できない値で、同じ入力の照合にだけ使える）。生成の開始の応答も同じで、同じ動画の応答は `status`・既存の記事のキー・`requestId` だけを持ち、文言・コピーした字幕・`videoUrl` の文字列・動画メタデータ・秘密の値を含まない。生成の開始のログの行は、受理した送信では `requestId`・今の入力のキー・`videoId`・`outcome` と送り方 `mode` を、同じ動画の応答を返した送信では `requestId`・今の入力のキー・`videoId`・`outcome=same_video`・`mode=inquiry`・返した記事のキー `sameVideoKey` という固定の属性だけを書く。既存の記事のキーを出すのは、`grep` で既存の記事のジョブの行と、その記事を返した照会の行をつなげて追えるようにするためである。状態の取得は、応答を返したときはログを書かない（ポーリングで数秒ごとに来るため）。拒否は拒否の行を 1 つ出す。`server.New` がロガーと `http.Server` の `ErrorLog` を `redact.Writer` の上に作るので、呼び出し側が伏せ字の処理を忘れても漏れない。サーバは標準出力に何も書かず、ログ・案内・エラーは標準エラー出力に書く。起動のログにはソケットのパスを記録する（秘密ではない）。
- **開発用のサーバ（`cmd/yt2column-devserver`・`internal/llm/devfake`）。** 開発用のサーバは、fake の LLM で記事を作り、本番のサーバと同じ `internal/server`・ソケット・起動のロックを使う。本番のバイナリと同じ場所で動くので、次を守る。
  - **本番のバイナリに fake を入れない。** `yt2column`・`yt2column-server`・`yt2column-nmhost` の推移的な依存に、`internal/llm/devfake` も `cmd/yt2column-devserver` も含めない。`go list -deps` で間接の依存まで列挙する `make test` のテスト（各 `cmd/` の `TestNoDevDependency`）が確かめる（[ADR-0045](adr/0045-dev-fake-llm.md)）。
  - **設定ファイルも API キーも読まない。** 開発用のサーバは設定ファイル（`$HOME/.config/yt2column/config.env`）を読まず、API キーも要らない。プロセスの環境から読むのは、ソケットのパスを導出する `HOME` だけである（`internal/config` の `LoadHost`）。`YT2COLUMN_LLM` などの環境変数は、振る舞いも出力も変えない（[ADR-0024](adr/0024-env-access-in-config.md)）。
  - **本番のサーバと同じソケットのパスと起動のロックを使う。** ソケットのディレクトリの検査・stale の判定・起動のロックは、本番のサーバと同じ `internal/serversock` が行う。両方を同時には動かせず、後から起動した方はロックを取れずに中止する。
  - **開発用のバイナリを常用の環境に置かない。** 成果物は `build/dev/` に作り、`PATH` の通った場所や常用の環境に置かない。`go install ./...` は `cmd/` の下の開発用のサーバも `GOPATH/bin` に入れるので、実行しない。
  - **残余のリスクを受け入れる。** 利用者が本番のサーバの代わりに開発用のサーバを起動すると、拡張は fake の記事を表示する。記事のタイトルの印、起動の行、料金の不明で気づけるようにする（要件書 §4.2。下の「残余のリスク」にも挙げる）。
- **Native Messaging のホスト（`cmd/yt2column-nmhost`・`internal/nmhost`）。** ブラウザは、拡張が送るたびにホストを起動する。ホストは 1 つのメッセージを UDS のサーバへ中継し、応答を返して終了する。
  - **起動できる拡張を限る。** ホストを起動できるのは、`nativeMessaging` の権限を持ち、`allowed_origins` に載った固定の拡張だけである。ホストの manifest の `allowed_origins` は、固定した拡張 ID のオリジン（`chrome-extension://clfmbbcdpnjcefbdihdoahomaifbabkk/`）だけである。ホストは、ブラウザが最初の引数に渡す呼び出し元のオリジンがこれと完全に一致する場合だけ中継する（2 つ目の防御）。一致しない起動は使い方の誤りとして、標準出力に何も書かずに終了する。
  - **送り先を拡張に選ばせない。** ホストが受理するのは新しい形のメッセージだけである。すべてのメッセージを新しい形として厳格に検査し、操作 `op` の値（`start`・`status`）を、決めたメソッドとパス（`POST /jobs`・`GET /jobs/{key}`）に対応づける。1 つの厳格な JSON オブジェクトとして読めないメッセージ、最上位に版のメンバ `v` を持たないメッセージ、そのほかの規則に合わないメッセージは、サーバにリクエストを送らずに `protocol_error` を返す。中身を直して送ることはしない。拡張がパスやメソッドを指定する手段はない。
  - **標準出力が通信路である。** ホストの標準出力はブラウザへの Native Messaging の通信路であり、書くのは応答のフレーム 1 つだけである。ログは標準エラー出力だけに書き、固定のイベント名・段階・ホストのエラー・状態コード・errno の固定の説明・経過時間・リクエストの長さ・導出したソケットのパス（`HOME` を含む。秘密ではない）・設定の読み込みの失敗（値を含まない `VarError`）・メッセージの読み込みと形の検査の段階（`read`・`form`）と属性（`op`・`rule`）だけを記録する。本文・サーバの応答の本文・環境変数の値そのものは書かない。標準出力を参照するのは、`main` だけを置いた `cmd/yt2column-nmhost/main.go` の配線だけである（`internal/pipeline/relay_guard_test.go` が確かめる）。
  - **秘密を読まない。** ホストが読む環境変数は `HOME` だけで、`.envrc` も API キーも読まない。HTTP のクライアントは環境変数のプロキシの設定を使わない。子プロセスを起動しない（`os/exec` を depguard が禁止する）。
  - **上限。** ホストのリクエストの上限は 32 MiB で、超える長さと長さ 0 では接続も本文の読み取りもしない。サーバの応答の本文は 512 KiB までを中継し、超えれば途中までを転送せず `protocol_error` を返す（サーバの状態の取得の応答は 256 KiB 以下なので、切り詰められない）。接続の後、送る前にメッセージの全体を読み、中継の全体を 20 秒で打ち切る。標準入力がその時間までに終わらなければ `server_timeout` を返し、リクエストを送らない（接続を先にするので、接続できない場合は標準入力を読まない）。接続は 1 回だけで、再送しない。
  - **manifest の install/uninstall。** `yt2column-nmhost install <browser>` は、ブラウザのユーザーデータのディレクトリがなければ何も作らずに拒否し、実行ファイルが相対パスか一時ディレクトリの下にあれば拒否する。manifest は同じディレクトリの `0600` の一時ファイルに書いてから `rename` で置く。自分が書いた manifest でないファイルは、上書きも削除もしない。
- **残余のリスク（許容する）。**
  - 同一ユーザーは、サーバの稼働中でもソケットのパスを `unlink` して自分のソケットを同じパスに bind でき、以後の字幕を受け取れる。起動のロックは、ロックを取らない相手を止めない（`flock` は助言的なロックである）。
  - サーバの停止中に、同一ユーザーがソケットのパスを先に bind して、字幕を受け取れる（以前の TCP のサーバの残余リスクと同じ種類で、他ユーザーにはできなくなった）。
  - ソケットのディレクトリの祖先（`HOME`・`Library/Application Support`・`.local/state`）は検査しない。他ユーザーがこれらに書き込めないことを前提とする（macOS の既定）。
  - macOS の拡張 ACL（アクセス制御リスト）は、モードのビットと独立に他ユーザーに検索や追加を許しうる。継承される ACE が祖先にある場合や、`chmod +a` で `run` に付けた場合、`Lstat` のモードは `0700` のままで検査を通る。標準ライブラリでは ACL を読めないので、ソケットのディレクトリとその親に他ユーザーを許す ACE がないことは、確かめていない前提である。Linux では、モード `0700` のとき POSIX ACL のマスクが `---` になるので、この問題はない。
  - macOS では、待ち行列が満杯の稼働中の待ち受けへの接続も `ECONNREFUSED` になりうるので、ロックを取らずに同じパスで待ち受ける同一ユーザーのプロセスを、stale と見なして削除することがある。同一ユーザーの信頼の範囲に含める。
  - サーバがシャットダウンを始めた瞬間に待ち行列にあった接続は、処理されずに切られる。
  - 同じ入力の再送では、その記事が処理中か完了している間は生成をやり直さない（生成の開始は同じキーを返す）。失敗したキーは再送で生成し直す。サーバの再起動の後、または記録が件数の上限で捨てられた後に、同じ入力から生成し直すと、前に生成した記事と同じ内容の記事がもう一度できる。
  - 同一ユーザーは、ホストのバイナリと manifest を置き換えられ、置き換えたホストは拡張の送る字幕を受け取れる。install の判定から `rename` までの間に同一ユーザーが置いたファイルは上書きされ、uninstall の判定から削除までの間に置き換えたファイルは削除される。拡張は同じ `key` を使えば誰でも同じ ID を名乗れるので、`allowed_origins` は同じ ID の拡張を読み込める同一ユーザーを排除しない。どれも同一ユーザーの信頼の範囲に含める。
  - サーバは設定ファイルの ACL（macOS の拡張 ACL と Linux の POSIX ACL）を検査せず、`config init` も作ったファイルの ACL を変えない。macOS では、モードが `0600` でも、ACL が他ユーザーに読む権利を与えていれば、サーバはそのファイルを受け付け、他ユーザーが秘密情報を読める。README で、`ls -le` での確かめ方と `chmod -N` での取り除き方を示す。Linux では、モードがちょうど `0600` なら ACL のマスクが空になるので、名前を付けたユーザーやグループの項目は権利を与えない。
  - 設定ファイルは平文で、同一ユーザーのプロセスは読める。CLI のための `.envrc` と同じ水準であり、同一ユーザーの信頼の範囲に含める。
  - 利用者が、本番のサーバの代わりに開発用のサーバ（`cmd/yt2column-devserver`）を起動すると、拡張は fake の記事を表示する。記事のタイトルの印・起動の行・料金の不明で気づけるが、取り違え自体は防がない。`go install ./...` で開発用のバイナリが `GOPATH/bin` に入ることも、防がない。同一ユーザーの信頼の範囲に含める。
  - 利用者 1 人の macOS を前提に、これらは受け入れる。
