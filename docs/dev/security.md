# セキュリティ考慮事項

yt2column の設計・実装・レビューで確認するセキュリティ上の観点をまとめる。`mkarch` / `weakreview` などのコマンドは、機能が `.claude/commands/_context.md` の "Conditional-guide trigger" に該当するとき本書を参照する。

yt2column はローカルで実行する。主経路では、利用者がブラウザ拡張からコピーした字幕（と動画の URL・メタ情報）を与え、CLI では動画 URL を与える。字幕・動画タイトル・概要欄・LLM の応答・外部サーバーのレスポンスは**信頼できない入力**として扱う。

## 1. 外部コマンド（yt-dlp）の起動

- `exec.CommandContext` に引数を配列で渡す。シェル（`sh -c`）を経由しない。
- 子プロセスへ渡す環境変数は allowlist に限定し、設定されている変数のみを渡す（例: `PATH`・`HOME`・`TMPDIR`・`XDG_CONFIG_HOME`・`XDG_CACHE_HOME`・proxy 関連・locale・`SSL_CERT_FILE` / `SSL_CERT_DIR`）。`exec.Cmd.Env` を nil のままにせず、API キーなどの秘密情報を子プロセスへ引き継がない。ブロックリスト（既知の秘密情報だけを除く）ではなく allowlist にして、秘密情報を追加したときに漏れないようにする。
- URL は引数として渡す前に検証する。YouTube の動画 URL 形式から動画 ID を取り出し、yt-dlp には正規化した URL を渡す。`-` で始まる値がオプションとして解釈されないよう、URL の直前に `--` を置く。
- 出力先のディレクトリは `-P`（`--paths`）の値として渡し、`-o` の出力テンプレートは動画 ID のフィールド（`%(id)s`）に基づく固定の文字列とする。yt-dlp は `-o` の値をテンプレートとして展開するため、`%` を含むキャッシュディレクトリのパスなど、呼び出し元が与えたパスを `-o` に含めない。動画 ID は `[A-Za-z0-9_-]{11}` に一致することを確認し、パス区切りや `..` を含む値を拒否する。
- `context` によるタイムアウトを設定する。
- yt-dlp の標準エラー出力をエラーメッセージに含める場合は長さを制限する。

## 2. 秘密情報（API キー）

- `DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` などの API キーは、CLI では環境変数からのみ読み込む。リポジトリ内のファイルに書かない（`.envrc` / `.env` は `.gitignore` 済み）。
- ブラウザ拡張は、Anthropic の API キーとワークスペース ID を、利用者がオプションページで入力した値として、ブラウザのプロファイルの `chrome.storage.local` に保存して使う（§8）。読むのは記事を生成するビューアだけで、保存した値を画面に再び示さない。
- テストでは、本番の API キー（`DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` に設定するもの）を使わない。ただし、実 API を呼ぶ統合テストに限り、本番とは別に用意した**テスト用の API キー**を使う例外を設ける（`docs/tasks/0003_deepseek_llm_client/02_architecture.md` §5.2）。テスト用の API キーは、DeepSeek API・Anthropic API・OpenAI API に実際に通る有効なキーであり、使えば料金が発生する。
  - ユニットテストは、本番のキーもテスト用の API キーも使わない。偽の値だけを使う。どのテストも API キーをコードやテストデータに書かない。
  - テスト用の API キーは、テスト専用の環境変数 `YT2COLUMN_TEST_DEEPSEEK_API_KEY` からだけ読む。統合テストは、本番の `DEEPSEEK_API_KEY` を、設定されていても読まない。テスト用の API キーには、本番と別のキー（利用上限を設けたものなど）を割り当てる。
  - Claude の統合テストも同じ方針で、テスト専用の `YT2COLUMN_TEST_ANTHROPIC_API_KEY` からだけ API キーを読み、本番の `ANTHROPIC_API_KEY` は設定されていても読まない。ワークスペース ID もテスト専用の `YT2COLUMN_TEST_ANTHROPIC_WORKSPACE_ID` からだけ読み、本番の `ANTHROPIC_WORKSPACE_ID` は読まない。テスト用の API キーには、利用上限を設けたワークスペースのものを割り当てる。
  - OpenAI の統合テストも同じ方針で、テスト専用の `YT2COLUMN_TEST_OPENAI_API_KEY` からだけ API キーを読み、本番の `OPENAI_API_KEY` は設定されていても読まない。テスト用の API キーには、本番と別の、利用上限を設けたプロジェクトのキーを割り当てる。
  - テスト用の API キーを使うのは、`//go:build integration` の次の 4 つの統合テストだけである。どれも、対応する make のターゲットだけがエクスポートするオプトインの変数の値がちょうど `1` でなければスキップする。各ターゲットは自分のオプトインだけをエクスポートし、他のオプトインはエクスポートしない。テスト用の API キーが `.envrc` などで常にエクスポートされていても、`go test -tags integration ./...` や IDE からの実行で料金が発生しない。

    | 統合テスト | make のターゲット | オプトインの変数 | テスト用の API キーがない場合 |
    |---|---|---|---|
    | `internal/llm/deepseek/integration_test.go`（DeepSeek のアダプタ） | `make test-integration-deepseek` | `YT2COLUMN_DEEPSEEK_INTEGRATION=1` | スキップする |
    | `internal/llm/claude/integration_test.go`（Claude のアダプタ） | `make test-integration-claude` | `YT2COLUMN_CLAUDE_INTEGRATION=1` | スキップする |
    | `internal/llm/openai/integration_test.go`（OpenAI のアダプタ） | `make test-integration-openai` | `YT2COLUMN_OPENAI_INTEGRATION=1` | スキップする |
    | `cmd/yt2column/integration_test.go`（CLI の組み立てで testdata の字幕からファイル出力まで） | `make test-integration-cli` | `YT2COLUMN_CLI_INTEGRATION=1` | 失敗する（本番の `DEEPSEEK_API_KEY` だけがある場合も、それを代わりに使わない） |

  - 実行するかどうかの判定とテスト用の API キーの読み込みは、DeepSeek の 2 つのテストが `internal/llm/deepseek/testutil` の `SettingsFrom` で、Claude のテストが `internal/llm/claude/testutil` の `SettingsFrom` で、OpenAI のテストが `internal/llm/openai/testutil` の `SettingsFrom` で行う。
  - CLI は API キーを `DEEPSEEK_API_KEY` という名前で受け取るので、CLI の統合テストは、読み込んだテスト用の API キーを、テストが組み立てて CLI に与える環境の中で `DEEPSEEK_API_KEY` という名前で渡す。プロセスの環境変数は変えない。名前は本番と同じだが、値はテスト用の API キーである。
  - テストの出力（ログ・失敗メッセージ・スキップの理由）に API キーもその一部も書かない。
- `GODEBUG` に `http2debug=1` または `http2debug=2` を含めると、Go の HTTP/2 の Transport は送信するリクエストヘッダーを値ごと標準エラー出力に記録する。`Authorization`・`x-api-key` などの API キーのヘッダーもそのまま出力される。この設定で通信を調査するときは、無効な API キー（本番のキーでもテスト用のキーでもないもの）を使う。`GODEBUG` はプロセスの開始時に一度だけ読まれ、実行中に取り除いても効かないため、統合テストは、API を呼ぶものも、送信の前にこの設定を検出して失敗する。
- 本番の CLI は `GODEBUG` の `http2debug` を拒否せずに読み込み、利用者が明示的に指定したものとしてデバッグを優先する。その代わり、LLM API を呼ぶ前に、`http2debug` により API キーが標準エラー出力に書かれうることを警告する（F-001・F-007・F-008）。警告はこの 1 つだけである。

## 3. ネットワーク通信

- HTTP クライアントにはタイムアウトを設定する（`http.DefaultClient` をそのまま使わない）。
- **レスポンスサイズの上限**: 外部サーバーのレスポンスを読むときは `io.LimitReader` などで上限を設ける。上限なしの `io.ReadAll` / `json.Decoder.Decode` は指摘対象とする。
- リトライする場合は回数または経過時間の上限を設ける。
- **応答から取り出すものを限定する**: `200` 以外の応答からは、エラーの識別子（`id`・`request_id`）だけを取り出し、`message` などの自由文は読まない・表示しない。
- **リダイレクトに従わない**: LLM の API へのリクエストは、リダイレクトに従わない。ネイティブのビルドでは `internal/llm/llmhttp` の `CheckRedirect` が拒否し、拡張の記事生成モジュール（`js` のビルド）では `fetch` にリダイレクトを通信の失敗として扱わせる。拡張では、さらに CSP の `connect-src` が、`https://api.anthropic.com` のほかへの送信を、リダイレクトの先を含めて止める（§8）。TLS のもとでリダイレクトを返しうるのは、送り先の側の予期しない応答と将来のコードの誤りに限られ、防げる範囲は狭い。費用の小さいうちは保ち、保つ手間が大きくなれば外すことを検討する多層の防御として位置づける。
- **モデル ID は要求本文にだけ入れる**: モデル ID（`YT2COLUMN_LLM`・`YT2COLUMN_REVIEW_LLM` の最初の `/` より後ろ。そこに `+` があれば `+` より前）は、`/` を含んだまま、要求本文（JSON）の値としてだけ送り、要求の URL には入れない。今の 3 つのアダプタは、モデルを要求本文の `model` の値としてだけ送る。URL のパスにモデルを入れる API のプロバイダを加えるときは、モデル ID の中の `/` や `..` がパスを変えないようにする。

## 4. LLM プロバイダへ送るデータ

- DeepSeek の API への入力は中国で処理・保存され、プライバシーポリシー上はデフォルトでモデルの学習に使われる（オプトアウトあり）。運用開始前にオプトアウトの設定を確認する。
- Anthropic の Messages API へ送る入力と出力は、商用製品の既定では Anthropic のモデルの学習に使われない（利用者がフィードバックを明示的に送った場合や、利用者が許可した場合を除く）。Anthropic API の入力と出力は、受け取りまたは生成から 30 日以内にバックエンドから自動的に削除される。利用者側で保持期間を延ばす機能を使う場合、別途合意した場合（ゼロデータ保持など）、利用ポリシー違反の調査、法令上の保持は例外である。出典: Anthropic Privacy Center [「Is my data used for model training?」](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)・[「How long do you store my organization's data?」](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)（2026-10-12 確認）。
- OpenAI の Responses API（`POST https://api.openai.com/v1/responses`）へ送るデータは、ほかのプロバイダと同じである（この節の最後の 2 項目）。アダプタは要求に `store: false` を常に付け、変える設定はない。出典: OpenAI [Data controls in the OpenAI platform](https://developers.openai.com/api/docs/guides/your-data)・[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)（2026-11-11 確認）。
  - API へ送った入力と出力は、既定では OpenAI のモデルの学習・改善に使われない（利用者が明示的にオプトインした場合を除く）。
  - `store: false` は、応答を後から API で取り出すための保存（既定や `store: true` では 30 日）を止めるだけである。下のプロンプトキャッシュの状態は止めない。不正利用の監視ログは `store` の値にかかわらず既定で作られ、通常は最大 30 日保持されうる（法令上の必要や、サービス・第三者を害から守るために長く保持する場合を除く）。監視ログから内容を除くのは、承認を受けた利用者の Modified Abuse Monitoring やゼロデータ保持であり、`store: false` はそれに当たらない。本ツールの要求をゼロデータ保持と説明しない。
  - プロンプトキャッシュは、`store` とは別に、暗号化したキーと値のテンソル（KV テンソル）をアプリケーションの状態として保持しうる。要求が指定する 30 分（`prompt_cache_options.ttl`）は最低保持期間であり、OpenAI はそれより長く保持しうる。30 分後の削除は保証されない。公式の文書は、プロンプトキャッシュの保持の上限を 24 時間としている。
  - これらは設計時（2026-11-10）と実装時（2026-11-11）に確認した公式の文書の記述であり、外部の仕様は変わりうる。設計の判断は [ADR-0041](adr/0041-openai-api.md) にある。
- 字数の調整の工程は生成した文面（タイトルと本文）も LLM に送る。検証・推敲の工程は、生成した文面に加えて素材（字幕・概要欄・動画タイトル・チャンネル名）も送る。検証・推敲のプロバイダを生成と別にする（`YT2COLUMN_REVIEW_LLM`）と、送り先の事業者が増える。
- LLM に送るのは、生成では公開動画の字幕・メタ情報、字数の調整では生成した文面、検証・推敲では生成した文面と素材、そしていずれの工程でもプロンプトテンプレートだけにする。API キー、ローカルのファイルパス、利用者の個人情報をプロンプトに含めない。

## 5. キャッシュディレクトリ

- ディレクトリは `0o700`、ファイルは `0o600` で作成する。
- キャッシュの読み込み時も、ファイル名を動画 ID から組み立てる（ディレクトリ内の任意のファイル名を信用しない）。
- ディレクトリを列挙する必要がある場合（dangling なエントリの掃除など）は、自分の命名規則に完全に一致し、動画 ID の検証を通った名前だけを扱う。操作するパスは検証済みの動画 ID から組み立て直し、シンボリックリンクを辿らない。
- 中間生成物（`--artifacts` の成果物）も `0o600` で作り、キャッシュの外の利用者が指定したディレクトリに置く（CLI はディレクトリを作らない）。名前は検証済みの動画 ID と固定の工程名から組み立てる。読み書きは `os.Root` のハンドルを基準に行い、読み込みでは `Lstat` で通常のファイルに限ることを確かめ、開いた記述子が同じファイルであること（`os.SameFile`）と大きさの上限を確かめてから読む。シンボリックリンク（ルート内を指す相対のものを含む）と FIFO は拒否し、`--artifacts` がキャッシュディレクトリの中にある場合は拒否する。

## 6. 信頼できないテキストの取り扱い

- 字幕・タイトル・概要欄はプロンプトに埋め込まれる。プロンプトインジェクションによって生成記事の内容が操作されうることを前提とし、生成結果を他のコマンドやコードとして実行しない。
- **出典リンクは、LLM の出力ではなくコードで付ける。** URL は検証済みの動画 ID から組み立て、生成したテキストの URL は使わない。出典リンクは、生成に成功した記事の本文の一部である。記事の出力は、`--out` のファイルへの保存と、ビューアでの表示・コピーの 2 つで、どれもこの本文から作るので、どの出力にも出典リンクが付く。
- LLM の空応答・途中打ち切り（`finish_reason` が `stop` 以外）はエラーとして扱い、不完全な記事を `done` にしない。
- 推論モデルの推論過程（DeepSeek の `reasoning_content`）は記事に含めない。
- **表示とコピーで、記事によるメンションの通知を抑止する。** 拡張の記事生成モジュールは、完成した記事の結果の `markdown` に、表示用の Markdown の対象の `@` を無効化した文字列を入れ、ビューアはそれをそのまま描画し、コピーする。表示した記事の全体を選択してブラウザでコピーしたときも、同じ位置で無効化した文字が貼り付けられる（Markdown の記号は描画で除かれる）（F-002・F-003、[ADR-0043](adr/0043-copy-mention-neutralization.md)）。
  - **対象の `@`:** `@` のうち、先頭にあるもの、または直前が文字でも数字でもないものである。`＠` などの見た目の似た文字と、`@` を表しうる文字参照（`@` を表す数値の文字参照と、すべての名前付きの文字参照）を含む。直後の文字は問わない（`@**channel**`・`@ `・末尾の `@` も対象になる）。語の途中の `@`（`Tech@Work`、`user@example.com`）は対象の `@` ではない。
  - **無効化:** 対象の `@` の直後（文字参照が表す `@` では、その `;` の直後）に U+200B を 1 つ入れることである。`@` そのものと、記事のほかの文字は変えない。入れるのは 1 つの `@` の単位に 1 つだけである。
  - **変えない `@`:** URL のパスの `/@`（Mattermost が自動リンクにしてメンションとして扱わない形）は変えない。条件は、`@` が文字参照でなく直前が `/`、`@` より前の同じ行に小文字の `http://` か `https://` があり、その直前が行頭か空白か ASCII でない文字か `(`（またはそれらの後ろの `<`）、ホストが文字・数字・`.`・`-` だけで先頭が文字か数字で直後が `/`、URL の始まりから `@` までに空白・`<`・`>`・`?`・`#`・`` ` `` がなく、表示用の Markdown の URL の始まりより前に `[` がない、の 5 つである。URL の中でも、これらに当たらない `@`（`https://@channel`、`https://example.com/?@here`）は無効化する。
  - **見出し:** ビューアの記事の上の見出し（動画のタイトルとチャンネル名）は、記事が完成した後は、記事生成モジュールが無効化した値を表示する。見出しでは、URL のパスの `/@` も含めてすべての対象の `@` を無効化する。記事が完成する前の見出しと、動画のタイトルがなかったときの見出しのタイトルは、拡張が読んだ値のままで、無効化しない。
  - **コードの中:** コードスパンとフェンス付きコードブロックの中の `@` も無効化する。ビューアは記号を除いて描画するので、選択によるコピーではコードの `@` がコードの外の `@` として貼り付くためである。
  - **変えない出力:** `Article` の値と、`--out` と「.md で保存する」のファイルの中身は変えない。
  - **拒否しない:** コピーは記事の内容によって拒否しない。以前の投稿が拒否した並び（コードの中の対象の `@`、直前が `/` の対象の `@`、`<!`・`<@`、文字参照、`<a|b>` の形）を含む記事もコピーでき、それらの並びは、上の規則で対象の `@` に U+200B を入れるほかは変わらない。URL のパスの `/@` は変えず、ほかの直前が `/` の対象の `@` は無効化する。
  - **通知:** 無効化したかどうかは、無効化の部品が値として返し、記事生成モジュールの結果の `mentionsNeutralized` にする。ビューアは、それが真のときだけ、コピーの通知で無効化したことを示す（数を示さない）。表示した記事を選択してブラウザでコピーしたときは通知を出さない。
  - **置き場所と時間:** 規則は `internal/publisher` の 1 か所にあり、入力の長さに比例する時間で終わる。拡張は、この部品を記事生成モジュール（WASM）の中で使う。ビューアは受け取った文字列を加工しない。
  - **根拠:** この規則は、Mattermost の `master`（コミット `d504067`）と `v11.11.3` のソースの読解と、Mattermost サーバ 11.11.3 の実機の確認に基づく。読解していない版では保証しない。
- **表示とコピーに残るリスク（許容する）。** (1) Slack では確かめていない。(2) `.md` で保存したファイルや `--out` のファイルの中身を貼り付けた場合は無効化されない。(3) `<https://…|表示>` の形は Mattermost でリンクになる（行き先は `about:blank#blocked` で、メンションにはならない）。(4) Mattermost が文字参照とエスケープを解く規則が変わり、こちらの判定が想定しない形で `@` を作ると、その `@` がメンションになりうる。(5) こちらが URL のパスの `/@` と判定するのに Mattermost が自動リンクにしない並びでは、その `@` がメンションになりうる。逆に、Mattermost が自動リンクにする URL のうち、こちらの定義より広い形（ポート付きのホスト、`_` を含むホスト、大文字のスキームなど）では、U+200B が入って URL が壊れる。(6) 表示した記事を選択してコピーしたときは、無効化したことの通知は出ない。(7) 記事の一部を選択するか分けて貼り付けるとき、変えなかった `@` の直前で切ると、その `@` がメンションになりうる。(8) Mattermost は、利用者が設定したキーワードや名前を、`@` がなくても通知する。(9) 記事が完成する前の見出しと、動画のタイトルがなかったときの見出しのタイトルは無効化しない。
- **チャンネル名は、タイトルと同じく外部由来の表示用の文字列として扱う。** 拡張が YouTube のページから読む値（拡張の記事生成モジュール）、または `yt-dlp` が出す値（CLI）で、信頼しない。同じ規則（有効な UTF-8、空白だけでない、制御文字なし、双方向の制御文字 U+202A〜U+202E・U+2066〜U+2069 なし、200 コードポイント以下。空文字は「チャンネル名なし」）を 3 か所で適用する。拡張の入力の入口（`internal/extjob` の `Prepare`。違反は `invalid_body`）、LLM を呼ぶ前（`validateTranscript`）、公開の直前（`CheckPublishable`）である。拒否のエラーは規則の名前だけを示し、値を含めない。表示とコピーの無効化の対象になり、見出しでは URL のパスの `/@` も無効化する。
- **`--out` のファイルのフロントマターの値は、すべて二重引用符の文字列にする。** 値の書き出しは `strconv.Quote` とし、引用符・バックスラッシュ・`:`・`#`・`---` を含む値でもフロントマターの行数とキーの並びは変わらない。値は検査済み（有効な UTF-8、制御文字なし）のものだけを渡し、変換で黙って値を変えない（制御文字の除去などをしない）。`CheckPublishable` が引用符で囲む値（チャンネル名・モデル名・モデルの版・出典 URL）の UTF-8 を検査する。見出しの下のチャンネル名の行は、行頭がブロックの記法になる場合に限り、行頭にバックスラッシュを 1 つ入れる（番号付きリストの記号は数字の後ろ）。行頭の空白は落とす。残るリスクとして、タイトルとモデル名の書式制御文字は拒否せず、チャンネル名の行の途中の記法（`*強調*`・自動リンク・インライン HTML）は描画するビューアで有効になる。拡張のビューアは記事を描画するので（§8.1）、チャンネル名の行の途中の `**…**`・`*…*` は強調に、`` `…` `` はコードになり、リンクの条件を満たす `<https://…>` はリンクになる。インライン HTML は文字のまま表示する。行の途中の ASCII の区切り文字の前の `\` は表示されない。
- **検証・推敲の応答を信頼しない。** 応答は LLM が書いた JSON であり、信頼できない入力として扱う。応答全体の大きさ（1 MiB）と項目の数（256）に上限を設け、正しい UTF-8・対になっていないサロゲート・末尾に続くデータ・未知のキーと重複したキー・値の型・制御文字（タブ以外を拒否し、`before`・`after` は改行 `\n` も拒否、`evidence` の `\n` だけを認める）を検査し、規則に反する応答は補正・部分受理せずに拒否する。直す前と直した後の記述は、記事の中にちょうど 1 回だけ現れ、範囲が重ならず、見出しの構成を変えないことを確かめてから当てはめる。拒否のエラーには応答の値を含めない。
- **LLM の応答の `usage` を信頼しない。** 応答の `usage` もネットワークから受け取る信頼できない入力である。規則に合わない値（要素の不在・重複、値が負でない整数でない：負数・`-0`・小数・指数・`int64` を超える数・文字列・真偽値・`null`・配列・オブジェクト）は受理せず、その呼び出しのトークン数を「不明」とする。`usage` の不正で応答を拒否せず、記事の生成も失敗させない（副次的な情報のために本来の機能を失わない）。不明の理由は壊れた規則と要素の名前（アダプタの定数）だけから作り、応答のテキストと `usage` の値を含めない。トークン数の行は `redact.Line` を通る。ただし Claude の `cache_read_input_tokens`・`cache_creation_input_tokens` の `null` だけは、文書化された値として 0 とする（プロンプトキャッシュを指定していないため）。
- **一覧のファイル（`--review-log`）に入る値**は、記事の値と検証・推敲の応答の値だけから作り、設定の値（API キー）を含めない。検証・推敲の応答から来る値は Markdown の引用ブロックの中に置き、値の中の見出し記号などがファイルの見出しの構造を壊さないようにする。記事のタイトルとモデル名・モデルの版は制御文字と改行を拒否する検査を通り、出典 URL は検証済みの動画 ID から組み立てるので、箇条書きの行も見出しの構造を変えない。公開の直前と同じく、書き出す前に記事の値を `CheckPublishable` で検査する。
- **中間生成物（`--artifacts`）に入る値**は、工程の出力（記事のタイトルと本文、検証・推敲の一覧）と来歴（工程・モデル名とモデルの版・トークン数・呼び出しの時刻・テンプレートの内容のダイジェスト・入力の識別子）だけとし、API キー・上書きテンプレートのローカルのパス・設定の値を含めない。読み込みは信頼できない入力として境界で検査し、未知のキー・重複したキー・末尾の内容・上限（ファイル 4 MiB・文面 1 MiB・一覧 256 項目）の超過・本文の先頭の U+FEFF を拒否し、入力の識別子を生成の出力まで順にたどって照合する。`usage` 要素も検査し、4 つの区分のオブジェクトか不明を表す `null` だけを受理し、宣言していない要素・要素の欠け・重複・負数や範囲外の数は拒否する。トークン数と呼び出しの時刻は来歴の一部として `id` の計算に含め、書き換えたファイルを拒否する。呼び出しの時刻（`call_time`）は `YYYY-MM-DDTHH:MM:SSZ` の 20 バイトの文字列だけを受理し、`time.Parse` の後に同じ書式で書き直した文字列とのバイト単位の一致でほかの書き方を拒否する。ゼロの時刻と UTC でない時刻も拒否する（`TestParseRecordRejectsCallTime`）。ただし `id` は秘密の鍵を使わない識別子なので、トークン数や呼び出しの時刻を書き換えたうえで `id` を計算し直したファイルは検出できない（残余のリスクであり、改ざんの影響は、再利用した工程のトークン数の表示と、料金の行の適用した単価・`at=` の時刻・推定コストを誤らせることに限られる）。壊れた入力は補正も部分受理もしない。拒否のエラーには成果物の値を含めない。

## 7. リポジトリに保存する実データ

テスト用に実際の取得結果（`yt-dlp` の出力、YouTube のページの HTML など）を `testdata/` に保存するときは、次を守る。個々のファイルの出典・加工内容・作り直し方は [testdata/README.md](../../testdata/README.md) に記録する。

- 保存してよいのは、再配布が許諾されたライセンス（CC BY など）の動画から取得したものだけにする。出典とライセンスを `testdata/README.md` に明記する。
- 取得者を特定できる情報は、コミットする前に取り除く。`yt-dlp` の info.json は署名付き URL に取得者の IP アドレスを埋め込むので、該当する値を置き換える。ブラウザで保存したページの HTML は、ログインした状態で保存するとアカウントの情報（アバター、登録チャンネルの一覧、視聴履歴に基づくおすすめなど）を含む。ログインしていない状態で保存し、さらに必要な要素だけを切り出す。
- ページ全体のスナップショットはコミットしない。YouTube 自身のマークアップ・スクリプト、他チャンネルの動画の情報を含み、ログインした状態で保存した場合はアカウントの情報も含むためである。スナップショットは、どの worktree からも参照できるように、リポジトリの外の `${YT2COLUMN_SNAPSHOT_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/yt2column/snapshots}` に置く。`.envrc` は worktree に複製されないので、この環境変数は任意とし、設定しなければ既定のパスを使う。テストはこのディレクトリを参照しない。
- 開発用のコマンド `cmd/yt2column-extjob` の入力のファイル（生成の開始の入力の JSON）は、リポジトリに入れない。利用者がコピーした字幕と、動画のタイトル・チャンネル名・概要欄を含みうるためである。リポジトリの外の一時のディレクトリに置く（使い方は [development.md](guides/development.md)）。

## 8. ブラウザ拡張（#43・#773）

ブラウザ拡張は、利用者が選択した字幕と動画ページの URL、動画ページの DOM から読んだ動画タイトル・チャンネル名・概要欄から、拡張に入れた記事生成モジュール（Go の WebAssembly。`cmd/yt2column-wasm`）で記事を作り、拡張のページに表示する。記事の生成は、ビューアのタブの中の Worker が、利用者がオプションページで保存した Anthropic の API キーで、Anthropic の API を直接呼んで行う。拡張のほかに、サーバもホストも動かさない（[ADR-0048](adr/0048-extension-only-generation.md)）。設計は [0090 設計書](../tasks/0090_extension_only_architecture/02_architecture.md) §5 と [0091 設計書](../tasks/0091_extension_only_migration/02_architecture.md) §5 にある。

- **守る資産。** API キーとワークスペース ID（`chrome.storage.local`。記事の生成の間は、実行するビューアと Worker のメモリ）、利用者の料金（意図しない生成で料金がかかる）、見た動画と作った記事（`chrome.storage.session` とビューアの URL）、コピーした字幕と動画メタデータ（生成の間の Service Worker と実行するビューアのメモリ）。
- **相手ごとの扱い。** 混同しない。
  - 同じ OS ユーザーのプロセス（AI Agent を含む）: 信頼する（排除しない）。プロファイルのディレクトリを読めるので、`chrome.storage.local` の API キーを平文で読める。CLI の `.envrc` と同じ水準として受け入れる（[ADR-0010](adr/0010-extension-stores-nothing.md)）。拡張の側の手段では防げない。
  - 他の OS ユーザーのプロセス: プロファイルのディレクトリの権限（OS の既定）で排除する。拡張は確かめない前提である。
  - ウェブページ（YouTube を含む）: 排除する。拡張のページを開くことも埋め込むこともできず（`web_accessible_resources` を宣言しない）、Service Worker へ送れない（`externally_connectable` を宣言せず、`onMessageExternal` を使わない）。`chrome.storage` に届かない。ページが偽れるのは、拡張が読む選択範囲と DOM の値だけで、それは信頼できない入力として検査する。
  - 注入した関数: 本リポジトリで書いた関数で、隔離された世界で動き、選択範囲と動画メタデータを読んで返すだけである。ポップアップは注入の直前に `chrome.storage.local.setAccessLevel` で注入した文脈から `chrome.storage.local` を読めないようにし、失敗したときは注入しない。注入した関数からの Service Worker へのリクエストは、送り手の URL が拡張のページでないので受け付けない。
  - ほかの拡張: 別のオリジンで、`chrome.storage` と拡張のページに届かず、メッセージも送れない。`tabs` や `history` の権限を持つ拡張は、ビューアの URL とページのタイトルを読める（受け入れる）。
  - プロンプトインジェクションで操作された LLM の出力: 信頼しない。記事は文字として描画し、HTML を解釈せず、スクリプトを動かせない（[ADR-0017](adr/0017-viewer-markdown-rendering.md)）。これが本当の守りである。
  - Anthropic の API: 利用者が自分の API キーで使う送り先として信頼する。データの扱いは §4。
  - 拡張のほかのページ（ポップアップ・ビューア・オプションページ）: 同じオリジンで本リポジトリのコードだけを動かすので信頼する。Service Worker は、ビューアが計算して送る入力のダイジェストと動画 ID をそのまま使う。

### 8.1. ブラウザ拡張（#110）

- **要求する権限**（`docs/tasks/0090_extension_only_architecture` の設計書 3.7.1 の manifest）: `activeTab`（利用者が起動したタブに限り、そのタブの URL・タイトルを読み、スクリプトを注入することを許す）、`scripting`（起動したタブに、選択範囲と動画メタデータを読む関数を注入する）、`storage`（API キーとワークスペース ID を `chrome.storage.local` に、ジョブの記録を `chrome.storage.session` に置く）。閲覧内容全般に及ぶ権限（すべてのサイトへのホストの権限、`tabs`、`history`、`cookies`、`webRequest` など）と、`host_permissions`・`nativeMessaging` の権限は要求しない。`host_permissions` がなくても、事前の確認（CORS の preflight）を 1 往復増やすだけで API を呼べる。
- **CSP。** 拡張のページの CSP（`content_security_policy.extension_pages`）は `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'; connect-src 'self' https://api.anthropic.com; img-src 'self'; media-src 'none'; frame-src 'none'; form-action 'none'` である。`'wasm-unsafe-eval'` は WASM のコンパイルだけを許し、JavaScript の `eval`・`new Function`・インラインのスクリプトは許さない。`connect-src` は、拡張のページと Worker からの送信を、拡張自身のファイルと Anthropic の API のオリジンだけに限り、リダイレクトの先も含めて、ほかの先へ API キーを送らない守りの 2 つ目になる（1 つ目は §3 のリダイレクトの拒否）。画像・メディア・フレーム・フォームの送信による送り出しも閉じる。CSP は、ビューアでスクリプトが動いたときのページの移動・`window.open`・`chrome.tabs.create` による送り出しは止めない（下の残余のリスク）。
- **シークレットモードでは有効にしない。** manifest の `incognito` は `not_allowed` である。シークレットモードの閲覧が、ビューアの URL・ページのタイトル・ジョブの記録として通常のプロファイルに残らないようにする（[#874](https://github.com/isseis/yt2column/issues/874)）。
- **API キーは決まった経路だけを通る。** 経路は、オプションページの入力の欄から `chrome.storage.local` へ、`chrome.storage.local` から実行するビューアのメインスレッドへ、そこから `postMessage` で Worker へ、Worker の中で Go の `secret.Secret` を経て Anthropic の API のリクエストの `x-api-key` のヘッダへ、である。保存の前の確かめでは、オプションページから Worker の `checkSettings` へ渡り、Models API のリクエストの `x-api-key` のヘッダへ渡る。Service Worker とポップアップは API キーの値を読まず、Service Worker は `chrome.storage.local.getKeys()` で項目の名前だけを得て、API キーがあるかを判断する。API キーは、開発者向けのログ、エラーの表示、ビューアの URL、保存するファイル、コピーする文章、LLM に送るプロンプト、`chrome.storage.sync`、`chrome.storage.session`、Service Worker へのメッセージ、`BroadcastChannel`、記事生成モジュールの結果と進み具合に出ない。
- **`chrome.storage` は決まった関数だけで使う。** `chrome.storage` を参照するのは `extension/src/browser/chromeDeps.ts` だけで、2 つの設定の項目（`anthropic.apiKey`・`anthropic.workspaceId`）を名前を固定して読む関数、1 回の `set` で書く関数、1 回の `remove` で消す関数、項目の名前だけを得る関数、アクセスの水準を設定する関数、`chrome.storage.session` を読み書きする関数と、その変更の知らせを受け取る関数だけを公開する。`chrome.storage.local` を全部読む呼び出し（`get()`・`get(null)`）はない。それぞれの関数を import してよいファイル（入口のページのスクリプト）は lint で限る。この規則は、うっかりの使用を止めるもので、別名を通した意図的な回避までは止めない。
- **変更の知らせは `chrome.storage.session.onChanged` だけで受け取る。** `chrome.storage.onChanged` と `chrome.storage.local.onChanged` は、API キーの値を知らせの受け手すべてに渡すので使わない（[ADR-0031](adr/0031-secret-closure.md)）。
- **ほかの端末へ同期しない。** `chrome.storage.sync` を使わない。オプションページの API キーの欄は `<form>` に入れず、`type="text"` に `-webkit-text-security: disc` で文字を伏せ、`autocomplete="off"` と `spellcheck="false"` を付ける。`type="password"` の欄と送信のある `<form>` は、ブラウザがパスワードの保存を勧め、保存した値がアカウントの同期でほかの端末へ渡りうるためである。保存した API キーは画面に再び示さない。
- **料金のかかる生成は、利用者の押下でだけ始まる。** Service Worker は、生成の開始を、送り手が自分の拡張で、タブを持たず、URL がポップアップのページと完全に一致する求めだけから受け付け、API キーの項目がなければ拒否し、ビューアを開かない。入力の受け取り・検査の拒否・予約は開始の文脈のタブのビューアからだけ、進み具合・結果・実行の Port は、ジョブの記録の実行するページ（タブ ID と、ページの読み込みごとの乱数の ID）と一致するページからだけ受け付ける。受け付けないリクエストと Port では、ジョブの記録を変えない。コピーした字幕はビューアが受け取るまで Service Worker のメモリにだけあり、1 回だけ渡す。ビューアの URL の値は生成の入力にしないので、ページを開く、読み込み直す、閉じたタブを復元する、履歴から開くことでは生成は始まらない。失敗した生成と結果の分からない生成は自動では始め直さない（[ADR-0028](adr/0028-no-automatic-resend.md)）。
- **ジョブの記録はメモリにだけ置く。** ジョブの記録と開始の文脈は `chrome.storage.session`（ブラウザのメモリ）に置き、ディスクに書かない。書くのは Service Worker だけである。記録はコピーした字幕と概要欄を持たない。件数（50）、合計の大きさ（8 MiB）、記事 1 本の大きさ（256 KiB）に上限を設ける。ジョブ ID は Service Worker が作る 128 ビットの乱数で、入力から計算できず、入力の中身も表さない。同じ入力の判定は、記事生成モジュールが計算するダイジェストの比較で行い、ダイジェストは記録の中にだけ置く。
- **読み戻す値と、ページの間の値を検査する。** 次の値は信頼できない入力として、受理する形（メンバの閉じた集合、値の型、列挙の値、桁数）に合うものだけを受け入れ、補正しない。ジョブの記録と開始の文脈の読み戻し（合わない記録はないものとして扱う）、ページの間のメッセージ、`BroadcastChannel` のメッセージ、記事生成モジュールの結果と進み具合（Worker からページへ。512 KiB まで）、ビューアの URL（合わなければ記事を表示せず何も始めない）。コピーした字幕と動画メタデータは、記事生成モジュールの `prepare` が、CLI と同じ Go の規則で検査する（4 MiB まで）。
- **LLM の API への送信を守る。** 記事生成モジュールの Claude アダプタの送り先は固定の `https://api.anthropic.com` で、リダイレクトに従わず（§3）、応答の本文を 8 MiB で読むのをやめ、1 回ごとに応答のヘッダが届くまで 15 分の期限を持つ。保存の前の確かめは Models API（`GET /v1/models?limit=1`）を 1 回呼び、状態コードだけを読み、本文を読まない。実行するビューアは記事の生成の全体に 50 分の期限を持ち、過ぎたら Worker を止める。
- **記事を untrusted テキストとして描画する。** 記事は LLM の出力で、字幕とメタデータへのプロンプトインジェクションで操作されうる。ビューアは、表示用の Markdown を、タスク 0063 の要件（`docs/tasks/0063_viewer_markdown/01_requirements.md` §3.2）が定める少ない規則だけで解釈し（ADR-0017）、見出し・段落・リスト・強調・コード・リンクに描画する。HTML は解釈しない。解釈の関数（`parseArticleMarkdown`）が記事の木を作り、組み立ての関数（`buildArticleBody`）は記事の木の種類だけで要素を選んで、要素の生成と文字のノードだけで DOM を作る。作る要素と属性は固定の一覧に限り、記事の内容から値を決める属性は、リンク先と番号付きリストの開始番号だけである。リンクにするのは `https` の自動リンク（`<https://…>`）のうち、URL として解釈でき、ホストを持ち、ユーザー名とパスワードを持たず、直列化と 1 文字も違わないものだけで、表示する文字列とリンク先は同じ URL の文字列である。リンクは新しいタブで、参照元を送らず、開いたページに `window.opener` を与えない形（`rel="noopener noreferrer"`）で開き、周りの文字の方向から分離して左から右に表示する。`[文字](URL)` の形のリンク、HTML のタグ、文字参照は、文字のまま表示する。HTML を解釈する API は lint で禁止し、リンク先の型 `LinkUrl` を作れるファイルも lint で解釈の関数のファイルに限る。ビューアは API キーを読むページと同じオリジンなので、記事からスクリプトが動けば、`chrome.storage.local` の API キーに届く。保存とコピーは描画の結果を使わず、記事生成モジュールが返す文字列を変えずに使う。元の動画へのリンクは、収集と同じ検査を通った動画ページの URL だけを、参照元を送らない形で表示する。
- **ビューアの URL とページのタイトル。** ビューアの URL は、開始の ID（予約の前）かジョブ ID（予約の後）、集めた動画の URL、ページのタイトル（動画のタイトルを 64 コードポイントまでに切ったもの）を持ち、既存の記事のビューアは既存の記事を表示していることを示す値（`e=1`）も持つ。コピーした字幕と概要欄は持たない。ページのタイトルは動画のタイトルで、ブラウザの履歴とタブに出る。これらはブラウザの履歴に残る。`history.replaceState` で URL を書き換える前と後の URL が、それぞれ履歴の項目になりうる。ブラウザの同期で履歴がほかの端末に渡りうるし、`tabs` や `history` の権限を持つほかの拡張はこれらを読める。これらは受け入れる。動画の URL とタイトルは、動画のページを開いた時点ですでに履歴に残る値である。ID は乱数で、記事の中身を表さない。細工した URL のビューアは、利用者を誤解させる見出しとタイトルを表示しうる（README に書く）。
- **権限を広げずに、ビューアを開き、保存し、コピーする。** ビューアのタブは `chrome.tabs` の権限の要らない操作（作成・選択・削除・取得）で開き、`chrome.windows.update` で前面に出す。同じ記事のビューアは `BroadcastChannel` で探す。このチャンネルは拡張自身のオリジンの文脈の間でだけ届き、ウェブページや注入したスクリプトは送れない。記事の保存は拡張のページからの Blob のダウンロードで、コピーは利用者の操作の中のクリップボードへの書き込みで行う。`tabs`・`downloads`・`clipboardWrite` の権限を要求しない。拡張のページは `web_accessible_resources` に含めないので、ウェブページはビューアを開くことも埋め込むこともできない。
- **開発者向けのログに値を出さない。** Service Worker・ポップアップ・ビューア・オプションページのログは、固定のラベル、結果と検査の種類、数だけを書き、字幕・記事・動画メタデータの値・API キー・ジョブ ID・URL の値を書かない。
- **利用者が起動するまでページを読まない。** `content_scripts` を宣言せず、ページの読み込み時に自動で実行されるコードを持たない。起動で読むのは起動したタブだけである（`activeTab`）。選択範囲はページの DOM の構造に依存せず、ブラウザの選択の API（`window.getSelection()`）で取得する。
- **動画メタデータは DOM から読むだけで、ページを操作しない。** 動画タイトル・チャンネル名・概要欄は、収集が成功したときだけ、起動したタブの動画ページの DOM から読む。新しい権限を加えず、既存の `scripting` の注入で DOM を読むだけで、クリック・フォーカス・入力などページを操作するコードを持たない（概要欄の「…もっと見る」も開かない）。読む時点のページの URL が収集した URL と一致しない場合は、別の動画の値を混ぜないよう 3 つの値をすべて省略する。DOM の構造は YouTube が独自に定義したもので変わりうるため、取得に失敗しても起動を失敗させず、拒否の理由にもしない（値を省略して記事を生成する）。開発者向けのログにはフィールドの名前・省略の理由・失敗した検査の種類・折りたたみの状態だけを残し、読み取った値は残さない。
- **動画メタデータと選択範囲を untrusted テキストとして扱う。** 読み取った結果は信頼できない入力であり、受理する形（決めたメンバと値の型）に合うものだけを受け入れる。値は HTML として解釈せず `textContent` だけで表示し、双方向の制御文字で表示順が変わらないよう `dir="auto"` と `unicode-bidi: plaintext` で分離する。`eval`・`new Function` と HTML を解釈する API は lint で禁止する。
- **成果物は本リポジトリのコードと Go のツールチェーンのファイルだけ。** 拡張の成果物（`extension/dist/`）は、`tsc` の出力、`static/` の写し、`cmd/yt2column-wasm` からビルドした記事生成モジュール、`go.mod` が定める版の Go のツールチェーンと中身が一致する `wasm_exec.js` だけを持ち、実行時にネットワークからコードを取得しない。ビルドの最後の検査が確かめる（[ADR-0026](adr/0026-extension-platform.md)）。拡張の実行時に読み込む npm の依存パッケージはない。インストールは `npm ci --ignore-scripts` で行い、依存パッケージのインストール時のスクリプト（`postinstall` など）を実行しない。
- **開発用のビルドを公開する成果物に入れない。** fake の LLM（`internal/llm/devfake`・`internal/extjob/devbackend`）を使う開発用の記事生成モジュール（`cmd/yt2column-wasm-dev`）は、`make ext-build-dev` が `extension/dist-dev/` に作る開発用のビルドにだけ入る。`yt2column` と、`GOOS=js GOARCH=wasm` の `cmd/yt2column-wasm` の推移的な依存に fake を含めないことを、`go list -deps` のテストが確かめる（[ADR-0045](adr/0045-dev-fake-llm.md)）。開発用のビルドの manifest は `key` を持たないので拡張の ID が別になり、`chrome.storage.local` も別になる。開発用のビルドは、拡張の名前と画面の文字の印で見分けられる。開発用のコマンド `cmd/yt2column-extjob` の入力のファイルは、リポジトリに入れない（§7）。
- **秘密鍵をリポジトリに含めない。** 拡張 ID の固定には manifest の `key`（公開鍵）だけを使い、生成した RSA の秘密鍵は生成直後に削除する。固定した拡張 ID は `clfmbbcdpnjcefbdihdoahomaifbabkk`。拡張 ID は秘密ではなく、`key` は公開情報なので誰でも同じ ID の拡張を読み込んで名乗れる。ID は `chrome.storage.local` の持ち主なので、ID が変わると保存した API キーは引き継がれない。
- **古い版が保存した値を読まない。** 0020 の版が `chrome.storage.local` に保存した共有トークンとポート（`sharedToken`・`serverPort`）は、拡張を更新しても残りうる。拡張はこれを読まず、消しもしない。通用する相手はない。
- **残余のリスク（許容する）。**
  - 同じ OS ユーザーのプロセスは、`chrome.storage.local` の API キーを読める。README で、月ごとの利用の上限を設けた専用のワークスペースで API キーを作ることを勧める。
  - ビューアでスクリプトが動いたときの、ページの移動・`window.open`・`chrome.tabs.create` による値の送り出しは、CSP では止められない。ビューアでスクリプトを動かさないこと（ADR-0017）に頼る。
  - 記事が `https` の自動リンクで任意のサイトを指すことは防がない。利用者が押せば、そのサイトが開く。リンクの表示は URL そのもので、プロンプトは本文に URL を書かせないので、出典の行のほかの自動リンクはプロンプトインジェクションの疑いが強い。リンク先には `https://localhost/`・LAN のアドレスも入りうる。押すと、そのアドレスへ GET のリクエストが 1 回送られる。チャンネル名の行の途中の記法は、本文と同じに描画される（§6）。同じ行の右から左への上書き（U+202E など）で、リンクの隣に見える文字が変わりうる。利用者が、リンクにならなかった記事の中の URL の文字列をコピーして開くことは防げない。
  - `tabs` や `history` の権限を持つほかの拡張と、ブラウザの同期は、ビューアの URL と、履歴のページのタイトル（動画のタイトル）を読める。
  - 利用者の組織がゼロデータ保持（ZDR）か Compliance API を有効にしていると、ブラウザからの API の呼び出しが受け付けられず、拡張を使えない。
  - API キーが記事の生成の工程の間に失効すると、後の工程が失敗する。作り直すと最初の工程からやり直すので、済んだ工程の料金が二重にかかる。
  - 応答の本文の途中で止まった呼び出しは、1 回ごとの期限（15 分）では終わらず、全体の期限（50 分）まで続く。背面のタブでは期限のタイマーも遅れうる。利用者はビューアを閉じて止められる。
  - 実行するビューアのタブを、利用者がそのページを一度も操作していないうちに閉じるか読み込み直すと、ブラウザは確かめずに記事の生成を止める。止まった生成の料金は不明と示す。
  - ブラウザの終了、拡張の再読み込みと更新で、ジョブの記録と完成した記事はすべて失われる。

### 8.2. 所有者だけが読めるファイル（`internal/privatefile`）

`internal/privatefile` は、所有者だけが読めるファイルの検査付きの読み込みと作成を持ち、`internal/chief` が自分の状態のファイルに使う。次を守る。

- **検査してから、検査した記述子から読む。** `O_NOFOLLOW`・`O_NONBLOCK` で開いた記述子の `fstat` で、通常のファイルであること・所有者が実効ユーザーであること・モードがちょうど `0600`（setuid・setgid・sticky のビットもなし）であることを確かめ、同じ記述子から読む。パスの `Lstat` は拒否にだけ使う。検査の後にパスのファイルを入れ替えられても、検査していないファイルの中身は使わない。シンボリックリンク・通常のファイルでないもの（FIFO は書き手を待たない）・他人の所有のファイル・モードの違うファイルは、何も直さずに拒否する。読む大きさに上限を設け、超えるファイルは全体を読まずに拒否する。
- **作るファイルは `0600` で、上書きしない。** ファイルは同じディレクトリの一時ファイルに書いて `link` で置き、モードは umask によらず `0600` で、既存のものは上書きしない。親のディレクトリを作るときは、umask によらず `0700` で作り、既存の親は変えない。
- **残余のリスク（許容する）。** ACL（macOS の拡張 ACL と Linux の POSIX ACL）は検査しない。macOS では、モードが `0600` でも、ACL が他ユーザーに読む権利を与えていれば、そのファイルを受け付ける。Linux では、モードがちょうど `0600` なら ACL のマスクが空になるので、名前を付けたユーザーやグループの項目は権利を与えない。ファイルは平文で、同じ OS ユーザーのプロセスは読める。
