# chief 利用ガイド

chief は、Herdr の workspace で並行して進むタスクを見渡し、人の判断を待つものを選択式で示し、マージの後の次のコマンドを自動で送る開発用の道具である。人が示した issue からタスク用の worktree と workspace を作り、終わったタスクの workspace を人の確認を得て消すこともできる。Go の道具 `chief`（`cmd/chief`・`internal/chief`）と、それを呼ぶコマンド `/chief`（`.claude/commands/chief.md`）からなる。判定と送信はすべて道具が行い、`/chief` のセッションは道具の出力を人に示し、人の選んだものを道具の引数で渡すだけである（[ADR-0046](../adr/0046-chief-of-staff.md)、[ADR-0014](../adr/0014-deterministic-checks-in-go.md)）。要件と設計は [0088 要件定義書](../../tasks/0088_chief_of_staff/01_requirements.md) と [0088 設計書](../../tasks/0088_chief_of_staff/02_architecture.md) に、作成と削除の要件と設計は [0092 要件定義書](../../tasks/0092_chief_task_workspace/01_requirements.md) と [0092 設計書](../../tasks/0092_chief_task_workspace/02_architecture.md) にある。

## 1. 前提条件

| 項目 | 条件 |
|---|---|
| Herdr | 0.9.1 で確かめた。`/chief` は Herdr の pane の中の Claude Code で動かす。Herdr の外では何も読まずに止まる |
| エージェント | Claude Code 2.1.322 と OpenCode v2.2.6 の画面で確かめた。版が上がって画面の形が変わると、その workspace は「要確認」になり、何も送らない。Claude Code の transcript の報告の形は、2.1.325 と 2.1.326 の transcript から採った報告のサンプル（`internal/chief/testdata/README.md` の「報告の transcript」に挙げたもの）で確かめた。Claude Code の版が上がったら、transcript のサンプルを採り直す |
| gh | 2.96.0 で確かめた。`gh auth login` を済ませておく |
| bash | `make test` には PATH の最初の `bash` が 4 以上であることが要る（CLAUDE.md の「Development Notes」） |
| workspace の作り | タスクごとに git の worktree を作り、それを Herdr の workspace で開く。chief に作らせる（3.3）ことも、手で作ることもできる。chief が作るのは、`~/.herdr/worktrees/yt2column/issue-<N>` に `origin/main` から detached で作った worktree と、それを開いた名前 `issue-<N>` の workspace で、タブ `cmd`（シェル）・`opencode`・`claude` に pane を 1 つずつ置く。手で作るときもこの形にしてよいが、chief が削除を提案するのは chief が作った workspace だけである（3.4）。送り先の pane は、workspace の中に送り先の種類のエージェント（Claude Code か OpenCode）の pane がちょうど 1 つあるときだけ選ばれる |
| chief の workspace | `/chief` を動かす workspace は、タスクの workspace と別にする。chief は自分の workspace へは送らない |

## 2. インストール

```bash
make install-chief
```

`go install ./cmd/chief` を実行する。道具は `main` から入れ、道具を変えた PR がマージされたら、`main` を更新してから入れ直す（ADR-0014 の「道具は `main` からインストールして使う」）。インストール済みのバイナリが作られたコミットは、`go version -m "$(command -v chief)"` の `vcs.revision` で確かめられる。

`/chief` の定義と道具は `--protocol` の番号で版を照合する。今の番号は次の表のとおりである。

| 項目 | 値 |
|---|---|
| プロトコル番号 | `5` |

番号が合わないと、道具は何もせずに `protocol_mismatch` で拒む。番号を上げる PR では、その PR の `/runpr` の前に、その PR のブランチで入れ直す。

**入れ直す順。** 動いている `/chief` を止めてから `make install-chief` を実行し、`/chief` を起動し直す。番号を上げた道具を `/chief` を止めずに入れると、動いている `/chief` は古い定義の番号のまま次のラウンドを走らせ、新しい道具に `protocol_mismatch` で拒まれる。定義はこのとき `make install-chief` での入れ直しを促して止まるが、道具はすでに新しいので、入れ直しても直らない。手当ては、`/chief` を起動し直して新しい定義を読ませることである。

**workspace の作成と削除を足した版（タスク 0092）への入れ替え。** サブコマンドと道具の出力の形が変わったので、道具と `/chief` の定義を同じコミットからそろえる。

1.  動いている `/chief` を止める。古い定義のまま走っている `/chief` は、新しい道具に `protocol_mismatch` で拒まれて止まる。
2.  chief の workspace の `.claude/commands/chief.md` を新しい版にし（`main` を更新する）、`make install-chief` を実行する。
3.  `/chief` を起動し直す。

**古い版に戻すとき。** 道具と `/chief` の定義を、同じコミットから入れる。新しい道具が書いた送信の記録は `kind`・`arg` の欄を持ち、古い道具は知らない欄を持つ記録を読まない。戻す前に、新しい道具の `chief start` を実行して、終わりの記録のない送信を送信の停止に変える（7 章の「片付け」）。停止した workspace があれば、その pane で送信が何をしたかを確かめてから停止を解く。そのうえで、最後の送信から 25 分たってから `chief start` をもう一度実行して終わった送信の記録を片付けさせるか、状態のディレクトリの workspace ごとの送信の記録（`send-*.json`）を消す。終わりの記録のない送信を停止に変える前に記録を消すと、送れたかが分からない送信が分からなくなる（5.1 の「送れたかが分からない送信は送り直さない」）。

番号を変えずに道具と定義が変わることもある（たとえばサブコマンドや出力の欄が増える）。道具を入れ直したら、動いている `/chief` のセッションを終えて、`/chief` を起動し直す。古いセッションは、読み込んだときの定義のまま動き続けるためである。

`.claude/settings.json` は `Bash(chief *)` を許すので、待ち受けの間に許可を尋ねない。道具は `chief` の語で始まり、ほかのコマンドと連ねない形でだけ呼ぶ（`/chief` の定義の「Calling the tool」）。ただし、削除の `chief remove` は `ask` の規則 `Bash(chief remove *)` に当たるので、呼ぶたびに Claude Code が許可を尋ねる（6 章）。

## 3. 使い方

chief の workspace の Claude Code の pane で、次のどちらかを実行する。

| 呼び方 | 振る舞い |
|---|---|
| `/chief` | 状況の表と、人の判断を待つものの番号つきの一覧を示し、待ち受けを続ける。待ち受けの間は、マージの後の次のコマンドを自動で送る。人はいつでも、一覧の番号か workspace の名前を打って選ぶ。番号は、セッションの中で項目ごとに変わらない |
| `/chief` に引数 `once` | 状況の表を 1 回示し、選択式の問いで尋ね、答えに応じて動いて止まる。自動送信はしない |

chief は同時に 1 つだけ動く。別のセッションで動いている chief があれば、2 つ目は表を示さずに止まる。前のセッションが終わっていれば（`/clear` を含む）、新しいセッションがロックを引き継ぐ。

### 3.1 状況の表の見方

表は道具が組み、`/chief` のセッションは道具の出力の `table` を code block にそのまま貼る。急ぎの度合い・作業項目の表示・状態の詳細・行の並び、列の幅、折り返しと切り方は、すべて道具が決める。表は上から次の順に並ぶ。

1.  凡例 `🛑 すぐ  🔶 あとで  🟢 待つ`。印は、急ぎの度合いを色に加えて形（八角形・菱形・円）でも示す。
2.  空行。
3.  見出し（状態・名前・タスク・PR・内容）と、`─` を並べた区切り線。
4.  workspace ごとの 2 行。workspace の間に空行を 1 つ置く。行が 1 つもなければ、`workspace なし` を置く。

列は罫線で区切らず、空白でそろえる。全角の文字と絵文字は 2 桁と数える。

| 列 | 1 行目 | 2 行目 |
|---|---|---|
| 状態 | 急ぎの度合いの印と、状態の文字列（下の表） | 空 |
| 名前 | workspace の名前。20 桁を超えれば、末尾を `…` にして 20 桁以内に切る | 空 |
| タスク | ブランチのタスク番号。タスクがなければ `-` | 作業項目の文字列（要件・設計・計画・PR-N・なし・要確認・-） |
| PR | ブランチで開いている PR の番号（`#980` の形）。なければ `-` | 空 |
| 内容 | 内容の文字列の 1 行目 | 内容の文字列の 2 行目 |

状態の文字列は状態の詳細から決まり、内容の文字列は状態の文字列ごとに次の部品を空白 1 つで区切って並べたものである。値のない部品は並べない。

| 状態の詳細 | 状態の文字列 | 内容 |
|---|---|---|
| 要確認 | 要確認 | 読めなかったもの（2 つ以上あれば `, ` で結ぶ） |
| 作成待ち | 次を提案 | 提案するコマンドと、括弧に入れたモデル。送れない提案なら、送れない理由 |
| 作成中・`/runpr` 実行中・実行中 | 作業中 | 実行中のコマンド。後に人が何か打っていれば `＋指示`、モデルが決まれば括弧に入れたモデルを添える。コマンドが決まらなければ、決まらない理由（下の「作業中の行のコマンド」） |
| マージの確認待ち | マージ確認 | 質問のタブの表示と質問の文 |
| 質問で停止 | 質問で停止 | 質問のタブの表示と質問の文。示す質問がマージの確認なら、頭に `マージ確認` を置く |
| レビュー待ち | レビュー待ち | PR の題名 |
| タスク完了 | タスク完了 | chief が作った workspace の削除を提案している行（3.4）なら `削除を提案`、そうでなければなし |

**示す質問とタブの表示。** 1 つの行に示す質問は 1 つで、マージの確認があれば道具の順で最初のマージの確認、なければ最初の質問である。質問が 2 つ以上あれば、頭に `<件数> 件` を置く（例: `2 件 マージ確認 [claude] …`）。タブの表示は、質問の pane があるタブのラベルを `[claude]` のように示す。タブの番号は示さない。Herdr の画面にはタブの番号が出ず、Herdr のタブの一覧の番号は画面の並びと対応しないためである。タブを引けないとき（Herdr のタブの一覧か、pane とタブの対応を読めない、pane のタブが一覧にない、ラベルが空）は、pane の ID を `[w3:p1]` のように示す。

**幅。** 使える幅は、chief の pane の幅（Herdr の pane の配置の `rect.width`）から余白を引いた値である。余白は、chief のタブを分割していなければ 2 桁（Claude Code が code block の左に取る分）、分割していれば 4 桁（Herdr が分割した pane に描く枠の 2 桁を加えた分。左右に分割した pane で確かめた）である。pane の配置を読めなければ、pane の幅を 80 桁とみなし、分割していないものとする。状態・名前・タスク・PR の列は、見出しと値（タスクの列は 2 行目の作業項目の文字列を含む）のうち最も広いものに合わせ、列の間に空白 2 つを置く。内容の列は、使える幅の残り（最小 20 桁）を取る。幅はラウンドごとに読む。

**内容の流し込み。** 内容の文字列は、内容の列の幅で折り返して 2 行に流し込み、収まらなければ 2 行目の末尾を `…` にして切る。英数字の語（`/runpr`・`feat(chief):`・`#980` など）は、1 行に収まる限り途中で折り返さない。日本語の文は文字の境目で折り返す。値の中の改行とタブは、表の中でだけ空白にする。制御文字は、ほかの出力と同じく `\x1b` のような見える形で示し、その途中では折り返しも切りもしない。全文は道具の出力の `rows` にある。

送信の停止と引き継ぎは、表に収まらないので、表の下に workspace の名前を添えて示す。番（次に動くのが人か AI か）は道具の出力にあるが、表には示さない。状態から分かるためである。

**急ぎの度合いと番。** 次の表を上から当て、最初に当たる行で決まる（[0093 要件定義書](../../tasks/0093_chief_status_sheet/01_requirements.md) の 3.1）。

| 行 | 急ぎ | 番 |
|---|---|---|
| 送信が止まった行（停止の記録を読めない行を含む） | すぐ | 人 |
| 質問で停止（マージの確認を含む） | すぐ | 人 |
| 使っていないか残った worktree の行 | 待つ | なし |
| レビュー待ち、次を提案、要確認 | あとで | 人 |
| 実行中（表では作業中） | 待つ | AI |
| タスク完了 | 待つ | なし |

「要確認」は、chief が画面を読めないだけのことが多いので「あとで」に置く。

**タスクの進行。** タスクは、決まった順の作業項目を 1 つずつ進む。通常の進め方では、要件定義書の作成 → アーキテクチャ設計書の作成 → 実装計画書の作成 → 計画書の PR-1 → PR-2 → … と進む。簡易な進め方では、3 つの文書を 1 つの作業項目で作り、その後に計画書の PR が続く。PR マーカーのない計画書の PR は PR-1 である。

**作業項目の表示。** 今の作業項目（まだ終わっていない最初の作業項目）か、作業項目でない値で、`origin/main` のタスクの文書から決まる。今の作業項目は、要件定義書・設計書・計画書（表の作業項目の文字列では要件・設計・計画）・PR-N（計画書の PR のうち、まだマージされていない最初のもの）のどれかである。作業項目でない値は 3 つある。-（タスクのないブランチ）、なし（すべての作業項目が終わった）、要確認（今の作業項目を決められない。fetch や文書の読み取りに失敗した、HEAD が detached など）である。簡易な進め方のタスクは、3 つの文書の PR がマージされるまで「要件定義書」と示される。`origin/main` の文書からは、マージの前に進め方が分からないためである。

**状態の詳細。** 行の状態を、実行中のコマンドやマージの確認かどうかで細かくしたもので、作業項目のない行にも示す。値は、行の状態と実行中のコマンドから、作成待ち・作成中・`/runpr` 実行中・実行中・マージの確認待ち・質問で停止・レビュー待ち・タスク完了・要確認のどれかになる。表での示し方は上の表のとおりである。

**行の並び。** すぐ → あとで → 待つ の順で、同じ急ぎの度合いの中は状態の順（質問で停止 → レビュー待ち → 次を提案 → 要確認 → 実行中 → タスク完了）に並ぶ。ここでの状態は行の状態の名前で、表の状態の文字列ではない（実行中の行は、表では作業中と示す）。使っていないか残った worktree の行は、いつも最後に並ぶ。人の判断を待つものの一覧の順は、急ぎの度合いに左右されない。

**作業中の行のコマンド。** 行の状態が実行中の行（表では「作業中」）の内容の列に示すコマンドは、Claude Code の pane ではセッションの記録（transcript）で人が最後に打ったタスクのコマンドから、OpenCode の pane では chief がその pane へ最後に送ったコマンドから決まる。chief が送ったコマンドも人が打ったコマンドも、Claude Code の pane では同じく示される。示すのは `/mkreq`・`/mkarch`・`/mkplan`・`/runplan`・`/runpr` と、決まった形の番号の引数だけである。Claude Code の pane で、そのコマンドの後に人が何か打っていれば（自由な文での指示、ほかのコマンドなど）、`＋指示` を添える。後に打ったものの中身は示さない。モデルは、走っているエージェントが 1 つで、chief が最後に送ったのと同じコマンドで、その後に人が何も打っていないときだけ示す。コマンドが決まらないときは、内容の列にその理由を短く示す（出力の `running_unknown`）。

| 理由 | 表の示し方 | 意味 |
|---|---|---|
| `no_session` | セッション不明 | Herdr がその pane のセッションを返さない |
| `unsupported_path` | 記録の場所が不明 | worktree のパスの文字から transcript の場所を求められない（8 章） |
| `unreadable` | 記録を読めない | transcript か送信の記録を読めない |
| `over_cap` | 記録が大きすぎる | transcript が読む量の上限を超える |
| `partial_line` | 記録の書き込み中 | transcript の最後の行が書きかけのまま |
| `not_task_command` | 読めるタスクのコマンドなし | 人がそのセッションで、読める形のタスクのコマンドを打っていない（引数なしで打ったものは読めない。8 章） |
| `no_sent_command` | 送ったコマンドの記録なし（OpenCode） | OpenCode の pane で、chief が送って送れたと記録したコマンドがない。人が打ったコマンドのほか、最後の送信がリセットか送れなかったもの、記録が片付けられた後の長いコマンドなどがある（8 章） |
| `panes_disagree` | pane ごとに異なる | 動いている pane が 2 つ以上あり、同じコマンドを示さない |

**調べ方。** `chief snapshot` の出力には、表に示さない値がある。番は `turn` で、使っていないか残った worktree の行は `idle` が `true` である。作業項目の表示は `position.document`（PR-N の N は `position.plan_pr`）に、状態の詳細は `position.progress` に入る。表の材料（chief の pane の幅、pane とタブの対応、タブのラベル）を Herdr から読めなかったときと、質問の pane をタブのラベルで示せなかったときは、`table_unreadable` に、読めなかったものとその理由が英語で示される。表が 80 桁で組まれた理由や、タブの表示に pane の ID が出た理由は、ここで調べる。`/chief` はこれを示さない。

### 3.2 人の判断を待つもの

人の判断を待つものは、エージェントを止めている質問、`/runpr` のマージの確認、レビュー待ちの PR、そのほかの提案、削除の提案（3.4）の順に、同じ種類の中では待っている時間の長い順に示される。一覧の最後、「何もしない」の前には、いつも「新しいタスクを始める」（3.3）が示される。道具の番号を持たないので、待ち受けの間は固定の英字 `[N]` を付けて示し、`N 930` のように英字か名前の後に issue 番号を付けて打って選ぶ（3.3）。報告が読めずに見送ったリセット（8 章の「報告が読めずに見送ったリセット」）は、そのほかの提案と同じ順位に並ぶ。待ち受けの間は、選択式の問いを開かずに一覧を示す。問いを開いている間はセッションが答えを待ち、待ち受けのラウンドが走らないためである。`once` の問いで示せるのは 3 つと「何もしない」で、示せなかったもの（「新しいタスクを始める」を含む）は問いの文に名前で挙がる。その名前を自由記述の答えに書けば選べる。選んだ後の問い（中継する選択肢、`/runpr` を送るか、issue の番号など）は、待ち受けの間も選択式で尋ねる。

### 3.3 新しいタスクを始める

待ち受けの間は、一覧への答えとして `N 930` か `新しいタスクを始める 930` のように打つ（`N` か名前だけを打つと、その形で打つよう示される）。`once` では、「新しいタスクを始める」を選ぶと、選択式の問いの自由記述で issue 番号を尋ねられる。番号の形（10 進の数字だけで、`#`・符号・先頭の 0 を付けない）が違えば、そのことを示して何もしない。形が合えば、chief は GitHub で issue を読み、存在しない番号、閉じた issue、ラベル `draft` が付いた issue（下書きの issue）、PR の番号を拒む。通れば、issue の番号と題名を示してから、始める先を、新しい workspace を作る・`/mkreq` を提案しているタスクのない既存の各 workspace・何もしない から選ぶ。題名で番号の打ち間違いに気づいたら、「何もしない」を選ぶ。

-   **既存の workspace を選んだとき。** その workspace の Claude Code の pane に `/mkreq <N>` を送る。issue は、始める先を尋ねる前に確かめてある。
-   **新しい workspace を作るとき。** chief は、作る直前に GitHub で issue をもう一度読み、同じ理由で拒む。次に、`origin/main` を fetch し、作る場所のパスにファイル・ディレクトリ・リンク・worktree の登録・そのパスを開いた workspace のどれかがあれば拒む。通れば、worktree・作ったことの記録・workspace・3 つのタブを作り、OpenCode と Claude Code を起動して、Claude Code の pane に `/mkreq <N>` を送る。結果には、issue の題名、作ったもの、`/mkreq` を送れたかが示される。
-   **作る途中で止まったとき。** 止まった段と理由、それまでに作ったものが示される。chief は作ったものを消さず、`/mkreq` も送らない。示されたものを人が端末で片付けるか、そのままタスクに使う。
-   **`/mkreq` を送れなかったとき。** 何も打たずに送らなかったとき（`not_sent`）は、起動した Claude Code がフォルダの信頼などを尋ねていればその pane で答え、どの場合も、その pane で `/mkreq <N>` を打つ。何かを打った後に確かめが外れたとき（`sent_then_failed`）は、その workspace への送信が止まる。`/mkreq` を打ち直さず、まず pane を見る。作った直後の worktree は detached なので、chief はその workspace に `/mkreq` を後から提案しない。

作成には数分かかることがある（道具の上限は 7 分）。`/chief` は、自分が背景で始めた送信がすべて終わってから作成を始め、作成の間は待ち受けのラウンドを走らせず、自動送信もしない。

### 3.4 終わったタスクの workspace を消す

chief が作った workspace のうち、作ったときの issue を `対応 issue` とするタスクが `origin/main` にちょうど 1 つあり、すべての PR がマージされたものは、一覧に削除の提案として並ぶ。HEAD が detached で、どのエージェントも実行中でも質問で止まってもいなければ、表の行も「タスク完了」・「削除を提案」と示される。そうでなければ、行はふだんの規則のままで、提案の確かめの結果に通らないものが示される。提案には、workspace の名前、worktree のパス、issue とタスクの番号、pane の数、その時点の確かめの結果が示される。

提案を選ぶと、chief は、消す workspace の名前、worktree のパス、workspace のすべての pane が閉じられることを示して、消すかを尋ねる。消すと答えると、Claude Code も道具の呼び出しの許可を尋ねる（6 章の `ask` の規則）。両方に答えると、道具は `origin/main` を fetch し、5.1 の確かめをすべて行い直し、通ったときだけ workspace を閉じて worktree を消す。通らなかったときは何も消さず、通らなかった確かめを示す。消す途中で止まったときは、止まった段と理由と残ったものを示し、消し直さない。残ったものは人が片付ける。

## 4. サブコマンドと終了コード

どのサブコマンドも `--protocol N` を必須とし、標準出力に 1 つの JSON を書く。サブコマンドの細部は [0088 設計書](../../tasks/0088_chief_of_staff/02_architecture.md) の 3.1.1 と、[0092 設計書](../../tasks/0092_chief_task_workspace/02_architecture.md) の 3.1 にある。

| サブコマンド | 何をするか |
|---|---|
| `start` | ロックを取り、状態のディレクトリを確かめ、古い記録を片付け、終わり方の分からない送信を送信の停止に変える |
| `snapshot` | 状況を読み、状況の表、人の判断を待つもの、新しい通知を返す。送らない |
| `tick` | `snapshot` に加えて、PR が開いているのを見た記録を作り、自動送信の条件を満たすものを送る |
| `wait` | 前のラウンドの基準から、タスクの workspace のエージェントの状態が変わるまで待つ（既定は 10 分で時間切れ） |
| `send` | 人の選んだコマンドを送る。`/runpr` の後は、PR を作ったコマンドの pane を空にする |
| `relay` | 人の選んだ答えを、質問で止まっているエージェントへ中継する |
| `reset` | 人の選んだ、見送ったリセットの項目を、確かめ直してから送る（`/clear` か `/new`） |
| `detail` | workspace の開いている PR の詳細を集め、控える |
| `release` | 人の選択で、workspace の送信の停止を解く |
| `targets` | issue 番号の形を確かめ、issue を読んで題名か拒否を返し、通れば `/mkreq` を提案しているタスクのない workspace を返す。何も作らない |
| `create` | issue を確かめ、worktree と workspace を作ってエージェントを起動し、`/mkreq` を送る（3.3） |
| `remove` | 削除の確かめを行い直し、通れば workspace を閉じて worktree を消す（3.4） |

| 終了コード | 意味 |
|---|---|
| `0` | 処理を終えた。送らなかった判断、作らなかった判断（issue 番号の形の違いを含む）、消さなかった判断、作成と削除が途中で止まったことも含み、出力が理由を持つ |
| `1` | 道具の失敗（読めない入力、記録を作れない、外部のコマンドの失敗、`wait` の時間切れ） |
| `2` | 使い方の誤り |
| `3` | 何もせずに拒んだ（Herdr の外、ほかの chief がロックを持つ、`start` していない、`--protocol` が合わない、状態のディレクトリの土台がない、`HERDR_PANE_ID` がほかの worktree の pane を指す） |

## 5. 保証すること・しないこと

### 5.1 保証すること

-   **送る入力は決まった範囲だけである。** 道具が pane へ送るのは、要件定義書 F-006 の表のコマンド（`/clear`・`/model`・`/new` と、タスクのコマンド）、中継の選択肢の番号、リセットの `/clear`・`/new` だけで、どれも型から組み立てる。文字列の入力は受け取らない。
-   **人が選ぶまで送らない。** 自動送信のほかは、人が `/chief` の問いで選んだものだけを送る。中継は、送る直前に、人に示した質問と選択肢がまだ画面にあることを照合値で確かめる。見送ったリセットの項目も、人が選んだときだけ送り、送る直前に、示したときと同じ pane・セッション・状態の変化の番号であることを照合値で確かめる。
-   **自動送信の引き金は画面ではない。** GitHub の PR の状態（`MERGED`）と git の状態で確かめ、画面と transcript からの判断は送ることを止めるか条件を狭める向きにだけ働く。マージした PR 1 件につき 1 回までで、chief を起動し直しても 2 回送らない。
-   **分からないものは送らない。** 画面、Herdr の出力、計画書の欄、送り先の表、記録のどれかが決まった形に合わなければ、「要確認」か「送らない」にし、理由を示す。例外が 2 つある。Claude Code の transcript の値や種類の名前（応答の終わりを示す値など）だけが変わったときと、pane のセッションの transcript のファイルがないときは、その pane に報告がないものとし、自動送信の前の NEXT の照合を通る（8 章）。
-   **送れたかが分からない送信は送り直さない。** その workspace への送信を、人が `release` で解くまで止める。
-   **ネットワークの操作は読み取りだけである。** 待ち受けの中では `git fetch origin main`・`git ls-remote`・`gh pr list`・`gh pr view`・`gh pr checks` だけを呼ぶ。新しいタスクを始めるときは、そのほかに `gh api graphql` で issue の番号・状態・題名・ラベルを読む（`targets` と `create` で 1 回ずつ）。push、マージ、コメント、issue を書き換える操作はしない。
-   **作るものは issue 番号だけから決まる。** パスと workspace の名前は issue 番号だけから決め、issue の題名などの中身では何も選ばない。題名は無害化して 200 文字までにして示すだけである。worktree は `git worktree add --detach` で作り、ブランチを作らない。エージェントは、人の代わりに許可や信頼を与える引数を付けずに起動する。同じパスに何かがあれば作らず、上書きしない。
-   **消すのは、chief が作り、確かめを通った workspace だけである。** 削除の候補は、作ったことの記録があり、その記録のパスが記録の issue 番号から作ったパスと等しく、そのタスクが `origin/main` で完了した workspace に限る。消す直前に、次のすべてを確かめ直す。HEAD が detached である。追跡していないファイルを含めて変更がない。HEAD が `origin/main` から届く。worktree の登録が固定されていない。どのエージェントも実行中でも質問で止まってもいない。エージェントでない pane の前面のプロセスがその pane のシェル自身である。ほかの workspace がそのパスに pane を持たない。読めないものがあれば消さない。workspace を閉じる直前と worktree を消す直前にも読み直す。worktree は `--force` なしの `git worktree remove` で消し、変更があれば git が拒む。ブランチ、ほかの worktree、worktree の外のファイルは消さない。
-   **作成と削除と自動送信は重ならない。** `create` は状態のディレクトリの作成の排他を持って動き、`tick` は自動送信の間その排他を持つ。取れないラウンドは自動送信をせず、そのことを示して、条件のそろった PR を次のラウンドへ持ち越す。

### 5.2 保証しないこと

-   **同じ利用者のほかのプロセスからの守り。** 同じ利用者のプロセス（ほかの worktree のエージェントを含む）は、`chief` も `herdr` も直接呼べ、状態のディレクトリも `origin/main` の参照も書ける。chief の守りは、chief のセッションが信頼できない文字列に従っても決まった範囲の外の入力を送らないことにあり、悪意のあるプロセスを防ぐことにはない（設計書 5.2 の残る危険）。
-   **settings.json の拒否の規則の外の書き方。** 拒否は前方一致の規則なので、パスで書いた呼び出しや、`git -C <ディレクトリ> worktree add` のようにサブコマンドの前に git の引数を書いた呼び出しなどは拒めない（6 章）。
-   **人の確認が行われたこと。** 削除の前に人に尋ねるのは `/chief` のセッションで、道具はそれが行われたかを確かめられない。`ask` の規則が、呼ぶたびに Claude Code の許可の確認を出すことで、これを補う。
-   **偽った作ったことの記録。** 記録は同じ利用者のプロセスが書ける。偽った記録が名指せるのは `issue-<N>` の形のパスの worktree だけで、消すには人の確認と 5.1 の確かめが要る。
-   **workspace を閉じて失われるもの。** シェルの背景のジョブと止めたジョブ、Claude Code の背景の実行は確かめられず、workspace を閉じると終わる。git が無視するファイル（ビルドの成果物など）は worktree とともに消える。
-   **人が選ぶ送信の次のコマンドの鮮度。** 人が選んで送るコマンドは、ローカルの `origin/main` の文書から決まる。マージの直後は、次の fetch まで 1 つ前の作業項目のコマンドを示しうる。表で確かめてから選ぶ。

## 6. `.claude/settings.json` の拒否

chief のセッションが道具を通さずに入力を送らず、タスクの作業を壊さないよう、リポジトリの `.claude/settings.json` は次の herdr と git の呼び出しを拒む（ADR-0046）。この拒否は、リポジトリで動くすべての Claude Code のセッションに効く。道具は子のプロセスとして `herdr` を呼ぶので、影響を受けない。

| 種類 | 拒む呼び出し |
|---|---|
| pane へ入力を送るか、pane でコマンドを走らせるか、pane の入力の経路を変える | `herdr agent prompt`・`herdr agent send-keys`・`herdr agent start`・`herdr agent attach`・`herdr pane send-text`・`herdr pane send-keys`・`herdr pane run`・`herdr pane input` |
| エージェントの状態とセッションを Herdr に報告する | `herdr pane report-agent`・`herdr pane report-agent-session`・`herdr pane release-agent` |
| pane・タブ・workspace・セッション・worktree を閉じるか消す、エージェントの連携を変える、Herdr を止めるか入れ替える | `herdr pane close`・`herdr tab close`・`herdr workspace close`・`herdr session stop`・`herdr session delete`・`herdr worktree remove`・`herdr integration install`・`herdr integration uninstall`・`herdr server stop`・`herdr update` |
| サブコマンドの前に、別のセッションか別の機械を指す引数を書く | `herdr --session`・`herdr --machine`・`herdr --remote` で始まるもの |
| workspace・タブ・pane・worktree を作るか、pane を動かす | `herdr workspace create`・`herdr tab create`・`herdr pane split`・`herdr pane move`・`herdr worktree create`・`herdr worktree open` |
| git の worktree を足す、消す、動かす | `git worktree add`・`git worktree remove`・`git worktree move` |

読み取りの呼び出し（`list`・`get`・`read`、`git worktree list` など）は拒まない。`herdr workspace rename`・`herdr tab rename` も拒まない。chief は workspace を名前でなくパスで確かめるためである。表に挙げた拒否の対象の操作は、Claude Code に頼むと拒まれるので、人が端末で直接行う。画面のサンプルを採り直すときのキー入力も、人が行う。

あわせて、`ask` に `Bash(chief remove *)` を置く。Claude Code の許可の規則は `deny`・`ask`・`allow` の順に強く、`allow` の `Bash(chief *)` より先に効くので、削除の呼び出しのたびに許可の確認が出る。auto mode のセッションでも出ることを確かめた（[0092 計画書](../../tasks/0092_chief_task_workspace/03_implementation_plan.md) の「PR-1 の実行の記録」）。

## 7. 状態のディレクトリ

記録とロックは、リポジトリの外の `$XDG_STATE_HOME/yt2column/chief/`（`XDG_STATE_HOME` が絶対パスでなければ `$HOME/.local/state/yt2column/chief/`）に置く。`start` の出力の `state_dir` が、解決したパスである。ファイルは利用者だけが読み書きでき、同じ名前の記録がすでにあれば作らない。

| 記録 | 置き場所 | 何のためか |
|---|---|---|
| ロック | `lock.json` | chief を 1 つに限る |
| 通知の記録 | `notice-*.json` | 同じものを 2 回通知しない。待っている時間による並べ方。セッションの中の項目の番号（人が番号で答えた項目を見分ける） |
| ラウンドの記録・PR が開いているのを見た記録 | `round-*.json`・`observe-*.json` | 自動送信の条件（chief の待ち受けの中でマージを見たこと） |
| 自動送信の記録 | `autosend-<PR 番号>.json` | マージした PR 1 件につき 1 回に限る |
| 作成の排他 | 下のディレクトリ `create` | 作成と、`tick` の自動送信を重ねない |
| workspace ごとの記録 | worktree の正規のパスの SHA-256 の 16 進を名前にした下のディレクトリ | 送信の記録（`send-*.json`）、PR の詳細の控え（`detail-*.json`）、報告の控え（`report-*.json`。PR の詳細の控えを作った後に書かれた、PR を作ったコマンドの報告を、人が PR の詳細を見直したときに控える）、送信の停止（`stop.json`）、見送りの記録（`skip-*.json`。報告が読めずに見送ったリセットを、後のラウンドで人に示すためのもの）、作ったことの記録（`created.json`。chief が作った worktree のパスと issue 番号。削除の候補を名指すことにだけ読む） |

-   **送信の停止を解く。** `/chief` の問いで `停止を解く: <workspace の名前>` と答えるか、ほかの方法がないときだけ、その workspace のディレクトリの `stop.json` を人が消す。停止の記録を読めない workspace（表に、停止の記録を読めないと示される）には `停止を解く` は示されないので、`stop.json` の中身と pane を人が確かめてから消す。停止の理由と、そのときの画面は、状況の表に示される。消す前に、止まった送信がその pane で何をしたかを確かめる。
-   **見送りの記録。** ラウンドは見送りの記録を読むだけで、作りも消しもしない。記録が消えるのは、人が選んだリセットを送る直前、chief がその pane へコマンドかリセットを打てたとき、`start` の片付けのときである。決まった形に合わない記録は項目にならず、ラウンドの `problems` にパスと理由が示される。その記録は、人が手で消してよい。
-   **片付け。** `start` が、終わったセッションのラウンド・観測・通知の記録、始めと終わりの両方を書いた古い送信の記録、14 日より古い PR の詳細の控えと報告の控えと見送りの記録（読めない見送りの記録は、ファイルの更新が 14 日より古いもの）を消す。終わりの記録のない送信の記録は消さず、送信の停止に変える。自動送信の記録は消さない（消すと、同じマージで 2 回送りうる）。
-   **作るときと消すときの記録。** `create` は、作る前に、同じパスの workspace ごとの記録（前の使い方の送信の停止など）をすべて消してから、作ったことの記録を書く。`remove` は、worktree を消し終えた後に、その workspace ごとの記録をすべて消す。作ったことの記録は最後に消す。
-   **すべてを消す。** chief が動いていないときに、ディレクトリごと消してよい。消した後は、chief を起動する前のマージを自動では送らず、提案として示す。作ったことの記録も消えるので、chief が作った workspace は削除の提案に出なくなる。

## 8. 既知の制限

-   **Claude Code の `/model` は既定のモデルも書き換える。** chief が Claude Code の pane で `/model` を送ると、そのセッションのモデルに加えて、利用者の Claude Code の既定のモデル（新しいセッションに使うもの）も書き換わる。既定のモデルは、chief が最後に送ったモデルになる。既定を書き換えない切り替えの方法がないので、受け入れている（設計書 1.3）。
-   **OpenCode のモデルは切り替えない。** OpenCode の pane のモデルが送り先の表と違うときは、chief は送らずにそのことを示す。人がその pane でモデルを切り替え、chief の問いで送り直すかを選ぶ。
-   **worktree のパスの文字。** Claude Code の pane へ送るときは、モデルが切り替わったことを Claude Code の transcript で確かめる。worktree のパスが英数字・`/`・`.`・`-` 以外の文字（たとえば `_`）を含むと transcript の場所を求められないので、その pane には何も送らない（`unsupported_path`）。そのとき、その pane の報告も読めないので、その workspace の自動送信も止まる（送り先が OpenCode の pane でも止まる）。その文字だけのパスの worktree を使うか、その pane でコマンドを打つ。
-   **コミットの数の上限。** gh は 1 つの PR のコミットを 100 件までしか返さない。PR の詳細は、100 件のときに「100 件以上」と示す。全体の数は GitHub の PR のページ（`gh pr view <番号> --web`）で確かめる。
-   **選んだ後の問いが開いている間は待ち受けが止まる。** 中継する選択肢や `/runpr` を送るかの問いに答えるまで、次のラウンドは走らない。そのため、その問いを開いたまま離れると、その間のマージの次のコマンドは自動では送られず、提案として示される。離れるときは問いに答えてから離れる。
-   **`HERDR_PANE_ID` を引き継いだセッション。** chief は、自分の pane を環境変数 `HERDR_PANE_ID` で知り、その pane の workspace を表から除く。Claude Code のプロセスがほかの pane の `HERDR_PANE_ID` を引き継いで動いていると（PR-7 の実地の確かめで、Herdr を起動し直した後に起きた）、chief は自分の workspace を取り違える。そのため道具は、`HERDR_PANE_ID` の pane のエージェントが、道具を呼んだプロセスと同じ worktree で動いていることを確かめ、違えば何もせずに拒む（`pane_mismatch`）。同じ worktree のほかの pane を指す取り違えは、この確かめでは見分けられず、そのとき状況の表はその pane の幅で組まれうる。拒まれたら、その Claude Code を終了し、pane のシェルで `herdr agent get "$HERDR_PANE_ID"` を実行して、出力の `cwd` が chief の worktree で、`workspace_id` が chief の workspace であることを確かめる。違えば、そのシェルも古い値を持っているので、Herdr で新しい pane を開き、そこから `claude` を起動する。取り違えた chief のロックが残ったときは、ほかに chief が動いていないことを確かめてから、状態のディレクトリの `lock.json` だけを消す。
-   **transcript の場所の規則が変わったとき。** chief は、Claude Code の pane へ送る前に transcript の場所を求められることだけを確かめ、ファイルは `/model` の後に読む。Claude Code が transcript の置き場所を変えると、chief は `/clear` と `/model` を送った後で確かめられずに止まり、その workspace の送信を止める。そのとき pane はすでに空にされている。また、chief は transcript のファイルがない pane を報告がないものとするので、自動送信の前の NEXT の照合はその pane で止まらずに通り、PR の詳細は PR の説明を示し、PR を作った pane は自動では空にされない。chief と Claude Code の設定のディレクトリ（`CLAUDE_CONFIG_DIR`）が違うときも、同じくファイルがないものとして読まれる。そのとき、自動送信の結果の `report_checks` と、PR の詳細の `description_reason` の説明に、探した transcript のパスと、transcript のディレクトリもないことが示される。
-   **Claude Code の pane の報告は transcript から読む。** chief は、Claude Code の pane の最後の報告を、画面ではなく、Herdr が報告するセッションの transcript の、最後に終わった応答から読む。画面より長い報告も全文を読み、PR の詳細には 64 KiB までを示す（超えた分は切り、切ったことを示す）。transcript を読めないとき（Herdr がセッションを報告しない、設定のディレクトリを決められない、ファイルを読めない、64 MiB を超える、サンプルから読んだ形に合わない、最後の行が書きかけ、worktree のパスの文字）は、画面に戻らずに次のように振る舞い、理由とその pane を示す。
    -   自動送信の前の NEXT の照合: その workspace に送らない。送り先が OpenCode の pane でも送らない。
    -   ブランチのない状態の自動送信: 送らない。自動送信の後の `/runpr` の pane のリセット: 空にしない（`no_transcript` か `unsupported_path`）。
    -   PR の詳細: その pane に報告がないものとし、ほかの pane のうち、最後の報告があり、そのセッションの transcript の PR の記録がその PR を名指すものがちょうど 1 つでなければ、PR の説明を示す。
    -   `/runpr` の後の PR を作った pane のリセット: 空にしない。PR の詳細を読んだときに読めなかったなら、控えは PR の説明から作られているので、理由は `no_report` である。控えを作った後に読めなくなったときは、`no_transcript` か `unsupported_path` である。
-   **報告が読めずに見送ったリセット。** マージの後の自動送信の後の `/runpr` の pane のリセットは、OpenCode の pane で報告が画面に収まらないと行われない。報告が見つからずに見送ったリセット（PR の詳細が PR の説明を示した、最後の報告がない、transcript のファイルがない）のうち、ほかの条件をすべて満たしていたものは、`/chief` の一覧に「`/clear` を送る」か「`/new` を送る」の項目として示される。人がその pane を見て、前のコマンドの報告の後に会話が続いていないことを確かめてから選ぶと、chief が確かめ直して送る。OpenCode の pane では、その pane で `/runpr` が走ったことも、その後に人の会話がないことも chief は確かめられないので、人の目に任せる。Claude Code の pane の transcript を読めずに見送ったリセットは、項目として示さない。
-   **PR の詳細が、PR を作ったコマンドでない報告を示しうる。** PR の詳細は、最後の報告があり、そのセッションの transcript の PR の記録がその PR を名指す pane の報告を示す。PR の記録は、PR に関わっただけのセッションにも書かれるので、その PR をレビューしただけの pane の報告を示しうる。また、報告の後に遅れて届いた知らせ（バックグラウンドのサブエージェントの終わりなど）に一言で応えると、その一言が最後の報告になる。`/runpr` の報告の後にそうなると、その一言には NEXT がないので、自動送信の前の NEXT の照合はその pane を照合せずに通り（`report_checks` の `no_next`）、ブランチのない状態の自動送信と、自動送信の後の `/runpr` の pane のリセットは行われない。
-   **Claude Code の transcript の名前が変わると、NEXT の照合が通りうる。** Claude Code が transcript の値や種類の名前（応答の終わりを示す値、本文の部分や行の種類の名前）を変えると、chief はその pane に報告がないものとし、自動送信の前の NEXT の照合はその pane で止まらずに通る。自動送信の結果の `report_checks` に、その pane を照合しなかったこと（`no_report`）が残る。Claude Code の版が上がったら、transcript のサンプルを採り直す（1 章）。
-   **報告が遅れて書かれると、PR を作った pane は自動では空にされない。** PR を作ったコマンドの報告が、PR の詳細の控えを作った後に書かれると、控えは PR の説明から作られたままである。人が `/chief` で PR の詳細を見直し、そのとき報告がちょうど 1 つの pane で読めると報告の控えが作られ、`/runpr` の後のリセットがそれを使う。見直さなければ、`/runpr` の後のリセットは見送られ、その pane は「報告が読めずに見送ったリセット」の項目として示される。
-   **OpenCode の pane で人が打ったコマンドは示されない。** OpenCode にはセッションの記録がないので、作業中の行（行の状態が実行中）のコマンドは chief の送信の記録からだけ決まる（ADR-0046 の「結果」）。人がその pane で打ったコマンドは示されず、chief が最後に送ったのがリセット（`/new`）なら何も示されない。
-   **打った直後のラウンドは 1 つ前のコマンドを示しうる。** 人が Claude Code の pane でコマンドを打った直後で、Claude Code がまだその行を記録に 1 バイトも書いていないラウンドは、1 つ前のコマンドを示す。書きかけの行は 200 ms の間隔で 3 回まで読み直し、それでも終わらなければ何も示さない（`partial_line`）が、書き始める前は見分けられない。
-   **`/clear` の直後は古いセッションのコマンドを示しうる。** ラウンドの初めに読んだ Herdr のセッションの識別が、`/clear` の直後でまだ古いと、古いセッションの記録のコマンドを示しうる。
-   **人が引数なしで打ったコマンドは示されない。** 人が引数なしで打ったコマンド（`/runpr` など）は、記録の形が人の入力の読み取りの受け付ける形と違い、「そのほかの人の入力」と読まれる。その前にタスクのコマンドがあればそれに `＋指示` を添えて示し、なければ何も示さない（`not_task_command`）。たとえば `/runplan` の後に引数なしの `/runpr` を打つと、`/runpr` が走っている間も、内容の列には前の `/runplan` のコマンドが `＋指示` を添えて示される。
-   **起動し直すと長く走る OpenCode のコマンドは示されない。** `chief start` は、始めと終わりの両方を書いた 25 分より古い送信の記録を消す（7 章の「片付け」）。そのため、長く走る OpenCode のコマンドは、chief を起動し直した後に示されなくなる。
-   **エージェントのいない workspace は提案されない。** chief はエージェントの作業ディレクトリから workspace を見つけるので、エージェントがすべて終了した workspace は表に出ず、削除も提案されない。人が端末で片付ける。
-   **作ったことの記録だけが残った worktree は表に出ない。** 作成が workspace を作る前に止まったときや、削除が workspace を閉じた後に止まったときは、worktree と記録が残っても表に出ない。結果に示された残ったものを、人が端末で片付ける。
-   **作るか消すと、ほかの workspace の `make coverage-compare` が止まる。** 比較は、走っている間の `git worktree list` の変化を見つけると止まる（`internal/coveragecompare/userstate.go`）。比較の間は作成と削除を避けるか、止まったら走らせ直す。
-   **表が折り返しうる。** 表の幅は、Claude Code が code block の左に取る余白（2 桁）と、Herdr が分割した pane に描く枠（2 桁）を見込んで決める。Claude Code か Herdr の版が変わり、これらの幅が変わると、表の行が折り返しうる。
-   **拡大したタブでは、表が画面より狭い。** chief のタブを分割して拡大（zoom）すると、Herdr が返す pane の幅が描かれる幅より狭く、表は画面より狭く組まれる（左右に分割したタブで確かめた）。
-   **pane の幅を変えた表は、次のラウンドまで古い幅のまま。** 幅はラウンドごとに読むので、ラウンドの後に pane の幅を変えると、次のラウンドまで前の幅の表が示される。
-   **狭い pane では行がはみ出す。** 内容の列が最小の 20 桁を取れないほど狭い pane では、内容の列を 20 桁として組むので、行が使える幅を超えて折り返す。凡例は、使える幅が 27 桁より狭いときにはみ出す。
-   **セッションの写しは機械的には保証されない。** `/chief` の定義は、表を 1 文字も変えずに貼ると定めるが、道具はセッションが写した表を確かめられない。値の全文は、道具の出力の `rows` にある。
-   **端末が道具と違う幅で描く文字。** 道具は、Unicode 17.0.0 の East Asian Width が W か F の文字を 2 桁、そのほかの文字を 1 桁と数える。端末がこれと違う幅で描く文字（結合文字、異体字セレクタを伴う絵文字、ハングルの字母など）を含む行は、列がずれうる。外側の端末か Herdr が曖昧な文字を 2 桁で描く設定（日本語の環境で選べる）では、`─` の区切り線と `…` を含む行が折り返しうる。
-   **表の材料は、読んだときのもの。** pane とタブの対応はラウンドの初めに、タブのラベルと pane の幅はすべての workspace を読んだ後に読む。その間やラウンドの後に変わったもの（タブの移動、ラベルの変更）は、次のラウンドまで正しく示されないことがある。
-   **表の材料を読めなかった表は、見た目では分からない。** 80 桁とみなして組んだ表や、タブの表示に pane の ID を示した表は、ふつうの表と見分けにくい。理由は `table_unreadable` で分かる（3.1 の「調べ方」）。
-   **決まった語に似せた値。** タブのラベルや質問の文などの外から来る文字列は、`マージ確認` や `2 件` のような決まった語に似せた文字を含みうる。表は表示にだけ使い、chief の送る判断はこれらの語を読まない。
-   **中継しない質問。** 権限の確認、自由に書く答え、複数を選ぶ問い、1 つの画面に複数の問い（タブ）がある質問、読む量の上限で切った質問は、中身を示すだけで中継しない。人がその pane で直接答える。

## 9. 試作から移る

0088 より前の試作（`.claude/commands/chief.md` と `.claude/chief/` のシェルスクリプト）を worktree に置いていたときは、次の順に移る。

1.  試作の `.claude/commands/chief.md` と `.claude/chief/` を、リポジトリの外へ移すか消す。試作を git の共通ディレクトリの `info/exclude` で除いていたときは、その行も消す。除いたままだと、同じパスの新しい定義が見えなくなる。
2.  試作の `hold.tsv` に、自動送信を止める行が残っていれば、その計画書の PR マーカーに `**自動送信**: hold` を書く PR を作る（`_context.md` の「PR marker conventions」）。chief は `hold.tsv` を読まない。
3.  `main` を更新し、`make install-chief` を実行する。
4.  chief の workspace の Claude Code の pane で、新しいセッションの `/chief` を実行する。
