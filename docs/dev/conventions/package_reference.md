# Package Reference

This document lists the packages under `cmd/` and `internal/`, plus the
`prompts` package at the repository root, with a short summary of each one's
responsibility. Update it in the same commit that adds, removes, or changes the
responsibility of a package.

The planned layout and the responsibility of each not-yet-created package are
described in [project_overview.md](../project_overview.md) ("想定ディレクトリ構成" and
"パイプライン").

### What a row holds

A row holds only:

- the package's responsibility, in one to three sentences;
- the names of its main exported types, functions, and sentinel errors;
- a link to where its detailed specification lives, at most one link per
  linked document.

A row does not hold unexported names, numbers or limits, exit codes, the list
of environment variables a child process receives, file names, or procedures.

### Where details live

The detailed behavior of a package belongs in:

- the package's and its exported identifiers' doc comments;
- a current document under `docs/dev/` (a specification document or a guide),
  `README.md`, or `prompts/README.md`;
- the section of a completed task's design document that describes the
  behavior as it is now.

When one of these documents already has a detail, link to that document
instead of copying the detail into the row. Move a contract that callers rely
on (accepted and rejected input, the sentinel that reports a failure, an
ordering or atomicity guarantee, how a secret is handled) to the package's or
the exported identifier's doc comment when no document has it. Otherwise the
code is the source of truth, and the detail stays out of the row.

### Kinds of package

- **Pipeline components** run the article pipeline or carry the values it
  passes: the stages, their data types, and the CLI entry point and templates
  that supply them.
- **Server and host** serve the browser extension: the localhost server, its
  job API, cache, and socket, the configuration file it reads, and the Native
  Messaging host that relays to it.
- **LLM** packages define the provider-independent client contract and the
  adapter and parameter types of each provider.
- **Shared parts** are packages used by several others, such as configuration
  loading, directory locking, command execution, redaction, secrets, strict
  JSON, nil checks, and signal handling.
- **Development tools** are the commands and packages behind `/mergepr`,
  `/fixpr`, `/runpr`, and the local review and coverage helpers.
- **Test-only packages** are test utilities and packages that only tests use,
  wherever they sit.

A task that adds a package that fits none of these kinds decides whether to
add a kind here or to widen one of these definitions.

## Pipeline Components

| Package | Responsibility |
|---|---|
| `cmd/yt2column` | Entry point of the CLI (`yt2column [flags] <video URL>`): `main` runs `run` under `internal/signalrun`, which parses the flags, validates the video URL, loads `internal/config`, builds the stages, and runs one job through `internal/job`, writing the article to `--out`. It writes the step summaries, the token usage, and the estimated costs to standard error through `internal/redact`. Usage, flags, exit codes, and the artifact options: [CLI guide](../guides/cli.md). |
| `internal/artifact` | Persists the article writer's intermediate artifacts: one JSON file per video ID and stage, under a directory the caller names. `Parse` and `Marshal` define the on-disk format and the identifier computed from each record's content, and `Parse` also reads the previous format so a resume reuses an earlier CLI's files. `NewStore`, `Save`, and `Load` read and write the files, verifying the chain from the requested stage back to generation and rejecting a missing, malformed, or mismatched artifact with `ErrMissing`, `ErrMalformed`, or `ErrMismatch`. Implements `writer.ArtifactStore`. The format and its compatibility: [0077 design §3.4.2](../../tasks/0077_openai_llm_client/02_architecture.md). |
| `internal/job` | Runs one job end to end: `Run` validates the requested `Output`, checks the output paths before any side effect, holds the cache directory's lock while `internal/pipeline` runs, removes the video's cache unless `KeepCache` is set, and writes the review log when `Request.ReviewLog` is set. A prune or cache-removal failure becomes a warning in `Result.Warnings`; a published article whose review log could not be written is a `*ReviewLogError`. Output rules: [CLI guide](../guides/cli.md). |
| `internal/pipeline` | Runs the three stages in order: `Pipeline`, `Stage`, `StageError`, `ErrNilStage`. |
| `internal/pricing` | Estimates what an LLM call cost from its token counts and the providers' published rates, which it holds as constants: `Estimate` returns one stage's `StageCost` (a known amount and `RateBasis`, or an unknown `UnknownReason`), `Totals` sums the stages into a run total and an article total, and `Amount.Format` renders an amount as US dollars. How to update the rates: [pricing update guide](../guides/pricing_update.md). |
| `internal/publisher` | Defines the publishing stage: the `Publisher` interface and `FilePublisher`, which writes one article to one new file and never overwrites it. `PrepareSlackMessages` checks an article and splits it into `SlackMessages`, and `SlackWebhookPublisher` posts them to a Slack-compatible Incoming Webhook. `DisplayMarkdown`, `FileContent`, and `FormatArticleCost` expose the same rendering and cost formatting; `ReviewLogWriter` writes a review log. `ErrOutputExists`, `*KeptFileError`, `SlackHTTPStatusError`, and `*SlackPostError` report the failures. File format: [CLI guide](../guides/cli.md); post text, mentions, and splitting: [README](../../../README.md#slack-への投稿). |
| `internal/transcript` | Defines the transcript stage (`Transcript`, `Segment`, `TranscriptSource`) and implements it with `YtDlpSource` (a shell-free `yt-dlp` run and a per-video cache) and `CopiedSource` (the transcript a user copies from YouTube's panel). `ValidateVideoURL` and `NormalizedVideoURL` are the video URL rules. The cache's guarantees: [cache consistency](../cache_consistency.md); the `yt-dlp` boundary: [security.md](../security.md). |
| `internal/writer` | Defines the article-writing stage: `Article`, the `ArticleWriter` and `ProgressWriter` interfaces, and their implementation. `New` and `NewProgressWriter` validate the options and the prompt templates; `Write` runs the generation, shorten, and review steps, checks each result, and records each stage's token usage in `RunUsage`. `CheckChannelName`, `Article.CheckPublishable`, and `ProseRanges` hold the checks callers share, and `Options.Artifacts` saves and reuses completed stages through a `writer.ArtifactStore`. The template contract: [prompts/README.md](../../../prompts/README.md). |
| `prompts` | Embeds the default prompt templates and returns them: the generation pair with `System` and `User`, and the shorten and review pairs with `ShortenSystem`/`ShortenUser` and `ReviewSystem`/`ReviewUser`. [README](../../../prompts/README.md) documents the template contract and the values each pair may reference. |

## Server and Host

| Package | Responsibility |
|---|---|
| `cmd/yt2column-nmhost` | Entry point of the Native Messaging host (`yt2column-nmhost`). The role comes from the arguments by exact match: the extension's origin alone (`nmhost.ExtensionOrigin`, which the browser passes) relays one request with `nmhost.Relay`; `install chrome\|brave` and `uninstall chrome\|brave` write or remove the browser's manifest with `nmhost.Install`/`Uninstall` and write the manifest path to standard error, adding on macOS that Chrome and Brave share the file; every other shape is a usage error (exit code `2`, standard output empty, standard input unread). `main` passes `os.LookupEnv`, the standard streams, and the executable lookup (`os.Executable` resolved with `filepath.EvalSymlinks`); every role reads `HOME` and nothing else (`config.LoadHost` for the relay, `config.LoadHostHome` for install and uninstall). A relay whose `config.LoadHost` fails is given a `Dialer` that fails at once, so it never connects or reads the message: a message within the limits gets `server_unavailable` (the length checks still come first) and the relay exits with `0`, as for every reply; a relay that writes no reply (the length unreadable, standard output failing) exits with `1`. Install and uninstall exit with `2` when `HOME` is unusable, `1` on a rejection or write failure, and `0` on success (an uninstall with no manifest included). `main.go` holds only `main` and the executable lookup and is the only host file that references standard output; the roles live in `run.go` |
| `cmd/yt2column-server` | Entry point of the localhost server (`yt2column-server` with no arguments) and of `yt2column-server config init`: `main` runs `run` under `internal/signalrun` and passes `os.LookupEnv` (the package's only environment access). `run` dispatches on the arguments by exact match: none starts the server (`runServer`), exactly `config init` runs `runInit`, which creates the configuration file's template with `config.InitServerFile` and names it on one line of standard error (exit code `0`; `2` when `HOME` yields no path, a `*config.VarError`; `1` for any other failure: the file exists, its base directory is missing, or creating failed), and anything else writes the accepted forms and exits with `2`, creating nothing. `runServer` loads `config.LoadServer` (each rejection, of `HOME` and the socket path derived from it, the configuration file, one of its lines, or one of its keys, on its own line, exit code `2`), builds the LLM clients, the `writer.ProgressWriter` (the shorten and review steps enabled and the built-in templates, as a CLI run with no step flags), the `SlackWebhookPublisher` only when `SLACK_WEBHOOK_URL` is set, and the `internal/server` server with the API keys and the Webhook URL as the redacted secrets (a construction failure exits with `2`), prepares the socket directory, takes the start lock, and binds the socket with `internal/serversock` (a failure exits with `1`, naming the cause: another server holds the lock, another process listens on the path, or a path not in the accepted form), logs the socket path and whether a Webhook is configured, warns in one line when it is not, and serves until the first signal; it then cancels the in-flight generations and waits for the post jobs, saying so, with the longest wait (`publisher.SlackMaxPostDuration` rounded to the nearest minute, at least 1), and that a second signal exits at once, releases the start lock only after that wait, and exits with `0` (a listener that fails while serving exits with `1` after the same wait). Nothing is written to standard output; standard error carries every line, through `internal/redact` |
| `internal/articlecache` | The server's in-memory article cache: the article key (`Keyer` computes an HMAC-SHA256 under a per-process secret over a length-prefixed encoding of the validated request values; `ParseKey` accepts only 64 lowercase hexadecimal characters; `Keyer.Subject` pairs the key with the input's video ID, which is not part of the key), one record per key with its generation, stage, and publish states and the video ID of the input that created or restarted it, `Cache.Begin`, which takes a `Subject` and a `StartMode` and, under one lock, answers a running or done key with itself, then, for `StartInquiry` only, answers with the key of the latest running or done record of the same video under another key (the highest record generation) while changing nothing (no slot taken, no record dropped, no failed record restarted), and otherwise starts or restarts a generation as before, the record limit that drops the oldest done or failed record not being posted, and the handles (`Run`, `PublishRun`) through which the generation and post jobs report, each acting only on the record generation it was issued for and returning from each transition the value it set (the duration, the failed stage, the delivered count), read under the same lock. `PublishStates`, `UnpostableReasons`, and `PublishFailureReasons` return every value of their enumeration, so the server's status response size check walks them all. One mutex guards everything, and out-of-range input is ignored rather than panicking. Imports only `internal/writer`'s value types; `depguard` forbids `net/http`, `internal/llm`, `internal/publisher`, and `internal/server` |
| `internal/nmhost` | The Native Messaging host's relay. `Relay` reads one message length (native byte order) from standard input; a length over 32 MiB is `message_too_large` and a zero length `protocol_error`, both without connecting or reading the message. Otherwise it connects once through the `Dialer` it is given (`SocketDialer`: the Unix socket, 2-second connect limit; any failure is `server_unavailable`, with the message unread), then reads the whole message into memory and checks it as the new form (`route`). The new form is one JSON object passing `strictjson.ParseObject`, `{"v":1,"op":…}` with exactly the members its `Operation` needs; the version is checked before the other members. `start` sends the original bytes of its `input` object as `POST /jobs` with `Content-Length`, `Content-Type: application/json`, and `Expect: 100-continue`, `status` sends `GET /jobs/{key}`, and `publish` sends `POST /jobs/{key}/publish` with `Content-Length: 0`; the key is any JSON string, escaped with `url.PathEscape` into one path segment and left for the server to check. A message that breaks a rule (object, version, operation, members, input, key) is `protocol_error` and nothing is sent: a message that is not one strict JSON object breaks `object`, and one without a top-level `v` member (escapes decoded) breaks `version` whatever else it holds. Every request goes over a one-use transport that never redials, never uses a proxy, and does not keep the connection alive. The relay, reading the message included, is bounded by `RelayTimeout`; after the connection, a passed deadline is `server_timeout` (a standard input that stalls mid-message included, which sends nothing) even when the transport reports a broken write instead, and every other failure (standard input ending early, a write failure, an unreadable or truncated response, a response body over 512 KiB) is `protocol_error`. Nothing after the one message is read from standard input. The reply is one frame, the length and the JSON in a single write and never over 1 MiB: `{"v":1,"kind":"response","status":…,"body":"<standard base64 of the server's response body>"}` or `{"v":1,"kind":"error","error":"<HostError value>"}`; `HostError`'s zero value and every value outside its constants are `protocol_error`. The log, in `log/slog` text form on the writer it is given, carries only the fixed stage (`length`, `connect`, `read`, `form`, `exchange`, `reply`), the host error or status code, the operation, the broken rule, the OS error number's fixed text, the elapsed time, and the message length, never the message or the response. `Install` and `Uninstall` manage the host's manifest (`io.github.isseis.yt2column.json`, `stdio`, the one extension origin) for `chrome` or `brave` under a given home: install refuses when the browser's user data directory is missing (creating nothing), when the executable is relative or under the temporary directory, and when the file at the manifest path is not a manifest this host wrote; it writes through a `0600` temporary file and a rename. Uninstall removes only this host's manifest. On macOS both browsers share Chrome's `NativeMessagingHosts` manifest |
| `internal/privatefile` | Reads and creates files only their owner may read, knowing nothing of their content or location. `Read` refuses, without reading, a name that is missing (`ErrNotExist`), a symbolic link, not a regular file, owned by another user, or not exactly mode `0600` without the setuid, setgid, or sticky bit (an `*UnsafeError` that wraps `ErrUnsafe` and carries the path, a fixed `UnsafeReason`, and the mode found), and a file over the caller's size limit (`ErrTooLarge`); the path's `Lstat` can only refuse, and the checks that allow the read are made on the open descriptor (`O_NOFOLLOW`, `O_NONBLOCK`, `O_NOCTTY`) that the content is read from. `Create` puts a new file with exactly mode `0600` at a path without ever replacing what is there (`ErrExist`): it writes and syncs the content under a temporary name in the same directory (a dot, the base name, and `.tmp-`), links it at the path, and removes the temporary name, so a failure leaves nothing at the path; a temporary name it cannot remove is returned after a success and named in the error after a failure. `MkdirBelow` creates the missing directories of a chain of names below a base that must exist (`ErrBaseMissing`), each with exactly mode `0700` whatever the umask, set through a descriptor opened without following a link, and leaves an existing element unchanged; it sets the process umask to `077` during each `mkdir`, so it must not run concurrently with other file creation. Built only on Unix (`//go:build unix`) |
| `internal/server` | The HTTP server, served on a Unix domain socket listener the caller opens, that the browser extension's requests reach. It serves the job API (`JobsPath`): `POST /jobs` starts a generation into the `internal/articlecache` cache and answers with the article key, `GET /jobs/{key}` answers with the key's record, and `POST /jobs/{key}/publish` (`PublishSuffix`) posts the key's done article to the Webhook. `New` validates `Options` (a `writer.ProgressWriter`, an optional `WebhookOptions` holding the `WebhookPublisher`, which needs only `PostMessages`, and a log output; a nil or typed-nil collaborator is rejected, every missing one is named, and a nil `WebhookOptions` declares that no Webhook is configured), draws the article key secret from `crypto/rand`, builds the cache (`articlecache.DefaultCapacity` records), and builds the `slog` logger and the `http.Server` `ErrorLog` over `redact.Writer`, so no log path can bypass the redaction. The handler matches the request target before any decoding (a query is `not_found`; `/jobs` matches exactly; `/jobs/<rest>` without another slash is a status request, and with exactly `/publish` after its first slash a publish operation; every other target is `not_found`, refused before its body is read or a slot is taken) and then the method (the `Host`, `Origin`, `Content-Type`, and `Authorization` headers are not checked: any process that reaches the socket can set them). Only the generation jobs take one of the two generation slots (no queue). A generation start takes one of two reading slots (refused without reading the body when none is free), reads the body under a 4 MiB cap (a larger `Content-Length` is refused before a byte is read, so a client that sends `Expect: 100-continue` never sends the body), checks its members with `strictjson` and `writer.CheckChannelName`, then the required send mode (`mode`, exactly `inquiry` or `plain`; any other shape is `invalid_body`, never repaired), then the video URL and transcript with `transcript.ValidateVideoURL`/`NewCopiedSource`, computes the key from the validated values (the mode is not part of it), and calls `Cache.Begin` with the subject and the mode, which takes a generation slot only for a new or failed key; a running or done key is answered with its key whatever the slots, and an inquiry start for a video that has another running or done article is answered 200 with that article's key (`{"status":"same_video",...}`, logged with `outcome=same_video` and `sameVideoKey`) whatever the slots and the cache limit, starting nothing. The generation job calls `WriteWithProgress` with the cache's `Run` as the progress observer, maps a write failure to the record's failure reason with `classifyWrite`, then runs the completion check (`CheckPublishable`, the status response size limit of 256 KiB, and the Slack pre-send checks, which make the article unpostable) and ends the `Run`; it recovers its panics, and the handlers' own recovers fail a `Run` they still hold and free its slot. A status request refuses a body and any key part that is not 64 lowercase hexadecimal characters (`invalid_key`), and answers with codes, the identifiers the server generated, numbers, and a done article's Markdown and file. A publish operation without a Webhook is refused with `webhook_not_configured` (503, `Connection: close`) before its body and key are checked; otherwise it refuses a body and a malformed key as a status request does and calls `Cache.BeginPublish`: a done article not posted, or whose last post failed, starts a post job and is answered 202 without waiting for the Webhook, an article posting or posted is answered 202 and posted no further, and a running, failed or unknown, or unpostable key is refused (`article_not_ready`, `article_not_found`, `article_not_postable`). The post job takes no generation slot and runs on a context `Serve` cancels only after every job has finished: it rebuilds the messages with `PrepareSlackMessages` and sends them with `PostMessages` from the first message not delivered, recording each delivery on the `PublishRun`, so a retry after a failure or a recovered panic resends only what was not delivered. The post job is the only path that sends to the Webhook. Every response is a fixed JSON object that carries no request value and no secret. `Serve` takes one listener, stops on cancellation or a listener failure (closing a `*net.UnixListener` removes its socket), counts the generations in progress and cancels them first, waits for the post jobs without canceling them (logging `canceledGenerations` and `postJobs`), and returns. The jobs log with the values the cache handles return from their transitions, never by reading a record back. |
| `internal/serversock` | Prepares the server's Unix domain socket. `Acquire` rejects a socket path that is relative or not in clean form, creates the socket directory (mode `0o700`) and its parent when missing, rejects a parent that is a symbolic link, not a directory, owned by another user, or writable by its group or others, and a socket directory that is a symbolic link, not a directory, owned by another user, or not exactly `0o700` without the setuid, setgid, or sticky bit, without changing any permission, then takes the start lock through `internal/cachelock` (a held lock is `ErrAlreadyRunning`). `Lock.Listen` removes only a stale socket (owned by the effective user, connection refused), returns `ErrInUse` for a socket that accepts a connection and an `*UnsafeError` for any other name, a foreign socket, or a connection attempt that fails otherwise, all left in place, then binds, sets the socket to `0o600`, and checks it (exactly `0o600`, no special bits; on failure the name is unlinked only while it is still the user's socket). Closing the listener removes the socket; `Lock.Release` releases the start lock, after which `Listen` fails. Every rejected shape is an `*UnsafeError` that wraps `ErrUnsafe` and carries the path and a fixed `UnsafeReason`. Built only on Unix (`//go:build unix`) |
| `internal/slackwebhook` | The rule a Slack-compatible Incoming Webhook URL (Mattermost or Slack) must meet (`ValidURL`: `net/url` parses it, its scheme is `https`, its host is not empty) and the parts of such a URL that must never appear in output (`SensitiveParts`: the URL, its path, query, and userinfo both as given and as `net/url` writes them, the last path segment, and the last eight characters). Depends on the standard library only; shared by `internal/config`, `internal/publisher`, `internal/redact`, and the webhook integration test |

## LLM

| Package | Responsibility |
|---|---|
| `internal/llm` | Defines the provider-independent `LLMClient` interface and its `GenerateRequest`/`GenerateResponse` types, the provider-common sentinel errors (`ErrInvalidRequest`, `ErrTruncated`, `ErrUnexpectedFinishReason`, `ErrEmptyResponse`), and `GenerateRequest.Validate`. `GenerateResponse` carries the token usage as `Usage`: `TokenCounts` with a `PricingContext`, built by `KnownUsage` or `KnownUsageWithPricingContext` (which rejects `ErrInvalidPricingContext`), or an unknown usage with an `UnknownRule`, built by `UnknownUsage`, read through `Counts`, `PricingContext`, and `UnknownReason`. |
| `internal/llm/claude` | Implements `llm.LLMClient` against the Anthropic Messages API: `New` validates the configuration and builds the client, requests go through `internal/llm/llmhttp`, and the response body is validated strictly before anything is returned. `ErrHTTPStatus` and `*HTTPStatusError` report an HTTP-status failure, and the adapter returns the rejected response's `Model` and `Usage` with a truncation, an unexpected finish reason, or an empty response. |
| `internal/llm/claudeparam` | The Claude adapter's parameter types: `Effort` (the `output_config.effort` value, with `ParseEffort`, `String`, `Valid`, and `EffortValues`) and `WorkspaceID` (the workspace ID, with `ParseWorkspaceID`). |
| `internal/llm/deepseek` | Implements `llm.LLMClient` against the DeepSeek Chat Completions API: `New` validates the configuration and builds the client, requests go through `internal/llm/llmhttp`, and the response body is validated strictly before anything is returned. `ErrHTTPStatus` and `*HTTPStatusError` report an HTTP-status failure, and `ErrPaddedModel` reports a model name with surrounding whitespace. The adapter returns the rejected response's `Model` and `Usage` with a truncation, an unexpected finish reason, or an empty response. |
| `internal/llm/deepseekparam` | The DeepSeek adapter's parameter type: `Effort` (the `reasoning_effort` value, with `ParseEffort`, `String`, `Valid`, and `EffortValues`). |
| `internal/llm/llmhttp` | Performs one HTTP POST for an LLM adapter: `Post` applies the adapter's timeout over the caller's context, never follows a redirect, returns the body of a `200` response under `MaxResponseBytes` without reading the body of a non-`200` response, and classifies a send or read failure into a context error or one of the adapter's own sentinels (`Errors`). `NewClient` returns a client that never redirects, and `CheckAPIKey` checks the shape every adapter requires of an API key (`ErrZeroAPIKey`, `ErrInvalidAPIKey`). | `internal/llm/openai` | Implements `llm.LLMClient` against the OpenAI Responses API: `New` validates the configuration and builds the client, requests go through `internal/llm/llmhttp`, and the consumed members of the response body are validated strictly before anything is returned. `ErrHTTPStatus` and `*HTTPStatusError` report an HTTP-status failure; the adapter reads the response's usage and pricing context, and returns the rejected response's `Model` and `Usage` with a truncation, an unexpected finish reason, or an empty response. | `internal/llm/openaiparam` | The OpenAI adapter's parameter type: `Effort` (the Responses API's reasoning effort, with `ParseEffort`, `String`, `Valid`, and `EffortValues`). `EffortNone` is a distinct accepted value that turns reasoning off. |

## Shared Parts

| Package | Responsibility |
|---|---|
| `internal/cachelock` | Serializes the processes that share one directory (the CLI's cache directory, and the server's socket directory through `internal/serversock`): `Acquire` creates the directory when missing, opens the fixed lock file without following a symbolic link or blocking on a named pipe, and takes a non-blocking exclusive `flock`. A held lock returns a `*LockedError` that wraps `ErrLocked`; `File` exposes the descriptor so a child process inherits the lock, and `Close` releases this process's reference. Built only on Unix (`//go:build unix`). |
| `internal/cmdrunner` | The shared execution boundary for external commands: `Runner` and `InputRunner` run a command without a shell and return its standard output. `NewOS` bounds the captured output (`MaxOutput`, `ErrOutputTooLarge`), the wait after cancellation, the working directory, and the environment, can start the command in its own process group, and can fail a command that writes to standard error (`ErrUnexpectedStderr`). A command that exits unsuccessfully fails with the typed `*ExitError`. `GitEnv` drops every inherited `GIT_*` variable, and `GitHardening` returns the global git options that read objects as stored. The `yt-dlp` boundary: [security.md](../security.md). |
| `internal/config` | Reads and validates the process configuration. For the CLI, `Load` and `LoadFor` read the environment through a `LookupFunc` into `Config`; for the server, `LoadServer` reads and validates the configuration file into `ServerConfig`, and `InitServerFile` creates its template. `Need` selects the stages a run has, so a resumed run does not require a skipped stage's settings. `LoadHost` and `LoadHostHome` read only `HOME` for the Native Messaging host. `LLMConfig` holds one `LLMSelection` per stage, returned by `Generation` and `Review`. Rejections are `*VarError`, `*FileError`, or `ErrMissing`/`ErrInvalid`. Configuration reference: [README](../../../README.md#設定); the server configuration file and its checks: [security.md](../security.md). |
| `internal/nilcheck` | Reports whether a value is nil, including a typed nil held in an interface (`IsNil`). Used by `internal/pipeline` to reject unset stages and by `internal/writer` to reject a missing `LLMClient`. |
| `internal/redact` | Keeps secret values out of output: `Line` renders one line for a terminal, `Writer` redacts each write for output already formatted by `log/slog`, and `SecretStrings` builds the string list from `secret.Secret` values. Depends on `internal/secret` and `internal/slackwebhook`, not on `internal/config`. |
| `internal/secret` | Holds a secret (API key, Webhook URL) and guarantees it never appears in `fmt`, `log/slog`, or JSON output. |
| `internal/signalrun` | `Run` calls a program's main function under a context that the first subscribed signal cancels: SIGTERM always, and SIGINT and SIGHUP unless each was ignored at startup; the subscription is dropped on that first signal before cancellation, so a second signal terminates the process. |
| `internal/strictjson` | Extracts values from JSON documents that passed strict checks: rejects the byte sequences and structural shapes `encoding/json` would silently repair (invalid UTF-8, unpaired surrogate escapes, trailing data, duplicate or `null` consumed members). Main types and methods: `Object.CollectOnly`, `Object.Has`, `Value.AsBool`, `Value.IsNull`, `Value.AsNonNegativeInt64`, `Value.Raw`. The rejected inputs: [0003 design §3.5](../../tasks/0003_deepseek_llm_client/02_architecture.md). Shared by `internal/transcript`, `internal/llm/deepseek`, `internal/llm/claude`, `internal/llm/openai`, `internal/publisher`, `internal/writer`, `internal/artifact`, `internal/fixprguard`, `internal/server`, `internal/nmhost`, `internal/codexreview`, and `internal/coveragecompare` |
