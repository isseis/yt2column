# ADR-0017: ビューアは記事を自前の最小限のレンダラーで描画し、HTML を解釈せず、リンクは https の自動リンクだけにする

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

ビューアは、記事を作る処理が返し、ジョブの記録に置いた記事（表示用の Markdown）を表示する拡張のページである。記事は LLM の出力で、字幕と動画メタデータを経由したプロンプトインジェクションで、意図しない HTML やリンクを含みうる。拡張のページはすべて同じオリジンで、ビューアから、拡張が保存した利用者の API キーに届く。記事からスクリプトが動けば、API キーを読んで外へ送ることにつながる（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「オプションページと API キーの保存」）。

拡張が出荷するのは本リポジトリで書いたコードと、例外として宣言した Go のツールチェーンの `wasm_exec.js` だけで（[ADR-0026](0026-extension-platform.md)）、npm のパッケージは開発用に限るので（[CLAUDE.md](../../../CLAUDE.md)「Dependencies」）、Markdown のライブラリは使えない。記事の書き方は生成のプロンプト（[prompts/system.tmpl](../../../prompts/system.tmpl)）が決める。表示用の Markdown には、記事のほかに、動画の持ち主が決めるチャンネル名の行と、出典の自動リンクの行が入る。

## 決定

-   **自前の最小限のレンダラーで描画する。** 扱う記法は、プロンプトが使う要素と、扱っても小さく安全な要素に限る。Markdown のライブラリを使わないという依存の制約の下で、記事を読みやすく表示するためである。規則は [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §3.2「記法の規則」と F-001〜F-003 にある。
-   **記法は、要件定義書が定める単純な規則で解釈する。** CommonMark の解釈には合わせず、規則に合わない記法は文字のまま表示する。記事はプロンプトが決めた単純な形なので、CommonMark の強調の区切りまで実装するとレンダラーとテストが大きくなるためである。規則は [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §3.2 にある。
-   **扱わない記法と HTML は、要素にせず文字のまま表示する。** 近い要素に直して描画することはしない。記号を失わず、入力から要素を推測しないためである。規則は [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) F-004 にある。
-   **HTML を解釈しない。** DOM は要素の生成と文字列の設定だけで組み立て、記事の内容から作る要素と属性は決めた一覧に限る。記事からスクリプトを動かし、API キーを読んで送らせないためである。規則は [security.md](../security.md) §8.1「ブラウザ拡張」と [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) F-004 にある。
-   **リンクにするのは `https` の自動リンクだけにする。** `<https://…>` のうち、URL として解釈でき、ホストを持ち、ユーザー名とパスワードを持たず、直列化した URL と 1 文字も違わないものだけをリンクにする。表示する文字列とリンク先を同じ URL の文字列にして、利用者を欺くリンクを作らないためである。規則は [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) F-003 にある。
-   **リンクは新しいタブで、参照元を送らず、開いたページにビューアのウィンドウを渡さない形で開く。** ビューアのタブを記事の表示のまま残し、リンク先にビューアの URL の値を渡さないためである。規則は [security.md](../security.md) §8.1 と [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) F-003 にある。
-   **保存とコピーは描画の結果を使わない。** ジョブの記録が持つ文字列を変えずに保存し、コピーする。描画を変えても、保存するファイルとコピーする Markdown を変えないためである。規則は [0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) F-006 にある。

ビューアがジョブの記録の記事を表示し、ビューアのオリジンから API キーに届くことは、まだコードに反映していない。今のビューアは状態の取得の応答の記事を表示し、API キーを持たない。この差分は [#773](https://github.com/isseis/yt2column/issues/773) の実装で解消する。

## 採らなかった案

-   **Markdown のライブラリを使う。** 拡張が出荷するのはこのリポジトリが書いたコードだけとする方針に反する（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **引用・水平線・入れ子のリスト・`###` 以下の見出し、または表まで描画する。** プロンプトはこれらの記法を使わないので、扱ってもレンダラーとテストが増えるだけになる（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **タイトルの行とチャンネル名の行を本文と別に返させ、本文だけを描画する。** サーバの API と応答の検査を変えることになり、#504 の範囲を大きく超える（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **扱う要素について CommonMark と同じ構造に描画する。** 保存した `.md` を別のビューアで開いたときと表示がそろうが、強調の区切りの規則まで実装するとレンダラーとテストが大きくなる。記事はプロンプトが決めた単純な形なので、実用上の差は小さい（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **`[文字](URL)` の形のリンクも `https` に限ってリンクにする。** 表示する文字列とリンク先が食い違いうる。プロンプトは URL を書かせないので、本文の中のリンクはプロンプトインジェクションの疑いが強い（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **記事の中のリンクを、出典の URL も含めてリンクにしない。** 0050 の表示のままだが、出典の動画を開くのに URL の文字列をコピーする手間が要る（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。
-   **リンクを同じタブで開く。** ビューアのタブが記事の表示から離れる（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md) §1）。

## 結果

-   記事が `https` の自動リンクで任意のサイトを指すことは防がない。リンクの表示は URL そのもので、参照元とビューアのウィンドウは渡らない。
-   チャンネル名の行の途中の記法も描画する。動画の持ち主は、LLM を介さずに、チャンネル名で自動リンクを作り、強調などで見た目を変えられる。レンダラーは 1 つの文字列を受け取り、チャンネル名の行の位置を推し量らないので、これを残余のリスクとして受け入れる。
-   保存した `.md` を CommonMark のビューアで開くと、ビューアの表示と細部が異なりうる（段落の中の改行など）。
-   プロンプトが新しい記法を使うようになっても、レンダラーを変えるまでは、その記法は文字のまま表示される。扱う記法を増やすタスクは、この ADR を更新する。
-   レンダラーは表示用の Markdown の中身を調べて描画する要素を選ぶので、CLAUDE.md「Declare, don't infer」の例外になる。例外の範囲はレンダラーの解釈に限る。
