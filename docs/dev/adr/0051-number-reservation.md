# ADR-0051: タスク番号と ADR 番号は GitHub の上で重複しないように道具で決め、決められなければ止め、ADR 番号の欠番を許す

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

タスクと ADR は、複数のセッションで並行して作られる。セッションは、ローカルの worktree だけでなく、別のクローンで動く cloud のセッション（claude.ai/code）でもある。タスク番号は `/mkreq` が「使用中の最大値 + 1」として計算し、ADR 番号は「`main` とその PR のブランチの最大値の次」として決めている。どちらも、計算してから番号を使うまでの間に排他がない。同じ時点の状態から計算した 2 つのセッションは、同じ番号を取る。ADR-0050 を別の PR が使っていたために、空いている番号を手で確かめ直した例がある（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) §1）。

## 決定

-   **タスク番号と ADR 番号は、別のクローンや cloud のセッションの間でも重複しないことを、サーバ側（GitHub）で保証する。** ローカルのロックやファイルは、別のクローンからは見えないためである。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の F-001・F-002 にある。番号を一意にする方式（ref の予約か、タスク番号を issue 番号にするか）は、0100 の設計で決めてこの ADR に書く。
-   **番号は道具が決め、エージェントは道具が返した番号だけを使う。** 番号の判定が、エージェントの読み違いで変わらないようにするためである。タスク番号と ADR 番号は、互いに影響しない別々の番号の空間に持つ。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の AC-05・AC-14 にある。
-   **番号を決められなければ止め、理由の種類を示す。従来の計算に戻して続けない。** 目的は重複を防ぐことであり、代わりの計算で続けると重複の余地が戻るためである。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の AC-06・AC-13 にある。
-   **一度決めた番号の記録は残し、番号を使い回さない。** 中断したタスクや PR の番号は欠番になる。記録を消すと、同じ番号を再び使う余地が生まれるためである。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の AC-03・AC-10 にある。
-   **ADR 番号の欠番を許し、重複だけを禁じる。** 番号を決めた順とマージの順が違うと、`main` で間の番号が一時的に欠ける。取り下げた PR の番号は欠けたまま残る。欠番を禁じると、そのたびにすべての PR の `TestADRRecords` が失敗するためである。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の F-003 にある。
-   **ADR 番号を決める手順は ADR の規約に書き、コマンドが作る PR にも手で作る PR にも当てはめる。付け替えた後の番号も同じ手順で決める。** ADR はどのコマンドの PR でも作られうるうえ、手で選んだ番号は、ほかの PR が決めてまだマージしていない番号と重なりうるためである。規則の置き場所は [adr.md](../conventions/adr.md) の「Location and naming」と「Taking in `main`」である。
-   **使用中とみなす PR は、このリポジトリの中にヘッドがあるものに限る。** fork の PR のブランチ名はリポジトリの外の人が付けられ、数えると番号を押し上げられるためである。要件は [0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md) の AC-02・AC-10 にある。
-   **番号を決める道具の呼び出しは、決まった形で行う限り、利用者に確かめずに実行してよい。** ADR 番号はどの PR でも決めるので、コマンドごとの承認では足りないためである。規則の置き場所は [CLAUDE.md](../../../CLAUDE.md) の「Tool Execution Safety」である。
-   **食い違い:** 番号を決める道具はまだなく、[adr.md](../conventions/adr.md) の「Location and naming」と `TestADRRecords` は欠番を誤りとしている。どちらもこの ADR の決定に合っていない（[#917](https://github.com/isseis/yt2column/issues/917)）。

## 採らなかった案

-   **ローカルのロック（git の共通ディレクトリでの `mkdir` によるロック）。** 同じマシンの worktree の間でしか効かず、別のクローンや cloud のセッションには効かない。エージェントが複数のツールの呼び出しにまたがってロックを持つのも壊れやすい（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「issue #917 で決めたこと」）。
-   **番号を決められないとき、従来の計算で続けて警告する。** 重複の余地が残り、マージの前に確かめる仕組みが別に要る（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）。
-   **ADR 番号の欠番を禁じたままにする。** マージの順を予約の順にそろえる運用と、取り下げた番号を別の ADR で埋める運用が要る（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）。
-   **使い終わった番号の記録を消す。** 消す手順が要り、消した番号を再び使う余地が生まれる（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）。
-   **ADR 番号の決定だけは、その都度利用者に確かめる。** ADR は手で作る PR でも作られ、コマンドごとの承認では扱えない（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）。

## 結果

-   番号を決めるには GitHub に届くことが要る。番号を決められない環境では、`/mkreq` と ADR の作成と付け替えが止まる。
-   中断したタスクや PR の番号は欠番として残る。番号の並びから、作られたタスクや ADR の数は分からない。
-   ADR の規約と `TestADRRecords` は、欠番を誤りとしない形に変わる。重複の検査と、`main` を取り込むときの付け替えの規則は残る。

## 経緯

- 2026-11-17 タスク番号と ADR 番号を GitHub の上で重複しないように道具で決め、決められなければ止め、番号の記録を残して使い回さず、ADR 番号の欠番を許し、道具の呼び出しを常設の承認にすると決めた。タスク番号と ADR 番号を別の空間に持ち、ADR 番号を決める手順（付け替えを含む）を ADR の規約に書き、使用中とみなす PR をこのリポジトリの中にヘッドがあるものに限ることにした（[0100 要件定義書](../../tasks/0100_number_reservation/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）
