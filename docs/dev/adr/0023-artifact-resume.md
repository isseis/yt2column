# ADR-0023: 中間生成物を工程ごとに保存し、壊れた中間生成物を拒否しながら後の工程から再開できるようにする

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

記事を作る処理は、生成・字数の調整・検証・推敲の最大 3 回の LLM の呼び出しを行う。同じ記事をもう一度作ると、生成の出力が実行ごとに変わり（DeepSeek の非決定性）、前の実行と比べるための条件が揃わない。検証・推敲だけをやり直したいときも、生成からやり直すと料金と時間がかかる（[0017 要件定義書](../../tasks/0017_intermediate_artifacts/01_requirements.md) §1）。

各工程の出力を残せば、後の工程の失敗や中断の後に、前の工程を飛ばして続きを実行できる。残したファイルは利用者が書ける場所にあり、壊れた値や改ざんされた値を読みうるので、境界で検証する必要がある。

## 決定

-   **中間生成物を残すかどうかは、`--artifacts <dir>` で明示する。** ディレクトリを渡さない実行は、保存も再開もしない。ディレクトリは利用者が用意し、CLI は作らない。キャッシュの削除で消えないよう、キャッシュディレクトリの中は拒否する。
-   **再開する工程は `--after <stage>` で指定する。** `generation`・`shorten`・`review` のいずれかで、指定した工程の出力を再利用し、それより後の工程だけを実行する。工程の実行の有無は、この値と `--no-shorten`・`--no-review` から導き、保存された値から推測しない。
-   **保存の単位は、動画 ID と工程の組ごとの 1 つの JSON ファイルである。** 形式は版 3 で、工程の名前・モデル名とモデルの版・テンプレートの識別子・入力の識別子・文面・使用量・呼び出しの時刻を持つ。各記録は内容から計算した識別子を持ち、生成以外の記録の入力は前の工程の記録の識別子を、生成の入力は素材の識別子を指す。
-   **読み込みは信頼しない入力として検証する。** 構文は `internal/strictjson` で厳密に検査し、宣言していないキー・重複・末尾のデータ・欠けた値・範囲外の値・版の違いを拒否する。再開する工程から生成の出力まで入力をたどり、生成の入力が今の素材と一致することを確かめる。不在・破損・食い違いは、部分的に受理せずに実行の失敗にする。
-   **工程が完了した時点で保存する。** 後の工程が失敗しても、それより前の工程の出力は残る。保存の失敗は、その工程の失敗として扱い、記事を公開しない。再開の実行でも、実行した工程は保存する。
-   **書き込みは一時ファイルと `rename(2)` で行う。** 中断の後、ファイルは置き換えの前か後のどちらかであり、書きかけの内容が次の再開に受理されない。
-   **古い形式の版は拒否する。** 版 3 だけを読み、版 1・版 2 のファイルは、その版を読まないことを示すエラーで拒否する。利用者は新しいディレクトリを使う。

この決定の仕様の正本は [cli.md](../guides/cli.md) の「使い方」のフラグの表と「生成の後の工程」、[security.md](../security.md) §5「キャッシュディレクトリ」である。使用量の返し方は [ADR-0021](0021-llm-client-contract.md) が、呼び出しの時刻と料金は [ADR-0022](0022-cost-estimate.md) が定める。

## 採らなかった案

-   **当初案の `--article <path>` と `--review-only` を、別々のフラグとして設ける。** `--article <path>` は任意の記事ファイルを入力にするもので、再開の入力が保存した中間生成物に限られない。`--after` は、保存した記録を動画 ID で選び、工程の順序から前段を決められるので、2 つのフラグを一般化できる（[0017 要件定義書](../../tasks/0017_intermediate_artifacts/01_requirements.md) §4.4）。
-   **版 2 の中間生成物を受理し、時刻がないものとして扱う。** 読み込みに版ごとの形の定義が 2 つ要り、再利用した工程の料金が不明か仮定の値になる。版 3 だけを読む（[0022 要件定義書](../../tasks/0022_cost_estimate/01_requirements.md) F-007）。

## 結果

-   検証・推敲だけをやり直すときも、生成と字数の調整の出力を再利用できる。実行した工程の出力は、再開の後も残る。
-   中間生成物は、利用者が指定したディレクトリに、利用者が削除するまで残る。キャッシュの掃除では消えない。
-   壊れた中間生成物や、今の素材と合わない中間生成物は、記事を公開せずに実行を失敗させる。利用者はそのファイルを消すか、新しいディレクトリを使う。
-   形式を変えるときは版を上げ、古い版を読まない。別の版の CLI との互換は保たない。

## 経緯

- 2026-10-14 中間生成物を `--artifacts` で保存し、`--after` で後の工程から再開する形にした。形式は版 1 で、保存した値は境界で検証した（[0017 設計書](../../tasks/0017_intermediate_artifacts/02_architecture.md)）
- 2026-10-15 使用量を中間生成物に加え、形式の版を 2 に上げた。版 1 のファイルは拒否する（[0019 設計書](../../tasks/0019_token_usage/02_architecture.md)）
- 2026-10-16 呼び出しの時刻を加え、形式の版を 3 に上げた。時刻は記録の識別子に含める（[0022 設計書](../../tasks/0022_cost_estimate/02_architecture.md)）
