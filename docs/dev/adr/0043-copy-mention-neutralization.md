# ADR-0043: ビューアの表示とクリップボードへのコピーで記事のメンションを無効化し、コピーは拒否しない

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

利用者は、ビューアで記事を Markdown 形式でクリップボードへコピーし、Slack や Mattermost のチャンネルに手で貼り付けて共有する。記事は LLM の出力で、タイトル・チャンネル名・本文は、字幕と動画メタデータへのプロンプトインジェクションで操作されうる。YouTube のハンドルは `@` で始まるので、概要欄やチャンネル名から `@名前` が記事に入りうる。貼り付けた `@channel`・`@here`・`@名前` は、チャンネル全体や個人への通知になる。

2026-11-11 に、Mattermost のチャンネルへの貼り付けを実機で確かめた（Mattermost サーバ 11.11.3、デスクトップアプリ 6.3.2）。送った人の画面の表示と、同じチャンネルの別のアカウントへの通知の両方を見た。`@channel`・`@here`・`@名前` はメンションになり、`@` の直後に U+200B を入れるとメンションにならなかった。URL でない `AC/@名前` は通知された。コードスパンとフェンス付きコードブロック（` ``` ` と `~~~`）の中の `@`、URL の中の `/@`、全角の `＠channel`、`<!channel>`・`<@名前>`・文字参照はメンションにも通知にもならず、`<https://…|表示>` はメンションでないリンクになった。確かめた並びと結果は [0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」にある。Slack では確かめていない。

同じ日に、Mattermost の `master` のソースを読んだ。Mattermost は、段落のテキストのノードだけからメンションを探し、自動リンクとコードスパンとフェンス付きコードブロックの中は探さない。どこまでを自動リンクやコードとするかには、こちらの判定と異なる条件がある（スキームの直前の文字、ホストの文字、`<`・`>`・`[` の扱い、`~~~` のフェンスの情報文字列のバッククォートなど）。読解の内容は [0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)「Mattermost の判定との比較（H-06）」にある。

## 決定

-   **コピーする文章では、対象の `@` を、`@` の直後に U+200B を入れて無効化する。** 対象はタイトルの見出しの行、チャンネル名の行、本文のコードの範囲の外である。コードの範囲を判定できない本文では、本文の対象の `@` を、URL のパスの `/@` を除いてすべて無効化する。語の途中の `@` と、URL のパスの `/@`（Mattermost が自動リンクにする形に限った、URL のホストの後ろの `/` の直後の `@`。定義は 0083 要件定義書 §3.1）は変えない。ほかの `/@` と、URL の中でもパスの `/@` でない `@`（`https://@channel`、`?@here` など）は無効化する。この規則はタイトルの行・チャンネル名の行・本文で同じである。貼り付けた記事がメンションにならないようにするためである。URL のパスの `/@` を変えないのは、`https://www.youtube.com/@ハンドル` のような URL を壊さないためであり、実機で通知されなかったためでもある。ほかの `/@` を無効化するのは、URL でない `/@` が実機で通知され、確かめていない形を `https://` を付けるだけで残せないようにするためである。URL のパスの `/@` を Mattermost の自動リンクの条件より狭く定めるのは、こちらが URL と判定して変えなかった `@` を、Mattermost が自動リンクにせず通知することがないようにするためである。チャンネル名の行を対象にするのは、チャンネル名が外部由来で `@` を含みうるためである。対象の `@` の定義と規則は [security.md](../security.md) §6「信頼できないテキストの取り扱い」と、0083 要件定義書 F-002 にある。
-   **こちらがコードとみなす範囲は、Mattermost もコードとして扱う形に限る。** Mattermost がコードとして扱わない書き方（情報文字列にバッククォートを含む `~~~` のフェンス、Mattermost が閉じるとみなすが CommonMark では閉じない閉じのフェンス、自動リンクの並びの中のバッククォート）を含む本文は、コードの範囲を判定できない本文として扱い、本文の対象の `@` をすべて無効化する。コードの中として変えなかった `@` を、Mattermost が通知しないようにするためである。規則は 0083 設計書「Mattermost の判定との比較（H-06）」にある。
-   **無効化はサーバで行い、ビューアは受け取った文字列を加工しない。** サーバは、記事のタイトル・チャンネル名・本文を別々に持つ段階で無効化し、状態の取得の応答の表示用の Markdown（`markdown`）を無効化した文字列にし、無効化したかどうか（`mentionsNeutralized`）を添える。保存するファイルの中身（`file`）は無効化しない。ビューアは、表示とコピーに `markdown` をそのまま使い、通知を `mentionsNeutralized` で選ぶ。規則を Go の 1 か所に置き、拡張に同じ規則を二重に書かないためであり、タイトル・チャンネル名・本文の切り分けは、記事の値を別々に持つ部品でしか正しく行えないためである。応答の形は [development.md](../guides/development.md) の「ジョブの API」に、設計は 0083 設計書にある。
-   **コピーは、記事の内容によって拒否しない。** コードの中の `@`、URL のパスの `/@`、`<!`、文字参照、`<a|b>` の形は、そのまま残す。`<@` の形の `@` は、ほかの対象の `@` と同じく無効化する。実機の確かめで、どれも貼り付けた後にメンションにも通知にもならなかったためである。コードの中を無効化しないのは、貼り付けたコードを写したときに見えない文字が混じるためでもある。拒否すると、利用者はその記事をコピーできなくなる。規則は 0083 要件定義書 F-002 にある。
-   **無効化したことを、「Markdown をコピーする」ボタンの結果の通知で知らせる。数は示さない。** 1 個以上を無効化したときだけ示す。表示した記事を選択してブラウザでコピーしたときは通知しない。その操作にはビューアのボタンが関わらず、通知を出す場所が操作と結びつかないためである。貼り付けた文章が見た目と違う文字を含むことを、利用者が知れるようにするためである。数を見ても利用者の次の行動は変わらないので、有無だけを示す。規則は 0083 要件定義書 F-003 にある。
-   **ビューアの表示も、コピーと同じ規則で無効化する。** 表示する記事の文字には、コピーする文章と同じ位置に U+200B が入る。利用者は表示した記事を選択してコピーすることがあり、ブラウザは描画した文字をコピーするためである。U+200B は目に見えないので、見た目は変わらない。規則は 0083 要件定義書 F-002 にある。
-   **保存するファイルと `--out` のファイルは無効化しない。** `--out` は開発用の CLI の出力で、エンドユーザー向けの機能ではなく、なるべく加工しないデータが要るためである。保存するファイルは `--out` のファイルと同じ中身である。規則は 0083 要件定義書 §2.3「スコープ外 (Out of Scope)」と F-002 にある。

この決定は、まだコードと security.md に反映していない。いまの表示とコピーは表示用の Markdown をそのまま使い、security.md §6 は Webhook への投稿の規則を述べる。この差分は [#770](https://github.com/isseis/yt2column/issues/770) の実装で解消する。

## 採らなかった案

-   **URL のパスの `/@` を、ホストの後ろの `/` の直後の `@` と広く定める（0083 要件定義書の最初の定義）。** スキームの直前に英字がある形、ホストに `_` を含む形、`<`・`[` が先にある形など、Mattermost が自動リンクにしない形でも `@` を変えず、貼り付けると通知になる（0083 要件定義書「設計の際に改めたこと（2026-11-11）」）。
-   **拡張（TypeScript）で無効化する。** 対象の `@` とコードの範囲の判定を TypeScript に書き直すと、規則が Go と二重になる。拡張が受け取る表示用の Markdown の 1 つの文字列からは、チャンネル名がないときに本文の最初の行とチャンネル名の行を見分けられない（[0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)「設計の際に決めたこと（2026-11-11）」）。
-   **状態の取得の応答に、無加工の表示用の Markdown と無効化した文字列の両方を入れる。** 拡張は無加工の表示用の Markdown を使わず、応答が記事 1 本分大きくなって、記事の大きさの上限が下がる。無加工の文字列は、保存するファイルの中身にある（0083 設計書「設計の際に決めたこと（2026-11-11）」）。

-   **Webhook への投稿の拒否の規則（無効化しない並びを含む記事を 1 通も送らない）を、コピーにも残す。** 実機の確かめで、拒否していた並びは貼り付けた後にメンションにならず、拒否するとコピーできない記事が生じる（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）。
-   **コピーで無効化したことを示さない。** 貼り付けた文章が見た目と違う文字を含むことに、利用者が気づけない（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **表示した記事を選択してコピーしたときも、ブラウザの `copy` イベントで捉えて通知する。** 利用者がボタンを操作していない場所に通知が出て分かりにくく、貼り付けた結果は表示の無効化ですでに安全である（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **コピーの通知に、無効化した `@` の数を示す。** 数を見ても利用者の次の行動は変わらず、有無で目的を果たせる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **直前が `/` の `@` を、URL のパスでも外でも変えない。** URL でない `AC/@名前` は、実機で通知された（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **直前が `/` の `@` を、URL のパスも含めてすべて無効化する。** `https://www.youtube.com/@ハンドル` のような URL が壊れる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **コードの範囲の中の `@` も無効化する。** 貼り付けたコードを写すと、見えない文字が混じる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **ビューアの表示は無効化せず、コピーする文章だけを無効化する。** issue #770 はこの形を決めていたが、表示した記事を選択してコピーすると、無効化されない文字が貼り付けられる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **チャンネル名の行を無効化の対象から外す。** チャンネル名は外部由来の値で、`@` を含みうる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。

## 結果

-   コピーした文章と表示した記事は、表示用の Markdown と U+200B の有無で異なる。ビューアのページ内検索や、貼り付けた後の文章の検索・比較で、U+200B のために `@名前` が一致しないことがある。
-   表示した記事を選択してコピーした場合は、無効化したことの通知が出ない。
-   保存したファイルの中身を貼り付けた場合は、無効化されない。
-   無効化が効くことは、確かめた版の Mattermost（サーバ 11.11.3）についてだけ言える。Slack と、確かめていない版では保証しない。
-   `<https://…|表示>` の形は、Mattermost に貼り付けるとリンクになる（行き先は `about:blank#blocked` で、メンションにはならない）。
-   こちらのコードの範囲や URL の判定と、Mattermost の判定が食い違う書き方では、変えなかった `@` がメンションになる。2026-11-11 に読んだ `master` の条件より狭く定めたが、読解していない版と形では保証しない。判定を変えるときは、Mattermost の扱いと比べる（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md) §4.2「セキュリティ (Security)」）。
-   Mattermost が自動リンクにする URL のうち、URL のパスの `/@` の定義より広い形（ポート付きのホスト、`_` を含むホストなど）は、コピーと表示で U+200B が入って壊れる。Mattermost がコードとして扱うのに判定できない本文とした書き方では、コードの中に U+200B が入る。
-   ビューアは、`<https://…>` の中に U+200B が入った自動リンクをリンクにせず、文字として表示する（リンクの条件は [ADR-0017](0017-viewer-markdown-rendering.md)）。
