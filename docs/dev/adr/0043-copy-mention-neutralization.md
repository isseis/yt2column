# ADR-0043: ビューアの表示とクリップボードへのコピーで記事のメンションを無効化し、コピーは拒否しない

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

利用者は、ビューアで記事を Markdown 形式でクリップボードへコピーし、Slack や Mattermost のチャンネルに手で貼り付けて共有する。表示した記事を選択してコピーすることもあり、長い記事は何回かに分けて貼り付けることもある。記事は LLM の出力で、タイトル・チャンネル名・本文は、字幕と動画メタデータへのプロンプトインジェクションで操作されうる。YouTube のハンドルは `@` で始まるので、概要欄やチャンネル名から `@名前` が記事に入りうる。貼り付けた `@channel`・`@here`・`@名前` は、チャンネル全体や個人への通知になる。

2026-11-11 に、Mattermost のチャンネルへの貼り付けを実機で確かめた（Mattermost サーバ 11.11.3、デスクトップアプリ 6.3.2）。`@channel`・`@here`・`@名前` はメンションになり、`@` の直後に U+200B を入れるとメンションにならなかった。URL でない `AC/@名前` は通知され、URL の中の `/@` と、コードスパンとフェンス付きコードブロックの中の `@` は通知されなかった。確かめた並びと結果は [0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」にある。Slack では確かめていない。

同じ日に、Mattermost のサーバのソース（`master` と、確かめた版のタグ `v11.11.3`）を読んだ。サーバは、段落のテキストのノードだけからメンションを探し、自動リンクとコードの中は探さない。Mattermost が自動リンクとする範囲の条件は、こちらが最初に定めた URL の判定と異なる。また、サーバは、メンションを探す前に文字参照（`&#64;` など）とバックスラッシュのエスケープを解く。解いた文字が前後とつながって 1 つの語になるかは、解析の内部の位置の扱いで決まり、読んだ版では `\@channel` が通知されうる。読解の内容は [0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)「Mattermost の判定との比較（H-06）」にある。

ビューアは、コードスパンのバッククォート、フェンスの行、`*` の強調の記号などを除いて描画する。表示した記事を選択してコピーすると、コードの中の `@` はコードの外の `@` として、`@**channel**` は `@channel` として貼り付けられる。

## 決定

-   **表示とコピーでは、対象の `@` を、U+200B を入れて無効化する。** 対象はタイトルの見出しの行、チャンネル名の行、本文（コードの中を含む）のすべてである。語の途中でない `@` は、直後の文字を問わずに対象にする。`@` を表しうる文字参照も対象にする。語の途中の `@` と、URL のパスの `/@` は変えない。URL のパスの `/@` は、Mattermost が自動リンクにする形より狭く定める。貼り付けた記事がメンションにならないようにするためである。コードの中の `@` と、直後に記法が続く `@` も対象にし、URL のパスの `/@` ではスキームの直前の文字を限るのは、選択によるコピーや分けた貼り付けでは、バッククォートや強調の記号などの記法が失われるためである。文字参照を対象にするのは、Mattermost が解いてからメンションを探し、解いた文字が前後の文字と合わせて 1 つの語になるかが版によって変わりうるためである。URL のパスの `/@` を変えないのは、`https://www.youtube.com/@ハンドル` のような URL を壊さないためであり、それを Mattermost の判定より狭く定めるのは、こちらが変えなかった `@` を Mattermost が通知しないようにするためである。チャンネル名の行を対象にするのは、チャンネル名が外部由来で `@` を含みうるためである。規則は [security.md](../security.md) §6「信頼できないテキストの取り扱い」と、0083 要件定義書 §3.1・F-002 にある。
-   **無効化は記事を作る処理の Go の部品（`internal/publisher`）で行い、拡張の WASM の入口が結果に入れる。ビューアは受け取った文字列を加工しない。** WASM の入口の結果の記事の `markdown` は無効化した表示用の Markdown で、無効化したかどうか（`mentionsNeutralized`）と、見出しに使う無効化した動画のタイトルとチャンネル名（`videoTitle`・`channelName`）を添える。保存するファイルの中身（`file`）は無効化しない。結果はジョブの記録に置き、ビューアは、表示とコピーに `markdown` を、完了した後の見出しに `videoTitle`・`channelName` を、そのまま使う。規則を Go の 1 か所に置き、拡張に同じ規則を二重に書かないためである。結果の形は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「入口が JavaScript に登録する関数」に、無効化の設計は [0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)にある。
-   **コピーは、記事の内容によって拒否しない。** URL のパスの `/@`、`<!`、`<a|b>` の形は、そのまま残す。実機の確かめで、どれも貼り付けた後にメンションにも通知にもならなかったためである。拒否すると、利用者はその記事をコピーできなくなる。規則は 0083 要件定義書 F-002 にある。
-   **無効化したことを、「Markdown をコピーする」ボタンの結果の通知で知らせる。数は示さない。** 1 個以上を無効化したときだけ示す。表示した記事を選択してブラウザでコピーしたときは通知しない。その操作にはビューアのボタンが関わらず、通知を出す場所が操作と結びつかないためである。貼り付けた文章が見た目と違う文字を含むことを、利用者が知れるようにするためである。数を見ても利用者の次の行動は変わらないので、有無だけを示す。規則は 0083 要件定義書 F-003 にある。
-   **ビューアの表示も、コピーと同じ規則で無効化する。** 表示する記事の文字には、コピーする文章と同じ位置に U+200B が入る。記事が完了した後は、記事の上の見出しの動画のタイトルとチャンネル名も、WASM の入口が無効化した値を表示する。利用者は表示した記事やページを選択してコピーすることがあり、ブラウザは描画した文字をコピーするためである。U+200B は目に見えないので、見た目は変わらない。規則は 0083 要件定義書 F-002 にある。
-   **保存するファイルと `--out` のファイルは無効化しない。** `--out` は開発用の CLI の出力で、エンドユーザー向けの機能ではなく、なるべく加工しないデータが要るためである。保存するファイルは `--out` のファイルと同じ中身である。規則は 0083 要件定義書 §2.3「スコープ外 (Out of Scope)」と F-002 にある。

WASM の入口が無効化した値を結果に入れることは、まだコードと security.md に反映していない。今は localhost サーバが状態の取得の応答に入れる。この差分は [#773](https://github.com/isseis/yt2column/issues/773) の実装で解消する。

## 採らなかった案

-   **Webhook への投稿の拒否の規則（無効化しない並びを含む記事を 1 通も送らない）を、コピーにも残す。** 実機の確かめで、拒否していた並びの多くは貼り付けた後にメンションにならず、拒否するとコピーできない記事が生じる（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）。
-   **コードの中の `@` を変えない。** 要件定義の際はこの形を決めていた。表示した記事を選択してコピーするか、記事を分けて貼り付けると、コードの中の `@` がコードの外の `@` として貼り付けられ、通知される（0083 要件定義書「設計の際に改めたこと（2026-11-11）」）。
-   **文字参照を変えずに残す。** 要件定義の際はこの形を決めていた。Mattermost のサーバは文字参照を解いてからメンションを探し、解いた文字が語につながるかは版によって変わりうる（0083 要件定義書「設計の際に改めたこと（2026-11-11）」）。
-   **直後に名前の文字が続く `@` だけを対象にする。** 要件定義の際はこの形を決めていた。ビューアは記法を除いて描画するので、選択によるコピーで `@**channel**` が `@channel` になる（0083 要件定義書「設計の際に改めたこと（2026-11-11）」）。
-   **URL のパスの `/@` を、ホストの後ろの `/` の直後の `@` と広く定める（0083 要件定義書の最初の定義）。** スキームの直前に英字がある形、ホストに `_` を含む形、`<`・`[` が先にある形など、Mattermost が自動リンクにしない形でも `@` を変えず、貼り付けると通知になる（0083 要件定義書「設計の際に改めたこと（2026-11-11）」）。
-   **直前が `/` の `@` を、URL のパスでも外でも変えない。** URL でない `AC/@名前` は、実機で通知された（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **直前が `/` の `@` を、URL のパスも含めてすべて無効化する。** `https://www.youtube.com/@ハンドル` のような URL が壊れる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **拡張（TypeScript）で無効化する。** 対象の `@` と URL の判定を TypeScript に書き直すと、規則が Go と二重になる（[0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)「設計の際に決めたこと（2026-11-11）」）。
-   **状態の取得の応答に、無加工の表示用の Markdown と無効化した文字列の両方を入れる。** 拡張は無加工の表示用の Markdown を使わず、応答が記事 1 本分大きくなって、記事の大きさの上限が下がる。無加工の文字列は、保存するファイルの中身にある（0083 設計書「設計の際に決めたこと（2026-11-11）」）。
-   **コピーで無効化したことを示さない。** 貼り付けた文章が見た目と違う文字を含むことに、利用者が気づけない（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **表示した記事を選択してコピーしたときも、ブラウザの `copy` イベントで捉えて通知する。** 利用者がボタンを操作していない場所に通知が出て分かりにくく、貼り付けた結果は表示の無効化ですでに安全である（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **コピーの通知に、無効化した `@` の数を示す。** 数を見ても利用者の次の行動は変わらず、有無で目的を果たせる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **ビューアの表示は無効化せず、コピーする文章だけを無効化する。** issue #770 はこの形を決めていたが、表示した記事を選択してコピーすると、無効化されない文字が貼り付けられる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **チャンネル名の行を無効化の対象から外す。** チャンネル名は外部由来の値で、`@` を含みうる（0083 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。

## 結果

-   コピーした文章と表示した記事は、表示用の Markdown と U+200B の有無で異なる。ビューアのページ内検索や、貼り付けた後の文章の検索・比較で、U+200B のために `@名前` が一致しないことがある。
-   コピーしたコードに `@` があると、見えない文字が混じる。そのコードを写して使うと、U+200B が入ったままになる。名前が続かない `@`（`@ ` など）と、名前付きの文字参照（`&amp;` など）の後ろにも U+200B が入る。
-   Mattermost が自動リンクにする URL のうち、URL のパスの `/@` の定義より広い形（ポート付きのホスト、`_` を含むホスト、記事の前のほうに `[` がある URL、`<` の直前が英字の `<https://…>` など）は、コピーと表示で U+200B が入って壊れる。ビューアは、U+200B が入った `<https://…>` をリンクにせず、文字として表示する（リンクの条件は [ADR-0017](0017-viewer-markdown-rendering.md)）。
-   表示した記事を選択してコピーした場合は、無効化したことの通知が出ない。変えなかった `@` の直前で切って貼り付けた場合（URL の `/@handle` だけ、`Tech@here` の `@here` だけ）は、その `@` がメンションになりうる。
-   保存したファイルの中身を貼り付けた場合は、無効化されない。
-   記事が完了する前のビューアの見出しと、動画のタイトルが送られなかったときの見出しのタイトルは、拡張が読んだ値のままで、無効化しない。
-   無効化が効くことは、確かめた版の Mattermost（サーバ 11.11.3）についてだけ言える。Slack と、確かめていない版では保証しない。Mattermost の自動リンクや文字参照の扱いが変わったら、判定を比べ直す（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md) §4.2「セキュリティ (Security)」）。
-   `<https://…|表示>` の形は、Mattermost に貼り付けるとリンクになる（行き先は `about:blank#blocked` で、メンションにはならない）。
-   利用者が設定したキーワードや名前による、`@` のない通知は防がない。

## 経緯

- 2026-11-11 Webhook への投稿の廃止に合わせて、メンションの無効化をビューアの表示とコピーに移した。コピーは拒否せず、URL のパス以外の `/@` とチャンネル名の行も対象にし、無効化したことを通知で示す（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）
- 2026-11-11 Mattermost のサーバのソースの読解に基づき、URL のパスの `/@` を Mattermost が自動リンクにする形だけに狭めた。あわせて、コードの中の `@`、`@` を表しうる文字参照、直後の文字を問わない `@`、完了した後のビューアの見出しも無効化することにした。また、URL のスキームの直前の文字と `[` の条件は、選択によるコピーで記法や段落の切れ目が失われても効くように限ることにした。無効化はサーバで行い、ビューアは受け取った文字列を加工しない（[0083 設計書](../../tasks/0083_remove_slack_webhook/02_architecture.md)「設計の際に決めたこと（2026-11-11）」）
- 2026-11-12 無効化を行う場所を、localhost サーバから、記事を作る処理を共有する拡張の WASM の入口に移した。値は WASM の入口の結果に入れ、ジョブの記録を経てビューアが使う（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)）
