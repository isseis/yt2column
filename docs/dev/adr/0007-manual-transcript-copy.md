# ADR-0007: 字幕は利用者が文字起こしパネルから手動でコピーし、拡張はページを読むだけにする

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

CLI は字幕の取得を `yt-dlp` に委譲しているが、`yt-dlp` は YouTube から HTTP 429 を繰り返し受けることがある。そこで、主経路では字幕の取得を利用者に任せ、利用者が YouTube の文字起こしパネルで選択した文字列を、拡張がサーバへ送る方式にした（[0015 要件定義書](../../tasks/0015_copied_transcript_source/01_requirements.md) §1）。

パネルの書式は YouTube が独自に定めるもので、要素の構成が同じまま中身の形が変わりうる。0029 では、利用者が文字列を選択していないときにパネルの DOM から字幕を読む案を設計したが、観測のゲートの結果、取り下げた（[0029 の観測のゲートのレビュー](../../tasks/0029_transcript_panel_read/observation_gate_review.md)）。

## 決定

-   **主経路の字幕の入力は、利用者が文字起こしパネルで選択した文字列とする。** 拡張は、起動したタブの選択範囲を `window.getSelection()` で読み、その文字列と動画の URL をサーバへ送る。拡張はクリップボードを読まず、パネルの DOM も読まない。利用者の選択を書き換えず、パネルを開く操作もしない。
-   **サーバは、受け取った文字列を `CopiedSource` で解析する。** 解析は `NewCopiedSource` の構築時に 1 回だけ行い、`Fetch` では再解析しない。サーバは `yt-dlp` を呼ばない（[ADR-0005](0005-server-architecture.md)）。受理する書式は [0015 設計書](../../tasks/0015_copied_transcript_source/02_architecture.md) と [0024 要件定義書](../../tasks/0024_copied_transcript_panel_lines/01_requirements.md) F-001・F-007・F-008 が定める。
-   **拡張はページを読むだけで、ページを操作しない。** 動画タイトル・チャンネル名・概要欄は、収集が成功したときだけ、起動したタブの DOM から読む。クリック・スクロール・フォーカス・入力を行わず、概要欄の「…もっと見る」も開かない。読む時点のページの URL が収集した URL と一致しない場合は、別の動画の値を混ぜないよう 3 つの値をすべて省略する。取得に失敗しても起動を失敗させず、値を省略する。
-   **パーサは、観測した 2 つの形だけを受理する。** 形 A と形 B をそれぞれ定義し、前置き、形 A のチャプターの見出し、形 B の時刻を期待する位置の見出し、末尾の操作ラベルを読み飛ばす。形 A では、定めた行以外のセグメントでない行を拒否し、未知の表記を推測で受理しない。表記の揺れを補正せず、受理しない入力は `ErrCopiedTranscriptFormat` で拒否する。
-   **CLI は `yt-dlp` の経路を代わりの手段として残す。** パネルの書式が変わって拒否が続く間は、`YtDlpSource` を使う CLI の経路で字幕を取得できる。
-   **パネルの DOM から字幕を読む方式は採らない。** 観測した 2 つの版のどちらにも、パネルの中身と動画を結びつける信号がなかった。SPA の画面遷移の後に前の動画の字幕を送ることを送信前に確かめられず、要素の構成が同じまま中身の形が変わる変更は、拒否されずに誤った字幕を送る。YouTube の非公式な仕様に依存する最も壊れやすい部分は、保守が活発なツールに任せるという方針にも逆らう。

この決定の仕様の正本は [project_overview.md](../project_overview.md) の「決定済みの方針」の字幕取得と「パイプライン」、[security.md](../security.md) §8.1「ブラウザ拡張」である。

## 採らなかった案

-   **文字起こしパネルの DOM から字幕を読む（0029 の当初の設計）。** どの版のパネルにも、中身と動画を結びつける信号がなく、SPA の画面遷移の後に前の動画の字幕を誤って送らないかを送信前に確かめられない。要素の構成が同じで中身の形や意味が変わる変更は、拒否されずに誤った字幕を送り、利用者が誤った記事を見て初めて分かる。観測のゲートでは、案 B（古い版の 1 つの変種だけを読む）、案 C（選択範囲が空ならサーバが `yt-dlp` で字幕を取る）、案 D（設計を直して続ける）も検討し、いずれも採用しなかった。案 B は対象になる動画が限られ、動画と結びつける信号がない問題が残る。案 C はサーバが `yt-dlp` を呼ばないという決定を変えることになる。案 D は信号の問題が解けず、費用が続く（[0029 の観測のゲートのレビュー](../../tasks/0029_transcript_panel_read/observation_gate_review.md) §4）。
-   **拡張が YouTube の内部 API から字幕を取る。** 書き起こしパネルの API（`/youtubei/v1/get_transcript`）や、プレーヤーの字幕トラック（`/api/timedtext`）を、拡張がページの中から呼ぶ案である。どちらも Innertube の非公開の API で、正規のクライアントを装ってリクエストを組み立てる必要がある。`/api/timedtext` は PO トークン（YouTube のボット対策の仕組みが出力する値）を求めることがあり、取得するには、プレーヤーが使ったトークンを拾って付け直すなどの回避が要る。これらは [YouTube 利用規約](https://www.youtube.com/static?template=terms)の「許可と制限事項」が禁じる、明示的に許可されていない方法でのアクセスやダウンロード、本サービスの迂回、自動化された手段によるアクセスに当たりうる。YouTube の非公式な仕様を自分で保守することにもなる。PO トークンを拾うためにプレーヤーの字幕ボタンを押すなど、ページの操作も伴いうる。他のツールがこれらの方法をどう使っているかは、[文字起こしの取得方法の調査](../../research/transcript_acquisition/README.md)に記録している。
-   **パネルを複数回に分けてコピーし、つなげて送る。** つなげる際の重複の一部は時刻の減少として拒否されるが、欠落は検出できない（[0015 設計書](../../tasks/0015_copied_transcript_source/02_architecture.md) §1.4.2）。
-   **形 A と形 B を相互に変換・正規化する。** 一方から他方へ変換すると、元の入力を変えることになり、`CLAUDE.md`「Reject, don't normalize」に反する（[0015 要件定義書](../../tasks/0015_copied_transcript_source/01_requirements.md) §2.3）。
-   **形 A の見出しを位置から推測して無視する（0015 の規則）。** 0015 では、位置で見出しを推測して無視する形にしなかった。拡張は選択範囲をそのまま送り、見出しを除かないためである。0024 で、形 B の見出しに限ってこの規則を反転した。実データで見出しが時刻を期待する位置に現れ、それ以外の方法では特定できないためである（[0015 要件定義書](../../tasks/0015_copied_transcript_source/01_requirements.md) F-002、[0024 要件定義書](../../tasks/0024_copied_transcript_panel_lines/01_requirements.md) F-008）。
-   **表記の揺れを吸収して受理する。** ゆるく受理すると本文の分割が黙ってずれ、拒否は利用者が気づけるが、誤った分割は気づかれないまま記事の生成に流れる（[0015 設計書](../../tasks/0015_copied_transcript_source/02_architecture.md) §1.1）。
-   **拡張が概要欄の「…もっと見る」をクリックして全文を取る。** ページを操作すると、読むだけの振る舞いが変わる（[0025 要件定義書](../../tasks/0025_extension_video_metadata/01_requirements.md) §1）。
-   **`window.ytInitialPlayerResponse` から動画メタデータを取る。** ページ内の移動の後に古い値を残す（[0025 要件定義書](../../tasks/0025_extension_video_metadata/01_requirements.md) §2.3）。

## 結果

-   利用者は、字幕を送る前にパネルで文字列を選択する。長い動画では選択の負担がある。選択を軽くする案内は設けていない。
-   字幕の取得は、YouTube のページの構造ではなく、コピーした文字列の書式だけに依存する。書式が変わればパーサが拒否し、利用者は CLI の `yt-dlp` の経路を使える。
-   拡張はページを操作しないので、読み取りが返らない場合に起動が止まりうる。このリスクは受け入れ、読み取りの上限時間を設けない（[0025 設計書](../../tasks/0025_extension_video_metadata/02_architecture.md) §5.4）。
-   形 B では、時刻を期待する位置の任意の非時刻行を読み飛ばすので、タイムスタンプの行が 1 行欠けた入力でも、そのセグメントの本文を黙って失いうる。未知の行を拒否して YouTube の UI の変更を検出する性質は、形 B では弱まる（[0024 要件定義書](../../tasks/0024_copied_transcript_panel_lines/01_requirements.md) F-008）。
-   動画メタデータは DOM に依存するので、取れなければ省略される。記事の生成は続く。
-   **YouTube 利用規約との関係。** 主経路の拡張は、利用者が YouTube の正規の UI で表示して選択した文字列を、利用者の操作を受けて読むだけである。リクエストを偽装せず、ボット対策を迂回しない。一方、CLI の `yt-dlp` の経路では、`yt-dlp` が Innertube のクライアントを装い、PO トークンを扱って字幕を取る。この経路は[利用規約](https://www.youtube.com/static?template=terms)の「許可と制限事項」に抵触しうる。利用者 1 人の開発用の経路として、このリスクを受け入れる。他人の動画の字幕を、規約がはっきり許す方法で取る手段はない（YouTube Data API の `captions.download` は、その動画を編集する権限を要する）。

## 経緯

- 2026-10-14 主経路の字幕を、利用者が文字起こしパネルからコピーした文字列を `CopiedSource` が解析する形にした。パネルの書式への依存はこのパーサに限り、`yt-dlp` の経路は代わりの手段として残した（[0015 要件定義書](../../tasks/0015_copied_transcript_source/01_requirements.md)）
- 2026-10-17 拡張が動画ページの DOM から動画タイトル・チャンネル名・概要欄を読むが、ページを操作せず、取得できた値だけを送るようにした（[0025 要件定義書](../../tasks/0025_extension_video_metadata/01_requirements.md)）
- 2026-10-18 パーサが、前置き・チャプターの見出し・末尾の領域を明示的に定義して読み飛ばし、形 A の未知の行は拒否するようにした（[0024 要件定義書](../../tasks/0024_copied_transcript_panel_lines/01_requirements.md) F-001・F-007・F-008）
- 2026-10-20 文字起こしパネルの DOM から字幕を読む案を、観測のゲートの結果を受けて取り下げ、字幕の取得は利用者の手動の選択に任せ続けた（[0029 の観測のゲートのレビュー](../../tasks/0029_transcript_panel_read/observation_gate_review.md)）
