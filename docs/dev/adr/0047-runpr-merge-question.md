# ADR-0047: /runpr のマージの質問は 1 つの単一選択の問いにし、詳細は作業ツリーの外のファイルに書いて会話には要約だけを出し、deferred のスレッドはその前に片付ける

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

`/runpr` は、PR をマージする前に 1 回だけ利用者に尋ね、PRE_MERGE、マージ、次のコマンドの扱いを決める（マージの質問）。この質問のメッセージには、承認に要る項目（squash commit の件名と本文の全文など）と、PRE_MERGE、diff 記録の再記録、レビューのスレッド、NEXT とモデルなどをすべて出していた。1 回の `AskUserQuestion` に最大 3 問と最大 5 つの選択肢があり、表示が画面に収まらなかった。特に OpenCode では選択肢が画面の外へ押し出され、選べなくなった（[0089 要件定義書](../../tasks/0089_runpr_merge_question/01_requirements.md) §1）。

`/runpr` は OpenCode で走り（[ADR-0046](0046-chief-of-staff.md)）、マージの後の次のコマンドは chief が送る。`AskUserQuestion` の 1 問の選択肢は 4 つまでである。

## 決定

以下の決定の仕様は、[0089 要件定義書](../../tasks/0089_runpr_merge_question/01_requirements.md) の機能要件が持ち、実装の後は [runpr.md](../../../.claude/commands/runpr.md) の「4. Confirm, record, and merge」と [mergepr.md](../../../.claude/commands/mergepr.md) の step 3 が持つ。

-   **deferred のスレッドは、マージの質問より前に、別の単一選択の問いで、直すか追跡 issue に移すかを人が選んで片付ける。** 直すか移すかは、マージするかどうかとは別の判断で、片付けてからマージを判断するべきだからである。マージの質問の選択肢を 4 つまでに収めるためでもある（F-001）。
-   **マージの質問は、1 つの問いだけを持つ単一選択の `AskUserQuestion` にする。選択肢は「先に PR レビューを依頼」「マージ」「承認なしでマージ」か「通常の進め方へ戻す」「マージしない」のうち、条件に合うものだけを示す。** 選択肢を画面に収めるためである。Escalation の判定が `ask` のときは「先に PR レビューを依頼」を推奨にし、それ以外のときは「マージ」を推奨にする。推奨は 1 つしか示せないので、今の規則を保つ形に決めた（F-003）。
-   **マージの質問に、NEXT をその `/runpr` のセッションで実行する選択肢を置かない。`/runpr` は NEXT を示すだけで、実行しない。** 次のコマンドは chief が送るためである（ADR-0046）。step 5 が NEXT の前に `/clear` を勧めていることとも食い違っていた（F-003）。
-   **承認の判断に要る詳細は、マージの質問のたびに作業ツリーの外の詳細ファイルに書き直し、会話には 1 項目 1 行の要約と、そのファイルのパスだけを出す。question の文は 1 行にし、長い本文を question の欄にも選択肢にも入れない。** 本文が多い PR でも、要約と選択肢を画面に収めるためである。問いのたびに書き直すのは、古い中身で承認しないためである（F-002）。
-   **`/runpr` の中では、squash commit の件名を要約に、本文と接頭辞を決めた規則の記録を詳細ファイルに示して承認を尋ねる。単独で実行する `/mergepr` は、件名と本文の全文を会話に示す。** 本文は長くなりやすく、要約を画面に収めるためである。単独の `/mergepr` は、承認に要る項目だけを示すので画面に収まる（F-004）。
-   **3 文書の PR の「通常の進め方へ戻す」と除外スレッドは、マージの質問で示す。** [ADR-0040](0040-simple-task-documents.md) の決定を変えないためである。除外スレッドの判定を覆すスレッドは、番号を自由記述で指定する（F-003）。

この決定は、まだ `runpr.md`・`mergepr.md` と、それを説明する文書に反映していない。このずれは [#857](https://github.com/isseis/yt2column/issues/857)（タスク 0089）の実装で解消する。

## 採らなかった案

-   **「承認なしでマージ」と「通常の進め方へ戻す」を選択肢から外し、自由記述だけで受け付ける（issue #857 の案）。** 「通常の進め方へ戻す」を自由記述だけにするのは、ADR-0040 が戻せることに人が気づきにくいとして採らなかった案に当たる。不要な選択肢は「NEXT をこのセッションで実行」だけである（0089 要件定義書「要件定義の際に決めたこと（2026-11-12）」）。
-   **deferred のスレッドを、マージの質問の選択肢か自由記述で扱う。** マージの時点で扱うのは遅く、片付けてからマージを判断するべきである（同上）。
-   **squash commit の件名と本文の全文を、今までどおり会話に出す。** 本文が長い PR では、要約が画面からはみ出す（同上）。
-   **Escalation の判定が `ask` のときも、「マージ」を推奨にする。** 今は PR レビューの問いで「先に PR レビューを依頼」を推奨にしており、それを保つ（同上）。

## 結果

-   利用者は、squash commit の本文、PRE_MERGE の行、diff 記録の再記録の中身を、詳細ファイルを開いて読む。要約は、承認の判断に関わるものがあることを種類ごとの 1 行で示す。
-   deferred のスレッドがある PR では、マージの質問の前にもう 1 つ問いが増える。
-   NEXT を `/runpr` と同じセッションで続けて走らせる手段はなくなる。人が `/clear` してから実行するか、chief が送る。
-   自由記述でだけ受け付ける操作（メッセージを直すこと、除外スレッドの判定を覆すこと）は、chief が中継しない（ADR-0046）ので、人がその pane で答える。

## 経緯

- 2026-11-12 マージの質問を 1 つの単一選択の問いにし、詳細を作業ツリーの外のファイルに書いて会話には要約だけを出し、deferred のスレッドをその前の問いで片付け、NEXT を続けて実行する選択肢を除くことにした。`/runpr` の中では、squash commit の本文を詳細ファイルで示すことにした（[0089 要件定義書](../../tasks/0089_runpr_merge_question/01_requirements.md)「要件定義の際に決めたこと（2026-11-12）」）
