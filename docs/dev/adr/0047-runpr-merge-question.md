# ADR-0047: /runpr のマージの質問は 1 つの単一選択の問いにし、詳細は作業ツリーの外のファイルに書いて会話には要約だけを出し、deferred のスレッドはその前に片付ける

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

`/runpr` は、PR をマージする前に 1 回だけ利用者に尋ね、PRE_MERGE（マージ直前の記録コミット）、マージ、次のコマンド（NEXT）の扱いを決める（マージの質問）。この質問のメッセージには、承認に要る項目（squash commit の件名と本文の全文など）と、PRE_MERGE、diff 記録の再記録、レビューのスレッド、NEXT とモデルなどをすべて出していた。1 回の `AskUserQuestion` に最大 3 問があり、表示が画面に収まらなかった。3 問を 1 つにまとめると、どれかの選択肢を外さない限り、1 問の選択肢が 4 つを超える。特に OpenCode では選択肢が画面の外へ押し出され、選べなくなった（[0089 要件定義書](../../tasks/0089_runpr_merge_question/01_requirements.md) §1）。

`/runpr` は OpenCode で走り（[ADR-0046](0046-chief-of-staff.md)）、マージの後の次のコマンドは chief が送る。`AskUserQuestion` の 1 問の選択肢は 4 つまでである。

## 決定

`/runpr` のマージの質問はハーネス非依存の単一選択の 1 問（[ADR-0055](0055-harness-independent-commands.md)）にし、詳細は作業ツリー外の詳細ファイルに出して会話には要約だけを示し、deferred のスレッドや受け付けない訂正の行の問いはその前に別の単一選択の問いで片付ける。仕様は [0089 要件定義書](../../tasks/0089_runpr_merge_question/01_requirements.md) の機能要件と [0120 要件定義書](../../tasks/0120_harness_independent_commands/01_requirements.md) の F-001 に定め、手順は [runpr.md](../../../.claude/commands/runpr.md) の step 4 と [mergepr.md](../../../.claude/commands/mergepr.md) の step 3 に置く。

-   **deferred スレッドの事前の片付け:** マージの質問より前に、別の単一選択の問いで、直すか追跡 issue に移すかを人が選んで片付ける。一部だけを直すときは、番号を自由記述で指定する。3 文書の PR では、この問いからも通常の進め方へ戻せる。分けるのは、直すか移すかがマージするかどうかとは別の判断であり、マージの質問の選択肢を 4 つまでに収めるためでもある。単一選択にするのは、chief が中継するのが 1 つを選ぶ問いだけだからである（[ADR-0046](0046-chief-of-staff.md)）。戻せるようにするのは、戻すときに deferred のスレッドの懸念を申し送りのファイルに残す [ADR-0040](0040-simple-task-documents.md) の扱いを保つためである（0089 要件定義書の F-001）。
-   **マージの質問の形式と選択肢:** 1 つの問いだけを持つハーネス非依存の単一選択の質問操作（Claude Code では `AskUserQuestion`、Antigravity では `ask_question`。[ADR-0055](0055-harness-independent-commands.md)）にする。選択肢は「先に PR レビューを依頼」「マージ」「承認なしでマージ」「通常の進め方へ戻す」「マージしない」のうち、条件に合うものだけを示す（「承認なしでマージ」と「通常の進め方へ戻す」は同時には示さない）。選択肢を画面と 4 択制約に収めるためである。PR レビューの併用対象（CodeRabbit と Sourcery AI）のうち `head` が未レビューのレビュアーが 1 社以上残っていれば「先に PR レビューを依頼」を示し、選んだ直後に別の単一選択の 1 問（「CodeRabbit」「Sourcery AI」「マージの質問に戻る」）で依頼先を選ぶ（[0122 要件定義書](../../tasks/0122_sourcery_trusted_reviewer/01_requirements.md) の F-004）。エスカレーションの判定が PR レビューを勧めるとき、すなわち直近の PR レビュー済みコミット `LAST_REVIEWED`（完了した PR レビューがなければ `none`）が `head` より古いコミットまたは `none` であり、かつ基準に当たるときは「先に PR レビューを依頼」を推奨にし、それ以外のとき（`LAST_REVIEWED == head` の場合を含む）は「マージ」を推奨にする。推奨は 1 つしか示せないので、今の規則を保つ形に決めた（0089 要件定義書の F-003）。勧めるのは、変更が信頼の境界・セキュリティ・耐久性の基準に当たるときと、ほかの基準にだけ当たり、ローカルの CLI レビューがすべてを見たと分からないときである。信頼の境界・セキュリティ・耐久性の基準に当たるときは、これまで自動で PR レビューを頼んでいたが、PR レビューを利用者が選んだときだけ頼むことにしたので、推奨に移した（[0118 要件定義書](../../tasks/0118_codex_removal/01_requirements.md) の F-005）。判定が迷ったとき、答えが決まった形でないとき、判定を走らせられなかったときも、今と同じく「先に PR レビューを依頼」を推奨にする。
    -   **食い違い:** `runpr.md` と `mergepr.md` はまだ `AskUserQuestion` を直接指定している（https://github.com/isseis/yt2column/issues/1072 の実装で解消する）。また、`runpr.md` のマージの質問はまだ単一のレビュアー（CodeRabbit）を前提にしており、依頼先を選ぶ 1 問と複数レビュアー向けの表示条件は未実装である（https://github.com/isseis/yt2column/issues/1095 の実装で解消する）。
-   **NEXT の扱い:** マージの質問に、NEXT をその `/runpr` のセッションで実行する選択肢を置かない。`/runpr` は NEXT を示すだけで、実行しない。次のコマンドは chief が送るためであり（[ADR-0046](0046-chief-of-staff.md)）、step 5 が NEXT の前に `/clear` を勧めていることとも食い違っていたためである（0089 要件定義書の F-003）。
-   **詳細ファイルへの分離と要約表示:** 承認の判断に要る詳細は、マージの質問のたびに作業ツリーの外の詳細ファイルに書き直し、会話には 1 項目 1 行の要約と、そのファイルのパスだけを出す。質問文は 1 行にし、長い本文を質問欄にも選択肢にも入れない。本文が多い PR でも要約と選択肢を画面に収め、古い中身で承認しないようにするためである（0089 要件定義書の F-002）。
-   **`/runpr` と単独 `/mergepr` の表示の使い分け:** `/runpr` の中では、squash commit の件名を要約に、本文と接頭辞を決めた規則の記録を詳細ファイルに示して承認を尋ねる。単独で実行する `/mergepr` は、件名と本文の全文を会話に示す。本文は長くなりやすく `/runpr` では要約を画面に収める必要がある一方、単独の `/mergepr` は承認に要る項目だけを示すので画面に収まるためである（0089 要件定義書の F-004）。
-   **受け付けない文字を含む訂正行の事前の問い:** PR のコミットの訂正の行に受け付けない文字を含む行があるときは、マージの質問の前に、該当するすべての行について 1 つの単一選択の問いで、すべて落とすか、ブランチで直すために止まるかを人が選ぶ。行ごとの報告は詳細ファイルに書く。マージの質問では、訂正の行を落とす答えを `C<番号>:<場合>` の形の自由記述で受け付け、訂正の行があるときだけ要約にその項目を出す。受け付けない文字を含む行を `main` に写さないことと落とす場合を限ることは [ADR-0039](0039-adr-writing-criteria.md) の決定で、どの場合を落とせるかは [0106 要件定義書](../../tasks/0106_squash_editorial_corrections/01_requirements.md) の F-004 が持つ。ブランチで直すときは行によらず `/mergepr` をやり直すので、行ごとに問うても選べる組み合わせは増えない。単一選択にするのは、chief が中継するのが 1 つを選ぶ問いだけだからである（[ADR-0046](0046-chief-of-staff.md)）。`C` を付けるのは、除外スレッドの判定を覆す数字だけの答えと見分けるためである（[0106 設計書](../../tasks/0106_squash_editorial_corrections/02_architecture.md)「1.2. 設計の際に決めたこと（2026-11-19）」）。
-   **3 文書 PR の差し戻しと除外スレッド:** 3 文書の PR の「通常の進め方へ戻す」と除外スレッドは、マージの質問で示す。[ADR-0040](0040-simple-task-documents.md) の決定を保つためである。deferred の問いからも戻せるようにしたことで、ADR-0040 の戻す入口が 1 つ増えた。除外スレッドの判定を覆すスレッドは、番号を自由記述で指定する（0089 要件定義書の F-003）。

## 採らなかった案

採らなかった案は、選択肢の 4 択制約や単一選択の中継を崩す案、または判断に必要な操作や表示を過度に省く案である。

-   「承認なしでマージ」と「通常の進め方へ戻す」を選択肢から外し、自由記述だけで受け付ける（issue #857 の案）。「通常の進め方へ戻す」を自由記述だけにするのは、ADR-0040 が戻せることに人が気づきにくいとして採らなかった案に当たる。不要な選択肢は「NEXT をこのセッションで実行」だけである（0089 要件定義書「要件定義の際に決めたこと（2026-11-12）」）。
-   deferred のスレッドを、マージの質問の選択肢か自由記述で扱う。マージの時点で扱うのは遅く、片付けてからマージを判断するべきである（同上）。
-   deferred のスレッドが 1〜3 件のときは、今までどおりスレッドごとに選ぶ複数選択の問いにする。複数を選ぶ問いは chief が中継しない（同上）。
-   squash commit の件名と本文の全文を、今までどおり会話に出す。本文が長い PR では、要約が画面からはみ出す（同上）。
-   エスカレーションの判定が `ask` のときも、「マージ」を推奨にする。`ask` は、ローカルの CLI レビューでは代わりにならない変更かもしれないという判定である。推奨はそのまま選ばれやすいので、「マージ」を推奨にすると、その変更が PR レビューを経ずにマージされることを既定の答えにしてしまう。また、レビューを推奨にして不要だったときの損は PR レビュー 1 回分の割り当てで済むが、マージを推奨にしてレビューが要ったときは、レビューされていない変更が `main` に入る（[pr-review-escalation.md](../../../.claude/commands/_lib/pr-review-escalation.md)）。今の PR レビューの問いも、`ask` のときは「先に PR レビューを依頼」を推奨にしている（同上）。
-   受け付けない文字を含む訂正の行を、行ごとに別の問いで聞く。ブランチで直すときは行によらず `/mergepr` をやり直すので、選べる組み合わせは増えず、問いの数だけが増える（[0106 設計書](../../tasks/0106_squash_editorial_corrections/02_architecture.md)「1.2. 設計の際に決めたこと（2026-11-19）」）。
-   マージの質問に CodeRabbit と Sourcery AI の依頼選択肢を 2 つ並べる、または「先に PR レビューを依頼」を CodeRabbit に固定する。2 つ並べると最大 4 択の制約を超える。CodeRabbit に固定すると `/runpr` から Sourcery AI へ手動再依頼できない（[0122 要件定義書](../../tasks/0122_sourcery_trusted_reviewer/01_requirements.md)「要件定義の際に決めたこと（2026-11-23）」）。
-   `LAST_REVIEWED == head` のときは「先に PR レビューを依頼」を表示しない。Sourcery AI の自動の PR レビューが完了した `head` に対して、信頼の境界の変更などで CodeRabbit の追加レビューを `/runpr` から頼めなくなる（同上）。

## 結果

マージの質問は 4 択の単一選択と簡潔な要約に収まり、詳細な確認は詳細ファイルに分離される。

-   利用者は、squash commit の本文、PRE_MERGE の行、diff 記録の再記録の中身を、詳細ファイルを開いて読む。要約は、承認の判断に関わるものがあることを種類ごとの 1 行で示す。
-   deferred のスレッドがある PR では、マージの質問の前にもう 1 つ問いが増える。
-   追跡 issue に移した deferred のスレッドは、後でマージしない答えを選んでも、移して解決した状態のまま残る。
-   deferred のスレッドが 1〜3 件のときも、スレッドごとに選ぶ複数選択の問いはなく、番号を自由記述で書く。
-   NEXT を `/runpr` と同じセッションで続けて走らせる手段はなくなる。人が `/clear` してから実行するか、chief が送る。
-   自由記述でだけ受け付ける操作（メッセージを直すこと、除外スレッドの判定を覆すこと）は、chief が中継しない（ADR-0046）ので、人がその pane で答える。
-   受け付けない文字を含む訂正の行がある PR では、マージの質問の前にもう 1 つ問いが増える。訂正の行を落とす答えも自由記述なので、chief は中継せず、人がその pane で答える。
-   「先に PR レビューを依頼」を選んだときは、依頼先（CodeRabbit・Sourcery AI・マージの質問に戻る）を選ぶ単一選択の問いが 1 つ増える。単一選択なので chief が中継できる。
