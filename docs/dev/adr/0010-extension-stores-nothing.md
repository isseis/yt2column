# ADR-0010: 拡張は何も保存せず、権限も加えず、状態の正しい値をサーバに置く

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

ブラウザ拡張は、字幕と動画メタデータをサーバへ送り、記事をビューアに表示する。拡張が設定や記事の状態を保存すると、保存した値の更新と、保存の権限の管理が要る。Service Worker はブラウザによっていつでも停止されるので、そのメモリだけを状態の正しい置き場所にはできない。

当初は、共有トークンとサーバのポートを `chrome.storage.local` に保存していた（[0020 要件定義書](../../tasks/0020_extension_send/01_requirements.md) §1）。0026 で共有トークンとポートを削除し、0050 でビューアを加えたときに、拡張が何を保存するかを改めて定めた。

## 決定

-   **拡張は `chrome.storage` を使わない。** 共有トークン・ポート・そのほかの設定を保存せず、オプションページも持たない。送信ごとの値は、ビューアの URL と各ページのメモリにだけ置く。Service Worker のメモリにある値は、ビューアに届けるまでの短い間だけのものである。
-   **要求する権限は `activeTab`・`scripting`・`nativeMessaging` の 3 つだけにする。** `host_permissions`・`storage`・`options_ui`・`tabs`・`downloads`・`clipboardWrite` を加えず、ページの読み込み時に自動で実行されるコード（`content_scripts`）も宣言しない（起動の経路は [ADR-0008](0008-launch-path.md)）。
-   **権限を広げずに、ビューアを開き、保存し、コピーする。** ビューアのタブは `chrome.tabs` の権限の要らない操作（作成・選択・削除・取得）で開き、`chrome.windows.update` で前面に出す。記事の保存は拡張のページからの Blob のダウンロードで、コピーは利用者の操作の中のクリップボードへの書き込みで行う。
-   **状態の正しい値はサーバに置く。** 生成・状態・投稿の状態はサーバが持ち、Service Worker は生成の開始を 1 回送るだけで、ポーリングはしない。ポップアップとビューアは、記事のキーを使って自分で状態の取得を送る。Service Worker が停止しても、キーを受け取った後の表示は失われない。
-   **サーバの状態はメモリにだけ置く。** 記事のキャッシュはサーバのプロセスの中だけにあり、ディスクに書かない（サーバの構成は [ADR-0005](0005-server-architecture.md)）。サーバを再起動すると、記事と投稿の状態はすべて失われ、ビューアは記事が失われたことを示す。これは受け入れる。
-   **古い版が保存した値は、読めないまま残ることを受け入れる。** 0020 の版が `chrome.storage.local` に保存した共有トークンとポートは、拡張を更新しても残りうる。拡張は `storage` の権限を持たないので、これを読むことも削除することもできない。新しいサーバはトークンを読まないので、残った値が通用する相手はない。
-   **ビューアの URL に持つ値は、ブラウザの履歴に残ることを受け入れる。** 見出し・チャンネル名・動画タイトル・動画の URL・送信の時刻と、受け付けた後は記事のキーを URL に持つ。コピーした字幕と概要欄は URL に入れない。

この決定の仕様の正本は [security.md](../security.md) §8.1「ブラウザ拡張」と §8.2「localhost サーバ」、[project_overview.md](../project_overview.md)、[extension/static/manifest.json](../../../extension/static/manifest.json) である。

## 採らなかった案

-   **共有トークンを `chrome.storage.sync` に保存する。** トークンがブラウザの外へ出る（[0020 要件定義書](../../tasks/0020_extension_send/01_requirements.md) §1）。
-   **共有トークンを残して認証を続ける。** 同一ユーザーのフル権限プロセスはトークンのファイルも `.envrc` も読めるので、トークンを残しても防げない（[0026 要件定義書](../../tasks/0026_native_messaging_relay/01_requirements.md) §4.2）。
-   **古い版の値を削除するために `storage` の権限を残す。** 0027 で Service Worker をなくしたので `chrome.runtime.onInstalled` を受け取れず、削除の処理を置く場所がない。ポップアップを開くたびに削除する形にすると、1 回の削除のために `storage` の権限を持ち続けることになる（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §3.7.1）。
-   **古い版が保存した値を、更新時に削除する。** 残しても害がない。新しいサーバはトークンを読まないので、残った値が通用する相手はない。値はプロファイルのディレクトリにあり、読めるのは同一ユーザーのプロセスだけである（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §3.7.1）。
-   **`downloads`・`clipboardWrite`・`tabs`・`storage`・host permission を加えて、保存・コピー・ビューアを実装する。** 権限の範囲を今より広げないためである（[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) §1）。
-   **最近の記事の一覧を設け、記事や入力を拡張に保存する。** 「設定を保存しない」という今の性質を保ち、権限を加えずに済ませるためである（[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) §1）。

## 結果

-   拡張のプロファイルに残るのは、ブラウザの履歴に残るビューアの URL と、0020 の版が残した読めない値だけである。拡張は設定を持たないので、設定の移行も要らない。
-   状態の表示はサーバへの状態の取得で行うので、Service Worker が停止しても、ビューアとポップアップは最新の状態を表示できる。
-   サーバを再起動すると記事と投稿の状態が失われる。利用者は記事を作り直す。投稿済みの記事を送り直すと、同じ内容がもう一度投稿されうる。
-   拡張の権限は、利用者が起動したタブの読み取りと、固定のホストへの送信に限られる。閲覧内容全般に及ぶ権限を持たない。

## 経緯

- 2026-10-15 共有トークンとサーバのポートを `chrome.storage.local` に保存し、`host_permissions` とオプションページを加えた。送信の履歴と結果の自動再送は保存しない（[0020 要件定義書](../../tasks/0020_extension_send/01_requirements.md) §1）
- 2026-10-19 共有トークン・ポート・`storage` の権限・`host_permissions`・オプションページを削除し、`nativeMessaging` に移した。拡張は `chrome.storage` を参照せず、ジョブはサーバ側で続く。旧版の保存値は削除せず、読めないまま残ることを残余のリスクとして受け入れた（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §3.7.1）
- 2026-10-29 拡張は何も保存せず、状態の正しい値をサーバに置くことにした。送信ごとの値はビューアの URL とページのメモリだけに置き、権限は `activeTab`・`scripting`・`nativeMessaging` のまま加えない（[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) §1）
