# ADR-0010: 拡張は API キーを chrome.storage.local に、ジョブの記録を chrome.storage.session に保存し、権限を activeTab・scripting・storage に、送り先を CSP で Anthropic の API に限る

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

ブラウザ拡張は、利用者が設定した Anthropic API キーで Claude API を呼び、記事をビューアに表示する（[ADR-0048](0048-extension-only-generation.md)）。API キーを置ける場所は拡張だけである。利用者が API キーを 1 回入力すれば済み、料金のかかった記事を再読み込みやタブを閉じる操作で失わないようにする必要がある（[0090 要件定義書](../../tasks/0090_extension_only_architecture/01_requirements.md) F-001）。

拡張が値を保存すると、保存の権限と、保存した値を読める相手の管理が要る。拡張のページはすべて同じオリジンにあり、記事を描画するビューアも保存の場所に届く。Service Worker はブラウザによっていつでも停止されるので、そのメモリだけを状態の正しい置き場所にはできない。

## 決定

-   **API キーと任意のワークスペース ID は、`chrome.storage.local` に保存し、ブラウザを再起動しても残す。** 項目の名前は `anthropic.apiKey` と `anthropic.workspaceId` とし、プロバイダの名前を前に付ける。SW は、API キーがあるかを `chrome.storage.local.getKeys()` で項目の名前だけを得て確かめ、API キーの値を読まない。`chrome.storage.sync` は使わない。利用者が 1 回入力すれば済み、ほかの端末へ同期させず、プロバイダを足したときに同じ場所に並べられるようにするためである。`getKeys()` は Chrome 130 から使え、最小の版（[ADR-0030](0030-minimum-chrome-version.md)）で使える。値はプロファイルのディスクに平文で残り、同じ OS ユーザーのプロセスは読める。これは、CLI の `.envrc` と同じ水準として受け入れる。規則は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「オプションページと API キーの保存」にある。
-   **保存した API キーを読める文脈を、拡張のページと SW に限る。** SW は起動のたびに最上位の処理で、ポップアップは関数を注入する直前に、`chrome.storage.local.setAccessLevel` を呼び、注入した関数の世界から読めないようにする。注入した関数は選択範囲を読むだけで、API キーを要らないためである。ポップアップでも呼ぶのは、関数を注入するポップアップを開いたときに SW が動いているとは限らないためで、起動のたびに呼ぶのは、設定がブラウザの再起動や拡張の更新の後も残るかが文書に書かれていないためである。この呼び出しが効かないと分かった場合は呼び出しをやめ、読めることを受け入れるリスクにする（0090 設計書の「確かめていない事項の判定（要件書 AC-21・AC-22）」）。規則は 0090 設計書の「オプションページと API キーの保存」にある。
-   **API キーとワークスペース ID は、オプションページで設定・変更・削除する。** 保存の前に記事生成モジュールの検査を通し、合わない値は補正せずに拒否する。保存した API キーは画面に再び表示せず、設定されているかどうかだけを示す。入力の欄は `<form>` に入れず、パスワードの欄として扱わせない（文字は伏せる）。オプションページで設定するのは、記事を描画するビューアとも、生成の操作をするポップアップとも、画面を分けるためである。再び表示しないのは、画面の共有や覗き見で漏らさず、DOM に値を残さないためである。パスワードの欄として扱わせないのは、ブラウザがパスワードの管理への保存を勧め、保存した値がアカウントの同期でほかの端末へ渡りうるためである。規則は 0090 設計書の「オプションページと API キーの保存」にある。
-   **ジョブの記録（生成の状態と完成した記事）は、`chrome.storage.session` に置き、書き込むのは SW だけにする。** ブラウザを終了するまで持ち、ディスクに書かない。SW の停止で正しい値を失わず、書き手を 1 つにして判定の排他を保つためである。記録の形、上限、消えるときは [ADR-0027](0027-article-job-api.md) が定める。
-   **ほかの値は保存しない。** コピーした字幕と概要欄は、記録にも URL にも入れない。送信ごとの値は、ジョブの記録、ビューアの URL、各ページのメモリにだけ置く。保存した値を管理する範囲を、要るものに限るためである。規則は 0090 設計書の「記録の形」にある。
-   **要求する権限は `activeTab`・`scripting`・`storage` の 3 つだけにする。** `host_permissions`・`tabs`・`history`・`downloads`・`clipboardWrite`・`unlimitedStorage`・`offscreen` を加えず、`content_scripts`・`web_accessible_resources`・`externally_connectable` を宣言しない（起動の経路は [ADR-0008](0008-launch-path.md)）。`host_permissions` がなくても、事前の確認を 1 往復増やすだけで Claude API を呼べる。閲覧内容全般に及ぶ権限を持たず、Web Store で説明する権限を減らすためである。規則は 0090 設計書の「権限」にある。
-   **シークレットモードでは動かさない（`"incognito": "not_allowed"`）。** 既定の `spanning` でシークレットモードを許すと、ビューアが通常のウィンドウで開き、動画のタイトルと URL を持つビューアの URL が通常のプロファイルの履歴に残り、ジョブの記録も通常のプロファイルと共有されるためである。シークレットモードで使うことは [#874](https://github.com/isseis/yt2column/issues/874) で扱う。規則は 0090 設計書の「権限」にある。
-   **拡張のページの CSP は `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'; connect-src 'self' https://api.anthropic.com; img-src 'self'; media-src 'none'; frame-src 'none'; form-action 'none'` にする。** `'wasm-unsafe-eval'` は、記事を作る処理の WASM（[ADR-0049](0049-wasm-core-sharing.md)）を読み込むのに要る。JavaScript の `eval` とインラインのスクリプトは許さない。`connect-src` は、拡張のページと Worker からの送信を、拡張自身のファイルと Anthropic の API に限り、リダイレクトの先を含め、ほかの先へ API キーを送らない守りの 1 つにする。画像・メディア・フレーム・フォームの指示は、外へ送る経路を閉じる。ページの移動、`window.open`、`chrome.tabs.create` による送り出しは CSP では止められないので、ビューアでスクリプトを動かさないこと（[ADR-0017](0017-viewer-markdown-rendering.md)）が本当の守りである。規則は 0090 設計書の「CSP」にある。
-   **権限を広げずに、ビューアを開き、保存し、コピーする。** ビューアのタブは `chrome.tabs` の権限の要らない操作で開き、`chrome.windows.update` で前面に出す。記事の保存は拡張のページからの Blob のダウンロードで、コピーは利用者の操作の中のクリップボードへの書き込みで行う。権限を広げずに要件を満たすためである。規則は 0090 設計書の「権限」にある。
-   **古い版が保存した値は、読まず、消さない。** 0020 の版が `chrome.storage.local` に保存した共有トークンとポート（`sharedToken`・`serverPort`）は、`storage` の権限で読めるようになるが、拡張は読まず、消す処理も持たない。どこにも通用しない値で、消す仕組みは版の移行の仕組みになり、利用者は開発者 1 人であるためである。規則は 0090 設計書の「オプションページと API キーの保存」にある。
-   **ビューアの URL に持つ値は、ブラウザの履歴に残ることを受け入れる。** URL は、見出しの値、動画の URL、送信の時刻と、受け付けた後はジョブ ID を持つ。値を URL に置けば、再読み込み・閉じたタブの復元・履歴からの表示の後も同じ記事を表示できるためである。ジョブ ID は乱数で、記事の中身を表さない。規則は 0090 設計書の「信頼できない入力の境界（要件書 AC-18）」にある。

この決定は、まだコードと [security.md](../security.md) §8.1 に反映していない。今の拡張は何も保存せず、権限は `activeTab`・`scripting`・`nativeMessaging` で、状態の正しい値はサーバにある。この差分は [#773](https://github.com/isseis/yt2column/issues/773) の実装で解消する。

## 採らなかった案

-   **`"incognito": "split"` にして、シークレットモードで使えるようにする。** ビューアをシークレットモードのタブで開けるが、`chrome.storage` は通常とシークレットモードで共有されるので、記録の名前を側ごとに分けて閉じたら消す設計が要り、確かめていない振る舞いも増える。拡張だけの構成への移行の要件ではないので、[#874](https://github.com/isseis/yt2column/issues/874) で扱う（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「権限」）。
-   **古い版が保存した値を、更新時に削除する。** 残しても害がない。サーバはトークンを読まないので、残った値が通用する相手はない。値はプロファイルのディレクトリにあり、読めるのは同一ユーザーのプロセスだけである（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §3.7.1）。
-   **`downloads`・`clipboardWrite`・`tabs`・host permission を加えて、保存・コピー・ビューアを実装する。** 権限の範囲を今より広げないためである（[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) §1）。
-   **入力の欄を `type="password"` にする。** ブラウザがパスワードの管理への保存を勧め、保存した値がアカウントの同期でほかの端末へ渡りうる（0090 設計書「オプションページと API キーの保存」）。
-   **API キーをメモリにだけ持ち、ブラウザの終了で消す。** ディスクには残らないが、利用者はブラウザを起動するたびに API キーを貼り直すことになる（0090 要件定義書「要件定義の際に決めたこと（2026-11-12）」）。
-   **API キーを残すか終了で消すかを、利用者が選べるようにする。** 設定の画面と保存の経路が 2 つになる（0090 要件定義書「要件定義の際に決めたこと（2026-11-12）」）。
-   **API キーを `chrome.storage.session` か IndexedDB か `localStorage` に置く。** `session` はブラウザの終了で消える。IndexedDB と `localStorage` は、注入した関数の世界から読めないようにする仕組みを持たない（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「オプションページと API キーの保存」）。
-   **API キーとワークスペース ID の欄をポップアップに置く。** 画面が狭く、生成の操作と混ざる（0090 設計書「設計の際に決めたこと（2026-11-12）」）。
-   **保存した API キーの末尾の数文字を示す。** どのキーかを見分ける助けになるが、値の一部を出すことになる（0090 設計書「オプションページと API キーの保存」）。
-   **`connect-src` を加えず、Go の送信のリダイレクトの拒否だけに頼る。** Go の守りは `fetch` の振る舞いに依存し、PoC で一度効かなかった（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「CSP」）。
-   **`host_permissions` に `https://api.anthropic.com/*` を加える。** 事前の確認を省けるが、なくても API を呼べ、Web Store で説明する権限が増える（0090 設計書「権限」）。

## 結果

-   拡張のプロファイルに残るのは、API キー（と任意のワークスペース ID）、ブラウザの履歴に残るビューアの URL、0020 の版が残した値である。API キーは平文で残り、同じ OS ユーザーのプロセスは読める。
-   完成した記事と生成の状態は、ブラウザの終了、拡張の再読み込みと更新で失われる（[ADR-0027](0027-article-job-api.md)）。
-   拡張の権限は、利用者が起動したタブの読み取りと、拡張自身の保存に限られる。閲覧内容全般に及ぶ権限を持たない。Claude API への送り先の制限は、権限ではなく CSP で行う。
-   拡張のページはすべて、保存した API キーに届く。記事を描画するビューアでスクリプトを動かさないことが、API キーを守る前提になる（[ADR-0017](0017-viewer-markdown-rendering.md)）。
