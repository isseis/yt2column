# ADR-0050: タスクの PR を開く前に Fable の部分レビューを範囲を絞って行い、走らないときは止めずに記録する

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

タスクの PR は、開く前に、サブエージェントのセルフレビューとローカルの CLI レビューを受け、開いたときに Codex の PR レビューを 1 回だけ受ける（[ADR-0013](0013-review-setup.md)）。PR を開いた後に見つかった問題を直すと、その修正は Codex の PR レビューに見られない。

PR を作った後に Fable のサブエージェントのレビューを手作業で頼んだ 7 件では、6 件で、マージの前に直すべき Major 級の問題が見つかった。Codex の最初の PR レビューが指摘 0 件を返した PR もあった。成果が大きかったのは、範囲を絞って役目を狭めた回と、文書の PR である。承認済みの設計を写した実装では、効果が薄かった。弱点は受け取る側のトリアージで、正しい指摘を誤って却下した。その 1 件は、ローカルの CLI レビューの指摘を誤って却下したものと同じだった（[0098 要件定義書](../../tasks/0098_fable_partial_review/01_requirements.md) §1）。

Fable は、Claude Code の Agent ツールで選べるモデルの 1 つで、OpenCode からは呼べない。

## 決定

以下の決定の仕様は、[0098 要件定義書](../../tasks/0098_fable_partial_review/01_requirements.md) の機能要件が持つ。

-   **タスクの PR を開くコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/mkplan2`・`/runplan`）は、PR を開く前に、Fable の部分レビューを 1 つの PR につき 1 回行う。ローカルの CLI レビューと並列に走らせる。** PR を開く前に直せば、Codex の最初の PR レビューが修正を見るためである。`/runplan` で phase group ごとに走らせないのは、費用が phase group の数だけ増えるためである。`/mkplan2` を含めるのは、PR の境界などを人に問わずに決めるためであり、共有の手順に置けば例外が要らないためでもある（F-001）。
-   **範囲は、信頼の境界・先行文書との照合・外部の振る舞いについての技術的な主張・人に問わずに決めたこと、の 4 つの基準に当たる箇所に限る。当たる箇所がなければ走らせない。** 範囲を絞った回の成果が大きかったためである。`/runplan` では、先行文書との照合を、文書の決めていない点・文書を解釈した点・文書と違えた点に限る。実装の PR には必ず先行文書があり、設計を写した実装では効果が薄かったためである。3 文書の PR では、3 文書をまとめて 1 回行い、3 文書どうしの食い違いを照合に含める（F-002）。
-   **範囲から外した箇所とその理由を Fable に渡し、外した判断が基準に当たると Fable が見たら指摘として返せるようにする。外した箇所は PR の説明にも残す。** 書き手のセッションが自分の盲点を外さないようにするためである（F-002、F-003）。
-   **Fable には、却下した指摘と決着済みの論点を、セッション自身の言葉で渡し、具体的な筋書きがあるときに限って再提起させる。Codex CLI の指摘の本文は渡さない。** 既出の指摘との重複を避けるためである。本文を渡さないのは、信頼しないテキストの扱い（[ADR-0015](0015-untrusted-review-threads.md)）を変えないためである（F-003）。
-   **Fable の指摘とローカルの CLI レビューの指摘を 1 回のトリアージにまとめる。このトリアージで却下するときは、該当箇所を読むか実験で根拠を確かめ、確かめた方法と結果を理由として記録する。この規則は、ローカルの CLI レビューの指摘だけのトリアージにも当てはめる。** 誤った却下が、Fable の指摘とローカルの CLI レビューの指摘の両方で起きたためである。Opus のレビューの指摘は、もともと人に尋ねる（[ADR-0042](0042-implementation-model-tiers.md)）ので対象にしない（F-004）。
-   **Fable の指摘の修正は、ローカルの CLI レビューの 2 回目の試行で確かめ、Fable をもう一度は走らせない。** 修正を確かめずに push しないためであり、費用を 1 回分に抑えるためでもある（F-004）。
-   **Fable で走らせられないとき（基準に当たる箇所がない、エラーや利用上限、走ったモデルが Fable でない、エージェントが Fable を呼べない）は、止めずに `not run` とその理由を記録して進む。ほかのモデルで代えない。Fable で走ったかは、サブエージェントが報告するモデル ID で確かめる。** Fable は追加のレビューであり、使えないことで PR を止めないためである。代えないのは、Fable で走ったつもりの記録を残さないためである。OpenCode で動く `/runplan` も `not run` とするのは、chief の送り先（[ADR-0046](0046-chief-of-staff.md)）を変えないためである（F-005）。
-   **Fable の部分レビューの実施と、指摘の却下・`deferred`・`unclear` を、コミットメッセージの決まった形の行と PR の説明に記録する。既存の記録の行の読み方は変えない。`/runpr` のマージの質問の要約には、Codex が見ていない変更をローカルの CLI レビューと Fable の部分レビューが見たかを 1 行で示す。** 1 つの PR が複数のセッションにまたがっても、記録がブランチと一緒に残るためである。要約に示すのは、人が PR レビューを追加で頼むかを決める材料にするためである（F-006、F-008）。

## 採らなかった案

-   **PR を作った後に Fable のレビューを行う（これまでの手作業の形）。** 修正が Codex の PR レビューに見られない（0098 要件定義書の「issue #924 で決めたこと」）。
-   **Fable で走らせられないときに、Opus かセッションのモデルで代える。** Opus のレビューと役目が重なり、記録の意味も曖昧になる（0098 要件定義書「要件定義の際に決めたこと（2026-11-17）」）。
-   **モデル ID を確かめない。** Agent ツールの `model` の指定が効いたことが分からない（同上）。
-   **Fable の指摘だけに、却下の根拠を確かめる規則を当てはめる。** 同じトリアージの中で却下の基準が 2 つになり、ローカルの CLI レビューの指摘の誤った却下を防げない（同上）。
-   **却下の根拠を確かめる規則を、`/fixpr` の PR のスレッドとセルフレビューの指摘にも広げる。** `/fixpr` を変えないという issue の範囲を超える（同上）。
-   **`/mkplan2` を対象から外す。** 共有の手順に例外が要り、`/mkplan2` が人に問わずに決めたことが見られない（同上）。
-   **OpenCode で動く `/runplan` では、PR を開く前に Claude Code に引き継いで Fable を走らせる。** `runplan-takeover` の行の役目を広げることになり、chief の動きが変わる（同上）。
-   **外した箇所を PR の説明に残すだけにする、または範囲を別のサブエージェントに選ばせる。** 前者は、人が PR の説明を読むまで盲点に気づけない。後者は、サブエージェントが 1 つ増え、その選び方を確かめる者がいない（同上）。
-   **`/runplan` では、Opus のレビューが走る PR で Fable を走らせない。** 信頼の境界と技術的な主張は、Opus のレビューのチェックリストの役目と違う（同上）。
-   **`/runplan` で、先行文書との照合を字面どおりに当てはめる。** 実装の全体が毎回範囲に入る（同上）。
-   **3 文書の PR で、文書ごとに 3 回走らせる。** 費用が 3 倍になる（同上）。

## 結果

-   タスクの PR を開くまでの時間は、Fable の部分レビューとローカルの CLI レビューのうち長い方の分だけ延びる。Fable の 1 回の費用は、これまでの実績で 2〜16 分、出力 2k〜260k トークンである。
-   `sonnet` の PR を OpenCode で実装すると、Fable の部分レビューは走らない。
-   トリアージの却下には、確かめた方法と結果が要る。却下の手間が増える。
-   Fable の出力の文は、コミットメッセージにも PR の説明にも写さない。指摘は、場所とセッション自身の要約で記録する。

## 経緯

- 2026-11-17 タスクの PR を開く前に Fable の部分レビューを範囲を絞って 1 回行い、ローカルの CLI レビューの指摘とまとめてトリアージし、却下の根拠を確かめて記録し、走らないときは止めずに `not run` と記録することにした（[0098 要件定義書](../../tasks/0098_fable_partial_review/01_requirements.md)「要件定義の際に決めたこと（2026-11-17）」）
