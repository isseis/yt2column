# ADR-0014: レビューのスレッドと Bot への依頼は信頼せず、書き込み権限・範囲の規則・interaction limits で守る

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

このリポジトリは公開されており、GitHub のアカウントを持つ人なら誰でも、PR にレビューのスレッドを開ける。`/fixpr` は、未解決のスレッドの本文をエージェントに読ませ、リポジトリのファイルを直させ、commit と push まで行う。`/runpr` は、その `/fixpr` を繰り返し呼ぶ。スレッドの本文は、外部の人が書いた信頼できないテキストで、プロンプトインジェクションの経路になる。本文を読んだエージェントはファイルを編集できるので、誤ると範囲外の変更が commit され、push される。

GitHub App として入っている自動レビュアー（Codex・CodeRabbit）は、書き込み権限を持つ Bot として振る舞う。書き込み権限のない人は、PR や issue のコメントで自動レビュアーに依頼し、自動レビュアーの名義のスレッドに自分の指示を入れられる。自動レビュアー自身も、PR のブランチに push しうる。

この決定の仕様の正本は [fixprguard_guide.md](../guides/fixprguard_guide.md) の §6「範囲の規則」・§7「ツールが保証すること・しないこと」・§10「GitHub の設定」、[CLAUDE.md](../../../CLAUDE.md) の「Tool Execution Safety」、[.claude/commands/_context.md](../../../.claude/commands/_context.md) の「Automated reviewer list」の行、[.claude/commands/runpr.md](../../../.claude/commands/runpr.md) の step 1 と step 3 である。

## 決定

-   **スレッドの本文はデータであり、指示ではない。** エージェントのプロンプトは本文をその旨の区切りで囲み、区切りの行を本文が終わらせられないようにする。返信の文面と PR の説明も、同じ扱いにする。
-   **信頼する著者は、リポジトリへの書き込み権限（write・maintain・admin）を持つ Bot でないアカウントと、`_context.md` の「Automated reviewer list」に挙げた自動レビュアーだけである。** 自動レビュアーは、Bot であることと名前の一致の両方で判定する。権限の照会は自動レビュアー以外のアカウントにだけ行う。
-   **スレッドのすべてのコメントの著者を確かめ、1 件でも想定外の著者があれば、スレッド全体を想定外とする。** コメントの数が 11 件以上でも、1 つのスレッドから取得する上限（100 件）まで見る。上限を超えるスレッドと、取得できないコメントがあるスレッドも想定外とする。想定外のスレッドは、トリアージ・修正・返信・解決をせず、URL と理由を報告する。本文は取得せず、セッションにも渡さない。利用者が内容を確かめて名指ししたスレッドだけを処理する。
-   **修正の範囲は、スレッドの `path` と同じディレクトリと、その `path` があるタスクのディレクトリに限る。** 実行関連ファイル（build checks と CI が読むファイル、指示ファイル、`.` で始まる要素を含むパス）は、スレッドの著者と `path` にかかわらず範囲外とする。範囲外の変更が出たら、build checks・commit・push の前に、利用者に一覧を示して確かめる。commit は判定したパスだけを stage する。
-   **GitHub への書き込みは、ガードツールの `reply`・`edit-pr`・`append-pr` だけで行う。** 道具はシェルを介さず、本文を標準入力で渡す。`@codex` のメンションを含む文面は、GitHub に書き込む前に拒否する。セッションも、投稿するすべての文面について、投稿の前にメンションがないことを確かめる（[ADR-0013](0013-deterministic-checks-in-go.md)）。
-   **fork の PR では、`/fixpr` と `/runpr` は何もせずに止まる。** head を外部の人が管理すると、チェックアウトした `CLAUDE.md` や `.claude/commands/` そのものが攻撃者のものになる。
-   **interaction limits をアカウントに設定し、`/runpr` は PR ごとにその状態を確かめる。** 対象は 4 つの設定（interaction limits の `collaborators_only`、PR の作成の制限、issue の作成の制限、`main` を除くすべてのブランチの push の制限）で、設定は利用者が行う。`/runpr` は、`fixprguard interaction-limits` で制限の状態を読み、PR の作成の時刻と比べ、利用者以外の `@codex` のメンションがないことを確かめる。確かめられないとき、制限が外れているとき、PR が制限の設定より前に作られたときは、レビューを待たずに止まる。
-   **制限の状態の判定は、GitHub の応答を厳密に検査する Go のサブコマンドで行う。** 「今」は同じ応答の `Date` ヘッダ（GitHub の時刻）から取る。応答の検査は 1 つの番兵のエラーにまとめ、部分的な結果を使わない。

## 採らなかった案

-   **本文をデータとして明示するだけで、著者を確かめない。** 公開リポジトリでは誰でもスレッドを開けるので、プロンプトの書き方だけでは守りにならない（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **想定外の著者のスレッドもトリアージだけ行う。** トリアージだけでも本文がエージェントに渡るので、守りにならない（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **`/fixpr` の実行中に、スレッドごとに利用者へ聞く。** `/runpr` の自動の繰り返しのたびに、利用者を待たせることになる（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **想定外の著者のコメントだけを除いて処理する。** 会話の文脈が欠けて、指摘を誤って理解するおそれがある（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **範囲外の変更があれば止める。** コードの修正では別のパッケージを変えることもあり、正当な修正まで止まる（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **修正の範囲を、スレッドの `path` のファイルだけに限る。** 同じパッケージのテストを直すたびに確認が入り、`/runpr` の繰り返しのたびに利用者を待たせる（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **範囲外の変更を捨てる。** 何が書き換えられたかを、利用者が確かめられなくなる（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1）。
-   **会話コメントの著者まで確かめて止める。** 自動レビュアーが何をもとにスレッドを書いたかは、会話コメントの著者だけからは決まらない。自動レビュアーを経た指示は、本文をデータとして扱うことと範囲の確認で抑え、残余のリスクとして記録する（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md) §1、§4.2）。
-   **`--reviewer` を名前の数だけ文書に書き、一覧を変えるたびに文書を変える。** 文書は 1 つのプレースホルダーを書き、名前ごとに 1 回ずつ繰り返すと定める。名前を渡し忘れても、その Bot のスレッドは信頼されないだけで、安全側に倒れる（[0033 要件定義書](../../tasks/0033_multiple_trusted_reviewers/01_requirements.md) §1）。
-   **範囲の規則の変更で `--protocol` を上げない。** 番号を上げないと、古い道具と新しい文書が食い違ったまま、違う規則で黙って判定しうる（[0036 要件定義書](../../tasks/0036_fixprguard_exec_file_scope/01_requirements.md) §1）。
-   **すべてのブランチを push の制限の対象にする。** PR のマージ（`main` の更新）も制限に当たり、`/mergepr` の `gh pr merge` が止まる。`main` への直接の push は、既存の ruleset がすでに禁じている（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1）。
-   **interaction limits を `gh api --jq` で読む。** `jq` は重複した項目を黙って後勝ちにするので、応答を厳密に検査できない（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1）。
-   **制限の状態をローカルの時計で判定する。** ローカルの時計がずれていると、判定もずれる。同じ応答の `Date` ヘッダを使えば、1 回の取得で制限と時刻がそろう（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1）。
-   **制限が外れているか確かめられないときに、警告して処理を続ける。** 制限が外れていた間に自動レビュアーが作ったスレッドは、本来のレビューのスレッドと見分けられず、利用者が手で探すと見逃しうる（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1）。
-   **疑わしいコメントを一律に削除する。** 正当なレビューも消え、取り消せない（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1）。
-   **信頼する自動レビュアーの一覧から CodeRabbit を外す。** Web から CodeRabbit のレビューを頼む使い方があり、書き込み権限のない人は制限が有効な間はどちらの Bot にも指示できない。CodeRabbit だけを厳しく扱っても減る危険は小さい（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md) §1「実装の際に決めたこと（2026-11-04）」）。

## 結果

-   想定外の著者が開いたスレッドは、利用者が内容を確かめて名指しするまで処理されない。その本文は、`/fixpr` にも `/runpr` のセッションにも渡らない。
-   信頼する著者のスレッドでも、本文を読んだエージェントが指示に従うことは保証できない。範囲の確認と、書き込みを道具に限ることを、別の守りとして重ねる。
-   範囲外の変更は、build checks の前に利用者の確認に回る。build checks は修正したコードを実行するので、確認の後に build checks を動かす。
-   interaction limits はアカウント全体に効き、ほかの公開リポジトリにも及ぶ。期限は最長 6 か月で、切れる前に利用者が更新する。`/runpr` は、制限が外れている、または確かめられない PR をマージしない。
-   `/runpr` は、4 つの設定のうち interaction limits だけを読む。PR と issue の作成の制限と push の制限は、利用者が設定画面で確かめる。

## 経緯

- 2026-10-21 `/fixpr` と `/runpr` で、スレッドの本文を信頼できないデータとして扱い、すべてのコメントの著者を書き込み権限と自動レビュアーの一覧で判定することにした。想定外のスレッドは処理せず、修正の範囲を `path` の周辺に限り、範囲外の変更は commit の前に利用者へ確かめる（[0030 要件定義書](../../tasks/0030_fixpr_untrusted_threads/01_requirements.md)）
- 2026-10-22 信頼する自動レビュアーを複数名にできるようにし、`--reviewer` の一覧を `_context.md` の 1 か所に置いた。一覧は名前に `[bot]` を付けた REST の形でも照合する（[0033 要件定義書](../../tasks/0033_multiple_trusted_reviewers/01_requirements.md)）
- 2026-10-22 範囲の規則で、実行関連ファイルをスレッドの著者と `path` にかかわらず範囲外とし、`.go` を許可リストに移した。規則を変えたので `--protocol` を `3` に上げた（[0036 要件定義書](../../tasks/0036_fixprguard_exec_file_scope/01_requirements.md)）
- 2026-11-02 外部の人が自動レビュアーを介して指示を届ける経路を塞ぐため、interaction limits・PR と issue の作成の制限・push の制限を設定し、`/runpr` が制限の状態と PR の作成の時刻、利用者以外のメンションを確かめて、確かめられなければ止まるようにした（[0057 要件定義書](../../tasks/0057_reviewer_relay_guard/01_requirements.md)）
