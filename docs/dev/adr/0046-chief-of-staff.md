# ADR-0046: chief は人の判断を待つものを示し、決まった入力だけをほかのエージェントに送り、マージの後の次のコマンドを自動で送る

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

タスクは、Herdr の workspace（タスクごとの git の worktree）で、Claude Code と OpenCode のエージェントが並行して進める。各タスクは `/mkreq`・`/mkarch`・`/mkplan`・`/runplan` が PR を作り、人がレビューしてから `/runpr` を実行し、`/runpr` がマージの確認を人に尋ねてマージする。workspace が増えると、人を待っているものが見えず、マージの後に次のコマンドを正しいモデルで走らせる操作にも人の手がかかる。

これを chief というコーディネーターに任せる。chief はほかのエージェントのセッションに入力を送るので、開発用の道具の信頼の境界になる。chief が誤った入力を送ると、人が選んでいない答えや、違うモデルでのコマンドが走る。エージェントの画面、PR の説明、レビューは、ほかのエージェントや外部が書いた信頼できない文字列である（[security.md](../security.md) §6）。

Herdr はリポジトリの外の道具で、chief はその CLI の出力に依る。

## 決定

以下の決定の仕様は、[0088 要件定義書](../../tasks/0088_chief_of_staff/01_requirements.md) の機能要件が持つ。

-   **chief は、人の代わりに判断しない。止まっているエージェントの質問には、人が chief の選択肢で選んだ答えだけを中継し、送る直前に質問と選択肢が人に示したときと同じであることを確かめる。権限の確認と自由に書く答えは中継しない。** 人の判断であることを保ったまま、pane を移る手間をなくすためである。権限の確認を中継しないのは、実行されるコマンドを見ないまま許可しやすくなるためである。自由に書く答えを中継しないのは、chief が送る入力が人の書いた任意の文まで広がるためである（0088 要件定義書の F-005）。
-   **chief がタスクの workspace へ送る入力は、`/clear`・`/model`（Claude Code）、`/new`（OpenCode）、`/mkreq`・`/mkarch`・`/mkplan`・`/runplan`・`/runpr`、質問の選択肢を選ぶ入力だけにする。`git` のコマンド、`gh pr merge`、自由な文、`/weakreview` は送らない。自分の workspace のエージェントには何も送らない。** 送る入力の範囲を決めておけば、chief の誤りで送られうるものも、その範囲に限られるためである。`/weakreview` を送らないのは、Opus のレビューを `/runplan` が PR を開く前に行う（[ADR-0042](0042-implementation-model-tiers.md)）からである（F-006）。
-   **コマンドごとのエージェントとモデルは、`/mkreq`・`/mkarch`・`/mkplan` が Claude Code・Opus、`/runplan` が実装計画書の PR マーカーの `**実装モデル要件**` が指すもの、`/runpr` が OpenCode・DeepSeek V4.1 Flash とする。モデルが切り替わったこと（OpenCode では、モデルが合っていること）を確かめてからコマンドを送り、確かめられなければ送らない。** 送り先とモデルの取り違えをなくすためである。読めない実装モデル要件の値は、推し量らずに送らない（F-006）。
-   **`/runpr` がマージを終えたら、chief は次のコマンド（`/mkarch`・`/mkplan`・`/runplan`）を人に尋ねずに送る。人がマージの確認に答えたことを、その承認とみなす。`/runpr` の報告の次のコマンドが chief の判断と一致し、worktree がきれいで、実装計画書の PR マーカーが自動送信を止めていないときに限る。** マージの後の操作には、人の判断が要らないためである。`/runpr` の報告は信頼できない文字列なので、照合に使うだけで、そのまま送らない（F-007）。
-   **自動送信を止める例外は、実装計画書の PR マーカーの欄で宣言し、`/mkplan` が書く。欄がない計画書は、自動送信してよいものとして扱う。** 途中で対話のセッションを挟むことは計画を作るときに決まり、計画書に置けば別の場所に書き写さずに済むためである（CLAUDE.md の「Declare, don't infer」）。欄がないのは、この決定の前に書かれた計画書の正しい形だからである（F-008）。
-   **レビュー待ちの PR への `/runpr` は、人が PR の詳細を見てから選んだときだけ送る。** 人がレビューした後に `/runpr` を実行するという流れを保つためである（F-004）。
-   **自動の進行と通知は、chief のセッションが待ち受けている間だけ行い、セッションと別に常駐するプロセスを置かない。** 常駐のプロセスは、エージェントのいないところでほかのセッションへ入力を送ることになり、信頼の境界が広がるためである。止まっている間に溜まったものは、次に状況の表を出したときに拾う（F-010）。
-   **送れたかが分からない送信は送り直さない。** 同じコマンドを 2 回走らせるより、人に示して止まるほうを選ぶためである（F-006）。
-   **chief は Herdr の中でだけ動き、Herdr の出力を読めないときは状態を推し量らずに「要確認」とする。** Herdr の出力の形はリポジトリの外で変わりうるためである（F-001）。

この決定は、まだコマンドの定義と道具に反映していない。この差分は [#837](https://github.com/isseis/yt2column/issues/837)・[#838](https://github.com/isseis/yt2column/issues/838)（タスク 0088）の実装で解消する。

## 採らなかった案

-   **質問には一切触れず、中身を示すだけにする（試作の形）。** 人が答えるたびに pane を移る手間が残り、選択式で次の操作をとれるようにするという要求に合わない（0088 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **権限の確認も中継する。** 実行されるコマンドを見ないまま許可しやすくなる（同上）。
-   **自由に書く答えも中継する。** chief が送る入力が、人の書いた任意の文まで広がる（同上）。
-   **自動送信の例外を、chief の手元のファイルに人が書く（試作の形）。** 計画書がすでに決めている事柄を、別の場所に書き写すことになる（同上）。
-   **自動送信の欄がない計画書は、自動送信しない。** 進行中のタスクを、最後まで人の手で進めることになる（同上）。
-   **セッションと別に常駐するプロセスを置き、セッションがなくてもマージの後の送信を行う。** 信頼の境界が広がり、作る量も大きくなる（同上）。

## 結果

-   chief のセッションが止まると、自動の進行と通知も止まる。利用上限などでセッションが止まった間のマージの後の送信は、次に状況の表を出すまで行われない。
-   OpenCode はコマンドでモデルを切り替えられないので、OpenCode のモデルが合わないときは、人がその pane で切り替える。
-   実装計画書の PR マーカーの欄が 1 つ増え、`/mkplan` はその値を決める。
-   権限の確認と自由に書く答えには、人がその pane へ移って答える。
-   chief は Herdr の CLI の出力の形に依り、Herdr の変化に合わせて直す必要がある。

## 経緯

- 2026-11-11 chief が人の判断を待つものを示し、人が選んだ答えだけを中継し、決まった入力だけをほかのエージェントに送り、マージの後の次のコマンドを自動で送ると決めた。自動送信の例外は実装計画書の PR マーカーで宣言し、自動の進行は chief のセッションの間だけ行うことにした（[0088 要件定義書](../../tasks/0088_chief_of_staff/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）
