# ADR-0046: chief は人の判断を待つものを示し、決まった入力だけをほかのエージェントに送り、マージの後の次のコマンドを自動で送る

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

タスクは、Herdr の workspace（タスクごとの git の worktree）で、Claude Code と OpenCode のエージェントが並行して進める。各タスクは `/mkreq`・`/mkarch`・`/mkplan`・`/runplan` が PR を作り、人がレビューしてから `/runpr` を実行し、`/runpr` がマージの確認を人に尋ねてマージする。workspace が増えると、人を待っているものが見えず、マージの後に次のコマンドを決まったモデルで走らせる操作にも人の手がかかる。

これを chief というコーディネーターに任せる。chief はほかのエージェントのセッションに入力を送るので、開発用の道具の信頼の境界になる。chief が誤った入力を送ると、人が選んでいない答えが送られたり、違うモデルでコマンドが走ったりする。エージェントの画面、PR の説明、レビューは、ほかのエージェントや外部が書いた信頼できない文字列である（[security.md](../security.md) §6）。

Herdr はリポジトリの外の道具で、chief はその CLI の出力に依る。OpenCode はコマンドでモデルを切り替えられず、質問を示しても Herdr に `blocked` と報告されない。

## 決定

以下の決定の仕様は、[0088 要件定義書](../../tasks/0088_chief_of_staff/01_requirements.md) の機能要件が持つ。

-   **chief は、人の代わりに判断しない。止まっているエージェントの質問には、人が chief の選択肢で選んだ答えだけを中継し、送る直前に質問と選択肢が人に示したときと同じであることを確かめる。中継するのは 1 つを選ぶ問いの選択肢だけで、権限の確認、自由に書く答え、複数を選ぶ問いは中継しない。質問と選択肢は画面のとおりに示す。** 人の判断であることを保ったまま、pane を移る手間をなくすためである。権限の確認を中継しないのは、実行されるコマンドを見ないまま許可しやすくなるためである。自由に書く答えを中継しないのは、chief が送る入力が人の書いた任意の文まで広がるためである（0088 要件定義書の F-005）。`/runpr` のマージの質問には、NEXT をそのセッションで実行する答えはない（[ADR-0047](0047-runpr-merge-question.md)）。
-   **chief がタスクの workspace へ送る入力は、`/clear`・`/model`（Claude Code）、`/new`（OpenCode）、`/mkreq`・`/mkarch`・`/mkplan`・`/runplan`・`/runpr`、1 つを選ぶ問いの選択肢を選ぶ入力だけにする。`git` のコマンド、`gh pr merge`、自由な文、`/weakreview` は送らない。自分の workspace のエージェントには何も送らない。** 送る入力の範囲を決めておけば、chief の誤りで送られうるものも、その範囲に限られるためである。`/weakreview` を送らないのは、Opus のレビューを `/runplan` が PR を開く前に行う（[ADR-0042](0042-implementation-model-tiers.md)）からである（F-006）。
-   **コマンドごとのエージェントとモデルは、`/mkreq`・`/mkarch`・`/mkplan` が Claude Code・Opus、`/runplan` が実装モデル要件の値に従い（`opus` は Claude Code・Opus、`sonnet+opus-review` は Claude Code・Sonnet、`sonnet` は OpenCode・DeepSeek V4.1 Flash）、`/runpr` が OpenCode・DeepSeek V4.1 Flash とする。モデルが切り替わったこと（OpenCode では、モデルが合っていること）を確かめてからコマンドを送り、確かめられなければ送らない。値が読めないときと、値がないときは、推し量らず、コマンドを送らない。** 送り先とモデルの取り違えをなくすためである。`/runpr` と `sonnet` の `/runplan` に Flash を使うのは、これらに Opus までは要らないと利用者が判断し、2026-11-11 の時点で運用がすでにそうなっていたためである。`sonnet` の対応は ADR-0042 が持つ（F-006）。
-   **実装モデル要件の値ごとの送り先とモデルは 1 か所に置き、そこを直すだけで差し替えられるようにする。`sonnet+opus-review` を OpenCode に差し替えた後は、OpenCode のセッションが Opus のレビューを走らせられずに PR を開かずに止まるので、chief は同じ workspace の Claude Code・Sonnet へ同じ `/runplan` を送ることを提案し、Claude Code が Opus のレビューと PR の作成を行う。** `sonnet+opus-review` を DeepSeek V4.1 Flash で実装して Opus のレビューを受ける形と、今の Sonnet の形の成果物の品質を、別の issue で比べてからどちらにするかを決めるためである（0088 要件定義書の F-006）。
-   **`/runpr` と `sonnet` の `/runplan` は、OpenCode を通して DeepSeek のサービスにリポジトリのコード、レビューのスレッド、コマンドの定義を送る。この送り先を選ぶことを受け入れる。** 上の項のとおり Flash を使うと決めたことに伴うものである。DeepSeek V4.1 Flash が手順を守れるかは、[#790](https://github.com/isseis/yt2column/issues/790) で確かめていない（0088 要件定義書の 4.2）。
-   **`/runpr` がマージを終えたら、chief は次のコマンド（`/mkarch`・`/mkplan`・`/runplan`）を人に尋ねずに送る。人がマージの確認に答えたことを、次のコマンドを送ることの承認とみなす。引き金は画面ではなく、GitHub の PR の状態（`MERGED`）と git の状態（`origin/main` に対して未コミットの変更も先のコミットもなく、次のブランチか `origin/main` を指している）で確かめ、画面から読み取った判断は、送信を止めるか条件を狭めるためだけに使う。自動送信は、chief が待ち受けの中で PR が開いている状態から `MERGED` になったのを見たときだけ、マージした PR 1 件につき 1 回までとし、chief を起動し直しても変わらない。chief が動いていなかった間のマージは、提案として示す。** マージの後の操作には人の判断が要らないためである。引き金を画面に頼らないのは、人に尋ねずに入力を送る判断を、信頼できない文字列に委ねないためである。1 回に限り、見たマージだけを対象にするのは、送ったコマンドが失敗して条件がまた満たされても、人が手で走らせた次のコマンドや古いマージがあっても、同じコマンドを 2 回走らせないためである（F-007）。
-   **自動送信を止める例外は、実装計画書の PR マーカーの欄に「この PR を作る `/runplan` を自動で送ってよいか」として宣言する。この欄は `/mkplan` が書く。欄がない計画書は、自動送信してよいものとして扱う。** 途中で対話のセッションを挟むことは計画を作るときに決まり、計画書に置けば別の場所に書き写さずに済むためである（CLAUDE.md の「Declare, don't infer」）。欄を PR を作る側に付けるのは、計画書のマージの後・PR-1 の前で止めることも表せるためである。欄がない計画書を自動送信してよいものとして扱うのは、欄がないことが、この決定の前に書かれた計画書の正しい形だからである（F-008）。
-   **pane の画面とセッションの記録の文字列から判断すること（エージェントが質問で止まっているかどうか、その質問が 1 つを選ぶ問いかどうか、`/runpr` の報告の次のコマンド、モデル、入力欄に残っている文字、PR を作ったコマンドの報告の要約）は、CLAUDE.md の「Declare, don't infer」の例外とする。合わない画面は広く解釈せず、「要確認」か「送らない」にする。** 画面は Claude Code と OpenCode が描く外部の値で、型で表せず、OpenCode の質問の画面は変えられないためである。範囲と境界は 0088 要件定義書の 5 章にあり、CLAUDE.md の例外の一覧に書く。
-   **レビュー待ちの PR への `/runpr` は、人が PR の詳細を見てから選んだときだけ送る。** 人がレビューした後に `/runpr` を実行するという流れを保つためである（F-004）。
-   **自動の進行と通知は、chief のセッションが待ち受けている間だけ行い、セッションと別に常駐するプロセスを置かない。chief は同時に 1 つだけ動かす。chief の読み取り専用のネットワークの操作（PR・CI・レビューの状態の取得、`git fetch`）は、chief を起動したことで承認したものとする。** 常駐のプロセスは、エージェントのいないところでほかのセッションへ入力を送ることになり、信頼の境界が広がるためである。1 つに限るのは、2 つの chief が同じコマンドを送らないためである。読み取りの承認は、人がいないときにも状態を読む必要があるためで、書き込みの操作は含めない。規則は CLAUDE.md の「Tool Execution Safety」に書く（F-010）。
-   **送れたかが分からない送信は送り直さず、その workspace への送信を、人が解除するまで止める。** 同じコマンドを 2 回走らせるより、人に示して止まるほうを選ぶためである（F-006）。
-   **chief は Herdr の中でだけ動き、Herdr の出力を読めないときは状態を推し量らずに「要確認」とする。** Herdr の出力の形はリポジトリの外で変わりうるためである（F-001）。
-   **chief の判定と送信は、Go の開発用の道具 `chief`（`cmd/chief`・`internal/chief`）に置く。`/chief` のコマンドの定義は、道具の呼び出し、人への問い、報告の要約だけを持つ。道具は送る入力を、コマンドの種類と検証した引数から型で組み立て、文字列の入力を受け取らない。** エージェントが手順を読み違えても、決まった範囲の外の入力が送られないようにし、判定をテストで確かめるためである（[ADR-0014](0014-deterministic-checks-in-go.md)）。構成は [0088 設計書](../../tasks/0088_chief_of_staff/02_architecture.md) の 3.1「道具 `chief`」にある。
-   **コマンドごとの送り先のエージェントとモデルは、`_context.md` の送り先の表 1 か所に置き、chief は `origin/main` の版から読む。** 人への案内と chief が同じ表を読み、値ごとの送り先を 1 行の直しで差し替えられるようにし、ブランチで表を書き換えても送り先が変わらないようにするためである。表は [_context.md](../../../.claude/commands/_context.md) が持つ（0088 設計書の 3.3）。
-   **自動送信の欄は `**自動送信**` とし、値は `auto` と `hold` にする。PR マーカーのない計画書では「PR 構成」の節に書く。** 値を ASCII にして、似た文字による読み違いをなくすためである。形は `_context.md` の「PR marker conventions」が持つ（0088 設計書の 3.8）。
-   **自動送信の記録、送信の記録、送信の停止、chief の待ち受けで PR を見た記録、ロックなどは、リポジトリの外の状態のディレクトリに、同名のものがすでにあれば作らず、上書きしない形で置く。判定にはそれを読み返す。記録は、送るコマンドとタスクを決めるためには使わない。送ることについて使うのは、送ることを止める条件（リセットの候補を狭める PR の詳細の控えを含む）と、自動送信の候補の workspace を名指す条件の 2 つだけである。名指された workspace は、Herdr・git・GitHub で確かめ直す。通知の記録は通知の重複の防止と待っている時間による並べ方に、送信の記録は送った入力の履歴と「実行中」の行の表示にだけ使い、どちらも送る中身を左右しない。入力を送る前に送信の記録を作り、終わりの記録のない送信は、送れたかが分からないものとしてその workspace への送信を止める。** 起動し直しても 2 回送らず、同時に動く 2 つの chief の一方だけが送り、途中で止まった送信を送り直さないためである。PR を見た記録は、自動送信を可能にする条件の 1 つである。この記録が偽られると、chief が見ていないマージでも自動送信が起きうる。ただし送られるのはその workspace の正しい次のコマンドだけなので、これを残る危険として受け入れる。ADR-0014 の例外である（0088 設計書の 3.5）。
-   **送り先の pane は、workspace の中に、送り先の種類のエージェントの pane がちょうど 1 つあるときだけ選ぶ。画面の文字列では選ばない。リセットする pane も同じ規則で候補を決め、画面にそのコマンドの報告が残っていて、その後エージェントが動いていないときだけリセットする。** 送るたびに文脈を空にするので、人が対話に使っている pane の文脈を、黙って失わないようにするためである。画面は候補を狭めることにだけ使う（0088 設計書の 3.1.3）。
-   **画面は、実画面のサンプルで確かめた形だけを受け付ける。答えを中継するときは、人に示した質問と選択肢から作った照合値を、送る直前に読み直した画面から作った照合値と比べ、一致したときに、選択肢の番号から決まったキー入力だけを送る。** 確かめていない形の画面で、人が選んでいない答えを送らないためである（0088 設計書の 3.4・3.6）。
-   **chief のセッションが道具を通さずに入力を送らないよう、リポジトリの `.claude/settings.json` で、次の 3 種類の herdr の呼び出しを拒む。(1) pane へ入力を送るか、pane でコマンドを走らせるか、pane の入力の経路を変える呼び出し。(2) エージェントの状態とセッションを Herdr に報告する呼び出し。(3) サブコマンドの前に、別のセッションか別の機械を指す引数を書いた呼び出し。読み取りの呼び出しは拒まない。** 画面や PR の説明の指示に従ったセッションが、任意の入力を送ることと、chief の確かめが頼る状態とセッションの値を偽ることを防ぐためである。読み取りは、ほかのセッションが使うことがあり、送ることも偽ることもできないので、拒まない。拒む呼び出しの一覧は [0088 実装計画書](../../tasks/0088_chief_of_staff/03_implementation_plan.md) の「計画の際に決めたこと」にある。パスで書いた呼び出しなど、規則の外の書き方は残る危険とする（0088 設計書の 5.2）。

この決定は、まだコマンドの定義、道具、CLAUDE.md、`_context.md`、`.claude/settings.json` に反映していない。このずれは [#837](https://github.com/isseis/yt2column/issues/837)・[#838](https://github.com/isseis/yt2column/issues/838)（タスク 0088）の実装で解消する。0088 要件定義書の AC-30・AC-46 は、`/runpr` のマージの質問の「NEXT をこのセッションで実行する」答えを扱うが、ADR-0047 でこの答えを除いたので、この 2 つの AC が扱う対象はなくなった。この 2 つの AC と、それを実装する 0088 の実装計画の手順は、0088 の実装（[#837](https://github.com/isseis/yt2column/issues/837)・[#838](https://github.com/isseis/yt2column/issues/838)）で `/runplan 0088` が計画の決定の変更として外す。

## 採らなかった案

-   **質問には一切触れず、中身を示すだけにする（試作の形）。** 人が答えるたびに pane を移る手間が残り、選択式で次の操作をとれるようにするという要求に合わない（0088 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **権限の確認、自由に書く答え、「NEXT をこのセッションで実行する」答えも中継する。** 実行されるコマンドを見ないまま許可しやすくなり、chief が送る入力が人の書いた任意の文まで広がり、コマンドごとのモデルの決まりを chief 自身が破る（同上）。
-   **自動送信の例外を、chief の手元のファイルに人が書く（試作の形）。** 計画書がすでに決めている事柄を、別の場所に書き写すことになる（同上）。
-   **自動送信の例外を、「この PR のマージの後」に付ける。** 実装計画書そのものの PR にはマーカーがなく、計画書のマージの後・PR-1 の前で止めることを表せない（同上）。
-   **自動送信の欄がない計画書は、自動送信しない。** 進行中のタスクを、最後まで人の手で進めることになる（同上）。
-   **自動送信の引き金を、`/runpr` の報告の画面で確かめる。** 人に尋ねずに入力を送る判断を、信頼できない文字列に委ねることになる（同上）。
-   **エージェントの側に、待っていることを示す決まった形の合図を要件として求める。** OpenCode の質問の画面は変えられない（同上）。
-   **セッションと別に常駐するプロセスを置き、セッションがなくてもマージの後の送信を行う。** 信頼の境界が広がり、作る量も大きくなる（同上）。
-   **`/runpr` も Claude Code で走らせる。** `/runpr` には Opus までは要らないと利用者が判断した（0088 要件定義書「issue #836・#837・#838 で決めたこと」）。
-   **chief の判定と送信を、コマンドの定義と bash スクリプトに置く（試作の形）。** 判定と副作用を持ち、JSON を読み、状態を持つので、テストで確かめられる道具が要る（[0088 設計書](../../tasks/0088_chief_of_staff/02_architecture.md)「設計の際に決めたこと（2026-11-11）」）。
-   **送り先の表を Go のコードに持ち、`_context.md` との一致をガードのテストで確かめる。** 値ごとの送り先を差し替えるのに 2 か所を直すことになる（同上）。
-   **自動送信の記録とロックを git の共通ディレクトリに置く。** worktree のエージェントが書ける点で、リポジトリの外の状態のディレクトリより守りが強くなるわけではない。置き場がリポジトリの clone ごとに分かれるだけである（同上）。
-   **`sonnet` の `/runplan` を Claude Code・Sonnet で走らせる（ADR-0042 のまま）。** `sonnet` の実装には Opus までは要らないと利用者が判断し、運用がすでに Flash だった（0088 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。

## 結果

-   chief のセッションが止まると、自動の進行と通知も止まる。利用上限などでセッションが止まっている間にマージされた PR の次のコマンドは、自動では送られず、次に状況の表（0088 要件定義書の F-001）を出したときに提案として示され、人が選んで送る。
-   OpenCode のモデルが合わないときは、人がその pane で切り替える。
-   実装計画書の PR マーカーの欄が 1 つ増え、`/mkplan` はその値を決める。
-   権限の確認、自由に書く答え、複数を選ぶ問いには、人がその pane へ移って答える。
-   リポジトリのコードとレビューのスレッドが DeepSeek のサービスへ送られる。`sonnet` の PR は Opus のレビューを受けないので、Flash の実装の誤りは、`/runplan` の中のレビュー、ローカルの CLI レビュー、Codex の PR レビューで見つける。
-   実装モデル要件の値の名前 `sonnet` が、Sonnet ではなく Flash を指す。名前の見直しは [#760](https://github.com/isseis/yt2column/issues/760) で扱う。
-   chief は Herdr の CLI の出力の形に依り、Herdr の変化に合わせて直す必要がある。
-   自動送信の記録を、chief のセッションの外（リポジトリの外の状態のディレクトリ）に残す。その記録を消しても、chief が待ち受けの間に PR が開いているのを見ていないマージについては、自動送信は行われない。
-   chief は `make install-chief` で `main` から入れ、道具を変えたマージの後は入れ直す。
-   Claude Code か OpenCode の版が上がって画面の形が変わると、実画面のサンプルを採り直すまで、その画面は「要確認」になり、答えの中継もできない。
