# ADR-0025: Claude アダプタの出力の上限の既定は 40,000 トークンとし、ストリーミングを使わない

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

Claude のアダプタは、非ストリーミングで 1 回の応答として記事を受け取る。`max_tokens` が小さすぎると、長い記事や推論の多い実行が途中で打ち切られ、記事が出ない。最初の既定は 16,000 トークンで、Anthropic が非ストリーミングの目安とする値に合わせていた。しかし評価では、16,000 で打ち切られる実行が現れた。生成・字数の調整・検証・推敲の 3 つの段階が同じ上限を共有するので、上限は記事の長さと推論の量の両方に余裕を持つ必要がある（[0041 設計書](../../tasks/0041_claude_effort_max_tokens/02_architecture.md) §1.2）。

## 決定

-   **Claude アダプタの `max_tokens` の既定は 40,000 とする。** リクエストの `MaxOutputTokens` が 0 のときだけ既定を使い、正の値が指定されたときはその値を使う。3 つの段階は同じ既定を共有する。
-   **ストリーミングを使わない。** 1 回の HTTP リクエストで応答を受け取り、送信から本文の読み取りまでを 1 本の `context` の期限で覆う。
-   **打ち切りは `ErrTruncated` として報告する。** メッセージは、そのリクエストが送った `max_tokens` を示す。テキストがないまま打ち切られた場合は、effort を下げるよう案内する。
-   **上限の値はコードの 1 つの定数にだけ置き、文書に写さない。** 値の根拠と測り直しの手順は [claude_output_limit.md](../guides/claude_output_limit.md) に置き、README と本番の構成の文書は数値を書かずにそのガイドを指す。値の条件はテストで固定する。
-   **非ストリーミングの長い無通信で接続が切れるリスクは受け入れる。** HTTP/2 の PING などの仕組みは、無通信による切断が実際に観測されるまで足さない。
-   **既定の値でも、`max` の effort では推論だけで上限に達しうる。** その場合は打ち切りとして報告し、記事を公開しない。README で案内する。

この決定の仕様の正本は [claude_output_limit.md](../guides/claude_output_limit.md) と [production_profile.md](../production_profile.md) である。値の文法と effort の既定は [ADR-0003](0003-llm-config-contract.md) が定める。

## 採らなかった案

-   **上限を 16,000 のままにする。** 評価で 16,000 に達して打ち切られた実行があり、長い記事と推論の多い実行に足りない（[0041 設計書](../../tasks/0041_claude_effort_max_tokens/02_architecture.md) §1.4）。
-   **上限を 32,000 にする。** 40 分前後の動画を v5 で測っておらず、16,000 で打ち切られた実行の真の出力も 16,000 以上としか分からない。観測した最大の 2 倍より大きい余裕を取る（[0041 設計書](../../tasks/0041_claude_effort_max_tokens/02_architecture.md) §1.2）。
-   **範囲の上端に近い値（約 42,700）にする。** 出力の時間の見積もりが 15 分の期限の半分にほぼ等しくなり、混雑時の速さの低下に余裕がない（[0041 設計書](../../tasks/0041_claude_effort_max_tokens/02_architecture.md) §1.2）。
-   **ストリーミングを使う。** 高い effort で生成が長くなり、タイムアウトが実際に問題になると分かった時点で、別の issue にする（[0009 要件定義書](../../tasks/0009_claude_llm_client/01_requirements.md) §2.3）。

## 結果

-   3 つの段階が同じ上限を使うので、段階ごとに値を決める必要がない。`MaxOutputTokens` を指定する呼び出しだけが、その値を上書きできる。
-   40,000 トークンの出力は、観測した速さでも 15 分の期限に収まる見込みである。期限を超えた場合は、期限切れとして失敗し、記事を公開しない。
-   上限に近い長さの記事や、`max` の effort の実行は、打ち切られることがある。打ち切られた実行の料金は発生し、記事は出ない。
-   上限を変えるときは、定数と、その値が満たす条件のテストを同じ変更で直す。文書の数値は変えない。

## 経緯

- 2026-10-10 Claude アダプタを書くとき、非ストリーミングの `max_tokens` の既定を 16,000 とし、3 つの段階で共有することにした（[0009 設計書](../../tasks/0009_claude_llm_client/02_architecture.md) §3.6）
- 2026-10-25 16,000 で打ち切られた実行を受け、既定を 40,000 に上げた。値は 1 つの定数に置き、根拠と測り直しの手順をガイドに移した（[0041 設計書](../../tasks/0041_claude_effort_max_tokens/02_architecture.md) §1.2）
