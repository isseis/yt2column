# ADR-0029: 拡張の UI を英語と日本語の 2 言語にし、表示の言語は resolveLocale の 1 か所で決める

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

最初の拡張は、利用者に表示する文言も英語で書いていた（[0007 要件定義書](../../tasks/0007_browser_extension_skeleton/01_requirements.md) F-001）。しかし、拡張の主な利用者は日本語の話者である。記事の本文は、プロンプトの指示によって素材の言語によらず日本語で書かれる。そのため利用者は、英語の UI と日本語の記事を行き来することになっていた（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md) §1）。

表示の言語は、ブラウザが返す UI の言語（`chrome.i18n.getUILanguage()`）から決める。この値は外部の文字列で、拡張の型では表せない。どこかで文字列の中身を調べて言語の型に変える必要があり、CLAUDE.md の「Declare, don't infer」と衝突する。そこで、調べる場所を 1 か所に限る必要がある（[0043 設計書](../../tasks/0043_extension_i18n/02_architecture.md) §3.1）。

拡張は設定を持たず、何も保存しない（[ADR-0010](0010-extension-stores-nothing.md)）。そのため、言語の選択を拡張の設定として持つことはできない。

## 決定

-   **表示の言語は英語（`en`）と日本語（`ja`）の 2 つにし、型 `Locale` で表す。** 拡張の UI、すなわちポップアップとビューアは、選んだ言語の文言で表示する。日本語でない UI の言語のブラウザでは、英語で表示する。
-   **言語はブラウザの UI の言語から決め、拡張に言語の設定を持たない。** 拡張は `chrome.i18n.getUILanguage()` の値を読む。例外を投げた場合と、文字列でない値を返した場合は、読めなかったものとして扱う。選んだ言語は保存しない。
-   **UI の言語の文字列の中身から振る舞いを選ぶのは、`resolveLocale` の 1 か所だけにする。** この例外の範囲・理由・境界は、[CLAUDE.md](../../../CLAUDE.md) の「Key Design Patterns」の「Declare, don't infer」にある `resolveLocale` の例外に従う。この ADR は、その理由と、採らなかった案を持つ。
-   **利用者に表示する文言は言語ごとのメッセージカタログに置き、英語と日本語の両方に必ず置く。** 英語と日本語のカタログは同じ型を持ち、片方に文言が欠けると型の検査が失敗する。開発者向けのログは英語のままとする。カタログの置き場所と、日本語の文言を置いてよいファイルは、[CLAUDE.md](../../../CLAUDE.md) の「Go Idioms」の拡張の段落に従う。ソースの言語の方針は [ADR-0035](0035-language-policy.md) が定める。
-   **ページの `lang` を表示の言語に合わせる。** ポップアップとビューアは、言語を決めた直後、最初の描画の前に、ページの `lang` を選んだ言語にする。静的な HTML の `lang` は `en` のままで、スクリプトが動かない場合は英語になる。ビューアの記事の本文は、UI の言語によらず `lang="ja"` を持つ。記事の内容の言語であり、UI の表示の言語ではない（[0063 要件定義書](../../tasks/0063_viewer_markdown/01_requirements.md)）。
-   **表示の言語の決まり方を利用者に説明するのは [README.md](../../../README.md) の「ブラウザ拡張」節の段落である。** この段落は、ポップアップの言語だけを述べている。現在のコードでは、ビューアも同じ規則で選んだ言語で表示する。段落がビューアに触れていないことは、記録した issue [#719](https://github.com/isseis/yt2column/issues/719) で扱う。

この決定の仕様の正本は、[CLAUDE.md](../../../CLAUDE.md) の「Key Design Patterns」の「Declare, don't infer」にある `resolveLocale` の例外と「Go Idioms」の拡張の段落、[README.md](../../../README.md) の「ブラウザ拡張」節の表示の言語の段落である。拡張の基盤は [ADR-0026](0026-extension-platform.md) が、拡張が何も保存しないことは [ADR-0010](0010-extension-stores-nothing.md) が定める。

## 採らなかった案

-   **利用者に表示する文言を英語だけにする。** 0007 の決定である。主な利用者は日本語の話者で、記事は日本語で書かれるので、英語の UI と日本語の記事を行き来することになる（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md) §1、[0043 設計書](../../tasks/0043_extension_i18n/02_architecture.md) §3.8）。
-   **拡張の中で言語を切り替える設定を設ける。** 拡張は設定画面を持たず、何も保存しない、という性質を保つためである（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md)「issue #506 で決めたこと」）。
-   **UI の言語の値が `ja` で始まれば日本語とする（文字どおりの前方一致）。** `jam`（ジャマイカ・クレオール語）のように `ja` で始まる別の言語の値も日本語になってしまう（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md)「要件定義の際に決めたこと（2026-10-27）」）。
-   **文言を持つ各モジュールの中に `Record<Locale, …>` の表を置く。** 言語を加えるたびに、文言を持つ 5 つ以上のファイルを変えることになり、英語と日本語の文言が混ざって読みにくくなる（[0043 設計書](../../tasks/0043_extension_i18n/02_architecture.md)「設計の際に決めたこと（2026-10-27）」）。
-   **ポップアップの文言に `chrome.i18n.getMessage` を使う。** issue #506 が TypeScript の表を決めており、`messages.json` では、理由の型との網羅を型で確かめられない（[0043 設計書](../../tasks/0043_extension_i18n/02_architecture.md)「設計の際に決めたこと（2026-10-27）」）。
-   **開発者向けのコンソールのログも多言語にする。** ログは利用者向けの UI ではない（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md)「要件定義の際に決めたこと（2026-10-27）」）。

## 結果

-   利用者に表示する文言を足すときは、英語と日本語の両方のカタログに同じ変更で足す。欠けると型の検査が失敗する。新しい画面も、`resolveLocale` で決めた言語と同じカタログを使う。
-   言語を加えるときは、`Locale` の型と `locales` に値を加え、その言語のカタログを加える。`resolveLocale` の判定の規則は変えずに済む（[0043 設計書](../../tasks/0043_extension_i18n/02_architecture.md) §3.1）。
-   英語と日本語以外の UI の言語の利用者は、英語の UI を見る。言語を拡張の中で選ぶ手段はない。
-   手順の中で示す YouTube のボタンの名前は、拡張の言語に合わせる。YouTube の表示言語と拡張の言語が違うと、名前が画面と一致しない。これはまれな場合として受け入れる（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md)「issue #506 で決めたこと」）。
-   UI の言語の文字列の中身を調べるコードを `resolveLocale` の外に足すことは、CLAUDE.md の「Declare, don't infer」に反する。足すときは、CLAUDE.md の例外の記述とこの ADR を同じ変更で改める。

- 2026-10-27 拡張の UI を英語と日本語の 2 言語にした。言語はブラウザの UI の言語から決め、最初の `-` より前の部分が `ja` のときだけ日本語にする。拡張に言語の設定は持たない。文言は言語ごとの表に置き、両方の言語を必須にする（[0043 要件定義書](../../tasks/0043_extension_i18n/01_requirements.md)「issue #506 で決めたこと」と「要件定義の際に決めたこと（2026-10-27）」）
