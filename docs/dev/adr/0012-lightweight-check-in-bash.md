# ADR-0012: 軽量プロセスの確かめ直しは、origin/main の版の bash スクリプトで行い、Go のツールにしない

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `廃止` |
| 廃止の日付 | 2026-11-09 |
| 廃止の理由 | 軽量プロセスを削除することにしたため。確かめ直しのスクリプトとそのテストは、0075 の実装の PR で削除するまで残り、その間は軽量プロセスを使わない（[0075 要件定義書](../../tasks/0075_remove_lightweight_process/01_requirements.md)） |
| 代わりの ADR | [ADR-0040](0040-simple-task-documents.md) |

## 背景

軽量プロセスでは、エージェントが要件・設計・計画の文書を作らずに 1 本の PR を作る。そのため、変更が軽量プロセスの条件を満たすかを、エージェントの申告ではなく、ブランチの実際の diff で確かめ直す必要がある。条件は、行数・ファイル数・除外するパス・道具のコミット（条件の表が許可したコマンド、つまり道具のコマンドが生成したコミット）についてのものである（[0061 設計書](../../tasks/0061_lightweight_process/02_architecture.md) 3.1「条件の定義」）。確かめ直しの結果が `FAIL` なら変更を戻すので、確かめ直しは信頼境界にある。

決定を縛る前提は次のとおりである。

-   確かめ直す仕組みは、確かめられる側のブランチから変更できてはならない。ブランチがその仕組みを書き換えれば、どの変更も通せる。
-   エージェントがコマンドを打ち直して実行すると、テストが走らせるものと実際に走るものが同じだと保証できない。PTY（疑似端末）は約 4000 バイトを超える入力を黙って切り詰めることがある。
-   タスク 0054 では、確かめる仕組みの方が、確かめる対象の変更より大きくなった。軽量プロセスの仕組みは、軽量に保つ。
-   bash では、単語分割・glob・`eval`・算術展開・呼び出し元の環境（エクスポートされた関数、`SHELLOPTS` など）によって、意図しないコマンドが動きやすい。

## 決定

-   **確かめ直しは、リポジトリのファイル `.claude/commands/_lib/lightweight-check.sh` の bash スクリプト（bash 3.2 で動く書き方）で行い、Go のツールは作らない。** パッケージ・テスト・インストールの手順を増やさず、確かめる仕組みを確かめる対象の変更より大きくしないためである。入力・出力・判定の取り決めは [0061 設計書](../../tasks/0061_lightweight_process/02_architecture.md) の 3.5.6「確かめ直しのスクリプト」にある。
-   **確かめ直しは、`git show origin/main:` で書き出した版のスクリプトを `bash` で実行し、作業ツリーの版は実行しない。** 確かめられる側のブランチが仕組みを書き換えられないようにするためである。呼び出しの形は、同じ 3.5.6 にある。
-   **bash の落とし穴への守りはスクリプトの本体に置く。** 呼び出し元の環境を持ち込まず、`eval` を使わず、外部のコマンドをシェルを通さずに語の配列として実行し、一時的なファイルと worktree を `trap` で消す。意図しないコマンドが動くのを防ぐためである（[lightweight-check.sh](https://github.com/isseis/yt2column/blob/dcc4edf34c99d8aecd47c81710420fb54b0a1b29/.claude/commands/_lib/lightweight-check.sh)）。
-   **git の設定・属性に左右されないための守り（設定の上書き、属性を空の tree から読むこと）も、同じスクリプトが持つ。** 利用者の git の設定（diff のアルゴリズム、外部の diff、textconv、hook など）で、数・コミットの読み取り・作業ツリーの判定が変わらないようにするためである。規則は [0061 設計書](../../tasks/0061_lightweight_process/02_architecture.md) の 3.1.2「行・ファイルの数え方」にある。

### 見直しの条件

次のどれかに当たったら、bash スクリプトのままにするか、Go のツールに移すかを決め直す。

1.  スクリプトの、空行とコメントの行を除いた行数が、テストの上限を超える。
2.  スクリプトが `eval` を使う。
3.  bash に特有の欠陥（単語分割・glob・`eval`・算術展開による注入、失敗の取りこぼし、bash の版による違い）が、レビューか実際の使用で見つかる。
4.  確かめ直しが、構造を持つ新しい種類の入力（JSON など）や、条件の表（軽量プロセスの条件を並べた表）の新しい種類の行を読む必要が出る。
5.  `origin/main` の版の Go のツールを、インストールの手順なしに、今と同じ程度の時間で動かせる方法が見つかる。

1 と 2 は、`make test` の `TestLightweightCheckRevisitConditions`（[lightweight_docs_test.go](https://github.com/isseis/yt2column/blob/dcc4edf34c99d8aecd47c81710420fb54b0a1b29/cmd/yt2column/lightweight_docs_test.go)）が、変更のたびに確かめる。行数の上限の値は、このテストの定数が持つ。3〜5 は数えられないので、テストにはしない。

決め直した結果、bash スクリプトのままにするときは、その理由をこの ADR の経緯に書く。1 に当たって bash スクリプトのままにするときは、同じ PR でテストの上限を上げる。Go に移すときは、条件の表と出力の形（0061 設計書 3.5.6）を保てば、実装の手順は変わらない。

## 採らなかった案

-   **Go のツールにする（`fixprguard` と同じ形）。** パッケージ・テスト・インストールの手順が増え、タスク 0054 で問題になった「確かめる仕組みの方が変更より大きい」状態を繰り返すため、採らなかった（0061 設計書 1.2 の H-01）。2026-11-05 に比べ直したところ、Go にすれば bash に特有の落とし穴（上の背景の最後の項目）はなくなる。一方で、次の 2 つがわかった。
    -   守りの大半（git の設定・属性への守りと、道具のコミットを worktree で再現すること）は git を呼ぶ側の守りで、Go でも同じだけ要る。
    -   `origin/main` の版を動かすという保証を維持するには、`origin/main` の worktree でのビルドか、利用者によるインストールが要る。インストールにすると、`origin/main` より古い版が動くことがある。

    そのため、今は移さず、見直しの条件を置いた。
-   **`runissue.md` のコードブロックに書く。** エージェントが打ち直して実行するので、テストが走らせるものと実際に走るものが同じだと保証できない。コマンドが長く、PTY の切り詰めのおそれもある。そのため採らなかった（0061 設計書 1.2 の H-01）。

## 結果

-   スクリプトは bash 3.2 で動く書き方に限られる。テストは、`PATH` 上の bash と macOS の `/bin/bash` の両方で走らせる。
-   `make test` は `bash` と、`--attr-source` を受け付ける `git` を要する（`CLAUDE.md` の「Development Notes」）。
-   スクリプトとそのテストには、仕様の見出しのための日本語のリテラルの例外がある（`CLAUDE.md` の「Go Idioms」）。ソースの言語の方針は [ADR-0035](0035-language-policy.md) が定める。
-   bash に特有の守りは、テストで支えるしかない。`TestLightweightCheck` は、fixture のリポジトリでスクリプトを実際に動かすので、時間がかかる（手元の開発環境では 30〜50 秒）。
-   スクリプトを変える PR は、見直しの条件に当たらないかを確かめる。数えられる条件はテストが確かめ、数えられない条件はスクリプトを読んで確かめる。

## 経緯

- 2026-11-04 確かめ直しを、リポジトリに置いた bash スクリプトで行い、`origin/main` の版を実行し、Go のツールを作らないと決めた（[0061 設計書](../../tasks/0061_lightweight_process/02_architecture.md) 1.2・3.5.6・9 章）
- 2026-11-05 見直しの条件を決め、数えられる 2 つ（行数の上限と `eval` を使わないこと）を `make test` のテストにした。スクリプトから `eval` を除いた（[0061 設計書](../../tasks/0061_lightweight_process/02_architecture.md) 1.5）
- 2026-11-09 軽量プロセスと、その確かめ直しのスクリプトとテストを削除することにしたので、この ADR を廃止した。文書を作る負荷を減らす役目は、[ADR-0040](0040-simple-task-documents.md) の簡易な進め方が引き継ぐ（[0075 要件定義書](../../tasks/0075_remove_lightweight_process/01_requirements.md)「要件定義の際に決めたこと（2026-11-09）」）
