# ADR-0008: 拡張の起動の経路をツールバーのポップアップだけにし、生成の開始は利用者のボタンの押下だけで行う

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

記事の生成は LLM の API の呼び出しにつながり、料金が生じる。生成の開始を送る操作は、利用者が送る内容を確かめてから行えなければならない（[0007 要件定義書](../../tasks/0007_browser_extension_skeleton/01_requirements.md) §1、[0020 要件定義書](../../tasks/0020_extension_send/01_requirements.md) F-005）。

起動の経路と、生成の開始を送る条件を、あわせて定める。

## 決定

-   **拡張を起動する手段は、ツールバーのアイコンから開くポップアップだけとする。** 右クリックメニューに項目を加えず、キーボードショートカットも設けない。生成を始める前に、利用者が送る内容を確かめられるようにするためである。規則は [security.md](../security.md) §8.1「ブラウザ拡張」にある。
-   **生成の開始は、利用者がポップアップの主ボタンか副次のボタンを押したときだけ送る。** 主ボタンの最初の押下は照会付きの生成の開始を送り、同じ動画の記事があれば、ポップアップは既存の記事を表示するか、現在の選択範囲で生成するかを選ばせる。ポップアップを開いたとき、オプションページを操作したとき、YouTube のページで文字列を選択したとき、ページに注入したスクリプトから、ほかの拡張からは、生成の開始を送らない。料金がかかる生成を、利用者の明示の操作のときだけ始めるためである。規則は [security.md](../security.md) §8.1、[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) F-001・F-004、[0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md) F-003 にある。
-   **Service Worker は、拡張自身のポップアップからの生成の開始だけを受け付ける。** 送り手が自分の拡張で、タブを持たず、URL がポップアップのページと完全に一致する求めだけを受け付け、ほかの求めには何も送らず、タブも開かない。ページに注入したスクリプトとほかの拡張から、料金のかかる生成を始めさせないためである。規則は [security.md](../security.md) §8.1 にある。
-   **API キーが保存されていなければ、生成を始めず、ビューアも開かない。** Service Worker は、生成の開始のリクエストを受けると、`chrome.storage.local.getKeys()` で API キーの項目があるかだけを確かめ、ないときは拒否を返す。Service Worker は API キーの値を読まない（[ADR-0010](0010-extension-stores-nothing.md)）。ポップアップは、設定が要ることと、オプションページを開く操作（`chrome.runtime.openOptionsPage`）を示す。LLM の API を呼ばず、利用者に次の手順を示すためである。規則は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「ポップアップ」にある。
-   **生成の開始を頼むボタンは、押下 1 回につき Service Worker に 1 回頼み、ビューアのタブを開かせる。** ポップアップは頼んだ後に自分では閉じず、予約の結果を待つ。1 回の操作で生成を 1 つだけ始め、その結果をビューアで見られるようにするためである。規則は 0090 設計書の「生成の開始と予約」と [ADR-0009](0009-viewer-opening.md) にある。
-   **ポップアップとビューアは、ジョブの記録を読み、`chrome.storage.onChanged` で表示を更新する。** 状態の取得を繰り返さない。開いただけで行うのは記録の読み取りで、LLM を呼ばない。Service Worker が停止しても、正しい値は `chrome.storage.session` にあり、表示を続けられるためである。記録は [ADR-0027](0027-article-job-api.md) が定め、規則は 0090 設計書の「ポップアップ」と「ビューアと Worker」にある。
-   **起動の経路のためのコードと権限は、ポップアップに要るものだけを持つ。** ページの読み込み時に自動で実行されるコード（`content_scripts`）を持たず、利用者が起動するまでページを読まない。結果のウィンドウ、ツールバーのバッジ、`contextMenus` の権限を持たない。`chrome.storage.session` はジョブの記録に使い、起動の経路には使わない。オプションページは API キーの設定だけを行い、生成の開始の契機にしない。利用者が起動するまでページを読まず、要求する権限を広げないためである。規則は 0090 設計書の「権限」と [ADR-0010](0010-extension-stores-nothing.md) にある。

この決定のうち、API キーの有無の確かめと、ジョブの記録による表示の更新は、まだコードに反映していない。今は、ポップアップとビューアがサーバへ状態の取得を繰り返す。この差分は [#773](https://github.com/isseis/yt2column/issues/773) の実装で解消する。

## 採らなかった案

-   **右クリックメニューの経路を残す。** メニューの経路では、誤って項目を選んだ場合や、字幕ではない場所を選択していた場合に送信を止められない。送信は LLM の API の呼び出しにつながるので、送る前に内容を確かめられるポップアップの経路のほうが安心で、使いやすかった。メニューの経路にしかない強みは、送信の途中でポップアップを閉じても結果を表示できることだけであり、ポップアップを閉じた場合の扱いは 0020 の設計がすでに受け入れている（[0027 要件定義書](../../tasks/0027_remove_context_menu/01_requirements.md) §1）。
-   **メニューの経路から `chrome.action.openPopup()` でポップアップを開く。** Brave で動作するか確かめていない（[0007 設計書](../../tasks/0007_browser_extension_skeleton/02_architecture.md) §3.6）。
-   **結果を通知やバッジだけで表示する。** 通知は OS の設定で表示されないことがあり、バッジは数文字しか表示できず、どちらも要件のタイトル・URL・プレビューを示せない（[0007 設計書](../../tasks/0007_browser_extension_skeleton/02_architecture.md) §3.6）。
-   **ポップアップも Service Worker に送信を依頼し、ポップアップが閉じられたら結果のウィンドウに示す。** ポップアップから Service Worker へ依頼するには、拡張の中のメッセージの受け口（`runtime.onMessage` または `runtime.onConnect`）が要る。この受け口は、拡張がページに注入した関数からも送れるので、YouTube のページの描画を担うプロセスが乗っ取られた場合、利用者の操作なしに送信を起動する入口になる（[0020 設計書](../../tasks/0020_extension_send/02_architecture.md) §3.8）。
-   **キーボードショートカットを設ける。** 理由は記録されていない（[0007 要件定義書](../../tasks/0007_browser_extension_skeleton/01_requirements.md) §2.3 はスコープ外とするだけである）。
-   **ポップアップとビューアが、実行するページに状態を問い合わせる。** ページの間の問い合わせが増え、Service Worker の停止と実行するページの再読み込みで表示が途切れうる（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「設計の際に決めたこと（2026-11-12）」）。

## 結果

-   生成の開始には、必ず利用者がポップアップで主ボタンか副次のボタンを押す操作が要る。ポップアップやオプションページを開いただけでは、LLM の呼び出しも課金も起きない。
-   拡張の起動経路は 1 つなので、経路ごとに送信の確認の有無を変える分岐がない。メニューの経路でだけ使っていたコードと権限もない。
-   Service Worker は、ポップアップからの生成の開始をまとめ、ビューアを開き、ジョブの記録を書き、同じジョブのビューアの引き継ぎを調整する。
-   利用者がポップアップを閉じても、生成は続く。結果はビューアで見られる。生成はビューアのタブの中で動くので、ビューアを閉じると止まる（[ADR-0009](0009-viewer-opening.md)）。

## 経緯

- 2026-10-07 拡張の起動の経路を、ツールバーのポップアップと右クリックメニューの 2 つにした。ポップアップは内容を確かめてから送る経路、メニューは確認なしに送る経路とする予定を決めた（[0007 要件定義書](../../tasks/0007_browser_extension_skeleton/01_requirements.md) §1）
- 2026-10-15 起動の手段ごとの送信の流れを定め、メニューの経路は確認なしに送り、ポップアップの経路はボタンを押すと送る形にした（[0020 要件定義書](../../tasks/0020_extension_send/01_requirements.md) F-005）
- 2026-10-19 右クリックメニューの経路を削除し、起動の経路をツールバーのポップアップだけにした。メニューの経路でだけ使っていた Service Worker・結果のウィンドウ・`chrome.storage.session`・バッジ・`contextMenus` の権限も削除した（[0027 要件定義書](../../tasks/0027_remove_context_menu/01_requirements.md)）
- 2026-10-29 ポップアップの主ボタンから Service Worker が生成の開始を送り、ビューアのタブを開く形にした。生成の開始は拡張自身のポップアップからの求めだけを受け付け、開いただけで送るのは状態の取得だけとした（[0050 要件定義書](../../tasks/0050_viewer_tab/01_requirements.md) §1）
- 2026-11-03 主ボタンの最初の押下を照会付きの生成の開始にし、同じ動画の記事があれば、ポップアップに選択の状態を示すことにした。選択の状態では、主ボタンは既存の記事を表示し、副次のボタン「現在の選択範囲で生成する」が照会なしの生成の開始を送る（[0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md)「要件定義の際に決めたこと（2026-11-03）」）
- 2026-11-11 Webhook への投稿の機能の廃止に合わせて、ビューアからの投稿の契機への参照を除いた（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md) F-001）
- 2026-11-12 状態の取得の繰り返しをやめ、ポップアップとビューアがジョブの記録を読んで表示を更新することにした。API キーがなければ生成を始めず、オプションページを開く操作を示す。`chrome.storage.session` をジョブの記録に使う（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)）
