# ADR-0044: 本番のバイナリに fake の LLM を入れず、fake の LLM はサーバに依存しない部品にして開発用のバイナリから使う

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

拡張とサーバの手での確認（レイアウト、状態の遷移、エラーの表示）は、LLM の出力の中身を必要としない。それでも、実際の LLM を呼ぶしかなく、料金と API キーが要り、記事・遅れ・失敗を再現できない。fake の `LLMClient` は単体テスト用のもの（ビルドタグ `test`）しかない。

fake を本番のバイナリに入れて設定で選べるようにすると、設定の誤りで、fake の記事が本番の利用者の前に出たり Webhook に投稿されたりしうる。

localhost サーバと Native Messaging のホストは、拡張だけの構成への移行で撤去される予定である（[#769](https://github.com/isseis/yt2column/issues/769)・[#773](https://github.com/isseis/yt2column/issues/773)）。サーバと一体の fake は、撤去とともに使えなくなる。

## 決定

-   **本番のバイナリ（`yt2column`・`yt2column-server`・`yt2column-nmhost`）は、fake の LLM にも開発用のバイナリのパッケージにも依存しない。これを機械的に確かめる。** 設定の誤りで fake の記事が本番の利用者の前に出ることや Webhook に投稿されることを、設定の検査ではなく構成で防ぐためである。規則は [0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md) の F-006 と、[security.md](../security.md) の §8.2「localhost サーバ（#109）」にある。
-   **fake の LLM は、サーバに依存しない部品にする。** サーバだけが使うパッケージに依存せず、WASM でビルドできる。サーバの撤去の後も、移行の後の開発用のビルドで使えるようにするためである。規則は 0086 要件定義書の F-001 にある。
-   **fake の振る舞いは、起動のときに選ぶ列挙値のシナリオで決める。開発用のサーバでは、シナリオをコマンドライン引数で渡す。** 本番の設定の読み込み（`YT2COLUMN_LLM` の構文と設定ファイルのキー）に fake を持ち込まず、[ADR-0003](0003-llm-config-contract.md)・[ADR-0018](0018-server-config-file.md)・[ADR-0024](0024-env-access-in-config.md) に例外を作らないためである。プロンプトの中身から振る舞いを推測しないのは、CLAUDE.md の「Declare, don't infer」による。規則は 0086 要件定義書の F-002 にある。
-   **開発用のサーバは、設定ファイルを読まず、API キーを要らず、Webhook への投稿に対応しない。** 投稿は [#770](https://github.com/isseis/yt2column/issues/770) で廃止される予定で、fake の記事を実際の Webhook に投稿する経路も構成で絶つためである。規則は 0086 要件定義書の F-002・F-005 にある。
-   **料金の単価の表（`internal/pricing`）に fake のモデルを入れない。fake の記事の料金は不明と表示させる。** 本番の単価の表に開発用の値を持ち込まないためである。規則は 0086 要件定義書の F-003 にある。

この決定は、まだコードと security.md に反映していない。この差分は [#687](https://github.com/isseis/yt2column/issues/687) の実装で解消する。

## 採らなかった案

-   **issue の提案のとおり、fake をサーバと一体で作り、#773 で一緒に撤去する。** 移行の後に使える部品が残らない（[0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）。
-   **拡張だけの構成の設計（#772）が決まるまで保留する。** #773 までの間の手での確認に、料金と再現性の問題が残る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **シナリオを、設定ファイルのキーか環境変数で渡す。** ADR-0018 の受理するキーが増えるか、ADR-0024 の入口の例外が要る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **開発用のサーバも本番と同じ設定ファイルを読み、投稿もできるようにする。** fake の記事が実際の Webhook に投稿されうる。投稿は #770 で廃止される（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake のモデルに単価 0 を与えて単価の表に入れる。** 本番の単価の表に fake が入る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。

## 結果

-   開発用のサーバは本番のサーバと同じソケットのパスで待ち受けるので、両方を同時には動かせない。本番のサーバの代わりに開発用のサーバを起動すると、拡張は fake の記事を表示する。記事のタイトルの印と起動の行で気づけるようにし、開発用のバイナリを常用の環境に置かないことを security.md で求める。
-   シナリオを変えるには、開発用のサーバを起動し直す。
-   fake の記事では、料金の表示は不明になる。料金がわかっているときの表示は、fake では確かめられない。
-   サーバの撤去（#773）のときに、開発用のサーバは一緒に撤去する。fake の部品は残り、移行の後の開発用のビルドへの配線は #772・#773 で決める。

## 経緯

- 2026-11-11 本番のバイナリに fake の LLM を入れず、fake をサーバに依存しない部品にして開発用のサーバから使い、開発用のサーバは設定ファイルを読まず投稿に対応しないと決めた（[0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）
