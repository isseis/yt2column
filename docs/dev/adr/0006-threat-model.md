# ADR-0006: ブラウザ拡張の脅威モデルは、同じ OS ユーザーを信頼し、ウェブページ・ほかの拡張・LLM の出力を排除する

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

拡張は、利用者の Anthropic API キーを保存し、利用者が選んだ字幕と動画メタデータを Claude API へ送り、返った記事を描画する（[ADR-0048](0048-extension-only-generation.md)）。記事の本文は LLM の出力で、字幕とメタデータへのプロンプトインジェクションで操作されうる。拡張のページはすべて同じオリジンにあり、記事を描画するビューアも API キーの保存の場所に届く。どの相手を信頼し、どの相手を排除し、何を受け入れるかで、権限・CSP・入力の検査・保存の手段が決まる。

守る資産は、API キーとワークスペース ID、利用者の料金、見た動画と作った記事、送る前のコピーした字幕と動画メタデータである。

## 決定

-   **同じ OS ユーザーのプロセス（AI Agent を含む）は信頼し、排除しない。** プロファイルのディレクトリを読めるので、`chrome.storage.local` の API キーを平文で読める。拡張の側の手段では防げず、CLI の `.envrc` と同じ水準として受け入れる（[ADR-0010](0010-extension-stores-nothing.md)）。規則は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「脅威モデル（要件書 AC-17）」にある。
-   **他の OS ユーザーのプロセスは、プロファイルのディレクトリの権限で排除する。** OS の既定に頼る前提で、拡張は確かめない。拡張の側に、他のユーザーを区別する手段がないためである。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」にある。
-   **ウェブページ（YouTube を含む）は排除し、拡張に届く経路を作らない。** 拡張のページを `web_accessible_resources` に含めず、`externally_connectable` を宣言せず、`onMessageExternal` を使わない。ページが偽れるのは、拡張が読む選択範囲と DOM の値だけで、それは信頼できない入力として検査する。ページから料金のかかる生成を始めさせず、保存した値に届かせないためである。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」と「信頼できない入力の境界（要件書 AC-18）」にある。
-   **注入した関数は、拡張のコードでも、隔離された世界で動くものとして扱う。** SW は、注入した関数からのリクエストをどれも受け付けない。`chrome.storage.local` は、`setAccessLevel` で注入した関数の世界から読めないようにする。注入した関数は選択範囲と動画メタデータを読むだけで、API キーを読まないためである。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」と「オプションページと API キーの保存」にある。
-   **ほかの拡張は排除する。** 別のオリジンなので、`chrome.storage` と拡張のページに届かず、`externally_connectable` がないのでメッセージも送れない。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」にある。
-   **プロンプトインジェクションで操作された LLM の出力は信頼しない。** 記事は文字として描画し、HTML を解釈しない（[ADR-0017](0017-viewer-markdown-rendering.md)）。ビューアと同じオリジンに API キーがあるので、スクリプトを動かさないことが本当の守りである。スクリプトが動いた場合の送り出しの経路は、CSP（[ADR-0010](0010-extension-stores-nothing.md)）が `fetch`・画像・フレーム・フォームについて狭めるが、ページの移動・`window.open`・`chrome.tabs.create` は止めない。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」と「CSP」にある。
-   **拡張のほかのページは、同じオリジンのものとして信頼する。** SW は、ビューアが計算して送る入力の値（`inputDigest` と動画 ID）をそのまま使う。どのページも本リポジトリで書いたコードだけを動かすためである。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」にある。
-   **Anthropic の API は送り先として信頼し、ネットワークの途中の相手は TLS で排除する。** 利用者が自分の API キーで使う先であり、ブラウザが証明書を検証する。規則は 0090 設計書の「脅威モデル（要件書 AC-17）」にある。秘密の持ち方と、秘密を出力に流さないことは [ADR-0031](0031-secret-closure.md) が定める。

この決定は、まだコードと [security.md](../security.md) §8 に反映していない。今の security.md §8 と拡張は、localhost サーバと Native Messaging のホストを前提にしている。規則は今は 0090 設計書の「セキュリティ考慮事項 (Security Considerations)」にあり、[#773](https://github.com/isseis/yt2column/issues/773) が security.md §8 に移し、この差分を解消する。

## 採らなかった案

-   **共有トークンで認証する。** 同一ユーザーのフル権限プロセスはトークンも `.envrc` も読めるので、トークンを残しても防げない（[0026 要件定義書](../../tasks/0026_native_messaging_relay/01_requirements.md) §4.2）。
-   **`Host`・`Origin` の検査を残し、ホストに `Origin` を付けさせる。** UDS ではソケットに接続できる相手なら誰でも偽れるので、検査しても排除できる相手がいない（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §3.4）。
-   **別ユーザー分離、launchd によるソケットの保護、拡張のエクスポートできない鍵によるリクエストの署名、リクエストごとの利用者の承認を行う。** 同一ユーザーのフル権限プロセスへの防御は本タスクの範囲外とし、必要になった場合は別のタスクとする（[0026 要件定義書](../../tasks/0026_native_messaging_relay/01_requirements.md) §2.3・§4.2）。
-   **拡張（ホスト）がサーバを認証する（接続先が本物のサーバであることを確かめる）。** 他のユーザーは、ソケットのディレクトリの `0700` と所有者の検査によって、ソケットのパスに名前を作れない。同じユーザーは、ファイルの権限でも uid でも区別できず、信頼の範囲に含める。認証で新たに排除できる相手が残らないので、行わない（[security.md](../security.md) §8.2）。ただし、ソケットのディレクトリがまだなく、その親に他ユーザーが書き込める既定でない設定では、ホストが接続先を検査しないので隙間が残る。これは [#678](https://github.com/isseis/yt2column/issues/678) で扱う。
-   **共有トークンを自動でローテーションする。** 漏洩時の作り直しは、利用者がトークンのファイルを削除してサーバを再起動する手動の手順とする（[0011 要件定義書](../../tasks/0011_localhost_server/01_requirements.md) §2.3）。
-   **API キーを読むページと、記事を描画するページを別のオリジンにする。** 拡張の中でオリジンを分ける手段がない（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「オプションページと API キーの保存」）。

## 結果

-   同じ OS ユーザーのプロセスは、`chrome.storage.local` の API キーを読め、利用者の料金で API を使える。
-   `tabs` や `history` の権限を持つほかの拡張と、ブラウザの同期は、ビューアの URL（ジョブ ID か開始の ID と、動画の URL）と、履歴のページのタイトル（動画のタイトル）を読める。ID は乱数で、記事の中身を表さない。動画の URL とタイトルは、YouTube の履歴にも残る値である。
-   記事の `https` の自動リンクは、任意のサイトを指しうる（ADR-0017）。
-   ビューアでスクリプトが動いたときの、ページの移動、`window.open`、`chrome.tabs.create` による値の送り出しは、CSP では止められない。ビューアでスクリプトを動かさないこと（ADR-0017）に頼る。
-   利用者の組織がゼロデータ保持（ZDR）か Compliance API を有効にしていると、ブラウザから Claude API を呼べず、拡張を使えない（0090 設計書の「構成を縛る外部の条件（要件書 AC-20）」）。
-   `setAccessLevel` が `chrome.storage.local` に効かないと分かった場合は、注入した関数の世界から API キーを読めることを受け入れる。注入した関数は本リポジトリで書いたもので、ページのスクリプトはその世界の拡張の API に届かない（0090 設計書の「確かめていない事項の判定（要件書 AC-21・AC-22）」）。
-   権限・CSP・保存の手段・入力の検査を変える変更は、この脅威モデルの相手ごとの根拠を崩さないかを確かめる。

## 経緯

- 2026-10-13 localhost サーバを loopback にだけ bind し、`Host`・`Origin`・`Content-Type`・共有トークンで入口を限定した。同一ユーザーとして動くプロセスは信頼し、トークンのファイルを読めることと、停止中に他の利用者がポートを先に使えることを残余のリスクとして受け入れた（[0011 設計書](../../tasks/0011_localhost_server/02_architecture.md) §5.1・§5.2・§5.4）
- 2026-10-16 拡張は共有トークンを `chrome.storage.local` に保存して送信に使い、サーバを認証しないこと（ポートを先に使うプロセスへの送信）を残余のリスクとして受け入れた。偽のサーバがありうるので、応答を信頼できない入力として検査する（[0020 設計書](../../tasks/0020_extension_send/02_architecture.md) §5.1・§5.4）
- 2026-10-19 待ち受けを TCP から UDS に変え、ソケットのディレクトリの `0700` とソケットの `0600` で他のユーザーを排除し、共有トークン・ポート設定・`Host`/`Origin` の検査を削除した。排除する相手ごとに根拠（他のユーザー・ウェブページ・サンドボックス化された Agent）を書き分けた（[0026 設計書](../../tasks/0026_native_messaging_relay/02_architecture.md) §5.1〜§5.4）
- 2026-11-03 照会付きの生成の開始で、同じ動画の記事の有無とキーを生成を始めずに返すことにした。0044 が排除する脅威とした、生成を始めずに記事の有無を知ること（T-10）を、ソケットに接続できる同じユーザーのプロセスは信頼するので、信頼の境界の内側で受け入れるリスクとして再評価した。キーをプロセスごとの秘密から計算することは、キーの計算方法に依存させないために保った（[0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md)「要件定義の際に決めたこと（2026-11-03）」）
- 2026-11-11 Webhook への投稿の機能の廃止に合わせて、同一ユーザーのプロセスが読める資産から Webhook URL を、直接使えるサービスから Slack を除いた（[0083 要件定義書](../../tasks/0083_remove_slack_webhook/01_requirements.md) F-001）
- 2026-11-12 localhost サーバと Native Messaging のホストの廃止に合わせて、拡張だけの構成の脅威モデルに改めた。同じ OS ユーザーを信頼し、ウェブページ・注入した関数・ほかの拡張・LLM の出力を根拠ごとに排除し、API キーを守る資産に加えた（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)）
