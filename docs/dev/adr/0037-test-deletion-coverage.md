# ADR-0037: テストを削除したことは、削除だけのコミットの前後のカバレッジの比較で確かめ、その出力をコミットメッセージと PR の説明に残す

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

テストを削除すると、そのテストだけが実行していた製品のコードが、どのテストからも実行されなくなることがある。残るテストはそれでも通るので、確認が失われたことに気づけない。

ファイルごとの網羅率の割合では、この低下を見つけられない。行を削除するファイルでは分母が変わるからである（[0027 要件定義書](../../tasks/0027_remove_context_menu/01_requirements.md) AC-09）。

規則は、もともと Go について `go tool cover -func` の結果を関数ごとに比べることだけを求めていた。比べる常設の道具はなかった。そのため、テストを削除するタスクのたびに比べる手順を設計し直し、一度きりの道具を作ってきた。拡張では、比較を規則の例外として承認を得る手間もかかった。0054 では、最終的な変更が 2 ファイル・16 行の削除だったのに対し、ローカルのレビューの指摘の多くは、一度きりの比較の手順の頑健さに集中した（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md) 1 章「背景」）。

拡張の lcov には、比べるときの落とし穴がある。名前のない関数の名前は、同じコミットでも実行のたびに変わる。カレントディレクトリやテストの指定を誤ると、テストが 1 つも動かずに報告が空になり、比較が通ってしまう。テストが失敗した実行の報告では、失敗したテストが実行させるはずの関数が欠ける（[0054 設計書](../../tasks/0054_remove_empty_metadata_result/02_architecture.md) §3.2）。

## 決定

-   **テストの削除は、削除だけのコミットの前後で、製品のコードのカバレッジを関数ごとに比べて確かめる。比較の出力は、そのコミットのメッセージと PR の説明に残す。** コミットの分け方、BASE の取り方、実行の時間の上限、合格の基準、合格にせずに止まる場合、出力を書く場所とメッセージの直し方は、[CLAUDE.md](../../../CLAUDE.md) の「Testing Strategy」の「Deleting a test is a claim that must be checked」に従う。2 つの入口は、[CLAUDE.md](../../../CLAUDE.md) の「Test Commands」の `make coverage-compare` と、「Extension Commands」の `make ext-coverage-compare` の項目にある。この ADR は、その規則の理由と、採らなかった案と、経緯を持つ。
-   **Go と拡張を同じ形で確かめる。** 拡張での比較は、規則の例外ではない。どちらも関数の単位で比べ、行と分岐の単位では比べない。比べるのは製品のコードの関数だけで、テストのための補助のコードは比べない。Go では `test` のタグで組まれるファイルを、拡張では `extension/src/`・`extension/scripts/` の外のファイルを比べない（`internal/coveragecompare` の製品のコードの見分け方）。
-   **削除した関数は、前後のソースの差分から道具が求める。** 利用者は、削除した関数を申告しない。残る関数の範囲に差分の行がある比較と、HEAD にだけある関数がある比較は、対応が取れないとして止まり、合格にならない。このため、テストの削除は、製品のコードの書き換えと別のコミットにする。
-   **比較は、テストを削除する変更で人やエージェントが実行する。** CI では実行しない。
-   **比較の道具を、テストのある Go の開発ツール（`cmd/coveragecompare` と `internal/coveragecompare`）に置くことは、[ADR-0014](0014-deterministic-checks-in-go.md) が定める。**

## 採らなかった案

-   **ファイルごとの網羅率の割合で比べる。** 行を削除するファイルでは分母が変わるので、関数ごとの到達の有無を比べられない（[0027 要件定義書](../../tasks/0027_remove_context_menu/01_requirements.md) AC-09、[0027 設計書](../../tasks/0027_remove_context_menu/02_architecture.md) §3.11）。
-   **行と分岐の単位でも比べる（0027 の比べ方）。** 関数の単位の比較で、テストの削除で関数が実行されなくなることは見つけられる。Go は関数ごとの網羅率まで比べるので、関数の中の文の網羅率の低下も見つけられる（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」、2.3）。
-   **テストを削除するタスクごとに、一度きりの手順や道具で比べる（0027・0038・0052・0054 の比べ方）。** タスクのたびに比べる手順を設計し直すことになり、拡張では比較を規則の例外として承認を得る手間もかかる。0054 では、レビューの指摘の多くが一度きりの手順の頑健さに集中した（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md) 1 章「背景」、2.1）。
-   **Go で、関数ごとの結果が前後で変わらないことを求める（0055 より前の規則と 0038・0052 の基準）。** 残る関数の中身が変わる変更は止めるので、網羅率の分母は前後で変わらない。テストを削除して網羅率が上がるのは、テストの順序などで実行が変わる場合に限られ、それは削除の確認の失敗ではない（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **`go tool cover -func` の出力で比べる。** 網羅率を小数第 1 位に丸めて出すので、丸めると同じになる小さな減少が見えなくなる（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md) AC-10、[0055 設計書](../../tasks/0055_coverage_compare/02_architecture.md) §3.4）。
-   **Go のカバレッジをパッケージごとに測る。** `cmd/yt2column` のテストが `internal/` のパッケージのコードも実行するので、パッケージごとに測ると、削除で起きる別のパッケージの網羅率の低下を見落とす（[0038 設計書](../../tasks/0038_doc_test_pruning/02_architecture.md) §7.1、[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **テストのための補助のコードも比べる。** テストを削除すると、補助のコードの網羅率が下がるのは自然なことであり、製品のコードに影響のない削除でも不合格になる（[0052 設計書](../../tasks/0052_doc_test_pruning/02_architecture.md) §7.1、[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **削除した関数を利用者が指定する。** 行番号のずれに対応を付けるために差分はどのみち使うので、指定の誤りという新しい失敗を増やさないよう、差分から求める（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **同じ行から始まる拡張の関数に、BASE で実行回数 0 の関数があれば止める（0054 の比べ方）。** 常設の道具でそうすると、`a => b => ...` のように内側が呼ばれない関数を持つファイルで、削除と関係なく毎回止まり、利用者が先に進めなくなる（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **比較の結果をコミットメッセージだけに書く（0038 の記録の仕方）。** PR は squash merge され、ブランチのコミットメッセージは `main` に残らないので、PR の説明にも書く（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   **比較を CI で自動で実行する。** 理由は記録されていない（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「issue #618 で決めたこと」は、テストを削除する変更で人や agent が実行するとだけ述べる）。

## 結果

-   テストを削除する変更では、削除だけのコミットを分け、テストの一式を 2 回走らせる比較を実行する。Go では 1 回の比較に数分かかる。
-   製品のコードの書き換えとテストの削除を分けられない変更では、道具は対応が取れないとして止まり、規則の手順では確かめられない。0059 と 0062 は、それぞれのタスクに限った扱いとして、テストの移し替えを製品のコードを変えないコミットにして削除より先に置き、残る関数を書き換える削除のコミットは、タスクの `_checks/` のスクリプトで、関数を名前で対応づけて比べた（[0059 設計書](../../tasks/0059_remove_legacy_articles_api/02_architecture.md)「1.3. 設計の際に決めたこと（2026-11-04）」、[0062 要件定義書](../../tasks/0062_remove_cli_slack/01_requirements.md)「要件定義の際に決めたこと（2026-11-04）」）。
-   カバレッジは、コードが実行されたことを示すだけで、削除したテストが何を確かめていたかは示さない（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md) 2.3）。製品のコードを通らない確認を誤って消しても、比較の結果は変わらない（[0038 設計書](../../tasks/0038_doc_test_pruning/02_architecture.md) §7.1）。
-   拡張で同じ行から始まる関数は、実行された数で比べる。BASE で実行されなかった関数が実行されるようになり、同時に別の関数が実行されなくなると、道具はこれを見逃す。この入れ替わりが起きるのは、同じ変更でテストを加えたか書き換えた場合に限られる（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「要件定義の際に決めたこと（2026-11-02）」）。
-   CI は比較を実行しないので、比較を実行したことの記録は、コミットメッセージと PR の説明に書いた出力だけである。
-   拡張の比較にも Go が要る。道具の置き場所と、拡張の関数の範囲を TypeScript の補助に求めることは [ADR-0014](0014-deterministic-checks-in-go.md) が定める。

## 経緯

- 2026-10-19 拡張のテストを削除するときも、削除の前後のカバレッジを比べることにした。ファイルごとの割合は分母が変わるので比べず、lcov の行・分岐・関数の到達を、ソースの差分で前後の行を対応づけて比べた。手順は一度きりとし、`make` の対象にしなかった（[0027 設計書](../../tasks/0027_remove_context_menu/02_architecture.md) §3.11）
- 2026-10-23 文書のテストを削除するたびに、Go のカバレッジを関数ごとに比べる方針を保った。`-coverpkg=./...` を付けてモジュール全体で測り、前後どちらもテストが通った実行だけを基準にし、変わらなかったことをコミットメッセージに書くことにした（[0038 要件定義書](../../tasks/0038_doc_test_pruning/01_requirements.md)「issue #455 で決めたこと」、[0038 設計書](../../tasks/0038_doc_test_pruning/02_architecture.md) §7.1）
- 2026-10-31 カバレッジの比較の方針を保ち、比べる対象を製品のコードの関数に限った。テストのための補助そのものを取り除くと、補助の関数の結果は必ず変わるためである。結果は、コミットメッセージに加えて PR の説明にも書くことにした（[0052 要件定義書](../../tasks/0052_doc_test_pruning/01_requirements.md)「issue #591 で決めたこと」、[0052 設計書](../../tasks/0052_doc_test_pruning/02_architecture.md) §7.1）
- 2026-11-01 拡張のテストの削除を、規則の例外として、`src/` の関数の実行回数が 0 にならないことで確かめることにした。行と分岐は比べず、関数は (ファイル, `FN` の行) で識別し、削除の前の報告は削除のコミットの親で取る（[0054 要件定義書](../../tasks/0054_remove_empty_metadata_result/01_requirements.md)「issue #560 で決めたこと」「方針の例外」、[0054 設計書](../../tasks/0054_remove_empty_metadata_result/02_architecture.md) §3.2）
- 2026-11-02 一度きりの手順に代えて、Go と拡張の両方を関数ごとに比べる常設の道具と、`make coverage-compare`・`make ext-coverage-compare` の 2 つの入口を設けることにした。Go は網羅率が下がらないこと、拡張は実行回数が 0 にならないことを基準とし、削除した関数は差分から求め、削除以外の変更を含む比較と測れていない比較は止める。CLAUDE.md の規則をこの道具を使う手順に書き換え、拡張での比較を規則の例外でなくした。結果はコミットメッセージと PR の説明に書く（[0055 要件定義書](../../tasks/0055_coverage_compare/01_requirements.md)「issue #618 で決めたこと」「要件定義の際に決めたこと（2026-11-02）」）
