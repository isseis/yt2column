# ADR-0009: ビューアは生成の開始と同時に背面のタブで開き、ポップアップは閉じずに状態を表示する

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

記事は必ずブラウザに表示し、Slack への投稿はビューアからの利用者の操作で行う（[ADR-0011](0011-webhook-publishing.md)）。生成の開始はポップアップの主ボタンか副次のボタンから Service Worker が送り、ビューアとポップアップが記事のキーで状態の取得を繰り返す（[ADR-0008](0008-launch-path.md)）。

ポップアップは、利用者がページやほかのタブをクリックするとブラウザが閉じる。生成の開始の応答は最大で約 20 秒かかるので、応答を待ってからビューアを開くと、待つ間にポップアップを閉じた場合に、拒否の理由がどこにも表示されない。ビューアの開き方と、ポップアップを閉じるかどうかを、あわせて定める。

## 決定

-   **生成の開始を送るボタンを押すと、Service Worker がビューアを背面のタブとして開く。** 開くのは生成の開始を送る前で、キーを受け取るのを待たない。タブは作業中の YouTube のタブの隣（同じウィンドウ、`index + 1`、`openerTabId` に YouTube のタブ）に開き、作業中のタブを切り替えない。
-   **ポップアップは、送った後に自分では閉じず、応答を待つ。** 閉じるのは利用者である。ポップアップは、生成中・生成済み・失敗の状態を表示し続け、ビューアのタブを前面に出す操作を持つ。前面に出すと、ポップアップは閉じる。
-   **照会付きの生成の開始で同じ動画の記事があると知らされたら、ポップアップは選択の状態を示す。** 選択の状態は、既存の記事があることとその状態（生成中か生成済みか）を示し、主ボタン「既存の記事を表示する」と副次のボタン「現在の選択範囲で生成する」を持つ。選択の状態の間に既存の記事が失敗したか失われたら、選択の状態を終え、主ボタンを照会付きの生成の開始に戻す。
-   **照会付きの生成の開始で開いたビューアのタブは、同じ動画の既存の記事を表示する。** ビューアは、既存の記事を表示していることの印（`e=1`）を URL に加え、一度付けた印は取り除かない。印を持つビューアは、現在の選択範囲からは生成していないことと、現在の選択範囲で生成する手順を示し、処理中の経過時間を示さない。同じキーのビューアがすでにあれば、下の引き継ぎと同じく新しいタブを閉じる。
-   **「ビューアを開く」と「既存の記事を表示する」では、ポップアップ自身が前面のタブを開く。** この送信の表示を受け持つビューアのタブ、なければ同じキーのほかのビューアのタブを前面に出し、どちらもなければ、ポップアップが新しいビューアのタブを前面に開く。この 2 つの操作は生成の開始を送らない。
-   **キーを受け取れなかった場合も、ビューアに理由と手順を表示する。** 拒否・未送信・結果不明のいずれでも、ビューアは生成の開始の結果を表示する。タブを開けなかった場合も、生成の開始は送る。
-   **同じキーのビューアがすでにあるときは、新しいタブを閉じて既存のビューアに引き継ぐ。** Service Worker が `BroadcastChannel` で同じキーのビューアを探し、引き継ぎを頼み、新しいタブを `tabs.remove` で閉じる。新しいビューアの最初の `AwaitStart` が届くのを最大 5 秒待ってから問い合わせ、送り直すたびにタブが増えるのを防ぐ。
-   **権限を加えずに開き、前面に出す。** ビューアのタブは `chrome.tabs` の権限の要らない操作（作成・選択・削除・取得）で開き、`chrome.windows.update` で前面に出す。ビューアは `web_accessible_resources` に含めない。送信ごとの値はビューアの URL と各ページのメモリにだけ置く（[ADR-0010](0010-extension-stores-nothing.md)）。

この決定の採らなかった案の全体は、[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) の付録 B「決定の履歴」B.1〜B.3 にある。仕様の正本は [security.md](../security.md) §8.1「ブラウザ拡張」と [0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) の §1.2・§6.1・§6.2 である。

## 採らなかった案

### ビューアの開き方

-   **前面のタブで開く。** 前面で開くとポップアップがすぐに閉じ、ポップアップの状態（生成中・生成済み・失敗）が表示されない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **キーを受け取ってから開く。** 生成の開始の応答は最大で約 20 秒かかる。その間に利用者がポップアップを閉じると、拒否の理由がどこにも表示されず、「ポップアップを閉じても結果は失われない」を満たせない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **ポップアップがタブを開く。** ポップアップは利用者がいつでも閉じられる。ポップアップがタブを開いてから Service Worker に送ると、その間に閉じられた場合、タブだけが開いて生成の開始が送られない。また、Service Worker はビューアの `AwaitStart` を `sender.tab.id` で記録と対応づけ、引き継ぎの後に新しいタブを閉じるので、タブを開く処理と送る処理を Service Worker の 1 つの処理に置くほうが、タブの ID を知る部品と送信を記録する部品が同じになる（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **`windows.create` で別のウィンドウを開く。** 要件は、記事をビューアのタブで表示すると定める。また、別のウィンドウで結果を表示する方式（0020 の結果のウィンドウ）は、0027 で右クリックメニューの経路と一緒に削除した（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。

### ポップアップを閉じるかどうか

-   **送った直後に `window.close` を呼ぶ。** 止まっていた Service Worker は、送った直後にスクリプトが同期的に閉じたポップアップからのメッセージを受け取らなかった（Chrome・Brave の両方）。タブが開かず、生成の開始も送られない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **`runtime.connect` のポートで送り、すぐに閉じる。** ポートで送っても、同期的に閉じた場合は、止まっていた Service Worker に届かなかった（Brave で確かめた）（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **ポートで Service Worker の受け取りの確認を受けてから閉じる。** 確認は 22〜31 ms で届き、閉じても生成の開始は送られたが、要件がポップアップを開いたままにして状態を表示すると定めるので、自分で閉じる仕組みそのものが要らない。閉じなければ、確認のためのポートの仕組みも要らない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **決めた時間（100 ms など）の後に閉じる。** 100 ms の後に閉じた場合は届いたが、閉じる理由がないことは上の案と同じである。また、待つ時間が足りることを保証する根拠がない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。

### 同じキーのビューアの引き継ぎを調整する部品

-   **新しいビューアが自分で調べ、自分のタブを閉じる。** 要件の書き方に近い案であるが、調整が 1 か所に集まらず、ポップアップは「ビューアを開く」で前面に出すタブを、推測ではなく Service Worker の応答で知ることができない。拡張のページが自分のタブを閉じるのに `window.close` を使わないという決まりにも合わない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.3）。

## 結果

-   ビューアは、生成の開始を送ると同時に背面のタブとして開く。利用者は作業中のタブを切り替えずに、生成の状態をポップアップで見られる。
-   ポップアップは自分では閉じない。利用者が閉じた場合は、ビューアがサーバへの状態の取得を続けるので、キーを受け取った後の表示は失われない。
-   同じキーのビューアがすでにあるときは、新しいタブを閉じて既存のビューアに引き継ぐ。送り直すたびに同じ記事のタブが増えることはない。
-   利用者が主ボタンを押した直後に手でポップアップを閉じた場合は、止まっていた Service Worker にもメッセージが届いた。この観察に頼る。
-   破棄されたタブは、`tabs` の権限を加えずには見つけられない。「ビューアを開く」は破棄されたタブを見つからないものとして扱い、同じ記事のタブが重複して開くことを例外として受け入れる。
-   権限は `activeTab`・`scripting`・`nativeMessaging` のままで、ビューアを開くために権限を加えない。
