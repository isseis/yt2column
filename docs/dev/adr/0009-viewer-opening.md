# ADR-0009: ビューアは生成の開始と同時に背面のタブで開いて Worker で記事を生成し、ポップアップは閉じずに状態を表示する

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

記事は必ずブラウザに表示し、保存とコピーはビューアからの利用者の操作で行う。生成の開始はポップアップの主ボタンか副次のボタンから Service Worker（SW）に頼み、ポップアップとビューアはジョブの記録を読んで状態を表示する（[ADR-0008](0008-launch-path.md)・[ADR-0027](0027-article-job-api.md)）。記事の生成は、それを実行する拡張のページの寿命に従う（[ADR-0048](0048-extension-only-generation.md)）。

利用者がページやほかのタブをクリックすると、ブラウザはポップアップを閉じる。生成を実行するページは、記事生成モジュールを読み込み、入力を検査し、予約の結果を受け取ってから生成を始めるので、その間にポップアップが閉じられても、拒否の理由と結果を表示できる場所が要る。WASM を読み込んだページは、生成を終えた後もそのメモリを手放さない。記事の生成を実行したタブ全体のメモリは、試行の前後で 61.6〜85.8 MB だった（うち WASM の分は測っていない。[調査記録](../../research/wasm_pipeline_poc/README.md)「測定 6：本番の構成（Chrome、`83ef12bd`、背面のまま）」）。ビューアの開き方、生成を実行する場所、ポップアップを閉じるかどうかを、あわせて定める。

## 決定

-   **生成の開始を頼むボタンを押すと、SW がビューアを背面のタブとして開く。** 開くのは予約の前で、予約の結果を待たない。作業中の YouTube のタブを切り替えずに、生成の状態を見られるようにするためである。規則は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「生成の開始と予約」にある。
-   **SW が開いたビューアが、専用の Web Worker の中で記事生成モジュールを動かして記事を生成し、完成か失敗で Worker を止める。** 止めた後は、ジョブの記録を表示するだけのビューアになる。生成の寿命をタブの寿命に合わせ、WASM のメモリを生成の間だけ使うためである。一度も前面にならなかった背面のタブで完走することは、0090 設計書の「確かめていない事項の判定（要件書 AC-21・AC-22）」の (a) で確かめる。規則は 0090 設計書の「ビューアと Worker」にある。
-   **実行するビューアは、実行の間 SW への Port を保ち、切れたらつなぎ直す。`chrome.storage.onChanged` で自分の記録を見張り、記録が消えたときと、記録の実行するページが自分でなくなったときに Worker を止める。記録が止まった状態になっただけでは止めない。** SW が、ページがなくなったことを Port の切断で知り、誤って止まった状態にした実行の結果も受け取れるようにするためである（[ADR-0027](0027-article-job-api.md)）。同じ入力が別のビューアで予約し直されたら、古い実行を止めて料金を並んでかけないためである。実行の間は、読み込み直す前に確認の表示を出す。規則は 0090 設計書の「ビューアと Worker」と「止まった実行の判定」にある。
-   **ビューアのタブを開けなかったときは、生成の開始を拒否する。** 生成を実行するのがそのタブなので、開けなければ生成できないためである。今の「タブを開けなくても生成の開始を送る」を改めた。規則は 0090 設計書の「生成の開始と予約」にある。
-   **ポップアップは、頼んだ後に自分では閉じず、結果を待つ。** 閉じるのは利用者である。ポップアップは、生成中・生成済み・失敗・止まった状態を表示し続け、ビューアのタブを前面に出す操作を持つ。前面に出すと、ポップアップは閉じる。前面で開くとポップアップがすぐに閉じ、表示すべき状態が見られないためである。規則は 0090 設計書の「ポップアップ」と [0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) §6.1 にある。
-   **照会付きの生成の開始で同じ動画の記事があると示されたら、ポップアップは選択の状態を示す。** 選択の状態は、既存の記事があることとその状態を示し、主ボタン「既存の記事を表示する」と副次のボタン「現在の選択範囲で生成する」を持つ。既存の記事を表示するか、現在の選択範囲で作り直すかを、利用者に選ばせるためである。規則は [0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md) F-003 にある。
-   **照会付きの生成の開始に同じ動画が示されたら、そのビューアのタブは Worker を止め、同じ動画の既存の記事を表示する。** ビューアは、既存の記事を表示していることを示す印を URL に加え、一度付けた印は取り除かない。印を持つビューアは、現在の選択範囲からは生成していないことと、現在の選択範囲で生成する手順を示し、処理中の経過時間を示さない。再読み込みや履歴からの表示の後も、既存の記事であることを利用者に示すためである。規則は [0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md) F-004 と [0058 設計書](../../tasks/0058_same_video_article/02_architecture.md) §3.7「既存の記事のビューア」にある。
-   **「ビューアを開く」と「既存の記事を表示する」では、ポップアップ自身が前面のタブを開く。** この開始の表示を受け持つビューアのタブ、なければ同じジョブのほかのビューアのタブを前面に出し、どちらもなければ新しいビューアのタブを前面に開く。この 2 つの操作は生成を始めない。頼み直さずに既存の記事を見せるためである。規則は [0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) §6.6「ビューアを開く（ポップアップ）」と [0058 要件定義書](../../tasks/0058_same_video_article/01_requirements.md) F-003 にある。
-   **予約に至らなかった場合も、ビューアに理由と手順を表示する。** 入力の検査の拒否、上限の拒否、入力を受け取れなかった場合のいずれでも、ビューアは結果を表示する。利用者が次に何をすればよいか分かるようにするためである。規則は 0090 設計書の「利用者に示す状態の種類」にある。
-   **同じジョブのビューアがすでにあるときは、新しいタブを閉じて既存のビューアに引き継ぐ。** 既存のジョブ（処理中か完成のジョブ。止まったか失敗したジョブは、予約で新しいビューアが実行するページになって生成し直す）を示された新しいビューアは、Worker を止めた後、同じジョブ ID のビューアを `BroadcastChannel` で探して引き継ぎ、押し直すたびにタブが増えないようにする。規則は 0090 設計書の「ビューアと Worker」と [0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) §6.2「同じキーのビューアの再利用」にある。
-   **権限を加えずに開き、前面に出す。** ビューアのタブは `chrome.tabs` の権限の要らない操作で開き、`chrome.windows.update` で前面に出す。ビューアは `web_accessible_resources` に含めない。権限を広げないためである。規則は [ADR-0010](0010-extension-stores-nothing.md) と 0090 設計書の「権限」にある。

この決定のうち、ビューアが記事の生成を実行すること、Port と記録の見張り、タブを開けなければ拒否すること、ジョブの記録による表示は、まだコードに反映していない。今のビューアは、サーバへ状態の取得を繰り返して表示するだけである。この差分は [#773](https://github.com/isseis/yt2column/issues/773) の実装で解消する。

この決定の採らなかった案の全体は、[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) の付録 B「決定の履歴」B.1〜B.3 にある。

## 採らなかった案

### ビューアの開き方

-   **前面のタブで開く。** 前面で開くとポップアップがすぐに閉じ、ポップアップの状態（生成中・生成済み・失敗）が表示されない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **キーを受け取ってから開く。** 生成の開始の応答は最大で約 20 秒かかる。その間に利用者がポップアップを閉じると、拒否の理由がどこにも表示されず、「ポップアップを閉じても結果は失われない」を満たせない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **ポップアップがタブを開く。** ポップアップは利用者がいつでも閉じられる。ポップアップがタブを開いてから Service Worker に送ると、その間に閉じられた場合、タブだけが開いて生成の開始が送られない。また、Service Worker はビューアの `AwaitStart` を `sender.tab.id` で記録と対応づけ、引き継ぎの後に新しいタブを閉じるので、タブを開く処理と送る処理を Service Worker の 1 つの処理に置くほうが、タブの ID を知る部品と送信を記録する部品が同じになる（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。
-   **`windows.create` で別のウィンドウを開く。** 要件は、記事をビューアのタブで表示すると定める。また、別のウィンドウで結果を表示する方式（0020 の結果のウィンドウ）は、0027 で右クリックメニューの経路と一緒に削除した（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.1）。

### ポップアップを閉じるかどうか

-   **送った直後に `window.close` を呼ぶ。** 止まっていた Service Worker は、送った直後にスクリプトが同期的に閉じたポップアップからのメッセージを受け取らなかった（Chrome・Brave の両方）。タブが開かず、生成の開始も送られない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **`runtime.connect` のポートで送り、すぐに閉じる。** ポートで送っても、同期的に閉じた場合は、止まっていた Service Worker に届かなかった（Brave で確かめた）（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **ポートで Service Worker の受け取りの確認を受けてから閉じる。** 確認は 22〜31 ms で届き、閉じても生成の開始は送られたが、要件がポップアップを開いたままにして状態を表示すると定めるので、自分で閉じる仕組みそのものが要らない。閉じなければ、確認のためのポートの仕組みも要らない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。
-   **決めた時間（100 ms など）の後に閉じる。** 100 ms の後に閉じた場合は届いたが、閉じる理由がないことは上の案と同じである。また、待つ時間が足りることを保証する根拠がない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.2）。

### 同じキーのビューアの引き継ぎを調整する部品

-   **新しいビューアが自分で調べ、自分のタブを閉じる。** 要件の書き方に近い案であるが、調整が 1 か所に集まらず、ポップアップは「ビューアを開く」で前面に出すタブを、推測ではなく Service Worker の応答で知ることができない。拡張のページが自分のタブを閉じるのに `window.close` を使わないという決まりにも合わない（[0050 設計書](../../tasks/0050_viewer_tab/02_architecture.md) 付録 B.3）。

### 生成を実行する場所

-   **ビューアのメインスレッドで WASM を動かし、完成の後に読み込み直す。** 読み込み直すときに画面が切り替わり、状態の知らせが途切れうる（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「設計の際に決めたこと（2026-11-12）」）。
-   **Offscreen Document で動かす。** 拡張に 1 つしか置けず、ビューアを閉じても止まらないので、生成の寿命をページの寿命とする決定（[ADR-0048](0048-extension-only-generation.md)）から外れる（0090 設計書「設計の際に決めたこと（2026-11-12）」）。

## 結果

-   ビューアは、生成の開始と同時に背面のタブとして開き、そのタブで記事を生成する。利用者は作業中のタブを切り替えずに、生成の状態をポップアップで見られる。
-   生成を実行しているビューアのタブを閉じるか読み込み直すと、生成は止まる。止まった実行は、止まった状態として示される（[ADR-0028](0028-no-automatic-resend.md)）。
-   ポップアップは自分では閉じない。利用者が閉じても、ビューアがジョブの記録を表示するので、表示は失われない。
-   同じジョブのビューアがすでにあるときは、新しいタブを閉じて既存のビューアに引き継ぐ。押し直すたびに同じ記事のタブが増えることはない。
-   利用者が主ボタンを押した直後に手でポップアップを閉じた場合は、止まっていた Service Worker にもメッセージが届いた。この観察に頼る。
-   破棄されたタブは、`tabs` の権限を加えずには見つけられない。「ビューアを開く」は破棄されたタブを見つからないものとして扱い、同じ記事のタブが重複して開くことを例外として受け入れる。
-   ビューアのタブが一度も前面にならなくても生成が完走することに、この決定は依る。完走しないと分かれば、ビューアを前面で開くように改める。
