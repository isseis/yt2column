# ADR-0045: 本番のバイナリに fake の LLM を入れず、fake の LLM はサーバに依存しない構成要素にして開発用のバイナリから使う

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

拡張とサーバの手での確認（レイアウト、状態の遷移、エラーの表示）は、LLM の出力の中身を必要としない。それでも、実際の LLM を呼ぶしかなく、料金と API キーが要り、記事・遅れ・失敗を再現できない。fake の `LLMClient` は単体テスト用のもの（ビルドタグ `test`）しかない。

fake を本番のバイナリに入れて設定で選べるようにすると、設定の誤りで、fake の記事が本番の利用者の前に出たり Webhook に投稿されたりしうる。

localhost サーバと Native Messaging のホストは、拡張だけの構成への移行で撤去される予定である（[#769](https://github.com/isseis/yt2column/issues/769)・[#773](https://github.com/isseis/yt2column/issues/773)）。サーバと一体の fake は、撤去とともに使えなくなる。

## 決定

-   **本番のバイナリ（`yt2column`・`yt2column-server`・`yt2column-nmhost`）は、fake の LLM にも開発用のバイナリのパッケージにも、直接にも間接にも依存しない。これを機械的に確かめる。** 設定の誤りで fake の記事が本番の利用者の前に出ることや Webhook に投稿されることを、設定の検査ではなく構成で防ぐためである。確かめるのは、`go list -deps` で間接の依存まで列挙する `make test` のテストである。直接の import だけでなく、間接の依存も検出するためである（[0086 設計書](../../tasks/0086_dev_fake_llm_server/02_architecture.md) の「設計の際に決めたこと（2026-11-11）」）。規則は [0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md) の「F-005: 本番のバイナリとの分離とビルド」と、[security.md](../security.md) の §8.2「localhost サーバ（#109）」にある。
-   **fake の LLM は、サーバだけが使うパッケージに依存しない構成要素にし、`GOOS=js GOARCH=wasm` でビルドできることを検査する。** サーバの撤去の後も、移行の後の開発用のビルドで使えるようにするためである。WASM の検査は、[ADR-0019](0019-pipeline-component-interfaces.md) が定める `make wasm-check` に fake の構成要素を加えて行う。検査を 1 つの `make` のターゲットにまとめ、#772 が見直す場所も 1 か所にするためである（0086 設計書の「設計の際に決めたこと（2026-11-11）」）。Go の WASM にするか TS に一本化するかは [#772](https://github.com/isseis/yt2column/issues/772) が決める。TS に一本化すると決めたときは、#772 がこの項を見直す。規則は 0086 要件定義書の「F-001: サーバに依存しない fake の LLM の構成要素」と「要件定義の際に決めたこと（2026-11-11）」にある。
-   **fake の振る舞いは、生成のジョブごとに、起動のときに選んだ列挙値のシナリオだけで決まる。プロンプトの中身からは決めない。** 同時に動くジョブや前のジョブに影響されず、選んだ記事と失敗を再現できるようにするためである。プロンプトの中身から決めないのは、CLAUDE.md の「Declare, don't infer」による。本番のサーバと `LLMClient` の契約（[ADR-0021](0021-llm-client-contract.md)）は変えない。規則は 0086 要件定義書の F-001 にある。
-   **開発用のサーバでは、シナリオと遅れをコマンドライン引数で渡す。開発用のサーバは設定ファイルを読まず、API キーも要らない。** 本番の設定の読み込み（`YT2COLUMN_LLM` の構文と設定ファイルのキー）に fake を持ち込まず、[ADR-0003](0003-llm-config-contract.md)・[ADR-0018](0018-server-config-file.md)・[ADR-0024](0024-env-access-in-config.md) に例外を作らないためである。規則は 0086 要件定義書の「F-002: 開発用のサーバの起動」にある。
-   **開発用のサーバは Webhook への投稿に対応しない。** 開発用のサーバは、投稿の API を消すタスク 0083（[#770](https://github.com/isseis/yt2column/issues/770)）の実装の後に着手するので、投稿の経路を持たない。fake の記事を実際の Webhook に投稿する経路は存在しない。規則は 0086 要件定義書の「要件定義の際に決めたこと（2026-11-11）」にある。
-   **料金の単価の表（`internal/pricing`）に fake のモデルを入れない。fake の記事の料金が不明と表示されるようにする。** 本番の単価の表に開発用の値を持ち込まないためである。規則は 0086 要件定義書の「F-003: fake の記事」にある。

この決定は、まだコードと security.md に反映していない。この差分は [#687](https://github.com/isseis/yt2column/issues/687) の実装で解消する。

## 採らなかった案

-   **issue の提案のとおり、fake をサーバと一体で作り、#773 で一緒に撤去する。** 移行の後に使える構成要素が残らない（[0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）。
-   **拡張だけの構成の設計（#772）が決まるまで保留する。** #773 までの間の手での確認に、料金と再現性の問題が残る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake の WASM でのビルドを検査しない。** 移行の後の開発用のビルドで使えることが、検査なしでは保たれない（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake の WASM のビルドを、`make wasm-check` とは別の検査で確かめる。** タスク 0084 と 0086 が、同じ役目の `make` のターゲットをそれぞれ作るおそれがある（0086 設計書「設計の際に決めたこと（2026-11-11）」）。
-   **`depguard` で、fake の import を開発用のサーバだけに許す。** `main` のパッケージは import できないので、本番のバイナリから fake を締め出すことは確かめられる。しかし、fake がサーバだけが使うパッケージに間接に依存しないことは確かめられない（0086 設計書「設計の際に決めたこと（2026-11-11）」）。
-   **開発用のサーバを同時に 1 ジョブだけで使う制限を受け入れ、呼び出しの順序で工程を区別する。** 2 つのジョブを始めると、選んだ工程で失敗させられない（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **シナリオを、設定ファイルのキーか環境変数で渡す。** ADR-0018 が受理する設定ファイルのキーが増えるか、ADR-0024 の入口の例外が要る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **0083 より先に実装し、投稿を Webhook が設定されていないときと同じく拒否する。** 0083 の実装で、投稿のリクエストへの応答の要件が食い違う（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake のモデルに単価 0 を与えて単価の表に入れる。** 本番の単価の表に fake が入る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。

## 結果

-   開発用のサーバは本番のサーバと同じソケットのパスで待ち受けるので、両方を同時には動かせない。本番のサーバの代わりに開発用のサーバを起動すると、拡張は fake の記事を表示する。記事のタイトルの印と起動の行で気づけるようにし、開発用のバイナリを常用の環境に置かないことを security.md で求める。
-   シナリオを変えるには、開発用のサーバを起動し直す。失敗の後に「やり直す」で成功する流れは、開発用のサーバでは確かめられない。
-   fake の記事では料金の表示が不明になる。料金が分かっているときの表示は、fake では確かめられない。
-   fake の構成要素が依存するパッケージ（`internal/llm` など）は、WASM でビルドできる状態を保たなければならない。
-   fake の構成要素は、単体テスト用の fake の置き場所の規則（`testutil/mocks.go` とビルドタグ `test`。[test_organization.md](../conventions/test_organization.md)「Pipeline fakes」）の例外になる。
-   サーバの撤去（#773）のときに、開発用のサーバは一緒に撤去する。fake の構成要素は残り、移行の後の開発用のビルドへの配線は #772・#773 で決める。

## 経緯
