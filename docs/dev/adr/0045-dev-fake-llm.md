# ADR-0045: 本番の成果物に fake の LLM を入れず、fake の LLM はサーバに依存しない構成要素にして開発用の拡張のビルドから使う

## 状態

| 項目 | 値 |
|---|---|
| 状態 | `有効` |

## 背景

拡張の手での確認（レイアウト、状態の遷移、エラーの表示）は、LLM の出力の中身を必要としない。それでも、実際の LLM を呼ぶしかなく、料金と API キーが要り、記事・遅れ・失敗を再現できない。本番の構成での記事の生成は、1 本あたり約 0.33〜0.46 USD かかる（[調査記録](../../research/wasm_pipeline_poc/README.md)「測定 6：本番の構成（Chrome、`83ef12bd`、背面のまま）」）。fake の `LLMClient` は単体テスト用のもの（ビルドタグ `test`）しかない。

fake を本番の成果物に入れて設定で選べるようにすると、設定の誤りで、fake の記事が本番の利用者の前に出うる。

記事は拡張だけで作り、localhost サーバと Native Messaging のホストは撤去する（[ADR-0048](0048-extension-only-generation.md)）。記事を作る処理は、Go のコアを WASM にした入口で拡張と共有する（[ADR-0049](0049-wasm-core-sharing.md)）。

## 決定

-   **本番の成果物（CLI の `yt2column` と、拡張の公開用の WASM の入口 `cmd/yt2column-wasm`）は、fake の LLM にも開発用の入口のパッケージにも、直接にも間接にも依存しない。これを機械的に確かめる。** 設定の誤りで fake の記事が本番の利用者の前に出ることを、設定の検査ではなく構成で防ぐためである。確かめるのは、`go list -deps` で間接の依存まで列挙する `make test` のテストである。直接の import だけでなく、間接の依存も検出するためである（[0086 設計書](../../tasks/0086_dev_fake_llm_server/02_architecture.md) の「設計の際に決めたこと（2026-11-11）」）。規則は [0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md) の「料金をかけずに拡張を動かす方法」と「セキュリティのテスト」にある。
-   **fake の LLM は、サーバだけが使うパッケージに依存しない構成要素にし、`GOOS=js GOARCH=wasm` でビルドできることを検査する。** 開発用の拡張のビルドで WASM の入口から使うためである。WASM の検査は、[ADR-0019](0019-pipeline-component-interfaces.md) が定める `make wasm-check` に、開発用の WASM の入口とその fake の構成要素を加えて行う。検査を 1 つの `make` のターゲットにまとめるためである（0086 設計書の「設計の際に決めたこと（2026-11-11）」）。規則は [0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md) の「F-001: サーバに依存しない fake の LLM の構成要素」と、0090 設計書の「ビルドと成果物」にある。
-   **fake の振る舞いは、生成のジョブごとに、起動のときに選んだ列挙値のシナリオだけで決まる。プロンプトの中身からは決めない。** 選んだ記事と失敗を再現できるようにするためである。プロンプトの中身から決めないのは、CLAUDE.md の「Declare, don't infer」による。`LLMClient` の契約（[ADR-0021](0021-llm-client-contract.md)）は変えない。規則は 0086 要件定義書の F-001 にある。
-   **fake は、開発用の拡張のビルドだけが使う。`make ext-build-dev` は、fake を使う開発用の WASM の入口（`cmd/yt2column-wasm-dev`。公開用とは別の `main` のパッケージ）をビルドし、`extension/dist-dev/` に置く。公開する成果物（`extension/dist/`）は fake を含まない。** 公開する成果物に開発用の分岐を入れないためである。規則は 0090 設計書の「料金をかけずに拡張を動かす方法」にある。
-   **fake のシナリオは、`make ext-build-dev` の引数で選ぶ。設定の画面と保存した値では選ばない。開発用のビルドは Anthropic の API を呼ばない。** 設定の画面や保存した値でシナリオを選べるようにすると、公開する成果物にも開発用の分岐が入るためである。シナリオを変えるには、ビルドし直して拡張を読み込み直す。本番の設定の読み込み（[ADR-0003](0003-llm-config-contract.md)・[ADR-0024](0024-env-access-in-config.md)）に fake を持ち込まない。規則は 0090 設計書の「料金をかけずに拡張を動かす方法」にある。
-   **料金の単価の表（`internal/pricing`）に fake のモデルを入れない。fake の記事の料金が不明と表示されるようにする。** 本番の単価の表に開発用の値を持ち込まないためである。規則は 0086 要件定義書の「F-003: fake の記事」にある。
-   **タスク 0086 は、PR-1（fake の構成要素と依存の検査）だけを実装し、開発用のサーバ（PR-2）と、その文書と手動の確認（PR-3）は行わない。** 開発用のサーバは、撤去するサーバの上に作る計画で、撤去までの短い間しか使わないためである。fake の構成要素を開発用の拡張のビルドにつなぐのは、[#773](https://github.com/isseis/yt2column/issues/773) が行う。規則は 0090 設計書の「設計の際に決めたこと（2026-11-12）」にある。

この決定は、まだコードと仕様の文書（[development.md](../guides/development.md)・[security.md](../security.md)）に反映していない。fake の構成要素はまだなく（[#687](https://github.com/isseis/yt2column/issues/687) のタスク 0086 の PR-1 が作る）、開発用の拡張のビルドもない（[#773](https://github.com/isseis/yt2column/issues/773) が作る）。

## 採らなかった案

-   **issue の提案のとおり、fake をサーバと一体で作り、#773 で一緒に撤去する。** 移行の後に使える構成要素が残らない（[0086 要件定義書](../../tasks/0086_dev_fake_llm_server/01_requirements.md)「要件定義の際に決めたこと（2026-11-11）」）。
-   **拡張だけの構成の設計（#772）が決まるまで保留する。** #773 までの間の手での確認に、料金と再現性の問題が残る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake の WASM でのビルドを検査しない。** 移行の後の開発用のビルドで使えることが、検査なしでは保たれない（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake の WASM のビルドを、`make wasm-check` とは別の検査で確かめる。** タスク 0084 と 0086 が、同じ役目の `make` のターゲットをそれぞれ作るおそれがある（0086 設計書「設計の際に決めたこと（2026-11-11）」）。
-   **`depguard` で、fake の import を開発用のサーバだけに許す。** `main` のパッケージは import できないので、本番のバイナリから fake を締め出すことは確かめられる。しかし、fake がサーバだけが使うパッケージに間接に依存しないことは確かめられない（0086 設計書「設計の際に決めたこと（2026-11-11）」）。
-   **開発用のサーバを同時に 1 ジョブだけで使う制限を受け入れ、呼び出しの順序で工程を区別する。** 2 つのジョブを始めると、選んだ工程で失敗させられない（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **シナリオを、設定ファイルのキーか環境変数で渡す。** ADR-0018 が受理する設定ファイルのキーが増えるか、ADR-0024 の入口の例外が要る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **0083 より先に実装し、投稿を Webhook が設定されていないときと同じく拒否する。** 0083 の実装で、投稿のリクエストへの応答の要件が食い違う（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **fake のモデルに単価 0 を与えて単価の表に入れる。** 本番の単価の表に fake が入る（0086 要件定義書「要件定義の際に決めたこと（2026-11-11）」）。
-   **開発用のサーバをタスク 0086 の計画どおりに作り、#773 でサーバと一緒に撤去する。** 撤去するサーバの上に作り、#773 までの短い間しか使わない（[0090 設計書](../../tasks/0090_extension_only_architecture/02_architecture.md)「設計の際に決めたこと（2026-11-12）」）。
-   **fake のシナリオを、オプションページの設定や保存した値で選ぶ。** 公開する成果物にも開発用の分岐が入る（0090 設計書「料金をかけずに拡張を動かす方法」）。

## 結果

-   開発用のビルドは、公開する成果物と別のディレクトリ（`extension/dist-dev/`）にできる。開発用のビルドを読み込んだ拡張は fake の記事を表示する。記事のタイトルの印で気づけるようにする。
-   シナリオを変えるには、ビルドし直して拡張を読み込み直す。拡張の読み込み直しで、`chrome.storage.session` の記事は失われる。
-   fake の記事では料金の表示が不明になる。料金が分かっているときの表示は、fake では確かめられない。
-   fake の構成要素が依存するパッケージ（`internal/llm` など）は、WASM でビルドできる状態を保たなければならない。
-   fake の構成要素は、単体テスト用の fake の置き場所の規則（`testutil/mocks.go` とビルドタグ `test`。[test_organization.md](../conventions/test_organization.md)「Pipeline fakes」）の例外になる。
-   タスク 0086 の計画の書き換え（PR-2・PR-3 を行わないこと）は、0086 の側の PR で行う。

## 経緯

- 2026-11-11 本番のバイナリとの分離を `go list -deps` のテストで確かめ、fake の WASM のビルドを ADR-0019 の `make wasm-check` で検査することにした。WASM の検査を 0084 の決定の例外とする記述は、0084 が検査を置くと決め直したため取り下げた（[0086 設計書](../../tasks/0086_dev_fake_llm_server/02_architecture.md)「設計の際に決めたこと（2026-11-11）」）
