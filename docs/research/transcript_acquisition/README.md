# 他ツールの文字起こしの取得方法の調査

YouTube の文字起こしを LLM で処理するツールのうち、利用者の多いものについて、文字起こしの取得方法を調べた記録である。調査の進み具合は [#679](https://github.com/isseis/yt2column/issues/679) で追う。

## 目的

主経路の文字起こしの取得を見直すときの判断の材料にする。現在の主経路では、利用者が文字起こしパネルで選択した文字列を拡張が読む（[ADR-0007](../../dev/adr/0007-manual-transcript-copy.md)）。この決定の理由は 3 つある。YouTube の壊れやすい非公式な仕様を自分で抱えたくないこと、ページを操作したくないこと、そして、パネルの中身と動画を結びつける信号がないことである。他のツールがこれらの問題をどう扱っているかを記録する。

## 記録の決まり

-   **ツールごとに 1 ファイル。** 下の「ツールごとの文書の見出し」に従って書く。
-   **時点の記録として扱う。** 冒頭に調査日と対象の版を書く。ツールは頻繁に変わるので、書いた内容が今も成り立つとは限らない。再調査では既存の記述を書き換えず、再調査の日付の節を加える。
-   **他者のコードを置かない。** CRX（Chrome 拡張のパッケージ）や、それを展開したファイルはコミットしない。引用は、根拠に必要な短い断片（関数名・URL・セレクタ・リクエストの形）に限る。
-   **根拠を示す。** 記述ごとに、根拠にしたファイル名と関数名（ミニファイされた名前を含む）を書く。推測は推測と明記する。

## 調査の観点

| 観点 | 確かめること |
|---|---|
| 取得経路 | どの API・データから文字起こしを得るか。複数あれば、試す順序と切り替えの条件 |
| PO トークン | `/api/timedtext`（字幕を配信する YouTube の API。以下 timedtext）が求める PO トークン（YouTube のボット対策の仕組みが出力する値）をどう扱うか |
| 動画との結びつき | 取得した文字起こしが、対象の動画のものであることをどう確かめるか。特に、YouTube の中で別の動画へ移った後に、前の動画のものと取り違えないか |
| ページの操作 | クリックなどで YouTube のページを操作するか |
| 権限 | 拡張の manifest が求める権限と、コンテンツスクリプトの注入の範囲 |
| 外部への送信 | 文字起こしや動画の情報を、ツールの提供者のサーバへ送るか |
| 利用規約との関係 | クライアントのなりすましやボット対策の迂回など、[YouTube 利用規約](https://www.youtube.com/static?template=terms)の「許可と制限事項」に抵触しうる方法を使うか |
| 壊れやすさ | YouTube のどの非公式な仕様（内部 API・HTML の構造・CSS セレクタ）に依存するか |

## 横断的な所見

-   調査したツールは、YouTube の内部 API（Innertube）か timedtext を使う。どちらも、YouTube が明示的に許可した方法ではない。他人の動画の字幕を、規約がはっきり許す方法で取る手段はない（YouTube Data API の `captions.download` は、その動画を編集する権限を要する）。
-   timedtext は PO トークンを求めることがあり、調査したツールは、ボット対策を避ける何らかの方法でトークンを得ている。
