## 1. 概要 (Overview)

**目的:** 本書は、`/chief` の定義（`.claude/commands/chief.md`）で、人に問いを出す方法が step 3 と step 4 で違うことを、読み違えない形で書き直す要件を定める。

**背景:**

-   `chief.md` の step 3「The choices」は、待ち受けの間は質問でセッションを止めないと定める。ラウンドの最後に、番号つきの一覧（`[<number>] <description>`）をテキストで書いて、ターンを終える（`.claude/commands/chief.md:259-274`）。`once` のときは `AskUserQuestion` で聞く（`chief.md:275-278`）。
-   step 4「Acting on the answer」は、人が選んだ直後の問いを、待ち受けの間も `once` でも `AskUserQuestion` で聞くと冒頭の 1 文で定める（`chief.md:296-297`）。step 4 で人に聞くのは次の 4 つである。
    -   中継する選択肢の選択（`chief.md:312-320`）
    -   PR の詳細を示した後の問い。選択肢は `/runpr` を送る・送らない・ほかの PR を見る（`chief.md:321-325`）
    -   `停止を解く` の確認（`chief.md:347-350`）
    -   `/mkreq` の提案での issue 番号（`chief.md:341-343`）。今の文は「ask the human for the issue number first」で、聞き方を定めていない

    リセットの項目は、選んだらそれ以上は聞かずに送る（`chief.md:332-337`）。`/mkreq` 以外の提案も聞かずに送る（`chief.md:344-346`）。中継の問いの前には pane の選択肢を、PR の詳細の後の問いの前には PR の詳細を、テキストで示す（`chief.md:300-309`・`359-388`）。これらは示すもので、聞く問いではない。
-   step 4 の「ほかの PR を見る」は、残りの項目を step 3 のとおり示し直す（`chief.md:331`）。step 3 の「Reading the answer」は、同じラベルの項目が複数あるとき、それらだけを挙げて聞き直す（`chief.md:289-291`）。どちらも step 3 の選択肢（6 章で定義）を示し直すもので、待ち受けの間は番号つきの一覧、`once` では `AskUserQuestion` で示す。
-   step 4 の冒頭の 1 文は、step 3 の「待ち受けの間は質問で止めない」という原則と読み違えやすい。2026-11-18 に、chief セッションが PR #979 の詳細を示した後、step 4 の問いを `AskUserQuestion` で聞かず、選択肢をテキストで書いた。人は自由記述で答えることになり、続けて `/runpr 979` を chief セッションに直接打ち込んだ。本来は `chief send` で OpenCode の pane へ送る経路だった（issue #983「起きたこと」）。テキストで聞くと、人の答えが step 3 の項目の番号として読まれうるほか、人がコマンドを chief セッションに直接打ち込み、chief の道具を通らずに実行させうる。
-   モデルの切り替えの後に送り直すかどうかの問いは、未回答の問いとして表の下に残し（`chief.md:352-357`）、step 3 の一覧に `送り直す: <label>`・`送り直さない: <label>` として番号なしで示す（`chief.md:252-255`）。この問いはラウンドをまたいで待つ。`once` は 1 回聞いて止まるので（`chief.md:92-93`）、次のラウンドの一覧がない。

対応 issue: [#983](https://github.com/isseis/yt2column/issues/983)

issue が挙げる問いとの対応：「PR の詳細のあとの質問」は PR の詳細の後の問い、「`停止を解く`」は `停止を解く` の確認、「中継の確認」は中継する選択肢の選択、「提案の確認」は `/mkreq` の issue 番号の問いに当たる。`/mkreq` 以外の提案は今も何も聞かずに送るので、聞く問いがない。「続けて聞く質問」は、これら 4 つの問いをまとめて指すものとして扱う。

**本書の記述範囲:** 本書は、`chief.md` の step 3 と step 4 で問いの出し方を述べる文の要件を定める。どの文をどう書き換えるかは `02_architecture.md` で、確かめ方は `03_implementation_plan.md` で定める。

-   **step 4 の冒頭に、step 3 の番号つきの一覧はラウンドの最後に出す `pending` の一覧にだけ使い、step 4 の問いには使わないことを明示する。** 同じ理由である。
    -   ADR：なし。同上。
-   **step 3 の「待ち受けの間」の説明に、step 4 の問いはこの例外であることを 1 行足す。** step 3 だけを読んでも、step 4 の問いを取り違えないためである。
    -   ADR：なし。同上。
-   **`chief` の手順（呼び出すサブコマンドと引数）は変えない。** issue の補足のとおり、変更は文だけである。

**要件定義の際に決めたこと（2026-11-18）:**

-   **進め方は簡易な進め方（`simple`）とする。この変更は、除外される変更に当たらない。** 変わるのは 1 つのコマンドの定義の文だけである。新しい仕組みは作らず、どの ADR の決定も変えない。未決の判断も少ない。除外の判断：変更は問いの出し方の文を明確にするだけで、次のどれも変えない（`docs/dev/conventions/requirements_process.md`「Simple Process」の「Excluded changes」）。
    -   `docs/dev/security.md` の規則と前提
    -   開発の道具（`fixprguard`・`codexreview`・`mergepr`）とその信頼境界。chief が送る入力と、人が選ぶまで送らない規則（`chief.md:34-37`、Rule 3）も変わらない
    -   外部依存
    -   ADR：なし。本タスクの中で閉じる、進め方の選択である。
-   **`/mkreq` の提案で issue 番号を聞く問いも、`AskUserQuestion` で聞く。人は issue 番号を自由記述の答えに書く（F-001）。** テキストで聞くと、待ち受けの間は、人が打った数字が step 3 の一覧の項目の番号として読まれうるためである（`chief.md:285-288`）。
    -   答えが数字だけでなければ、選択として扱わず、そう言って何も送らない。`#983` や URL から番号を取り出すこともしない。道具に渡す issue 番号は人が答えたままにし、作り直さない規則（`chief.md:38-42`、Rule 4）に合わせるためである。
    -   選択肢は「送らない」と「ほかの項目を見る」とする（2026-11-18 に人が選んだ）。`AskUserQuestion` の選択肢は 2〜4 個なので（ツールの定義）、番号を書く自由記述の答えのほかに、選ぶ形の選択肢が 2 つ要る。PR の詳細の後の問いの「送らない」「ほかの PR を見る」（`chief.md:321-331`）と同じ形にした。「送らない」は何もしないのと同じで、待ち受けを続けるか、`once` では止まる。「ほかの項目を見る」は、残りの項目を step 3 のとおり示し直す。`once` で示し直す項目が 1 つもないときは、何もしないのと同じに扱い、そう伝えて止まる。`AskUserQuestion` に「何もしない」だけの問いを出すと、選択肢の数の下限に届かないためである。
    -   採らなかった案：選択肢を「送らない」だけにする案。選択肢の数の下限に届かない。
    -   採らなかった案：自由記述の答えなので、この問いだけはテキストで聞く例外として残す案。上の取り違えが残る。
    -   ADR：なし。本タスクの中で閉じる。
-   **モデルの切り替えの後に送り直すかどうかの問いは、今のまま step 3 の一覧に示し、step 4 の問いの規則の対象にしない。対象にしないことを step 4 に書く（F-001）。** この問いはラウンドをまたいで待つ問いで、人が選んだ直後の確認ではないためである。`AskUserQuestion` で聞くと、答えるまでラウンドと自動送信が止まる。
    -   採らなかった案：`model_mismatch` が返った直後に `AskUserQuestion` で聞く案。人が pane のモデルを切り替えるまで待ち受けが止まる。
    -   ただし `once` では、止まる前に `AskUserQuestion` で聞く。`once` には次のラウンドの一覧がなく、一覧に示すだけでは問いが聞かれないまま終わるためである。`once` はもともと選択肢を `AskUserQuestion` で聞くので、待ち受けは止まらない。上の人の選択（step 3 の一覧に残す）を、一覧のない `once` に当てはめた結果である。
    -   ADR：なし。本タスクの中で閉じる。
-   **step 3 の選択肢の示し直し（「ほかの PR を見る」「ほかの項目を見る」と、同じラベルの項目の聞き直し）は、step 4 の問いではなく step 3 の選択肢とし、モードごとの step 3 の形で示す（F-001）。** 示し直す項目は道具の番号を持つ step 3 の項目で、待ち受けの間に番号つきの一覧で示しても、答えの読み方が変わらないためである。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   chief セッションが、step 4 の問いをテキストの一覧で書かず、`AskUserQuestion` で聞くようにする。
-   step 3 と step 4 の、問いの出し方の境目を、どちらの節から読んでも分かるようにする。

### 2.2. スコープ (In Scope)

-   `chief.md` の step 4 の冒頭の文の書き換え（F-001）。
-   `chief.md` の step 4 の提案の項目で、issue 番号の聞き方を定める文の書き換え（F-001）。
-   `chief.md` の step 3 の「待ち受けの間」の項目への 1 行の追加（F-001）。

### 2.3. スコープ外 (Out of Scope)

-   `chief` の道具（`cmd/chief`・`internal/chief`）の変更。呼び出すサブコマンドと引数も変えない（issue の補足）。
-   `docs/dev/guides/chief_guide.md` の変更。理由は 1 章の「要件定義の際に決めたこと」にある。
-   モデルの切り替えの後に送り直すかどうかの問いの出し方の変更。理由は 1 章の「要件定義の際に決めたこと」にある。
-   step 4 の問いが開いている間にラウンドが止まることへの対処。今の定義（`chief.md:296-297`）のままである。`/mkreq` の issue 番号の問いでは、人が issue を探すか作る間、ラウンドと自動送信が止まりうる。人が自分で選んだ直後の問いであり、答えないまま待ち受けを続けたいときは「送らない」を選べる。そのため、残る危険として受け入れる。
-   ADR-0046 の変更。問いの出し方は ADR の決定に含まれない。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: step 4 の問いを AskUserQuestion で聞くことを明示する

**Acceptance Criteria**:
- **AC-01**: `chief.md` の step 4 の冒頭は、この節で人に聞く問いを、待ち受けの間も `once` でも `AskUserQuestion` で聞くと述べる。対象の問いとして、中継する選択肢の選択、PR の詳細を示した後の問い、`停止を解く` の確認、`/mkreq` の提案での issue 番号の 4 つを挙げる。
- **AC-02**: `chief.md` の step 4 の冒頭は、次の 3 つを述べる。
    -   step 4 の問いをテキストで聞かない。つまり、問いをテキストで書いて、人が打ち込む答えを待ってターンを終えることをしない。
    -   中継の問いの前の pane の選択肢と、PR の詳細は、今のとおりテキストで示す。これらは示すもので、聞く問いではない。
    -   step 3 の番号つきの一覧（`[<number>] <description>` の行）は、step 3 の選択肢にだけ使う。「ほかの PR を見る」「ほかの項目を見る」で残りの項目を示し直すのは step 3 の選択肢で、モードごとの step 3 の形で示す。
- **AC-03**: `chief.md` の step 4 の冒頭は、モデルの切り替えの後に送り直すかどうかの問いが AC-01 の対象でないと述べる。待ち受けの間は step 3 の一覧に示し、`once` では止まる前に `AskUserQuestion` で聞き、その答えは今の「Sending again after a model switch」（`chief.md:352-357`）のとおりに扱う（送り直すなら同じ送信をもう一度呼び、送り直さないなら何もしない）。
- **AC-04**: `chief.md` の step 4 の提案の項目は、次のことを述べる。
    -   `/mkreq` の issue 番号を `AskUserQuestion` で聞き、人は番号を自由記述の答えに書く。選択肢は「送らない」と「ほかの項目を見る」である。
    -   自由記述の答えが数字だけでなければ、選択として扱わない。そう言って、何も送らない。
    -   「送らない」では何も送らず、待ち受けを続けるか、`once` では止まる。「ほかの項目を見る」では、残りの項目を step 3 のとおり示し直す。`once` で示し直す項目が 1 つもないときは、何もしないのと同じに扱い、そう伝えて止まる。
- **AC-05**: `chief.md` の step 3 の「待ち受けの間」の項目は、step 4 の問いはこの項目の例外で、待ち受けの間も `AskUserQuestion` で聞くと述べ、step 4 を参照する。

#### F-002: 変更の範囲を文に限る

**Acceptance Criteria**:
- **AC-06**: 実装の PR の差分のうち、`.claude/commands/chief.md` 以外のファイルの変更は、本タスクのディレクトリ（`docs/tasks/0103_chief_step4_askuserquestion/`）の中に限る。
- **AC-07**: `chief.md` の差分は、step 3 の「待ち受けの間」の項目（`chief.md:259-274`）、step 4 の冒頭の段落（`chief.md:296-297`。段落を置き換えて長くなってよい）、step 4 の提案の項目のうち `/mkreq` の issue 番号を聞く文（`chief.md:341-343`）の追加・書き換えに限る。`chief` を呼び出す行（`chief <subcommand> ...` のコードスパン）は変わらない。
- **AC-08**: `go test -tags test ./cmd/chief` が通る。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。
-   **ラウンド:** `/chief` が状況を読み取って示す 1 回分（用語集の「ラウンド」）。
-   **待ち受け:** 引数なしの `/chief` が、ラウンドを繰り返しながら人の答えを待つこと（`chief.md` の「watching」。`chief_guide.md:50`）。
-   **step 4 の問い:** `chief.md` の step 4 で、人が項目を選んだ直後に聞く問い（AC-01 の 4 つ）。
-   **step 3 の選択肢:** `chief.md` の step 3 が示す、人が選ぶ項目（道具の `pending` の項目と、`停止を解く`・`送り直す`・`送り直さない`・`何もしない`）。待ち受けの間はラウンドの最後に番号つきの一覧で、`once` では `AskUserQuestion` で示す。「ほかの PR を見る」などで示し直すときも同じ形で示す。
