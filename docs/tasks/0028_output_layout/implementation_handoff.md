# 実装への申し送り：出力の構成の見直し

本書は、[02_architecture.md](02_architecture.md) のレビューで挙がった事項のうち、手順の詳細にあたるものを集める（設計書には外部から確かめられる動作と不変条件だけを残す）。`03_implementation_plan.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## I-01: `ProseRanges` の実装

-   **事項:** `writer.ProseRanges`（設計書 3.7）が、本文のコードスパンとコードブロックの外のバイトの範囲を返す手順を決める。
-   **内容:** `markdown.go` の `proseLines` は行の文字列と行番号を返し、`codeSpans` は行の中の範囲を返す。行の先頭の位置を累積して、本文の中の範囲に直す。判定できない本文には false を返す。判定できないのは、閉じていないコードフェンス（`errUnclosedFence`）、インデントされた、または引用・リストの中のフェンスらしい行（`errFenceLikeLine`）、対にならないバッククォートの並びのある行（`codeSpans` が `ok=false`）、`codeSpansExempt` が偽になる本文（バックスラッシュや `[`・`]` などを含み、コードスパンの対応を信頼できない）である。false のときは本文に何も無効化せず、対象の `@` は拒否される。コードスパンが複数の行にまたがる場合は、行ごとの対応では表せないので、同じく判定できないものとして扱う。インデントのコードブロックは `writer` の検査が区別しないので、散文として扱う（その中の対象の `@` に U+200B が入りうることは、受け入れる限界である）。
-   **関連:** AC-14、AC-14b

## I-02: rune の添字とバイトの位置の変換

-   **事項:** `neutralizeProse` が、`mentionAts` の rune の添字を、元の本文のバイトの位置に直して `ProseRanges` の範囲と比べる手順を決める。
-   **内容:** `mentionAts` は V3 で置き換えた文字列の rune の添字を返す。V3 は 1 文字を 1 文字に置き換えるが、バイト数は変わる（`＠` は 3 バイト、`@` は 1 バイト）。元の本文を先頭から数えて、添字をバイトの位置に直す。テストには、`＠` がコードスパンの中にある本文と外にある本文を入れる。
-   **関連:** AC-14

## I-03: 分割の切る位置の移動と確認の層

-   **事項:** 分割が、語の途中の `@` を断片の先頭にしないようにする手順（設計書 3.7(3)）を決める。
-   **内容:** 改行の後以外の位置で切るとき、切る位置の直後の文字が、名前の文字が続く `@` で、切る位置の直前の文字（前の断片の最後の文字）が文字または数字なら、切る位置を 1 文字前に動かす。1 回の移動で足りる（動かした位置の直後は、文字または数字であり、`@` ではない）。動かすと断片が空になる場合は `ErrSlackUnsplittable` で拒否する。確認の層は、分割した後、位置の記号を含む各メッセージの先頭にある `@` について、投稿の全体では語の途中だった（直前が文字または数字）のに、メッセージの中で対象になったものがないかを確かめ、見つかれば `ErrSlackUnsplittable` で拒否する。
-   **関連:** AC-14d

## I-04: 切る位置の探索の範囲

-   **事項:** `splitSlackText`（設計書 3.5）が、`keepTogetherFrom` を考えて切る位置を探す手順を決める。
-   **内容:** 残りが 1 通の容量（`slackMaxMessageRunes` から位置の記号の長さ `slackDisplayMaxRunes` を引いた値）を超えるとき、切る位置の探索の範囲の上限を、容量の位置と `keepTogetherFrom` の小さいほうにする。その範囲で最も後ろの改行の後で切り、改行が見つからなければ、その上限で切る。開始位置が `keepTogetherFrom` 以降（最後の領域）で、残りが容量を超えれば `ErrSlackUnsplittable` で拒否する。空白だけの断片を拒否する既存の検査（`isWhitespaceOnly`）は、`keepTogetherFrom` で切った断片にも適用する。位置は rune の添字である。テストには、切る位置が `keepTogetherFrom` の手前で容量にちょうど収まる入力と、10 通に脚注が加わる入力を入れる。
-   **関連:** AC-12、AC-13

## I-05: M2 の検査用の文字列

-   **事項:** `mentionAts`（設計書 3.7）が判定する文字列の作り方を決める。
-   **内容:** M2 の検査用の文字列は、V3（見た目の似た文字を置き換える。`＠`（U+FF20）・`﹫`（U+FE6B） → `@` など）だけを行う。V3 は 1 文字を 1 文字に置き換えるので、添字は元の文字列と一致する。V2（Unicode の Cf を除く）と V1（バックスラッシュのエスケープを戻す）は、M2 では行わない。書式文字は語の区切りとして扱うので、`a`・U+200B・`@here` は対象になり、`@`・U+200B・`name` は対象にならない。バックスラッシュも区切りとして扱うので、`a\@here` は対象になる。M1 の検査用の文字列（V2 → V3 → V1）は変えない。M1・M3・M4 の判定は変えない。
-   **関連:** AC-14、AC-14a
