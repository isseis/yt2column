# 設計への申し送り：PR のタイトルを日本語にし、squash のコミットは英語のままにする

本書は、[01_requirements.md](01_requirements.md) の起草（とレビュー）で挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: タイトルの形を定める場所

-   **事項:** PR のタイトルの形（`<type>(<scope>): <日本語の要約>`）と、squash のコミットの件名との関係を、どの文書に 1 か所で定め、各コマンドからどう参照するかを決める。
-   **理由:** 今は、英語のタイトルの規則が `CLAUDE.md:49-52`、`_lib/task-pr-handoff.md:100-101`、`runpr.md:85-87`、`fixpr.md:466`、`mergepr.md:49-52`、`_context.md:62`、`mkplan2.md:62`・`mkplan2.md:80`・`mkplan2.md:129`、`runplan.md:198` に、それぞれの言葉で書かれている。同じ規則を各ファイルに書き直すと、次に規則を変えるときに書き漏らしが起きる（要件書 AC-17）。
-   **候補の方針:** 規則は `CLAUDE.md` の「Language」に置き、形は `_context.md` に置く。各コマンドは、そこを参照する。
-   **関連:** F-001、F-002、F-004、AC-02、AC-16、AC-17

## H-02: タスクの文書の PR の PR_TEXT

-   **事項:** `_lib/task-pr-handoff.md` の PR_TEXT の定義（`_lib/task-pr-handoff.md:35-37`）を、どう書き換えるかを決める。今は「文書を追加したコミットのタイトル」をそのまま PR のタイトルにする。
-   **理由:** コミットの件名は英語のままなので、そのままでは日本語のタイトルにならない。要件書は、タスクの文書の PR のタイトルを `docs(<task-id>): <日本語の要約>` と決めた（AC-04）。
-   **候補の方針:** PR_TEXT を「`docs(<task-id>): ` と、その PR で追加または変更した文書の内容の日本語の要約」と定める。または、呼び出す各コマンドが、日本語のタイトルを PR_TEXT として明示する。
-   **関連:** F-002、AC-04

## H-03: 英語の `推奨タイトル` の扱い

-   **事項:** `/runplan` が `推奨タイトル` から日本語の PR のタイトルを書く手順を決める（要件書 AC-05・AC-06）。
-   **理由:** 承認済みのプランに英語の値が残る（2026-10-21 の時点で、`docs/tasks/*/03_implementation_plan.md` に 168 個）。要件書は、値が日本語か英語かで振る舞いを分けていない。値の言語を見て分岐させる手順にすると、判定の誤りが起きうる。
-   **候補の方針:** 値の言語を判定せず、`/runplan` は常に `推奨タイトル` を下書きとして扱う。AC-13 の形の接頭辞はそのまま使い、そうでなければ AC-06 のとおりに補う。要約は日本語で書く。
-   **関連:** F-002、F-004、AC-05、AC-06

## H-04: `/mergepr` が件名の接頭辞を PR のタイトルから取る規則の書き方

-   **事項:** `mergepr.md` の step 2 で、接頭辞を決める順序（要件書 AC-12）、受け付ける形（AC-13）、PR のタイトルをデータとして扱う規則（`mergepr.md:46-48`）を、どう書くかを決める。受け付ける `<type>` の一覧を、どこに 1 か所で定めるかも決める（AC-13 と AC-16 が同じ一覧を使う）。
-   **理由:** PR のタイトルはレビュアーが GitHub で書き換えられる。形の判定をエージェントの読み取りに任せるので、判定の基準を定義の中で一意に書く必要がある。
-   **候補の方針:** 型の一覧と `<scope>` の文字の範囲を `_context.md` に置き、`mergepr.md` と PR マーカーの規約から参照する。
-   **関連:** F-003、F-004、AC-12、AC-13、AC-14、AC-16

## H-05: タスク 0031 との重なり

-   **事項:** タスク 0031（PR #407）とタスク 0032 が、同じファイル（`_lib/task-pr-handoff.md`、`runpr.md`）を変える場合の進め方を決める。
-   **理由:** 両タスクは独立しているが、`_lib/task-pr-handoff.md` の Part B（タスク 0031 は step 5、本タスクは step 3）と `runpr.md` を変える見込みである（要件書 5 節）。
-   **候補の方針:** 先にマージされた側の変更の上に重ねる。互いの記述を書き換えない。
-   **関連:** 要件書 5 節
