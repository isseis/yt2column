# 設計への申し送り：PR のタイトルを日本語にし、squash のコミットは英語のままにする

本書は、[01_requirements.md](01_requirements.md) の起草（とレビュー）で挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: タイトルの形を定める場所

-   **事項:** PR のタイトルの形（`<type>(<scope>): <日本語の要約>`）と、squash のコミットの件名との関係を、どの文書に 1 か所で定め、各コマンドからどう参照するかを決める。
-   **理由:** 今は、英語のタイトルの規則が `CLAUDE.md:49-52`、`_lib/task-pr-handoff.md:100-101`、`runpr.md:85-87`、`fixpr.md:466`、`mergepr.md:49-52`、`_context.md:62`、`mkplan2.md:62`・`mkplan2.md:80`・`mkplan2.md:129` に、それぞれの言葉で書かれている。同じ規則を各ファイルに書き直すと、次に規則を変えるときに書き漏らしが起きる（要件書 AC-16）。
-   **候補の方針:** 規則は `CLAUDE.md` の「Language」に置き、形は `_context.md` に置く。各コマンドは、そこを参照する。
-   **関連:** F-001、F-002、F-004、AC-16

## H-02: タスクの文書の PR の PR_TEXT

-   **事項:** `_lib/task-pr-handoff.md` の PR_TEXT の定義（`_lib/task-pr-handoff.md:35-37`）を、どう書き換えるかを決める。今は「文書を追加したコミットのタイトル」をそのまま PR のタイトルにする。
-   **理由:** コミットの件名は英語のままなので、そのままでは日本語のタイトルにならない（要件書 AC-04）。`/mkplan2` のコミットの件名は、ほかのコマンドと違い、形が決まっていない（`mkplan2.md:105`）。
-   **候補の方針:** PR_TEXT を「コミットの件名の接頭辞と、その件名と同じ内容の日本語の要約」と定める。または、呼び出す各コマンドが、日本語のタイトルを PR_TEXT として明示する。
-   **関連:** F-002、AC-04

## H-03: 英語の `推奨タイトル` の扱い

-   **事項:** `/runplan` が、英語の `推奨タイトル`（本タスクの前のプランの値）から日本語の PR のタイトルを書く手順を決める（要件書 AC-05・AC-06）。
-   **理由:** 承認済みのプランに英語の値が残る（2026-10-21 の時点で、`docs/tasks/*/03_implementation_plan.md` に 168 個）。値が日本語か英語かを見て分岐させると、判定の誤りが起きうる。
-   **候補の方針:** 値が日本語か英語かを判定せず、`/runplan` は常に `推奨タイトル` を下書きとして扱う。接頭辞はそのまま使い、要約を日本語で書く。日本語の値なら、結果はその値と同じになる。
-   **関連:** F-002、F-004、AC-05、AC-06

## H-04: `/mergepr` が件名の接頭辞を PR のタイトルから取る規則

-   **事項:** `mergepr.md` の step 2 で、PR のタイトルの接頭辞を件名に使う規則（要件書 AC-11）と、PR のタイトルをデータとして扱う規則（`mergepr.md:46-48`）を、どう両立させて書くかを決める。
-   **理由:** PR のタイトルはレビュアーが GitHub で書き換えられる。接頭辞の形が崩れている場合（`<type>` が conventional-commit の型でない、`:` の後に空白がない、など）の扱いを決める必要がある。
-   **候補の方針:** 接頭辞が conventional-commit の形に合わなければ、接頭辞がないものとして扱う（要件書 AC-11 の後半）。件名は step 3 で利用者の承認を受けるので、誤りはそこで直せる。
-   **関連:** F-003、AC-11、AC-12

## H-05: タスク 0031 との重なり

-   **事項:** タスク 0031（PR #407）とタスク 0032 が、同じファイル（`_lib/task-pr-handoff.md`、`runpr.md`）を変える場合の進め方を決める。
-   **理由:** 両タスクは独立しているが、`_lib/task-pr-handoff.md` の Part B（タスク 0031 は step 5、本タスクは step 3）と `runpr.md` を変える見込みである。
-   **候補の方針:** 先にマージされた側の変更の上に重ねる。互いの記述を書き換えない。
-   **関連:** 要件書 5 節
