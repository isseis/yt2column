# 設計への申し送り（0050_viewer_tab）

要件定義（`01_requirements.md`）の際に挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目の扱い（採った方法、または当てはまらない理由）を記録する。

-   **H-01: Service Worker・ポップアップ・ビューアの分担とメッセージ（F-001・F-002・F-004、AC-02・AC-05・AC-10）。** 生成の開始を Service Worker が送る（issue の決定）。状態の取得と投稿の操作を、ビューアとポップアップが自分で `chrome.runtime.sendNativeMessage` で送るか、Service Worker を通すかを決める。ポップアップから Service Worker への送信の求めの形と、送り手が拡張自身のポップアップであることの確かめ方（`sender.id`・`sender.url` など）を決める。キーを受け取る前に開いたビューアに、生成の開始の結果をどう渡すか（タブの ID、メッセージ）、その前にビューアが再読み込みされた場合と、Service Worker が停止した場合の扱いを決める。ビューアが生成の開始の結果を待つ時間（25 秒のやり取りの上限から決める）を決める（AC-10）。その時間の後に届いた結果を無視するか、表示に使うかを決める。ネイティブの呼び出しの最中に Service Worker が停止しないことを、Chrome の版ごとの寿命の規則で確かめる。
-   **H-02: ビューアの URL の形（F-002・3.2、AC-07・AC-09・AC-43）。** クエリかフラグメントか、値の名前と符号化、キーを受け取った後に URL を書き換える方法（`history.replaceState` など）、各値の長さの上限、宣言していない値と重複する値の拒否、送信の時刻の表し方を決める。ブラウザの履歴に残る値を、要件の値（キー・見出し・チャンネル名・動画タイトル・収集した URL・送信の時刻）に限る。
-   **H-03: サーバの応答の検査（3.2、AC-41・AC-42）。** 今の `classifyResponse`（`extension/src/core/response.ts:158-223`）は、バックスラッシュを拒否し、引用符の数でメンバの重複を見つける。記事を含む応答には使えないので、厳格な JSON の検査（どの階層でもメンバの重複を拒否する、対になっていないサロゲートのエスケープを拒否する）を、外部のライブラリを使わずにどう作るかを決める。拡張の応答の上限の値（256 KiB 以上、512 KiB 以下）、操作と状態ごとのメンバの集合、`cost.usd` の形、状態コードとの組を、`docs/dev/guides/development.md`「ジョブの API」と突き合わせて決める。`docs/dev/guides/development.md` の値と拡張の値を突き合わせるガードのテストを設けるか決める。
-   **H-04: ポーリング（F-003・F-004・F-006、4.1、AC-16・AC-18・AC-19）。** 間隔の値（1 秒以上）、止める条件、状態の取得が失敗したときの続け方、背面のタブでのタイマーの間引き（Chrome は背面のタブのタイマーを間引く）の影響、ポップアップとビューアが同時にポーリングすることを決める。投稿の状態が `posting` の間は続けること、1 つのページが同時に送る状態の取得を 1 つにすること、続ける結果と止める結果の分け方（F-003 の表）を含める。
-   **H-05: ファイル名と保存の方法（F-007、AC-33・AC-34）。** ファイル名に使えない文字の集合（パスの区切り、制御文字、macOS と Windows で使えない文字、先頭の `.`、末尾の `.` と空白など）、長さの上限（バイト数かコードポイント数か）、置き換えた結果の扱いを決める。`<a download>` と Blob の URL で、`downloads` の権限なしに拡張のページから保存できることを確かめ、Blob の MIME の型と、URL を解放する時機を決める。動画 ID を収集した URL から取り出す方法を決める（`acceptedUrl.ts` は `v` を 1 つだけ持つ URL を受け付ける）。
-   **H-06: クリップボード（F-008、AC-35・AC-36）。** `navigator.clipboard.writeText` を、`clipboardWrite` の権限なしに、利用者の操作の中で拡張のページから呼べることを確かめる。失敗（文書にフォーカスがないなど）の表示を決める。
-   **H-07: タブを開く・前面に出す（F-002・F-004、AC-06・AC-21）。** `chrome.tabs.create`（`active: false`）と、タブの ID による `chrome.tabs.update`（`active: true`）・ウィンドウを前面に出す操作が、`tabs` の権限なしで動くことを確かめる。「ビューアを開く」で、この送信で開いたタブが閉じられたことを知る方法を決める。ビューアを開く位置（YouTube のタブの隣など）を決める。
-   **H-08: ポップアップの状態の構造（F-004、AC-20〜AC-24）。** `0046` `02_architecture.md` 9 章の方針（画面の内容の判別共用体に種類を加え、確認のセクションに状態の表示を、主ボタンに別の操作を描く）に沿って、送信中・受け付けられなかった・処理中・完了・失敗・不明の種類と、主ボタンの操作を決める。状態の領域の最初の変化を読み上げさせるための時機（同 9 章）を守る。
-   **H-09: 文言と書式（F-009、AC-37）。** コードと拒否の理由ごとの英語と日本語の文言、経過時間と所要時間の書式（`Intl.NumberFormat`・`Intl.DateTimeFormat` か、分と秒の組み立てか）、料金の書式（USD、小数 4 桁の文字列をどう見せるか）を決める。工程の名前（下書き・本文の短縮・検証・推敲）を `docs/translation_glossary.md` に合わせる。
-   **H-10: manifest とビルド（4.2・4.4）。** `background.service_worker`（`type: "module"` にするか）、`viewer.html` と Service Worker のスクリプトのビルドと配置、`extension/test/checkDist.test.ts`・`manifest.test.ts` の更新、権限が変わらないことのガード、`web_accessible_resources` を持たないことを決める。`minimum_chrome_version`（103）で、使う API（Service Worker の寿命の規則、`chrome.tabs`、Clipboard API）が動くかを確かめ、要れば上げる。
-   **H-11: 使わなくなるコードとガードの整理（4.5、AC-38・AC-40）。** `/articles` の応答の解釈、Slack を案内する文言、`ServerRejectReason` の今の集合を、新しい API の応答の検査に置き換える範囲を決める。`docs/dev/guides/development.md` の拒否の理由の表を読む `serverReasons.test.ts` と、両方の README（`README.md`・`README.en.md`）の「ブラウザ拡張」節を読む `metadataDocs.test.ts` などのガードを、書き直す文書に合わせる。
-   **H-12: ビューアのアクセシビリティ（4.6、AC-44〜AC-51）。** 見出しの構造、状態の領域（`role="status"` など）と読み上げの頻度（経過時間の毎秒の更新を読み上げさせない方法）、状態が変わったときのフォーカスの扱い、工程のチェックリストの要素（`<ol>`・`<li>` と、状態を伝える文字）、押せないボタンを `disabled` で表すか、ライトとダークの配色を決める。各 AC を `test` か `static` で検証する方法（色の変数からのコントラストの計算、`prefers-reduced-motion` の規則、押せる要素の大きさ）を決める。
-   **H-13: テストの組み立て（5.）。** `chrome.runtime`・`chrome.tabs`・クリップボード・ダウンロードの fake、jsdom でのビューアの描画のテスト、時刻とタイマーの注入（経過時間とポーリング）を決める。今の `launch.test.ts`・`popupPreview.test.ts` の作り方に合わせる。
