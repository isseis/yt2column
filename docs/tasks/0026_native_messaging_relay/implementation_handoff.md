# 実装への申し送り：Native Messaging ホストを中継役にした Unix ドメインソケット経由の送信

本書は、[01_requirements.md](01_requirements.md) と [02_architecture.md](02_architecture.md) のレビューで挙がった事項のうち、実装計画の段階で決めるものを集める。`03_implementation_plan.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## I-01: UDS のテストの補助の具体

-   **事項:** テスト専用の `internal/udstest` の具体（ビルドタグ、ソケットを置く短いディレクトリの作り方と置き場所、リスナーの後始末、使うパッケージの一覧）を決める。設計書 3.12 の表は、この行の責務（UDS を使うテストが共有する、ソケットの置き場所とリスナーの補助）だけを記す。
-   **理由:** macOS の `t.TempDir()` の下にソケットを置くと `sun_path` の上限（103 バイト）を超えうる（設計書 7.2）。並行の実行や中断した実行の後の再実行で、ディレクトリの名前がぶつからないようにする必要もある。これらは設計書の水準より下の詳細なので、レビュー（CodeRabbit）の指摘に従い、設計書から移した。
-   **候補の方針:** `03_implementation_plan.md` の §1.3「UDS のテストの補助」とステップ 1-4 にすでに記した方針（`//go:build test`、`/tmp` の下に実行のたびに乱数を含む短いディレクトリを作り `t.Cleanup` で消す、リスナーの後始末を `t.Cleanup` に登録する、パスの長さの余裕を補助自身のテストで確かめる）に従う。
-   **関連:** F-001、設計書 3.12・7.2
