# 設計への申し送り

`01_requirements.md` を書く際に出た、設計で決めることを挙げる。`02_architecture.md` は、各項目について、採った方法か、当てはまらない理由を記録する。

## H-01: `mkreq.md` に AC の書き方の規則を書くか

AC の書き方の規則（AC-04）は、規約の §1 に置く。`mkreq.md` の step 6 は、規約の §1 に従うと定めている。そのため、`mkreq.md` の本文に同じ規則を書き足すかどうかは、規則の正本を 1 つに保つことと、`/mkreq` が規則を見落とさないこととの兼ね合いで決める。人は、AC の並べ挙げを指摘する項目を `mkreq.md` のチェックリストに足す案を選ばなかった（要件定義書 1 章）。設計は、この選択と矛盾しない形にする。

- 関連: F-003、AC-04

## H-02: 文書を読む既存の guard への影響

`mkplan.md`・`runplan.md`・`weakreview.md`・`CLAUDE.md`・規約を読む Go の guard（`cmd/yt2column` の `TestRunprDocContract`、`TestInstructionDocPaths`、`CLAUDE.md` の対象を読む guard など）が、変える節の見出しや値を読んでいないかを調べる。読んでいるときは、その guard を同じ PR で直すか、変え方を guard が読む値に触れない形にする。

- 関連: AC-09

## H-03: 規則の置き場所と言い回し

AC-01〜AC-03・AC-05・AC-07 の規則を、規約と各コマンドの定義のどの節に、どの言い回しで書くか。規則を 1 か所に置き、ほかから参照するか、各所に短く書くかを決める。チェックリストの項目は、`_lib/simple-process.md` がそのまま写して使うので（AC-08）、項目の形を保つ。

- 関連: F-001、F-002、F-004、F-006

## H-04: 記録した差分の読み取りの、計画での形

計画の確かめの行に、`git diff` の出力とコミットの ID をどう記録するか（コードブロック、実行したコマンド、記録する時点）。`runplan.md` の step 7 のチェックリストは、今、`diff` のスクリプトが実行され、その出力と 2 つのコミットの ID が計画に記録されたことを確かめる。記録した差分の読み取りでも、同じ確かめが働く形にする。

- 関連: F-002、AC-02

## H-05: guard-test literal exception の言い回し

今の例外は、範囲を Go の guard のテスト（`_test.go`）と `internal/doctestutil` とし、拡張の guard のテストにも当てはめている（`CLAUDE.md`「Go Idioms」）。`_checks/` のスクリプトは、Go に限らずシェルでもありうる。例外の範囲・理由・リテラルの種類を、既存の書き方に合わせてどう足すかを決める。

- 関連: F-005、AC-06
