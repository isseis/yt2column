## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張の 2 つの起動経路のうち、右クリックメニュー（以下、メニュー）の経路を削除し、ツールバーのポップアップの経路だけにするための要件を定義する（[#329](https://github.com/isseis/yt2column/issues/329)）。

**背景:**

拡張には現在、起動経路が 2 つある（`0007_browser_extension_skeleton`・`0020_extension_send`）。

-   **ポップアップの経路:** ツールバーのアイコンを押すとポップアップが開き、収集した内容の要約（行数・プレビュー）と動画メタデータ（`0025_extension_video_metadata`）を表示する。利用者が「Send to yt2column」を押して初めて送信する。
-   **メニューの経路:** 字幕の行を選択して右クリックし、拡張の項目を選ぶと、確認なしに送信する。送信中と送信の結果は、別に開く結果のウィンドウに表示する。

送信は、サーバでの LLM の API の呼び出し（課金）につながる。実際に使ってみると、送る前に内容を確かめられるポップアップの経路のほうが安心で、使いやすかった。メニューの経路では、誤って項目を選んだ場合や、字幕ではない場所を選択していた場合に、送信を止められない。

メニューの経路にしかない強みは、送信の途中でポップアップを閉じても結果を表示できることだけである。ポップアップを閉じた場合の扱いは、0020 の設計（`02_architecture.md` §3.8 H-01）がすでに受け入れている。送信中の表示は「閉じない。閉じた場合は、送り直す前に Slack を確かめる」と案内する。Native Messaging への移行（`0026_native_messaging_relay`）の後も、同じ種類の振る舞いである（0026 `02_architecture.md` §3.5.5 の S-5）。

拡張の service worker（`extension/src/background.ts`）は、メニューの項目の登録とメニューの経路のためだけにある。結果のウィンドウ、結果のウィンドウへ表示内容を渡す `chrome.storage.session`、結果のウィンドウを開けないときの代わりの表示であるツールバーのバッジも、メニューの経路だけが使う。メニューの経路を削除すると、これらもまとめて不要になる。利用者の操作なしに送信を始める入口がなくなり、権限も 1 つ減る。

後続の [#330](https://github.com/isseis/yt2column/issues/330)（テキストが選択されていないときに、文字起こしパネルの DOM から書き起こしを読み取る）は、本タスクの完了を前提に、ポップアップの経路だけを対象にする。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   拡張の起動経路をポップアップだけにし、送信の前に必ず利用者が内容を確かめる段階を通るようにする。
-   メニューの経路にだけ使うコード・静的ファイル・manifest の項目・権限をなくし、拡張の構成と要求する権限を小さくする。

### 2.2. スコープ (In Scope)

-   メニューの項目の登録と、メニューの経路の処理を削除する。
-   メニューの経路にだけ使うものを削除する: service worker、結果のウィンドウ、`chrome.storage.session` の使用、ツールバーのバッジ。
-   manifest から、service worker の宣言（`background`）と `contextMenus` の権限を削除する。
-   削除したコードにだけ対応するテストを削除し、残るテストを合わせる。
-   利用者と開発者向けの文書を、ポップアップだけの構成に合わせる: `README.md` の「Browser extension」節、`docs/dev/security.md` §8.1。
-   文書を読むテスト（拡張の node のテストと、Go の文書のテスト）を、更新後の文書に合わせる。

### 2.3. スコープ外 (Out of Scope)

-   ポップアップの経路の振る舞いの変更。収集・要約・動画メタデータ・送信前の確認・送信・結果の表示・文言は変えない。
-   オプションページ（共有トークンとポートの設定）の変更。
-   送信の時間の上限（`sendTimeoutMs`、25 秒）の値の変更。値は変えない。ただし、値を選んだ理由のうち「メニューの経路の service worker が 30 秒で止められうる」は当てはまらなくなる。理由の記述の扱いは設計で決める（[design_handoff.md](design_handoff.md) H-04）。
-   サーバ（Go）の変更。サーバは拡張の起動経路を区別しないので、変更は要らない。
-   完了したタスクの文書（`0007`・`0020`・`0025` など）の書き換え。これらは当時の決定の記録として残す。
-   `0026_native_messaging_relay` の文書の訂正。0026 の要件（AC-24 など）と実装計画は、メニューとポップアップの両方からの送信を前提にしている。本タスクの完了後に、0026 の側で訂正する（§5）。
-   #330（DOM からの書き起こしの読み取り）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: メニューの経路の削除

拡張は右クリックメニューに項目を加えない。拡張を起動する手段は、ツールバーのアイコンから開くポップアップだけとする。

-   拡張は service worker を持たない。利用者がポップアップで「Send to yt2column」を押す以外に、送信を始める手段はない。
-   拡張は `chrome.storage.session` を使わない。設定の保存（`chrome.storage.local`）は変えない。
-   結果のウィンドウ（`result.html`）と、ツールバーのバッジによる表示はない。

**Acceptance Criteria**:
- **AC-01**: ビルドした manifest（`extension/dist/manifest.json`）に `background` のメンバがなく、`permissions` が `activeTab`・`scripting`・`storage` の 3 つだけである。`host_permissions` は変わらない（ユニットテスト・ビルドの検査）。
- **AC-02**: ビルドの成果物（`extension/dist/`）に、service worker のスクリプトと結果のウィンドウのページ（とそのスクリプト）が含まれない（ビルドの検査）。
- **AC-03**: 拡張のソースに、`chrome.contextMenus`・`chrome.storage.session`・`chrome.action.setBadgeText`・`chrome.windows` を使うコードがない（静的な確認）。
- **AC-04**: 拡張を読み込んだ Chrome と Brave で、YouTube の動画ページの字幕の行を選択して右クリックしても、拡張の項目が表示されない（手動確認）。
- **AC-05**: メニューの経路が入った版を読み込んでいたブラウザで、本タスクの版に読み込み直す（`chrome://extensions/` の再読み込み）と、拡張の項目が右クリックメニューから消え、権限の追加の確認を求められない（手動確認。Chrome と Brave）。

#### F-002: ポップアップの経路の維持

ポップアップの経路の振る舞いを変えない。

**Acceptance Criteria**:
- **AC-06**: ポップアップの経路の既存のユニットテスト（収集・要約・動画メタデータの表示・送信前の確認・送信・結果の表示）が、期待値を変えずに通る（ユニットテスト）。
- **AC-07**: Chrome と Brave で、ポップアップから送信し、受付・拒否・結果が分からない、の各表示が従来どおりに出る。少なくとも受付（`202`）と、共有トークンが未設定の場合の送らない理由を確かめる（手動確認）。
- **AC-08**: ポップアップの送信中の表示が、従来どおり、結果が表示されるまで閉じないことと、閉じた場合は送り直す前に Slack を確かめることを案内する（`Do not close this window until the result appears.`・`If you close it, check Slack before sending again.`）。文言は変えない（ユニットテスト）。

#### F-003: テストの削除の確認

削除したコードにだけ対応するテストを削除する。削除によって、残るコードの検査が失われていないことを確かめる。

**Acceptance Criteria**:
- **AC-09**: 削除の前後で、拡張のテストのカバレッジ（`node --test` のカバレッジの報告）を関数ごとに比べ、残るファイル・関数のカバレッジが下がっていないことを確かめ、結果を実装計画に記録する（CLAUDE.md の「Deleting a test is a claim that must be checked」）。比べ方は設計で決める（[design_handoff.md](design_handoff.md) H-03）。
- **AC-10**: Go のテストを削除する場合は、`go tool cover -func` が削除の前後で関数ごとに変わらないことを確かめ、記録する。Go のテストを削除しない場合は、その旨を記録する。

#### F-004: 文書の更新

利用者と開発者向けの文書を、ポップアップだけの構成に合わせる。

**Acceptance Criteria**:
- **AC-11**: `README.md` の「Browser extension」節が、起動の手段をポップアップだけとして記述する。メニューの経路、結果のウィンドウ、service worker のコンソールへの言及がない（静的な確認。文書のテスト）。
- **AC-12**: `docs/dev/security.md` §8.1 の「要求する権限」が、manifest の `permissions` と一致し（`contextMenus` がない）、`storage` の用途に `chrome.storage.session` と結果のウィンドウが含まれない。§8.1 のほかの記述にも、結果のウィンドウへの言及がない（静的な確認。既存の manifest と文書の一致のテストを含む）。
- **AC-13**: `make ext-check` と `make test` と `make lint` が通る。文書だけを読む Go のテスト（`doc-guard` の CI ジョブが実行するもの）も通る。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

本タスクは信頼できない入力の境界を新しく加えない。結果のウィンドウが `chrome.storage.session` から読む値の検査（`parseResultView`）は、結果のウィンドウとともに読み手がなくなる。ポップアップの経路の既存の境界（選択範囲の文字列、タブの URL・タイトル、動画メタデータ、サーバの応答）は変えない。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   要件はない。ポップアップの経路の処理は変えない。

### 4.2. セキュリティ (Security)

-   要求する権限を減らす（`contextMenus` を削除する）。権限を増やさない。
-   拡張の中で、利用者がポップアップのボタンを押す以外に送信を始める入口を持たない。0007 の「拡張は `runtime.onMessage` を使わない」（0007 `02_architecture.md` §5.1）を保つ。
-   共有トークンを、ログ・表示・送る本文に出さない、という既存の扱い（`docs/dev/security.md` §8.1）を変えない。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   送信の途中でポップアップを閉じた場合は、結果を表示できない。この扱いは 0020 の設計（`02_architecture.md` §3.8 H-01）が受け入れたものと同じで、本タスクで新しく加わるリスクではない。メニューの経路という代わりの手段はなくなる。

### 4.4. 互換性 (Compatibility)

-   対象のブラウザは、従来どおり Chrome と Brave とする。manifest の `minimum_chrome_version` は変えない。

### 4.5. 保守性 (Maintainability)

-   ポップアップの経路だけが使うコードと、メニューの経路と共有していたコードを区別し、ポップアップの経路が使うものは残す（例: 送らない理由の表示）。メニューの経路にだけ使う型・関数・定数を残さない（`make deadcode` は Go だけを対象にするので、拡張では設計で確かめ方を決める。[design_handoff.md](design_handoff.md) H-01）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   本タスクは `0026_native_messaging_relay` の実装より前に完了させる。0026 がメニューの経路の Native Messaging への対応（0026 `02_architecture.md` の S-7）を実装せずに済むようにするためである。本タスクの完了後に、0026 の要件・設計・実装計画からメニューの経路を外す訂正を、0026 の側で行う。0026 の要件（AC-24）の訂正は判断の変更にあたるので、0026 の要件書の状態を `draft` に戻して承認を受け直す（requirements_process.md の「Editing an approved document」）。
-   拡張の依存パッケージを追加しない。

## 6. 用語集 (Glossary)

-   **メニューの経路:** 字幕の行を選択して右クリックし、拡張の項目を選ぶと、確認なしに送信する起動経路。本タスクで削除する。
-   **ポップアップの経路:** ツールバーのアイコンから開くポップアップで、収集した内容を表示し、利用者が送信のボタンを押して送信する起動経路。本タスクの後は唯一の起動経路になる。
-   **結果のウィンドウ:** メニューの経路で、送信中と送信の結果を表示するために開くウィンドウ（`result.html`）。本タスクで削除する。
-   (その他の用語は `docs/translation_glossary.md` と統一する)
