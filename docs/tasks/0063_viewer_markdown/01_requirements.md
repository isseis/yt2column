## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張のビューアで、完了した記事の表示用の Markdown を、見出し・段落・リスト・強調などを整えた読みやすい形に描画するための要件を定義する。描画の対象は信頼できないテキストなので、描画してよい要素と属性、リンクにする条件、扱わない記法の表示も、あわせて定める。

**背景:**

今のビューアは、状態の取得が返す表示用の Markdown（`article.markdown`）を、`textContent` でそのまま文字として表示する（`extension/src/ui/articleBody.ts:13-22`）。CSS は行の折り返しと空白を保ち、行ごとに文字の方向を分けるだけで（`extension/static/viewer.css:53-62`）、`#` や `**` などの記号も文字として見える。これは、Markdown の描画を本 issue に分けた 0050 の決定による（[0050 要件定義書](../0050_viewer_tab/01_requirements.md) §1・F-005・AC-25）。

表示用の Markdown は、記事のタイトルの行（`# <タイトル>`）、チャンネル名の行（チャンネル名があるとき）、本文の順に並ぶ（`internal/publisher/display_render.go:28-36`）。チャンネル名の行は、行頭が Markdown のブロックの記法になる場合だけ、行頭（番号付きリストの記号では数字の後ろ）にバックスラッシュを 1 つ入れてある（`internal/publisher/file_render.go:87-99`）。行の途中の記法はエスケープしない（[security.md](../../dev/security.md) §6）。本文の末尾には、出典リンクの行 `出典: <https://www.youtube.com/watch?v=…>`（以下、出典の行）が、空行を挟んで付く（`internal/writer/output.go:31-33`・`236-240`）。

本文の書き方は生成のプロンプトが指示する（`prompts/system.tmpl` §4〜§6）。レベル 1 の見出しはタイトルだけ、節はレベル 2 の見出しだけで、`###` 以下は使わない。箇条書きは必要な箇所だけ、対談記事では発言の段落を `**話者の名前**：` で始める。コードフェンスは使うなら閉じる。生の HTML は使わず、URL も書かない。引用・水平線・表は、プロンプトが指示も禁止もしていない。生の HTML と、閉じていないコードフェンスを含む出力は、生成の段階で拒否している（`internal/writer/errors.go:66-71`）。

記事は LLM の出力であり、字幕と動画メタデータを経由したプロンプトインジェクションで、意図しない HTML やリンクを含みうる（security.md §6・§8.1）。ビューアは `nativeMessaging` を呼べる拡張のページなので、記事の中のスクリプトが動けば、ホストへの任意の送信につながる（security.md §8.1「記事を untrusted テキストとして表示する」）。一方、拡張が出荷するのはこのリポジトリが書いたコードだけで、npm のパッケージは開発用に限るため（[CLAUDE.md](../../../CLAUDE.md)「Dependencies」）、Markdown のライブラリは使えない。

対応 issue: [#504](https://github.com/isseis/yt2column/issues/504)（親: [#501](https://github.com/isseis/yt2column/issues/501)、前提: [#503](https://github.com/isseis/yt2column/issues/503)（`0050_viewer_tab`、完了））

**本書の記述範囲:** 本書は、観測できる振る舞いを定める。どの記法をどの要素に描画するか、描画した要素の文字列、リンクにする条件、扱わない記法の表示、文字組み、アクセシビリティ、ほかの機能への影響である。レンダラーの構成（走査の手段、関数の分け方、データ構造）、CSS の具体的な値、テストの手段は、設計（`02_architecture.md`）で決める。要件のレビューで挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #504 で決めたこと:**

-   **自前の最小限のレンダラーを書く:** 記事が使う Markdown の要素だけを扱う。Markdown のライブラリは使わない。拡張が出荷するのはこのリポジトリが書いたコードだけで、npm のパッケージは開発用に限るためである（CLAUDE.md「Dependencies」）。
-   **生の HTML を描画しない:** DOM は `textContent` と要素の生成で組み立て、`innerHTML` を使わない。記事は信頼できないテキストで、ビューアは権限のあるページだからである。
-   **リンクのスキームを制限する:** `https` だけを許す。
-   **扱わない要素は文字列のまま表示する:** 扱わない記法を、近い要素に直して描画することはしない（CLAUDE.md「Reject, don't normalize」）。
-   **本文の幅は 700〜800px 程度、読みやすい文字の大きさと行間にする。**

**要件定義の際に決めたこと（2026-11-05）:**

-   **扱う要素は、プロンプトが使う要素とその周りの小さな要素に限る:** プロンプトが指示する見出し（`#`・`##`）・段落・箇条書き・強い強調（`**`）・コードブロックに、扱っても小さく安全な番号付きリスト（1 階層）・強調（`*`）・コードスパン・バックスラッシュのエスケープ（チャンネル名の行の頭のエスケープを表示するのに要る）・自動リンク（出典の行に要る）を加える。引用・表・水平線・入れ子のリスト・画像・`###` 以下の見出しは、文字のまま表示する（F-004）。プロンプトが使わない記法を扱えば、レンダラーとテストが増えるだけになるためである。LLM がプロンプトの禁じていない引用・水平線・表を書いた場合は、記号を含めて文字のまま表示されることを受け入れる。ADR の判断: 下の ADR-0017 に含める。
-   **リンクにするのは `https` の自動リンクだけにする:** `<https://…>` の形の自動リンクだけをリンクにする。`[文字](URL)` の形のリンクは文字のまま表示する（F-003・F-004）。プロンプトは URL を書かせない（本文の URL は出典の行だけである）ので、本文の中のリンクはプロンプトインジェクションの疑いが強い。また、`[YouTube](https://悪意の URL)` のように、表示する文字とリンク先が食い違う形も防げる。自動リンクなら、表示する文字は URL そのものになる。リンクを何も作らない案（今の表示）は採らない。出典の動画を開くのに、URL の文字列をコピーする手間が要るためである。ADR の判断: 下の ADR-0017 に含める。
-   **リンクは新しいタブで、参照元を送らずに開く:** ビューアの元動画へのリンクと同じ扱いにする（`extension/static/viewer.html:13`）。同じタブで開くと、ビューアのタブが記事の表示から離れる。新しいタブなら、ビューアのタブは記事の表示のまま残り、遷移先のページは参照元とビューアのウィンドウを得られない。ADR の判断: 下の ADR-0017 に含める。
-   **記事の見出しを 1 段下げる:** 記事のタイトルの行（`#`）をレベル 2、節の見出し（`##`）をレベル 3 の見出しにする（F-001）。ビューアには、動画のセクションの見出しがレベル 1 の見出しとしてすでにあり（`extension/static/viewer.html:11`）、ページの見出しの構造を 1 本に保つためである（WCAG 1.3.1）。ADR の判断: 作らない。ビューアの 1 つの画面の構造の決定で、このタスクの中で閉じる。
-   **記法の解釈は、本書で定める単純な規則による:** CommonMark の解釈には合わせず、3.2 節の規則に従う。例えば、強調は 1 行の中の対になった記号だけで、入れ子にしない。規則に合わないものは文字のまま表示する。記事はプロンプトが決めた単純な形をしており、CommonMark に合わせても実用上の差は小さい。強調の区切りの規則まで実装するとレンダラーとテストが大きくなるので、小さく保つことを選んだ。そのため、保存した `.md` を CommonMark のビューアで開くと、ビューアの表示と細部が異なりうる（例えば段落の中の改行）。これは受け入れる。規則の中の次の 2 点も、この決定に含める。番号付きリストの番号は、最初の項目の数から 1 ずつ増やして表示する（B-5）。理由は 2 つある。1 つは、項目ごとに書かれた数を表示するには、項目ごとに記事の内容から属性を作る必要があることである。もう 1 つは、最初の項目の数から 1 ずつ増やす表示が、CommonMark のビューアの表示と同じになることである。コードブロックの情報文字列（言語の名前など）は表示しない（B-3）。記事の内容ではなく、コードの種類の注記だからである。ADR の判断: 下の ADR-0017 に含める。
-   **文字組みの範囲を要件で定める:** 本文の 1 行の最大の幅を 700〜800 CSS px、本文の文字の大きさをブラウザの既定（16 CSS px）以上、行間を文字の大きさの 1.7〜2.0 倍とする（F-005）。具体的な値は設計で決める。日本語の長文に読みやすい範囲である。ADR の判断: 作らない。CSS の値はこのタスクの中で閉じる。
-   **記事の部分の言語を日本語と示す:** 描画した記事の要素の言語を日本語（`ja`）とする（F-005）。ページの `lang` は UI の表示言語なので（`extension/src/ui/pageLocale.ts:10-12`）、英語の UI では記事の部分の言語がページと食い違う。記事は、プロンプトの指示で素材の言語によらず日本語で書かれる（`prompts/system.tmpl` §4）。WCAG 3.1.2（レベル AA）を満たすためである。プロンプトを書き換えて日本語以外の記事を作った場合は誤りになるが、記事の言語はプロンプトが決めるものとして受け入れる。ADR の判断: 作らない。このタスクの中で閉じる。
-   **チャンネル名の行の中の記法は、本文と同じに描画することを受け入れる:** チャンネル名は LLM の出力ではなく、動画の持ち主が決める値で、行の途中の記法はエスケープされない（security.md §6）。そのため、`<https://…>` を含むチャンネル名はリンクになり、`**…**` を含む名前は強調になる。レンダラーが受け取るのは 1 つの文字列で、チャンネル名の行があるかを示す値はないので、行の位置からチャンネル名の行を推し量ることはしない（CLAUDE.md「Declare, don't infer」）。サーバの応答を分ける案は、#502 の API と応答の検査を変えることになり、本 issue の範囲を大きく超えるので採らない。リンクの表示は URL そのもので、新しいタブで参照元を送らずに開くので、LLM が書いた自動リンクと同じ種類のリスクとして受け入れる（4.2）。ADR の判断: 下の ADR-0017 の結果に含める。
-   **ADR:** 描画の安全性の規則（HTML を解釈しない、扱う要素を限る、`https` の自動リンクだけをリンクにし、新しいタブで参照元を送らずに開く、記法を単純な規則で解釈する）を、新しい [ADR-0017](../../dev/adr/0017-viewer-markdown-rendering.md)（ビューアは記事を自前の最小限のレンダラーで描画し、HTML を解釈せず、リンクは https の自動リンクだけにする）に記録する。拡張のセキュリティの前提（security.md §8.1）を変え、このレンダラーを後で変えるタスクを縛るためである。

**方針の変更:**

-   [security.md](../../dev/security.md) §8.1「記事を untrusted テキストとして表示する」は、ビューアが記事を `textContent` だけで文字として表示し、Markdown を解釈せず、記事の中のリンクもリンクにしないとしている（0050 の決定）。本タスクは、本書の規則で Markdown を描画し、`https` の自動リンクをリンクにする（F-001〜F-003）。理由は、記事を読みやすく表示することが issue の目的そのものだからである。HTML を解釈しないこと、HTML を解釈する API を lint で禁止すること、拡張のページの既定の Content Security Policy を緩めないことは変えない。同じ項の残余のリスク（記事の中の URL の文字列を利用者がコピーして開くこと）も、リンクを押して開ける形に書き換える。security.md §8.2「返す記事は untrusted なテキスト」の「Markdown の描画の安全性は #504 で扱う」も、本書の規則を指す形に直す。security.md §6 の「チャンネル名の行の途中の記法は描画するビューアで有効になる」という残余のリスクは、本タスクで現実のものになるので、ビューアでの結果（リンク・強調になる）を書き足す。
-   0050 の次の決定を、本書の F-001〜F-004 で置き換える。0050 F-005 の「Markdown の記法は解釈せず、記事の中の HTML のタグやリンクの記法は、文字としてそのまま表示する」（[0050 要件定義書](../0050_viewer_tab/01_requirements.md) §3 F-005 の本文）、0050 AC-25（表示した文字列は表示用の Markdown と一致する）、0050 §4.2 の「記事の中のリンクは、本タスクではリンクにしない」、0050 §1「方針の変更」の「記事は HTML として解釈せず（4.2）、リンクにしない」。HTML のタグを文字として表示することは F-004 で保ち、表示した文字列は、F-001〜F-003 が除く記号とエスケープの文字を除いて、表示用の Markdown と一致する（AC-12・AC-21）。
-   [CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」は、呼び出し側が渡した文字列の中身を調べて処理を選ぶことを禁じ、例外を列挙している。レンダラーは表示用の Markdown の中身を調べて描画する要素を選ぶので、この方針の例外になる。理由は、表示用の Markdown が LLM の出力（とチャンネル名）で、拡張が型で表せない外部の値だからであり、Markdown を描画すること自体が issue の目的だからである（issue #504 の決定から導かれる）。範囲は、記事の本文を描画するレンダラーが 3.2 節の規則で表示用の Markdown を解釈することだけに限る。どの規則にも合わない入力は広く解釈せず、文字のまま表示する。CLAUDE.md の例外の一覧に、範囲・理由・境界を書き加える（H-08）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   ビューアで、記事を見出し・段落・リスト・強調を整えた読みやすい形で表示する。
-   信頼できない記事から、スクリプト・生の HTML・利用者を欺くリンクを作らない。
-   扱わない記法と規則に合わない記法を、文字を失わずにそのまま表示する。
-   描画の後も、記事の保存とコピーの中身を変えない。

### 2.2. スコープ (In Scope)

-   ビューアの記事の本文の描画（F-001〜F-004）。
-   本文の文字組みとアクセシビリティ（F-005）。
-   描画の後も保存・コピーを変えないこと（F-006）。
-   方針の変更に伴う文書の更新: `docs/dev/security.md` §6・§8.1・§8.2、ADR-0017 とその索引、`CLAUDE.md`「Declare, don't infer」の例外、README の記事の表示の説明（`README.md:630`。`README.en.md` は `/mktrans` で同期する）。

### 2.3. スコープ外 (Out of Scope)

-   引用・表・水平線・入れ子のリスト・画像・`###` 以下の見出し・Setext 形式の見出し（下線で書く見出し）・インデントのコードブロック・取り消し線などの描画: プロンプトが使わない記法なので扱わない（1 章の決定）。文字のまま表示する（F-004）。
-   `[文字](URL)` の形のリンク・参照のリンク・`http` などの `https` 以外のスキームのリンク: リンクにしない（1 章の決定）。
-   HTML の文字参照（`&amp;` など）の解釈: 文字のまま表示する（F-004）。プロンプトは文字参照を使わず、解釈すると表示する文字が元の文字と変わるためである。
-   CommonMark との完全な互換: 本書の規則で解釈する（1 章の決定）。
-   タイトルの行とチャンネル名の行を本文と別に扱うこと: 応答を分ける必要があり、採らない（1 章の決定）。
-   ポップアップの表示: ポップアップは記事の本文を表示しない（0050 の範囲）。
-   Slack への投稿の整形と `.md` のファイルの中身: Go の実装のまま変えない（issue #501 の決定。F-006）。
-   生成のプロンプトの変更: 記事が使う記法は今のプロンプトのままとする。
-   記事の中の URL を開く前の確認の画面: リンクの表示が URL そのものなので設けない（1 章の決定）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 描画の対象

描画の対象は、ビューアが完了した記事を表示するときの表示用の Markdown（`article.markdown`）である。状態の取得の応答の検査（[0050 要件定義書](../0050_viewer_tab/01_requirements.md) §4.2 の表）を通った、空でない文字列だけが届く。それ以外の場面（処理中・失敗・失われた記事）の表示は、0050 のまま変えない。ファイルの中身（`article.file`）は描画しない。

### 3.2. 記法の規則

レンダラーは、次の規則だけで表示用の Markdown を解釈する。規則は、どの入力に対しても描画を 1 通りに決める。

**用語:**

-   **空白:** U+0020（スペース）と U+0009（タブ）だけ。U+3000（全角スペース）・U+00A0 などは空白ではなく、ふつうの文字として扱う。
-   **制御文字:** Unicode の一般カテゴリ Cc の文字。
-   **ASCII の区切り文字:** `` !"#$%&'()*+,-./:;<=>?@[\]^_`{|}~ `` の 32 文字。

**行:** 表示用の Markdown を LF（U+000A）で行に分ける。CR（U+000D）は改行として扱わず、文字として扱う。ブロックの記法は、行の先頭の文字から判定する。行頭に空白がある行は、空行（B-1）とコードブロックを閉じる行（B-3）を除いて、どのブロックの記法にも当たらない（段落の行か、項目の継続の行になる）。

**ブロックの規則:** 行を先頭から順に、コードブロックの中の行を除いて、B-1〜B-7 の順に当てはめる。

-   **B-1 空行:** 空か、空白だけの行。ブロックを区切り、それ自体は何も表示しない。
-   **B-2 見出し:** `# ` か `#` とタブで始まる行は記事のタイトルの見出し、`## ` か `##` とタブで始まる行は節の見出しである。記号と、その後ろに続く空白を除いた残りが見出しの文字列で、インラインの規則を当てはめる。残りが空なら見出しではなく、段落の行になる。`#` が 3 つ以上の行と、`#` の直後に空白のない行は見出しではない。見出しは 1 行で終わる。
-   **B-3 コードブロック:** `` ` `` か `~` が 3 つ以上並んで始まる行は、コードブロックを開く。ただし、`` ` `` の並びで始まり、並びの後ろに `` ` `` を含む行は開かない。並びの後ろの文字列（情報文字列）は表示しない。開いたコードブロックは、開いた行より後の最初の閉じる行で閉じる。閉じる行は、行頭の 0〜3 個の U+0020 に続いて、開いた並びと同じ文字が同じ数以上並び、その後ろが空白だけの行である（サーバが閉じたと判定する形と同じ。`internal/writer/markdown.go:176-185`）。間の行は、インラインの規則を当てはめず、改行と空白を保って等幅で表示する。閉じる行がないときは、開いた行はコードブロックを開かず、その行と以降の行を、ほかの規則で解釈する。
-   **B-4 箇条書き:** `- `・`* `・`+ ` のいずれかで始まる行は、箇条書きの項目である。記号と直後の U+0020 1 つを除いた残りが項目の文字列で、インラインの規則を当てはめる。同じ記号の項目が続く間（間に空行があってもよい）は 1 つのリストになり、記号が変わると新しいリストになる。
-   **B-5 番号付きリスト:** 1〜9 桁の数字、`.` か `)`、U+0020 1 つの順で始まる行は、番号付きリストの項目である。それらを除いた残りが項目の文字列で、インラインの規則を当てはめる。同じ区切りの文字（`.` か `)`）の項目が続く間（間に空行があってもよい）は 1 つのリストになる。リストの番号は、最初の項目の数の値から 1 ずつ増やして表示する。
-   **B-6 項目の継続:** 項目の行か、その継続の行の直後（間に空行がない）の行が、空行でもなく、見出し・コードブロックを開く行・項目の行でもないとき、その行は直前の項目の続きで、項目の中に改行を入れて表示する。行頭の空白で入れ子のリストを書いた行も、この規則で項目の続きの文字になる。
-   **B-7 段落:** ほかの規則に当たらない行は段落の行である。続いている段落の行は 1 つの段落になり、行の間の改行は段落の中の改行として表示する。段落は、空行と、見出し・コードブロックを開く行・項目の行で終わる。

段落・項目・見出しの文字列の中の空白（行頭の空白と、連続した空白を含む）は、詰めずに書いたとおりに表示する。

**インラインの規則:** 見出し・項目・段落の文字列に、行ごとに当てはめる。どの規則も行をまたがない。

行を左から右へ 1 回だけ走査する。各位置で、I-1・I-2・I-5・I-3・I-4 の順に試し、最初に当たった規則がその部分を処理し、走査はその後ろから続ける。どれにも当たらない文字は、文字として表示する。連続した `` ` `` と、連続した `*` は、それぞれ 1 つの並びとして扱う。並びは I-1 で文字として表示した記号を含まない（`\**` の 2 つ目の `*` は、1 個の `*` の並びである）。空白かどうかを調べる直前・直後の文字には、I-1 で表示しない `\` を数えない。開く記号になれなかった並びは、並び全体を文字として表示し、走査は並びの後ろから続ける。I-1 で文字として表示した記号は、開く記号にも閉じる記号にもならない。

-   **I-1 エスケープ:** `\` の直後の文字が ASCII の区切り文字なら、`\` を表示せず、その文字を記法の記号として扱わずに文字として表示する。それ以外の `\` は文字として表示する。行頭の `\` はブロックの記号ではないので、`\#` や `\-` で始まる行は段落の行になり、`1\.` で始まる行も番号付きリストの項目にならない。
-   **I-2 コードスパン:** `` ` `` が n 個並んだところで開き、同じ行の中で、その後ろで最初に `` ` `` がちょうど n 個並んだところで閉じる。閉じる並びを探すときは、I-1 を当てはめない。間の文字列を、ほかの規則を当てはめずに等幅で表示する。閉じる並びがなければ、開く並びを文字として表示する。
-   **I-3 強い強調:** ちょうど 2 個の `*` の並びで、直後が空白でないところで開き、同じ行の中で、その後ろで最初の、ちょうど 2 個の `*` の並びで直前が空白でないところで閉じる。間の文字列を強い強調として表示する。閉じる並びがなければ、開く並びを文字として表示する。
-   **I-4 強調:** ちょうど 1 個の `*` で、直後が空白でないところで開き、同じ行の中で、その後ろで最初の、ちょうど 1 個の `*` で直前が空白でないところで閉じる。間の文字列を強調として表示する。閉じる記号がなければ、`*` を文字として表示する。3 個以上の `*` の並びは、開く記号にも閉じる記号にもならず、常に文字として表示する。`_` は強調の記号として扱わない。
-   **I-5 自動リンク:** `<https://` で始まり、同じ行の中の最も近い `>` で終わる並びで、間に空白・制御文字・`<` を含まないもの。F-003 の条件を満たすときだけリンクとして描画する。満たさないときは `<` を文字として表示し、走査は `<` の後ろから続ける。
-   **入れ子:** 強い強調と強調の中では、I-1 だけを当てはめ、ほかの規則（コードスパン・強調・自動リンク）は当てはめない。閉じる記号を探すときも同じで、間の `` ` `` や `<` は閉じる位置に影響しない。コードスパンと自動リンクの中では、どの規則も当てはめない。

I-3 と I-4 は、開く記号の直後と閉じる記号の直前が空白でないので、中身が空になることはない。

### 3.3. 機能一覧

#### F-001: ブロックの描画

ビューアは、完了した記事の表示用の Markdown を、3.2 節のブロックの規則に従って、見出し・段落・リスト・コードブロックに描画する。

-   記事のタイトルの見出し（B-2 の `#`）はレベル 2、節の見出し（B-2 の `##`）はレベル 3 の見出しとして描画する（1 章の決定）。
-   描画した各ブロックの文字列は、そのブロックの行から、ブロックの記号（B-2・B-4・B-5 で除く部分）と、インラインの規則で表示しない文字（F-002・F-003）を除いたものと一致する。

**Acceptance Criteria**:
- **AC-01**: `# <タイトル>` の行はレベル 2 の見出し、`## <節の見出し>` の行はレベル 3 の見出しとして描画され、見出しの文字列は記号と直後の空白を除いた残りと一致する。`### x`・`#x`・`#` だけの行・`# ` の後ろが空白だけの行は、見出しにならず、段落の文字として表示される。
- **AC-02**: 空行で区切られた行のまとまりは、それぞれ 1 つの段落として描画される。段落の中の行の間の改行は、改行として表示される。段落の中の行頭の空白と連続した空白は、詰められずに表示される。
- **AC-03**: `- `・`* `・`+ ` で始まる項目の並びは箇条書きとして描画される。同じ記号の項目は、間に空行があっても 1 つのリストになり、記号が変わると別のリストになる。
- **AC-04**: `1. ` や `3) ` のように始まる項目の並びは、番号付きリストとして描画される。番号は最初の項目の数の値から 1 ずつ増えて表示され（例: `3. a`・`3. b` は 3・4）、区切りの文字が変わると別のリストになる。10 桁以上の数字で始まる行は項目にならない。
- **AC-05**: 項目の行の直後の、ブロックの記法に当たらない行と、さらにその直後の同じ種類の行は、その項目の続きとして項目の中に改行を入れて表示される。行頭の空白で書いた入れ子のリストの行（例: `  - 子`）も、入れ子のリストにならず、親の項目の続きの文字として表示される。
- **AC-06**: 閉じたコードフェンスの間の行は、改行と空白を保ったまま等幅で表示され、間の `**`・`#`・`<https://…>` などは描画されずに文字として表示される。情報文字列は表示されない。行頭に 3 個までの U+0020 がある閉じる行でも閉じる。閉じる行のないフェンスは、開いた行を含めてほかの規則で解釈される。
- **AC-07**: 表示用の Markdown の形（タイトルの行、チャンネル名の行、本文、出典の行）をそのまま描画すると、タイトルはレベル 2 の見出し、チャンネル名の行と出典の行はそれぞれ段落になる。チャンネル名の行の頭のエスケープ（例: `\- 名前`、`1\. 名前`、`\# 名前`）はバックスラッシュを表示せず、行頭の記号を文字として表示する（I-1）。チャンネル名の行の途中の記法は、本文と同じ規則で描画される（例: `名前 <https://example.com/x>` の URL はリンクになる。1 章の決定）。

#### F-002: インラインの描画

ビューアは、見出し・項目・段落の文字列に、3.2 節のインラインの規則を当てはめて描画する。

**Acceptance Criteria**:
- **AC-08**: 1 行の中の `**話者**：` は、`話者` が強い強調として描画され、`**` は表示されない。`**　話者**`（開く記号の直後が U+3000）も強い強調になる。1 行の中の `*語*` は、`語` が強調として描画される。行をまたぐ記号の対、閉じる記号のない記号、開く記号の直後か閉じる記号の直前が空白（U+0020・タブ）の記号、3 個以上の `*` の並び（例: `***語***`・`****`）は、強調にならず、記号が文字として表示される。`_語_` は強調にならない。
- **AC-09**: `` `x` `` は等幅のコードスパンとして描画され、中の `**` や `<https://…>` は文字として表示される。閉じる並びのない `` ` `` の並びは、並び全体が文字として表示される。
- **AC-10**: `\*`・`\#`・`\<`・`` \` `` などの ASCII の区切り文字の前の `\` は表示されず、その文字は記法の記号として働かない（例: `**a \** b**` は `a ** b` の強い強調になる）。ASCII の区切り文字ではない文字の前の `\`（例: `\あ`、行末の `\`）は文字として表示される。
- **AC-11**: 強い強調と強調の中のコードスパン・強調・自動リンクの記号は、描画されずに文字として表示される（例: `*a**b*` は `a**b` の強調になる）。強調の中のエスケープ（I-1）は働く。
- **AC-12**: 描画した見出し・項目・段落の文字列は、元の文字列から、強い強調・強調・コードスパンの記号、I-1 で表示しない `\`、リンクとして描画した自動リンクの `<` と `>` を除いたものと一致し、文字の順序は元のままである。

#### F-003: リンク

ビューアは、自動リンク（I-5）のうち、次の条件をすべて満たすものだけをリンクとして描画する。

-   `<` と `>` の間の文字列（以下、URL の文字列）を、WHATWG の URL Standard に従って URL として解釈できる。
-   スキームが `https` で、URL の文字列は小文字の `https://` で始まる。
-   URL のホスト（ドメイン名の部分）が空でなく、ユーザー名もパスワードも持たない。
-   URL の文字列が、URL として解釈して文字列に戻したもの（URL Standard の直列化）と 1 文字も違わない。解釈で文字列が変わる URL（大文字のスキーム、`\` を含むパス、全角の文字を含むドメイン名、エンコードが必要な文字、パスのない URL に補われる末尾の `/` など）をリンクにすると、表示する文字列とリンク先が食い違うので、リンクにせず文字として表示する（CLAUDE.md「Reject, don't normalize」）。

リンクの表示する文字列とリンク先は、どちらも URL の文字列とする。リンクの文字列は、周りの文字の方向によらず、左から右へ URL の文字の順に表示する。リンクを押すと、リンク先を新しいタブで、参照元を送らず、開いたページがビューアのウィンドウを得られない形で開く（1 章の決定）。

**Acceptance Criteria**:
- **AC-13**: 出典の行 `出典: <https://www.youtube.com/watch?v=abcdefghijk>` は、`出典: ` に続くリンクとして描画され、リンクの文字列とリンク先は `https://www.youtube.com/watch?v=abcdefghijk` に一致する。`<` と `>` は表示されない。
- **AC-14**: 次の自動リンクの形は、いずれもリンクにならず、`<` と `>` を含めて文字として表示される: `<http://example.com>`、`<HTTPS://example.com/>`、`<javascript:alert(1)>`、`<https://>`、`<https://example.com>`（直列化で末尾に `/` が補われる）、`<https://user:pass@example.com/>`、`<https://example.com\path>`、`<https://ｅxample.com/>`（全角の文字を含むドメイン名）、`<https://example.com/a b>`、`<https://example.com/<x>`。例は網羅を主張しない。
- **AC-15**: `[文字](https://example.com/)` と `[文字][ref]`、`![画像](https://example.com/a.png)` は、リンクにも画像にもならず、文字として表示される。
- **AC-16**: リンクを押すと、リンク先は新しいタブで開き、ビューアのタブは記事の表示のまま残る。リンクの要素は、参照元を送らず、開いたページに `window.opener` を与えない属性（`rel="noopener noreferrer"`）を持つ。
- **AC-17**: リンクの直前に右から左への制御文字（U+202E・U+202B・U+2067・U+2066 など）や右から左に書く文字があっても、リンクの文字列は左から右へ URL の文字の順に表示される。

#### F-004: 扱わない記法と HTML

ビューアは、3.2 節の規則に当たらない記法と HTML を、要素に描画せずに文字として表示する。描画した記事の中の要素と属性は、次のものに限る。

-   要素: 見出し（レベル 2 と 3）、段落、箇条書き、番号付きリスト、項目、強い強調、強調、コードスパン、コードブロック、リンク、改行、およびこれらを入れる要素。
-   記事の内容から値を決める属性: リンクのリンク先（F-003 の条件を満たした URL の文字列）と、番号付きリストの開始番号（B-5 の数の値）だけ。属性の名前を記事の内容から決めることはない。

**Acceptance Criteria**:
- **AC-18**: `<img src=x onerror=alert(1)>`、`<a href="javascript:alert(1)">x</a>`、`<script>alert(1)</script>`、`<!-- x -->`、`<div>` を含む行は、ほかの行と同じ規則で段落などとして描画され、タグからは要素も属性も作られない。タグは文字として表示され、スクリプトは動かない。
- **AC-19**: `> 引用`、`| a | b |` の表、`---`・`***`・`___` の水平線（`- - -`・`* * *` は B-4 の項目になり、項目の文字列 `- -`・`* *` が表示される）、`### 見出し`、4 つの空白で始まる行、`見出し` の次の行の `===`・`---`（Setext 形式の見出し）、`~~取り消し~~`、`&amp;`・`&#60;` の文字参照は、いずれも描画されず、記号を含めて文字として表示される。文字参照は解釈されず、`&amp;` は `&amp;` のまま表示される。
- **AC-20**: どのような入力を描画しても、記事の中に作られる要素は上の一覧の種類だけで、属性はリンクのリンク先・新しいタブの指定・`rel`、番号付きリストの開始番号、および記事の内容によらない固定の属性だけである。
- **AC-21**: 描画した記事の文字列（記事の要素の文字列を順につなげたもの）は、表示用の Markdown から次のものを除いたものと一致し、それ以外の文字を失わず、順序を変えない。除くもの: ブロックの間の改行と空行、見出しと項目の記号とその直後の空白（B-2・B-4・B-5 で除く部分）、コードフェンスの開く行と閉じる行、F-002 と F-003 が除く記号と `\`。段落・項目・コードブロックの中の改行は、改行（U+000A）1 つとして数えて残る。

#### F-005: 文字組みとアクセシビリティ

ビューアは、描画した記事を、日本語の長文に読みやすい文字組みで表示し、[CLAUDE.md](../../../CLAUDE.md)「Accessibility」の基準を満たす。

**Acceptance Criteria**:
- **AC-22**: タブの幅が 900 CSS px 以上のとき、記事の段落の 1 行の幅は、700〜800 CSS px の範囲内の最大幅で頭打ちになる。タブの幅が 320 CSS px のとき、記事はページの横のスクロールなしに収まる。コードブロックの長い行は、コードブロックの中で折り返すか、ブロックの中だけで横にスクロールする。横にスクロールする場合、そのブロックはキーボードでフォーカスでき、矢印のキーでスクロールできる。
- **AC-23**: 段落と項目の文字の大きさは 16 CSS px 以上で、行の高さは文字の大きさの 1.7〜2.0 倍である。
- **AC-24**: 描画した記事を入れる要素は `lang="ja"` を持つ。ページの `lang` は今までどおり UI の表示言語である。
- **AC-25**: ページの見出しの構造で、動画のセクションの見出し（レベル 1）の下に、記事のタイトルの見出し（レベル 2）、節の見出し（レベル 3）の順に並ぶ。
- **AC-26**: 記事の中のリンクは、ポインティングデバイスなしで、Tab と Shift+Tab で表示の順に移動でき、Enter で開ける。フォーカスしたリンクは、隣り合う色との間に 3:1 以上のコントラストがある表示で見分けられる。リンクの名前は表示している URL の文字列である。
- **AC-27**: リンクは色だけでなく下線でも本文と区別できる。リンク・コードスパン・コードブロックの文字と背景のコントラストは、明るいテーマと暗いテーマの両方で 4.5:1 以上である。
- **AC-28**: 1 つの行（段落と項目の中の行、見出し、コードブロックの行）の中の双方向の制御文字や右から左に書く文字は、ほかの行の表示の順序を変えない。各行の文字の方向は、その行の文字から決まる（今の表示と同じ。`extension/static/viewer.css:53-62`）。
- **AC-29**: 記事の中のリンクは文の中のリンクで、WCAG 2.5.5 の例外（文の中の対象）に当たるので、44×44 CSS px の大きさを求めない。ビューアのほかの操作の大きさは 0050 のまま変えない。

#### F-006: 保存・コピー・ほかの表示を変えない

描画は記事の本文の表示だけを変える。記事の保存とコピーは、描画した結果ではなく、状態の取得が返す文字列を変えずに使う。

**Acceptance Criteria**:
- **AC-30**: 「Markdown をコピー」でクリップボードに書き込まれる文字列は、表示用の Markdown と一致する（[0050](../0050_viewer_tab/01_requirements.md) AC-35 のまま）。`.md` の保存で保存される中身は、ファイルの中身（`article.file`）と一致する（0050 の F-007 のまま）。
- **AC-31**: 処理中・失敗・失われた記事の表示、動画のセクション（見出し・チャンネル名・元動画へのリンク）、操作のボタン、推定の料金と所要時間の表示は、0050 のまま変わらない。
- **AC-32**: 同じ記事の状態の取得の応答が繰り返し届いても、描画した記事は描き直されず、記事の中のフォーカスと選択は保たれる（0050 の今の振る舞い。`extension/src/ui/renderViewer.ts:319-321`、`extension/test/renderViewer.test.ts:705-727`）。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   **AC-33**: 拡張が受け付ける応答の上限（512 KiB）に収まる最大の長さの表示用の Markdown の描画が、1 秒以内に終わる。記号だけの長い行（例: `*`・`` ` ``・`<https://` を数万回繰り返した行）や、閉じない記号の多い入力でも同じである。描画の時間は 1 回の実行の全体（数秒から数十秒）に比べて小さく、上限は、入力の長さの 2 乗に比例して時間がかかる解釈を防ぐためのものである（CLAUDE.md「Performance」）。測る環境は設計で決める（H-01）。

### 4.2. セキュリティ (Security)

本タスクは、信頼できないテキスト（LLM が生成した記事と、記事に入るチャンネル名）をビューアに描画するので、[security.md](../../dev/security.md) を適用する（§6・§8.1）。

-   記事は HTML として解釈しない。DOM は要素の生成と文字列の設定だけで組み立てる（issue #504 の決定）。HTML を解釈する API を lint で禁止していることは変えない（security.md §8.1）。
-   拡張のページの既定の Content Security Policy を緩めない。manifest の権限を加えない（[ADR-0010](../../dev/adr/0010-extension-stores-nothing.md)）。
-   記事の内容から作る要素と属性は F-004 の一覧に限る。リンクは F-003 の条件を満たす `https` の自動リンクだけで、表示する文字列とリンク先が一致し、周りの文字の方向でリンクの文字列の見え方が変わらない（AC-17）。
-   開発者向けのログに記事の値と URL の値を書かない（security.md §8.1「開発者向けのログに値を出さない」のまま）。描画は新しいログを書かない。
-   残余のリスク（許容する）:
    -   記事が `https` の自動リンクで任意のサイトを指すことは防がない。利用者がリンクを押すと、そのサイトが開く。リンクの表示は URL そのもので、参照元とビューアのウィンドウは渡らない。プロンプトは本文に URL を書かせないので、出典の行のほかの自動リンクは、プロンプトインジェクションの結果である疑いが強い。
    -   チャンネル名の行の途中の記法は描画される（1 章の決定）。動画の持ち主は、LLM を介さずに、チャンネル名で自動リンクを作り、強調などで見た目を変えられる。リンクの扱いは上と同じである。
    -   チャンネル名の行の途中で、ASCII の区切り文字の前にある `\` は表示されない（I-1）。そのチャンネル名は、`\` を除いた形で表示される。表示の正確さの限界で、セキュリティの影響はない。行頭の `\` は、サーバがエスケープするので表示される（`internal/publisher/file_render.go:106-109`）。
    -   これらの残余のリスクを security.md §6・§8.1 に書く。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   描画は失敗の結果を持たない。どの文字列を受け取っても、記事を表示する（F-004）。

### 4.4. 互換性 (Compatibility)

-   拡張の最小の Chrome の版（`extension/static/manifest.json:8` の `minimum_chrome_version`）と Brave で動く。新しい権限を要求しない。
-   サーバ・ホスト・応答の形は変えない。保存とコピーの中身は変わらない（F-006）。
-   保存した `.md` を CommonMark のビューアで開いたときの表示は、ビューアの表示と細部が異なりうる（1 章の決定）。

### 4.5. 保守性 (Maintainability)

-   記事の本文を描画する処理は 1 か所にまとめる（0050 の H-14 で `renderArticleBody` に集めた構成を保つ）。ビューアのほかの部分は、記事の文字列を変えずに使う。
-   Markdown のライブラリと新しい npm のパッケージを加えない（CLAUDE.md「Dependencies」）。
-   扱う記法を後で増やすときは、ADR-0017 を更新する。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   拡張が出荷するのはこのリポジトリが書いたコードだけで、Markdown のライブラリは使わない（CLAUDE.md「Dependencies」）。
-   拡張の文字列の規則（CLAUDE.md「Go Idioms」の拡張の項）に従う。描画は利用者に見せる新しい文言を加えない。
-   ユーザーに見せる UI の WCAG 2.2 レベル AA（と、プロジェクトが採る 2.5.5・2.3.3）を満たす（CLAUDE.md「Accessibility」）。動きのある表示は加えないので、2.3.3 は当てはまらない。状態のメッセージ（4.1.3）は、描画が新しい状態の表示を加えないので当てはまらない。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。

-   **ビューア・動画のセクション・見出し:** 用語集のとおり。本書の「見出し」は、単独では用語集の見出し（動画のセクションの先頭の動画タイトル）を指し、描画する Markdown の見出しは「記事のタイトルの見出し」「節の見出し」と書く。
-   **表示用の Markdown:** 状態の取得が返す `article.markdown`。タイトルの行・チャンネル名の行・本文（出典の行を含む）から成る（0050）。
-   **出典の行:** 本文の末尾の、出典リンク（用語集）を持つ行 `出典: <URL>`。
-   **描画:** 表示用の Markdown を、3.2 節の規則で見出し・段落などの要素にして表示すること。
-   **自動リンク:** `<` と `>` で囲んだ URL の記法（I-5）。
-   **URL の文字列:** 自動リンクの `<` と `>` の間の文字列（F-003）。
