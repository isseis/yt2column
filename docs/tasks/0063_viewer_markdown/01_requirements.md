## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張のビューアで、完了した記事の表示用の Markdown を、見出し・段落・リスト・強調などを整えた読みやすい形に描画するための要件を定義する。描画の対象は信頼できないテキストなので、描画してよい要素と属性、リンクにする条件、扱わない記法の表示も、あわせて定める。

**背景:**

今のビューアは、状態の取得が返す表示用の Markdown（`article.markdown`）を、`textContent` でそのまま文字として表示する（`extension/src/ui/articleBody.ts:13-22`）。CSS は行の折り返しと空白を保つだけで（`extension/static/viewer.css` の `.article-body`）、`#` や `**` などの記号も文字として見える。これは、Markdown の描画を本 issue に分けた 0050 の決定による（[0050 要件定義書](../0050_viewer_tab/01_requirements.md) §1・F-005・AC-25）。

表示用の Markdown は、記事のタイトルの見出し（`# <タイトル>`）、チャンネル名の行（チャンネル名があるとき）、本文の順に並ぶ（`internal/publisher/display_render.go:28-36`）。チャンネル名の行は、行頭が Markdown のブロックの記法になる場合だけ、行頭（番号付きリストの記号では数字の後ろ）にバックスラッシュを 1 つ入れてある（`internal/publisher/file_render.go:87-99`）。本文の末尾には、出典の行 `出典: <https://www.youtube.com/watch?v=…>` が付く（`internal/writer/output.go:236-240`）。本文の書き方は生成のプロンプトが指示する。レベル 1 の見出しはタイトルだけ、節はレベル 2 の見出しだけで、`###` 以下は使わない。箇条書きは必要な箇所だけ、対談記事では発言の段落を `**話者の名前**：` で始める。生の HTML は使わず、URL も書かない（`prompts/system.tmpl` §4〜§6）。生の HTML と、閉じていないコードフェンスを含む出力は、生成の段階で拒否している（`internal/writer/errors.go:66-71`）。

記事は LLM の出力であり、字幕と動画メタデータを経由したプロンプトインジェクションで、意図しない HTML やリンクを含みうる（[security.md](../../dev/security.md) §6・§8.1）。ビューアは `nativeMessaging` を呼べる拡張のページなので、記事からスクリプトが動けば、ホストへの任意の送信につながる（security.md §8.1「記事を untrusted テキストとして表示する」）。一方、拡張が出荷するのはこのリポジトリが書いたコードだけで、npm のパッケージは開発用に限るため（[CLAUDE.md](../../../CLAUDE.md)「Dependencies」）、Markdown のライブラリは使えない。

対応 issue: [#504](https://github.com/isseis/yt2column/issues/504)（親: [#501](https://github.com/isseis/yt2column/issues/501)、前提: [#503](https://github.com/isseis/yt2column/issues/503)（`0050_viewer_tab`、完了））

**本書の記述範囲:** 本書は、観測できる振る舞いを定める。どの記法をどの要素に描画するか、描画した要素の文字列、リンクにする条件、扱わない記法の表示、文字組み、アクセシビリティ、ほかの機能への影響である。レンダラーの構成（字句の解析の手段、関数の分け方、データ構造）、CSS の具体的な値、テストの手段は、設計（`02_architecture.md`）で決める。要件のレビューで挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #504 で決めたこと:**

-   **自前の最小限のレンダラーを書く:** 記事が使う Markdown の要素だけを扱う。Markdown のライブラリは使わない。拡張が出荷するのはこのリポジトリが書いたコードだけで、npm のパッケージは開発用に限るためである（CLAUDE.md「Dependencies」）。
-   **生の HTML を描画しない:** DOM は `textContent` と要素の生成で組み立て、`innerHTML` を使わない。記事は信頼できないテキストで、ビューアは権限のあるページだからである。
-   **リンクのスキームを制限する:** `https` だけを許す。
-   **扱わない要素は文字列のまま表示する:** 扱わない記法を、近い要素に直して描画することはしない（CLAUDE.md「Reject, don't normalize」）。
-   **本文の幅は 700〜800px 程度、読みやすい文字の大きさと行間にする。**

**要件定義の際に決めたこと（2026-11-05）:**

-   **扱う要素は、プロンプトが使う要素に限る:** 見出し（`#`・`##`）、段落、箇条書きと番号付きリスト（1 階層）、強い強調と強調、コードスパンとコードブロック、バックスラッシュのエスケープ、自動リンクを扱う。引用・表・水平線・入れ子のリスト・画像・`###` 以下の見出しは、文字のまま表示する（F-004）。プロンプトはこれらの記法を使わないので、扱えば、レンダラーとテストが増えるだけになるためである。ADR の判断: 下の ADR-0016 に含める。
-   **リンクにするのは `https` の自動リンクだけにする:** `<https://…>` の形の自動リンクだけをリンクにする。`[文字](URL)` の形のリンクは文字のまま表示する（F-003・F-004）。プロンプトは URL を書かせない（本文の URL は出典の行だけである）ので、本文の中のリンクはプロンプトインジェクションの疑いが強い。また、`[YouTube](https://悪意の URL)` のように、表示する文字とリンク先が食い違う形も防げる。自動リンクなら、表示する文字は URL そのものになる。ADR の判断: 下の ADR-0016 に含める。
-   **リンクは新しいタブで、参照元を送らずに開く:** ビューアの元動画へのリンクと同じ扱いにする（`extension/static/viewer.html:13`）。ビューアのタブが記事の表示のまま残り、遷移先のページは参照元とビューアのウィンドウを得られない。ADR の判断: 下の ADR-0016 に含める。
-   **記事の見出しを 1 段下げる:** 記事のタイトル（`#`）をレベル 2、節（`##`）をレベル 3 の見出しにする（F-001）。ビューアには動画タイトルのレベル 1 の見出しがすでにあり（`extension/static/viewer.html:11`）、ページの見出しの構造を 1 本に保つためである（WCAG 1.3.1）。ADR の判断: 作らない。ビューアの 1 つの画面の構造の決定で、このタスクの中で閉じる。
-   **記法の解釈は、本書で定める単純な規則による:** CommonMark の解釈には合わせず、3.2 節の規則に従う。例えば、強調は 1 行の中の対になった記号だけで、入れ子にしない。規則に合わないものは文字のまま表示する。記事はプロンプトが決めた単純な形をしており、CommonMark に合わせても実用上の差は小さい。強調の区切りの規則まで実装するとレンダラーとテストが大きくなるので、小さく保つことを選んだ。そのため、保存した `.md` を CommonMark のビューアで開くと、ビューアの表示と細部が異なりうる（例えば段落の中の改行）。これは受け入れる。ADR の判断: 下の ADR-0016 に含める。
-   **文字組みの範囲を要件で定める:** 本文の 1 行の最大の幅を 700〜800 CSS px、本文の文字の大きさをブラウザの既定（16 CSS px）以上、行間を文字の大きさの 1.7〜2.0 倍とする（F-005）。具体的な値は設計で決める。日本語の長文に読みやすい範囲である。ADR の判断: 作らない。CSS の値はこのタスクの中で閉じる。
-   **記事の部分の言語を日本語と示す:** 描画した記事の要素の言語を日本語（`ja`）とする（F-005）。ページの `lang` は UI の表示言語なので（`extension/src/ui/pageLocale.ts`）、英語の UI では記事の部分の言語がページと食い違う。記事は、プロンプトの指示で素材の言語によらず日本語で書かれる（`prompts/system.tmpl` §4）。WCAG 3.1.2（レベル AA）を満たすためである。プロンプトを書き換えて日本語以外の記事を作った場合は誤りになるが、記事の言語はプロンプトが決めるものとして受け入れる。ADR の判断: 作らない。このタスクの中で閉じる。
-   **ADR:** 描画の安全性の規則（HTML を解釈しない、扱う要素を限る、`https` の自動リンクだけをリンクにし、新しいタブで参照元を送らずに開く、記法を単純な規則で解釈する）を、新しい [ADR-0016](../../dev/adr/0016-viewer-markdown-rendering.md)（ビューアは記事を自前の最小限のレンダラーで描画し、HTML を解釈せず、リンクは https の自動リンクだけにする）に記録する。拡張のセキュリティの前提（security.md §8.1）を変え、このレンダラーを後で変えるタスクを縛るためである。

**方針の変更:**

-   [security.md](../../dev/security.md) §8.1「記事を untrusted テキストとして表示する」は、ビューアが記事を `textContent` だけで文字として表示し、Markdown を解釈せず、記事の中のリンクもリンクにしないとしている（0050 の決定）。本タスクは、本書の規則で Markdown を描画し、`https` の自動リンクをリンクにする（F-001〜F-003）。理由は、記事を読みやすく表示することが issue の目的そのものだからである。HTML を解釈しないこと、HTML を解釈する API を lint で禁止すること、拡張のページの既定の Content Security Policy を緩めないことは変えない。同じ項の残余のリスク（記事の中の URL の文字列を利用者がコピーして開くこと）も、リンクを押して開ける形に書き換える。security.md §8.2「返す記事は untrusted なテキスト」の「Markdown の描画の安全性は #504 で扱う」も、本書の規則を指す形に直す。
-   0050 の AC-25（記事の中の HTML のタグや Markdown のリンクを文字として表示し、表示した文字列は表示用の Markdown と一致する）と、0050 §4.2 の「記事の中のリンクは、本タスクではリンクにしない」は、本書の F-001〜F-004 で置き換える。HTML のタグを文字として表示することは F-004 で保ち、表示した文字列は、F-001・F-002 で除く記号とエスケープの文字を除いて、表示用の Markdown と一致する。
-   [CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」は、呼び出し側が渡した文字列の中身を調べて処理を選ぶことを禁じ、例外を列挙している。レンダラーは表示用の Markdown の中身を調べて描画する要素を選ぶので、この方針の例外になる。理由は、表示用の Markdown が LLM の出力で、拡張が型で表せない外部の値だからであり、Markdown を描画すること自体が issue の目的だからである（issue #504 の決定から導かれる）。範囲は、記事の本文を描画するレンダラーが 3.2 節の規則で表示用の Markdown を解釈することだけに限る。どの規則にも合わない入力は広く解釈せず、文字のまま表示する。CLAUDE.md の例外の一覧に、範囲・理由・境界を書き加える（H-08）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   ビューアで、記事を見出し・段落・リスト・強調を整えた読みやすい形で表示する。
-   信頼できない記事から、スクリプト・生の HTML・利用者を欺くリンクを作らない。
-   扱わない記法と規則に合わない記法を、文字を失わずにそのまま表示する。
-   描画の後も、記事の保存とコピーの中身を変えない。

### 2.2. スコープ (In Scope)

-   ビューアの記事の本文の描画（F-001〜F-004）。
-   本文の文字組みとアクセシビリティ（F-005）。
-   描画の後も保存・コピーを変えないこと（F-006）。
-   方針の変更に伴う文書の更新: `docs/dev/security.md` §8.1・§8.2、ADR-0016 とその索引、`CLAUDE.md`「Declare, don't infer」の例外、README の記事の表示の説明（`README.md:630`。`README.en.md` は `/mktrans` で同期する）。

### 2.3. スコープ外 (Out of Scope)

-   引用・表・水平線・入れ子のリスト・画像・`###` 以下の見出し・セテキストの見出し・インデントのコードブロック・取り消し線などの描画: プロンプトが使わない記法なので扱わない（1 章の決定）。文字のまま表示する（F-004）。
-   `[文字](URL)` の形のリンク・参照のリンク・`http` などの `https` 以外のスキームのリンク: リンクにしない（1 章の決定）。
-   HTML の文字参照（`&amp;` など）の解釈: 文字のまま表示する（F-004）。プロンプトは文字参照を使わず、解釈すると表示する文字が元の文字と変わるためである。
-   CommonMark との完全な互換: 本書の規則で解釈する（1 章の決定）。
-   ポップアップの表示: ポップアップは記事の本文を表示しない（0050 の範囲）。
-   Slack への投稿の整形と `.md` のファイルの中身: Go の実装のまま変えない（issue #501 の決定。F-006）。
-   生成のプロンプトの変更: 記事が使う記法は今のプロンプトのままとする。
-   記事の中の URL を開く前の確認の画面: リンクの表示が URL そのものなので設けない（1 章の決定）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 描画の対象

描画の対象は、ビューアが完了した記事を表示するときの表示用の Markdown（`article.markdown`）である。状態の取得の応答の検査（[0050 要件定義書](../0050_viewer_tab/01_requirements.md) §4.2 の表）を通った、空でない文字列だけが届く。それ以外の場面（処理中・失敗・失われた記事）の表示は、0050 のまま変えない。ファイルの中身（`article.file`）は描画しない。

### 3.2. 記法の規則

レンダラーは、次の規則だけで表示用の Markdown を解釈する。この規則が決めない場合（例えば `*` が 3 つ以上並ぶ並び）の扱いは設計で決める（H-03）。その場合も、扱う要素と属性（F-004）の範囲を出ず、入力の文字を失わず、順序を変えない。

**行:** 表示用の Markdown を LF（U+000A）で行に分ける。CR（U+000D）は改行として扱わず、文字として扱う。ブロックの記法は、行の先頭の文字から判定する。行頭に空白がある行は、どのブロックの記法にも当たらない（段落の行か、項目の継続の行になる）。

**ブロックの規則:**

-   **B-1 空行:** 空か、空白（U+0020）とタブだけの行。ブロックを区切り、それ自体は何も表示しない。
-   **B-2 見出し:** `# ` で始まる行は記事のタイトルの見出し、`## ` で始まる行は節の見出しである。記号と、その後ろに続く空白とタブを除いた残りが見出しの文字列で、インラインの規則を当てはめる。残りが空なら見出しではなく、段落の行になる。`#` が 3 つ以上の行、`#` の直後に空白のない行は、見出しではない。見出しは 1 行で終わる。
-   **B-3 コードブロック:** `` ` `` か `~` が 3 つ以上並んで始まる行は、コードブロックを開く。並びの後ろの文字列（情報文字列）は表示しない。開いた行の後で、同じ文字が開いた並びと同じ数以上並び、その後ろが空白だけの行で閉じる。間の行は、インラインの規則を当てはめず、改行と空白を保って等幅で表示する。閉じる行がないときは、開いた行はコードブロックを開かず、その行と以降の行を、ほかの規則で解釈する。
-   **B-4 箇条書き:** `- `・`* `・`+ ` のいずれかで始まる行は、箇条書きの項目である。記号と直後の空白 1 つを除いた残りが項目の文字列で、インラインの規則を当てはめる。同じ記号の項目が続く間（間に空行があってもよい）は 1 つのリストになり、記号が変わると新しいリストになる。
-   **B-5 番号付きリスト:** 1〜9 桁の数字、`.` か `)`、空白 1 つの順で始まる行は、番号付きリストの項目である。それらを除いた残りが項目の文字列で、インラインの規則を当てはめる。同じ区切りの文字（`.` か `)`）の項目が続く間（間に空行があってもよい）は 1 つのリストになる。リストの番号は、最初の項目の数の値から 1 ずつ増やして表示する。
-   **B-6 項目の継続:** 項目の行の直後（間に空行がない）の行が、空行でもなく、見出し・コードブロック・項目の行でもないとき、その行は直前の項目の続きで、項目の中に改行を入れて表示する。行頭の空白で入れ子のリストを書いた行も、この規則で項目の続きの文字になる。
-   **B-7 段落:** ほかの規則に当たらない行は段落の行である。続いている段落の行は 1 つの段落になり、行の間の改行は段落の中の改行として表示する。段落は、空行と、見出し・コードブロック・項目の行で終わる。

**インラインの規則:** 見出し・項目・段落の文字列に、行ごとに当てはめる。どの規則も行をまたがない。

-   **I-1 エスケープ:** `\` の直後の文字が ASCII の区切り文字（`!"#$%&'()*+,-./:;<=>?@[\]^_` と `` ` ``・`{|}~`）なら、`\` を表示せず、その文字を記法の記号として扱わずに文字として表示する。それ以外の `\` は文字として表示する。行頭の `\` はブロックの記号ではないので、`\#` や `\-` で始まる行は段落の行になり、`1\.` で始まる行も番号付きリストの項目にならない。
-   **I-2 コードスパン:** `` ` `` が n 個並んだところで開き、同じ行の中で次に `` ` `` がちょうど n 個並んだところで閉じる。間の文字列を、ほかの規則を当てはめずに等幅で表示する。閉じる並びがなければ、`` ` `` を文字として表示する。
-   **I-3 強い強調:** `**` の直後が空白でないところで開き、同じ行の中で、直前が空白でない最も近い `**` で閉じる。間の文字列を強い強調として表示する。閉じる記号がなければ、`**` を文字として表示する。
-   **I-4 強調:** `*` 1 つの直後が空白でないところで開き、同じ行の中で、直前が空白でない最も近い `*` で閉じる。間の文字列を強調として表示する。閉じる記号がなければ、`*` を文字として表示する。`_` は強調の記号として扱わない。
-   **I-5 自動リンク:** `<https://` で始まり、同じ行の中の最も近い `>` で終わる並びで、間に空白・制御文字・`<` を含まないもの。F-003 の条件を満たすときだけリンクとして描画し、満たさないときは `<` と `>` を含めて文字として表示する。
-   **入れ子:** 強い強調と強調の中では、I-1 だけを当てはめ、ほかの規則（コードスパン・強調・自動リンク）は当てはめない。コードスパンと自動リンクの中では、どの規則も当てはめない。

### 3.3. 機能一覧

#### F-001: ブロックの描画

ビューアは、完了した記事の表示用の Markdown を、3.2 節のブロックの規則に従って、見出し・段落・リスト・コードブロックに描画する。

-   記事のタイトルの見出し（B-2 の `#`）はレベル 2、節の見出し（B-2 の `##`）はレベル 3 の見出しとして描画する（1 章の決定）。
-   描画した各ブロックの文字列は、そのブロックの行から、ブロックの記号（B-2・B-4・B-5 で除く部分）と、インラインの規則で表示しない文字（F-002）を除いたものと一致する。

**Acceptance Criteria**:
- **AC-01**: `# <タイトル>` の行はレベル 2 の見出し、`## <節の見出し>` の行はレベル 3 の見出しとして描画され、見出しの文字列は記号と直後の空白を除いた残りと一致する。`### x`・`#x`・`#` だけの行・`# ` の後ろが空白だけの行は、見出しにならず、段落の文字として表示される。
- **AC-02**: 空行で区切られた行のまとまりは、それぞれ 1 つの段落として描画される。段落の中の行の間の改行は、改行として表示される。
- **AC-03**: `- `・`* `・`+ ` で始まる項目の並びは箇条書きとして描画される。同じ記号の項目は、間に空行があっても 1 つのリストになり、記号が変わると別のリストになる。
- **AC-04**: `1. ` や `3) ` のように始まる項目の並びは、番号付きリストとして描画される。番号は最初の項目の数の値から 1 ずつ増えて表示され、区切りの文字が変わると別のリストになる。10 桁以上の数字で始まる行は項目にならない。
- **AC-05**: 項目の行の直後の、ブロックの記法に当たらない行は、その項目の続きとして項目の中に改行を入れて表示される。行頭の空白で書いた入れ子のリストの行（例: `  - 子`）も、入れ子のリストにならず、親の項目の続きの文字として表示される。
- **AC-06**: 閉じたコードフェンスの間の行は、改行と空白を保ったまま等幅で表示され、間の `**`・`#`・`<https://…>` などは描画されずに文字として表示される。情報文字列は表示されない。閉じる行のないフェンスは、開いた行を含めてほかの規則で解釈される。
- **AC-07**: 表示用の Markdown の形（`# タイトル`、チャンネル名の行、本文、出典の行）をそのまま描画すると、タイトルはレベル 2 の見出し、チャンネル名の行は段落になる。チャンネル名の行の頭のエスケープ（例: `\- 名前`、`1\. 名前`）はバックスラッシュを表示せず、チャンネル名のとおりに表示される（I-1）。

#### F-002: インラインの描画

ビューアは、見出し・項目・段落の文字列に、3.2 節のインラインの規則を当てはめて描画する。

**Acceptance Criteria**:
- **AC-08**: 1 行の中の `**話者**：` は、`話者` が強い強調として描画され、`**` は表示されない。1 行の中の `*語*` は、`語` が強調として描画される。行をまたぐ記号の対、閉じる記号のない記号、開く記号の直後か閉じる記号の直前が空白の記号は、強調にならず、記号が文字として表示される。`_語_` は強調にならない。
- **AC-09**: `` `x` `` は等幅のコードスパンとして描画され、中の `**` や `<https://…>` は文字として表示される。閉じる並びのない `` ` `` は文字として表示される。
- **AC-10**: `\*`・`\#`・`\<`・`` \` `` などの ASCII の区切り文字の前の `\` は表示されず、その文字は記法の記号として働かない。ASCII の区切り文字ではない文字の前の `\`（例: `\あ`、行末の `\`）は文字として表示される。
- **AC-11**: 強い強調と強調の中のコードスパン・強調・自動リンクの記号は、描画されずに文字として表示される。強調の中のエスケープ（I-1）は働く。
- **AC-12**: 描画した見出し・項目・段落の文字列は、元の文字列から、強い強調・強調・コードスパンの記号と、I-1 で表示しない `\` を除いたものと一致し、文字の順序は元のままである。

#### F-003: リンク

ビューアは、自動リンク（I-5）のうち、次の条件をすべて満たすものだけをリンクとして描画する。

-   `<` と `>` の間の文字列（以下、URL の文字列）を URL として解釈できる。
-   スキームが `https` で、URL の文字列は小文字の `https://` で始まる。
-   ホストが空でなく、ユーザー名もパスワードも持たない。
-   URL の文字列が、URL として解釈して文字列に戻したものと 1 文字も違わない。解釈で文字列が変わる URL（大文字のスキーム、`\` を含むパス、全角のホスト名、エンコードが必要な文字など）をリンクにすると、表示する文字列とリンク先が食い違うので、リンクにせず文字として表示する（CLAUDE.md「Reject, don't normalize」）。

リンクの表示する文字列とリンク先は、どちらも URL の文字列とする。リンクを押すと、リンク先を新しいタブで、参照元を送らず、開いたページがビューアのウィンドウを得られない形で開く（1 章の決定）。

**Acceptance Criteria**:
- **AC-13**: 出典の行 `出典: <https://www.youtube.com/watch?v=abcdefghijk>` は、`出典: ` に続くリンクとして描画され、リンクの文字列とリンク先は `https://www.youtube.com/watch?v=abcdefghijk` に一致する。`<` と `>` は表示されない。
- **AC-14**: 次の自動リンクの形は、いずれもリンクにならず、`<` と `>` を含めて文字として表示される: `<http://example.com>`、`<HTTPS://example.com>`、`<javascript:alert(1)>`、`<https://>`、`<https://user:pass@example.com>`、`<https://example.com\path>`、`<https://ｅxample.com>`（全角の文字を含むホスト名）、`<https://example.com/a b>`、`<https://example.com/<x>`。例は網羅を主張しない。
- **AC-15**: `[文字](https://example.com)` と `[文字][ref]`、`![画像](https://example.com/a.png)` は、リンクにも画像にもならず、文字として表示される。
- **AC-16**: リンクを押すと、リンク先は新しいタブで開き、ビューアのタブは記事の表示のまま残る。リンクの要素は、参照元を送らず、開いたページに `window.opener` を与えない属性（`rel="noopener noreferrer"`）を持つ。

#### F-004: 扱わない記法と HTML

ビューアは、3.2 節の規則に当たらない記法と HTML を、要素に描画せずに文字として表示する。描画した記事の中の要素と属性は、次のものに限る。

-   要素: 見出し（レベル 2 と 3）、段落、箇条書き、番号付きリスト、項目、強い強調、強調、コードスパン、コードブロック、リンク、改行、と、これらを入れる要素。
-   記事の内容から値を決める属性: リンクのリンク先（F-003 の条件を満たした URL の文字列）と、番号付きリストの開始番号（B-5 の数の値）だけ。属性の名前を記事の内容から決めることはない。

**Acceptance Criteria**:
- **AC-17**: `<img src=x onerror=alert(1)>`、`<a href="javascript:alert(1)">x</a>`、`<script>alert(1)</script>`、`<!-- x -->`、`<div>` を含む行は、どの要素も属性も作らず、タグを含めて文字として表示され、スクリプトは動かない。
- **AC-18**: `> 引用`、`| a | b |` の表、`---`・`***`・`___` の水平線、`### 見出し`、4 つの空白で始まる行、`見出し` の次の行の `===`・`---`（セテキストの見出し）、`~~取り消し~~`、`&amp;`・`&#60;` の文字参照は、いずれも描画されず、記号を含めて文字として表示される。文字参照は解釈されず、`&amp;` は `&amp;` のまま表示される。
- **AC-19**: どのような入力（AC-17・AC-18 の形、ランダムな文字列を含む）を描画しても、記事の中に作られる要素は上の一覧の種類だけで、属性はリンクのリンク先・新しいタブの指定・`rel`、番号付きリストの開始番号、と記事の内容によらない固定の属性だけである。
- **AC-20**: 描画した記事の文字列（記事の要素の文字列を順につなげたもの）は、表示用の Markdown から、F-001・F-002・F-003 が除く記号・空白・エスケープの `\`・情報文字列・コードフェンスの行を除いたものと一致し、それ以外の文字を失わず、順序を変えない。

#### F-005: 文字組みとアクセシビリティ

ビューアは、描画した記事を、日本語の長文に読みやすい文字組みで表示し、[CLAUDE.md](../../../CLAUDE.md)「Accessibility」の基準を満たす。

**Acceptance Criteria**:
- **AC-21**: タブの幅が 900 CSS px 以上のとき、記事の段落の 1 行の幅は 700〜800 CSS px の範囲の最大の幅で止まる。タブの幅が 320 CSS px のとき、記事はページの横のスクロールなしに収まる（コードブロックの長い行は、コードブロックの中で折り返すか、ブロックの中だけで横にスクロールする）。
- **AC-22**: 段落と項目の文字の大きさは 16 CSS px 以上で、行の高さは文字の大きさの 1.7〜2.0 倍である。
- **AC-23**: 描画した記事を入れる要素は `lang="ja"` を持つ。ページの `lang` は今までどおり UI の表示言語である。
- **AC-24**: 記事の見出しは、ページの見出しの構造で、動画タイトルのレベル 1 の見出しの下に、記事のタイトル（レベル 2）、節（レベル 3）の順に並ぶ。
- **AC-25**: 記事の中のリンクは、ポインティングデバイスなしで、Tab と Shift+Tab で表示の順に移動でき、Enter で開ける。フォーカスしたリンクは、隣の色と 3:1 以上のコントラストの印で見える。リンクの名前は表示している URL の文字列である。
- **AC-26**: リンクは色だけでなく下線でも本文と区別できる。リンク・コードスパン・コードブロックの文字と背景のコントラストは、明るいテーマと暗いテーマの両方で 4.5:1 以上である。
- **AC-27**: 1 つのブロックの中の双方向の制御文字や右から左に書く文字は、ほかのブロックの表示の順序を変えない。各ブロックの文字の方向は、そのブロックの文字から決まる。
- **AC-28**: 記事の中のリンクは文の中のリンクで、WCAG 2.5.5 の例外（文の中の対象）に当たるので、44×44 CSS px の大きさを求めない。ビューアのほかの操作の大きさは 0050 のまま変えない。

#### F-006: 保存・コピー・ほかの表示を変えない

描画は記事の本文の表示だけを変える。記事の保存とコピーは、描画した結果ではなく、状態の取得が返す文字列を変えずに使う。

**Acceptance Criteria**:
- **AC-29**: 「Markdown をコピー」でクリップボードに書き込まれる文字列は、表示用の Markdown と一致する（[0050](../0050_viewer_tab/01_requirements.md) AC-35 のまま）。`.md` の保存で保存される中身は、ファイルの中身（`article.file`）と一致する（0050 の F-007 のまま）。
- **AC-30**: 処理中・失敗・失われた記事の表示、記事のヘッダー（動画タイトル・チャンネル名・元動画へのリンク）、操作のボタン、推定の料金と所要時間の表示は、0050 のまま変わらない。
- **AC-31**: 同じ記事の状態の取得の応答が繰り返し届いても、描画した記事は描き直されず、記事の中のフォーカスと選択は保たれる（0050 の今の振る舞い。`extension/test/renderViewer.test.ts:711-724`）。

### 3.4. 信頼できない入力の境界

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   **AC-32**: 拡張が受け付ける応答の上限（512 KiB）に収まる最大の長さの表示用の Markdown を描画しても、開発機の node のテストで 1 秒以内に終わる。記号だけの長い行（例: `*`・`` ` ``・`<https://` を数万回繰り返した行）や、閉じない記号の多い入力でも同じである。描画の時間は 1 回の実行の全体（数秒から数十秒）に比べて小さく、上限は、入力の長さの 2 乗で時間がかかる解釈を防ぐためのものである（CLAUDE.md「Performance」）。

### 4.2. セキュリティ (Security)

本タスクは、信頼できないテキスト（LLM が生成した記事）をビューアに描画するので、[security.md](../../dev/security.md) を適用する（§6・§8.1）。

-   記事は HTML として解釈しない。DOM は要素の生成と文字列の設定だけで組み立てる（issue #504 の決定）。HTML を解釈する API を lint で禁止していることは変えない（security.md §8.1）。
-   拡張のページの既定の Content Security Policy を緩めない。manifest の権限を加えない（[ADR-0010](../../dev/adr/0010-extension-stores-nothing.md)）。
-   記事の内容から作る要素と属性は F-004 の一覧に限る。リンクは F-003 の条件を満たす `https` の自動リンクだけで、表示する文字列とリンク先が一致する。
-   開発者向けのログに記事の値と URL の値を書かない（security.md §8.1「開発者向けのログに値を出さない」のまま）。描画は新しいログを書かない。
-   残余のリスク（許容する）: 記事が `https` の自動リンクで任意のサイトを指すことは防がない。利用者がリンクを押すと、そのサイトが開く。リンクの表示は URL そのもので、参照元とビューアのウィンドウは渡らない。プロンプトは本文に URL を書かせないので、出典の行のほかの自動リンクは、プロンプトインジェクションの結果である疑いが強い。この残余のリスクを security.md §8.1 に書く。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   描画は失敗の結果を持たない。どの文字列を受け取っても、記事を表示する（F-004）。

### 4.4. 互換性 (Compatibility)

-   拡張の最小の Chrome の版（`minimum_chrome_version`。`extension/static/manifest.json`）と Brave で動く。新しい権限を要求しない。
-   サーバ・ホスト・応答の形は変えない。保存とコピーの中身は変わらない（F-006）。
-   保存した `.md` を CommonMark のビューアで開いたときの表示は、ビューアの表示と細部が異なりうる（1 章の決定）。

### 4.5. 保守性 (Maintainability)

-   記事の本文を描画する処理は 1 か所にまとめる（0050 の H-14 で `renderArticleBody` に集めた構成を保つ）。ビューアのほかの部分は、記事の文字列を変えずに使う。
-   Markdown のライブラリと新しい npm のパッケージを加えない（CLAUDE.md「Dependencies」）。
-   扱う記法を後で増やすときは、ADR-0016 を更新する。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   拡張が出荷するのはこのリポジトリが書いたコードだけで、Markdown のライブラリは使わない（CLAUDE.md「Dependencies」）。
-   拡張の文字列の規則（CLAUDE.md「Go Idioms」の拡張の項）に従う。描画は利用者に見せる新しい文言を加えない。
-   ユーザーに見せる UI の WCAG 2.2 レベル AA（と、プロジェクトが採る 2.5.5・2.3.3）を満たす（CLAUDE.md「Accessibility」）。動きのある表示は加えないので、2.3.3 は当てはまらない。状態のメッセージ（4.1.3）は、描画が新しい状態の表示を加えないので当てはまらない。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。

-   **ビューア:** 記事の状態と記事を表示する拡張のページ（`viewer.html`）。用語集のとおり。
-   **表示用の Markdown:** 状態の取得が返す `article.markdown`。見出し・チャンネル名の行・本文（出典の行を含む）から成る（0050）。
-   **描画:** 表示用の Markdown を、3.2 節の規則で見出し・段落などの要素にして表示すること。
-   **自動リンク:** `<` と `>` で囲んだ URL の記法（I-5）。
-   **URL の文字列:** 自動リンクの `<` と `>` の間の文字列（F-003）。
