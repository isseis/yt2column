# 設計への申し送り：ビューアで記事の Markdown を描画する

要件定義（[01_requirements.md](01_requirements.md)）の作成とレビューで挙がった、設計で決める事項を記録する。`02_architecture.md` は、各項目の扱い（採った方式、または当てはまらない理由）を記録する。

## H-01: 解釈の時間が入力の長さの 2 乗にならないこと

AC-33 は、512 KiB の入力を 1 秒以内に描画することを求める。閉じる記号を開く記号ごとに行の終わりまで探す実装は、閉じない記号の多い行（例: `**a` の繰り返し）で 2 乗の時間になる。行ごとに閉じる位置を決める走査など、時間が入力の長さにほぼ比例する方式を選ぶ。測る環境（node のテストか、ブラウザか）と、病的な入力の作り方を決める。512 KiB の入力は十数万の要素を作りうるので、node のテストの時間がブラウザでの配置の時間を表さないことにも注意し、ブラウザで一度測るかを決める。

## H-02: URL の解釈と、文字列に戻したものの比較

F-003 は、URL の文字列が、URL Standard の直列化と 1 文字も違わないことを求める。`new URL()` と `href` を使う場合、node のテストとブラウザ（Chrome・Brave）で解釈と直列化が同じであることを確かめる。出典の URL（`https://www.youtube.com/watch?v=<動画 ID>`。`internal/transcript/video_id.go:68`）が一致することを、テストで確かめる。

## H-03: インラインの規則の走査の実装

3.2 節は、走査の順序（I-1・I-2・I-5・I-3・I-4）、記号の並びの扱い、開けなかった並びの扱いまで決めている。設計は規則に場合を足さず、1 つの走査で規則をそのまま実装する。AC の例（`**a \** b**`・`*a**b*`・`***語***` など）に加えて、`\**a**`・`**a\***` など、規則の境目の入力をテストで固定する。

## H-04: 要素と属性の一覧の確かめ方

AC-20 は、どの入力でも、作る要素と属性が一覧の範囲に収まることを求める。描画した DOM を走査して、要素の名前と属性の名前を一覧と比べるテストを、AC-18・AC-19 の形とランダムな入力（性質のテスト）で行う方式を検討する。テストの環境（node のテストの DOM の代わり）で、要素と属性を数えられるかも確かめる。

## H-05: 描き直しの判定

今のビューアは、記事の要素の `textContent` と表示用の Markdown を比べて、違うときだけ描き直す（`extension/src/ui/renderViewer.ts:319-321`）。描画した後の `textContent` は表示用の Markdown と一致しない（記号を除くため）ので、この比較のままでは毎回描き直し、AC-32（フォーカスと選択を保つ）を満たせない。描いた表示用の Markdown を覚えて比べるなど、比較の方式を設計で決める。0050 の `extension/test/renderViewer.test.ts:705-727` のテストも、これに合わせて直す。

## H-06: 文字組みの値とコードブロックのはみ出し

AC-22・AC-23 の範囲の中で、本文の最大の幅、文字の大きさ、行の高さ、見出し・リスト・コードブロックの余白の値を決める。今のページは `body` の `max-width: 48rem` で、本文に枠と内側の余白がある（`extension/static/viewer.css`）。本文の行の幅が 700〜800 CSS px に入るように、ページの幅と本文の余白をあわせて決める。コードブロックの長い行を折り返すか、ブロックの中で横にスクロールするかも決める（後者の場合は、AC-22 のとおりキーボードでスクロールできるようにする）。明るいテーマと暗いテーマのコントラスト（AC-27）は `extension/static/theme.css` の色の変数で確かめる。

## H-07: 双方向の文字の扱い

今の本文は `dir="auto"` と CSS の `unicode-bidi: plaintext` で、行ごとに文字の方向を決めている（`extension/src/ui/articleBody.ts:19`、`extension/static/viewer.css:53-62`）。段落と項目の中の行を改行の要素でつなぐと、行ごとの分離が保たれるかを確かめ、AC-28 を満たす方式を決める。リンクの文字列を周りの文字の方向から分離し、左から右に表示する方式（AC-17）も決める。分離のために F-004 の一覧にない要素や属性（行を包む要素、`dir` など）が要る場合は、記事の内容によらない固定の要素と属性として F-004 の一覧に加え、要件定義書と ADR-0016 を直す（AC-20 で確かめられるように、一覧を閉じた集合に保つ）。

## H-08: CLAUDE.md「Declare, don't infer」の例外の文

要件 1 章「方針の変更」のとおり、レンダラーは表示用の Markdown の中身を調べて描画する要素を選ぶ。CLAUDE.md の例外の一覧に、ほかの例外（`resolveLocale` など）と同じ形で、範囲（レンダラーの関数の名前とファイル）・理由・境界を書き加える。CLAUDE.md は英語で書く。
