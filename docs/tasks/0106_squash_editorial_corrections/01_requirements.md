## 1. 概要 (Overview)

**目的:** 本書は、PR のブランチのコミットにある編集上の訂正の行を、`/mergepr` が書く squash の本文に引き継ぐための要件を定義する。対象は、タスク文書と ADR の両方の訂正の行である。

**背景:**

本書で使う「訂正の行」「引き継ぐ範囲」「受け付けない文字」「squash の本文」「承認の質問」は、3 章の冒頭で定義する。

編集上の訂正は、ブランチのコミットメッセージの訂正の行と、PR の説明の訂正の段落に記録する（`docs/dev/conventions/requirements_process.md:438-482`「Recording in the PR description」、`docs/dev/conventions/adr.md:307-314`「Editorial corrections」の「Recording」）。訂正の行は、タスク文書と ADR で同じ形である（タスク 0074、`docs/tasks/0074_adr_editorial_correction/01_requirements.md`）。ADR の訂正は「経緯」に項目を残さず、タスク文書の訂正は状態表にも変更履歴にも残らない（[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md)、[ADR-0036](../../dev/adr/0036-task-document-status-records.md)）。

このリポジトリは、すべての PR を squash マージする（`.claude/commands/_context.md:53`「PR merge method」）。squash マージの後は、ブランチのコミットが `main` からたどれなくなる。このため、文書がいつ、なぜ直されたかは、squash の件名の PR 番号から開く PR の説明でしか分からない。PR の説明はリポジトリの外にあり、書き換えられる。本書の PR の前の ADR-0039 の「結果」は、squash の本文に訂正の行を引き継がないこと、引き継ぐかどうかは本 issue で扱うことを述べていた。

今の `/mergepr` の手順は、訂正の行を扱っていない。

-   `mergepr prepare` は、PR のコミットのメッセージを `log.txt` に書く（`internal/mergepr/mergepr.go:250`）。
-   `/mergepr` の step 2 は、squash の本文を 10 行程度に抑えるよう求める。その例外は、`CLAUDE.md` がコミットメッセージに求める記録（壊して確かめた記録、最適化の義務、依存の追加の理由、テストの削除のカバレッジ）を 1 行ずつ運ぶことだけである（`.claude/commands/mergepr.md:104-131`）。訂正の行は例外に入っていない。
-   squash の件名には、印字できる ASCII だけからなる 1 行であることの確かめがある（`.claude/commands/_context.md:222`「Checking a squash subject」）。本文にはない。

`main` の squash コミットのうち 9 件（#657・#685・#697・#751・#766・#808・#824・#872・#976）は、本文に訂正の行を計 11 行持つ。手順にない判断でエージェントが運んだもので、運ぶかどうかは PR によって違う。#872 の行の 1 つは途中で折り返されていて、`removed the note that` で切れている。今は、運ばれることはあっても、それが保証されていない。

**通常の進め方を取る理由:** この変更は、ADR-0039 と ADR-0036 の決定を変える。また、`/mergepr` が PR の材料（コミットメッセージ）を `main` の履歴へ写す経路を加える。これは開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）に触れるおそれがあり、迷うときは除外と判断する規則に従った（`docs/dev/conventions/requirements_process.md`「Simple Process」の「Excluded changes」）。人は、通常の進め方を選んだ（「要件定義の際に決めたこと」の 1 つ目の項目）。

対応 issue: [#747](https://github.com/isseis/yt2column/issues/747)（前提: [#732](https://github.com/isseis/yt2column/issues/732)、タスク 0074。関連: [#728](https://github.com/isseis/yt2column/issues/728)、タスク 0070、[ADR-0036](../../dev/adr/0036-task-document-status-records.md)（タスク文書の状態と訂正の記録）、[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md)（ADR の書き方と、決定を変えない編集上の訂正））

**本書の記述範囲:** 本書は、squash の本文に何がどの順で入るか、何のときに止まるか、人が承認の質問で何を変えられるかを、観測できる振る舞いとして定める。訂正の行を取り出して確かめるのを `mergepr` のツールにするかエージェントの手順にするか、`mergepr.md` と関係する文書の英語の文面、文書のテストの変え方は、`02_architecture.md` で決める（[design_handoff.md](design_handoff.md)）。

**issue #747 で決めたこと:**

-   **#732 が `main` に入った後に着手する:** タスク 0074 で、訂正の行の形がタスク文書と ADR で同じになった（#766）。ADR：なし。作業の順序の決定で、本タスクの中で閉じる。
-   **タスク文書の訂正の行も同じに扱うかを決める:** 本書の「要件定義の際に決めたこと」の 2 つ目の項目で決めた。ADR：同項目による。

**要件定義の際に決めたこと（2026-11-19）:**

-   **通常の進め方を取る:** 3 文書を、別々の PR で作る。
    -   **理由:** 上の「通常の進め方を取る理由」のとおり、既存の 2 つの ADR の決定を変える。また、`mergepr` の信頼の境界に触れるおそれがあり、除外と判断した。
    -   **採らなかった案:** 除外の判断を覆して簡易な進め方を取る案は、信頼の境界の判断を設計の前に固めることになるので採らない。
    -   ADR：なし。本タスクの進め方の決定で、本タスクの中で閉じる。
-   **タスク文書と ADR の両方の訂正の行を、squash の本文に引き継ぐ（F-001）:** 引き継ぐ範囲のコミットにある訂正の行は、どの文書のパスを持つかを問わずに引き継ぐ。
    -   **理由:** 訂正の行の形は、タスク文書と ADR で同じである。片方だけを引き継ぐと、ADR-0036 と ADR-0039 で記録の置き場所が分かれる。引き継げば、訂正の記録が `main` の履歴に残り、書き換えられる PR の説明に頼らずに済む。
    -   **採らなかった案:** ADR の行だけを引き継ぐ案は、タスク文書の訂正だけが PR の説明に頼ったまま残るので採らない。引き継がずに理由を ADR-0039 に記録する案は、訂正の記録がリポジトリの外にしか残らない今の問題が残るので採らない。
    -   ADR：[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md) と [ADR-0036](../../dev/adr/0036-task-document-status-records.md) を更新する。両 ADR の「決定」は訂正の記録の置き場所を定めており、それを変えるので、`CLAUDE.md`「Design decisions (ADR)」の基準で major である（既存の ADR の決定を変える決定）。引き継ぎ方は ADR-0039 に書き、ADR-0036 はそれへリンクする。
-   **訂正の行は、要約せず、1 行ずつそのまま写す（AC-01）:** コミットにある行と同じバイト列を、squash の本文の 1 行にする。
    -   **理由:** そのまま写せば、`main` の履歴から `git log --grep='^Editorial correction: '` で訂正を探せる。要約すると、何を直したかが PR の説明に頼ったまま残る。
    -   **採らなかった案:** 件数と対象のパスだけを本文に書き、詳細を PR の説明に任せる案は、上の理由で採らない。
    -   ADR：ADR-0039 の更新に含める。
-   **訂正の行はすべて引き継ぎ、行数と 1 行の長さに上限を設けない（AC-05）:** 本文を 10 行程度に抑える目安の例外とする。
    -   **理由:** 目的は、訂正の記録を欠けずに `main` に残すことである。多くの ADR を直す PR（タスク 0073 のような見直し）ほど記録が要る。訂正の行を書くのは、PR を作ったエージェントのセッションと人である。人は承認の質問で、その行を読む。
    -   **採らなかった案:** 行数の上限を超えた分を件数だけにして PR の説明を参照させる案は、上限を超えた PR だけ記録が欠けるので採らない。1 行の長さに上限を設けて止める案も、同じ理由で採らない。
    -   ADR：ADR-0039 の更新に含める。
-   **同じ行は 1 つにまとめる（AC-03）:** バイト列として同じ訂正の行が引き継ぐ範囲の複数のコミットにあるときは、初めて現れた位置に 1 回だけ書く。
    -   **理由:** コミットを作り直したときや、同じ訂正を書き直したときに、同じ行が複数のコミットに入りうる。同じ行を何度も書いても、記録は増えない。
    -   **採らなかった案:** コミットごとに現れた回数だけ書く案は、本文が長くなるだけなので採らない。
    -   ADR：なし。引き継ぎの書き方の細部で、本タスクの中で閉じる。
-   **接頭辞で始まる行は、後ろの形が崩れていてもそのまま写す（AC-02）:** 1 列目が `Editorial correction: ` で始まる行は、`<パス>: <説明>; no decision changed` の形に合わなくても訂正の行として写す。ただし、受け付けない文字を含む行は、次の項目のとおり扱う。
    -   **理由:** 訂正の行の定義は、接頭辞で始まることだけである（`docs/dev/conventions/requirements_process.md:446-448`）。形の崩れた行で止めると、ブランチの履歴を書き換えない限りマージできない。写した行は、承認の質問で人が読む。
    -   **採らなかった案:** 形が合わない行でマージを止めて報告する案は、上の理由で採らない。
    -   ADR：なし。引き継ぎの書き方の細部で、本タスクの中で閉じる。
-   **受け付けない文字を含む訂正の行があれば、その行のままではマージしない（F-003）:** 受け付けない文字は、人に見えない文字（タブを除く制御文字、書式文字、行区切りと段落区切り）、UTF-8 として不正なバイト列、`@`、`<` である（3 章の冒頭）。そのような行があれば、`/mergepr` は承認の質問の前に報告する。人がその行を落とすか（F-004 の項目）、ブランチで直すかを選ぶまで、承認の質問に進まず、マージしない。
    -   **理由:** 見えない文字と不正なバイト列は、承認の質問で本文を見ても人には確かめられない。そのまま写すと、人が確かめられない文字が `main` の履歴に残る。件名にも、同じ理由で印字できる文字だけという確かめがある（`.claude/commands/_context.md:222`）。訂正の行には日本語も入るので（#976 の行）、件名のように ASCII に限ることはできない。`@` と `<` は、訂正の行が含まないと規約が定める文字であり（`docs/dev/conventions/requirements_process.md:456`）、その決まりをマージでも確かめる。タブは空白として表示され、文字を隠さないので除く。似た形の文字は、見えないわけではなく、機械的に決められないので扱わない。
    -   **採らなかった案:** 制御文字と不正な UTF-8 だけで止め、書式文字（ゼロ幅の文字、文字の向きを変える文字、BOM）をそのまま写す案は、書式文字も人に見えないので採らない。`@` と `<` をそのまま写し、規約を書く側の決まりにとどめる案は、決まりを破った行が `main` に残るので採らない。
    -   ADR：なし。`/mergepr` が行を受け付ける条件で、仕様は本タスクの文書と `mergepr.md` に置く。
-   **承認の質問で人が本文の修正を頼んでも、訂正の行は消せない（AC-08）:** 修正した本文にも、引き継いだ訂正の行がすべて残る。例外は次の項目だけである。
    -   **理由:** 記録を失わない側に倒す。訂正の行は、ブランチのコミットを書いた時点の記録であり、マージの時点で選び直すものではない。
    -   **採らなかった案:** 人が明示すれば、理由を問わずに行を消してマージできる案は、記録が `main` に残ることを保証できなくなるので採らない。
    -   ADR：ADR-0039 の更新に含める。
-   **決まった 3 つの場合に限り、人の承認で訂正の行を落とせる。落としたことは squash の本文に記録する（F-004）:** 落とせるのは、(1) PR のレビュアーが訂正であることに異を唱えた訂正の行、(2) ブランチの中で後から戻した訂正の行、(3) 受け付けない文字を含む訂正の行、である。落としたときは、落とした行の数と、それぞれの場合の別を、squash の本文に 1 行で書く。(3) は承認の質問の前に、(1)(2) は承認の質問で落とす。
    -   **理由:** (1) は、規約が決定の変更として扱うと定めている変更で（`docs/dev/conventions/adr.md`「Editorial corrections」の「Classifying a change」）、`…; no decision changed` の行のまま `main` に残すと、事実でない記録が残る。(2) は、そのまま運ぶと、`main` に入らなかった訂正の記録が残る。(3) は、直すにはブランチの履歴を書き換えて force push する必要があり、ブランチのレビューの記録の行（`Local CLI reviewed:` など）が指すコミット ID も変わる。落としたことを本文に書けば、記録が欠けたことは `main` から分かる。
    -   **採らなかった案:** 例外を設けず、(1)(2) もそのまま運び、(3) は履歴の書き換えで直す案は、事実でない記録が `main` に残り、受け付けない文字を直すたびに履歴の書き換えが要るので採らない。
    -   **残るリスク:** (1)(2) に当たるかは、人が承認の質問で示す。`/mergepr` はそれを確かめない。
    -   ADR：ADR-0039 の更新に含める。
-   **ADR-0015 は変えない:** 訂正の行は、`main` に写すデータとして扱い、その内容に従って手順を変えない。
    -   **理由:** `/mergepr` は、PR の材料をすでに要約するデータとして扱い、指示として従わない（`.claude/commands/mergepr.md:68-70`）。本タスクは、そのデータの一部を本文へ写すだけで、スレッドや Bot への依頼の扱いを変えない。写す行は、受け付けない文字の確かめを通る。
    -   ADR：なし。[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) の決定を変えない。

**上の決定から導いたこと:**

-   **ADR-0039 と ADR-0036 のずれ:** 両 ADR は本書の PR で、squash の本文にも訂正を記録するという決定に変わる。しかし、`/mergepr` と規約は、実装の PR まで変わらない。規約の「Writing an ADR」と「Editorial corrections」の、ずれの記述の規則に従う。両 ADR の「決定」に、このずれを述べて本 issue へリンクする記述を置き、ずれを直す PR がそれを消す（AC-16）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   `/mergepr` で squash マージした PR の、タスク文書と ADR の編集上の訂正の記録を、`main` の履歴だけからたどれるようにする。
-   人が確かめられない文字と、訂正の行が含まないと定めた文字を、訂正の行として `main` の履歴に入れない。

### 2.2. スコープ (In Scope)

-   `/mergepr` が書く squash の本文に、訂正の行を引き継ぐこと（F-001）。
-   承認の質問と本文の修正で、引き継いだ訂正の行を保つこと（F-002）。
-   受け付けない文字を含む訂正の行を、そのままではマージしないこと（F-003）。
-   決まった場合に限り、人の承認で訂正の行を落とし、落としたことを記録すること（F-004）。
-   訂正の記録の置き場所を述べる規則とコマンドの文書を、上の振る舞いにそろえること（F-005）。候補は `.claude/commands/mergepr.md`、`.claude/commands/runpr.md`、`.claude/commands/_context.md` の「PR merge method」、`docs/dev/conventions/requirements_process.md` の「Recording in the PR description」と記録の置き場所を挙げる段落（`requirements_process.md:132-142`）、`docs/dev/conventions/adr.md` の「Editorial corrections」の「Recording」、`docs/dev/guides/mergepr_guide.md`、`CLAUDE.md` である。どの文書のどの文を変えるかは設計で決める。
-   ADR-0039 と ADR-0036 を更新すること。本書の PR で行う（`.claude/commands/_lib/settle-decisions.md` の手順による）。ずれを直す PR で、両 ADR のずれの記述を消すこと（F-005）。
-   上の変更で古くなる文書のテスト（`cmd/mergepr/docs_test.go` など）をそろえること（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   **`main` にすでにある squash コミットの本文。** `main` の履歴は書き換えない。過去の PR の訂正は、今のまま PR の説明に残る。
-   **`/mergepr` を通らないマージ。** `gh pr merge` を直接使うマージや、GitHub の画面からのマージでは引き継がれない。このリポジトリのマージは `/mergepr` で行う（`.claude/commands/_context.md:53`）。
-   **訂正の行のない訂正。** PR の説明の訂正の段落にだけ手で書かれた訂正や、訂正と報告されなかった変更は、引き継がない。引き継ぐのはコミットの訂正の行だけで、PR の説明の段落は読まない。訂正の段落は訂正の行から作るという、今の決まりと同じである（[ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」）。
-   **折り返された訂正の行。** 訂正の行が途中で改行されているとき（#872 の行）、2 行目以降は訂正の行ではなく、引き継がれない。1 行目だけが、切れたまま引き継がれる。訂正の行が 1 行であることは、今の規約が書く側に求める決まりである（`docs/dev/conventions/requirements_process.md:440-444`）。
-   **訂正の行と訂正の段落の形の変更。** 形は今のまま（`docs/dev/conventions/requirements_process.md:438-482`）とし、本タスクは引き継ぐことだけを足す。
-   **訂正の行以外のコミットメッセージの行の扱い。** `CLAUDE.md` が求める記録の運び方と、本文を短く保つ規則は、訂正の行の例外を足すことを除いて変えない（`.claude/commands/mergepr.md:104-131`）。受け付けない文字の確かめも、訂正の行だけに行う。
-   **squash の件名の規則。** 件名の形と確かめは変えない（`.claude/commands/_context.md`「PR title and squash subject」）。
-   **PR の説明の訂正の段落の作り方。** `_lib/task-pr-handoff.md` Part B と `/fixpr` の Phase 6 が段落を作る手順は変えない。

## 3. 機能要件 (Functional Requirements)

本章の用語は次のとおりである。

-   **訂正の行:** コミットメッセージの、1 列目が `Editorial correction: `（大文字と小文字を区別し、コロンの後ろに半角の空白 1 つ）で始まる行を指す（`docs/dev/conventions/requirements_process.md:446-448`）。件名の行も含む。字下げした行や、文の途中にある語句は含まない。行の残りの形は問わない。行のバイト列は、コミットオブジェクトに格納されたメッセージのものである。
-   **引き継ぐ範囲:** `/mergepr` がマージに使う準備（`mergepr merge` に渡す最後の `prepare`）で、マージ先のブランチからはたどれず、PR の head からはたどれるコミットを指す。今は、`prepare` がメッセージを `log.txt` に書くコミットである（`internal/mergepr/mergepr.go:250`）。ブランチに取り込んだ `main` のコミットは含まない。`/runpr` が記録のコミットの後に `prepare` をやり直すときは、やり直した準備の範囲である。
-   **範囲の順:** 引き継ぐ範囲のコミットを `git rev-list --reverse --topo-order <マージ先>..<head>` の順に並べ、各コミットの中では行を書かれた順に並べたときの、行全体の順序を指す。
-   **受け付けない文字:** 次のどれかを指す。
    -   Unicode の一般カテゴリ Cc の文字のうち、タブ（U+0009）を除くもの。行の末尾の CR（U+000D）も含む。
    -   一般カテゴリ Cf の文字（ゼロ幅の文字、文字の向きを変える文字、U+FEFF など）。
    -   一般カテゴリ Zl と Zp の文字（U+2028、U+2029）。
    -   UTF-8 として不正なバイト列。
    -   `@`（U+0040）と `<`（U+003C）。
-   **squash の本文:** `/mergepr` が `mergepr merge --body-file` に渡し、`main` の squash コミットのメッセージの、件名の後ろの部分になるもの（squash コミットの本文）を指す。
-   **承認の質問:** `/mergepr` の step 3 で、件名と本文を示してマージしてよいかを人に聞く質問を指す。`/runpr` から `/mergepr` を使うときは、`/runpr` のマージの質問がこれに当たる（`.claude/commands/mergepr.md` の step 3）。
-   **落とした記録の行:** F-004 で訂正の行を落としたときに squash の本文に書く 1 行を指す。`Editorial correction: ` では始まらない。

### 3.1. 機能一覧

#### F-001: 訂正の行を squash の本文に引き継ぐ

`/mergepr` は、引き継ぐ範囲のコミットにある訂正の行を、squash の本文に書く。

**Acceptance Criteria**:

-   **AC-01**: `/mergepr` でマージした squash コミットについて `git cat-file commit <commit> | grep '^Editorial correction: '` が出す行（コミットオブジェクトに格納されたバイト列）の並びは、引き継ぐ範囲の訂正の行から、重複を除き（AC-03）、F-004 で落とした行を除いた並びと、バイト列として一致する。それより多くも少なくもない。
-   **AC-02**: 訂正の行は、パスがタスク文書（`docs/tasks/` の下）でも ADR（`docs/dev/adr/` の下）でも、そのどちらでもなくても引き継がれる。`<パス>: <説明>; no decision changed` の形に合わない行も、受け付けない文字を含まなければ、書かれたとおり引き継がれる。
-   **AC-03**: 訂正の行は範囲の順に並ぶ。バイト列として同じ行が 2 回以上現れるときは、初めて現れた位置に 1 回だけ書かれる。
-   **AC-04**: 1 列目が `Editorial correction: ` で始まらない行（字下げした行、`editorial correction: ` のように大文字と小文字の違う行、文の途中に語句がある行）は、訂正の行として引き継がれない。
-   **AC-05**: 訂正の行の数と 1 行の長さに上限はない。本文を 10 行程度に抑える目安を超えても、すべての訂正の行が引き継がれる。
-   **AC-06**: 引き継いだ訂正の行と落とした記録の行は、本文の `Co-Authored-By:` などのトレーラーの段落より前に、トレーラーの段落とは空行で分けて置かれる。squash コミットのメッセージに `git interpret-trailers --parse` を実行して得る行は、訂正の行も落とした記録の行も含まない。引き継ぐ範囲に訂正の行がないときは、本文に訂正の行も落とした記録の行も書かず、そのための見出しや空の段落も書かない。

#### F-002: 承認の質問と本文の修正で訂正の行を保つ

人が承認する本文と、マージされる本文に、引き継いだ訂正の行がすべてある。

**Acceptance Criteria**:

-   **AC-07**: 承認の質問で人に示す本文には、引き継ぐ訂正の行のうち、承認の質問の前に AC-11 で落とした行を除くものが、すべてある。受け付けない文字を含む行は、承認の質問の本文には現れない。`/runpr` のマージの質問では、本文を書く詳細ファイル（`.claude/commands/runpr.md`「Summary and detail file」）の、本文のどの形（承認の行のない形も含む）にもすべてある。
-   **AC-08**: 人が本文の修正を頼んだとき、修正した本文にも、引き継いだ訂正の行がすべて範囲の順で残る。訂正の行を消すか書き換える修正（F-004 の場合を除く）と、`Editorial correction: ` で始まる行を足す修正を頼まれたときは、`/mergepr` はその部分を適用せず、訂正の行は変えられないことと、その理由を人に伝える。
-   **AC-09**: 本文の `Editorial correction: ` で始まる行が AC-01 の並びと一致しないとき（行が欠けているか、余分な行があるとき）、マージは行われない。この確かめは、承認の質問の前（最初の `prepare` の範囲に対して）と、マージの直前（マージに使う準備の範囲に対して）の両方で行う。承認の質問の前に止まったときは、`/mergepr` は欠けた行と余分な行を示して本文を書き直し、`/runpr` は記録のコミットも push も行わない。`/runpr` の記録のコミットと push の後に止まったときは、マージせずに、欠けた行と余分な行と、記録のコミットが push 済みでブランチに残ることを報告する。

#### F-003: 受け付けない文字を含む訂正の行をそのままではマージしない

人が確かめられない文字と、訂正の行が含まないと定めた文字を、`main` の履歴に入れない。

**Acceptance Criteria**:

-   **AC-10**: 引き継ぐ範囲の訂正の行のどれかが受け付けない文字を含むとき、`/mergepr` は承認の質問の前に報告する。報告は、該当する行ごとに、コミット ID と、その行がコミットメッセージの何行目かと、どの種類の受け付けない文字か（見えない文字、不正な UTF-8、`@`、`<`）を示す。行は、印字できる文字はそのまま、見えない文字は `U+XXXX`、不正なバイトは `\xNN` の形にして示す。
-   **AC-11**: AC-10 の報告は、直し方として、その行を落とすこと（F-004 の (3)）と、そのコミットのメッセージをブランチで書き直してから `/mergepr` をやり直すことの 2 つを示す。この確かめも、AC-09 と同じく承認の質問の前とマージの直前の両方で行う。承認の質問の前に報告したときは、人がどちらかを選ぶまで、承認の質問に進まず、マージは行われず、`/runpr` は記録のコミットも push も行わない。落とすことを選んだ行は、F-004 の (3) として落とされる。マージの直前に初めて見つかったときは、AC-09 の後の場合と同じく、マージせずに報告する。
-   **AC-12**: 受け付けない文字の確かめは、訂正の行だけに行う。訂正の行でない行に受け付けない文字があっても、AC-10 の報告は出ない。タブ（U+0009）を含む訂正の行は、AC-01 のとおり書かれたとおり引き継がれる。

#### F-004: 決まった場合に限り訂正の行を落とす

人は、決まった 3 つの場合に当たる訂正の行だけを落とせる。(3) は承認の質問の前に、(1)(2) は承認の質問で落とす。落としたことは squash の本文に残る。

**Acceptance Criteria**:

-   **AC-13**: 人は、(1) PR のレビュアーが訂正であることに異を唱えた訂正の行と、(2) ブランチの中で後から戻し、PR の head の時点でも戻したままの訂正の行を、承認の質問で場合の別とともに示して落とせる。(3) 受け付けない文字を含む訂正の行は、AC-11 の選択で落とせる。(1)(2) に当たるかは、人が示したとおりとする。(3) に当たるのは、AC-10 の報告に挙がった行だけである。落とすのは AC-03 で重複を除いた後の行であり、同じバイト列の行は、どのコミットに現れたものも一緒に落ちる。
-   **AC-14**: 1 行以上を落としたとき、squash の本文には落とした記録の行が 1 行だけ入る。その行は、落とした行の数（AC-03 で重複を除いた後の数）を (1)・(2)・(3) の場合ごとに示す。落とした行の文字は含まない。1 行も落とさないときは、落とした記録の行は入らない。
-   **AC-15**: 3 つの場合に当たらない理由で訂正の行を落とす修正を頼まれたときは、AC-08 のとおり適用しない。

#### F-005: 文書と ADR をそろえる

規則・コマンドの文書・ADR が、F-001〜F-004 の振る舞いと食い違わないようにする。

**Acceptance Criteria**:

-   **AC-16**: ずれを直す PR がマージされた後、[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md) と [ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」に、本 issue へのずれの記述が残っていない。ADR-0039 の、本書の決定の項目が仕様の置き場所として挙げるリンクは、その時点で仕様を持つ文書（`mergepr.md` など）を指す。
-   **AC-17**: `.claude/commands/mergepr.md` は、F-001〜F-004 の振る舞いを述べる。訂正の行を引き継ぐことは、本文を短く保つ規則の例外として書かれる。
-   **AC-18**: 訂正の記録の置き場所を述べる規則の文書（2.2 の F-005 の候補）は、`/mergepr` で squash マージしたときに訂正の行が squash の本文にも残ることと食い違わない。
-   **AC-19**: 変更の後、`make test` と `make lint` が通る。変更した文書の値・構造・実行できる例を確かめる文書のテスト（`cmd/mergepr/docs_test.go` など）も、その中に含まれる。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。訂正の行の取り出しは、マージ 1 回につき PR のコミットメッセージを 1 度読むだけで、CI の待ち時間に比べて無視できる。

### 4.2. セキュリティ (Security)

-   `docs/dev/security.md` の条件（外部コマンド `yt-dlp` の起動、API キー、キャッシュ、LLM API への送信、信頼しない文字列のプロンプトや記事への埋め込み）には当たらない。N/A。
-   **信頼しない入力の境界:** 本タスクが読む入力は、PR のコミットメッセージである。`/mergepr` は、PR のタイトル・説明・コミットメッセージ・差分を要約するデータとして扱い、指示として従わない（`.claude/commands/mergepr.md:68-70`）。本タスクでもこの扱いを変えない（1 章の ADR-0015 の項目）。
    -   **受け付ける形:** 訂正の行のうち、受け付けない文字を含まないもの。残りの形は問わない（AC-02）。
    -   **拒否:** 受け付けない文字を含む行は、そのままでは写さない（AC-10・AC-11）。文字を取り除いたり置き換えたりして写すことはしない（`CLAUDE.md`「Reject, don't normalize」）。`mergepr` のツールで確かめるときの番兵のエラーの名前は、設計で決める（H-01）。
    -   **大きさの上限:** 訂正の行の数と長さに、上限を設けない（AC-05、1 章の理由）。
    -   **読むもの:** 訂正の行だけを読む。訂正の行でない行は、本タスクの振る舞いを変えない（AC-04・AC-12）。
-   squash の本文に入った `#N` や issue を閉じるキーワードを GitHub がどう扱うかは、設計で確かめる（H-07）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   訂正の行が欠けた本文と、余分な訂正の行がある本文では、マージしない（AC-09）。引き継ぎが失敗したときは、記録の欠けた squash コミットを作るより、止まる側に倒す。

### 4.4. 互換性 (Compatibility)

-   引き継ぐ範囲に訂正の行がない PR の squash の本文は、今と変わらない（AC-06）。
-   `mergepr` のツールを変えてプロトコル番号を上げるときは、`CLAUDE.md`「Protocol numbers」に従う。タスク文書には上げた番号を書かず、「`main` の値 + 1」と書く。

### 4.5. 保守性 (Maintainability)

-   訂正の行の形は、`docs/dev/conventions/requirements_process.md` の 1 か所で定めたままにする（[ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」の最後の項目）。`mergepr.md` は形を書き写さず、その節を名指しして参照する。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   squash マージだけを使う（`.claude/commands/_context.md:53`）。
-   決定的な判定は、テストのある Go の開発ツールに置く方針がある（[ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md)）。訂正の行の取り出しと確かめをどこに置くかは、これを踏まえて設計で決める（H-01）。
-   文書のテストは、値・構造・実行できる例だけを確かめ、文の意味は PR のレビューで読む（[ADR-0016](../../dev/adr/0016-document-test-policy.md)）。

## 6. 用語集 (Glossary)

-   **訂正の行**・**引き継ぐ範囲**・**範囲の順**・**受け付けない文字**・**squash の本文**・**承認の質問**・**落とした記録の行:** 3 章の冒頭で定義する。
-   **訂正の段落:** PR の説明に書く、訂正の行を日本語にした段落（`docs/dev/conventions/requirements_process.md`「Recording in the PR description」）。
-   **トレーラー:** コミットメッセージの最後の段落にある `Co-Authored-By:` などの `キー: 値` の行（`git interpret-trailers` が読むもの）。
-   **ずれの記述:** ADR の「決定」に置く、決定と正本の文書やコードとのずれを述べて issue へリンクする記述（`docs/dev/conventions/adr.md`「Writing an ADR」）。
-   用語は `docs/translation_glossary.md` と統一する。
