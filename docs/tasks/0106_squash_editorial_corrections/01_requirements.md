## 1. 概要 (Overview)

**目的:** 本書は、PR のブランチのコミットにある編集上の訂正の行を、`/mergepr` が書く squash コミットの本文に引き継ぐための要件を定義する。対象は、タスク文書と ADR の両方の訂正の行である。

**背景:**

本書で使う「訂正の行」「引き継ぐ範囲」「制御文字」は、3 章の冒頭で定義する。

編集上の訂正は、ブランチのコミットメッセージの訂正の行と、PR の説明の訂正の段落に記録する（`docs/dev/conventions/requirements_process.md:438-482`「Recording in the PR description」、`docs/dev/conventions/adr.md:307-314`「Editorial corrections」の「Recording」）。訂正の行は、タスク文書と ADR で同じ形である（タスク 0074、`docs/tasks/0074_adr_editorial_correction/01_requirements.md`）。ADR の訂正は「経緯」に項目を残さず、タスク文書の訂正は状態表にも変更履歴にも残らない（[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md)、[ADR-0036](../../dev/adr/0036-task-document-status-records.md)）。

このリポジトリは、すべての PR を squash マージする（`.claude/commands/_context.md`「PR merge method」）。squash マージの後は、ブランチのコミットが `main` からたどれなくなる。このため、文書がいつ、なぜ直されたかは、squash の件名の PR 番号から開く PR の説明でしか分からない。PR の説明はリポジトリの外にあり、書き換えられる。ADR-0039 の「結果」は、squash コミットの本文に訂正の行を引き継がないこと、引き継ぐかどうかは本 issue で扱うことを述べている。

今の `/mergepr` の手順は、訂正の行を扱っていない。

-   `mergepr prepare` は、PR のコミットのメッセージを `log.txt` に全文で書く（`internal/mergepr/mergepr.go:250`）。
-   `/mergepr` の step 2 は、squash の本文を 10 行程度に抑えるよう求める。その例外は、`CLAUDE.md` がコミットメッセージに求める記録（壊して確かめた記録、最適化の義務、依存の追加の理由、テストの削除のカバレッジ）を 1 行ずつ運ぶことだけである（`.claude/commands/mergepr.md:104-131`）。訂正の行は例外に入っていない。
-   squash の件名には、印字できる ASCII だけからなる 1 行であることの検査がある（`.claude/commands/_context.md`「Checking a squash subject」）。本文にはない。

`main` の squash コミットのうち 9 件（#657・#685・#697・#751・#766・#808・#824・#872・#976）は、本文に訂正の行を計 11 行持つ。手順にない判断でエージェントが運んだもので、運ぶかどうかは PR によって違う。#872 の行の 1 つは途中で折り返されていて、`removed the note that` で切れている。今は、運ばれることはあっても、それが保証されていない。

**通常の進め方を取る理由:** この変更は、ADR-0039 と ADR-0036 の決定を変える。また、`/mergepr` が PR の材料（コミットメッセージ）を `main` の履歴へ写す経路を加える。これは開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）に触れるおそれがあり、迷うときは除外と判断する規則に従った（`docs/dev/conventions/requirements_process.md`「Simple Process」の「Excluded changes」）。人は、通常の進め方を選んだ（「要件定義の際に決めたこと」の 1 つ目の項目）。

対応 issue: [#747](https://github.com/isseis/yt2column/issues/747)（前提: [#732](https://github.com/isseis/yt2column/issues/732)、タスク 0074。関連: [#728](https://github.com/isseis/yt2column/issues/728)、タスク 0070、[ADR-0036](../../dev/adr/0036-task-document-status-records.md)（タスク文書の状態と訂正の記録）、[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md)（ADR の書き方と、決定を変えない編集上の訂正））

**本書の記述範囲:** 本書は、squash コミットの本文に何がどの順で入るか、何のときに止まるか、人が承認の質問で何を変えられるかを、観測できる振る舞いとして定める。訂正の行を取り出して確かめるのを `mergepr` のツールにするかエージェントの手順にするか、`mergepr.md` と関係する文書の英語の文面、文書のテストの変え方は、`02_architecture.md` で決める（[design_handoff.md](design_handoff.md)）。

**issue #747 で決めたこと:**

-   **#732 が `main` に入った後に着手する:** タスク 0074 で、訂正の行の形がタスク文書と ADR で同じになった（#766）。ADR：なし。作業の順序の決定で、本タスクの中で閉じる。
-   **タスク文書の訂正の行も同じに扱うかを決める:** 本書の「要件定義の際に決めたこと」の 2 つ目の項目で決めた。ADR：同項目による。

**要件定義の際に決めたこと（2026-11-19）:**

-   **通常の進め方を取る:** 3 文書を、別々の PR で作る。
    -   **理由:** 上の「通常の進め方を取る理由」のとおり、既存の 2 つの ADR の決定を変える。また、`mergepr` の信頼の境界に触れるおそれがあり、除外と判断した。
    -   **採らなかった案:** 除外の判断を覆して簡易な進め方を取る案は、信頼の境界の判断を設計の前に固めることになるので採らない。
    -   ADR：なし。本タスクの進め方の決定で、本タスクの中で閉じる。
-   **タスク文書と ADR の両方の訂正の行を、squash コミットの本文に引き継ぐ（F-001）:** 引き継ぐ範囲のコミットにある訂正の行は、どの文書のパスを持つかを問わずに引き継ぐ。
    -   **理由:** 訂正の行の形は、タスク文書と ADR で同じである。片方だけを引き継ぐと、ADR-0036 と ADR-0039 で記録の置き場所が分かれる。引き継げば、訂正の記録が `main` の履歴に残り、書き換えられる PR の説明に頼らずに済む。
    -   **採らなかった案:** ADR の行だけを引き継ぐ案は、タスク文書の訂正だけが PR の説明に頼ったまま残るので採らない。引き継がずに理由を ADR-0039 に記録する案は、訂正の記録がリポジトリの外にしか残らない今の問題が残るので採らない。
    -   ADR：[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md) と [ADR-0036](../../dev/adr/0036-task-document-status-records.md) を更新する。両 ADR の「決定」は訂正の記録の置き場所を定めており、それを変えるので、`CLAUDE.md`「Design decisions (ADR)」の基準で major である（既存の ADR の決定を変える決定）。
-   **訂正の行は、要約せず、1 行をそのまま写す（AC-01）:** コミットにある行と同じバイト列を、squash の本文の 1 行にする。
    -   **理由:** そのまま写せば、`main` の履歴から `git log --grep='^Editorial correction: '` で訂正を探せる。要約すると、何を直したかが PR の説明に頼ったまま残る。
    -   **採らなかった案:** 件数と対象のパスだけを本文に書き、詳細を PR の説明に任せる案は、上の理由で採らない。
    -   ADR：ADR-0039 と ADR-0036 の更新に含める。
-   **訂正の行はすべて引き継ぎ、行数の上限を設けない（AC-05）:** 本文を 10 行程度に抑える目安の例外とする。
    -   **理由:** 目的は、訂正の記録を欠けずに `main` に残すことである。多くの ADR を直す PR（タスク 0073 のような見直し）ほど記録が要る。
    -   **採らなかった案:** 上限を超えた分を件数だけにして PR の説明を参照させる案は、上限を超えた PR だけ記録が欠けるので採らない。
    -   ADR：ADR-0039 と ADR-0036 の更新に含める。
-   **同じ行は 1 つにまとめる（AC-03）:** バイト列として同じ訂正の行が引き継ぐ範囲の複数のコミットにあるときは、初めて現れた位置に 1 回だけ書く。
    -   **理由:** コミットを作り直したときや、同じ訂正を書き直したときに、同じ行が複数のコミットに入りうる。同じ行を何度も書いても、記録は増えない。
    -   **採らなかった案:** コミットごとに現れた回数だけ書く案は、本文が長くなるだけなので採らない。
    -   ADR：なし。引き継ぎの書き方の細部で、本タスクの中で閉じる。
-   **接頭辞で始まる行は、後ろの形が崩れていてもそのまま写す（AC-02）:** 1 列目が `Editorial correction: ` で始まる行は、`<パス>: <説明>; no decision changed` の形に合わなくても訂正の行として写し、マージを止めない。ただし、制御文字を含む行は次の項目のとおり止める。
    -   **理由:** 訂正の行の定義は、接頭辞で始まることだけである（`docs/dev/conventions/requirements_process.md:446-448`）。形の崩れた行で止めると、ブランチの履歴を書き換えない限りマージできない。写した行は、承認の質問で人が読む。
    -   **採らなかった案:** 形が合わない行でマージを止めて報告する案は、上の理由で採らない。
    -   ADR：なし。引き継ぎの書き方の細部で、本タスクの中で閉じる。
-   **制御文字を含む訂正の行があれば、マージを止めて報告する（F-003）:** 引き継ぐ訂正の行のどれかに制御文字があれば、承認の質問の前に止まり、何もマージしない。
    -   **理由:** 制御文字は、承認の質問で本文を見ても人には見えない。そのまま写すと、人が確かめられない文字が `main` の履歴に残る。件名にも、同じ理由で印字できる文字だけという検査がある（`.claude/commands/_context.md`「Checking a squash subject」）。訂正の行には日本語も入るので（#976 の行）、件名のように ASCII に限ることはできない。
    -   **採らなかった案:** 形の崩れた行と同じく、そのまま写す案は、上の理由で採らない。
    -   ADR：なし。`mergepr` の止まる条件の 1 つで、仕様は本タスクの文書と `mergepr.md` に置く。
-   **承認の質問で人が本文の修正を頼んでも、訂正の行は消せない（AC-07・AC-08）:** 修正した本文にも、引き継いだ訂正の行がすべて残る。
    -   **理由:** 記録を失わない側に倒す。訂正の行は、ブランチのコミットを書いた時点の記録であり、マージの時点で選び直すものではない。
    -   **採らなかった案:** 人が明示したときは行を消してマージできる案は、記録が `main` に残ることを保証できなくなるので採らない。
    -   ADR：ADR-0039 と ADR-0036 の更新に含める。

**上の決定から導いたこと:**

-   **不正な UTF-8 のバイト列を含む訂正の行も、制御文字と同じく止める（AC-09）:** 不正なバイト列は、端末では置換文字や別の文字として表示され、人は書かれたとおりのバイトを確かめられない。制御文字で止める理由と同じである。
-   **ブランチの中で後から戻した訂正の行も、そのまま引き継ぐ:** 引き継ぐのは、引き継ぐ範囲のコミットに書かれた行であり、最後の差分から判断し直さない。PR の説明の訂正の段落も、同じ行から作られている（`docs/dev/conventions/requirements_process.md:472-473`）。
-   **ADR-0039 と ADR-0036 のずれ:** 両 ADR は本書の PR で、squash コミットの本文にも訂正を記録するという決定に変わる。しかし、`/mergepr` と規約は、実装の PR まで変わらない。規約の「Writing an ADR」と「Editorial corrections」の、ずれの記述の規則に従う。両 ADR の「決定」に、このずれを述べて本 issue へリンクする記述を置き、実装の PR がそれを消す（AC-14）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   `/mergepr` で squash マージした PR の、タスク文書と ADR の編集上の訂正の記録を、`main` の履歴だけからたどれるようにする。
-   人が確かめられない文字を、訂正の行として `main` の履歴に入れない。

### 2.2. スコープ (In Scope)

-   `/mergepr` が書く squash コミットの本文に、訂正の行を引き継ぐこと（F-001）。
-   承認の質問と本文の修正で、引き継いだ訂正の行を保つこと（F-002）。
-   制御文字か不正な UTF-8 を含む訂正の行で止まること（F-003）。
-   訂正の記録の置き場所を述べる規則とコマンドの文書を、上の振る舞いにそろえること（F-004）。対象は `.claude/commands/mergepr.md`、`docs/dev/conventions/requirements_process.md` の「Recording in the PR description」、`docs/dev/conventions/adr.md` の「Editorial corrections」の「Recording」、`docs/dev/guides/mergepr_guide.md`、`CLAUDE.md` のうち、その記述が変わるものである。どの文書のどの文を変えるかは設計で決める。
-   ADR-0039 と ADR-0036 を更新すること。本書の PR で行う（`.claude/commands/_lib/settle-decisions.md` の手順による）。実装の PR で、両 ADR のずれの記述を消すこと（F-004）。
-   上の変更で古くなる文書のテスト（`cmd/mergepr/docs_test.go` など）をそろえること（F-004）。

### 2.3. スコープ外 (Out of Scope)

-   **`main` にすでにある squash コミットの本文。** `main` の履歴は書き換えない。過去の PR の訂正は、今のまま PR の説明に残る。
-   **`/mergepr` を通らないマージ。** `gh pr merge` を直接使うマージや、GitHub の画面からのマージでは引き継がれない。このリポジトリのマージは `/mergepr` で行う（`.claude/commands/_context.md`「PR merge method」）。
-   **訂正の行のない訂正。** PR の説明の訂正の段落にだけ手で書かれた訂正や、訂正と報告されなかった変更は、引き継がない。引き継ぐのはコミットの訂正の行だけで、PR の説明の段落は読まない。訂正の段落は訂正の行から作るという、今の決まりと同じである（[ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」）。
-   **訂正の行と訂正の段落の形の変更。** 形は今のまま（`docs/dev/conventions/requirements_process.md:438-482`）とし、本タスクは引き継ぐことだけを足す。
-   **訂正の行以外のコミットメッセージの行の扱い。** `CLAUDE.md` が求める記録の運び方と、本文を短く保つ規則は、訂正の行の例外を足すことを除いて変えない（`.claude/commands/mergepr.md:104-131`）。制御文字の確かめも、訂正の行だけに行う。
-   **squash の件名の規則。** 件名の形と検査は変えない（`.claude/commands/_context.md`「PR title and squash subject」）。
-   **PR の説明の訂正の段落の作り方。** `_lib/task-pr-handoff.md` Part B と `/fixpr` の Phase 6 が段落を作る手順は変えない。

## 3. 機能要件 (Functional Requirements)

本章の用語は次のとおりである。

-   **訂正の行:** コミットメッセージの、1 列目が `Editorial correction: `（大文字と小文字を区別し、コロンの後ろに半角の空白 1 つ）で始まる行を指す（`docs/dev/conventions/requirements_process.md:446-448`）。字下げした行や、文の途中にある語句は含まない。行の残りの形は問わない。
-   **引き継ぐ範囲:** `/mergepr` がマージする PR のコミットのうち、`mergepr prepare` がメッセージを `log.txt` に書くコミットを指す。今は、マージ先のブランチから届かず、`prepare` が記録した PR の head から届くコミットである（`internal/mergepr/mergepr.go:250`）。ブランチに取り込んだ `main` のコミットは含まない。
-   **制御文字:** Unicode の一般カテゴリ Cc の文字のうち、タブ（U+0009）を除くものを指す。U+0000〜U+0008、U+000A〜U+001F、U+007F、U+0080〜U+009F である。改行（U+000A）は行の区切りであり、行の中には現れない。行の末尾の CR（U+000D）も制御文字に含む。
-   **squash の本文:** `/mergepr` が `mergepr merge --body-file` に渡し、`main` の squash コミットのメッセージの、件名の後ろの部分になるものを指す。

### 3.1. 機能一覧

#### F-001: 訂正の行を squash の本文に引き継ぐ

`/mergepr` は、引き継ぐ範囲のコミットにある訂正の行を、squash の本文に書く。

**Acceptance Criteria**:

-   **AC-01**: 引き継ぐ範囲のコミットに訂正の行があるとき、`/mergepr` でマージした squash コミットの本文には、その訂正の行のそれぞれが、コミットにあるのと同じバイト列の 1 行として入る。`main` の squash コミットについて `git log -1 --format=%B <commit> | grep '^Editorial correction: '` を実行すると、引き継ぐ範囲の訂正の行と同じ行が出る。
-   **AC-02**: 訂正の行は、パスがタスク文書（`docs/tasks/` の下）でも ADR（`docs/dev/adr/` の下）でも、そのどちらでもなくても引き継がれる。`<パス>: <説明>; no decision changed` の形に合わない行も、制御文字と不正な UTF-8 を含まなければ（F-003）、マージを止めずに書かれたとおり引き継がれる。
-   **AC-03**: 訂正の行の順は、引き継ぐ範囲のコミットの古い順で、同じコミットの中では書かれた順である。バイト列として同じ行が 2 回以上現れるときは、初めて現れた位置に 1 回だけ書かれる。
-   **AC-04**: 1 列目が `Editorial correction: ` で始まらない行（字下げした行、`editorial correction: ` のように大文字と小文字の違う行、文の途中に語句がある行）は、訂正の行として引き継がれない。
-   **AC-05**: 訂正の行の数に上限はない。本文を 10 行程度に抑える目安を超えても、すべての訂正の行が引き継がれる。
-   **AC-06**: 引き継いだ訂正の行は、本文の `Co-Authored-By:` などのトレーラーの段落より前に、トレーラーの段落とは空行で分けて置かれる。squash コミットに `git interpret-trailers --parse` を実行して得るトレーラーは、訂正の行を引き継がなかった場合と同じである。引き継ぐ範囲に訂正の行がないときは、本文に訂正の行を書かず、訂正の行のための見出しや空の段落も書かない。

#### F-002: 承認の質問と本文の修正で訂正の行を保つ

人が承認する本文と、マージされる本文に、引き継いだ訂正の行がすべてある。

**Acceptance Criteria**:

-   **AC-07**: `/mergepr` の承認の質問（step 3）で人に示す本文には、引き継いだ訂正の行がすべてある。`/runpr` のマージの質問から `/mergepr` を使うときは、本文を書く詳細ファイル（`.claude/commands/runpr.md`「Summary and detail file」）にすべてある。
-   **AC-08**: 人が本文の修正を頼んだとき、修正した本文にも、引き継いだ訂正の行がすべて、AC-03 の順で残る。訂正の行を消すか書き換える修正を頼まれたときは、`/mergepr` はその部分を適用せず、訂正の行は消せないことと、その理由を人に伝える。訂正の行のどれかが欠けた本文では、マージは行われない。

#### F-003: 人が確かめられない文字を含む訂正の行で止まる

**Acceptance Criteria**:

-   **AC-09**: 引き継ぐ範囲の訂正の行のどれかが、制御文字を含むか、UTF-8 として不正なバイト列を含むとき、`/mergepr` は承認の質問の前に止まり、何もマージしない。止まったときの報告は、該当する行ごとに、コミット ID と、その行がコミットメッセージの何行目かと、問題が制御文字か不正な UTF-8 かを示す。報告には行の文字を生のまま出さない。制御文字と不正なバイトは、`U+XXXX` か `\xNN` のように見える形で示す。
-   **AC-10**: AC-09 で止まったときの報告は、直し方として、該当するコミットのメッセージをブランチで書き直してから `/mergepr` をやり直すことを示す。
-   **AC-11**: 制御文字と不正な UTF-8 の確かめは、訂正の行だけに行う。訂正の行でない行にそれらがあっても、AC-09 では止まらない。タブ（U+0009）を含む訂正の行では止まらず、AC-01 のとおり書かれたとおり引き継がれる。

#### F-004: 文書と ADR をそろえる

**Acceptance Criteria**:

-   **AC-12**: `.claude/commands/mergepr.md` は、F-001〜F-003 の振る舞いを述べる。訂正の行を引き継ぐことは、本文を短く保つ規則の例外として書かれる。
-   **AC-13**: 訂正の記録の置き場所を述べる規則の文書（`docs/dev/conventions/requirements_process.md`「Recording in the PR description」、`docs/dev/conventions/adr.md`「Editorial corrections」の「Recording」）は、`/mergepr` で squash マージしたときに訂正の行が squash の本文にも残ることと矛盾しない。どの文書が何を述べるかは設計で決める。
-   **AC-14**: 実装の PR がマージされた後、[ADR-0039](../../dev/adr/0039-adr-writing-criteria.md) と [ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」に、本 issue へのずれの記述が残っていない。両 ADR の「結果」は、squash コミットの本文に訂正の行を引き継がないとは述べない。
-   **AC-15**: 変更した `mergepr.md` の値・構造・実行できる例を確かめる文書のテスト（`cmd/mergepr/docs_test.go` など）が、変更の後も通る。`mergepr` のツールの振る舞いを変えるときは、F-001〜F-003 の振る舞いをコードのテストで確かめる。どちらで確かめるかは設計で決める。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。訂正の行の取り出しは、マージ 1 回につき PR のコミットメッセージを 1 度読むだけで、CI の待ち時間に比べて無視できる。

### 4.2. セキュリティ (Security)

-   `docs/dev/security.md` の条件（外部コマンド `yt-dlp` の起動、API キー、キャッシュ、LLM API への送信、信頼しない文字列のプロンプトや記事への埋め込み）には当たらない。N/A。
-   **信頼しない入力の境界:** 本タスクが読む入力は、PR のコミットメッセージである。`/mergepr` は、PR のタイトル・説明・コミットメッセージ・差分を要約するデータとして扱い、指示として従わない（`.claude/commands/mergepr.md:68-70`）。本タスクでもこの扱いを変えない。訂正の行は、`main` に写すデータとして扱い、その内容に従って手順を変えない。
    -   **受け付ける形:** 1 列目が `Editorial correction: ` で始まる行。残りは、制御文字と不正な UTF-8 を含まない任意の文字列である（AC-02）。
    -   **拒否:** 制御文字か不正な UTF-8 を含む訂正の行があれば止まる（AC-09）。行を直したり、文字を取り除いたり置き換えたりして写すことはしない（`CLAUDE.md`「Reject, don't normalize」）。`mergepr` のツールで確かめるときの番兵のエラーの名前は、設計で決める（H-01）。
    -   **大きさの上限:** 訂正の行の数と長さに、本タスクは上限を設けない（AC-05）。
    -   **読むもの:** 訂正の行だけを読む。訂正の行でない行は、本タスクの振る舞いを変えない（AC-04・AC-11）。
-   訂正の行は、`@` と `<` を含まない（`docs/dev/conventions/requirements_process.md:456`）。ただし、squash コミットのメッセージは GitHub のコメントではないので、メンションの確かめ（`.claude/commands/_context.md`「PR review request」）は squash の本文には当たらない。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   訂正の行が欠けた本文ではマージしない（AC-08）。引き継ぎが失敗したときは、記録の欠けた squash コミットを作るより、止まる側に倒す。

### 4.4. 互換性 (Compatibility)

-   引き継ぐ範囲に訂正の行がない PR の squash の本文は、今と変わらない（AC-06）。
-   `mergepr` のツールを変えてプロトコル番号を上げるときは、`CLAUDE.md`「Protocol numbers」に従う。タスク文書には上げた番号を書かず、「`main` の値 + 1」と書く。

### 4.5. 保守性 (Maintainability)

-   訂正の行の形は、`docs/dev/conventions/requirements_process.md` の 1 か所で定めたままにする（[ADR-0036](../../dev/adr/0036-task-document-status-records.md) の「決定」の最後の項目）。`mergepr.md` は形を書き写さず、その節を名指しして参照する。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   squash マージだけを使う（`.claude/commands/_context.md`「PR merge method」）。
-   決定的な判定は、テストのある Go の開発ツールに置く方針がある（[ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md)）。訂正の行の取り出しと確かめをどこに置くかは、これを踏まえて設計で決める（H-01）。
-   文書のテストは、値・構造・実行できる例だけを確かめ、文の意味は PR のレビューで読む（[ADR-0016](../../dev/adr/0016-document-test-policy.md)）。

## 6. 用語集 (Glossary)

-   **訂正の行**・**引き継ぐ範囲**・**制御文字**・**squash の本文:** 3 章の冒頭で定義する。
-   **訂正の段落:** PR の説明に書く、訂正の行を日本語にした段落（`docs/dev/conventions/requirements_process.md`「Recording in the PR description」）。
-   **トレーラー:** コミットメッセージの最後の段落にある `Co-Authored-By:` などの `キー: 値` の行（`git interpret-trailers` が読むもの）。
-   **ずれの記述:** ADR の「決定」に置く、決定と正本の文書やコードとのずれを述べて issue へリンクする記述（`docs/dev/conventions/adr.md`「Writing an ADR」）。
-   用語は `docs/translation_glossary.md` と統一する。
