## 1. 概要 (Overview)

**目的:** 本書は、検証・推敲の段階が、直す前（`before`）と直した後（`after`）が同一の文の項目を返した場合の扱いを定める。前後が同一の項目（以下「無変更の項目」）を受理し、`--review-log` の一覧でそれと分かるようにする。

**背景:**
タスク `0010_post_generation_review` の `ArticleWriter` は、検証・推敲の応答の各項目を受理の規則で検査する。`internal/writer/revision.go` の `Revision.check()` は、空の値・制御文字・未知の action と reason を拒否するが、`Before == After` は調べない。そのため、無変更の項目は受理され、記事の該当箇所の文面は変わらないまま、`--review-log` の一覧には「直した箇所」として残る。

タスク 0010 の評価では、claude-sonnet-5-5 の検証・推敲が、`zW1RBacSqjk` の記事で無変更の項目を 1 つ返し、`ArticleWriter` はそれを受理した（[0010 の 02_evaluation.md](../0010_post_generation_review/02_evaluation.md) §3.5）。記事は変わらず、実害は小さい。ただ、一覧を読む人は直したと誤解し、評価で項目を数えるときにも混ざる。0010 の要件はリトライも部分的な受理も禁じているため、拒否すると無害な 1 項目のために記事全体が失敗し、生成と字数の調整の呼び出しも無駄になる。どちらにするかは要件の判断が要るので、0010 では決めず、別の issue（#186）にした（0010 の 02_evaluation.md §4.3）。

対応 issue: #186

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

- 無変更の項目を受理し、記事を失敗させない（0010 の受理の規則と段階の失敗の方針を変えない）。
- `--review-log` の一覧を読む人が、無変更の項目を直した箇所と取り違えないようにする。
- 変更のある置換と削除の扱い、および既存の拒否の規則を変えない。

### 2.2. スコープ (In Scope)

- `ArticleWriter` の受理の規則における無変更の項目の扱い（受理することの明文化）。
- `--review-log` の一覧の書式に、無変更の項目の印を加えること。
- 上記のテストと、関連する文書（0010 の 02_architecture.md・02_evaluation.md、`internal/publisher` の説明。更新の要否は設計で決める）。

### 2.3. スコープ外 (Out of Scope)

- 無変更の項目を拒否すること（issue #186 の候補 A）。受理の規則と段階の失敗の方針を変えるため、本書では扱わない。
- 検証・推敲のテンプレートに、無変更の項目を返さないよう指示すること（issue #186 の候補 C）。モデルが守る保証がなく、無変更の項目が返る場合の扱いは別に要るため、本書の外で検討する。
- 一覧から無変更の項目を取り除くこと、応答を補正すること。0010 の「補正しない」「一覧は変更の完全な記録になる」の方針に反するため、採らない。
- CLI の要約（`the review step returned …`）の件数の数え方。0010 の要件（AC-22）は要約の件数を定めていないため、本書では扱わない。
- 検証・推敲の段階そのもの、テンプレートの参照できる値、0010 の他の要件。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 無変更の項目の受理

検証・推敲の応答の項目が、`after` を持ち（`ActionReplace`）、`before` と `after` が同じ文字列である場合、この項目を無変更の項目として受理する。当てはめは今までどおり行い、記事の該当箇所の文面は変わらない。

**Acceptance Criteria**:
- **AC-01**: `ActionReplace` で `Before == After` の項目は、`ReviewResult.Check` と応答の解析（`parseReviewResponse`）の両方で受理される（拒否されない）。
- **AC-02**: 無変更の項目だけからなる応答、または無変更の項目と他の項目を合わせて持つ応答に対して、`ArticleWriter.Write` は成功し、ゼロ値でない `Article` を返す。返る記事の `Review.Revisions` には、無変更の項目が応答の順序どおりに含まれる。
- **AC-03**: 無変更の項目を当てはめた結果の文面は、当てはめの対象の文面と同じである（その項目の `before` の範囲が同じ文字列で置き換わる）。
- **AC-04**: `ActionDelete` の項目、および `Before != After` の `ActionReplace` の項目の受理と当てはめは、変わらない。無変更の項目は、既存の応答の受理の規則と、0010 F-003 が定める信頼できない入力の境界の契約を、そのまま受ける（無変更の項目を理由に新しい受理・拒否を加えない）。境界の契約をどう適用するかの詳細は設計で扱う（[design_handoff.md](design_handoff.md) H-01）。

#### F-002: 一覧での無変更の印

`--review-log` の一覧の各項目のうち、無変更の項目には、変更がなかったことを示す固定の印を書く。

**Acceptance Criteria**:
- **AC-05**: `--review-log` の一覧で、無変更の項目には、`ActionDelete` の項目の `Deleted.` と同じ位置に、変更がなかったことを示す固定の英語の 1 行（`No change.`）を書く。
- **AC-06**: 無変更の項目でも、`Before:` の引用（`before`）・`After:` の引用（`after`）・`Evidence:` の引用（`evidence`）と、見出しの理由の値（`reason`）は、変更のある項目と同じ形で読める（0010 の AC-20 を満たす）。
- **AC-07**: `ActionDelete` の項目の書式と、`Before != After` の `ActionReplace` の項目の書式は、変わらない。一覧の先頭の `- Revisions:` の件数も、無変更の項目を含めた項目の数である（0010 の書式を変えない）。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

- LLM の呼び出しの回数を増やさない。無変更の項目は応答の中にあり、判定はローカルで完結する。

### 4.2. セキュリティ (Security)

- 一覧の値（`before`・`after`・`evidence`・理由の値）は、0010 と同じく信頼できない入力として扱う。追加する印は固定の英語の 1 行で、応答の値を含めない。
- 無変更の項目の判定は、応答の解析の後に行うので、値に制御文字が含まれる場合は既存の検査が先に拒否する（[security.md](../../dev/security.md) の検証・推敲の応答の節を変えない）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

- 無変更の項目は、記事全体の失敗の理由にしない（0010 の F-006・§5.4 の失敗の種類を変えない）。

### 4.4. 互換性 (Compatibility)

- `--review-log` を指定しない実行の振る舞いは変わらない（無変更の項目は記事の文面を変えないため）。
- 無変更の項目を含まない一覧の書式は変わらない。無変更の項目を含む一覧だけが、固定の 1 行を増やす。

### 4.5. 保守性 (Maintainability)

- 無変更の判定は、一覧の値（`Revision`）から決まる。プロバイダやモデルに依存しない。

## 5. 制約条件 (Constraints)

- [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」に従う。外部ライブラリは追加しない。
- タスク `0010_post_generation_review` の承認済みの文書（01_requirements.md・02_architecture.md）の決定を変える部分は、本書と 0013 の設計で明示する。0010 の要件（F-003・AC-12・AC-13・AC-14・AC-20）のうち、変えるものと変えないものを、設計で対応付ける。
- 一覧の書式は 0010 の 02_architecture.md §3.8 を正典とする。0013 の設計で、§3.8 を変えずに差分（無変更の項目の印）を 0013 側に置くか、0010 §3.8 を draft に戻して追記するかを決める。

本書のレビューで挙がった実装・設計の段階の事項は、[design_handoff.md](design_handoff.md) に集め、設計が扱う。

## 6. 用語集 (Glossary)

-   **無変更の項目:** 検証・推敲の応答の項目のうち、`after` を持ち、`before` と `after` が同じ文字列であるもの。当てはめても記事の文面を変えない。
-   **一覧（直した箇所の一覧）:** 検証・推敲の LLM が返す項目の列（0010 の用語と同じ）。
-   **検証・推敲:** 記事を素材と突き合わせて直す段階（0010 の用語と同じ）。
