# 設計への申し送り：変更のない検証・推敲の項目

本書は、[01_requirements.md](01_requirements.md) のレビューで挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: 無変更の項目への応答の境界の契約の適用

-   **事項:** F-001（無変更の項目の受理）が、0010 F-003 が定める検証・推敲の応答の境界の契約を、無変更の項目についても変えずに受けることを、設計でどう明示するかを決める。契約には、受理する形と消費するメンバー、未知・重複したメンバーの拒否、拒否の番兵（`ErrMalformedOutput`）、応答全体の大きさと項目の数の上限、標準ライブラリが黙って修復・破棄・無視する入力の拒否が含まれる。
-   **理由:** 無変更の項目も 0010 F-003 と同じ信頼できない応答の境界を通る。0013 の設計は書式（`No change.`）と受理の維持を定めるが、境界の契約の引き継ぎを明示していないため、実装とテストがどの規則に従うかが設計から読み取りにくい。要件のレビューでは、F-001/AC-04 が「既存の検査」とだけ述べてこの契約を明示的に引き継いでいないことが指摘され、要件側は抽象度を上げて境界の契約への参照に改めた。
-   **候補の方針:** 境界の契約は 0010 F-003・0010 §3.5.3 に置いたまま再利用する。0013 の設計は、無変更の項目が受理の規則のいずれにも違反せず（したがって境界の拒否を新たに加えず）、同じ境界を通ることを記録する。構文・上限の値・不正な入力の検出方法は 0010 の決定（[0010 の design_handoff.md](../0010_post_generation_review/design_handoff.md) H-01 以降）を再定義しない。
-   **関連:** F-001、AC-04
