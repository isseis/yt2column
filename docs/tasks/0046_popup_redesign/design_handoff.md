# 設計への申し送り：ポップアップの画面の再設計

要件定義（[01_requirements.md](01_requirements.md)）の検討で挙がった、設計で決める事項。`02_architecture.md` は、各項目について採った方法、または当てはまらない理由を記録する。

-   **H-01: #503 の状態を加えられる枠の構造（要件書 4.5、AC-20・AC-21）。** 今は `popup.html` の `#summary` と `#send` の 2 つの領域に描く（`extension/static/popup.html:9-10`）。動画のセクション・確認のセクション・操作のセクション・詳細を、どの領域と要素に描くか、#503 の状態（生成中・生成済み・失敗）を同じ 3 つのセクションの構成の中でどう切り替えるかを決める。モックアップの #503 の状態では、動画のセクションを残し、確認のセクションの位置に状態の表示が入り、主ボタンが別の操作に変わる。#503 の生成中の表示（段階ごとのチェックリスト、経過時間、`prefers-reduced-motion` で止めるアニメーション、issue #507）が入る余地を考える。
-   **H-02: 表示のための型の作り直し（AC-01〜AC-16）。** 今の要約の型（`OutcomeSummary`・`SummaryField`、`extension/src/core/types.ts:29-43`）と、要約の欄の表（`extension/src/ui/render.ts:47-53`）・メタデータの行の表（`extension/src/ui/render.ts:130-134`）は、ラベルと値の行を前提にしている。確認の行の状態（✓・⚠）と、⚠ の理由（折りたたまれている、送られない、大きすぎる）を、型の上の宣言として持つ形にする（`CLAUDE.md`「Declare, don't infer」）。
-   **H-03: プレビューの切り詰めと表示（AC-08〜AC-10）。** 最後の 100 コードポイントを、サロゲートペアの途中で切らずに取り出す方法（今の `truncate`、`extension/src/core/summary.ts:14-21`、は先頭だけを扱う）。改行を空白に置き換える処理を表示の側に置き、送る値に影響させない（AC-19）。ポップアップの幅に収まらないプレビューを 1 行に収め、末尾のプレビューでは前の側を省略する CSS と、`unicode-bidi: plaintext`・`dir="auto"` との組み合わせ（右から左の文字で始まる値で、どちらの側が切れるか）。`\r\n` を 1 つの空白にする置き換えと、100 コードポイントの数え方（元の選択範囲の上で数える）の順序。
-   **H-04: 文言の表の変更（AC-17・AC-23・AC-29・AC-30）。** `Catalog`（`extension/src/core/i18n/catalog.ts:23-51`）の、要約とメタデータの欄の名前（`summaryLabels`・`metadataLabels`）を、新しい行の名前と状態の説明に置き換える方法。数を埋め込む文言（「12,345 文字・420 行」「全文・1,203 文字」）は、値を受け取る関数で組み立てる（0043 の決めたこと）。促しのメッセージの文言を短くする場合（モックアップは手順を 2 つの短い文にしている）は、README の引用と、それを比べるガードのテスト（`extension/test/metadataDocs.test.ts:28-33`）を同じ変更で直す。拒否のカードに見出しを加えるか（モックアップは「Select the transcript first」のような見出しと、理由の文を分けている）。加える場合は、理由ごとの見出しの文言を英語と日本語の両方で決める。
-   **H-05: 判定の順序と、それまでの表示（AC-05・AC-11）。** 今は、収集の要約を先に描き、動画メタデータを後から加え、リクエストの本文の大きさの判定は送信の領域を描くときに行う（`extension/src/launch.ts:180`・`:184-190`・`:211-216`）。すべてが終わってから一度に描く順序に変え、動画メタデータを含めた本文で大きさを判定することを保つ（0025 AC-08）。終わるまでの間に、読み込み中の表示を出すか、何も出さないかを決める。
-   **H-06: 色とコントラストの確かめ方（AC-25・AC-26・AC-37・AC-40）。** ライトとダークの色を CSS の変数で持つか、`prefers-color-scheme` の media query で切り替えるか。今の `color-scheme: light dark`（`extension/static/style.css:2`）との関係。コントラスト比を確かめる方法（色の組の表から計算するテストか、手動の確認か）。✓ と ⚠ の色と ⚠ の行の背景を、赤と緑の組にしない選び方と、1 型・2 型の色覚を模して確かめる方法（Chrome の開発者ツールの「視覚障害をエミュレート」など）。フォーカスの表示の色を、ライトとダークの両方で 3:1 以上にする方法。
-   **H-07: 状態を文字で伝える方法と、支援技術に渡す名前（AC-27・AC-38・AC-39）。** ✓ と ⚠ の記号を `aria-hidden` にし、状態を表示する文字か、読み上げ用の文字で伝えるか。記号を、外部のフォントを使わずに描く方法（インラインの SVG か、文字か）。主ボタン・詳細の開閉・見出しを、どの要素（`<button>`・`<summary>`・`<h1>` など）で作り、どこまで HTML の要素の意味に任せ、どこで ARIA の属性を使うか。押せない主ボタンを `disabled` で表すか `aria-disabled` で表すか（AC-36 の、フォーカスが移るかどうかと合わせて決める）。送信中の案内と送信の結果を伝える領域（`role="status"`・`aria-live` など）を、#503 の状態の表示でも使えるように置く方法。
-   **H-08: 押せる要素の大きさとキーボードでの操作（AC-28・AC-36・AC-37）。** `<details>` の `<summary>` を 44 CSS ピクセル以上にする方法。押せない主ボタンの見た目。主ボタンと詳細の開閉を作り直すときに、キーボードで操作でき、フォーカスの位置が見える状態を保つ（ブラウザ既定のフォーカスの表示を消さないか、AC-37 を満たす表示に置き換える）。ポップアップを開いたときにフォーカスをどこに置くか。送信の後に主ボタンが押せなくなったとき、フォーカスがどこへ移るか。
-   **H-09: 主ボタンが開いた時点で見えること（AC-04・AC-17）。** Chrome のポップアップの大きさの上限（幅 800 px・高さ 600 px）の中で、見出しを 2 行に収める方法（`line-clamp` など）と、確認のセクションの 2 行がどちらも ⚠ で手順を持つときの高さを見積もる。ポップアップの幅（モックアップは 360 px、今は `min-width: 20rem`、`extension/static/style.css:10`）と、日本語の行間（0043）の影響を含める。
-   **H-10: テストの方法。** セクションの順序（AC-01）・見出しの代替（AC-03）・読み取りが終わるまでの表示（AC-05）・プレビュー（AC-08・AC-10）・行の状態（AC-11〜AC-14）・リクエストの本文が変わらないこと（AC-19）・送信の後の表示（AC-21）を jsdom で確かめる方法。見出しの 2 行（AC-04）・プレビューの見え方（AC-09）・主ボタンが見えること（AC-17）・配色（AC-25）・コントラスト（AC-26）・大きさ（AC-28）・双方向テキスト（AC-33）・キーボードでの操作（AC-36）・フォーカスの表示（AC-37）・支援技術が読み上げる名前と状態（AC-38・AC-39）・色覚（AC-40）のうち、手動の確認に回すものと、その手順（Chrome と Brave、ライトとダーク、英語と日本語。読み上げは macOS の VoiceOver など）。要素の役割と名前（AC-38）は jsdom で確かめられる範囲がある。
-   **H-11: README の更新とガードのテスト（AC-31）。** README のポップアップの説明（`README.md:1013-1027`）を書き直すとき、ボタンの名前や引用する文言を英語の文言の表と比べるガードのテストを加えるかを決める（今は促しのメッセージだけを比べる、`extension/test/metadataDocs.test.ts:28-33`）。
-   **H-12: 用語集への追加（AC-29）。** 本書 6 章の用語（セクション・確認の行・選択範囲の行・主ボタン・拒否のカード・収集の拒否の理由・リクエストの本文など）を `docs/translation_glossary.md` に加えるか。日本語の UI の文言に使う語を決める（モックアップは「字幕」「概要欄」「詳細」。用語集の「字幕」は yt-dlp の字幕ファイルを指すので、UI の行の名前に使うかを含める）。
