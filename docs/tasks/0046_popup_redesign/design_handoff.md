# 設計への申し送り：ポップアップの画面の再設計

要件定義（[01_requirements.md](01_requirements.md)）の検討で挙がった、設計で決める事項。`02_architecture.md` は、各項目について採った方法、または当てはまらない理由を記録する。

-   **H-01: #503 の状態を加えられる枠の構造（要件書 4.5、AC-17・AC-18）。** 今は `popup.html` の `#summary` と `#send` の 2 つの領域に描く（`extension/static/popup.html:9-10`）。動画の段・確認の段・操作の段・詳細を、どの領域と要素に描くか、操作の段の中身だけを状態ごとに入れ替える構造をどうするかを決める。#503 の生成中の状態の表示（段階ごとのチェックリスト、経過時間、`prefers-reduced-motion` で止めるアニメーション、issue #507）が入る余地を考える。
-   **H-02: 表示のための型の作り直し（AC-01〜AC-14）。** 今の要約の型（`OutcomeSummary`・`SummaryField`、`extension/src/core/types.ts:29-43`）と、要約の欄の表（`extension/src/ui/render.ts:47-53`）・メタデータの行の表（`extension/src/ui/render.ts:130-134`）は、ラベルと値の行を前提にしている。確認の行の状態（✓・⚠）と、⚠ の理由（折りたたまれている、送られない、大きすぎる）を、型の上の宣言として持つ形にする（`CLAUDE.md`「Declare, don't infer」）。
-   **H-03: 末尾のプレビューの切り詰めと表示（AC-06〜AC-08）。** 最後の 100 コードポイントを、サロゲートペアの途中で切らずに取り出す方法（今の `truncate`、`extension/src/core/summary.ts:14-21`、は先頭だけを扱う）。改行を空白に置き換える処理を表示の側に置き、送る値に影響させない。ポップアップの幅に収まらない末尾のプレビューで、最後の文字が見えるようにする CSS（前の側を省略する方法）と、`unicode-bidi: plaintext`・`dir="auto"` との組み合わせ（右から左の文字で始まる値で、どちらの側が切れるか）。
-   **H-04: 文言の表の変更（AC-15・AC-20・AC-26・AC-27）。** `Catalog`（`extension/src/core/i18n/catalog.ts:23-51`）の、要約とメタデータの欄の名前（`summaryLabels`・`metadataLabels`）を、新しい行の名前と状態の説明に置き換える方法。数を埋め込む文言（「12,345 文字・420 行」「全文・1,203 文字」）は、値を受け取る関数で組み立てる（0043 の決めたこと）。促しのメッセージの文言を短くする場合（モックアップは手順を 2 つの短い文にしている）は、README の引用と、それを比べるガードのテスト（`extension/test/metadataDocs.test.ts:28-33`）を同じ変更で直す。拒否のカードに見出しを付けるか（モックアップは「Select the transcript first」のような見出しと、理由の文を分けている）。
-   **H-05: 本文が大きすぎるときの表示の位置（AC-09）。** 今は、送れない理由を送信の領域に描く（`extension/src/launch.ts:211-216`・`extension/src/ui/renderSend.ts:37-45`）。字幕の行の中に描くには、本文の大きさの判定（`prepareSend`）を、確認の段を描く前に行う必要がある。判定の順序と、動画メタデータを含めた本文の大きさで判定することを保つ方法（0025 AC-08）を決める。
-   **H-06: 色とコントラストの確かめ方（AC-22・AC-23）。** ライトとダークの色を CSS の変数で持つか、`prefers-color-scheme` の media query で切り替えるか。今の `color-scheme: light dark`（`extension/static/style.css:2`）との関係。コントラスト比を確かめる方法（色の組の表から計算するテストか、手動の確認か）。
-   **H-07: 状態を文字で伝える方法（AC-24）。** ✓ と ⚠ の記号を `aria-hidden` にし、状態を表示する文字か、読み上げ用の文字で伝えるか。記号を、外部のフォントを使わずに描く方法（インラインの SVG か、文字か）。
-   **H-08: 押せる要素の大きさ（AC-25）。** `<details>` の `<summary>` を 44 CSS ピクセル以上にする方法。押せない主ボタンの見た目。
-   **H-09: 主ボタンが画面の外に出ないこと（要件書 2.1）。** Chrome のポップアップの大きさの上限（幅 800 px・高さ 600 px）の中で、確認の段の ⚠ の行が 2 つとも手順を持つとき、長い動画タイトル（2 行に収めるか）でも、主ボタンが開いた時点で見えるかを確かめる。モックアップの幅（360 px）と、今の `min-width: 20rem`（`extension/static/style.css:10`）の関係。
-   **H-10: テストの方法。** 段の順序（AC-01）・見出しの代替（AC-03）・プレビュー（AC-06・AC-08）・行の状態（AC-09〜AC-12）・送信の後の表示（AC-18）を jsdom で確かめる方法。末尾のプレビューの見え方（AC-07）・テーマ（AC-22）・コントラスト（AC-23）・読み上げ（AC-24）・大きさ（AC-25）・双方向テキスト（AC-30）のうち、手動の確認に回すものと、その手順（Chrome と Brave、ライトとダーク、英語と日本語）。
-   **H-11: README の更新とガードのテスト（AC-28）。** README のポップアップの説明（`README.md:1013-1027`）を書き直すとき、ボタンの名前や引用する文言を英語の文言の表と比べるガードのテストを加えるかを決める（今は促しのメッセージだけを比べる、`extension/test/metadataDocs.test.ts:28-33`）。
-   **H-12: 用語集への追加（AC-26）。** 本書 6 章の用語（段・確認の行・主ボタン・拒否のカードなど）を `docs/translation_glossary.md` に加えるか、日本語の UI の文言に使う語をどれにするか（モックアップは「字幕」「概要欄」「詳細」）。
