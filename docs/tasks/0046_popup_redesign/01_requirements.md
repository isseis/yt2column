## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張のポップアップの画面を、送る前に確かめたいことから順に読める構成へ作り直すための要件を定義する（[#507](https://github.com/isseis/yt2column/issues/507)）。

**背景:**

今のポップアップは、収集した値と動画メタデータを、同じ見た目の「ラベルと値」の行として縦に並べ、その下に送信のボタンを置く。

-   収集の要約は、タブのタイトル・URL・文字数・行数・プレビューの順に並ぶ（`extension/src/ui/render.ts:47-53`）。プレビューは選択範囲の先頭の 200 コードポイントで、末尾は表示しない（`extension/src/core/summary.ts:6`・`:46`）。
-   要約の下に、動画タイトル・チャンネル名・概要欄の本文が並び（`extension/src/ui/render.ts:130-134`）、概要欄が折りたたまれているときは、その下に促しのメッセージが同じ見た目で続く（`extension/src/ui/render.ts:170-172`）。
-   送信のボタン（`Send to yt2column`、`extension/src/core/i18n/en.ts:136`）と、送信中・送信の結果の文言は、その下の別の領域に出る（`extension/src/launch.ts:219-245`・`extension/static/popup.html:9-10`）。
-   収集が拒否されたときは、拒否の理由と手順だけを出し、ボタンを出さない（`extension/src/launch.ts:206-209`）。このときは動画メタデータを読まない（`extension/src/launch.ts:181-183`、0025 AC-04a）。本文が 4 MiB を超えるときは、要約を出したまま、送信の領域に理由を出し、ボタンを出さない（`extension/src/launch.ts:211-216`）。

issue #507 は、この並びの問題を 4 つ挙げる。確かめたい 3 点（正しい動画か、字幕をすべて選べているか、概要欄は全文か）が見るべき順に並んでいない。タブのタイトルと動画タイトル、文字数と行数が別の行に分かれて重複している。概要欄の警告がほかの項目と同じ見た目で目立たない。項目が多いとボタンが画面の外に出る。

本タスクは親 issue [#501](https://github.com/isseis/yt2column/issues/501) の子 issue の 1 つで、UI の多言語化（[#506](https://github.com/isseis/yt2column/issues/506)、タスク `0043_extension_i18n`）の上に作る。Service Worker からの送信と Viewer（[#503](https://github.com/isseis/yt2column/issues/503)）は、本タスクの完了を待つ（#501 の「子 issue（タスク）」）。

対応 issue: [#507](https://github.com/isseis/yt2column/issues/507)（親: [#501](https://github.com/isseis/yt2column/issues/501)、前提: [#506](https://github.com/isseis/yt2column/issues/506)、関連: [#503](https://github.com/isseis/yt2column/issues/503)）

**本書の記述範囲:** 本書は、ポップアップの各状態で何をどの順に表示し、どの行を警告とし、ボタンがいつ押せるかという観測できる振る舞いと、表示が満たすべき見やすさの基準を定める。英語と日本語の文言の正確な字句、色の値、画面の寸法、要素の構造、テストの方法は設計（`02_architecture.md`）で決める。本書の用語は 6 章で定義する。要件の検討で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #507 で決めたこと（2026-10-25）:**

モックアップ: https://claude.ai/artifact/PbvqApgFfSC7hi86DV34RG （以下「モックアップ」）

-   **3 段の構成:** 動画の段（動画タイトルとチャンネル名）、確認の段、操作の段の順に並べる。確かめたい 3 点を見るべき順に並べるためである。
-   **確認の段:** 字幕と概要欄の状態を ✓ と ⚠ で示す。字幕は文字数と行数を 1 行にまとめ、先頭と末尾を 1 行ずつ見せる。末尾を見せるのは、選択範囲が最後まで届いていないことに気づけるようにするためである。警告がある行だけを色付きで目立たせ、手順もその行の中に置く。モックアップでは、概要欄の行は本文を出さず、状態と文字数だけを出す。
-   **操作:** 主ボタンを幅いっぱいに置く。名前は「Generate article」（日本語は「記事を生成する」）。項目が多くてもボタンが詳細より上に来るようにするためである。
-   **詳細は畳む:** URL とタブのタイトルは `<details>` の中に入れる。動画タイトルとの重複をなくし、常に見る必要のない値を後ろへ回すためである。
-   **拒否されたとき:** 項目を並べず、理由と手順のカード 1 枚にする。
-   **#503 の状態:** 生成中・生成済み・失敗の状態は、同じ 3 段の枠の中で切り替える。本タスクでは枠組みだけを用意し、それぞれの状態は #503 で実装する。
-   **ライトとダーク:** どちらのテーマでも表示できるようにする。
-   **多言語:** #506 の土台の上に、英語と日本語の文言を書く。
-   **今のまま保つこと:** 値は `textContent` だけで設定する。双方向テキストの扱い（`unicode-bidi: plaintext`、`dir="auto"`）を保つ。外部のフォントやライブラリを使わない。押せる要素の大きさは 44px 以上にする。

**要件定義の際に決めたこと（2026-10-27）:**

-   **拒否のときは動画の段を出さない（issue の「決める必要があること」）:** 収集が拒否されたときは、今と同じく動画メタデータを読まず、拒否のカードだけを出す（F-005）。必要な操作は選択範囲を作ることで、動画の見出しはその助けにならず、拒否のときにページを読む場面を増やす理由もないためである。
-   **字幕の末尾のプレビューの長さ（issue の「決める必要があること」）:** 先頭のプレビューは選択範囲の最初の 100 コードポイント、末尾のプレビューは最後の 100 コードポイントとする。改行は表示のときだけ空白に置き換え、それぞれを 1 行で見せる（F-002）。issue の「1 行ずつ」を、選択範囲の最初と最後の行と読むと、形 B では先頭の行が時刻だけになる。また、パネル全体を選んだときは、末尾の行が操作のラベル（`Sync to video time` など。サーバは読み飛ばす）になり、最後の字幕が見えない。コードポイントで切り出せば、形 A と形 B のどちらでも時刻と本文が見え、末尾に操作のラベルがあっても最後の字幕がたいてい見える。選択範囲の中身を形として解釈しないので、`CLAUDE.md` の「Declare, don't infer」の例外も要らない。選択範囲が 100 コードポイント以下のときは、末尾のプレビューを出さない。出しても先頭のプレビューと同じ文字列になるためである。
-   **概要欄が取れなかったときは ⚠ にする:** 概要欄の値を送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）は、概要欄の行を ⚠ にし、送られないことを示す。手順は付けない（F-003）。✓ と ⚠ の二値に収め、概要欄が記事の素材に入らないことを送る前に知らせるためである。概要欄のない動画でも ⚠ が出るが、まれなので許容する。
-   **動画タイトルが取れなかったときはタブのタイトルを見出しにする:** 動画タイトルを送らないときは、動画の段の見出しにタブのタイトルを出す。チャンネル名の行は、チャンネル名を送るときだけ出す（F-001）。タブのタイトルは、収集の時点で空でないことが保証されているので（空なら `empty-title` で拒否される、`extension/src/core/types.ts:6`）、どの動画かを見分けられる。
-   **本文が大きすぎるときは字幕の行を ⚠ にする:** 本文が 4 MiB を超えて送れないときは、字幕の行を ⚠ にし、理由と手順をその行の中に置き、主ボタンを押せない状態で出す（F-002・F-004）。原因は字幕の量なので、確認の段に収まるためである。
-   **拒否のカードの下に、押せない主ボタンを出す:** モックアップに合わせ、拒否のカードの下に、押せない状態の主ボタンを出す（F-005）。今はボタンを出さない（`extension/src/launch.ts:206-209`）。本文が大きすぎるときと同じく、このポップアップで何をするのかが分かるようにするためである。issue の「カード 1 枚にする」は、項目の代わりにカードを置くという意味に読む。
-   **主ボタンの名前は本タスクで変え、送信の振る舞いと文言は変えない:** 主ボタンの名前を「Generate article」（「記事を生成する」）に変える。送信の経路（`202` を受けたら結果は Slack に届く）、送信中と送信の結果の文言は変えず、操作の段の中、主ボタンの下に出す（F-004）。issue がボタンの名前を決めており、ボタンを押すと記事の生成が始まるという点で、名前は今の振る舞いとも合う。送信の経路と結果の文言は #503 で変わるので、本タスクで書き直すと二度手間になる。
-   **README を新しい画面に合わせる:** README の「Browser extension」の節にあるポップアップの説明（ボタンの名前と、表示する項目。`README.md:1013-1027`）を、新しい画面に合わせる（F-007）。直さないと、ボタンの名前と表示の説明が画面と食い違うためである。
-   **見やすさの基準を加える:** ✓ と ⚠ を、色と記号だけでなく文字でも伝える（読み上げ機能でも伝わるようにする）。文字のコントラストを、ライトとダークの両方で 4.5:1 以上にする（F-006）。⚠ の行が警告であることを、色を見分けにくい利用者や読み上げ機能の利用者にも伝えるためである。issue は「ライトとダーク」と「44px 以上」だけを定めているので、本書で加える。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   ポップアップを開いた利用者が、「正しい動画か」「字幕をすべて選べているか」「概要欄は全文か」の 3 点を、この順に上から確かめられるようにする。
-   警告がある項目だけを目立たせ、直す手順をその項目の中で示す。
-   項目が多くても、主ボタンが詳細より上に来るようにする。
-   #503 が、生成中・生成済み・失敗の状態を、同じ 3 段の枠の中に加えられるようにする。

### 2.2. スコープ (In Scope)

-   収集に成功したときの画面（動画の段・確認の段・操作の段・詳細）
-   収集が拒否されたときの画面（拒否のカードと押せない主ボタン）
-   本文が大きすぎるときの表示
-   送信中と送信の結果の、操作の段の中への配置（文言は変えない）
-   主ボタンの名前の変更
-   新しく表示する文言の、英語と日本語の文言の表への追加
-   ライトとダークのテーマ、文字のコントラスト、✓ と ⚠ の文字による表現、押せる要素の大きさ
-   README のポップアップの説明の更新

### 2.3. スコープ外 (Out of Scope)

-   生成中・生成済み・失敗の各状態の実装、Service Worker からの送信、Viewer（issue #507 の「決めたこと」により #503 で行う）。
-   送信の経路と、送信中・送信の結果の文言の変更（1 章「要件定義の際に決めたこと」。#503 で変わるため）。
-   収集・動画メタデータの読み取り・送る本文の変更。何を集め、何を送るかは変えない（本タスクは表示だけを変える）。
-   拒否のときの動画メタデータの読み取り（1 章「要件定義の際に決めたこと」）。
-   選択範囲を形 A・形 B として解釈すること（1 章「要件定義の際に決めたこと」）。
-   言語の決め方と、英語・日本語以外の言語（0043 で決めたことを変えない）。
-   拡張の中で表示のテーマを切り替える設定（拡張は設定画面を持たず、何も保存しない、`README.md:1002`）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 3 段の構成と動画の段

収集に成功したとき、ポップアップは上から、動画の段・確認の段・操作の段・詳細の順に表示する。動画の段は、どの動画の字幕を送るのかを示す。

**Acceptance Criteria**:
- **AC-01**: 収集に成功したとき、ポップアップは上から、動画の段・確認の段・操作の段・詳細の順に表示する。詳細は、ポップアップを開いた時点で閉じている。
- **AC-02**: 動画タイトルを送るとき、動画の段の見出しは動画タイトルである。チャンネル名を送るときは、見出しの下にチャンネル名を表示する。
- **AC-03**: 動画タイトルを送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）、動画の段の見出しはタブのタイトルである。チャンネル名を送らないときは、チャンネル名の行を表示しない。どちらの場合も、起動は成功し、送信に進める。
- **AC-04**: 詳細を開くと、収集した URL とタブのタイトルが表示される。URL とタブのタイトルは、AC-03 の見出しを除き、詳細の外には表示されない。

#### F-002: 字幕の行

確認の段の 1 行目は字幕の行である。選択範囲の大きさと、先頭と末尾を示し、選択範囲が最後まで届いているかを確かめられるようにする。

**Acceptance Criteria**:
- **AC-05**: 本文が送れる大きさのとき、字幕の行は ✓ の状態で、選択範囲の文字数と行数を 1 行に表示する。文字数と行数の数え方は今と同じ（文字数はコードポイントの数、行数は `\r\n`・`\r`・`\n` で区切った数、`extension/src/core/summary.ts:23-31`）で、数は選んだ言語の書式で表示する（0043 AC-13）。
- **AC-06**: 字幕の行は、選択範囲の最初の 100 コードポイントを先頭のプレビューとして、最後の 100 コードポイントを末尾のプレビューとして、それぞれ 1 行で表示する。表示の中では、改行（`\r\n`・`\r`・`\n` のそれぞれ）を 1 つの空白として表示する。切り詰めたプレビューには、切り詰めた側に省略記号を付ける（先頭のプレビューは後ろに、末尾のプレビューは前に）。サロゲートペアの途中で切らない。
- **AC-07**: ポップアップの幅に収まらない末尾のプレビューでは、選択範囲の最後の文字が見えている（見えなくなるのは末尾のプレビューの前の側である）。
- **AC-08**: 選択範囲が 100 コードポイント以下のときは、先頭のプレビューに選択範囲の全体を表示し、末尾のプレビューを表示しない。
- **AC-09**: 送る本文が 4 MiB（4,194,304 バイト）を超えるときは、字幕の行が ⚠ の状態になり、送れない理由と手順（選ぶ字幕の行を減らす）をその行の中に表示する。主ボタンは押せない状態で表示され、リクエストは送られない。理由の判定は今と同じ（0025 AC-08）である。

#### F-003: 概要欄の行

確認の段の 2 行目は概要欄の行である。送る概要欄が全文か、冒頭だけか、送られないかを示す。概要欄の本文は表示しない。

**Acceptance Criteria**:
- **AC-10**: 概要欄の値を送り、概要欄が折りたたまれていないとき、概要欄の行は ✓ の状態で、全文であることと、送る概要欄の文字数（コードポイントの数）を表示する。
- **AC-11**: 概要欄の値を送り、概要欄が折りたたまれているとき、概要欄の行は ⚠ の状態で、冒頭だけが送られることと、全文を送るための手順（動画の下の「…もっと見る」を開く、ポップアップを開き直す）を、その行の中に表示する。主ボタンは押せ、押すとページにある冒頭だけが送られる（0025 AC-13 を保つ）。
- **AC-12**: 概要欄の値を送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）、概要欄の行は ⚠ の状態で、概要欄が送られないことを表示する。手順は表示しない。主ボタンは押せる。
- **AC-13**: 概要欄の行は、概要欄の本文を表示しない。0025 AC-11 のうち概要欄の本文を表示する部分は、本書の AC-10〜AC-12 に置き換わる（5 章）。
- **AC-14**: ⚠ の状態の行だけが、背景の色でほかの行と区別される。✓ の状態の行には、その色を付けない。

#### F-004: 操作の段

操作の段は、確認の段の直後に主ボタンを置き、送信中と送信の結果をその中に表示する。

**Acceptance Criteria**:
- **AC-15**: 主ボタンは操作の段の中で、ポップアップの内容の幅いっぱいに表示される。名前は、英語では `Generate article`、日本語では `記事を生成する` である。
- **AC-16**: 主ボタンを押すと、今と同じくリクエストを 1 回だけ送る。送信中と送信の後は、結果によらず押せない（0020 の振る舞い、`README.md:1016-1017`）。
- **AC-17**: 送信中の案内と送信の結果（文言とリクエスト ID）は、操作の段の中、主ボタンの下に表示される。その文言は、本タスクの前と同じである。
- **AC-18**: 送信中と送信の後も、動画の段・確認の段・詳細は表示されたまま変わらない。

#### F-005: 拒否のカード

収集が拒否されたとき（`not-watch-page`・`collection-failed`・`empty-selection`・`empty-title`）、ポップアップは拒否の理由と手順を 1 枚のカードにまとめて表示する。

**Acceptance Criteria**:
- **AC-19**: 収集が拒否されたとき、ポップアップは拒否のカードと、その下の押せない主ボタンだけを表示する。動画の段・確認の段・詳細は表示しない。
- **AC-20**: 拒否のカードは、拒否の理由ごとに異なる文言と、その理由の手順（手順がある理由のとき）を表示する。理由と手順の対応は、本タスクの前と変わらない（`extension/src/core/i18n/en.ts:5-27`、0043 で日本語版を加えたもの）。文言の字句は、設計で書き直してよい。
- **AC-21**: 収集が拒否されたとき、動画メタデータを読まない（0025 AC-04a を保つ）。

#### F-006: テーマと見やすさ

**Acceptance Criteria**:
- **AC-22**: ポップアップは、ブラウザ（OS）のライトとダークの設定（`prefers-color-scheme`）に合わせて表示される。どちらのテーマでも、F-001〜F-005 の表示のすべてが表示される。
- **AC-23**: ライトとダークの両方で、文字（✓ と ⚠ の行、警告の行の手順、ボタンの名前を含む）と、その背景のコントラスト比は 4.5:1 以上である。押せない主ボタンの名前は、この基準の対象外とする（WCAG 2.2 の達成基準 1.4.3 が、使えない UI の部品を除外するのに合わせる）。
- **AC-24**: 確認の段の各行の状態（✓ か ⚠ か）は、色と記号だけでなく、文字でも伝わる。読み上げ機能は、各行の状態を読み上げる。
- **AC-25**: ポップアップの押せる要素（主ボタン、詳細の開閉）は、幅と高さがそれぞれ 44 CSS ピクセル以上である。

#### F-007: 文言と README

**Acceptance Criteria**:
- **AC-26**: 本タスクで新しく表示する文言（段と行の名前、✓ と ⚠ の状態の説明、拒否のカードの文言、主ボタンの名前など）は、英語と日本語の両方の文言の表にある。日本語の文言は `docs/translation_glossary.md` の用語に合わせる（0043 AC-10 と同じ）。
- **AC-27**: 手順の中で示す YouTube のボタンの名前は、0043 AC-11 で決めた表記である（拡張の言語に合わせる）。
- **AC-28**: README の「Browser extension」の節は、主ボタンの名前を `Generate article` と書き、ポップアップに表示する内容（動画の段・確認の段とその警告・主ボタン・詳細）を新しい画面に合わせて説明する。README が引用するポップアップの英語の文言は、英語の文言の表の文言と一致する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   表示だけを変える。ページの読み取りの回数とリクエストの回数は、本タスクの前と変わらない（AC-16・AC-21）。

### 4.2. セキュリティ (Security)

`docs/dev/security.md` の適用の条件（外部コマンドの呼び出し、API キー・Webhook URL の扱い、キャッシュのディレクトリの読み書き、ネットワークへの送信、信頼できないテキストのプロンプトや公開する記事への埋め込み）には当たらない: N/A。本タスクは、ポップアップの中に値を表示する方法だけを変える。

ポップアップは、信頼できないテキスト（選択範囲、タブのタイトル、URL、動画タイトル、チャンネル名）を表示する。今の扱い（0025 の 4.2・AC-14）を保つ。

- **AC-29**: 動画の段の見出し・チャンネル名・先頭と末尾のプレビュー・詳細の URL とタブのタイトルに `<img src=x onerror=alert(1)>` のような文字列を含めても、要素にならない（`querySelector("img")` が `null` で、`textContent` に元の文字列が含まれる）。
- **AC-30**: 動画タイトル・チャンネル名・選択範囲の先頭と末尾・タブのタイトルに双方向の制御文字（U+202E など）を含めても、ほかの値・行の名前・状態の文字の表示順が変わらない。
- **AC-31**: ポップアップは、外部のフォント・スタイルシート・スクリプトを読み込まない。拡張のページで、外部から取得したスクリプトや文字列から生成したコードを実行せず、Manifest V3 の既定の Content Security Policy を緩めない（0007 の制約を保つ）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   ポップアップの起動と送信は、本タスクの前と同じく例外を投げずに完了する（`extension/src/launch.ts:161-164`・`:195-198`）。表示の失敗が、送信の回数を変えない（AC-16）。

### 4.4. 互換性 (Compatibility)

-   Chrome と Brave で動作する（0007 以来の対象）。
- **AC-32**: manifest の権限（ホストの権限を含む）が、本タスクの前と変わらない。
-   信頼できない入力の境界: 本タスクは新しい入力を受け取らない。すでに受理した値（収集の結果、0025 の動画メタデータの受理の結果と折りたたみの印、本文の大きさの判定の結果）だけを表示に使う。受理の形・拒否の理由・上限は、それぞれの要件書（0007、0025、0020）のとおりで、変えない。

### 4.5. 保守性 (Maintainability)

-   #503 が、生成中・生成済み・失敗の状態を、動画の段と確認の段を作り直さずに操作の段の中へ加えられる構造にする（issue #507 の「決めたこと」）。どの構造にするかは設計で決める（design_handoff.md H-01）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   `CLAUDE.md` の拡張の言語の規則に従う。利用者に見せる文言は英語と日本語の文言の表に置き、両方を必須にする（0043）。
-   拡張の npm のパッケージは開発用に限り、出荷するコードはこのリポジトリが書くものだけにする（`CLAUDE.md`「Dependencies」）。表示のためのライブラリやフォントを加えない（AC-31）。
-   **先行タスクの要件の変更:** 0025 AC-11（`docs/tasks/0025_extension_video_metadata/01_requirements.md:124`）は、ポップアップに概要欄の本文を表示すると定める。本タスクは、概要欄の本文を表示せず、状態と文字数だけを表示する（AC-10〜AC-13）。理由は、issue #507 のモックアップが概要欄の行を状態と文字数だけで示しており、確かめたいのは本文の中身ではなく、全文が送られるかどうかだからである。動画タイトルとチャンネル名の表示、表示だけを切り詰めること、本文には切り詰める前の値を入れることは、0025 AC-11 のとおり保つ。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。本書で加える用語は次のとおり。

| 用語 | 英語 | 意味 |
|---|---|---|
| 段 | section | ポップアップの縦の区分。動画の段・確認の段・操作の段の 3 つ |
| 動画の段 | video section | 動画の見出し（動画タイトル、または取れないときはタブのタイトル）とチャンネル名を表示する段 |
| 確認の段 | checks section | 字幕の行と概要欄の行を表示する段 |
| 操作の段 | action section | 主ボタンと、送信中と送信の結果を表示する段。#503 の状態もここに加わる |
| 確認の行 | check row | 確認の段の 1 行。✓ か ⚠ の状態を持つ。字幕の行と概要欄の行がある |
| 主ボタン | primary button | 操作の段の、送信を始めるボタン（`Generate article`） |
| 詳細 | details | URL とタブのタイトルを入れた、開閉できる区分 |
| 拒否のカード | rejection card | 収集が拒否されたときに、理由と手順をまとめて表示する 1 枚の区分 |
| 先頭のプレビュー | head preview | 選択範囲の最初の 100 コードポイントの表示 |
| 末尾のプレビュー | tail preview | 選択範囲の最後の 100 コードポイントの表示 |
| 選択範囲 | selection | 利用者が文字起こしパネルで選んだ文字列。サーバへはコピーした字幕として送る |
