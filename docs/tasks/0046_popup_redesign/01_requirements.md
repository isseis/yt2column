## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張のポップアップの画面を、送る前に確かめたいことから順に読める構成へ作り直すための要件を定義する（[#507](https://github.com/isseis/yt2column/issues/507)）。

**背景:**

本書の用語（「収集の拒否の理由」「リクエストの本文」など）は 6 章で定義する。

今のポップアップは、収集した値と動画メタデータを、同じ見た目の「ラベルと値」の行として縦に並べ、その下に送信のボタンを置く。

-   収集の要約は、タブのタイトル・URL・文字数・行数・プレビューの順に並ぶ（`extension/src/ui/render.ts:47-53`）。プレビューは選択範囲の先頭の 200 コードポイントで、末尾は表示しない（`extension/src/core/summary.ts:6`・`:42`・`:51-52`）。
-   要約の下に、動画タイトル・チャンネル名・概要欄の文章が並び（`extension/src/ui/render.ts:130-134`）、概要欄が折りたたまれているときは、その下に促しのメッセージが、警告の見た目を持たない通常の文として続く（`extension/src/ui/render.ts:75-91`・`:170-172`）。
-   送信のボタン（`Send to yt2column`、`extension/src/core/i18n/en.ts:136`）と、送信中・送信の結果の文言は、その下の別の領域に出る（`extension/src/launch.ts:218-244`・`extension/static/popup.html:9-10`）。
-   収集の要約は、動画メタデータを読む前に表示され、動画メタデータはその後に加わる（`extension/src/launch.ts:180`・`:184-190`）。送信のボタンは、両方が終わってから表示される（`extension/src/launch.ts:267-271`）。
-   収集が拒否されたときは、収集の拒否の理由と手順だけを出し、ボタンを出さない（`extension/src/launch.ts:206-209`）。このときは動画メタデータを読まない（`extension/src/launch.ts:181-183`、0025 AC-04a）。リクエストの本文が 4 MiB を超えるときは、要約を出したまま、送信の領域に理由を出し、ボタンを出さない（`extension/src/launch.ts:211-216`）。

issue #507 は、この並びの問題を 4 つ挙げる。確かめたい 3 点（正しい動画か、字幕をすべて選べているか、概要欄は全文か）が見るべき順に並んでいない。タブのタイトルと動画タイトル、文字数と行数が別の行に分かれて重複している。概要欄の警告がほかの項目と同じ重さで並び、目立たない。項目が多いとボタンが画面の外に出る。

本タスクは親 issue [#501](https://github.com/isseis/yt2column/issues/501) の子 issue の 1 つで、UI の多言語化（[#506](https://github.com/isseis/yt2column/issues/506)、タスク `0043_extension_i18n`）の上に作る。Service Worker からの送信と Viewer（[#503](https://github.com/isseis/yt2column/issues/503)）は、本タスクの完了を待つ（#501 の「子 issue（タスク）」）。

対応 issue: [#507](https://github.com/isseis/yt2column/issues/507)（親: [#501](https://github.com/isseis/yt2column/issues/501)、前提: [#506](https://github.com/isseis/yt2column/issues/506)、関連: [#503](https://github.com/isseis/yt2column/issues/503)）

**本書の記述範囲:** 本書は、ポップアップの各状態で何をどの順に表示し、どの行を警告とし、主ボタンをいつ押せるかという観測できる振る舞いと、表示が満たすべき見やすさの基準を定める。英語と日本語の文言の正確な字句、色の値、画面の寸法、要素の構造、テストの方法は設計（`02_architecture.md`）で決める。本書の用語は 6 章で定義する。要件の検討で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #507 で決めたこと（2026-10-25）:**

モックアップ: https://claude.ai/artifact/PbvqApgFfSC7hi86DV34RG （以下「モックアップ」）

-   **3 段の構成:** 動画の段（動画タイトルとチャンネル名）、確認の段、操作の段の順に並べる。
-   **確認の段:** 選択範囲と概要欄の状態を ✓ と ⚠ で示す。選択範囲は文字数と行数を 1 行にまとめ、先頭と末尾を 1 行ずつ見せる（末尾を見せるのは、選択範囲が足りないことに気づくため）。警告がある行だけを色付きで目立たせ、手順もその行の中に置く。
-   **操作:** 主ボタンを幅いっぱいに置く。名前は「Generate article」（日本語は「記事を生成する」）。
-   **詳細は畳む:** URL とタブのタイトルは `<details>` の中に入れる。
-   **拒否されたとき:** 項目を並べず、理由と手順のカード 1 枚にする。
-   **#503 の状態:** 生成中・生成済み・失敗の状態は、同じ 3 段の構成の中で切り替える。本タスクでは枠組みだけを用意し、それぞれの状態は #503 で実装する。
-   **ライトとダーク:** どちらのテーマでも表示できるようにする。
-   **多言語:** #506 の土台の上に、英語と日本語の文言を書く。
-   **今のまま保つこと:** 値は `textContent` だけで設定する。双方向テキストの扱い（`unicode-bidi: plaintext`、`dir="auto"`）を保つ。外部のフォントやライブラリを使わない。押せる要素の大きさは 44px 以上にする。このうち 44px の規則は、issue が「今のまま保つこと」に挙げているが、今の送信のボタンには大きさの規則がない（`extension/static/style.css` に `.send-button` の規則がない）。本書では AC-28 で新しく要件にする。

**要件定義の際に決めたこと（2026-10-27）:**

-   **モックアップは例示とする:** 必須とするのは、本書の受け入れ基準に書いたことだけとする。モックアップのうち受け入れ基準に書いていない要素（最上部の製品名 `YT2COLUMN`、プレビューの書体、アイコンの形、拒否のカードの見出しなど）は、設計で採るかどうかを決めてよい。製品名は、各段の上に表示してもよい。モックアップは画面の方向を示すもので、細部まで要件にすると設計の自由を不必要に縛るためである。
-   **拒否のときは動画の段を出さない（issue の「決める必要があること」）:** 収集が拒否されたときは、今と同じく動画メタデータを読まず、拒否のカードだけを出す（F-005）。必要な操作は選択範囲を作ることで、動画の見出しはその助けにならず、拒否のときにページを読む場面を増やす理由もないためである。
-   **末尾のプレビューの長さ（issue の「決める必要があること」）:** 先頭のプレビューは選択範囲の最初の 100 コードポイント、末尾のプレビューは最後の 100 コードポイントとする。改行は表示のときだけ空白に置き換え、それぞれを 1 行で見せる（F-002）。issue の「1 行ずつ」を、選択範囲の最初と最後の行と読むと、形 B では先頭の行が時刻だけになる。また、パネル全体を選んだときは、末尾の行が操作のラベル（`Sync to video time` など。サーバは読み飛ばす）になり、最後の字幕が見えない。コードポイントで切り出せば、形 A と形 B のどちらでも時刻と字幕の文が見え、末尾に操作のラベルがあっても最後の字幕がたいてい見える。選択範囲の中身を形 A・形 B として解釈しないので、`CLAUDE.md` の「Declare, don't infer」の例外も必要ない。選択範囲が 100 コードポイント以下のときは、末尾のプレビューを出さない。出しても先頭のプレビューと同じ文字列になるためである。
-   **選択範囲の行の ✓ は、送れる大きさであることだけを表す:** 拡張は、選択範囲が字幕のすべてを含むか、文字起こしパネルの書式に合うかを判定できない（書式はサーバが判定する、0024）。✓ は、リクエストの本文が上限以下で送れることだけを表し、状態の文言も「すべて選べている」とは言わない（AC-07）。すべて選べているかは、利用者が末尾のプレビューで確かめる。判定できないことを ✓ で示すと、利用者に誤解させるためである。
-   **概要欄が取れなかったときは ⚠ にする:** 概要欄の値を送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）は、概要欄の行を ⚠ にし、送られないことを示す。手順は付けない（F-003）。✓ と ⚠ の二値に収め、概要欄が記事の素材に入らないことを送る前に知らせるためである。概要欄のない動画でも ⚠ が出るが、まれなので許容する。
-   **動画タイトルが取れなかったときはタブのタイトルを見出しにする:** 動画タイトルを送らないときは、動画の段の見出しにタブのタイトルを出す。チャンネル名の行は、チャンネル名を送るときだけ出す（F-001）。タブのタイトルは、収集の時点で空でないことが保証されているので（空なら `empty-title` で拒否される、`extension/src/core/types.ts:6`）、どの動画かを見分けられる。
-   **見出しは 2 行までにし、ポップアップを開いた時点で主ボタンが見えることを要件にする:** 見出しは 2 行までに収め、超えた分は省略記号で示す。そのうえで、確認の段の 2 行がどちらも ⚠ で手順を持つときでも、ポップアップを開いた時点で、スクロールせずに主ボタンの全体が見えることを要件にする（AC-04・AC-17）。issue が挙げる「ボタンが画面の外に出る」問題は、表示の順序だけでは解けず、高さが伸びる要素を抑える必要があるためである。見出しの 2 行はモックアップに合わせた。
-   **読み取りと判定が終わってから一度に表示する:** 収集・動画メタデータの読み取り・リクエストの本文の大きさの判定がすべて終わるまでは、動画の段と確認の段を表示せず、主ボタンを押せない状態にする。終わったら、各段を一度に表示する（AC-05）。見出しは動画メタデータの読み取りの結果で決まり、選択範囲の行の状態は大きさの判定の結果で決まるので、途中の表示は後で差し替わる。差し替わる表示は読みにくく、判定の前にボタンを押せてしまう余地も生むためである。
-   **本文が大きすぎるときは選択範囲の行を ⚠ にする:** リクエストの本文が 4 MiB を超えて送れないときは、選択範囲の行を ⚠ にし、理由と手順をその行の中に置き、主ボタンを押せない状態で出す（F-002・F-004）。原因は選択範囲の量であり、確認の段で扱うのが自然なためである。
-   **拒否のカードの下に、押せない主ボタンを出す:** モックアップに合わせ、拒否のカードの下に、押せない状態の主ボタンを出す（F-005）。今はボタンを出さない（`extension/src/launch.ts:206-209`）。本文が大きすぎるときと同じく、このポップアップで何をするのかが分かるようにするためである。issue の「カード 1 枚にする」は、項目の代わりにカードを置くという意味に読む。
-   **主ボタンの名前は本タスクで変え、送信の振る舞いと文言は変えない:** 主ボタンの名前を「Generate article」（「記事を生成する」）に変える。送信の経路（`202` を受けたら結果は Slack に届く）、送信中と送信の結果の文言は変えず、操作の段の中、主ボタンの下に出す。送信中と送信の後も、動画の段と確認の段はそのまま残す（F-004）。issue がボタンの名前を決めており、ボタンを押すと記事の生成が始まるという点で、名前は今の振る舞いとも合う。送信の経路と結果の表示は #503 で変わるので、本タスクで書き直すと二度手間になる。
-   **README を新しい画面に合わせる:** README の「Browser extension」の節にあるポップアップの説明（ボタンの名前と、表示する項目。`README.md:1013-1027`）を、新しい画面に合わせる（F-007）。直さないと、ボタンの名前と表示の説明が画面と食い違うためである。
-   **見やすさの基準を加える:** ✓ と ⚠ を、色と記号だけでなく文字でも伝える（支援技術にも伝わるようにする）。文字のコントラストを、ライトとダークの両方で 4.5:1 以上にする（F-006）。⚠ の行が警告であることを、色を見分けにくい利用者や支援技術の利用者にも伝えるためである。issue は「ライトとダーク」と「44px 以上」だけを定めているので、本書で加える。

**PR のレビューで決めたこと（2026-10-28）:**

-   **視覚に障害のある利用者が使える基準を加える:** 次の 4 点を受け入れ基準にする（F-006、AC-36〜AC-40）。基準は WCAG 2.2 の達成基準（レベル AA）に合わせる。
    -   ポインティングデバイスを使わず、キーボードだけで操作でき、フォーカスの位置が見える。
    -   主ボタンや詳細の開閉などに、支援技術が読み上げる適切な名前と状態があり、送信中の案内と送信の結果も読み上げられる。
    -   文字と図形のコントラストを保つ（AC-26 を、⚠ の行の背景の上の文字とフォーカスの表示にも広げる）。
    -   赤と緑を見分けにくい色覚でも、✓ と ⚠ の区別がつく色を使う。

    レビューで、視覚と聴覚に障害のある利用者が使えることを要件に含めると決めたためである。ポップアップは音声や動画を再生しないので、聴覚についての基準は当てはまらない。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   ポップアップを開いた利用者が、「正しい動画か」「字幕をすべて選べているか（末尾のプレビューで利用者が確かめる）」「概要欄は全文か」の 3 点を、この順に上から確かめられるようにする。
-   警告がある項目だけを目立たせ、直す手順をその項目の中で示す。
-   項目が多くても、ポップアップを開いた時点で主ボタンが見えるようにする。
-   #503 が、生成中・生成済み・失敗の状態を、同じ 3 段の構成の中に加えられるようにする。

### 2.2. スコープ (In Scope)

-   収集に成功したときの画面（動画の段・確認の段・操作の段・詳細）
-   収集が拒否されたときの画面（拒否のカードと押せない主ボタン）
-   リクエストの本文が大きすぎるときの表示
-   読み取りと判定が終わるまでの表示
-   送信中と送信の結果の、操作の段の中への配置（文言は変えない）
-   主ボタンの名前の変更
-   新しく表示する文言（英語と日本語）の、文言の表への追加
-   ライトとダークのテーマ、文字のコントラスト、✓ と ⚠ の文字による表現、押せる要素の大きさ
-   キーボードだけでの操作、フォーカスの表示、支援技術が読み上げる名前と状態、赤と緑を見分けにくい色覚への配慮
-   README のポップアップの説明の更新

### 2.3. スコープ外 (Out of Scope)

-   生成中・生成済み・失敗の各状態の実装、Service Worker からの送信、Viewer（issue #507 の「決めたこと」により #503 で行う）。
-   送信の経路と、送信中・送信の結果の文言の変更（1 章「要件定義の際に決めたこと」。#503 で変わるため）。
-   収集・動画メタデータの読み取り・リクエストの本文の変更。何を集め、何を送るかは変えない（AC-19）。
-   拒否のときの動画メタデータの読み取り（1 章「要件定義の際に決めたこと」）。
-   選択範囲を形 A・形 B として解釈すること、選択範囲が字幕のすべてを含むかの判定（1 章「要件定義の際に決めたこと」）。
-   言語の決め方と、英語・日本語以外の言語（0043 で決めたことを変えない）。
-   拡張の中で表示のテーマを切り替える設定（拡張は設定画面を持たず、何も保存しない、`README.md:1002`）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 3 段の構成と動画の段

収集に成功したとき、ポップアップは動画の段・確認の段・操作の段・詳細をこの順に表示する。動画の段は、どの動画の字幕を送るのかを示す。

**Acceptance Criteria**:
- **AC-01**: 収集に成功したとき、ポップアップは動画の段・確認の段・操作の段・詳細を、上からこの順に表示する（製品名を表示する場合は、各段より上に置く）。詳細は、ポップアップを開いた時点で閉じている。
- **AC-02**: 動画タイトルを送るとき、動画の段の見出しは動画タイトルである。チャンネル名を送るときは、見出しの下にチャンネル名を表示する。
- **AC-03**: 動画タイトルを送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）、動画の段の見出しはタブのタイトルである。チャンネル名を送らないときは、チャンネル名の行を表示しない。どちらの場合も、起動は成功し、送信に進める。
- **AC-04**: 見出しは、ポップアップの中で 2 行までに制限して表示する。2 行に収まらない場合は、2 行目の終わりに省略記号を付ける。見出しの元の値（動画タイトルかタブのタイトル）によらず、同じ規則で表示する。
- **AC-05**: 収集・動画メタデータの読み取り・リクエストの本文の大きさの判定がすべて終わるまで、ポップアップは動画の段と確認の段を表示せず、主ボタンは押せない。終わった時点で、各段を一度に表示する。表示した見出しと確認の行の状態は、その後に別の値へ差し替わらない。
- **AC-06**: 詳細を開くと、収集した URL とタブのタイトルが表示される。URL とタブのタイトルは、AC-03 の見出しを除き、詳細の外には表示されない。

#### F-002: 選択範囲の行

確認の段の 1 行目は選択範囲の行である。選択範囲の大きさと、先頭と末尾を示す。利用者は末尾のプレビューで、選択範囲が最後まで届いているかを確かめる。

**Acceptance Criteria**:
- **AC-07**: 選択範囲の行は、状態によらず、選択範囲の文字数と行数を 1 行に表示する。文字数と行数の数え方は今と同じ（文字数はコードポイントの数、行数は `\r\n`・`\r`・`\n` で区切った数、`extension/src/core/summary.ts:24-32`）で、数は選んだ言語の書式で表示する（0043 AC-13）。リクエストの本文が送れる大きさのとき、選択範囲の行は ✓ の状態である。✓ の状態の文言は、選択範囲が字幕のすべてを含むことや、書式が正しいことを述べない。
- **AC-08**: 選択範囲の行は、選択範囲の最初の 100 コードポイントを先頭のプレビューとして、最後の 100 コードポイントを末尾のプレビューとして、それぞれ 1 行で表示する。100 コードポイントは、改行を空白に置き換える前の、元の選択範囲に対して数える。表示の中では、改行（`\r\n`・`\r`・`\n` のそれぞれ）を 1 つの空白として表示し、ほかの文字は変えない。100 コードポイントで切り詰めたプレビューには、切り詰めた側に省略記号を付ける（先頭のプレビューは後ろに、末尾のプレビューは前に）。サロゲートペアの途中で切らない。
- **AC-09**: ポップアップの幅に収まらないプレビューは、1 行のまま、見えない部分があることを省略記号で示す。先頭のプレビューでは選択範囲の最初の文字が、末尾のプレビューでは選択範囲の最後の文字が見えている（見えなくなるのは、先頭のプレビューでは後ろの側、末尾のプレビューでは前の側である）。
- **AC-10**: 選択範囲が 100 コードポイント以下のときは、先頭のプレビューに選択範囲の全体を表示し、末尾のプレビューを表示しない。
- **AC-11**: リクエストの本文が 4 MiB（4,194,304 バイト）を超えるときは、選択範囲の行が ⚠ の状態になり、送れない理由と手順（選ぶ字幕を減らす）をその行の中に表示する。主ボタンは押せない状態で表示され、リクエストは送られない。大きさの判定は今と同じ（0020 AC-16、0025 AC-08）である。

#### F-003: 概要欄の行

確認の段の 2 行目は概要欄の行である。送る概要欄が全文か、冒頭だけか、送られないかを示す。概要欄の文章は表示しない。

**Acceptance Criteria**:
- **AC-12**: 概要欄の値を送り、概要欄が折りたたまれていないとき、概要欄の行は ✓ の状態で、全文であることと、送る概要欄の文字数（コードポイントの数）を表示する。
- **AC-13**: 概要欄の値を送り、概要欄が折りたたまれているとき、概要欄の行は ⚠ の状態で、冒頭だけが送られることと、全文を送るための手順（動画の下の「…もっと見る」を開く、ポップアップを開き直す）を、その行の中に表示する。文字数は表示しない。概要欄の行のこの状態は、主ボタンを押せなくしない。リクエストの本文が送れる大きさなら（AC-11）、主ボタンは押せ、押すとページにある冒頭だけが送られる（0025 AC-13 を保つ）。
- **AC-14**: 概要欄の値を送らないとき（ページにない、空白文字だけ、対になっていないサロゲートを含む、読み取りの失敗）、概要欄の行は ⚠ の状態で、概要欄が送られないことを表示する。手順は表示しない。この状態も、主ボタンを押せなくしない（主ボタンを押せるかは AC-11 で決まる）。
- **AC-15**: 概要欄の行は、概要欄の文章を表示しない（5 章の、0025 AC-11 の変更）。
- **AC-16**: ⚠ の状態の行だけが、背景の色でほかの行と区別される。✓ の状態の行には、その色を付けない。

#### F-004: 操作の段

操作の段は、確認の段の直後に主ボタンを置き、送信中と送信の結果をその中に表示する。

**Acceptance Criteria**:
- **AC-17**: 主ボタンは操作の段の中で、ポップアップの内容の幅いっぱいに表示される。名前は、英語では `Generate article`、日本語では `記事を生成する` である。見出しが 2 行で、確認の段の 2 行がどちらも ⚠ で手順を持つ場合（概要欄が折りたたまれ、かつリクエストの本文が大きすぎる場合）でも、各段を表示した時点（AC-05）で、スクロールせずに主ボタンの全体が見える。
- **AC-18**: 主ボタンを押すと、今と同じくリクエストを 1 回だけ送る。送信中と送信の後は、結果によらず押せない（0020 AC-20）。
- **AC-19**: 同じ収集の結果と動画メタデータからは、本タスクの前と同じリクエストの本文が送られる（メンバ・値・省略するメンバが変わらない。0025 AC-06・AC-07）。リクエストの本文の大きさの判定は、本タスクの前と同じく、動画メタデータを含めた本文で行う（0025 AC-08）。
- **AC-20**: 送信中の案内と送信の結果（文言とリクエスト ID）は、操作の段の中、主ボタンの下に表示される。その文言は、本タスクの前と同じである。
- **AC-21**: 送信中と送信の後も、動画の段・確認の段・詳細は表示されたまま変わらない。

#### F-005: 拒否のカード

収集が拒否されたとき（`not-watch-page`・`collection-failed`・`empty-selection`・`empty-title`）、ポップアップは収集の拒否の理由と手順を 1 枚のカードにまとめて表示する。

**Acceptance Criteria**:
- **AC-22**: 収集が拒否されたとき、ポップアップは拒否のカードと、その下の押せない主ボタンだけを表示する（製品名を表示する場合は、カードより上に置く）。動画の段・確認の段・詳細は表示しない。
- **AC-23**: 拒否のカードは、収集の拒否の理由ごとに、本タスクの前と同じ文と手順を表示する（`extension/src/core/i18n/en.ts:5-27` と、0043 で加えた日本語版）。理由ごとに互いに異なる文言が表示される（0007 AC-22 を保つ）。カードに見出しを加えるかは設計で決める（design_handoff.md H-04）。
- **AC-24**: 収集が拒否されたとき、動画メタデータを読まない（0025 AC-04a を保つ）。

#### F-006: テーマと見やすさ

ポップアップは、ライトとダークのどちらの配色でも読め、視覚に障害のある利用者も、キーボードと支援技術（スクリーンリーダーなど）で使える。

**Acceptance Criteria**:
- **AC-25**: ポップアップは、ブラウザが拡張のページに伝えるライトとダークの設定（`prefers-color-scheme`）に合わせて、ライトかダークの配色で表示される。どちらの配色でも、F-001〜F-005 で表示する文字と記号のすべてが、AC-26 の基準を満たす。
- **AC-26**: ライトとダークの両方で、文字（選択範囲の行と概要欄の行の文言、警告の行の手順、主ボタンの名前、拒否のカードの文と手順を含む。⚠ の行の背景の上の文字も含む）と、その背景のコントラスト比は 4.5:1 以上である。✓ と ⚠ の記号は、文字ではなく図形として、背景とのコントラスト比を 3:1 以上にする（WCAG 2.2 の達成基準 1.4.11）。押せない主ボタンの名前は、4.5:1 の対象外とする（WCAG 2.2 の達成基準 1.4.3 が、無効な UI の部品を除外するのに合わせる）。
- **AC-27**: 確認の行の状態（✓ か ⚠ か）は、色と記号だけでなく文字でも伝わる。各確認の行のテキスト（表示する文字か、支援技術に渡す名前）は、その行の状態を表す語を含む。
- **AC-28**: ポップアップの押せる要素（主ボタン、詳細の開閉）は、幅と高さがそれぞれ 44 CSS ピクセル以上である。
- **AC-36**: ポインティングデバイスを使わず、キーボードだけで、ポップアップのすべての操作（主ボタンを押す、詳細を開閉する）ができる。Tab と Shift+Tab で押せる要素の間を移動でき、移動の順序は、画面の上から下への表示の順序と同じである。主ボタンは Enter と Space で押せ、詳細は Enter と Space で開閉できる。フォーカスが 1 つの要素の中に閉じ込められることはない（WCAG 2.2 の達成基準 2.1.1・2.1.2・2.4.3）。押せない主ボタンには、フォーカスが移らなくてよい。
- **AC-37**: フォーカスのある要素は、フォーカスの表示（枠など）で、ほかの要素と見分けられる。フォーカスの表示と、それに隣り合う色のコントラスト比は、ライトとダークの両方で 3:1 以上である（WCAG 2.2 の達成基準 2.4.7・1.4.11）。
- **AC-38**: 支援技術は、ポップアップの要素を次のとおりに読み上げる（WCAG 2.2 の達成基準 1.3.1・2.5.3・4.1.2）。
    -   主ボタンは、ボタンとして、表示する名前（`Generate article`、`記事を生成する`）と同じ名前で伝わる。押せない状態のときは、押せないことも伝わる。
    -   詳細の開閉は、表示する名前と、開いているか閉じているかが伝わる。
    -   動画の段の見出しは見出しとして伝わる。AC-04 の 2 行での省略と AC-09 の幅による省略で見えない部分も、支援技術には伝わる。
    -   ✓ と ⚠ の記号は、記号の名前ではなく、AC-27 の状態を表す語として伝わる。
    -   ページの言語は、選んだ言語として伝わる（0043 AC-14 を保つ）。
- **AC-39**: 送信中の案内と送信の結果（AC-20）は、表示されたときに、フォーカスを動かさずに支援技術に伝わる（WCAG 2.2 の達成基準 4.1.3）。
- **AC-40**: ✓ と ⚠ の区別と、⚠ の行の背景（AC-16）は、赤と緑の色の違いに頼らない。1 型と 2 型の色覚（赤と緑を見分けにくい色覚）を模した表示でも、ライトとダークの両方で、⚠ の行と ✓ の行の区別がつき、✓ と ⚠ の記号を形で見分けられる。状態は色だけで伝えず、記号の形と AC-27 の文字でも伝える（WCAG 2.2 の達成基準 1.4.1）。

#### F-007: 文言と README

**Acceptance Criteria**:
- **AC-29**: 本タスクで新しく表示する文言（確認の行の名前、✓ と ⚠ の状態の説明、主ボタンの名前など）は、英語と日本語の両方の文言の表にある。日本語の文言は `docs/translation_glossary.md` の用語に合わせる（0043 AC-10 と同じ）。
- **AC-30**: 手順の中で示す YouTube のボタンの名前は、0043 AC-11 で決めた表記である（拡張の言語に合わせる）。
- **AC-31**: README の「Browser extension」の節は、主ボタンの名前を `Generate article` と書き、ポップアップに表示する内容（動画の段・確認の段とその警告・主ボタン・詳細）を新しい画面に合わせて説明する。README が引用するポップアップの英語の文言は、英語の文言の表の文言と一致する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   表示だけを変える。ページの読み取りの回数とリクエストの回数は、本タスクの前と変わらない（AC-18・AC-24）。

### 4.2. セキュリティ (Security)

`docs/dev/security.md` の適用の条件（外部コマンドの呼び出し、API キー・Webhook URL の扱い、キャッシュのディレクトリの読み書き、ネットワークへの送信、信頼できないテキストのプロンプトや公開する記事への埋め込み）には当たらない: N/A。本タスクは、ポップアップの中に値を表示する方法だけを変える。

ポップアップは、信頼できないテキスト（選択範囲、タブのタイトル、URL、動画タイトル、チャンネル名）を表示する。今の扱い（0025 の 4.2・AC-14）を保つ。

- **AC-32**: 動画の段の見出し・チャンネル名・先頭と末尾のプレビュー・詳細の URL とタブのタイトルに `<img src=x onerror=alert(1)>` のような文字列を含めても、要素にならない（`querySelector("img")` が `null` で、`textContent` に元の文字列が含まれる）。
- **AC-33**: 動画タイトル・チャンネル名・選択範囲の先頭と末尾・タブのタイトルに双方向の制御文字（U+202E など）を含めても、ほかの値、行の名前、状態の文字の表示順が変わらない。
- **AC-34**: ポップアップは、外部のフォント・スタイルシート・スクリプトを読み込まない。拡張のページで、外部から取得したスクリプトと、文字列から生成したコードを実行せず、Manifest V3 の既定の Content Security Policy を緩めない（0007 の制約を保つ）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   ポップアップの起動と送信は、本タスクの前と同じく例外を投げずに完了する（`extension/src/launch.ts:161-164`・`:195-198` の関数の説明）。リクエストを送る回数は AC-18 のとおりである。

### 4.4. 互換性 (Compatibility)

-   Chrome と Brave で動作する（0007 以来の対象）。

- **AC-35**: manifest の権限（ホストの権限を含む）が、本タスクの前と変わらない。
-   信頼できない入力の境界: 本タスクは新しい入力を受け取らない。すでに受理した値（収集の結果、0025 の動画メタデータの受理の結果と折りたたみの印、リクエストの本文の大きさの判定の結果）だけを表示に使う。受理の形・拒否の理由・上限は、それぞれの要件書（0007、0025、0020）のとおりで、変えない。

### 4.5. 保守性 (Maintainability)

-   #503 が、生成中・生成済み・失敗の状態を、同じ 3 段の構成の中で切り替えて加えられる構造にする（issue #507 の「決めたこと」）。どの構造にするかは設計で決め、設計のレビューで確かめる（design_handoff.md H-01）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   `CLAUDE.md` の拡張の言語の規則に従う。利用者に見せる文言は英語と日本語の文言の表に置き、両方を必須にする（0043）。
-   拡張の npm のパッケージは開発用に限り、出荷するコードはこのリポジトリが書くものだけにする（`CLAUDE.md`「Dependencies」）。表示のためのライブラリやフォントを加えない（AC-34）。
-   **先行タスクの要件の変更（0007 AC-21）:** 0007 AC-21（`docs/tasks/0007_browser_extension_skeleton/01_requirements.md:179`）は、収集に成功するとタイトル（タブのタイトル）・URL・文字数と行数・選択範囲の先頭の一部が表示されると定める。本タスクでは、URL とタブのタイトルは詳細を開いたときだけ表示される（AC-03 の見出しを除く。AC-06）。理由は、issue #507 が「詳細は畳む」と決め、動画タイトルと重複するタブのタイトルと、常に見る必要のない URL を後ろへ回すためである。文字数と行数、選択範囲の先頭の表示は保つ（AC-07・AC-08）。
-   **先行タスクの要件の変更（0025 AC-11）:** 0025 AC-11（`docs/tasks/0025_extension_video_metadata/01_requirements.md:124`）は、ポップアップに概要欄の文章を表示すると定める。本タスクでは、概要欄の文章を表示せず、状態と文字数だけを表示する（AC-12〜AC-15）。理由は、issue #507 のモックアップが概要欄の行を状態と文字数だけで示しており、確かめたいのは文章の中身ではなく、全文が送られるかどうかだからである。動画タイトルとチャンネル名の表示、表示だけを切り詰めること、リクエストの本文には切り詰める前の値を入れることは、0025 AC-11 のとおり保つ。見出しの表示は AC-04 の規則による。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。本書で加える用語は次のとおり。

| 用語 | 英語 | 意味 |
|---|---|---|
| 段 | section | ポップアップの縦の区分。動画の段・確認の段・操作の段の 3 つ |
| 動画の段 | video section | 見出しとチャンネル名を表示する段 |
| 見出し | heading | 動画の段の先頭に表示する、動画タイトル（取れないときはタブのタイトル） |
| 確認の段 | checks section | 選択範囲の行と概要欄の行を表示する段 |
| 操作の段 | action section | 主ボタンと、送信中と送信の結果を表示する段 |
| 確認の行 | check row | 確認の段の 1 行。✓ か ⚠ の状態を持つ。選択範囲の行と概要欄の行がある |
| 選択範囲の行 | selection row | 選択範囲の文字数と行数、先頭と末尾のプレビューを表示する確認の行。✓ はリクエストの本文が送れる大きさであることだけを表す |
| 概要欄の行 | description row | 送る概要欄が全文か、冒頭だけか、送られないかを表示する確認の行 |
| 主ボタン | primary button | 操作の段の、送信を始めるボタン（`Generate article`） |
| 詳細 | details | URL とタブのタイトルを入れた、開閉できる区分 |
| 拒否のカード | rejection card | 収集が拒否されたときに、収集の拒否の理由の文と手順をまとめて表示する 1 枚の区分 |
| 収集の拒否の理由 | collection rejection reason | 拡張が収集を拒否する理由（`RejectionReason`。`not-watch-page` など）。サーバが返す拒否の理由（`rejectReason`）とは別 |
| 先頭のプレビュー | head preview | 選択範囲の最初の 100 コードポイントの表示 |
| 末尾のプレビュー | tail preview | 選択範囲の最後の 100 コードポイントの表示 |
| 選択範囲 | selection | 利用者が文字起こしパネルで選んだ文字列。サーバへはコピーした字幕として送る |
| 支援技術 | assistive technology | スクリーンリーダーなど、画面の要素の名前と状態を利用者に伝える技術 |
| フォーカスの表示 | focus indicator | キーボードの操作の対象になっている要素を示す、枠などの見た目 |
| リクエストの本文 | request body | 拡張がサーバへ送る JSON の本文（`videoUrl`・`transcript` と動画メタデータ）。概要欄の文章とは別 |
