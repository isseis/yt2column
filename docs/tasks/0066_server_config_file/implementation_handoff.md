# 実装への申し送り：サーバが設定ファイルを読むようにする

要件定義（[01_requirements.md](01_requirements.md)）と設計（[02_architecture.md](02_architecture.md)）のレビューで挙がった、実装計画で決める事項。`03_implementation_plan.md` は、各項目にどう対応したか、または対応しない理由を記録する。

## I-01: `MkdirBelow` が作ったディレクトリのモードを umask によらず `0700` にする手順

- **懸念:** 設計（02_architecture.md 3.1）は、`MkdirBelow` が作った各ディレクトリのモードを umask によらずちょうど `0700` にすること、モードをそろえる対象を作ったディレクトリそのものに限ることを求める。作ったディレクトリを読み取り用に開いてから記述子にモードを設定する手順では、所有者の読み取りの権限を落とす umask（例: `0400`）のとき、`mkdir` が `0300` のディレクトリを作り、続く読み取り用の open が `EACCES` で失敗して、モードを設定する前に止まる（PR #706 のレビューで、Linux の非 root で再現が報告された）。
- **重要な理由:** この umask で `config init` が親のディレクトリを作れず失敗するか、モードが `0700` でないディレクトリが残る。AC-23 の「モード `0700` で作る」を満たさない。
- **対応の候補:** 読み取りの権限を要しない開き方（Linux の `O_PATH` は `fchmod` できないので不可。`O_SEARCH`/`O_EXEC` の可否は OS ごとに確かめる）を使う、親のディレクトリの記述子を基点に `fchmodat(..., AT_SYMLINK_NOFOLLOW)` 相当で名前のモードを設定してから開いて種類を確かめる、作る間だけ umask を `0077` などにする（プロセス全体に効くので並行性に注意）、のいずれかを、シンボリックリンクへの差し替えでほかのもののモードを変えない条件と合わせて選ぶ。テストに、所有者の読み取りを落とす umask（`0400`）と探索を落とす umask（`0100`）の場合を加える（root では結果が変わるので扱いを決める）。
- **関連:** F-005、AC-23、02_architecture.md 3.1・7.1、H-05。
