## 1. 概要 (Overview)

**目的:** 本書は、localhost サーバ（`yt2column-server`）が設定を環境変数ではなく決まった場所の設定ファイルから読むようにするための要件と、その雛形を作るサブコマンド `yt2column-server config init` の要件を定義する（[#576](https://github.com/isseis/yt2column/issues/576)）。

**背景:**

サーバは設定を環境変数だけから読む。`main` が `os.LookupEnv` を `run` に渡し（`cmd/yt2column-server/main.go:29`）、`run` が `config.LoadServer` で LLM の変数・`SLACK_WEBHOOK_URL`・`HOME` を読む（`cmd/yt2column-server/run.go:133`、`internal/config/config.go:362-383`）。拒否は変数ごとに 1 行ずつ、まとめて標準エラーに書かれ、終了コード `2` で止まる（`cmd/yt2column-server/run.go:131-138`）。`LoadServer` は、廃止した 5 つの LLM の変数があれば値を読まずに設定エラーで止まり（`internal/config/config.go:515-524`）、`GODEBUG` は HTTP/2 のデバッグログの警告のためだけに読む（`internal/config/config.go:769-772`、`cmd/yt2column-server/run.go:144-146`）。プロバイダ固有の変数は、生成か検証・推敲が選んだプロバイダのものだけを読み、ほかのプロバイダの変数は空でも拒否しない（`internal/config/config.go:618-634`、[ADR-0003](../../dev/adr/0003-llm-config-contract.md)）。拒否のメッセージは「environment variable ...」の形である（`internal/config/config.go:174-179`）。

エンドユーザー向けの配布（親の issue [#574](https://github.com/isseis/yt2column/issues/574)）では、サーバを `brew services`（macOS は launchd、Linux は systemd の user unit）で常駐させる（[#578](https://github.com/isseis/yt2column/issues/578)）。そうして起動したサーバには、シェルで `export` した変数や `.envrc` が届かない。サーバを常駐させるには、サーバが自分で設定を読める場所が要る。

今のサーバは引数を受け取らず、引数があれば終了コード `2` で止まる（`cmd/yt2column-server/run.go:126-129`、README「サーバの起動」の終了コードの表）。拡張のビューアは、Webhook がないときに「`SLACK_WEBHOOK_URL` を設定して、サーバを起動し直す」よう案内する（`extension/src/core/i18n/en.ts:27`、`extension/src/core/i18n/ja.ts:24`）。

対応 issue: [#576](https://github.com/isseis/yt2column/issues/576)（親: [#574](https://github.com/isseis/yt2column/issues/574)、関連: [#578](https://github.com/isseis/yt2column/issues/578)）

**本書の記述範囲:** 本書は、観測できる振る舞いを定める。対象は、設定ファイルの場所・書式・検査、サーバが何をどこから読むか、CLI の廃止した変数の扱い、`config init` の振る舞い、拒否の分類と利用者に示す内容と終了コード、文書と拡張の案内である。ファイルを開いて検査する手段、`LookupFunc` の組み立て方、拒否の型と番兵のエラーの識別子、雛形の文面、テストの手段は、設計（`02_architecture.md`）で決める。要件のレビューで挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #576 で決めたこと:**

-   **方式は決まった場所の設定ファイル（`KEY=VALUE`）:** 今の変数名をそのまま使え、変更が小さく、標準ライブラリで書ける。秘密情報が平文になるのは今の `.envrc` と同じ水準である。Keychain・libsecret（外部コマンドの呼び出しと OS ごとの実装が要る）、launchd の plist の `EnvironmentVariables`（`brew upgrade`・`brew services restart` で上書きされる）、起動用のスクリプトで `.env` を `source` する案（設定がシェルとして実行され、検証をすり抜ける）、拡張の設定画面から送る案（API キーがブラウザを通る）は採らない。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) を作る。
-   **サーバは設定ファイルだけを読み、CLI は今までどおり環境変数を読む:** 入口ごとに読む場所を 1 つに決め、どの値が効いているかを曖昧にしない（`CLAUDE.md`「Declare, don't infer」）。サーバは、ソケットのパスを導出する `HOME` だけを今までどおり環境変数から読む（例外は下の `GODEBUG`）。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md)。
-   **パスは `HOME` だけから導出する:** ソケットのパスと同じ考え方である。macOS は `$HOME/Library/Application Support/yt2column/config.env`、その他の Unix は `$HOME/.config/yt2column/config.env`。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md)。
-   **書式は 1 行に 1 つの `KEY=VALUE`:** シェルとして実行しない。知らないキー・重複したキー・不正な行は拒否する（`CLAUDE.md`「Reject, don't normalize」）。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md)。
-   **起動時に権限を検査する:** ファイルが自分の持ち物の通常のファイル（シンボリックリンクではない）で、モードが `0600` であることを確かめ、満たさなければ修正せずに起動を止める。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md)。
-   **値の検証は今のものを使う:** ファイルの中身から `LookupFunc` を作って `config.LoadServer` に渡す。ADR: なし（実装の方針。値の規則は ADR-0003 のままで、空の値の扱いだけがファイルで異なる。下記「要件定義の際に決めたこと」）。
-   **雛形を作る `yt2column-server config init`:** モード `0600` で作り、既存のファイルは上書きしない。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md)。
-   **対象外:** Keychain・libsecret への保存、CLI が設定ファイルを読むこと、設定の点検をする `doctor` サブコマンド。ADR: なし（範囲の決定。Keychain は ADR-0018 の採らなかった案に記す）。

**要件定義の際に決めたこと（2026-11-06）:**

-   **書式は Docker の `--env-file` の規則を土台にし、さらに厳格にする（F-003）:** TOML・JSON も検討した。TOML は外部のモジュールが要り、標準ライブラリ以外のモジュールを 1 つも許していない今の方針（`CLAUDE.md`「Dependencies」）を変えることになる。値は 6 つ（F-002 の「6 つのキー」）の平らな文字列だけで、TOML の表や型は使わない。JSON は `internal/strictjson` で厳密に読めるが、コメントを書けないので雛形で各キーを説明できず、手で書くと末尾のカンマなどで誤りやすい。Docker の env-file は、`#` で始まる行と空行を読み飛ばし、値を引用符も含めてそのまま使うという文書化された規則を持つ。標準ライブラリだけで書け、キーは CLI の環境変数と同じ名前のままで、雛形に説明を書ける。そのうえで、Docker が受け付ける `VAR` だけの行（環境から値を取る形）、行頭の空白、`export `、引用符で始まる値、CR、BOM などは拒否する。`.envrc` から写した `export X="..."` を黙って直さず、拒否で気づかせるためである。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **行末のコメントに見える形は拒否する（F-003）:** issue #576 の「決めること」の 1 つ目、「行末のコメント」への答えである。値の中の「空白（U+0020）に続く `#`」は書式の誤りとして拒否する。Docker の規則では値の一部になるが、`ANTHROPIC_API_KEY=sk-xxx # personal` は書式も値の検証（`secret.New` は空でない値を受け付ける。`internal/secret/secret.go:31-36`）も通り、最初の LLM の呼び出しで認証の失敗になるまで気づけない。6 つのキーの正しい値（API キー・プロバイダとモデルの指定・ワークスペース ID・URL）は空白を含まないので、拒否で失うものはない。空白を伴わない `#`（URL のフラグメントなど）は値の一部である。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **ファイルでは、空の値をどのキーでも拒否する（F-003）:** 今の環境変数では、使わないプロバイダの変数は空でも拒否しない（`internal/config/config.go:618-634`、ADR-0003）。ファイルでは、キーを書いて値を空にした行を、どのキーでも書式の誤りとして拒否する。環境変数は別のツールのために `export` されていることがあるが、設定ファイルはサーバのためだけのもので、空の値の行は書いた人の書き忘れとみなせるためである。ADR: [ADR-0003](../../dev/adr/0003-llm-config-contract.md) を更新する（ファイルでの違いを記す）。
-   **ファイルがなければ起動を止める（F-004）:** ファイルのパスと `yt2column-server config init` を示し、終了コード `2` で止める。ファイルがなくても API キーがないので結局止まるが、ファイルがないことを専用のメッセージで示すほうが分かりやすい。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **サーバは環境変数の設定を黙って無視する（F-002）:** プロセスの環境に 6 つのキーや廃止した 5 つの LLM の変数があっても、サーバは読まず、止まらず、警告もしない。止めると、CLI のために `.envrc` を読み込んだシェルからサーバを起動できなくなる。警告も含め、読まない変数を検査するためだけのコードは持たない（レビュアーの判断）。環境変数を設定したのに効かない場合の手がかりは、README の説明（F-007）で補う。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **CLI も廃止した 5 つの変数を拒否するのをやめ、無視する（F-002）:** 今の CLI とサーバは、廃止した 5 つの変数があれば値によらず設定エラーで止まる（`internal/config/config.go:515-524`、ADR-0003）。この検査のコードと、それを説明する文書を削除し、CLI はこれらの変数を読まない。読まない変数を明示的に拒否するコードは持たない（レビュアーの判断）。issue #576 の範囲を超えるが、サーバの経路から検査を外すのと同じ変更で、CLI にだけ残す理由がないので、本タスクで行う。受け入れるリスク: 古い `.envrc` で廃止した変数だけで DeepSeek を選んでいる場合、CLI は気づかせずに既定の Claude を選ぶ（`ANTHROPIC_API_KEY` がなければ、その設定エラーで止まる）。利用者はリポジトリの外にいない。ADR: [ADR-0003](../../dev/adr/0003-llm-config-contract.md) を更新する（廃止した変数を拒否するという決定を変えるため）。
-   **`config init` はサーバのサブコマンドにする（F-005・F-006）:** 引数なしなら今までどおりサーバとして動き、ちょうど `config init` なら雛形を作り、ほかの引数は今までどおり終了コード `2` で止める。配布するバイナリを増やさないためである。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **移行は README の手順だけにする（F-007）:** `config init` で雛形を作り、`.envrc` などの値を写し、サーバを起動し直す。環境変数から値を取り込む補助は作らない。利用者は 1 人で、秘密情報を自動で写す経路を増やさないためである。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) の結果に記す。
-   **`GODEBUG` は環境から読み続ける（F-002）:** issue の「`HOME` だけを環境変数から読む」に対する例外とする。`GODEBUG` は Go のランタイム自身が環境から読む変数で、ファイルに書いても効かない。サーバは、ランタイムが HTTP/2 のデバッグログで API キーを漏らしうることを警告するためだけに読む。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **権限の検査はファイルだけにする（F-004）:** 親のディレクトリの所有者や権限は検査しない。検査するのは、読むファイルそのものが自分の通常のファイルで、シンボリックリンクではなく、モードがちょうど `0600` であることである。検査は読むファイルそのものについて行い、検査したファイルと読んだファイルが同じであることを要件とする。そのため、親のディレクトリの名前を入れ替えられても、検査していないファイルの中身は使わない。ソケットのディレクトリと違い、サーバは設定ファイルの親に何も作らないので、親を検査して守るものがない。`config init` は、親のディレクトリがなければ `0700` で作る。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **ACL は検査せず、残余リスクとして受け入れる（F-004・F-005）:** サーバは設定ファイルの ACL（macOS の拡張 ACL と Linux の POSIX ACL）を検査せず、`config init` も作ったファイルの ACL を変えない。設計書のレビューで、レビュアーの判断により変えた（2026-11-06）。macOS の拡張 ACL を検出して取り除くには、CGO で libc の ACL の API を呼ぶか、Apple が文書化していないシステムコール（`fchmod_extended` など）を `syscall` で直接呼ぶことになる。どちらでも OS に依存するコードが入り、そのコードは Linux だけで動く CI ではテストできない。この実装と保守のコストを、防げるリスクと比べて対応しないことにした。macOS の既定のホームディレクトリ（`~/Library/Application Support` を含む）には、読む権利を与えて継承される ACL はない。ACL が付くのは、利用者が `chmod +a` で付けた場合、管理ツールや共有の設定で継承する ACL を持つディレクトリに置いた場合、ACL ごとコピーした場合などに限られる。受け入れるリスク: macOS でモードが `0600` でも、ACL が他のユーザーに読む権利を与えていれば、サーバはそのファイルを受理し、他のユーザーが秘密情報を読める。README で、モードの検査が ACL を見ないことと、`ls -le` での確かめ方と `chmod -N` での取り除き方を示す。Linux では、ACL があるファイルのモードのグループのビットが ACL のマスクを表すので、モードがちょうど `0600` ならマスクは空で、名前を付けたユーザーやグループの項目は権利を与えない。ADR: [ADR-0018](../../dev/adr/0018-server-config-file.md) に含める。
-   **雛形は 6 つのキーをすべてコメントにしたものにする（F-005）:** 各キーの説明と、`# ANTHROPIC_API_KEY=` のようにコメントにしたキーの行を書く。作ったファイルのパスは標準エラーに 1 行で示す。手を加えずに起動すると `ANTHROPIC_API_KEY` が未設定の設定エラーで止まるので、書き忘れに気づける。ADR: なし（雛形の中身で、このタスクの中で閉じる）。
-   **`config init` の終了コードは、作れたときは `0`、作らなかった、または作れなかったときは `1`、引数か `HOME` の誤りのときは `2`（F-005）:** すでにファイルがある場合と、書き込みに失敗した場合は `1` とする。サーバの今の終了コードが、引数と設定の誤りを `2`、その後の操作の失敗を `1` に分けている（`cmd/yt2column-server/run.go` の先頭の注釈、README の終了コードの表）のに揃えるためである。ADR: なし（このタスクの中で閉じる）。
-   **廃止した変数の名前がファイルにあれば、ほかの未知のキーと同じく拒否する（F-003）:** 廃止した変数のための特別な案内は付けない。ADR: なし（F-003 の未知のキーの規則の 1 つの場合で、このタスク の中で閉じる）。
-   **ファイルの大きさの上限は 64 KiB（F-003）:** 6 つのキーと説明には十分で、誤って大きなファイルを置いたときに読まずに拒否できる。ADR: なし（定数の値）。
-   **環境変数を前提にした文書と、拡張のビューアの案内も本タスクで直す（F-007・F-008）:** 案内のとおりに環境変数を設定しても、サーバには効かなくなるためである。ADR: なし（文書と文言で、このタスクの中で閉じる）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   シェルの環境を受け継がずに起動したサーバ（`brew services` など）が、決まった場所のファイルから設定を読んで動けるようにする。
-   サーバが読む設定の出どころをファイル 1 つに決め、環境変数とファイルのどちらの値が効いているかを曖昧にしない。
-   秘密情報を持つファイルが、モードのビットで他人に読める状態や、別のファイルに差し替えられた状態では起動しない。
-   雛形を 1 つのコマンドで、正しい権限で作れるようにする。

### 2.2. スコープ (In Scope)

-   設定ファイルのパス（F-001）
-   サーバが設定をファイルから読むことと、CLI の廃止した変数の検査の削除（F-002）
-   設定ファイルの書式と、その拒否（F-003）
-   設定ファイルの種類・所有者・モードの検査と、ファイルがない場合（F-004）
-   `yt2column-server config init`（F-005）
-   サーバの引数の約束（F-006）
-   文書（F-007）: `README.md`・`README.en.md`（`/mktrans`）、`docs/dev/project_overview.md`、`docs/dev/security.md`、`docs/dev/production_profile.md`、`docs/dev/guides/development.md`、`docs/dev/guides/cli.md`、`docs/dev/conventions/package_reference.md`、`CLAUDE.md`、`docs/translation_glossary.md`、およびこれらの文書の値を読む Go のガードテスト
-   拡張のビューアの案内（F-008）

### 2.3. スコープ外 (Out of Scope)

-   Keychain・libsecret への秘密情報の保存（issue #576 の案 B。平文のファイルが問題になったときに検討する）
-   CLI（`yt2column`）が設定ファイルを読むこと。CLI は今までどおり環境変数だけを読む
-   ホスト（`yt2column-nmhost`）の変更。ホストは今までどおり `HOME` だけを読む（`internal/config/config.go:402`）
-   設定の点検をする `doctor` サブコマンド（#574 の対象外）
-   環境変数の値を設定ファイルに取り込む補助（要件定義の際に決めたこと「移行」）
-   `brew services` の `service` ブロックや formula（#578）
-   Go のランタイムと標準ライブラリが自分で環境から読む変数（`GODEBUG` のランタイムへの効果、HTTP のクライアントが使うプロキシの変数、`TZ` など）。サーバのコードが読む設定ではないので、本タスクでは変えない
-   設定を読み直すこと（サーバの再起動なしにファイルの変更を反映すること）。ファイルは起動時に 1 回だけ読む
-   親のディレクトリの検査（要件定義の際に決めたこと「権限の検査はファイルだけにする」）
-   ACL の検査と変更（macOS の拡張 ACL と Linux の POSIX ACL。要件定義の際に決めたこと「ACL は検査せず、残余リスクとして受け入れる」）

## 3. 機能要件 (Functional Requirements)

### 3.1. 用語と共通の規則

-   **実行したユーザー:** サーバまたは `config init` を実行したプロセスの実効ユーザー。
-   **設定エラー:** サーバが待ち受ける前に、設定（`HOME`、設定ファイルの有無・検査・書式、値の検証）を理由に終了コード `2` で止まること。
-   **値を出さない:** 標準エラーに書く行（拒否・警告・案内）は、設定の値、設定ファイルの中身（値・未知のキーの文字列・行の文字列）、環境変数の値を含まない。キーや変数の名前として示すのは、6 つのキー（F-002 で定義）と `HOME`・`GODEBUG` の名前だけで、ファイルから読んだ文字列をそのまま示さない。パスは今の起動の行と同じく `redact` の規則で書く。
-   **設定エラーで止まるとき、サーバはソケットのディレクトリ・起動のロック・ソケットを作らず、設定ファイルとその親のディレクトリを変えない。**

### 3.2. 機能一覧

#### F-001: 設定ファイルのパス

設定ファイルのパスは、`HOME` だけから導出する。ほかの環境変数（`XDG_CONFIG_HOME`・`XDG_*`・`TMPDIR` など）はパスを変えない。サーバの起動と `config init` は同じパスを使う。

**Acceptance Criteria**:
- **AC-01**: macOS では、パスは `$HOME/Library/Application Support/yt2column/config.env` である。
- **AC-02**: macOS 以外の Unix（Linux を含む）では、パスは `$HOME/.config/yt2column/config.env` である。`XDG_CONFIG_HOME` を設定しても、パスは変わらない。
- **AC-03**: `HOME` が未設定・空・相対パスのとき、またはパスの規則がない OS（今のソケットのパスと同じく Windows・Plan 9・js・wasip1。`internal/config/socketpath.go:30-41`）では、サーバも `config init` も、何も作らずに終了コード `2` で止まり、`HOME` を名指しするエラーを標準エラーに書く。エラーは `HOME` の値を含まない。サーバは今までどおり、ソケットのパスが OS の上限を超える `HOME` でも終了コード `2` で止まる。`config init` はソケットのパスを使わないので、その上限では止まらない。

#### F-002: サーバは設定をファイルから読む

サーバは、LLM と Webhook の設定（`YT2COLUMN_LLM`・`YT2COLUMN_REVIEW_LLM`・`DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`ANTHROPIC_WORKSPACE_ID`・`SLACK_WEBHOOK_URL`。以下「6 つのキー」）を設定ファイルだけから読む。値の意味と検証は、F-003 の空の値の規則を除き、今の環境変数のとき（`docs/dev/project_overview.md`「設定（環境変数）」）と同じである。サーバのコードが環境変数から読むのは、`HOME`（パスの導出）と `GODEBUG`（警告）だけである。

**Acceptance Criteria**:
- **AC-04**: 設定ファイルに書いた 6 つのキーの値が、環境変数のときと同じ規則で効く。例: `ANTHROPIC_API_KEY` だけを書いたファイルでは、生成・字数の調整・検証・推敲のすべてが `claude` の `claude-opus-5-5`（effort `high`）になる（既定値は `internal/config/config.go` の `defaultLLMValue`）。`YT2COLUMN_LLM=deepseek/deepseek-flash` と `DEEPSEEK_API_KEY` を書いたファイルでは、生成が `deepseek` になる。
- **AC-05**: 値の検証で拒否されたキーは、今の環境変数のときと同じく、拒否ごとに 1 行ずつ、すべてまとめて標準エラーに報告され（`cmd/yt2column-server/run.go:131-138`）、サーバは設定エラーで止まる。各行は、キーの名前と固定の理由と、それが設定ファイルのキーであることを示し、そのキーを環境変数とは呼ばない。報告は値を含まない。例: `YT2COLUMN_LLM=Claude/x` は `YT2COLUMN_LLM` の拒否、`SLACK_WEBHOOK_URL=http://example.com/hook` は `SLACK_WEBHOOK_URL` の拒否になる。
- **AC-06**: プロセスの環境にある 6 つのキーの値は、サーバの設定に効かない。例: 環境に `ANTHROPIC_API_KEY` があっても、ファイルになければ、設定ファイルに `ANTHROPIC_API_KEY` がないことを示す設定エラーで止まる。環境に `YT2COLUMN_LLM=deepseek/deepseek-flash` があっても、ファイルに `YT2COLUMN_LLM` がなければ、生成は既定の `claude/claude-opus-5-5` になる。
- **AC-07**: プロセスの環境に、6 つのキーか廃止した 5 つの LLM の変数（`YT2COLUMN_LLM_PROVIDER`・`YT2COLUMN_MODEL`・`YT2COLUMN_REVIEW_PROVIDER`・`YT2COLUMN_REVIEW_MODEL`・`YT2COLUMN_CLAUDE_EFFORT`）のどれかがあっても（空の値を含む）、サーバはそれを理由に止まらず、それについて標準エラーに何も書かない。ファイルが正しければ起動する。
- **AC-09**: プロセスの環境の `GODEBUG` が `http2debug=1` か `http2debug=2` を含むとき、今と同じ警告（`cmd/yt2column-server/run.go:144-146`）を書く。
- **AC-10**: CLI（`yt2column`）は今までどおり環境変数だけを読み、設定ファイルを読まない。設定ファイルがあってもなくても、その中身が何であっても、CLI の設定と振る舞いは変わらない。ただし CLI は、廃止した 5 つの変数を拒否しなくなる: どれかが環境にあっても（空の値を含む）、それを理由に止まらず、その値を使わない。

#### F-003: 設定ファイルの書式

書式は Docker の `--env-file` の規則（`#` で始まる行と空行を読み飛ばし、`VAR=VAL` の値を変換せずに使う）を土台にし、それより厳格にする。ファイルは信頼できない入力として境界で検査し、受理する形に合わないものは直さずに拒否する。本書で「空白」は U+0020 を指す。

受理する形:

-   ファイル全体が UTF-8 として正しいバイト列で、大きさは 64 KiB（65,536 バイト）以下である。
-   バイトの検査（UTF-8 として正しいこと、制御文字・CR・DEL・U+FEFF がないこと）は、コメントの行を含むファイル全体にかかる。
-   行は LF（`\n`）で区切る。最後の行は LF で終わらなくてもよい。
-   各行は次のどれかである。
    -   **空行:** 0 バイトの行。
    -   **コメントの行:** 最初のバイトが `#` の行。バイトの検査のほかには中身を読まない。
    -   **設定の行:** `<キー>=<値>`。キーは最初の `=` より前の全体で、6 つのキーのどれかと完全に一致する。値は最初の `=` より後ろから行の終わり（LF を除く）までの全体で、変換しない（空白を伴わない `#` と、`=` も値の一部である）。値は 1 バイト以上で、先頭と末尾が空白でなく、`"` か `'` で始まらず、「空白に続く `#`」を含まない。
-   同じキーは 1 回までしか書けない。6 つのキーはどれも省ける。省いたキーは、今の環境変数が未設定のときと同じ扱いになる。
-   ファイルが受け付けるキーは 6 つだけで、ほかのキーを追加で受け付けることはない。

拒否するもの（例であり、受理する形に合わないものはすべて拒否する）:

-   `=` を含まない設定の行（Docker の `VAR` だけの行を含む）
-   6 つのキー以外のキー（小文字のキー、`export ANTHROPIC_API_KEY`、廃止した 5 つの変数、`GODEBUG`、`HOME`、U+3000 や U+00A0 を含むキーなど）
-   空白で始まる行、空白だけの行、キーの前後に空白がある行（`ANTHROPIC_API_KEY =x`）
-   値の先頭か末尾が空白の行、値が `"` か `'` で始まる行、値に「空白に続く `#`」がある行（`ANTHROPIC_API_KEY=sk-xxx # personal`）
-   同じキーが 2 回以上ある
-   値が空の設定の行（`DEEPSEEK_API_KEY=`）。使わないプロバイダのキーでも拒否する
-   CR（`\r`）を含む（CRLF の改行を含む）、LF 以外の制御文字（タブ・NUL を含む）か DEL を含む、U+FEFF（BOM）をどこかに含む
-   UTF-8 として正しくないバイト列を含む、大きさが 64 KiB を超える

**Acceptance Criteria**:
- **AC-11**: 上の受理する形のファイルを受理する。空行とコメントの行は設定に影響しない。値の中の空白を伴わない `#` と `=` は値の一部として扱われる（例: `SLACK_WEBHOOK_URL=https://example.com/hook#x` の値は `https://example.com/hook#x`）。最後の行が LF で終わらなくても受理する。
- **AC-12**: 上の「拒否するもの」のそれぞれについて、そのファイルでサーバは設定エラーで止まる。拒否したファイルの値はどれも使わない（一部の行だけを受理して起動することはない）。拒否の前後でファイルは変わらない。
- **AC-13**: 書式の拒否は、設定ファイルのパスと、拒否した行のうち少なくとも最初の 1 行について、その行番号（1 から数える）と固定の理由を標準エラーに示す。重複したキーの拒否は、キーの名前（6 つのキーのどれか）も示す。ファイル全体にかかる拒否（大きさ・UTF-8 として正しくない）は、行番号を示さない。どの拒否も、ファイルの中身を示さない（3.1「値を出さない」）。

#### F-004: 設定ファイルの検査

サーバは、設定ファイルを読む前に、それが読んでよいファイルであることを確かめる。満たさなければ、何も直さずに（モード・所有者・ACL を変えずに）設定エラーで止まる。検査したファイルと読んだファイルは同じでなければならない。

**Acceptance Criteria**:
- **AC-14**: 設定ファイルのパスに何もないとき、サーバは設定エラーで止まり、設定ファイルのパスと、雛形を作るコマンド `yt2column-server config init` を標準エラーに示す。
- **AC-15**: 設定ファイルのパスにあるのがシンボリックリンクのとき（リンク先が実行したユーザーのモード `0600` の通常のファイルでも、リンク先がなくても）、サーバは設定エラーで止まり、パスとシンボリックリンクであることを示す。
- **AC-16**: 設定ファイルのパスにあるのが通常のファイルでないとき（ディレクトリ・FIFO・ソケットなど）、サーバは設定エラーで止まり、パスと通常のファイルでないことを示す。FIFO の書き手を待たずに止まる。
- **AC-17**: 設定ファイルの所有者が実行したユーザーでないとき、サーバは設定エラーで止まり、パスと所有者が違うことを示す。
- **AC-18**: 設定ファイルのモードがちょうど `0600` でないとき（`0644`・`0640`・`0400`・`0700`、setuid・setgid・sticky のビットが立った `0600` など）、サーバは設定エラーで止まり、パスと、モードが `0600` でないことと、直し方（`chmod 600 <パス>`）を示す。サーバはモードを変えない。
- **AC-19**: 設定ファイルを開けないか読めないとき（AC-14 から AC-18 以外の理由。例: 読む権限がない）、サーバは設定エラーで止まり、パスと読めなかったことを示す。
- **AC-19a**: 検査の後にパスの指すものが別のファイルに入れ替わっても、サーバは検査していないファイルの中身を設定に使わない。
- **AC-20**: AC-03・AC-05・AC-12・AC-14 から AC-19a のどれかで止まるとき、サーバはソケットのディレクトリ・起動のロック・ソケットを作らず、設定ファイルとその親のディレクトリを変えない。

#### F-005: `yt2column-server config init`

`config init` は、設定ファイルの雛形を作る。サーバとしては動かない。

雛形は、空行とコメントの行だけからなる。6 つのキーのそれぞれについて、その説明と、コメントにしたキーの行（例: `# ANTHROPIC_API_KEY=`）を持つ。

**Acceptance Criteria**:
- **AC-21**: 設定ファイルのパスに何もないとき、`config init` は雛形をそのパスに作り、終了コード `0` で終わる。作ったファイルは、実行したユーザーが所有する通常のファイルで、モードはちょうど `0600` である（umask によらない）。作ったファイルのパスを標準エラーに 1 行で示し、標準出力には何も書かない。ソケットのディレクトリ・起動のロック・ソケットは作らない。
- **AC-22**: 雛形の中身は、空行とコメントの行だけで、6 つのキーの名前をそれぞれコメントの行に含む。プロセスの環境に 6 つのキーの値があっても、雛形はその値を含まない。
- **AC-23**: `config init` が作る親のディレクトリは、macOS では `$HOME/Library/Application Support/yt2column`、ほかの Unix では `$HOME/.config` と `$HOME/.config/yt2column` のうち、まだ存在しないものだけを、モード `0700` で作る。それより上のディレクトリ（macOS の `$HOME/Library/Application Support`、ほかの Unix の `$HOME`）がなければ、何も作らずに終了コード `1` で終わり、そのディレクトリがないことを示す。すでにある親のディレクトリのモード・所有者・ACL は変えない。
- **AC-24**: 設定ファイルのパスにすでに何かあるとき（通常のファイル、シンボリックリンク、リンク先のないシンボリックリンク、ディレクトリなど）、`config init` はそれを変えず、終了コード `1` で終わり、パスと、すでにあるので作らなかったことを標準エラーに示す。
- **AC-25**: 雛形を書いている途中で失敗したとき（親のディレクトリを作れない、書き込めないなど）、`config init` は終了コード `1` で終わり、パスと失敗したことを示し、そのパスに書きかけのファイルを残さない。それまでに作った親のディレクトリは残る。
- **AC-26**: `config init` が作った雛形に手を加えずにサーバを起動すると、書式（F-003）と検査（F-004）は通り、設定ファイルに `ANTHROPIC_API_KEY` がないことを示す設定エラーで止まる。

#### F-006: サーバの引数

**Acceptance Criteria**:
- **AC-27**: 引数がなければ、サーバとして動く（F-002 から F-004）。
- **AC-28**: 引数がちょうど `config` と `init` の 2 つなら、`config init` を行う（F-005）。
- **AC-29**: それ以外の引数（`config` だけ、`init` だけ、`config init extra`、`--help`、`config Init` など）では、ソケットを含め何も作らずに終了コード `2` で止まり、受け付ける形（引数なし、または `config init`）を標準エラーに示す。

#### F-007: 文書

**Acceptance Criteria**:
- **AC-30**: `README.md` が、サーバの設定について次を示す: 設定ファイルのパス（OS ごと）、書式（受理する行と、拒否する主な形）、モード `0600` と所有者とシンボリックリンクの検査、ACL は検査しないこと（macOS ではモードが `0600` でも ACL で他人に読める場合があること、`ls -le` での確かめ方と `chmod -N` での取り除き方）、`yt2column-server config init` とその終了コード、サーバが環境変数を読まず、環境にあっても無視すること、CLI は今までどおり環境変数を読むこと。クイックスタート・サーバの起動・設定・推奨構成の手順は、サーバについては設定ファイルを使う形にする。廃止した変数についての説明（「設定」の節の段落、「廃止した LLM の変数からの移行」の節、トラブルシューティングの項目）は削除する。
- **AC-31**: `README.md` が、環境変数から設定ファイルへの移行の手順を示す: `config init` で雛形を作り、サーバの設定に使っていた値を写し、サーバを起動し直す。
- **AC-32**: `README.en.md` が、`/mktrans` で `README.md` の変更に同期している（`TestReadmeSyncMarker` が通る）。README と `development.md` の値を読む拡張のテストを含め、`make ext-test` が通る。
- **AC-33**: 次の文書が、サーバが設定ファイルを読むことに合わせて書き換わっている: `docs/dev/project_overview.md` の方針と設定の節（廃止した変数の段落を削除する）、`docs/dev/security.md` の §2（秘密情報）と §8.2（localhost サーバ）、`docs/dev/production_profile.md` の構成の設定、`docs/dev/guides/development.md` の「開発用に別のサーバを動かす」（専用の `HOME` の下に設定ファイルを置いてサーバを動かす形になる）、`docs/dev/guides/cli.md` のサーバと共有する変数の説明、`docs/dev/conventions/package_reference.md` の `cmd/yt2column-server` と `internal/config` の行、`CLAUDE.md` の Architecture Overview と Development Notes の設定と秘密の記述、`docs/translation_glossary.md`（「設定エラー」を環境変数に限らない定義にし、「設定ファイル」「雛形」を加える）。
- **AC-34**: 文書の値（パス・終了コード・キーの名前・ファイルの大きさの上限）を読む Go のガードテストが、コードの値と文書の値の一致を確かめる。

#### F-008: 拡張のビューアの案内

**Acceptance Criteria**:
- **AC-35**: Webhook がないとき（`webhook_not_configured`）にビューアが示す案内は、`SLACK_WEBHOOK_URL` を設定ファイルに書いてサーバを起動し直すことを示し、環境変数を設定するようには示さない。英語と日本語のカタログの両方を変え、`make ext-check` が通る。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   設定ファイルは起動時に 1 回だけ読む。大きさの上限（64 KiB）を超えるファイルは、全体を読まずに拒否する。

### 4.2. セキュリティ (Security)

本タスクは API キーと Webhook URL を扱い、それを持つファイルを読み書きするので、`docs/dev/security.md` を適用する。

-   **出力に秘密と中身を流さない:** 3.1「値を出さない」（AC-05・AC-13）。起動の後のログは今までどおり `redact` を通し、ファイルから読んだ秘密の値を伏せ字にする。
-   **ファイルを実行しない:** 設定ファイルはシェルとして実行せず、変数の展開・コマンドの置換・引用符の解釈をしない（F-003）。
-   **直さない:** サーバは設定ファイルを書かず、モード・所有者・ACL を変えない（AC-12・AC-18・AC-20）。`config init` は既存のものを変えない（AC-24）。
-   **他人が読める・差し替えられる状態で読まない:** ファイルの種類・所有者・モードの検査（F-004）と、検査したファイルと読んだファイルが同じであること（AC-19a）。ACL が他人に与える権利は検査しない（残余リスク。要件定義の際に決めたこと「ACL は検査せず、残余リスクとして受け入れる」）。
-   **雛形に秘密を入れない:** `config init` は 6 つのキーの環境変数の値を読まず、雛形に値を書かない（AC-22）。
-   **環境の値を読まない:** サーバのコードが環境から読むのは `HOME` と `GODEBUG` だけである（F-002）。
-   **信頼の範囲:** 同一ユーザーのプロセスは信頼する（`docs/dev/security.md` §8、[ADR-0006](../../dev/adr/0006-threat-model.md)）。平文のファイルを同じユーザーが読めるのは、今の `.envrc` と同じ水準であり、受け入れる。
-   **拒否の分類:** 拒否は次の分類に分け、分類ごとに番兵のエラーを 1 つ持つ（識別子は設計で決める）。呼び出し側は分類を `errors.Is` で判定でき、メッセージ文字列の照合に頼らない。
    -   `HOME` とパスの規則（AC-03）: 今の `VarError`（`HOME` を名指しする）
    -   ファイルがない（AC-14）
    -   読んではならないファイル（AC-15 から AC-18。種類・所有者・モード）
    -   読めない（AC-19。もとの入出力のエラーを包む）
    -   書式（AC-12。行の誤りとファイル全体の誤り）
    -   値の検証（AC-05）: 今の `ErrMissing`・`ErrInvalid` の分類
    -   `config init` の失敗（AC-23 から AC-25。すでにあるため作らなかった場合と、作れなかった場合）

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   設定エラーでは待ち受ける前に止まり、別のサーバの起動のロックを取らない（AC-20）。
-   `config init` は、途中で失敗しても書きかけのファイルを残さない（AC-25）。

### 4.4. 互換性 (Compatibility)

-   macOS と Linux で動作すること。
-   **今の利用者への影響:** 更新後のサーバは、設定ファイルを作るまで起動しない（AC-14）。今の環境変数の設定は、サーバには効かなくなる（AC-06）。互換のための仕組み（環境変数を読み続ける期間、自動の取り込み）は設けず、README の移行の手順（AC-31）で移る。利用者はリポジトリの外にいない。
-   CLI の設定は変わらない（AC-10）。ホストは変わらない。

### 4.5. 保守性 (Maintainability)

-   値の検証は `config.LoadServer` の今の規則を共有し、ファイルのための別の値の検証を書かない（issue #576 で決めたこと）。ファイルに固有の規則は書式（F-003。空の値の規則を含む）だけである。6 つのキーの名前は 1 か所で持ち、ファイルのキーと文書のガードテストがそれを使う。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。本タスクで変える方針は次のとおりで、`project_overview.md` と ADR も同じ PR で変える。
    -   `project_overview.md`「設定（環境変数）」と ADR-0003 は、CLI とサーバが環境変数から設定を読み、廃止した変数があれば CLI もサーバも止まり、使わないプロバイダの変数は空でも拒否しないとしている。本タスクで、サーバは設定ファイルから読み、CLI もサーバも廃止した変数を無視し、ファイルでは空の値をどのキーでも拒否するように変える。理由は「要件定義の際に決めたこと」にある。
    -   `docs/dev/security.md` §2 は、API キーと Webhook URL を環境変数からのみ読み込むとしている。本タスクで、サーバについてはモード `0600` の設定ファイルから読むように変える。
-   外部のモジュールを加えない（`CLAUDE.md`「Dependencies」）。
-   `CLAUDE.md`「Declare, don't infer」の例外を増やさない: ファイルの中身による分岐は、受理する形の解析（行の種類・キー）に限る。キーは 6 つの名前との完全な一致で決め、`HasPrefix` などで推し量らない。
-   雛形の説明の文は、Go の文字列リテラルなので英語で書く（`CLAUDE.md`「Go Idioms」）。拡張の案内は、英語と日本語のカタログの両方に置く（`CLAUDE.md`「Go Idioms」の拡張の規則）。

## 6. 用語集 (Glossary)

-   **設定ファイル:** サーバが設定を読むファイル（F-001 のパス）。
-   **6 つのキー:** `YT2COLUMN_LLM`・`YT2COLUMN_REVIEW_LLM`・`DEEPSEEK_API_KEY`・`ANTHROPIC_API_KEY`・`ANTHROPIC_WORKSPACE_ID`・`SLACK_WEBHOOK_URL`。
-   **廃止した 5 つの変数:** `YT2COLUMN_LLM_PROVIDER`・`YT2COLUMN_MODEL`・`YT2COLUMN_REVIEW_PROVIDER`・`YT2COLUMN_REVIEW_MODEL`・`YT2COLUMN_CLAUDE_EFFORT`。
-   **雛形:** `config init` が作る、コメントの行と空行だけの設定ファイル。
-   **実行したユーザー・設定エラー:** 3.1 の定義による。
-   ほかの用語は `docs/translation_glossary.md` と統一する。
