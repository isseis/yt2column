# 設計への申し送り：localhost サーバの起動時に共有トークンを表示する

本書は、[01_requirements.md](01_requirements.md) の起草（とレビュー）で挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: 表示の判断と、`LoadOrCreate` の `created` の扱い

-   **事項:** 起動のたびに表示するにあたり、`internal/authtoken.LoadOrCreate` の `created` の戻り値を残すかを決める。表示の行の作り方（値だけか、末尾の改行の付け方）と、貼り付けの案内（標準エラー出力）を常に書くか、生成した起動と読み込んだ起動で変えるかを決める。
-   **理由:** `0011` の実装（`cmd/yt2column-server`）は `created` を見て、生成した起動だけトークンと案内を書く。本タスクでは表示の条件を外すため、`created` が表示の判断に使われなくなる。`created` は「生成したかどうか」を表す値として残す意味がある（テストや、将来の利用）一方、呼び出し側で使わない値になる。要件 F-001 は、表示を 1 行の値だけとし、案内は標準エラー出力に書くことだけを定め、案内の条件は設計に委ねている。
-   **候補の方針:** `LoadOrCreate` の契約（`created` を含む）は変えず、呼び出し側で常に表示する。案内は、生成した起動では「拡張のオプションページに貼り付ける」ことを示し、読み込んだ起動では「保存済みの値を再確認するための表示である」ことを示す、など、起動の種類で文言を変える。あるいは、案内を常に同じ文言にして単純化する。`created` を使わなくなる場合も、`make deadcode` は使われない戻り値を検出しないので、残すか削除するかはこの項で決める（戻り値は契約の一部であり、削除は `0011` の `authtoken` のテストと契約に影響する）。
-   **関連:** F-001、AC-01、AC-02、4.5

## H-02: 露出の経路と README の起動例

-   **事項:** 標準出力をリダイレクトした場合にトークンがファイルに残る問題の扱いを決める。README の起動例（`0011` の設計書 §3.12 の `2>>server.log`）を維持するか、注意書きを加えるかを決める。
-   **理由:** ログは標準エラー出力に分けているので、標準エラー出力だけをファイルに残す起動例（`2>>server.log`）ではトークンはそのファイルに残らない。一方、利用者が標準出力もリダイレクトすると（`>server.log 2>&1` など）、トークンがファイルに残る。要件 4.2 は、この露出を「利用者が明示的に行った場合」として受け入れ、README に注意を記すことを求めている。
-   **候補の方針:** `0011` の起動例（標準エラー出力だけをファイルに残す形）を維持し、README に「標準出力には共有トークンが表示されるので、標準出力をファイルに残すとトークンがそのファイルに残る」旨の注意を加える。セキュリティの節（`security.md` §8.2）にも同じ経路を列挙する。
-   **関連:** F-002、4.2、README、`security.md` §8.2

## H-03: 表示の検査の作り方（標準出力・標準エラー出力と伏せ字）

-   **事項:** 表示をユニットテストで確かめる方法（標準出力と標準エラー出力の差し替え）と、共有トークンがログ・応答・失敗の通知に現れないことを確かめる方法を決める。
-   **理由:** 要件 F-001 と AC-06 は、トークンを標準出力の 1 行だけに載せ、ログ・応答・エラーメッセージ・失敗の Slack への投稿には載せないことを求める。`0011` の `redact.Writer` は、呼び出し側が伏せ字の処理を忘れないようにログの出力先を包む（`0011` の設計書 §3.10。`redact.Writer` の定義は §3.11）。表示の 1 行だけが例外であり、その例外がほかの出力へ広がっていないことをテストで固定する必要がある。
-   **候補の方針:** サーバの組み立て（`cmd/yt2column-server`）のテストで、標準出力と標準エラー出力を `bytes.Buffer` に差し替え、生成した値と読み込んだ値のそれぞれについて、標準出力に値の 1 行だけが出て、標準エラー出力のログと失敗の通知に値が出ないことを確かめる。`0011` の既存のテスト（伏せ字とログの検査）と同じ手段を使い、新しい仕組みを足さない。`created` の扱い（H-01）に合わせて、テストの入力（ファイルがある状態・ない状態）を分ける。
-   **関連:** F-001、AC-01、AC-02、AC-06、4.5
