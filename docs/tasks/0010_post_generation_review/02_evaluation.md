## 1. 概要

本書は [01_requirements.md](01_requirements.md)（以下、要件定義書）の F-008 に従い、2 つの段階（字数の調整と、検証・推敲）の評価の手順と記録を残す。評価では、段階が記事に加える変更を次の 2 つの面から確かめる（要件定義書 F-008）。

-   **直したこと:** 段階なしの記事にあった根拠のずれ・誤認識の写し・字数の超過が、段階の後に残っていないか。
-   **壊したこと:** 段階が新しい根拠のずれを入れていないか、直す必要のない記述を変えていないか、構成を変えていないか。

対象は、0008 の評価と同じ 5 本の動画、同じ観点（0008 の F-006）とする。生成のテンプレートは 0008 の v5 とする。

手順の多くは [0008 の 02_evaluation.md](../0008_column_prompt/02_evaluation.md)（以下、0008 評価記録）と同じである。本書は同じ内容を写さず、次を参照する。

## 2. 手順

### 2.1. 生成のテンプレート

生成のテンプレートには 0008 の v5（`docs/tasks/0008_column_prompt/v5/system.tmpl`・`v5/user.tmpl`）を使い、CLI の `--system-prompt`・`--user-prompt` で指定する（要件定義書 F-008）。2 つの段階のテンプレートは既定のものを使い、上書きしない。

### 2.2. 段階なしの記事（比較の基準）

まず、2 つの段階を無効にした記事を生成する。これは、段階が直したこと・壊したことを比べる基準になる。0008 評価記録 §2.3 のコマンドに `--no-shorten --no-review` を加え、出力先を段階なし用のディレクトリにする。所要時間の基準を測るため、`time` で実行する。

```sh
V=v5; RUN=1
mkdir -p ~/yt2column-eval/out/$V-nosteps
time YT2COLUMN_YTDLP_PATH=/usr/bin/false yt2column --keep-cache \
  --no-shorten --no-review \
  --system-prompt docs/tasks/0008_column_prompt/$V/system.tmpl \
  --user-prompt docs/tasks/0008_column_prompt/$V/user.tmpl \
  --out ~/yt2column-eval/out/$V-nosteps/<動画 ID>-$RUN.md <URL>
```

段階を無効にした記事の `--out` の書式は、0008 の v5 の記録（0008 評価記録 §5.6）と同じである（要件定義書 AC-19）。

### 2.3. 段階ありの記事と一覧

次に、2 つの段階を既定で行う記事を生成し、検証・推敲が直した箇所の一覧を `--review-log` で書き出す。所要時間（AC-30）を測るため、`time` で実行する。

```sh
V=v5; RUN=1
mkdir -p ~/yt2column-eval/out/$V-steps ~/yt2column-eval/review
time YT2COLUMN_YTDLP_PATH=/usr/bin/false yt2column --keep-cache \
  --system-prompt docs/tasks/0008_column_prompt/$V/system.tmpl \
  --user-prompt docs/tasks/0008_column_prompt/$V/user.tmpl \
  --review-log ~/yt2column-eval/review/<動画 ID>-$RUN.md \
  --out ~/yt2column-eval/out/$V-steps/<動画 ID>-$RUN.md <URL>
```

-   `time` の `real` を、生成から出力までの所要時間として記録する（AC-30）。段階なしと段階ありの両方を測る。§3.2 には段階ありの所要時間を記録し、段階が増やした時間は §4 の結論で比べる。
-   `--review-log` は検証・推敲の段階を必要とする。`--no-review` とは同時に指定できない（要件定義書 AC-21）。`--out` に同じパスを指定することもできない（[02_architecture.md](02_architecture.md) §3.9）。
-   検証・推敲のプロバイダとモデル（AC-30）は、まず生成と同じ `deepseek-flash`（`YT2COLUMN_MODEL=deepseek-flash`）とする（要件定義書 F-008）。0008 評価記録 §2.3 のとおり、DeepSeek の料金が 2 倍になる時間帯（日本時間の平日 10–13 時と 15–19 時）を避ける。
-   1 本の記事につき、LLM の呼び出しは生成 1 回・字数の調整 0〜1 回・検証・推敲 1 回が上限である（要件定義書 §4.1）。各段階は最大 1 回しか呼ばないので、成功した実行では、CLI の要約の `the shorten step ran` と `the review step returned ...` の有無から、実際に呼ばれた段階が決まる（生成は常に 1 回、字数の調整は要約の行があれば 1 回、検証・推敲は要約の行があれば 1 回）。失敗した実行では、エラーのメッセージは段階名を示すが回数は示さないので、失敗がその段階の LLM 呼び出しの後（応答の拒否・打ち切り・上限超過）か前（テンプレートの展開の失敗、呼び出し前の取り消し）かで、呼び出しの有無を判断し、§3.2 に記録する。`time` の `real` は所要時間であり、呼び出しの回数ではない。`--review-log` は変更の一覧であり、回数の記録には使わない。
-   記事を生成する DeepSeek の呼び出しは実 API の呼び出しなので、実行のたびに人が承認する（要件定義書 §5）。
-   実行は 1 本ずつ順に行う。CLI はキャッシュディレクトリのロックを取るので、同じ `YT2COLUMN_CACHE_DIR` で並行して起動した実行は、LLM を呼ぶ前に失敗する。

### 2.4. 判定の方法

判定の方法（スクリプト・LLM・人の分担、人の確認）は 0008 と同じとする（0008 評価記録 §2.4・§2.5・§4）。

-   機械的に判定できる部分は `check_article.py` で判定する。
-   残りの部分は Claude が一次採点し、人は必須の観点の不合格と、品質の観点の 1・2 の判定をすべて確認する。
-   段階が加えた変更については、`--review-log` の各項目を素材に照らして確認する（§3.3、AC-29）。

### 2.5. 失敗の種類の記録

段階の応答が拒否された場合、記事は失敗し、その理由がエラーのメッセージに出る（[02_architecture.md](02_architecture.md) §5.4）。失敗は種類ごとに件数を数え、§3.4 の表に記録する。

### 2.6. 中間生成物を固定した比較（タスク 0017 以降）

段階の効果を切り分けるため、生成を 1 回だけ行って中間生成物を保存し、同じ生成の出力に別の字数の調整・検証・推敲を当てる。`--artifacts <dir>` で各段階の出力を保存し、`--after <stage>` でその段階の保存した出力から再開する。

```sh
V=v5; RUN=1; A=~/yt2column-eval/artifacts/<動画 ID>
mkdir -p "$A"
YT2COLUMN_YTDLP_PATH=/usr/bin/false yt2column --keep-cache --artifacts "$A" \
  --system-prompt docs/tasks/0008_column_prompt/$V/system.tmpl \
  --user-prompt docs/tasks/0008_column_prompt/$V/user.tmpl \
  --review-log ~/yt2column-eval/review/<動画 ID>-$RUN.md \
  --out ~/yt2column-eval/out/$V/<動画 ID>-$RUN.md <URL>
YT2COLUMN_YTDLP_PATH=/usr/bin/false yt2column --keep-cache --artifacts "$A" \
  --after generation \
  --review-log ~/yt2column-eval/review/<動画 ID>-$RUN-after-generation.md \
  --out ~/yt2column-eval/out/$V/<動画 ID>-$RUN-after-generation.md <URL>
YT2COLUMN_YTDLP_PATH=/usr/bin/false yt2column --keep-cache --artifacts "$A" \
  --after shorten \
  --review-log ~/yt2column-eval/review/<動画 ID>-$RUN-after-shorten.md \
  --out ~/yt2column-eval/out/$V/<動画 ID>-$RUN-after-shorten.md <URL>
```

-   1) の実行だけが生成を呼ぶ。2) の実行は生成を呼ばず、字数の調整（本文が上限を超えるときだけ）・検証・推敲を呼ぶ。3) の実行は生成と字数の調整を呼ばず、検証・推敲だけを呼ぶ。呼び出し回数は §2.3 と同じく CLI の要約の行から決める（生成は常に 1 回、字数の調整は `the shorten step ran`、検証・推敲は `the review step returned ...`）。`--after` に与えた段階より前の段階は呼ばれないので、料金もその分減る。
-   保存した成果物（`<動画 ID>.generation.json` など）を使い回すことで、生成の非決定性を切り離し、字数の調整・検証・推敲の差だけを比べられる。段階の前の文面（§3.1 の「段階の前の文面」）も成果物から読める。
-   **すべての実行に `--keep-cache` を付ける。** 付けないと成功後にその動画のキャッシュが削除され、再開が字幕を取り直す。取り直した字幕が保存時と変わると、再開は入力の識別子の食い違いで拒否される（[01_requirements.md](01_requirements.md) の AC-21）。
-   実 API を呼ぶ実行は、§2.3 と同じく人が承認する。段階の呼び出し回数と料金は、再開では呼ばない段階があることを記録する。

### 4.2. 0008 の評価を再開するか

いまの構成のままでは、0008 の評価（最終の版の 10 本の記事）を再開しない（人の判断、2026-10-14）。どちらの構成でも、1 回目の 5 本で合格条件を満たしていないので、2 回ずつの評価をしても合格しない見込みが高い。

再開を判断する前に、次のどれかを検討する。どれを選ぶかは人が判断する。この 2 つの候補は、§3.6（テンプレートの強化）と §3.7（上位のモデル）で試した。§3.7 では根拠のずれが減ったが、天才の定義の取り違えと、検証・推敲が入れた話者のずれが残り、検証・推敲によらない不合格（生成のばらつきによる `18tb` の長さと、生成か字数の調整かを区別できない `roNZ` の論点の欠落）もある。どちらも合格条件（10 本すべて合格）には届いていない。

-   検証・推敲のテンプレートの指示を強める。直せなかったずれの種類（知識による補足、誤認識の写し、人を評した発言の話者）を、確かめる対象として具体的に挙げる。テンプレートを変える場合は、別のコミットにし、変えた後の評価も本書に記録する（要件定義書 F-008）。§3.6 で試した結果、誤認識の写しと話者の取り違えは sonnet-5-5 では直らなかった。
-   検証・推敲のモデルを、Claude の上位のモデルや effort にする。0008 の §5.7〜§5.9 では、生成のモデルを Claude にした評価もあり、claude-opus-5-5 による生成（0008 評価記録 §5.9）には「交代」が現れなかった（§4.4）。§3.7 で試した結果、検証・推敲は「交代」と GPS の補足を直したが、天才の定義の取り違えは直らず、新しい話者のずれを 1 つ入れた（「核子」は生成の時点で正しかった）。
-   生成のばらつきを除く。§3.7 で残った不合格のうち、`18tb` の長さは生成のばらつきによる。`roNZ` の論点の欠落は、生成の取りこぼしか字数の調整が落としたかを区別できない。生成物を固定するだけではこの 2 つを切り分けられないので、字数の調整の前後の文面も残し、字数の調整と検証・推敲の影響を比べられるようにする。生成物を固定して段階だけを比べる入口（CLI に推敲専用のフラグを足す）を別の issue（#213）で検討する。
