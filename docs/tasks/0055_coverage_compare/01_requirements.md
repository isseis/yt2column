## 1. 概要 (Overview)

**目的:** 本書は、テストを削除する変更の前と後の 2 つのコミットでカバレッジを取り、関数ごとに比べる常設の道具の要件を定義する。対象は Go のコードとブラウザ拡張のコードの両方である（[#618](https://github.com/isseis/yt2column/issues/618)）。あわせて、[CLAUDE.md](../../../CLAUDE.md)「Deleting a test is a claim that must be checked」を、この道具を使う手順に書き換える。

**背景:**

[CLAUDE.md](../../../CLAUDE.md)「Testing Strategy」の「Deleting a test is a claim that must be checked」は、テストを削除した後に `go tool cover -func` の結果が関数ごとに変わらないことを確かめ、そう書くよう求めている（`CLAUDE.md:490-491`）。ところが、この確認には常設の道具がない。リポジトリにある `go tool cover -func` の呼び出しは、CI 向けの `make test-ci` が全体の網羅率の 1 行を出すものだけである（`Makefile:101-103`）。そのため、テストを削除するタスクのたびに、比べる手順を設計し直してきた。

-   Go：0038 は、`go test -tags test -count=1 -coverpkg=./... -coverprofile=<file> ./...` の `go tool cover -func` の出力を前後で比べ、関数ごとに同じであることを確かめた（0038 `02_architecture.md` 7.1）。`-coverpkg=./...` を付けたのは、`cmd/yt2column` のテストが `internal/` のパッケージを通るため、パッケージごとに測ると、削除で失われるほかのパッケージの網羅を見落とすからである。
-   拡張：拡張には `go tool cover` がない。0027（`02_architecture.md` 3.11）、0046（`03_implementation_plan.md` 1.2）、0054（`02_architecture.md` 3.2）の 3 回、`node --test --experimental-test-coverage --test-reporter=lcov` の lcov を前後で比べる手順を、それぞれ設計した。そのつど、拡張での比較を CLAUDE.md の方針の例外として要件で承認を得た（たとえば 0054 `01_requirements.md` 1 章「方針の例外」）。
-   0054（[#560](https://github.com/isseis/yt2column/issues/560)）の最終的な変更は 2 ファイル・16 行の削除だった。それに対して、ローカルのレビューの指摘の多くは、この一度きりの比較の手順の頑健さに向いていた（issue #618）。

0054 の設計で分かった、拡張の lcov を比べるときの注意点は次のとおりである（0054 `02_architecture.md` 3.2）。

-   名前のない関数の `anonymous_<番号>` は、同じコミットでも実行のたびに変わる。名前のある関数でも、1 つのファイルに同じ名前が複数あることがある（`<instance_members_initializer>`）。そのため、関数は (ファイル, `FN` の行) で識別する。
-   1 つの `FN` の行から複数の関数が始まることがある（入れ子のアロー関数）。
-   カレントディレクトリやテストの指定を誤ると、テストが 1 つも動かずに報告が空になり、比較が通ってしまう。
-   テストが失敗した実行の報告は使えない。失敗したテストが実行させるはずの関数が、報告から欠けるからである。

0054 では、削除した関数がファイルの最後の関数だったので、ほかの関数の行番号は変わらなかった（0054 `02_architecture.md` 3.2）。常設の道具は、削除でほかの関数の行番号がずれる場合も扱う必要がある。

後続の [#619](https://github.com/isseis/yt2column/issues/619)（軽量プロセスの定義）は、類型 D「削除」の確かめ方として、本タスクの道具を使う予定である。

対応 issue: [#618](https://github.com/isseis/yt2column/issues/618)（関連: [#560](https://github.com/isseis/yt2column/issues/560)・[#619](https://github.com/isseis/yt2column/issues/619)）

**本書の記述範囲:** 本書は、道具の入口、比べる対象と合格の基準、止まる場合とそのときの報告、合格したときに出す結果、道具が自分自身を確かめるテスト、CLAUDE.md の手順の書き換えを定める。道具を書く言語と置き場所、カバレッジの報告の取り方（コマンドとその引数）、前後の行の対応の付け方の手段、作業用のチェックアウトの作り方、テストの手段は、設計（`02_architecture.md`）で決める。要件の作成で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #618 で決めたこと:**

-   **対象は Go と拡張の両方:** Go は `go tool cover -func` の関数ごとの網羅率を、拡張は `node --test --experimental-test-coverage --test-reporter=lcov` の `FN`・`FNDA` を比べる。0054 の注意点は道具の中で扱う。それぞれのタスクで比べる手順を設計し直さずに済むようにするためである。
-   **比べるのは 2 つのコミット:** 削除の前と後の 2 つのコミットでカバレッジを取る。
-   **基準は「削除の前に実行された関数が、削除の後も実行されている」こと:** あわせて、削除した関数だけが消えたことも確かめる。
-   **合格とせずに止まる場合:** 何も測れていない場合、テストが失敗した場合、関数の対応が取れない場合は止まる。この止まり方を、壊した報告で確かめるテストを道具の側に持たせる。測れていない比較が通るのを防ぐためである。
-   **CLAUDE.md の書き換え:** 「Deleting a test is a claim that must be checked」を、この道具を使う手順に書き換える。これで、拡張での比較は方針の例外ではなくなる。
-   **CI では自動実行しない:** 道具は、テストを削除する変更で人や agent が実行する。

**要件定義の際に決めたこと（2026-11-02）:**

-   **比べる細かさ:** Go は、関数ごとの網羅率が削除の前より下がらないことを確かめる。拡張は、削除の前に実行回数が 1 以上だった関数が、削除の後も 1 以上であることを確かめる。どちらも行と分岐の単位では比べない。Go は関数ごとの網羅率をそのまま出せるので、今の CLAUDE.md の「関数ごとに変わらない」（`CLAUDE.md:490-491`）と 0038 の基準を緩めずに、比べる手間も増えないためである。拡張の lcov の関数の記録は実行回数だけを持つので、issue の基準どおりに比べる（F-003）。
-   **削除した関数は差分から求める:** 前後のソースの差分で削除された行から始まる関数を、削除した関数とする。利用者は削除した関数を指定しない。行番号のずれに対応を付けるために差分はどのみち使うので、指定の誤りという新しい失敗を増やさないためである（F-004）。
-   **Go はモジュール全体で測る:** Go の関数は、モジュールのどのパッケージのテストから実行されても数える（0038 の `-coverpkg=./...` と同じ範囲）。理由は 0038 と同じで、パッケージごとに測ると、ほかのパッケージのテストだけが実行させていた関数の網羅の喪失を見落とすからである。拡張の lcov も、どのテストからの実行も数える（F-003）。
-   **比べる時点は BASE と HEAD:** 削除の前は利用者が指定したコミット（BASE）、削除の後は今のコミット（HEAD）とする。コミットしていない変更があれば止める。測った内容とコミットした内容が同じであることを保つためである（0054 `02_architecture.md` 3.2 と同じ前提。F-001）。
-   **削除以外の変更で対応が付かなければ止める:** 残る関数の始まりの行が書き換わっている場合と、HEAD にだけある関数がある場合は、どちらも「関数の対応が取れない」として止める。この道具は削除を確かめるためのものであり、新しい関数や書き換えた関数は、前後で比べる相手を持たないためである（F-004）。
-   **比べるのは本番のコードだけ:** Go は、テスト用のビルドタグ `test` を付けたときだけビルドされるファイル（`test_helpers.go`、`internal/doctestutil` などのテスト専用のパッケージ）を比べない。拡張は `src/` と `scripts/` の下のファイルだけを比べ、`test/` の下のファイルは比べない。テストを削除すると、テストの補助のコードの網羅率が下がるのは自然なことであり、本番のコードに影響のない削除でも止まってしまうためである（F-003）。
-   **入口は Go と拡張で 2 つ:** Go 用と拡張用の、2 つの `make` の対象を設ける。拡張だけのテストを削除するときに、Go の全テストを 2 回走らせずに済むためである。名前は issue の例のとおり `make coverage-compare BASE=<commit>` と `make ext-coverage-compare BASE=<commit>` とする（F-001）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   テストを削除する変更で、削除の前に実行されていた本番の関数が削除の後も実行されていることを、1 つのコマンドで確かめられるようにする。Go と拡張で同じ形の確かめ方にする。
-   何も測れていない比較、テストが失敗した比較、関数の対応が取れない比較を、合格として報告しない。
-   テストを削除するタスクのたびに比べる手順を設計し直す手間と、拡張での比較を方針の例外として承認を得る手間をなくす。

### 2.2. スコープ (In Scope)

-   Go のコードの比較の入口（`make coverage-compare`）と、拡張のコードの比較の入口（`make ext-coverage-compare`）。
-   比べる対象と合格の基準、止まる場合と、そのときの報告。
-   合格したときに出す結果（コミットメッセージに書くもの）。
-   止まり方を、壊した報告で確かめる道具のテスト。
-   [CLAUDE.md](../../../CLAUDE.md)「Deleting a test is a claim that must be checked」の書き換えと、CLAUDE.md の「Commands」への 2 つの入口の追加。

### 2.3. スコープ外 (Out of Scope)

-   **行と分岐の単位の比較:** 比べない。関数の単位の比較で、テストの削除で関数が実行されなくなることは見つけられる。Go は関数ごとの網羅率まで比べるので、関数の中の文の網羅の減少も見つけられる（1 章「要件定義の際に決めたこと」）。
-   **CI での自動実行:** しない（issue #618）。道具のテスト（F-006）は、既存のテストの一式の中で動く。
-   **追加や書き換えを含む変更の比較:** 残る関数の始まりの行の書き換えや、新しい関数の追加を含む変更は比べずに止まる（F-004）。これらの変更は、削除を確かめるという道具の目的の外にある。
-   **テストの補助のコードの比較:** Go のテスト用のビルドタグのファイルと、拡張の `test/` の下のファイルは比べない（1 章「要件定義の際に決めたこと」）。
-   **削除したテストが確かめていた内容の行き先:** カバレッジはコードが実行されたことを示すだけで、何を確かめたかは示さない（0027 `02_architecture.md` 3.10.2）。確認の内容の行き先をたどることは、この道具の外にある。
-   **過去のタスク文書:** 0027・0038・0046・0054 のタスク文書の比べ方の記述は書き換えない。各タスクの時点の決定の記録だからである。
-   **#619 の軽量プロセス:** 軽量プロセスの定義と、そこからこの道具を呼ぶ手順は #619 で扱う。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

本章の用語は 6 章の定義に従う。

#### F-001: 比較の入口と、比べる 2 つの時点

利用者は、リポジトリのルートで `make coverage-compare BASE=<commit>`（Go）または `make ext-coverage-compare BASE=<commit>`（拡張）を実行する。道具は、BASE と HEAD のそれぞれのコミットの内容でテストを実行してカバレッジの報告を取り、比べる。

**Acceptance Criteria**:
- **AC-01**: `make coverage-compare BASE=<commit>` は Go の本番のコードを、`make ext-coverage-compare BASE=<commit>` は拡張の本番のコードを、BASE と HEAD のコミットの内容で測って比べる。合格のときは終了コード 0 で終わり、合格でないときは 0 以外で終わる。
- **AC-02**: 次のどれかに当たるときは、テストを実行する前に止まり、当たった理由を出して 0 以外で終わる。BASE の指定がない。BASE がコミットとして解決できない。BASE と HEAD が同じコミットである。作業ツリーまたはインデックスに、コミットしていない変更がある（git が無視するファイルは数えない）。
- **AC-03**: 道具の実行の前と後で、利用者の作業ツリーのファイル、インデックス、今のブランチ、HEAD のコミットは変わらない。道具が作った一時的なファイルとチェックアウトは、合格・不合格・途中で止まった場合のどれでも、終わるときに残らない。
- **AC-04**: `make ext-coverage-compare` は、`node --version` が `extension/.node-version` の版と一致しないとき、または `extension/node_modules` がないときは、テストを実行する前に止まり、当たった理由を出して 0 以外で終わる。ほかの `ext-*` の対象と同じく、依存パッケージを入れたり、ネットワークを使ったりはしない。

#### F-002: 測れていることの確認

BASE と HEAD のどちらの実行も、テストがすべて通り、比べる関数が報告に含まれていなければ、比較に使わない。

**Acceptance Criteria**:
- **AC-05**: BASE と HEAD のどちらかの実行で、テストが 1 つでも失敗した場合（テストの実行が 0 以外で終わった場合を含む）は、比べずに止まる。止まるときは、どちらの時点で失敗したかと、失敗したテストの名前を出す。
- **AC-06**: BASE と HEAD のどちらかの実行で、実行されたテストの数が 0 の場合、または比べる対象のファイルの関数の数が 0 の場合は、「何も測れていない」として比べずに止まる。
- **AC-07**: カバレッジの報告が、道具が読む形で読めない場合は、比べずに止まる。読めない場合には、少なくとも次のものを含む。拡張の lcov のファイルのまとまり（`SF` から `end_of_record` まで）が閉じていない。1 つのまとまりの中で `FN` と `FNDA` の数が違う。Go の `go tool cover -func` の出力の行が `<ファイル>:<行>:` `<関数名>` `<網羅率>` の形でない。読めない部分を飛ばして、残りの部分だけで比べることはしない。

#### F-003: 関数ごとの比較

前後で対応が付いた関数（F-004）について、削除の前に実行されていた関数が削除の後も実行されていることを確かめる。

**Acceptance Criteria**:
- **AC-08**: Go では、BASE で網羅率が 0% より大きかった本番の関数のうち削除した関数でないものは、どれも HEAD での網羅率が BASE での網羅率以上である。下がった関数があれば不合格とし、その関数の (ファイル, 行, 名前) と前後の網羅率を出す。
- **AC-09**: Go の網羅率は、モジュールのどのパッケージのテストから実行された文も数える。あるパッケージの関数が、ほかのパッケージのテストからだけ実行されている場合も、その関数は実行されたものとして比べる。
- **AC-10**: 拡張では、BASE で実行回数が 1 以上だった本番の関数のうち削除した関数でないものは、どれも HEAD での実行回数が 1 以上である。0 になった関数があれば不合格とし、その関数の (ファイル, 行) と、報告にある名前を出す。拡張では、実行回数の増減は比べない（1 以上かどうかだけを比べる）。
- **AC-11**: 拡張で、1 つの (ファイル, `FN` の行) から複数の関数が始まる場合は、その行の関数を名前で対応させず、その行の実行回数の多重集合として比べる。BASE でその行の関数がすべて実行回数 1 以上のときは、HEAD で実行回数が 1 以上の関数の数が BASE より少なければ不合格とする。BASE でその行に実行回数 0 の関数が含まれるときは、対応が取れないとして止まる。0 から 1 以上になった関数と、1 以上から 0 になった関数が入れ替わると、数が減らずに見逃すためである（0054 `02_architecture.md` 3.2）。
- **AC-12**: Go で、同じ (ファイル, 行) から始まる関数が報告に複数ある場合は、対応が取れないとして止まる。
- **AC-13**: 比べるのは本番のコードの関数だけである。Go では、テスト用のビルドタグ `test` を付けたときだけビルドされるファイルの関数を比べない。拡張では、`extension/src/` と `extension/scripts/` の下のファイルの関数だけを比べる。比べないファイルの関数の網羅率や実行回数が下がっても、不合格にはしない。
- **AC-14**: 関数は (ファイル, 始まりの行) で識別し、名前では識別しない。名前のない関数の名前が実行のたびに変わる場合（拡張の `anonymous_<番号>`）や、同じファイルに同じ名前の関数が複数ある場合も、比較の結果は名前によらない。

#### F-004: 前後の関数の対応と、削除した関数

BASE と HEAD の本番のコードの差分から、残る関数の前後の行を対応させ、削除した関数を求める。

**Acceptance Criteria**:
- **AC-15**: BASE の本番の関数で、その始まりの行が BASE から HEAD への差分で削除された行に当たるものを、削除した関数とする。ファイルごと削除された場合は、そのファイルのすべての関数が削除した関数である。削除した関数は比較の対象にせず、合格の結果（F-005）に一覧として出す。
- **AC-16**: BASE の本番の関数で削除した関数でないもの（残る関数）は、差分で変わらない行から始まり、その行の HEAD での位置から始まる関数として HEAD の報告にあるものと対応させる。削除で後ろの行番号がずれた関数も、この対応で比べる。
- **AC-17**: 次のどれかに当たるときは、対応が取れないとして止まり、当たった関数の (ファイル, 行) を出す。残る関数の始まりの行が、差分で変わらない行でない（書き換えられた行に当たる）。残る関数の HEAD での位置から始まる関数が HEAD の報告にない。HEAD の本番の関数で、BASE のどの残る関数にも対応しないもの（HEAD にだけある関数）がある。ファイルの名前の変更や移動は、BASE のファイルの削除と HEAD のファイルの追加として扱う。
- **AC-18**: 削除した関数のうち、BASE で実行されていなかった（Go で網羅率 0%、拡張で実行回数 0）ものがあっても、それだけを理由に不合格にはしない。合格の結果の一覧に、実行されていなかったことを添えて出す。

#### F-005: 結果の報告

合格のときも不合格のときも、比べた内容を、コミットメッセージに書ける形で出す。

**Acceptance Criteria**:
- **AC-19**: 合格のときは、次のものを出す。実行した入口（`make` の対象と BASE の指定）、BASE と HEAD のコミットの ID、使った go または node の版、BASE と HEAD のそれぞれでの、実行されたテストの数・比べたファイルの数・比べた関数の数、削除した関数の一覧（(ファイル, 行, 名前)）、比べた関数で網羅率が下がった（拡張では実行回数が 0 になった）ものがないこと。
- **AC-20**: 不合格のとき（AC-08・AC-10・AC-11）と止まったとき（AC-02・AC-04〜AC-07・AC-12・AC-17）は、合格のときの結果を出さず、合格と取り違える出力をしない。止まった理由と、それに当たった関数・テスト・時点を出す。不合格と、止まった場合は、終了コードがどちらも 0 以外であることのほかに、出力で区別できる。
- **AC-21**: 道具の出力に、テストの出力やカバレッジの報告の全文は含めない。コミットメッセージに書く量に収まるよう、AC-19・AC-20 に挙げたものだけを出す。

#### F-006: 道具のテスト

道具の判定は、壊した報告を与えるテストで確かめる。

**Acceptance Criteria**:
- **AC-22**: 道具のテストは、少なくとも次の入力のそれぞれで、道具が合格とせずに止まる、または不合格とすることを確かめる。空の報告（テストの数 0、関数の数 0）。テストが失敗した実行。`FN` と `FNDA` の数が違うまとまり。閉じていないまとまり。形の崩れた Go の出力の行。網羅率が下がった Go の関数。実行回数が 0 になった拡張の関数。同じ行から始まる関数の数が減った場合と、その行に BASE で実行回数 0 の関数がある場合。書き換えられた行から始まる残る関数。HEAD にだけある関数。
- **AC-23**: 道具のテストは、合格する入力（ファイルの途中の関数を削除して、後ろの関数の行番号がずれた場合を含む）で、道具が合格とし、削除した関数を正しく一覧に出すことも確かめる。
- **AC-24**: 道具のテストは、実際の Go や拡張のテストの一式を実行せず、用意した報告と差分を与えて判定を確かめる。道具のテストは、既存の `make test` または `make ext-test` の中で動く。

#### F-007: 手順の書き換え

CLAUDE.md の「Deleting a test is a claim that must be checked」を、この道具を使う手順に書き換える。

**Acceptance Criteria**:
- **AC-25**: [CLAUDE.md](../../../CLAUDE.md)「Deleting a test is a claim that must be checked」は、Go のテストを削除したときは `make coverage-compare BASE=<削除の前のコミット>` を、拡張のテストを削除したときは `make ext-coverage-compare BASE=<削除の前のコミット>` を実行し、合格の結果（AC-19）をコミットメッセージに書くよう求める。両方のテストを削除したときは、両方を実行する。拡張の比較を方針の例外として扱う記述はない。
- **AC-26**: CLAUDE.md の「Commands」に、`make coverage-compare BASE=<commit>` と `make ext-coverage-compare BASE=<commit>` が、それぞれの説明とともに載っている。`make ext-coverage-compare` は、拡張の `ext-*` の対象の一覧（「Extension Commands」）に載っている。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   1 回の実行で、Go または拡張のテストの一式を 2 回（BASE と HEAD）走らせる。それ以上の時間の上限は定めない。テストを削除する変更で、人や agent が一度実行するものだからである（CLAUDE.md「Performance」の、絶対的な予算で判断する方針）。

### 4.2. セキュリティ (Security)

-   N/A。この道具は `yt-dlp` を呼ばず、API キーや Webhook URL を扱わず、キャッシュのディレクトリを読み書きせず、ネットワークで送信せず、信頼できない文字列をプロンプトや記事に埋め込まない（`docs/dev/security.md` の適用条件に当たらない）。BASE のコミットのテストを実行するが、それはリポジトリの利用者自身のコミットであり、`make test`・`make ext-test` を実行するのと同じ範囲の操作である。テストの一式は、今の `make test` と同じく、`yt-dlp`・LLM API・Webhook を呼ばない（CLAUDE.md「Testing Strategy」）。
-   道具が読むカバレッジの報告とテストの出力は、道具自身が実行した go と node のコマンドの出力である。読めない形のものは、飛ばさずに止まる（AC-07）。報告の大きさの上限は定めない。利用者の機械で、リポジトリのテストの一式が出すものに限られるからである。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   道具は、合格の判定の根拠にならない状態（テストの失敗、空の報告、読めない報告、対応の取れない関数）では、合格としない（F-002・F-004）。
-   途中で止まった場合も、利用者の作業ツリーとブランチは変わらない（AC-03）。

### 4.4. 互換性 (Compatibility)

-   既存の `make` の対象（`make test`・`make test-ci`・`make ext-test` など）の振る舞いは変えない。
-   拡張の比較は、ほかの `ext-*` の対象と同じく、`extension/.node-version` の node の版で動く（AC-04）。
-   macOS と Linux で動く（開発に使う環境）。

### 4.5. 保守性 (Maintainability)

-   依存は増やさない。Go の道具ならば標準ライブラリだけを使い、`.golangci.yml` の `depguard` に module を加えない。拡張の側に置くならば、npm のパッケージを加えない（CLAUDE.md「Dependencies」）。
-   道具の出力の文言、識別子、コメントは英語である（CLAUDE.md「Language」「Go Idioms」）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   CLAUDE.md「Tool Execution Safety」に従う。道具はネットワークを使わない。`extension/node_modules` がないときは自分で入れず、止まる（AC-04）。
-   道具の判定に使う値は、道具が実行したテストの報告から読む。テストの数・関数の数・削除した関数を利用者が申告する形にはしない（1 章「要件定義の際に決めたこと」）。

## 6. 用語集 (Glossary)

-   **カバレッジの報告:** テストの一式を実行したときに、関数ごとの実行の記録を出したもの。Go は `go tool cover -func` の出力、拡張は node のテストランナーが出す lcov の形式のもの（0027・0054 と同じ用語）。
-   **網羅率:** Go の `go tool cover -func` が関数ごとに出す、その関数の文のうちテストで実行された文の割合。
-   **実行回数:** 拡張の lcov の中で、関数ごとに記録される、テストの実行中にその関数が呼ばれた回数（`FNDA` の値。0054 と同じ用語）。
-   **BASE:** 削除の前の時点として、利用者が `BASE=<commit>` で指定するコミット。
-   **HEAD:** 削除の後の時点。道具を実行したときの今のコミット。
-   **本番のコード:** 比べる対象のファイル。Go では、テスト用のビルドタグ `test` を付けずにビルドされるファイル（`_test.go` を除く）。拡張では `extension/src/` と `extension/scripts/` の下のファイル。
-   **本番の関数:** 本番のコードのファイルにある関数。
-   **削除した関数:** BASE の本番の関数のうち、始まりの行が BASE から HEAD への差分で削除された行に当たるもの（AC-15）。
-   **残る関数:** BASE の本番の関数のうち、削除した関数でないもの（AC-16）。
-   **対応が取れない:** 残る関数と HEAD の関数を、差分の変わらない行で 1 対 1 に結べない状態（AC-11・AC-12・AC-17）。
-   用語は `docs/translation_glossary.md` と統一する。
