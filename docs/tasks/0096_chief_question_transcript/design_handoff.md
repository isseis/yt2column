# 設計への申し送り（0096）

要件定義の段階で挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目にとった方針か、当てはまらない理由を記録する。

## H-01: transcript の読み方と、その費用

**懸念:** 状況の表を作るたびに、Claude Code の pane ごとに最大 64 MiB の transcript を読むことになる（AC-22）。今は、リセットの判定のときだけ 64 MiB の上限で読んでいる（`internal/chief/reset.go:59`）。

**なぜ重要か:** 待ち受けの周ごとの費用が、pane の数と transcript の大きさに比例して増える。CLAUDE.md の「Performance」は、仕組みを足す前に、実際の時間を測ることを求める。

**候補:** まず、毎回すべてを読む形で、大きな transcript の 1 周の時間を測る。費用が問題になる場合に限って、前回読んだ位置から続きを読む形を考える。その場合、ファイルの差し替えや切り詰めを見分けることが、正しさのための新しい義務になる。

**関連:** AC-22、4.1

## H-02: 照合値の作り方

**懸念:** 今の照合値は、画面から読んだ問いの文・選択肢・カーソルの位置と、Herdr の `agent_session` と `state_change_seq` から作っている（`internal/chief/relay.go:35`）。transcript には、カーソルの位置がない。

**なぜ重要か:** 照合値に入れる部分が、送る直前に「同じ問いである」と言える範囲を決める。

**候補:** 呼び出しの ID、問いと選択肢の中身、pane、`agent_session` から作る。`state_change_seq` を入れるかどうかは、答えを待っている間に Herdr の値が変わるかを確かめてから決める。照合値は、今と同じく中身を読めない値にする（CLAUDE.md の「Keep internals unobservable」）。

**関連:** AC-14、AC-17

## H-03: 送る直前の画面と、transcript の問いの比べ方

**懸念:** 画面は、問いの文や選択肢の文を折り返して描く。また、transcript にない選択肢（自由に書く答え「Type something.」、チャットへ移る答え「Chat about this」）を、transcript の選択肢の後に番号を付けて描く。

**なぜ重要か:** 比べ方が厳しすぎると、合っている問いでも送れない。緩すぎると、画面の確かめの意味がなくなる。

**候補:** 今の画面の読み取り（`internal/chief/screen_claude.go:228`）で 1 つを選ぶ問いを読み、問いの文と選択肢の番号・`label` を、空白と折り返しをそろえたうえで transcript と比べる。transcript の選択肢の数に 1 と 2 を足した番号に、自由に書く答えとチャットの選択肢があることも確かめる。選択が自由に書く答えにある画面と、そこに文字が打たれている画面は、合わないものとする（AC-15）。そのときに数字のキーが文字として入るかは確かめていないので、確かめる。

**関連:** AC-15

## H-04: サブエージェントの呼び出しの見分け方

**懸念:** サブエージェントが質問か権限の確認で待っているとき、親の transcript には答えのないサブエージェントの呼び出しが残る。要件は、その pane を「要確認」にする（AC-11）。道具の名前が `Agent` であることは手元の transcript で見たが、サブエージェントの行が親の transcript に書かれるか（手元の transcript には `isSidechain` が `true` の行はなかった）、別の名前の道具がサブエージェントを起動するかは確かめていない。

**なぜ重要か:** 見分けられないと、サブエージェントの呼び出しを権限の確認として示し、人を誤らせる。サブエージェントの行が親の transcript に書かれるなら、その中の質問の呼び出しを親の質問として示しうる。

**候補:** サブエージェントが質問と権限の確認で待っている間の transcript をサンプルとして採り、どの行が書かれるかを確かめる。親の transcript にサブエージェントの行が書かれると分かれば、その行の扱いを要件に足すために、本書を `draft` に戻して決め直す。

**関連:** AC-09、AC-11、4.2

## H-05: 答えを待っている間の transcript のサンプル

**懸念:** 本書の確かめ（1 章の背景）は、答えた後の transcript で行った。答えを待っている間の transcript（質問の呼び出しの後に、どんな種類の行が書き足されるか）と、権限の確認を待っている間の transcript は、サンプルとして採っていない。

**なぜ重要か:** 受け付ける形と、書きかけの行の扱い（AC-21）が、実際の書き足しに合っているかを確かめる必要がある。

**候補:** 1 つを選ぶ問い、複数を選ぶ問い、問いが 2 つの呼び出し、権限の確認のそれぞれで、答えを待っている間の transcript と Herdr の状態を採り、Herdr が権限の確認の間に `blocked` と報告するか（1 章の背景の前提）も確かめる。`internal/chief/testdata/transcript/` に置く。実データの扱いは `docs/dev/security.md` の 7 章に従う。

**関連:** AC-01〜AC-13、AC-21

## H-06: 同じ呼び出しの ID が別の種類の行にあること

**懸念:** 同じ呼び出しの ID が、`type` が `api-request-blob` の行にも書かれ、その中身は `assistant` の行と異なることがある（1 章の背景）。

**なぜ重要か:** その行も読むと、同じ ID の呼び出しが 2 つあることになり、AC-09 や 4.2 の拒む入力に当たって、どの pane も「要確認」になる。

**候補:** 要件（4.2）のとおり、`assistant` の行の呼び出しと `user` の行の答えだけを読み、ほかの種類の行は読まない。この行の扱いを、テストのサンプルに含める。

**関連:** 4.2

## H-07: 使わなくなる画面の読み取り

**懸念:** Claude Code の画面の読み取りのうち、権限の確認、タブのある問いとその確認のページ、複数を選ぶ問いの読み取り（`internal/chief/screen_claude.go:350`・`:389` など）は、本書の後、表の判定に使わなくなる。中継の直前の確かめ（AC-15）と、送る前の確かめ（AC-25）で使う部分は残る。

**なぜ重要か:** 使わない読み取りを残すと、保守とテストの費用が残る。消すと、AC-25 の「画面が質問を示すときも止める」の範囲が狭まる。

**候補:** AC-25 の止める確かめに要る部分を決め、それ以外を消すか #908 に残すかを、設計で決める。消すときは、CLAUDE.md の「Testing Strategy」に従い、テストの削除を単独のコミットにして、カバレッジを比べる。

**関連:** AC-15、AC-25、AC-26
