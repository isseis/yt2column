# 設計への申し送り（0035）

要件定義の際に挙がった、設計（`02_architecture.md`）で扱う事項。`02_architecture.md` は、各項目について採った方法か、当たらない理由を記録する。

-   **H-01: ファイルのバイト列の比較をやめた後の、起動の順序の保証。** 今は、config のファイルのバイト列を git を起動する前に比べ、その後で `git config --list` を起動している（`internal/fixprguard/gitstate.go:514-561`）。バイト列の比較をやめるなら、書き換えられた config のまま `git config --list` を起動しても、コマンドが起動されないことを確かめる。確かめる対象は、`gitHardening` の `-c` が上書きしない設定、`include.path`・`includeIf` の読み込み、壊れた config のときの振る舞い、FIFO やデバイスを指す include（`gitTimeout` の 2 分まで待つことになるか）である。確かめられない場合は、要件書 1 章「本書の記述範囲」のとおり、レビュアーに戻す。
-   **H-02: 外す対象のブランチの設定を読む git の有無。** ツールが実行の間に起動する git（`config --get`・`status`・`diff`・`diff-tree`・`add`・`commit`・`ls-files`・`ls-remote`・`push`・`rev-parse`・`symbolic-ref`・`cat-file`）と、`inspect` が起動する `gh`（とその中で `gh` が起動する git。0030 `02_architecture.md` 3.7）が、今のブランチ以外の `branch.<name>.*` を読まないことを確かめる。`push` は明示した refspec を使うので、`push.default` や upstream の解決には頼らない（`gitstate.go:612-650`）。build checks（`make test`）が起動する git は、ツールの守りの対象ではない（0030 `02_architecture.md` 5.3）。
-   **H-03: 今のブランチと `main` の名前の求め方。** 要件書 3.1 は、今のブランチを `begin` の時点のブランチと定める。基準値は、ブランチの名前をダイジェストでしか持たない（`gitstate.go:98-113`）。設定の名前のサブセクションのダイジェストを基準値のものと比べるなどの方法で、比較の前に git を起動せずに済むかを検討する。`main` を定数とするか、どこから求めるかを決める。`CheckState` は HEAD の確認（`headState`）より前に呼ばれる（`gitstate.go:747-776`）ので、AC-13 の `parts` がどちらになるかもここで決める。
-   **H-04: 設定の値の一覧の形と、名前の分解。** `git config --list -z --show-origin` の出力の形（読み込み元・名前・値の区切り、値を持たない項目の形）を、使う git の版で確かめる。セクションと変数の名前は小文字で、サブセクションはそのまま出力されると考えている。古い `[branch.Name]` の書き方では、サブセクションも小文字になる。これも確かめる。サブセクションは、最初の `.` と最後の `.` の間として取り出す。AC-04・AC-05 の `branch.feature.a.remote`、`[branch "Feature"]`、`[branch.Feature]` は、テストの入力の候補である。
-   **H-05: 基準値のトークンの形と `Protocol`。** トークンの版（`baselineVersion`、`gitstate.go:28-32`）を上げるか、項目の数を変えるかを決める。いずれにしても、前の版のトークンは `ParseBaseline` が `ErrInvalidInput` で拒否する（AC-15）。トークンにブランチの名前や設定の値を平文で入れないこと（ダイジェストは今と同じく可）を、0030 の方針として保つ。トークンの形の変更が、ガイド 9 章の「出力または引数の契約の変更」に当たるかを判断する。当たれば `Protocol` を上げる（AC-19）。
-   **H-06: タスク 0034 との順序。** 0034 の要件案（PR #429）も、基準値に項目を加える。本タスクのトークンの形を、0034 が上に重ねやすい形にする。0034 の要件案の `gitstate.go` の行番号の引用は、0034 の側で合わせる。
-   **H-07: テストの構成。** 一時ディレクトリの実際のリポジトリで、別の worktree から外す対象のブランチの設定を変える場合と、`git config` で直接書く場合を作る（0030 のテストの方法。ガイド 9 章）。CLAUDE.md「A layered path needs inputs only one layer can handle」に従い、ファイルの比較と値の一覧の比較が並ぶ場合は、どちらの比較が止めたのかを区別できる入力を使う。
-   **H-08: git の最低の版。** `gitstate.go:66-71` のコメントは、使う機能がすべて git 2.5 以降にあるとしている。しかし、`git config --show-origin` は 2.8、`includeIf` は 2.13 からと考えられる。使う機能と最低の版を確かめ、コメントとガイドを合わせる。
-   **H-09: 前提とした git と `gh` の振る舞いの確認。** 次の前提を、git と `gh` の文書か実際の動作で確かめる。(1) git は、`branch.<name>.*` を、`<name>` がブランチの名前と完全に一致するときだけ使う。(2) issue #431 の表の操作（`gh pr checkout` を含む）が書き込むのは、そのブランチの `branch.<name>.*` だけであり、`main` の設定には書き込まない。`gh pr checkout` が `remote.*` を加える場合（fork の PR など）は、AC-08 のとおり止まる。
