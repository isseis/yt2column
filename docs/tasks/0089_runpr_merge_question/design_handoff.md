# 設計への申し送り（0089）

要件定義の段階で挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目にとった方針か、当てはまらない理由を記録する。

## H-01: 詳細ファイルの場所・名前と、古い中身で承認しないための書き方

**懸念:** 詳細ファイルは作業ツリーの外に置く（AC-06）。問いをもう一度尋ねるたびに書き直す（AC-11）。場所と名前、前の回の中身を残さない書き方（上書きするか、回ごとに別のファイルにするか）は、要件で決めていない。

**なぜ重要か:** 前の回の詳細ファイルが残っていて要約がそれを指すと、利用者は古い本文を見て承認する。逆に、利用者が詳細ファイルを手で編集した場合に、その編集をマージに使うかも決まっていない。要件では、マージに使うメッセージは `/runpr` が書いたものと同じとしている（AC-12）。

**候補:** `mergepr prepare` が作る準備のディレクトリか、スクラッチパッドの下に、PR 番号と head を名前に含むファイルを置き、問いのたびに書き直す。マージには、`mergepr` の件名と本文のファイルだけを使い、詳細ファイルは読み戻さない。詳細ファイルを編集してもメッセージは変わらないことを、要約か詳細ファイルに書く。

**関連:** F-002、AC-06・AC-11・AC-12

## H-02: deferred の問いを `runpr.md` のどこに置くか

**懸念:** deferred の問い（F-001）は、step 3 の後、マージの質問の前に来る。step 3 の末尾に置くか、step 4 の前の項目に置くか、新しい step にするかは決めていない。新しい step にすると、後の step の番号と見出しが変わる。

**なぜ重要か:** `_lib/simple-process.md` は `runpr.md` の step を番号と見出しの言葉で参照しており、step の番号を変える変更は同じ PR でそこを確かめる必要がある（`simple-process.md` の冒頭）。文書のガードのテストも、step の見出しを定数として読む（`cmd/yt2column/fixpr_docs_test.go` の `runprStep1`〜`runprStep4`、`codex_review_docs_test.go` の `runprStep5`）。

**候補:** step 番号を変えないよう、step 4 の項目 1（`mergepr.md` の準備）より前に deferred の問いの項目を置く。または step 3 の末尾に置く。どちらにするかは、直すと step 3 に戻るという流れ（AC-03）の書きやすさで決める。

**関連:** F-001、AC-01〜AC-05、AC-21

## H-03: 文書のガードのテストの直し方

**懸念:** `cmd/yt2column/codex_review_docs_test.go` の `postingSections` は、`runpr.md` step 4 の節に、追跡 issue への投稿（`gh issue comment <issue> --body-file`、`gh issue create `）と `fixprguard reply ` があることを前提に、その節のメンションの確認を確かめている。deferred のスレッドの手順を step 4 の外へ移すと、この対象を合わせる必要がある。

**なぜ重要か:** 対象がずれると、メンションの確認の抜けをテストが見つけなくなるか、テストが落ちる。メンションの確認は、文書のテストの例外として残す信頼の境界である（`CLAUDE.md`「Testing Strategy」）。

**候補:** H-02 で決めた置き場所に合わせて、`postingSections` の節の見つけ方と投稿の命令の一覧を直す。選択肢の文言や要約の行の形は、文の意味に当たるので、テストにせず PR のレビューで読む（[ADR-0016](../../dev/adr/0016-document-test-policy.md)）。

**関連:** F-001、AC-02、5 章

## H-04: 要約の行と選択肢の文言

**懸念:** 要約の各行（AC-07〜AC-09）、選択肢の label と description（AC-01・AC-14・AC-15）、自由記述でできる操作の 1 行（AC-17）の文言は決めていない。

**なぜ重要か:** OpenCode でも画面に収まるかは、行の長さと選択肢の数で決まる。0088 の chief は、選択肢を画面のとおりに人へ示して中継する（ADR-0046）。

**候補:** issue #857 の「案 1」の要約の例を基にする。選択肢の description は 1 行に収め、条件や理由は要約と詳細ファイルに置く。

**関連:** F-002・F-003、AC-07〜AC-10・AC-14・AC-15・AC-17
