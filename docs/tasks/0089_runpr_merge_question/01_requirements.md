## 1. 概要 (Overview)

**目的:** 本書は、`/runpr` のマージの質問を画面に収まる形にするための要件を定義する。具体的には、詳細を作業ツリーの外のファイルに書いて会話には要約だけを出し、問いを 1 つの単一選択にまとめ、deferred のスレッドをマージの質問より前に片付ける（[#857](https://github.com/isseis/yt2column/issues/857)）。

**背景:**

`/runpr` は、PR をマージする前に 1 回だけ利用者に尋ねる（マージの質問。`.claude/commands/runpr.md:712-715`）。今のマージの質問には、次の 2 つの問題がある。

-   **メッセージに出す情報が多い。** メッセージには、`mergepr.md` step 3 が求める項目（PR の URL、ベースブランチ、CI の結果、squash commit の件名と本文の全文、接頭辞を決めた規則の記録、承認の行のない版）を出す（`runpr.md:729-732`、`.claude/commands/mergepr.md:118-126`）。さらに、PRE_MERGE の変更、diff 記録の再記録、PR の説明に追記できなかった編集上の訂正、`#未記入` の行、deferred のスレッド、除外スレッド、NEXT（`runpr.md:732-747`）、実装モデル要件と推奨するモデル（`runpr.md:748-766`）、LIMITS_NOTE（`runpr.md:766`）も出す。
-   **問いと選択肢が多い。** 1 回の `AskUserQuestion` の中に、deferred のスレッドの問い、PR レビューの問い、マージの問いの最大 3 問がある（`runpr.md:766-806`）。マージの問いの選択肢だけで最大 5 つある（`runpr.md:781-802`）。

そのため、表示が画面に収まらない。特に OpenCode では選択肢が画面の外へ押し出され、選べなくなる（issue #857 の「背景」）。

deferred のスレッドは、`/fixpr` が 3 回目以降のラウンドで、自動レビュアーの `worth-fixing` の指摘を直さずに残したスレッドである（`.claude/commands/fixpr.md:140-147`）。今は、マージの質問で直すスレッドを選ばせ（`runpr.md:768-775`、`runpr.md:823-833`）、選ばなかったスレッドを、マージを選んだ答えの後に追跡 issue へ移している（`runpr.md:929-961`）。

対応 issue: [#857](https://github.com/isseis/yt2column/issues/857)

関連: [#837](https://github.com/isseis/yt2column/issues/837)・[#838](https://github.com/isseis/yt2column/issues/838)（タスク 0088 の chief。マージの質問の答えを中継し、マージの後の次のコマンドを送る）

本書で使う用語は 6 章で定義する。

**本書の記述範囲:** 本書は、マージの質問とその前の deferred の問いで利用者が見るもの、選べるもの、答えごとの振る舞い、およびそれらを説明する文書の記述を定める。次の事項は設計（`02_architecture.md`）で決める。

-   `runpr.md` の中で deferred の問いをどの step に置くか、その step と step 3・step 4 の行き来の書き方。
-   詳細ファイルの場所と名前、要約の各行と選択肢の文言。
-   文書のガードのテストの直し方と、加えるかどうか。

要件の起草の際に挙がった設計の事項は、[design_handoff.md](design_handoff.md) に申し送る。

**issue #857 で決めたこと:**

-   **詳細はファイルに書き、会話には要約だけを出す（issue の案 1）。** 会話に出すのは約 10 行の要約と、詳細ファイルのパスだけにする。PRE_MERGE や diff 記録の再記録が多い PR では、問いを 1 つにしても本文が画面からはみ出すためである（issue の「方針」）。
-   **`AskUserQuestion` の question の文は 1 行にし、長い本文を question の欄に入れない（issue の案 1）。** 本文を question の欄に入れると、選択肢が画面の外へ押し出されるためである。
-   **問いを、条件付きの選択肢を持つ単一選択の 1 問にする（issue の案 2）。** 選択肢を画面に収めるためである。
-   **「NEXT をこのセッションで実行」を削除する（issue の案 2）。** step 5 は NEXT の前に `/clear` を勧めており（`runpr.md:1052-1061`）、この選択肢はもともとそれと食い違っていた。NEXT のコマンドは、これまでどおり step 5 で示す。
-   **NEXT のモデルの情報は 1 行にまとめ、例外の場合の詳細はファイル側に書く（issue の案 3）。** 案 1 の要約の 1 行として扱う。
-   **影響範囲は `runpr.md` step 4（必要に応じて step 5）、`mergepr.md` step 3、文書のガードのテスト、ADR の判断とする（issue の「影響範囲」）。**

**要件定義の際に決めたこと（2026-11-12）:**

-   **進め方は通常の進め方にする。** 除外の判定は「対象外（疑わしい）」とする。squash commit の本文を会話の外へ移すと、マージの承認の前に人が見るものが変わり、`mergepr` の承認の守りに触れる。開発用の道具の信頼の境界（[requirements_process.md](../../dev/conventions/requirements_process.md)「Simple Process」の「Excluded changes」）に当たるかを判断しきれないので、規則に従い対象外とした。加えて、ADR を新しく作り、既存の ADR の決定を変え、2 つのコマンドにまたがる。ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
-   **削除する選択肢は「NEXT をこのセッションで実行」だけにする。** タスク 0088 で、マージの後の次のコマンドは chief が送るようになるためである（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)）。issue #857 の案 2 は「承認なしでマージ」と「通常の進め方へ戻す」も自由記述に移すとしていたが、この 2 つは選択肢に残す（F-003）。ADR: [ADR-0047](../../dev/adr/0047-runpr-merge-question.md) を作る。
-   **3 文書の PR の「通常の進め方へ戻す」は選択肢に残す。** [ADR-0040](../../dev/adr/0040-simple-task-documents.md) は、3 文書の PR では承認なしでマージする選択肢の代わりにこの選択肢を示すと決めている。自由記述だけで受け付ける案は「戻せることに人が気づきにくい」として採らなかった。選択肢に残せば、ADR-0040 の決定は変わらない。ADR: ADR-0040 は変えない。
-   **deferred のスレッドは、マージの質問より前に、別の問いで片付ける（F-001）。** 直すか追跡 issue に移すかは、マージするかどうかとは別の判断である。マージの時点で扱うのは遅く、片付けてからマージを判断するべきだからである。これによってマージの質問の選択肢は最大 4 つに収まる。ADR: ADR-0047。
-   **3 文書の PR の除外スレッドは、マージの質問に残す（F-003）。** 除外スレッドが残っている間、マージの質問の選択肢は「通常の進め方へ戻す」と「マージしない」が中心になる（AC-15）。判定を覆すスレッドは、番号を自由記述で指定する。除外スレッドの判定を覆すか通常の進め方へ戻すかを、マージの質問で人に示すという ADR-0040 の決定を変えないためである。ADR: ADR-0040 は変えない。
-   **squash commit の件名は会話に出し、本文は詳細ファイルに書く（F-002、F-004）。** issue #857 の未決事項への答えである。本文は長くなりやすく、要約を画面に収めるためである。そのため、`/runpr` の中では、`mergepr.md` step 3 の承認の条件を「本文は詳細ファイルで示す」に改める。ADR: ADR-0047。
-   **単独で実行する `/mergepr` は、今のまま件名と本文の全文を会話に出す（F-004）。** 単独の `/mergepr` が出すのは承認に要る項目だけで、画面に収まるためである。ADR: ADR-0047 に含める。
-   **未レビューの変更があり Escalation の判定が `ask` のとき、「先に PR レビューを依頼」を推奨にし、先頭に置く。このとき「マージ」は推奨にしない（AC-14）。** 今の規則（`runpr.md:776-780`）と同じ扱いである。1 問にまとめると推奨は 1 つしか示せないので、決めておく必要があった。ADR: なし（今の規則を保つだけで、このタスクの中で閉じるため）。
-   **要約には、diff 記録の再記録、`#未記入` の行、PR の説明に追記できなかった編集上の訂正、LIMITS_NOTE を、あるときだけ種類ごとに 1 行で示し、中身は詳細ファイルに書く（AC-08）。** 承認の判断に関わるものがあることを見落とさず、要約を短く保つためである。ADR: なし（要約の行の決め方はこのタスクの中で閉じるため）。
-   **この PR で ADR-0046 を更新する。** ADR-0046 は「NEXT をこのセッションで実行する」答えを中継しないと決めている。選択肢がなくなるので、その記述を除き、経緯に記す。0088 の要件定義書の AC-30・AC-46 は対象を失う。そのことを ADR-0046 に書き、0088 の実装計画で外す。ADR: ADR-0046 を更新する。
-   **マージの質問の形（1 つの単一選択の問い、詳細ファイルと要約、deferred の問いを前に置くこと、`/runpr` の中での squash commit の本文の示し方）は、主要な決定として ADR にする。** `runpr.md` と `mergepr.md` の 2 つのコマンドにまたがり、0088 の chief が中継する問いの形も縛るためである。ADR: ADR-0047 を作る。

**起草の際に補った振る舞い（PR のレビューで確かめる）:** 次の振る舞いは、issue にも上の決定にも定めがない場合について、起草の際に補ったものである。

-   **deferred の問いの選択肢と推奨:** 「すべて追跡 issue に移す」「すべて直す」「マージせずに止める」の 3 つとし、どれも推奨と示さない（AC-01）。直すか移すかは、レビューを終えた人の判断だからである。止める選択肢を置くのは、今のマージの質問でも、マージしない答えで止まれる（`runpr.md:812-813`）ためである。
-   **接頭辞を決めた規則の記録と、承認の行のない版のメッセージ:** 詳細ファイルに書き、要約には出さない（AC-06、AC-07）。どちらも本文と同じく squash commit の中身の確認に使うものだからである。
-   **除外スレッドが残っている間の「先に PR レビューを依頼」:** 未レビューの変更があれば、選択肢に示す（AC-15）。issue #857 は、この場合の選択肢を「通常の進め方へ戻す」と「マージしない」の 2 つとしていた。今は PR レビューの問いが別にあり（`runpr.md:776-780`）、除外スレッドが残っていても PR レビューを依頼できる。その振る舞いを保つためである。選択肢は 3 つまでで、4 つの上限に収まる。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   マージの質問の表示と選択肢が、OpenCode でも Claude Code でも画面に収まり、選べるようにする。
-   承認の判断に要る情報を、要約と詳細ファイルで失わずに示す。
-   deferred のスレッドを、マージを判断する前に片付ける。

### 2.2. スコープ (In Scope)

-   deferred のスレッドを、マージの質問の前に別の問いで片付けること（F-001）。
-   マージの質問のメッセージを、要約と詳細ファイルに分けること（F-002）。
-   マージの質問を 1 つの単一選択の問いにし、選択肢を定めること。「NEXT をこのセッションで実行」を削除し、step 5 の振る舞いを合わせること（F-003）。
-   `mergepr.md` step 3 の承認の条件を、`/runpr` の中では本文を詳細ファイルで示す形に改めること（F-004）。
-   `/runpr` がマージの後に次のコマンドを実行しうると述べる文書の記述と、deferred のスレッドの扱いを述べる文書の記述を合わせること（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   NEXT の決め方（`runpr.md` の「2. Decide the PR's bookkeeping and next command」）と、PRE_MERGE の中身を変えること。本書は示し方だけを変える。
-   `/fixpr` が deferred のスレッドを作る規則（ラウンドの上限。`fixpr.md:140-147`）を変えること。
-   Escalation の判定の規則（`.claude/commands/_lib/pr-review-escalation.md`）を変えること。
-   `/runpr` を走らせるモデルを、修正の難しさに応じて切り替えること。deferred のスレッドを直す修正は、今と同じく `/runpr` のセッションの `/fixpr` が行う。モデルの切り替えは [#840](https://github.com/isseis/yt2column/issues/840) で扱う。
-   単独で実行する `/mergepr` の表示を変えること（F-004 の決定のとおり）。
-   ほかのコマンドの質問の表示を変えること。
-   タスク 0088 の文書（要件定義書の AC-30・AC-46 など）を直すこと。0088 は承認済みの文書を持つので、対象を失った AC は 0088 の実装計画で扱う。本タスクは ADR-0046 にそのことを書くだけにする。
-   完了したタスクの文書（`docs/tasks/` の過去のタスク）にある、今のマージの質問の記述を直すこと。過去の時点の記録だからである。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: deferred のスレッドをマージの質問の前に片付ける

`/runpr` は、step 3（Codex の PR レビューと `/fixpr` の往復）を終えて、未解決の deferred のスレッドがあるとき、マージの質問の前に deferred の問いを尋ね、それらを片付けてからマージの質問に進む。

**Acceptance Criteria**:

-   **AC-01**: 未解決の deferred のスレッドがあるとき、`/runpr` はマージの質問より前に、1 つの問いだけを持つ単一選択の `AskUserQuestion`（deferred の問い）を尋ねる。選択肢は「すべて追跡 issue に移す」「すべて直す」「マージせずに止める」の 3 つで、どれも推奨と示さない。メッセージには、各スレッドの番号、要旨、直すと何が変わるか、URL を示す。一部のスレッドだけを直すときは、番号を自由記述で指定する。指定しなかったスレッドは追跡 issue に移す。そのことをメッセージに 1 行で示す。未解決の deferred のスレッドがないときは、deferred の問いを尋ねない。
-   **AC-02**: 追跡 issue に移す答え（「すべて追跡 issue に移す」と、番号を指定した答えの残りのスレッド）では、今のマージの答えの後の手順（`runpr.md:929-961`）と同じく次を行い、その後にマージの質問へ進む。追跡 issue を探すか作り、そこへ書き写し、各スレッドに issue の URL を返信して resolve する。このとき、追跡 issue に投稿する文とスレッドへの返信に、今と同じメンションの確認を行う。メンションの確認に通らないとき、または返信が止まったときは、マージの質問に進まずに止まる。報告の中身は今と同じで、止まったスレッドの URL と止まった種類を示す。
-   **AC-03**: 直す答え（「すべて直す」と、番号を指定した答えのスレッド）では、それらのスレッドを `/fixpr` に caller override として渡し（`fixpr.md:167-170`）、step 3 に戻る。この答えではマージしない。step 3 を終えた後に未解決の deferred のスレッドがあれば、AC-01 の問いをもう一度尋ねる。
-   **AC-04**: 「マージせずに止める」答えでは、マージの準備があれば破棄して止まる。deferred のスレッドは未解決のまま残す。
-   **AC-05**: 3 文書の PR の除外スレッドは、deferred の問いの対象に含めない。「すべて追跡 issue に移す」と「すべて直す」は除外スレッドを含まず、deferred の問いのメッセージにも除外スレッドを示さない。除外スレッドは、マージの質問で扱う（AC-15）。

#### F-002: マージの質問の要約と詳細ファイル

`/runpr` は、マージの質問のたびに、承認の判断に要る詳細を作業ツリーの外の詳細ファイルに書き、会話には要約だけを出す。

**Acceptance Criteria**:

-   **AC-06**: マージの質問を尋ねる前に、`/runpr` は詳細ファイルを作業ツリーの外に書く。詳細ファイルには、今のマージの質問がメッセージに出している項目（`runpr.md:729-766`）のうち、F-001 で前に移した deferred のスレッドを除くすべてを書く。対象は次のとおりである。
    -   PR の URL、ベースブランチ、CI の結果。
    -   squash commit の件名と本文の全文、接頭辞を決めた規則の記録、承認の行のない版のメッセージ（当てはまるとき）。
    -   PRE_MERGE の変更（どのファイルのどの行か、承認の行が書くレビュアーの名前と日付、PR 番号の記入の行）。
    -   diff 記録の再記録（AC の文、記録した出力と新しい出力の違い、新しい出力で AC が成り立つという判断）。
    -   PR の説明に追記できなかった編集上の訂正、`#未記入` の行。
    -   3 文書の PR の除外スレッド（番号、除外の印、要旨、理由、URL）。
    -   Escalation の判定とその理由（未レビューの変更があるとき）。
    -   NEXT、実装モデル要件と推奨するモデル、およびその読み方の詳細（旧値、読めない値、値がないときの理由）。
    -   LIMITS_NOTE（あるとき）。

    詳細ファイルを書いても、作業ツリーの `git status --short` の出力は変わらない。
-   **AC-07**: マージの質問のとき会話に出すメッセージは、次の行だけからなり、各項目は 1 行である。
    -   PR の番号、ベースブランチ、CI の結果。
    -   squash commit の件名。
    -   PRE_MERGE の要約（変えるファイルと行の数、承認か PR 番号の記入か。PRE_MERGE がないときは「なし」）。
    -   未レビューの変更の有無（あるときは Escalation の判定）。
    -   除外スレッドの数（3 文書の PR で、除外スレッドがあるときだけ）。
    -   NEXT（AC-09）。
    -   AC-08 の「要確認」の行（あるときだけ）。
    -   自由記述でできる操作（AC-17）。
    -   詳細ファイルのパス。

    squash commit の本文、接頭辞を決めた規則の記録、承認の行のない版のメッセージは、会話に出さない。
-   **AC-08**: diff 記録の再記録、PR の説明に追記できなかった編集上の訂正、`#未記入` の行、LIMITS_NOTE のうち、該当するものがある種類だけ、要約に種類ごとに 1 行を出す。その行は種類と件数を示し、中身は詳細ファイルにあることを示す（例:「要確認: diff 記録の再記録 1 件（詳細ファイル）」）。該当するものがない種類の行は出さない。
-   **AC-09**: NEXT の行は、NEXT がないときは「なし」を示す。NEXT が `/runplan` のときは、コマンドと引数、実装モデル要件の値、推奨するモデルを 1 行で示す（例: `NEXT: /runplan 0083（要件 sonnet → Sonnet）`）。旧値のときは、旧値と読み替えた値を同じ行に示す。読めない値のとき、または値がないときは、そのことと推奨するモデルがないことを同じ行に示し、理由（値の文、値がない理由）は詳細ファイルに書く。NEXT がそれ以外のコマンドのときは、コマンドと引数を示す。
-   **AC-10**: マージの質問の `AskUserQuestion` の question の文は 1 行で、要約の行も詳細ファイルの中身も含まない。選択肢の label と description にも、要約の行や詳細ファイルの中身を入れない。
-   **AC-11**: マージの質問をもう一度尋ねるとき（PR レビューの後、deferred のスレッドを直した後、メッセージを直した後、PRE_MERGE の commit の後の取り直しなど）は、そのたびに詳細ファイルと要約を、そのときの head と squash commit のメッセージに合わせて書き直す。要約が示すパスの詳細ファイルは、その回の問いで示した中身を持つ。
-   **AC-12**: マージする答えでマージに使う squash commit のメッセージは、その回の問いで要約に示した件名と、詳細ファイルに書いた本文（承認なしでマージする答えでは、承認の行のない版）と同じである。メッセージを直す自由記述の答えでは、今と同じく件名と本文を書き直し、件名を確かめ直してから（`runpr.md:808-811`）、AC-11 のとおり問いをもう一度尋ねる。

#### F-003: マージの質問の選択肢

マージの質問は、1 つの単一選択の問いで、条件付きの選択肢を最大 4 つ持つ。

**Acceptance Criteria**:

-   **AC-13**: マージの質問は、1 つの問いだけを持つ `AskUserQuestion` で、単一選択である。複数を選ぶ問いと、2 つ目の問いを持たない。
-   **AC-14**: 除外スレッドが残っていないとき、選択肢は次の表の条件に合うものを、表の順に示す。示す数は 4 つ以内になる。

    | 選択肢 | 示す条件 | 推奨 |
    |---|---|---|
    | 先に PR レビューを依頼 | 未レビューの変更があり（LAST_REVIEWED が head より前か、ない）、Escalation の判定が `ask` のとき。この行を先頭に置く | 推奨 |
    | マージ（PRE_MERGE があるときは、PRE_MERGE を記録してマージ） | 常に | Escalation の判定が `ask` でないとき推奨。`ask` のときは推奨にしない |
    | 先に PR レビューを依頼 | 未レビューの変更があり、Escalation の判定が `ask` でないとき | 推奨にしない |
    | 承認なしでマージ（PR 番号だけを記録する） | 今と同じ条件（`runpr.md:788-799`）。PRE_MERGE に承認があるタスク文書の PR で、3 文書の PR とプランの PR を除く | 推奨にしない |
    | 通常の進め方へ戻す | 3 文書の PR（今と同じ条件。`runpr.md:800-801`） | 推奨にしない |
    | マージしない | 常に。最後に置く | 推奨にしない |

    「先に PR レビューを依頼」は、Escalation の判定によって 1 行目か 3 行目のどちらか一方だけに示す。「承認なしでマージ」と「通常の進め方へ戻す」は、同じ PR に両方が示されることはない。
-   **AC-15**: 3 文書の PR で除外スレッドが残っているとき、選択肢は「通常の進め方へ戻す」と「先に PR レビューを依頼」（未レビューの変更があるときだけ）と「マージしない」だけで、どれも推奨と示さない。判定を覆して直す除外スレッドは、番号を自由記述で指定する。その答えは、今と同じく覆すスレッドとして `/fixpr` に渡し（`runpr.md:829-833`）、マージしない。
-   **AC-16**: マージの質問に、NEXT をこの `/runpr` のセッションで実行する選択肢はない。どの答えでも、`/runpr` は NEXT を実行しない。step 5 は、NEXT があり次のブランチを用意し終えたとき、`/clear` の案内（`runpr.md:1052-1061`）を付けて最終の状態を報告して終わる。
-   **AC-17**: マージの質問のメッセージは、自由記述でできる操作を 1 行で示す。その操作は、メッセージを直すこと、除外スレッドの判定を番号で覆すこと（3 文書の PR で除外スレッドがあるときだけ）である。
-   **AC-18**: `runpr.md` の step 4 と step 5 の、答えを受けた手順の diff は、次の 3 つに限る。deferred のスレッドを扱う手順の F-001 への移動、NEXT を続けて実行する答えとその分岐の削除、AC-11 の書き直しと AC-12 のメッセージの扱い。PR レビューを依頼する答え、承認なしでマージする答え、通常の進め方へ戻す答え、マージしない答え、PRE_MERGE の記録とマージの手順は、本書が変える点のほかは変えない。

#### F-004: `mergepr.md` の承認の条件

**Acceptance Criteria**:

-   **AC-19**: 単独で実行する `/mergepr` は、今と同じく、PR の URL、ベースブランチ、CI の結果、件名と本文の全文、接頭辞を決めた規則の記録を会話に示してから承認を尋ねる。`mergepr.md` の diff は、step 3 の「`runpr.md` の中で実行するとき」を述べる文に限る。その文は次の 2 点を述べる。`runpr.md` step 4 が、件名を会話に、本文と接頭辞を決めた規則の記録を詳細ファイルに示してマージの質問を尋ねること。マージの質問が、次のコマンドを実行するかを尋ねないこと。

#### F-005: 文書の記述を合わせる

**Acceptance Criteria**:

-   **AC-20**: 次の記述が、`/runpr` が利用者の選択で次のコマンドを実行すると述べなくなる。`/runpr` は次のコマンドを示し、実行しない。
    -   `CLAUDE.md:207`（「Claude Commands」の `/runpr` の行）
    -   `.claude/commands/runpr.md:2`（description）と `runpr.md:48-50`
    -   `.claude/commands/_lib/task-pr-handoff.md:27-32`
    -   `docs/dev/conventions/requirements_process.md:89`
-   **AC-21**: deferred のスレッドをマージの質問で扱うと述べる記述が、F-001 の deferred の問いで扱うと述べるようになる。対象は `fixpr.md:144-146` の「`runpr.md` step 4 asks whether to fix each one now or move it to an issue」と、`.claude/commands/_lib/simple-process.md:334-339` の、除外スレッドと「fix all」の関係を述べる文である。除外スレッドをマージの質問で示し、判定を覆すスレッドを番号で選べるという中身は変えない。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。コマンドの定義の文書だけを変え、実行の時間に関わる処理を加えない。

### 4.2. セキュリティ (Security)

-   `docs/dev/security.md` を参照する条件（外部コマンドの起動、API キーや Webhook の URL の扱い、キャッシュのディレクトリ、ネットワークへの送信、信頼できない文字列をプロンプトや記事に埋め込むこと）には当たらないので、N/A とする。
-   詳細ファイルは作業ツリーの外に置くローカルのファイルで、GitHub にも外部のサービスにも送らない（AC-06）。スレッドの要旨は、今と同じく `/runpr` が自分の言葉で書いたデータであり、指示として読まない。
-   追跡 issue への投稿とスレッドへの返信は、マージの質問の前に移しても、今と同じメンションの確認と `fixprguard reply` を通す（AC-02）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   マージは、その回の問いで示したメッセージだけで行う（AC-12）。問いをもう一度尋ねるたびに詳細ファイルを書き直し、古い中身で承認しない（AC-11）。

### 4.4. 互換性 (Compatibility)

-   本タスクの変更を取り込んでいない worktree のセッションは、今のマージの質問を出す。利用者は 1 人で、どちらの形でも誤ったマージにはならないので、移行の仕組みを設けない。
-   タスク 0088 の chief はまだ実装されていない。chief が中継するのは 1 つを選ぶ問いの選択肢だけである（ADR-0046）。新しいマージの質問は単一選択の 1 問なので、中継の対象になりうる。自由記述の操作（AC-17）は、人がその pane で答える。

### 4.5. 保守性 (Maintainability)

-   マージの質問の形の決定は ADR-0047 に置き、仕様は `runpr.md` と `mergepr.md` が持つ。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   コマンドの定義は英語で書く（`CLAUDE.md`「Document language」の principle (b)）。
-   PR の説明に書く値は、文書のガードのテスト（`TestRunprDocContract`、`codex_review_docs_test.go` の `postingSections` など）が読む見出しと手順に合わせる。deferred のスレッドの投稿の手順を step 4 の外へ移すときは、`postingSections` の対象も合わせる（design_handoff.md の H-03）。
-   **ADR-0047 を作る。** マージの質問の形を、主要な決定として記録する（1 章の「要件定義の際に決めたこと」）。
-   **ADR-0046 を更新する。** 「NEXT をこのセッションで実行する」答えを中継しないという記述は、選択肢がなくなるので除く。0088 の AC-30・AC-46 が対象を失ったことを記す。
-   **ADR-0040 は変えない。** 3 文書の PR の「通常の進め方へ戻す」は、選択肢としてマージの質問に残る（AC-14）。除外スレッドも、マージの質問で人に示す（AC-15）。
-   方針の例外はない。

## 6. 用語集 (Glossary)

-   **マージの質問**: `runpr.md` step 4 が、マージの前に利用者に 1 回尋ねる問い（用語集の「簡易な進め方」の説明と同じ呼び方）。
-   **deferred のスレッド**: `/fixpr` が 3 回目以降のラウンドで、自動レビュアーの `worth-fixing` の指摘を直さずに残した、未解決のレビューのスレッド（`fixpr.md:140-147`）。
-   **deferred の問い**: F-001 の、マージの質問の前に deferred のスレッドを片付けるための問い。
-   **除外スレッド**: 3 文書の PR で、修正に除外に当たる決定が要るレビューのスレッド（`.claude/commands/_lib/simple-process.md`「When an excluded decision appears」）。
-   **追跡 issue**: `/runpr` が直さない deferred のスレッドを書き写す issue「PR #<number> のレビュー指摘の追跡」（`runpr.md:929-944`）。
-   **詳細ファイル**: マージの質問のたびに `/runpr` が作業ツリーの外に書く、承認の判断に要る詳細のファイル（F-002）。
-   **要約**: マージの質問のとき会話に出すメッセージ（AC-07）。
-   **NEXT、PRE_MERGE、LAST_REVIEWED、Escalation、LIMITS_NOTE**: `runpr.md` の定義のとおり。
-   ほかの用語は `docs/translation_glossary.md` と統一する。
