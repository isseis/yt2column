# 設計への申し送り：テキストが選択されていないとき、文字起こしパネルの DOM から字幕を読み取る

本書は、[01_requirements.md](01_requirements.md) の起草（とレビュー）で挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: パネルとセグメントの一覧のセレクタ、読む範囲

-   **事項:** 文字起こしパネルと、その中のセグメントの一覧を指すセレクタを確定する。読む範囲を、パネルの見出し・検索欄・操作ラベルを含まないセグメントの一覧に絞れるかを決める。絞れない場合は、サーバのパーサが読み飛ばす行（0024 の前置き・末尾の操作ラベル）だけが混じることを確かめるか、ほかの扱いを決める。
-   **理由:** パネルは `ytd-engagement-panel-section-list-renderer[target-id="PAmodern_transcript_view"]` の中にある（issue #330）。形 A と形 B は DOM の版の違いから生じるので、セレクタが両方の版で同じとは限らない。チャプターの見出しの行は、セグメントの一覧の中に差し込まれるので、絞っても残りうる（0024 F-001・F-008 でサーバが読み飛ばす）。
-   **候補の方針:** `testdata/2tcCWM-sRBw.transcript_panel.html` と、リポジトリの外のスナップショット（形 B は `Yoboo9g7saY` など）で、両方の版の DOM を観測して決める。
-   **関連:** F-002、F-006、AC-04、AC-19

## H-02: パネルが開いているかの判定

-   **事項:** パネルが DOM にあって開いている（表示されている）ことを判定する手段を決める。閉じたパネルに前の内容が残る場合を、開いた状態と区別する。
-   **理由:** 閉じたパネルが DOM に残る場合、表示されていない要素の `innerText` は改行を含まない `textContent` と同じになりうる。また、閉じていれば利用者が中身を確かめられない。`empty-selection` と `transcript-unavailable` の分かれ目でもある（F-003）。
-   **候補の方針:** パネルの要素の `visibility` 属性（`ENGAGEMENT_PANEL_VISIBILITY_EXPANDED` など）や、計算済みのスタイルを観測して決める。判定は属性の値の列挙で行い、未知の値は「開いていない」として扱う。
-   **関連:** F-002、F-003、AC-06

## H-03: 一部だけ読めた状態の観測と判定

-   **事項:** 長い動画（2 時間を超えるもの）で、パネルが全行を描画するか（遅延描画・仮想スクロールの有無）を観測する。パネル内の検索で行が絞り込まれた状態になるか、その状態を DOM から判定できるかを観測する。判定できる状態について、判定の手段を決める。
-   **理由:** 一部だけ読めた字幕が送られることが、本タスクで最も危険な失敗である（要件書 §1）。サーバの `invalid_transcript` は書式の崩れしか防がない。要件は、判定できる状態を拒否し（AC-08）、判定できない欠けを末尾のプレビューで補う（F-004）。
-   **候補の方針:** 観測の結果を `02_architecture.md` に記録し、判定できない欠けがある場合は、その残余のリスクを明記する。検索欄の値が空でないことを、絞り込みの判定に使えるかを確かめる。
-   **関連:** F-002、F-006、AC-08、AC-20

## H-04: パネルが今の動画のものかの判定

-   **事項:** SPA の画面遷移の後に、前の動画のパネルが DOM に残るかを観測する。パネルが読み取りの時点のページの動画のものであることを確かめる手段を決める。
-   **理由:** 別の動画の字幕を今の動画の URL と組み合わせて送ることは、要件で禁じた（F-002・AC-09）。文書の URL の照合（AC-05）は、ページの URL が変わっていないことしか確かめず、パネルの中身が今の動画のものかは確かめない。
-   **候補の方針:** パネルやその親の要素が動画 ID を持つか、画面遷移のときにパネルが作り直されるか・閉じられるかを観測する。確かめる手段がない場合は、パネルを読まずに拒否する（要件書 §1 の決定）。その場合、この機能は実質的に使えないので、要件の見直しをレビューに諮る。
-   **関連:** F-002、F-006、AC-09、AC-20

## H-05: `innerText` のユニットテストの手段

-   **事項:** 注入する関数がセグメントの一覧の `innerText` を読むことを、ユニットテストで確かめる手段を決める。
-   **理由:** jsdom は `innerText` のレイアウトに依存する振る舞い（ブロック要素の改行、非表示の要素の除外）を実装しないので、jsdom の上の `innerText` は実際のブラウザと一致しない。実際の文字列の一致は手動で確かめる（AC-19）。ユニットテストでは、読んだ値が補正されずに送る内容になること（AC-04）と、使わない条件の判定（AC-06〜AC-09）を確かめる。
-   **候補の方針:** テストでは要素の `innerText` を固定の値に差し替えるなど、DOM の実装に依存せず「読んだ値がそのまま渡る」ことを確かめる方法を選ぶ。
-   **関連:** F-002、AC-04

## H-06: メッセージの文言と、要約の配置

-   **事項:** `empty-selection` に加える手順と、`transcript-unavailable` のメッセージの正確な文言を決める。要約での取得元の表示と、末尾のプレビューの配置・長さを決める。
-   **理由:** 文言は英語の固定の文字列とする（CLAUDE.md の拡張の規則）。`transcript-unavailable` は、パネルを開いても読めない状況（DOM の変化、検索の絞り込み、前の動画のパネル）を含むので、手動の選択に戻す手順を中心にする。パネル内の検索欄を空にする手順も含める（F-003）。
-   **候補の方針:** 既存の `rejectionMessage` と `Message` の形（文と番号付きの手順）に従う。末尾のプレビューの長さは、既存の先頭のプレビュー（200 文字）に合わせることを候補とする。
-   **関連:** F-003、F-004、AC-12、AC-15

## H-07: 注入の結果の形と、ログの内容

-   **事項:** 選択範囲を読む既存の注入の戻り値に、パネルの読み取りの結果をどう加えるかを決める（取得元・使わなかった理由の列挙、字幕の文字列）。境界での形の検査（未知のメンバ・重複の拒否）の方法を決める。拒否のログに残す項目を決める。
-   **理由:** 既存の `isPageSelection` は、`text` と `documentUrl` が文字列であることだけを確かめ、未知のメンバを拒否しない。要件は、結果のメンバを閉じた集合とした（§3.2・AC-22）。また、既存のポップアップのログ（`popupLogLabel`）は収集の結果をそのまま記録するので、パネルから読んだ字幕を含めるかの扱いを決める必要がある（AC-13 は拒否のログに字幕を含めないことを求める）。
-   **候補の方針:** 0025 のメタデータの読み取り（`readPageMetadata` が JSON の文字列を返し、受け取った側で厳格に検査する）の形にそろえるかを検討する。
-   **関連:** F-002、F-003、§3.2、AC-13、AC-22
