## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張のポップアップを開いたときにテキストが選択されていなければ、拡張が動画ページの文字起こしパネルの DOM から字幕を読み取り、送る内容にするための要件を定義する（[#330](https://github.com/isseis/yt2column/issues/330)）。読み取れない場合は、今までどおり手動での選択を促すメッセージを表示する。

**背景:**

現在の拡張では、利用者が文字起こしパネルを開き、字幕の行をドラッグして選択してからポップアップを開く（`0007_browser_extension_skeleton`・`0020_extension_send`）。長い動画では、パネルの中をスクロールしながら行を選択する作業が負担になる。

`0025_extension_video_metadata`（[#170](https://github.com/isseis/yt2column/issues/170)）で、拡張は動画タイトル・チャンネル名・概要欄を動画ページの DOM から読むようになった。本タスクは、同じ方法を字幕にも使う。

2026-10-01 に決めた製品の方針は「字幕の取得は利用者に任せる」だった（[#43](https://github.com/isseis/yt2column/issues/43)。0007 の要件書 §1）。拡張で YouTube のページの内部を解析すると壊れやすい、というのがその理由である。本タスクはこの方針を一部変える。ただし、読み取れない場合は手動の選択に戻るので、DOM の構造が変わっても、字幕を送る機能そのものは失われない。

字幕はメタデータと違って必須の入力で、記事の中身そのものになる。そのため、読み取りに失敗して手動の選択に戻る場合よりも、**一部だけ読めて、そのまま送られる**場合のほうが危険である。サーバの `invalid_transcript` が防ぐのは書式が崩れた場合だけで、書式は正しいのに中身が欠けている場合は防げない。本書は、一部だけ読めた場合を、判定できる範囲では拒否し（F-002）、判定できない範囲では送る前の要約で利用者が気づけるようにする（F-004）。

文字起こしパネルは、開くまで中身がない（`testdata/2tcCWM-sRBw.transcript_panel_hidden.html` にはスピナーしかない）。本タスクで省けるのは「行を選択する」作業であり、「パネルを開く」作業は残る。

前提の [#329](https://github.com/isseis/yt2column/issues/329)（右クリックメニューの経路の削除。`0027_remove_context_menu`）は完了しており、拡張の起動経路はポップアップだけである。

対応 issue: [#330](https://github.com/isseis/yt2column/issues/330)（前提: [#329](https://github.com/isseis/yt2column/issues/329)、関連: [#331](https://github.com/isseis/yt2column/issues/331)・[#43](https://github.com/isseis/yt2column/issues/43)）

**本書の記述範囲:** 本書は、観測できる振る舞い（いつパネルを読み、何を送り、利用者に何を示すか）を定める。セレクタ、パネルが開いているかの判定の手段、一部だけ読めた状態の判定の手段、パネルが今の動画のものかを確かめる手段、表示の正確な文言と配置、テストの手段は、設計（`02_architecture.md`）で決める。要件のレビューで挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #330 で決めたこと:**

-   **対象の経路:** ポップアップの経路だけを対象にする（#329 の後には、ほかの経路はない）。送る前に要約とプレビューを確かめられることを、一部だけ読めた場合に利用者が気づくための手段とする。
-   **送る文字列:** パネルのセグメントの一覧の `innerText` を、既存の `transcript` にそのまま入れる。コピーしたときと同じ規則で並ぶ文字列であり、サーバ・API・パーサは変えない。サーバの書式の検査が、最後の守りとして残る。構造化したセグメントを送る案は、[#331](https://github.com/isseis/yt2column/issues/331) で検討する。
    -   `Range.toString()` は `textContent` と同じく改行を含まないので使わない。`selection.selectAllChildren()` で選択してから読む方法は、利用者の選択範囲を書き換えるので使わない。
-   **優先順位:** 選択範囲が空のとき（空白文字だけの場合を含む。既存の `whitespaceOnly` と同じ規則）だけパネルを読む。選択範囲があれば、今までどおりそれを送る。
-   **パネルを開くのは利用者:** 拡張は「文字起こしを表示」をクリックしない。0025 の「ページを操作しない」方針（0025 AC-19）を保つ。
-   **読み取りの場所:** 選択範囲を読む既存の注入の中で、選択範囲が空のときにパネルを読む。`location.href` の照合を 1 か所に保ち、上限時間なしで待つ注入（0025 `02_architecture.md` §5.4 のリスク）を増やさない。
-   **取得元を型で表す:** 収集した入力に、取得元（選択範囲かパネルか）を型で持たせる（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」）。要約に取得元を表示する。

**要件定義の際に決めたこと（2026-10-19）:**

-   **拒否の理由を状況で分ける:** 文字起こしパネルが DOM にない場合、または閉じている場合は、既存の `empty-selection` で拒否する。パネルは開いているのに読めない場合（セグメントの一覧がない、空、一部だけ読めた状態と判定した、今の動画のものと確かめられない）は、新しい拒否の理由 `transcript-unavailable` で拒否する（F-003）。開発者向けのログで「利用者がパネルを開いていない」と「DOM の構造が変わった」を区別できるようにするためである。
-   **一部だけ読めた状態を拒否する:** パネル内の検索で行が絞り込まれている状態や、全行がまだ描画されていない状態を DOM から判定できる場合は、警告して送らせるのではなく `transcript-unavailable` で拒否する（F-002）。一部だけ読めた字幕で記事が生成されると、利用者はそれに気づきにくいためである。判定できない種類の欠けは、設計での観測と、要約の表示（F-004）で補う。
-   **要約に末尾のプレビューを加える:** 取得元がパネルのときは、先頭のプレビューに加えて末尾のプレビューを表示する（F-004）。末尾が欠けたことに、先頭のプレビューでは気づけないためである。プレビューは文字列を切り出すだけで、字幕の内容（時刻など）を解析しない。
-   **前の動画のパネルを送らない:** SPA の画面遷移の後に前の動画のパネルが DOM に残っていても、その字幕を送らないことを必須にする（F-002）。パネルが今の動画のものかを確かめる手段は、設計で決める。確かめられない場合はパネルを読まずに拒否する。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   文字起こしパネルを開いた状態で、何も選択せずにポップアップを開けば、パネルの字幕を送れるようにする。長い動画でパネルの行を選択する作業をなくす。
-   一部だけ読めた字幕を、判定できる範囲では送らせない。判定できない範囲では、送る前の要約で利用者が気づけるようにする。
-   別の動画のパネルの字幕を送らない。
-   読み取れない場合は手動の選択に戻し、DOM の構造が変わっても字幕を送る機能を失わない。
-   拡張がページを操作しない（選択範囲を変えない、クリックしない）という振る舞いを保つ。
-   選択範囲がある場合の振る舞い、送信のクライアント、サーバ・API を変えない。

### 2.2. スコープ (In Scope)

-   選択範囲が空のときに、文字起こしパネルから字幕を読むかを決める優先順位（F-001）。
-   既存の選択範囲の注入の中での、文字起こしパネルのセグメントの一覧の読み取りと、読み取った字幕を使わない条件（パネルが閉じている、一部だけ読めた、別の動画のもの）（F-002）。
-   読み取れない場合の拒否の理由の追加（`transcript-unavailable`）と、`empty-selection` の文言の更新（F-003）。
-   取得元の型と、要約での取得元・末尾のプレビューの表示（F-004）。
-   パネルから読んだ字幕を既存の `transcript` として送ること（F-005）。
-   形 A・形 B の両方での、パネルから読んだ文字列と手でコピーした文字列の一致の確認と、一部だけ読める場合の観測の記録（F-006）。
-   文書: README の「Browser extension」節、`docs/dev/security.md` §8・§8.1、`docs/dev/project_overview.md`（F-007）。

### 2.3. スコープ外 (Out of Scope)

-   サーバ・API・Go のパーサ（`internal/transcript` の `CopiedSource`）の変更。パネルから読んだ字幕は、コピーした字幕と同じ書式の文字列として送り、サーバは区別しない。
-   構造化したセグメント（時刻と本文の組）として送ること（[#331](https://github.com/isseis/yt2column/issues/331)）。
-   ページの操作。拡張は「文字起こしを表示」をクリックせず、パネルをスクロールせず、検索欄を空にせず、選択範囲を変えない。
-   ポップアップ以外の起動経路（#329 で削除済み）。
-   送信のクライアント（本文の形・送信・応答の解釈と表示。0020）と、動画メタデータの読み取り（0025）の変更。
-   パネルから読んだ字幕の整形（前後の空白の除去、行の並べ替え、見出しの行の除去）。見出しの行や前置きの行の読み飛ばしは、サーバのパーサが行う（`0024_copied_transcript_panel_lines`）。
-   字幕の内容（時刻・本文）を拡張で解析すること。末尾のプレビュー（F-004）も文字列の切り出しだけで行う。
-   新しい権限。
-   表示する文言の多言語化。Chrome と Brave 以外のブラウザ（0007 2.3 と同じ）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 取得元の選択（選択範囲を優先する）

-   ポップアップを開いたとき、拡張は既存の収集（0007 F-005）と同じ順に、URL の受理・選択範囲の読み取り・読み取った文書の URL の照合を行う。
-   選択範囲が空白文字だけでない場合は、今までどおり選択範囲を送る内容にする。このときパネルを読まない。
-   選択範囲が空、または空白文字だけの場合に限り、文字起こしパネルから字幕を読む（F-002）。空白文字の判定は、既存の `empty-selection` の判定と同じ規則（Unicode の `White_Space`。既存の `whitespaceOnly`）とする。
-   パネルから読めた場合は、その字幕を送る内容にする。読めなかった場合は拒否する（F-003）。
-   取得元が決まった後の検査（タブのタイトルが空でないこと。0007 F-005 の `empty-title`）は、取得元によらず今までどおり行う。

**Acceptance Criteria**:
- **AC-01**: 選択範囲が空白文字だけでない場合、選択範囲がそのまま送る内容になり、取得元は選択範囲になる。DOM に開いた文字起こしパネルがあっても、パネルの字幕は使われない（ユニットテスト）。
- **AC-02**: 選択範囲が空、または空白文字（全角空白・改行を含む）だけの場合、パネルの字幕が送る内容になり、取得元はパネルになる（ユニットテスト）。
- **AC-03**: 拒否の理由の順序は、既存の順序（起動の情報がない場合の `collection-failed`、`not-watch-page`、読み取りの失敗と URL の照合による `collection-failed`）、選択範囲とパネルによる判定（`empty-selection`・`transcript-unavailable`。F-003）、`empty-title` の順である。既存の拒否の理由とその順序は、選択範囲がある場合に変わらない（ユニットテスト）。

#### F-002: 文字起こしパネルからの読み取り

-   パネルの読み取りは、選択範囲を読む既存の注入の中で行う。新しい注入を加えない。読み取った文書の URL の照合（0007 F-005。一致しない場合は `collection-failed`）は、選択範囲とパネルの両方に対して 1 回だけ行う。
-   読むのは、文字起こしパネルの**セグメントの一覧**の `innerText` である。パネルの見出し・検索欄・操作ラベルを、可能な限り含めない。読む範囲をセグメントの一覧に絞れない場合の扱いは、設計で決める（[design_handoff.md](design_handoff.md) H-01。サーバのパーサは前置きと末尾の操作ラベルを読み飛ばす。0024 F-007・F-002）。
-   読み取った文字列は補正しない。前後の空白・改行・全角空白・サロゲートペアの文字を保つ。
-   次の場合は、パネルから読んだ字幕を送る内容にしない（拒否の理由は F-003）。
    -   **パネルがない、または閉じている:** 文字起こしパネルが DOM にない場合、および DOM にあっても開いていない（表示されていない）場合。閉じたパネルに前の内容が残っていても、それを読まない。開いているかを判定する手段は設計で決める（H-02）。
    -   **セグメントの一覧がない、または空:** パネルは開いているが、セグメントの一覧の要素がない場合、および読み取った文字列が空、または空白文字だけの場合（読み込み中のスピナーだけの場合を含む）。
    -   **一部だけ読めた状態:** パネル内の検索で行が絞り込まれている状態、および全行がまだ描画されていない状態（遅延描画・仮想スクロール）のうち、DOM から判定できるもの。どの状態を判定できるかは、設計での観測で決める（H-03）。
    -   **別の動画のパネル:** パネルが、読み取りの時点のページの動画のものと確かめられない場合。SPA の画面遷移の後に、前の動画のパネルが DOM に残っている場合を含む。確かめる手段は設計で決める（H-04）。
-   拡張はページを操作しない。「文字起こしを表示」のクリック、パネルのスクロール、検索欄への入力や消去、フォーカスの移動、選択範囲の変更（`selectAllChildren()`・`addRange()` などを含む）を行わない。
-   パネルの DOM は YouTube が独自に定義したもので、予告なく変わりうる。構造の変化で読めない場合は、拒否して手動の選択に戻す（F-003）。

**Acceptance Criteria**:
- **AC-04**: 開いた文字起こしパネルのセグメントの一覧から読んだ字幕が、その要素の `innerText` と一致し、補正されずに送る内容になる。前後の空白・改行・全角空白・サロゲートペアの文字が保たれる（ユニットテスト。注入する関数を、組み立てた DOM で実行する。`innerText` を DOM の実装に依存せず確かめる手段は設計で決める。H-05）。
- **AC-05**: パネルの読み取りは、選択範囲を読む既存の注入の中で行われ、読み取った文書の URL の照合は 1 回だけである。URL が一致しない場合は、選択範囲が空でも `collection-failed` になり、パネルの字幕は使われない（ユニットテスト。注入の数は静的な確認）。
- **AC-06**: 文字起こしパネルが DOM にない場合、および DOM にあって閉じている場合（閉じたパネルにセグメントが残っている場合を含む）、パネルの字幕は使われず、`empty-selection` で拒否される（ユニットテスト）。
- **AC-07**: パネルが開いていて、セグメントの一覧がない場合、読み取った文字列が空または空白文字だけの場合、および読み込み中のスピナーだけの場合、`transcript-unavailable` で拒否される（ユニットテスト。スピナーだけの場合は、`testdata/2tcCWM-sRBw.transcript_panel_hidden.html` のスピナーの形を、開いた状態のパネルに置いた DOM を使う。同ファイルのパネルは閉じた状態（`visibility="ENGAGEMENT_PANEL_VISIBILITY_HIDDEN"`）なので、そのままの形は AC-06 の対象である）。
- **AC-08**: 設計で判定できるとした一部だけ読めた状態（パネル内の検索による絞り込み、全行がまだ描画されていない状態）では、`transcript-unavailable` で拒否され、字幕は送られない（ユニットテスト。対象の状態は設計の観測で決める）。
- **AC-09**: パネルが読み取りの時点のページの動画のものと確かめられない場合（前の動画のパネルが残っている場合を含む）、`transcript-unavailable` で拒否され、そのパネルの字幕は送られない（ユニットテスト。実際のページでの SPA の画面遷移は手動の確認。AC-20）。
- **AC-10**: 注入の前後で、ページの選択範囲（範囲の数と各範囲の境界）が変わらない。注入する関数は、クリック・スクロール・フォーカス・入力・選択範囲の変更を行うコードを持たない（ユニットテストと静的な確認）。

#### F-003: 読み取れないときの拒否の理由とメッセージ

-   拒否の理由（`RejectionReason`）に `transcript-unavailable` を加える。0007 の拒否の理由と同じく、型として宣言し、表示する文言は拒否の理由の型で選ぶ（文字列の内容から推し量らない）。
-   拒否の理由は、次のように分ける。
    -   **`empty-selection`:** 選択範囲が空で、文字起こしパネルが DOM にない、または閉じている場合（F-002）。利用者がパネルを開いていない状況である。
    -   **`transcript-unavailable`:** 選択範囲が空で、パネルは開いているが、F-002 のほかの理由で字幕を使えない場合（セグメントの一覧がない・空・一部だけ読めた状態・別の動画のパネル）。DOM の構造の変化、またはパネルの状態によって読めない状況である。
-   `empty-selection` のメッセージは、既存の文言を元にし、「文字起こしパネルを開いておけば、行を選択しなくてもよい」という手順を加える。
-   `transcript-unavailable` のメッセージは、`empty-selection` と区別できる文で、パネルから読めなかったことを伝え、既存の `empty-selection` の手順（パネルを開き、行を選択して、ポップアップを開き直す）で手動の選択を促す。パネルの検索欄に文字が入っている場合は空にすることも、手順に含める。
-   メッセージは固定の文言とし、ページの文字列を含めない。正確な文言は設計で決める（H-06）。
-   パネルの開閉を表す値が、設計で列挙した既知の値のどれでもない場合は、閉じているとはみなさず `transcript-unavailable` とする。`empty-selection` で拒否したときも、パネルが DOM になかったか、閉じていたかを開発者向けのログに残す。パネルのセレクタや開閉の値が変わったことを、ログで「利用者がパネルを開いていない」と区別できるようにするためである（H-02）。
-   拒否したときは、拒否の理由と、`transcript-unavailable` の場合は使わなかった理由（セグメントの一覧がない・空・一部だけ読めた状態・別の動画のパネル。設計で列挙として決める）を開発者向けのログに残す。ログに、パネルから読んだ文字列そのものは含めない。

**Acceptance Criteria**:
- **AC-11**: `transcript-unavailable` と `empty-selection` が、異なる拒否の理由として区別され、それぞれ異なるメッセージで表示される。拒否の理由とメッセージの対応に漏れがあると型の検査が失敗する（既存の `rejectionMessage` の網羅の検査と同じ）（ユニットテスト）。
- **AC-12**: `empty-selection` のメッセージに、パネルを開いておけば行を選択しなくてもよいことを示す手順が含まれる。`transcript-unavailable` のメッセージに、パネルを開き、行を選択して、ポップアップを開き直す手順が含まれる（ユニットテスト）。
- **AC-13**: `transcript-unavailable` で拒否したとき、使わなかった理由が開発者向けのログに記録され、ログにパネルから読んだ文字列が含まれない（ユニットテスト。識別できる文字列をパネルに入れ、ログに現れないことを確かめる）。`empty-selection` で拒否したとき、パネルが DOM になかったか閉じていたかがログに記録され、開閉の値が未知の場合は `transcript-unavailable` になる（ユニットテスト）。

#### F-004: 取得元と要約の表示

-   収集した入力（`CollectedInput`）に、取得元（選択範囲・パネル）を型で持たせる。表示・送信・ログは、取得元の型で振る舞いを選ぶ。字幕の文字列の内容から取得元を推し量らない。
-   ポップアップの要約（0007 F-006）に、取得元を表示する。
-   取得元がパネルのときは、先頭のプレビューに加えて、末尾のプレビューを表示する。末尾のプレビューは、字幕の末尾から一定の文字数を切り出したもので、字幕の内容（時刻・行）を解析しない。切り出す長さは設計で決める。サロゲートペアの途中で切らない（既存のプレビューと同じ）。
-   取得元が選択範囲のときの要約は、取得元の表示を除いて今までと変えない。
-   末尾のプレビューも、既存のプレビューと同じく、HTML やほかのマークアップとして解釈せずテキストとして表示し、双方向の制御文字によって周囲の表示順が変わらないようにする（0025 F-003 と同じ）。
-   文字数・行数の表示は、取得元によらず、送る内容の文字列から今までと同じ方法で数える。

**Acceptance Criteria**:
- **AC-14**: 取得元が型として収集した入力に含まれ、選択範囲から収集した場合は選択範囲、パネルから収集した場合はパネルになる。要約に取得元が表示される（ユニットテスト）。
- **AC-15**: 取得元がパネルのとき、要約に先頭と末尾のプレビューが表示される。末尾のプレビューは字幕の末尾の文字列と一致し、サロゲートペアの途中で切れない。取得元が選択範囲のときは、末尾のプレビューを表示せず、要約は取得元の表示を除いて今までと同じである（ユニットテスト）。
- **AC-16**: パネルの字幕に `<img src=x onerror=alert(1)>` のような文字列を含めても、先頭と末尾のプレビューで要素にならない（`querySelector("img")` が `null` で、`textContent` に元の文字列が含まれる）（ユニットテスト）。字幕の先頭と末尾に双方向の制御文字（U+202E など）を含む動画で、要約のラベルとほかの値の表示順が変わらない（手動確認。Chrome と Brave。0025 AC-14 と同じ）。

#### F-005: 送信

-   パネルから読んだ字幕を、既存の `transcript` にそのまま入れて送る。送信のクライアント（本文の形・送信・応答の解釈と表示。0020）を変えない。取得元を本文に入れない。
-   本文の大きさの確認（0020 F-004）は、パネルから読んだ字幕にもそのまま適用する。上限を超える場合は、既存の「送る内容が大きすぎる」で送信を止める。
-   サーバの書式の検査（`invalid_transcript`）を、最後の守りとして変えずに残す。
-   動画メタデータの読み取り（0025）は、取得元によらず、収集が成功したときに今までどおり行う。

**Acceptance Criteria**:
- **AC-17**: パネルから読んだ字幕が、本文の `transcript` の値と一致する。本文は宣言したメンバだけを持ち、取得元を含まず、選択範囲から収集した場合の本文と同じ形になる（ユニットテスト）。
- **AC-18**: パネルから読んだ字幕を含む本文の UTF-8 のバイト数が 4,194,304 を超える場合は送らず、既存の「送る内容が大きすぎる」が表示される（ユニットテスト）。

#### F-006: 実際のページでの確認と記録

-   パネルから読んだ文字列が、パネルの全行を手で選択してコピーした文字列と一致することを、形 A と形 B の両方の DOM の版で手動で確認し、記録する。CSS の表示状態や、画面読み上げ用のラベル（例: `12 秒`）の扱いを含めて確かめる。形 A と形 B は DOM の版の違いから生じるので、両方の版のページで観測する（形 B の例は `Yoboo9g7saY`）。
-   次の観測を行い、結果と、それぞれを F-002 のどの扱いで防ぐか（または防ぐ必要がないか）を記録する。
    -   長い動画（2 時間を超えるもの）で、パネルが全行を描画するか（遅延描画・仮想スクロールの有無）。
    -   パネル内の検索で、行が絞り込まれた状態になるか。その状態を DOM から判定できるか。
    -   SPA の画面遷移の後に、前の動画のパネルが DOM に残るか。残る場合に、今の動画のものと区別できるか。
-   記録には、動画 ID、ブラウザとその版、観測した日付、ログインの状態を含める。観測のうち、設計の判断に使うもの（セレクタ、判定の手段）は `02_architecture.md` に、実装後の確認の結果は実装計画に記録する。
-   動画ページの HTML 全体のスナップショットは、リポジトリに保存しない（`security.md` §7）。テストに使う DOM の抜粋を `testdata/` に加える場合は、§7 の条件（再配布できるライセンスの動画で、取得した人を特定しない）に従う。

**Acceptance Criteria**:
- **AC-19**: 形 A・形 B の両方で、パネルから読んだ文字列と、パネルの全行を手で選択してコピーした文字列が一致することを、手動で確認し記録している。一致しない場合は、その差と扱いを記録している（手動の確認。Chrome と Brave）。
- **AC-20**: 長い動画（2 時間を超えるもの）での描画、パネル内の検索による絞り込み、SPA の画面遷移の後のパネルの 3 つを観測し、それぞれ、F-002 の扱いで送られないこと、または起きないことを確認して記録している（手動の確認。Chrome と Brave）。

#### F-007: 文書

-   README の「Browser extension」節: 選択範囲が空のときに文字起こしパネルから字幕を読むこと、選択範囲を優先すること、パネルを開くのは利用者であること、読めないときは手動の選択に戻ること、要約の取得元と末尾のプレビューで送る内容を確かめることを記す。
-   `security.md` §8・§8.1: 拡張が文字起こしパネルの DOM から字幕を読むこと。読むのは選択範囲が空のときだけで、既存の注入の中で行い、新しい権限を加えないこと。ページを操作しないこと（クリック・スクロール・選択範囲の変更をしない）。読んだ字幕は untrusted テキストとして扱うこと。一部だけ読めた状態と別の動画のパネルの扱いを記す。
-   `project_overview.md`: 「字幕の取得は利用者に任せる」という方針を一部変えることと、その理由（長い動画での選択の負担）、読めない場合は手動の選択に戻るので DOM が変わっても機能を失わないことを記す。
-   README の「Browser extension」節と `security.md` §8.1 は拡張の node のテスト（`metadataDocs.test.ts`・`manifest.test.ts` など）が読むので、これらの更新では `make ext-test` を実行する（[CLAUDE.md](../../../CLAUDE.md)「Development Notes」）。
-   0007・0020・0025・0027 の文書のうち、字幕の取得を選択範囲に限るとした記述は、それぞれのタスクの記録として残し、変更しない。

**Acceptance Criteria**:
- **AC-21**: 上記の各文書に、上記の内容が記載されている（静的な確認）。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

文字起こしパネルから読む字幕は、記事生成のプロンプトに埋め込まれる untrusted テキストである（`docs/dev/security.md` §6・§8）。

| 境界 | 受理する形 | 上限 | 失敗・拒否時の扱い | 主な AC |
|---|---|---|---|---|
| 注入した読み取りの結果 | 選択範囲の文字列、読み取りの時点の文書の URL、パネルの読み取りの結果（読まなかった・読めなかった理由、または字幕の文字列）に限る。パネルの読み取りの結果は、取得元・理由を列挙の値として持ち、字幕の文字列の内容から理由を推し量らない。未知のメンバを含む結果、メンバが重複する結果（結果の表現が重複を許す場合）、または形が合わない結果は受理しない（許可するメンバは閉じた集合であり、拡張可能と宣言しない） | 読み取りの段階では独自の上限を設けない（選択範囲の場合と同じ）。字幕の文字列は、送る前に本文の上限（0020 F-004 の 4 MiB）で検査する | `collection-failed` で拒否する（既存の注入の失敗と同じ）。本文の上限を超える場合は、既存の「送る内容が大きすぎる」で送信を止める | AC-05・AC-18・AC-22 |
| 読み取りの時点の文書の URL | 起動したタブの URL（0007 F-005）と一致する | -（形で決まる） | `collection-failed` で拒否する（既存と同じ） | AC-05 |
| パネルから読んだ字幕 | 開いた文字起こしパネルの、今の動画のセグメントの一覧の `innerText`（UTF-16）。補正しない | 本文の上限（0020 F-004 の 4 MiB）に含む | 空・空白文字だけ・一部だけ読めた状態・別の動画のパネルは `transcript-unavailable`。パネルがない・閉じている場合は `empty-selection` | AC-06・AC-07・AC-08・AC-09・AC-18 |

-   字幕を本文へ入れるときは、既存の送信のクライアントのとおり `JSON.stringify` を使う。字幕を JSON の構文として解釈しない。
-   字幕の書式の検査（形 A・形 B）は拡張では行わず、サーバの `CopiedSource` に任せる（`invalid_transcript`）。拡張は字幕の内容を解析しない。
-   対になっていないサロゲートを含む字幕の扱いは、選択範囲の場合（0020）と同じとし、本タスクで変えない。
-   注入の結果の形と、境界での形の検査の方法は設計で決める（H-07）。
-   本タスクの既存の境界（選択範囲の文字列、タブの URL、タブのタイトル、動画メタデータ）は、0007・0020・0025 の境界をそのまま使う。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)
-   パネルの読み取りは、送信と記事の生成に比べて無視できる時間で終わればよい。性能のための仕組みは設けない（[CLAUDE.md](../../../CLAUDE.md)「Performance」）。
-   上限時間なしで待つ注入を増やさない（1. 概要の決定）。

### 4.2. セキュリティ (Security)
-   **権限:** 新しい権限を加えない。既存の `scripting` の注入（`activeTab` で起動したタブ）で DOM を読むだけとする。
-   **ページを操作しない:** パネルを開くためのクリック、スクロール、検索欄の操作、フォーカスの移動、選択範囲の変更をしない（F-002）。
-   **untrusted テキストの扱い:** パネルから読んだ字幕は untrusted な入力である。要約の表示では HTML やほかのマークアップとして解釈せず、テキストとしてだけ表示し、双方向の制御文字によって周囲の表示順が変わらないようにする（F-004）。値からコードを実行しない。`eval`・`new Function` を使わない（既存の制約を保つ）。
-   **別の動画の字幕を送らない:** 前の動画のパネルの字幕を、今の動画の URL と組み合わせて送らない（F-002）。
-   **秘密の扱い:** 共有トークンを、読み取る値、本文、開発者向けのログ、ポップアップの表示に出さない（0020 4.2 と同じ）。
-   **プロンプトへの埋め込み:** 字幕は記事生成のプロンプトに埋め込まれる。プロンプトインジェクションによって生成記事の内容が操作されうることを前提とする（`security.md` §6）。選択範囲から送る場合と変わらない。
-   **既存の制約の維持:** `content_scripts` を宣言しない、利用者が起動するまでページを読まない、Manifest V3 の既定の Content Security Policy を緩めない、実行時に npm の依存パッケージを読み込まない（0007 4.2）。

**Acceptance Criteria**:
- **AC-22**: 注入した読み取りの結果が期待する形に合わない場合、未知のメンバを含む場合、およびメンバが重複する場合（結果の表現が重複を許す場合）、`collection-failed` で拒否され、パネルの字幕は使われない（ユニットテスト）。
- **AC-23**: manifest の権限（ホストの権限を含む）が、0027 の後の権限から変わらない（静的な確認。既存の manifest のガードのテストを変えない）。

### 4.3. 信頼性・可用性 (Reliability/Availability)
-   DOM の構造の変化でパネルを読めない場合は、拒否して手動の選択に戻す。選択範囲から送る機能は、パネルの DOM の変化の影響を受けない。
-   拒否の後も、次の起動は通常どおり動作する（0007 4.3 と同じ）。

### 4.4. 互換性 (Compatibility)
-   利用時: macOS 上の Chrome と Brave の、本タスクの作業時点の安定版で動作すること（0007 4.4 と同じ）。セレクタと判定の手段は、設計の時点の観測（形 A・形 B の両方の DOM の版）に基づく。DOM の構造は YouTube が予告なく変えうることを前提とする。
-   API: サーバの現在の API と組み合わせて動作すること。API を変えない。

### 4.5. 保守性 (Maintainability)
-   取得元（選択範囲・パネル）、拒否の理由、パネルの字幕を使わなかった理由は、読み取りの段階で型（列挙）として決める。表示・送信・ログは、その型で振る舞いを選び、字幕の文字列の内容から推し量らない（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」）。
-   パネルの読み取りの判定（取得元の選択、使わない条件、拒否の理由への対応）は、ブラウザの API から分離し、ブラウザなしでユニットテストできるようにする。読み取りはテストで fake に置き換えられるようにする（0007 4.5 と同じ）。
-   パネルの DOM の知識（セレクタ、開いているかの判定、一部だけ読めた状態の判定、今の動画のものかの判定）は、注入する関数の中に閉じ込める。
-   送信のクライアント（0020）と、動画メタデータの読み取り（0025）を変更しない。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」に従う。本タスクは「字幕の取得は利用者に任せる」という方針を一部変えるので、F-007 で同書を更新する。
-   サーバ側（Go のコード、API）を変更しない。
-   拡張の実行時に読み込むコードは、本リポジトリで書いたコードだけとする。npm の依存パッケージを実行時に加えない（0007 F-001）。
-   ユニットテストは、実際のブラウザも実際のサーバも起動しない。動画ページの読み取りは fake に置き換える。実際の YouTube の動画ページとの組み合わせは手動で確認する（F-006）。
-   動画ページの HTML 全体のスナップショットは、リポジトリに保存しない（`security.md` §7）。必要なら、リポジトリの外の `${YT2COLUMN_SNAPSHOT_DIR:-...}` にあるスナップショットを使う。

## 6. 用語集 (Glossary)

-   **0007**: ブラウザ拡張の骨格のタスク（`docs/tasks/0007_browser_extension_skeleton/`）。「0007 F-NNN」はその要件書の項番を指す。
-   **0020**: ブラウザ拡張からサーバへの送信のタスク（`docs/tasks/0020_extension_send/`）。
-   **0024**: コピーした字幕に混じるパネルの行を読み飛ばすタスク（`docs/tasks/0024_copied_transcript_panel_lines/`）。
-   **0025**: 動画メタデータの取得のタスク（`docs/tasks/0025_extension_video_metadata/`）。
-   **0027**: 右クリックメニューの経路の削除のタスク（`docs/tasks/0027_remove_context_menu/`）。
-   **文字起こしパネル**: YouTube の動画ページで「文字起こしを表示」を押すと開くパネル。`ytd-engagement-panel-section-list-renderer[target-id="PAmodern_transcript_view"]` の中にある（2026-10 時点の観測。設計で確かめる）。
-   **セグメントの一覧**: 文字起こしパネルの中で、字幕のセグメント（時刻と本文）が並ぶ部分。パネルの見出し・検索欄・操作ラベルを含まない。
-   **パネルから読んだ字幕**: 拡張がセグメントの一覧の `innerText` として読んだ文字列。コピーした字幕と同じ書式（形 A・形 B）であることを期待し、`transcript` として送る。
-   **取得元**: 送る字幕を、選択範囲から得たか、文字起こしパネルから得たかを表す型の値。
-   **一部だけ読めた状態**: パネル内の検索による絞り込みや、全行がまだ描画されていないことによって、セグメントの一覧が動画の字幕の一部しか含まない状態。
-   **末尾のプレビュー**: 取得元がパネルのとき、要約に表示する、字幕の末尾から切り出した文字列。
-   **形 A・形 B**: コピーした字幕の 2 つの書式（`docs/translation_glossary.md`）。
-   用語は [translation_glossary.md](../../translation_glossary.md) と統一する。
