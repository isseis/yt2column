本書は、[02_architecture.md](02_architecture.md)（以下、設計書）8.1 の観測のゲートの結果を受けて、本タスク（[#330](https://github.com/isseis/yt2column/issues/330)）を続けるかを要件のレビューに諮るための資料である。観測の記録そのものは設計書 3.1.4 にあり、本書はそれに基づく判断の材料と提案をまとめる。[03_implementation_plan.md](03_implementation_plan.md) を実装計画と呼ぶ。F-NNN・AC-NN は [01_requirements.md](01_requirements.md)（以下、要件書）の項番、H-NN は [design_handoff.md](design_handoff.md) の項番を指す。

本書では、設計書の用語を次の意味で使う。

-   **変種:** 文字起こしパネルの DOM の版ごとの違い。観測では、新しい版（`target-id="PAmodern_transcript_view"` のパネル）、古い版（`target-id="engagement-panel-searchable-transcript"` のパネル）、`target-id` を持たないパネルの 3 つが開いた。
-   **結びつける信号:** パネルの中身がどの動画のものかを確かめる手掛かり（パネルの子孫の要素の属性やリンクに含まれる動画 ID など）。
-   **注入:** 拡張がページで実行する関数。パネルの DOM の読み取りはこの中で行う。

## 1. 提案

**本タスクを取り下げ、字幕の取得は今までどおり利用者の手動の選択に任せる。** 長い動画で選択する負担は、パネルの DOM に依存しない方法で軽くできるかを、別のタスクとして検討する（§4）。

## 2. 諮る理由

設計書 3.1.3 は、結びつける信号が見つからない場合、試行の結果によらず、本タスクを続けるかを要件のレビューに諮ると定めている（H-04）。観測した新しい版と古い版のどちらにも、その信号はなかった（設計書 3.1.4）。

加えて、観測のゲートで次のことが分かった。いずれも、要件書が前提にしていた「パネルの DOM を、判定できない状態を拒否する形で読めば、DOM が変わっても手動の選択に戻るだけで済む」（要件書 4.3・4.4）が成り立たないことを示している。

| 発見 | 内容 | 要件への影響 |
|---|---|---|
| 変種が少なくとも 3 つある | 1 日の観測で、新しい版（`PAmodern_transcript_view`）、古い版（`engagement-panel-searchable-transcript`）、`target-id` を持たないパネルの 3 つが開いた。どれが開くかは動画で決まり、利用者は選べない | 変種ごとに、一覧・検索欄・描画の途中の判定を別々に定義し、それぞれを観測で確かめる必要がある。描画の途中の判定は、新しい版は `aria-busy`、古い版は `hidden` 属性で、共通の規則がない |
| 新しい版の `innerText` が、手でコピーした形と違う | 新しい版の一覧の `innerText` は、時刻・読み上げ用ラベル・本文が別々の行になる。サーバのパーサはこれをエラーなしで形 B として受理し、ラベル（`4 秒` など）を本文にして、本当の本文を読み飛ばした | 要素の構成は想定どおりでも、中身の形が違うと、拒否されずに誤った字幕が送られる。F-002 の「読み取った文字列は補正しない」を保ったままでは、これを防げない。防ぐには、注入の中で字幕を組み立てるか（DOM の知識がさらに増える）、サーバのパーサに新しい形を加える必要がある |
| 動画と結びつける信号がない | 新しい版と古い版のどちらでも、パネルの子孫に動画 ID を含む属性やリンクがなかった | F-002 の「前の動画のパネルを送らない」（必須）を、送る前に確かめる手段がない。実装計画のステップ 0-4（SPA の画面遷移の試行）で失敗が見られなくても、時間に依存する失敗が起きないことまでは、試行では証明できない（設計書 3.1.3） |
| 手でコピーすると形 B になるページでは古い版が開く | 手でコピーすると形 B になる動画（`Yoboo9g7saY`）のページでは、古い版のパネルが開いた。今の設計は古い版を読まない | 古い版を読めるようにしない限り、このようなページでは本機能が動作しない |

## 3. 将来の保守の費用

本タスクを続けた場合、実装の後も次の費用が続く。

-   **黙って誤る変更を検出できない。** 要素が見つからなくなる変更は、設計どおり拒否されて手動の選択に戻る。一方、要素の構成は同じで中身の形や意味が変わる変更（今回の新しい版の `innerText` の形）は、拒否されずに誤った字幕を送る。ユニットテストは実際の YouTube に触れないので（CLAUDE.md「Testing Strategy」）、この種類の変更はテストで捕まえられず、利用者が誤った記事を見て初めて分かる。
-   **変種が増えるたびに観測が要る。** 1 つの変種を加えるたびに、本タスクの観測のゲートと同じ観測（Chrome と Brave で、開閉・検索・長い動画・SPA の画面遷移・ログインの状態や表示言語などの環境の違い）が要る。新しい版と古い版が並んで存在していることは、YouTube が移行の途中にあるか A/B テストを行っていることを示唆しており、構成は今後も変わりうる。
-   **依存が増える。** 手動の選択の経路が依存するのは、ブラウザが選択範囲を文字列にする書式と、サーバのパーサが解析するコピーの書式だけである。パネルの DOM を読む経路は、これに加えて、変種ごとの要素の名前・開閉の属性・描画の途中を示す要素・検索欄・`innerText` の形にも依存する。これは、プロジェクトの方針「YouTube の非公式な仕様に依存する最も壊れやすい部分は、保守が活発なツールに任せる」（`docs/dev/project_overview.md`「決定済みの方針」）とも逆の向きである。

## 4. 検討した選択肢

| 案 | 内容 | 判断 |
|---|---|---|
| A. 取り下げて、手動の選択を続ける | 本タスクを取り下げる。長い動画で選択する負担は、DOM に依存しない方法（例: 最初の行をクリックし、一番下までスクロールして最後の行を Shift+クリックすれば全体を選択できると、ポップアップで案内する）で軽くできるかを、別のタスクで検討する | **採る**。DOM への依存を増やさない。Shift+クリックで全体を選べるかと、そのときにコピーされる書式は、Chrome と Brave で確かめていない |
| B. 1 つの変種だけを読む | たとえば、`innerText` が手でコピーした形と一致した古い版だけを読む | 採らない。対象になる動画が限られ、動画と結びつける信号がない問題は残る |
| C. 選択範囲が空なら URL だけを送り、サーバが `yt-dlp` で字幕を取る | `yt-dlp` に任せる | 本タスクでは採らない。localhost サーバは `yt-dlp` を呼ばないという決定済みの方針（`docs/dev/project_overview.md`「決定済みの方針」）を変えることになるので、検討するなら、その方針を決めた理由を確かめたうえで別のタスクとして扱う |
| D. 設計を直して続ける | 3 つの変種、注入の中で字幕を組み立てる処理、SPA の画面遷移への対策を加える | 採らない。§2 の信号の問題が解けず、§3 の費用が続く |

## 5. 取り下げる場合の扱い

-   要件書・設計書・実装計画は、記録としてリポジトリに残す。要件書の Document Status の Comments に、取り下げたことと本書への参照を書く。設計書は `draft` のままとする。観測の記録は設計書 3.1.4 にある。実装計画のフェーズ 1〜5 は実装しない。
-   拡張とサーバのコードは変更しない。観測はコードを書く前に行ったので、取り下げに伴って戻すコードはない。
-   #330 には、§7 の文案を残して閉じる。

## 6. 本タスクとは別に扱う事項

-   **サーバのパーサが、時刻・読み上げ用ラベル・本文の 3 行の形を形 B として受理する。** このとき、本当の本文の行は、時刻を待つ位置にあるためチャプターの見出しとみなされて読み飛ばされ、読み上げ用ラベルが本文になる。手で選択した文字列でも同じ形が届けば、同じことが起こる。時刻から決まる読み上げ用ラベルと同じ文字列だけの本文の行を拒否するなど、パーサの拒否を強める変更として、別の issue で扱うかを判断する。
-   **長い動画で選択する負担を軽くする方法（§4 の案 A）。** Shift+クリックでの範囲の選択を Chrome と Brave で確かめ、コピーされる書式がサーバのパーサで受理されることを確かめたうえで、ポップアップの案内（`empty-selection` の手順）や README に加えるかを検討する。

## 7. #330 に残す文案

> 観測のゲート（`docs/tasks/0029_transcript_panel_read/02_architecture.md` 8.1）を 2026-10-20 に Chrome 155 と Brave 1.97 で行い、ステップ 0-3 の途中で中断しました。記録は同書 3.1.4 にあります。
>
> - 文字起こしパネルの DOM には、少なくとも 3 つの変種（新しい版、古い版、`target-id` を持たないパネル）があり、どれが開くかは動画で決まります。
> - 新しい版の一覧の `innerText` は、手でコピーした形と違います（時刻・読み上げ用ラベル・本文が別々の行）。サーバはこれをエラーなしで受理し、ラベルを本文にします。
> - どの版のパネルにも、中身と動画を結びつける信号がありません。そのため、SPA の画面遷移の後に前の動画の字幕を誤って送らないかを、送信前に確かめる手段がありません。
>
> パネルの DOM を読む方式では、変種ごとの観測と、黙って誤る変更への追従に、費用がかかり続けます。そこで本 issue は取り下げます（`docs/tasks/0029_transcript_panel_read/observation_gate_review.md`）。長い動画で選択する負担を軽くする方法と、サーバのパーサが 3 行の形を受理する問題は、別の issue で扱います。
