## 1. 概要 (Overview)

**目的:** 本書は、YouTube の文字起こしパネルからコピーした字幕に、セグメントではない行が混じっていても受理し、その行を読み飛ばしてセグメントだけを組み立てるための要件を定義する。対象は、最初のセグメントより前の行（前置き）、チャプターの見出し行、入力の末尾の空白行とパネルの操作ラベルの行である。

**背景:**

`internal/transcript` のコピーした字幕のパーサ（`copied_format.go`）は、タスク `0015_copied_transcript_source` で定義した形 A・形 B の書式に合わない行を拒否する。そのため、パネル全体や、パネルの少し上から選択してコピーすると、次の行が混じって `invalid_transcript`（`400`）で拒否される。

- **最初のセグメントより前の行（前置き）。** パネルの最初のセグメント（`0:00` など）より前には、動画ページの表示項目とパネルのタイトル・検索欄が並ぶ。これらは文字起こしではないが、文字起こしと同じ親要素に属するため、範囲の選択に容易に入る。2026-10-17 に日本語 UI の形 A のパネルで観測した前置きは、次の行の並びである（`""` は 0 文字の行）: `動画の関連情報`・`""`・`""`・`タイムライン`・`""`・`文字起こし`・`文字音声変換を検索`・`文字音声変換を検索`・`""`。その次の行が最初のセグメント（`0:011 秒…`）である。前置きには空行が混じり、検索欄のラベルが 2 回現れる。形 B のパネルでは、検索欄が `動画内を検索` になる（0015 §1.4.1）。また、最初のチャプターの見出し行は最初のセグメントの直前に現れる。
- **チャプターの見出し行。** パネルは、動画のチャプターを、セグメントの間に時刻のない行として差し込む。日本語 UI の形 A では `チャプター 1: タイトル` の形で現れる（0015 `02_architecture.md` §1.4.1 で `LR6mhKRKX9Q` の `チャプター 2: 通常スピード` を観測）。0015 の設計はこれを拒否し、利用者への案内で見出しを含めないよう求めている（同 §3.2.4・§4.4）。
- **入力の末尾の空白行と操作ラベル行。** パネルの末尾には `動画の時間と同期` のボタンがある（`testdata/2tcCWM-sRBw.transcript_panel.html:3206-3211`）。最後のセグメントのすぐ下にあり、選択から外すのが難しい。2026-10-17 に、最後のセグメントからボタンまでを選択して観測した文字列の末尾は、`…\n17:0017 分<本文>\n\n動画の時間と同期` である。最後のセグメントとボタンの間に空行が 1 つ入り、ボタンのラベルの後に行の区切りはない。範囲の選び方によっては、ボタンを含めずに末尾に空行だけが入ることもある（例: `17:3017 分 30 秒<本文>\n\n`）。0015 §3.2.1 は、末尾の行の区切りが 2 個以上続く入力を空行として拒否する。

**報告された事象:** 動画 `https://www.youtube.com/watch?v=dsuNgos_kxA` の文字起こしを、チャプターの見出し行（`チャプター 1` から `チャプター 24` までの 24 行）を含めて送ったところ、サーバが `invalid_transcript` を返した。見出し行を除いた同じ入力は受理される（本要件の作成時に `internal/transcript` のパーサで再現を確認した）。

**方針の変更:** 0015 は、セグメントでない行をすべて拒否し、見出しを含めないことを利用者への案内で求める設計だった。本書はこれを次のように変える。

- **前置き（F-007）。** 最初のセグメントの行より前の行は、内容にかかわらず、実害のない範囲で読み飛ばす（実害のある行は §F-007 の決定のとおり拒否する）。前置きの範囲は、行の内容から推測せず、時刻の文法（0015 §3.2.2）で決まる最初のセグメントの行の位置で決める。
- **最初のセグメントの行より後（F-001・F-002・F-006）。** **内容から特定できる行**（形 A のチャプターの見出し行と、入力の末尾の空白行と既知の操作ラベル行）だけを読み飛ばし、それ以外のセグメントでない行は引き続き拒否する。この範囲では、位置から見出しを推測して無視する形にはしない（0015 §3.2.9 の方針を維持する）。未知の行を拒否する性質を残すのは、YouTube の UI の変更で書式が変わったことを検出するためである（0015 §1.4.4）。
- あわせて、0015 §3.2.1 の「末尾の行の区切りは 0 個か 1 個」という規則を、末尾の領域を無視する規則に変え（F-006）、0015 §3.2.5 の「形は先頭の行で判定する」という規則を、最初のセグメントの行で判定する規則に変える（F-007）。

対応 issue: [#301](https://github.com/isseis/yt2column/issues/301)。

本書で節番号だけを示す 0015 の参照（`0015 §3.2.1` など）は、`docs/tasks/0015_copied_transcript_source/02_architecture.md` の節を指す。AC 番号の参照（`0015 AC-06` など）は、同じタスクの `01_requirements.md` の AC を指す。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

- 最初のセグメントの行より前の行（前置き）を、形 A・形 B の入力で実害のない範囲で読み飛ばす（F-007）。
- チャプターの見出し行を、形 A の入力で受理して読み飛ばす（F-001）。
- 入力の末尾の空白行と既知の操作ラベル行（`動画の時間と同期`）を、形 A・形 B の入力で読み飛ばす（F-002・F-006）。
- 上記以外の、最初のセグメントの行より後のセグメントでない行を拒否する振る舞いを維持する（F-003）。
- 拒否のエラーの契約（`ErrCopiedTranscriptFormat` とその非公開の理由の番兵、値の非包含）を維持する（F-004）。
- 上記を確かめるテストと、必要な実データ・文書を整える（F-005）。

### 2.2. スコープ (In Scope)

- 形 A・形 B の入力の前置きの読み飛ばしと、形の判定の位置の変更（F-007）。
- 形 A の入力に混じるチャプターの見出し行の読み飛ばし（F-001）。
- 形 A・形 B の入力の末尾の領域（空白行と操作ラベル行）の読み飛ばし（F-002・F-006）。
- 上記の読み飛ばしと、既存の拒否の振る舞いとの関係（F-003）。
- 拒否のエラーの契約の維持（F-004）。
- 上記を確かめるユニットテスト（F-005）。

### 2.3. スコープ外 (Out of Scope)

- **形 B のチャプターの見出し行（前置きにあるものを除く）。** 形 B の見出しは、`チャプター N: タイトル` の接頭辞を持たない素のタイトル（`存在感のある声`・`What is symmetry in physics?` など。0015 §1.4.1）として現れ、内容から見出しと本文を区別できない。最初のチャプターの見出しは前置きとして読み飛ばす（F-007）が、2 つ目以降のチャプターの見出しがある形 B の入力は、本タスクの後も `invalid_transcript` で拒否される。形 B の見出しの扱いは将来のタスクとする。
- 最初のセグメントの行より後で、末尾の領域より前にある、パネル以外の表示項目（`タイムライン` など）の読み飛ばし。これらはセグメントでない行として引き続き拒否する（F-003）。
- 最初のセグメントの行と末尾の領域の間にある空行（空白文字だけの行）の読み飛ばし。従来どおり拒否する。
- 末尾の領域の行と前置きの行の数の上限。入力全体の上限（4 MiB）だけを適用する。
- パーサが受理するセグメントの書式（時刻の文法、読み上げ用ラベル、行の区切り、本文の規則）の変更。0015 のままとする。
- 拡張（`extension/`）の変更。拡張は選択範囲を `window.getSelection().toString()` のまま送り、行を除去しない（0015 §1.4.3、[security.md](../../dev/security.md) §8.1）。
- サーバ（`internal/server`）の拒否の理由と応答の形式の変更。
- `transcript.Transcript`・`Segment`・`TranscriptSource` の型の変更。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-007: 前置きの読み飛ばし（形 A・形 B）

形 A・形 B のどちらの入力でも、**最初のセグメントの行**より前の行（**前置き**）を、解析の対象から除く（セグメントを作らない）。

**決定（最初のセグメントの行）:** 最初のセグメントの行とは、入力の先頭から順に見て、行の先頭から時刻を読める（0015 §3.2.2 の時刻の文法で、`parseTimestampPrefix` に相当する読み取りが成功する）最初の行である。時刻だけの行（形 B の時刻の行）と、時刻で始まりそれ以外の文字が続く行（形 A の行）のどちらでもよい。行の内容の他の部分（読み上げ用ラベルの一致など）は、最初のセグメントの行かどうかの判定に使わない。

**決定（形の判定）:** 0015 §3.2.5 の形の判定は、入力の先頭の行ではなく、最初のセグメントの行で行う。最初のセグメントの行が時刻だけの行なら形 B、そうでなければ形 A とする。判定の規則そのもの（時刻だけの行か否か）は 0015 のままとする。

**決定（実害のない範囲）:** 前置きの行の内容は出力に入らないので、前置きを読み飛ばす実害は、本来受理すべきでない入力を受理してしまうことと、セグメントを黙って失うことに限られる。これを防ぐため、次の行は前置きにあっても読み飛ばさずに拒否する。

| 前置きの行 | 扱い | 理由 |
|---|---|---|
| 制御文字を含む行（0015 §3.2.1） | `errCopiedControlChar` で拒否する | 行全体の検査は前置きにも適用する。パネルの前置きには現れない |
| ASCII の数字・`:`（ASCII）・ASCII の数字がこの順に連続する部分を含む行（例: `05:00`・`60:00`・`0:5`・先頭に U+FEFF や空白が付いた `0:00`） | `errCopiedNotTimestamp` で拒否する | 時刻の文法に合わない時刻か、前に文字が付いた時刻である可能性がある。読み飛ばすと、そのセグメントを黙って失う |

-   上の表以外の行（0 文字の行、空白文字だけの行、`動画の関連情報`・`タイムライン`・`文字起こし`・検索欄のラベル・チャプターの見出し行などの任意の文字列）は、内容にかかわらず読み飛ばす。前置きの行の内容を一覧と照合しない。
-   文書全体の検査（生バイトの UTF-8、空白文字以外の文字を含まない入力の拒否、行の区切りの統一。0015 §3.2.1）は、前置きを含む入力の全体に、従来どおり適用する。
-   最初のセグメントの行がない入力（前置きと末尾の領域だけの入力）は、`errCopiedNoText`（本文のあるセグメントがない。0015 §3.2.6）で拒否する。
-   拒否のエラーの行番号は、前置きを除く前の入力の行番号とする。
-   前置きの行は、読み上げ用ラベルの言語の固定（0015 §3.2.4）に影響しない。言語は最初のセグメントの行で固定する。
-   前置きの判定は、最初のセグメントの行で終わる。最初のセグメントの行より後には適用しない（F-003）。

**Acceptance Criteria**:
- **AC-28**: §1 で観測した前置き（`動画の関連情報`・空行 2 つ・`タイムライン`・空行・`文字起こし`・`文字音声変換を検索` 2 行・空行）の後に形 A のセグメントが続く入力を解析すると成功する。返る `Segments` は、前置きを取り除いた入力の `Segments` と、要素の数・各要素の `StartMs`・`Text`・順序がすべて等しい。前置きのどの行の文字列も、返るどの `Segment.Text` にも含まれない。
- **AC-29**: 前置き（`文字起こし`・`動画内を検索`・形 B の最初のチャプターの見出しを模した架空の行 `はじめの話`）の後に形 B のセグメントが続く入力を、形 B として解析して成功する（`errCopiedMixedForms` にならない）。返る `Segments` は、前置きを取り除いた入力の `Segments` と等しい。
- **AC-30**: 前置きに、ASCII の数字・`:`・ASCII の数字が連続する部分を含む行（`05:00`・`0:5`・`﻿0:00`・` 0:00`）があり、その後に正しいセグメントが続く入力を、その行の行番号の `errCopiedNotTimestamp` で拒否する。前置きに制御文字を含む行（`タイ\tムライン`）がある入力を、その行の行番号の `errCopiedControlChar` で拒否する。
- **AC-31**: 最初のセグメントの行がない入力（`タイムライン\n`・`文字起こし\n\n動画の関連情報`）を、`errCopiedNoText` で拒否する。
- **AC-32**: 前置きの行は読み上げ用ラベルの言語の固定に影響しない。前置きに日本語の行があり、最初のセグメントの行が英語 UI のラベル（`0:000 secondsHello` など）の入力を受理する。

#### F-001: チャプター見出し行の読み飛ばし（形 A）

形 A の入力を解析するとき、最初のセグメントの行より後の行が次の**見出しの形**に一致する場合、その行をチャプターの見出し行として読み飛ばす（セグメントを作らない）。読み飛ばした行は、セグメントの数・`StartMs`・`Text`・順序に影響しない。最初のセグメントの行より前の見出し行は、前置きとして読み飛ばす（F-007）。

**決定（見出しの形）:** 1 つの行の全体が、次のいずれかに一致することを要する。数字は ASCII の `0`〜`9` だけを使う。

| 表示言語 | 形 |
|---|---|
| 日本語 UI | `チャプター` + U+0020（1 つ）+ 正の整数 + `:`（ASCII）+ U+0020（1 つ）+ タイトル |
| 英語 UI | `Chapter` + U+0020（1 つ）+ 正の整数 + `:`（ASCII）+ U+0020（1 つ）+ タイトル |

-   正の整数は先頭に `0` を付けない（`[1-9][0-9]*`。`0` と `01` は見出しの形に一致しない）。
-   タイトルは 1 文字以上で、最後の文字は空白文字ではない（行の末尾の空白文字を許さない次の規則による。このため空白文字だけのタイトルは一致しない）。タイトルの先頭に空白文字を含めてよい。タイトルの途中の `:`・空白・`チャプター` などの語を含めてよい。タイトルは行末までである。
-   行の先頭・末尾の空白文字を許さない（形 B の時刻の行と同じく、前後に空白文字のある行は見出しの形に一致しない）。行全体の制御文字の検査（0015 §3.2.1）は見出しの形にも適用する。
-   見出しの語（`チャプター`・`Chapter`）の言語は、読み上げ用ラベルの言語の固定（0015 §3.2.4）に影響しない。見出しの語の言語と、入力で固定したラベルの言語が一致することを要さない。見出し行は入力の言語の判定に使わない。
-   見出し行は、セグメントの間の行でも、最後のセグメントの行の後の行でもよい。
-   英語 UI の `Chapter` は観測していない。英語 UI の読み上げ用ラベル（0015 §1.4.1 で `24 seconds` などを観測）を受理するのと同じ規則として受理する（0015 §3.2.8 と同じく、理由のある未観測の形）。実物での確認を §7 に記す。

**決定（観測していない見出しの形）:** 上記の形に一致しない見出しの表記（全角コロン `：`、区切りの空白がない `チャプター2: タイトル`、番号のない `チャプター: タイトル`、`チャプター 2 タイトル`、英語 UI の `chapter 2: title` など）は、見出しの形に一致しないので、最初のセグメントの行より後では F-003 により拒否する。観測していない表記を推測で受理しない（0015 §1.4.4 と同じ方針）。

**Acceptance Criteria**:
- **AC-01**: 日本語 UI の見出し行（`チャプター 1: はじめに`・`チャプター 2: 3つの準備と1つの注意`）がセグメントの間にある形 A の入力を解析すると成功する。返る `Segments` は、同じ入力から見出し行を取り除いた入力の `Segments` と、要素の数・各要素の `StartMs`・`Text`・順序がすべて等しい。
- **AC-02**: 見出し行のタイトルの文字列が、返るどの `Segment.Text` にも含まれない。`Segments` の要素の数は、入力のうち時刻で始まり本文を持つ行の数に等しい。
- **AC-03**: 最後のセグメントの行の後の行がチャプターの見出し行のとき（末尾の領域の前でも）、その行は読み飛ばされる。見出しの語の言語と読み上げ用ラベルの言語が異なる入力（日本語 UI の見出し行と、英語 UI のラベルのセグメントの行 `0:000 secondsHello` など）も受理する。
- **AC-04**: 最初のセグメントの行より後にある、見出しの形に一致しない行（`チャプター: タイトル`・`チャプター 0: タイトル`・`チャプター 01: タイトル`・`チャプター2: タイトル`・`チャプター 2 タイトル`・`チャプター 2: `（区切りの空白の後のタイトルが空）・英語 UI で `chapter 2: title`）は、読み飛ばさずに拒否する。
- **AC-05**: 見出し行だけで本文のあるセグメントが 1 つもない入力（例: `チャプター 1: はじめに\n`。前置きだけの入力になる）は、`errCopiedNoText` で拒否する（AC-31）。
- **AC-06**: タイトルに `:`・空白・`チャプター` を含む見出し行（例: `チャプター 5: 手順 2: 次のチャプターの準備`・`チャプター 12: 朝 と 夜`）を受理し、読み飛ばす。

#### F-002: 末尾の操作ラベル行（形 A・形 B）

入力の末尾の領域（F-006）にある行のうち、行の全体が下の**操作ラベルの一覧**のいずれかの文字列と完全に一致する行を、パネルの操作ラベルとして読み飛ばす（セグメントを作らない）。パネルの先頭の操作ラベル（`文字起こし`・`文字音声変換を検索`・`動画内を検索`・`Search transcript`）は前置きとして読み飛ばす（F-007）ので、この一覧に含めない。

**決定（操作ラベルの一覧）:** 次を、`testdata/2tcCWM-sRBw.transcript_panel.html` と §1 の観測に基づいて定める。

| 表示言語 | ラベル | パネルでの位置 | 出典 |
|---|---|---|---|
| 日本語 UI | `動画の時間と同期` | パネルの末尾のボタン | `transcript_panel.html:3206`・`:3211`、§1 の観測 |
| 英語 UI | `Sync to video time` | パネルの末尾のボタン | 2026-10-17 に英語 UI のパネルで観測 |

**決定（観測していない操作ラベル）:** 上の表以外の末尾の操作ラベルは観測していない。観測していない文字列を推定で一覧に加えない（0015 §1.4.4）。英語 UI の末尾のボタンのラベルは `Sync to video time` であり、`Sync to video` などの観測していない表記は一覧に一致しない。英語 UI で、最後のセグメントとボタンの間に空行が入るかは観測していないが、F-006 は空行の有無にかかわらず末尾の領域として扱うので、どちらでも受理する。

-   一致は行の全体で行う。前後に空白文字のある行、ラベルの一部だけを含む行（例: `動画の時間と同期について話します`）、ラベルに別の文字が続く行は、操作ラベルに一致しない。
-   行全体の制御文字の検査（0015 §3.2.1）は操作ラベル行にも適用する。
-   操作ラベル行を読み飛ばすのは末尾の領域の中だけである。最初のセグメントの行と末尾の領域の間にある操作ラベル行は、セグメントでない行として拒否する（F-003）。
-   操作ラベル行は、読み上げ用ラベルの言語の固定（0015 §3.2.4）に影響しない。
-   形 B では、末尾の領域の判定が本文の行より先に行われる。形 B の最後のセグメントの本文が、操作ラベルと完全に一致する文字列（`動画の時間と同期` の 1 行）である場合、その行は操作ラベルとして読み飛ばされ、最後の時刻は本文のないセグメントになる。本文の全体がボタンのラベルと完全に一致する場合に限るので、受け入れる。

**Acceptance Criteria**:
- **AC-07**: §1 で観測した末尾（最後のセグメントの行・空行・`動画の時間と同期`。最後の行の区切りなし）を持つ形 A の入力を解析すると成功する。返る `Segments` は、空行と `動画の時間と同期` の行を取り除いた入力の `Segments` と、要素の数・各要素の `StartMs`・`Text`・順序がすべて等しい。`動画の時間と同期` の文字列は、返るどの `Segment.Text` にも含まれない。英語 UI のラベルのセグメントの末尾に `Sync to video time` の行がある入力も同様に受理し、その行を読み飛ばす。
- **AC-08**: 同じ末尾を持つ形 B の入力を解析すると成功し、空行と `動画の時間と同期` の行を読み飛ばす。前置き（AC-29）と末尾の両方を持つ形 B のパネル全体の選択（2 つ目以降のチャプターの見出しを含まないもの）も受理する。
- **AC-09**: 操作ラベルと同じ語を含むが一致しない末尾の行（`動画の時間と同期について話します`・`動画の時間と同期 `（末尾に空白）・`Sync to video`・`sync to video time`）は、読み飛ばさずに拒否する。
- **AC-10**: セグメントの間にある `動画の時間と同期` の行（`0:000 秒はい\n動画の時間と同期\n0:1010 秒です\n`）は、末尾の領域にないので拒否する。
- **AC-11**: 操作ラベル行だけで本文のあるセグメントが 1 つもない入力（例: `文字起こし\n動画の時間と同期\n`）は、`errCopiedNoText` で拒否する。

#### F-003: セグメントでない行の拒否の維持

最初のセグメントの行より後で、末尾の領域より前にある、F-001 で定めた行以外のセグメントでない行は、引き続き拒否する。これは、利用者がパネル以外の文字列を選んだ場合と、YouTube の UI の変更で新しい種類の行が現れた場合を検出するためである。

**決定（`タイムライン` などのパネル以外の表示項目）:** 0015 が拒否の対象として挙げた `タイムライン`・`存在感のある声`・`What is symmetry in physics?` などの行は、前置き（F-007）にあれば読み飛ばし、最初のセグメントの行より後にあれば、F-001・F-002 のどちらにも一致しないので拒否する。

**Acceptance Criteria**:
- **AC-12**: 最初のセグメントの行より後にある、時刻で始まらず、F-001 の見出しの形にも末尾の領域にも当たらない行（`タイムライン`・`存在感のある声`・`What is symmetry in physics?`・`こんにちは`）を含む入力を、`ErrCopiedTranscriptFormat` を包むエラーで拒否する。
- **AC-13**: 最初のセグメントの行より後にある、未知の新しいラベル（例: `チャプターの一覧`・`Download transcript`）を含む入力を拒否する（書式の変更の検出を残す）。

#### F-004: 拒否のエラーの契約の維持

#### F-006: 入力の末尾の領域の無視（形 A・形 B）

形 A・形 B のどちらの入力でも、入力の末尾に続く、空白文字だけの行（0 文字の行を含む）と操作ラベル行（F-002）からなる行の並び（**末尾の領域**）を、解析の対象から除く。除いた後、入力は末尾の領域の直前の行で終わるとみなす。

**決定（末尾の領域の形）:** 末尾の領域は、入力の最後の行から前に向かって、次のどちらかに当たる行が続く限りの範囲である。空白文字だけの行と操作ラベル行は、どの順で何行混じってもよい。

-   行の内容が 0 文字であるか、Unicode の White_Space の文字（U+0020・U+3000・NBSP など）だけからなる行。
-   F-002 の操作ラベルの一覧のいずれかと完全に一致する行。

次の 2 点を要する。

-   末尾に限る。最初のセグメントの行と末尾の領域の間にある空白文字だけの行は、従来どおり拒否する（0015 §3.2.1 の空行の拒否）。最初のセグメントの行より前の空白文字だけの行は、前置きとして読み飛ばす（F-007）。
-   行全体の制御文字の検査（0015 §3.2.1）を適用する。タブ（U+0009）などの制御文字を含む行は、末尾にあっても制御文字の理由で拒否する。

**決定（末尾の行の区切り）:** 0015 §3.2.1 は、末尾の行の区切りが 2 個以上続く入力を空行として拒否していた。本書は、末尾の空白文字だけの行を無視するので、末尾の行の区切りの数に上限を設けない。入力の最後の行の区切りの有無も問わない（§1 の観測では `動画の時間と同期` の後に区切りがない）。末尾の領域を取り除いた後に残る入力で、行番号は除く前の行番号を保つ（拒否のエラーに使う行番号を変えない）。

-   例: `0:000 秒はい\n0:1010 秒ということで\n\n` を、`0:000 秒はい\n0:1010 秒ということで` と同じ `Segments` にする。
-   3 個以上続く区切り（`…\n\n\n`）も、末尾の空行 2 つとして無視する。
-   形 B でも同じく無視する。形 B の最後の時刻の行の後にある空白文字だけの行は、本文の行ではなく末尾の領域として無視し、その時刻は本文のないセグメントになる。0015 ではこの入力（例: `0:00\nx\n0:05\n \n`）を `errCopiedBlankText` で拒否していたが、本書は受理する。

**決定（検査の順序）:** 0015 §4.3 の検査の順序に、次のように加える。

1.  手順 3（行の区切り）の後、手順 4（行ごとの検査）の前に、末尾の領域を除く。末尾の領域の行には、除く前に制御文字の検査を適用する（AC-26）。
2.  続けて、残った行の先頭から前置きを除く。前置きの各行には、制御文字の検査と、F-007 の数字・`:`・数字の検査をこの順に適用する。最初のセグメントの行に達した時点で前置きは終わる。最初のセグメントの行がなければ `errCopiedNoText` で拒否する。
3.  形の判定（0015 §3.2.5）を、最初のセグメントの行で行う。
4.  最初のセグメントの行から末尾の領域の直前までの行に、手順 4 を適用する。F-001 の読み飛ばしの判定は、手順 4 の 1（空の行）と 2（制御文字）の後、3（形ごとの規則）の前に行う。

**Acceptance Criteria**:
- **AC-21**: 形 A の入力の末尾に空行（0 文字の行）がある入力（`17:3017 分 30 秒寝ます\n\n`）を解析すると成功する。返る `Segments` は、末尾の空行を取り除いた入力の `Segments` と、要素の数・各要素の `StartMs`・`Text`・順序がすべて等しい。
- **AC-22**: 末尾に空白文字だけの行（U+0020 だけの行・U+3000 だけの行）がある形 A の入力と、末尾に空行がある形 B の入力を解析すると成功し、どちらも、末尾の行を取り除いた入力と同じ `Segments` にする。
- **AC-23**: 末尾に 2 個以上の空行がある入力（`0:000 秒はい\n\n\n`）と、空行と `動画の時間と同期` が混じる末尾（`0:000 秒はい\n\n動画の時間と同期\n\n`）を解析すると成功し、末尾の領域をすべて無視する。
- **AC-24**: 最初のセグメントの行と末尾の領域の間にある空行（`0:000 秒はい\n\n0:1010 秒です\n`）は、0015 §3.2.1 の空行として引き続き拒否する。入力の先頭の空行（`\n0:000 秒はい\n`）は前置きとして読み飛ばし、受理する。
- **AC-25**: 入力のすべてが空行である場合（`\n\n`）は、空白文字以外の文字を含まない入力として拒否する（0015 §3.2.1 の `errCopiedBlank`）。
- **AC-26**: 末尾の行にタブなどの制御文字を含む場合（`0:000 秒はい\n\t\n`）は、制御文字の理由で拒否する。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

| 境界 | 消費する要素 | 受理する形 | 上限 | 拒否時の扱い | 主な AC |
|---|---|---|---|---|---|
| 形 A・形 B の入力の前置き | 最初のセグメントの行より前の行の全体 | 制御文字を含まず、ASCII の数字・`:`・ASCII の数字の連続を含まない任意の行（F-007） | 行の数の上限なし。入力全体の上限は 4 MiB | 読み飛ばす（拒否しない）。前置きの行は出力（`Segments`・プロンプト・記事・中間生成物）に含めない。表の拒否の対象の行は `ErrCopiedTranscriptFormat` | AC-28〜AC-32 |

| 形 A・形 B の入力の末尾の領域 | 行全体 | 0 文字の行、Unicode の White_Space だけからなる行、F-002 の一覧と完全に一致する行。いずれも制御文字を含まないもの。末尾に限る（F-006） | 数の上限なし。入力全体の上限は 4 MiB | 読み飛ばす（拒否しない）。セグメントの間の空白行・操作ラベル行は拒否する | AC-07〜AC-11・AC-21〜AC-26 |

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   解析の時間とメモリは入力の長さに比例する（AC-20）。前置きの判定は、各行の時刻の接頭辞の読み取りと数字・`:`・数字の走査であり、行の長さに比例する。見出し行の判定は、行の先頭の定数文字と数字の比較であり、行の長さに比例する。末尾の領域の判定は、空白文字の判定と一覧（2 文字列）との比較であり、行の長さに比例する。
-   LLM の呼び出しと `yt-dlp` の呼び出しの回数を変えない。

### 4.2. セキュリティ (Security)

-   読み飛ばした前置きの行・見出しのタイトル・操作ラベルを、`Segments`・プロンプト・記事・中間生成物・ログのいずれにも含めない（AC-02・AC-07・AC-28）。読み飛ばす行の内容は、解析の振る舞いを選ぶためだけに使う（0015 §1.3.1 の例外 1 の範囲）。
-   拒否のエラーの文字列に、入力の字幕の文字列を含めない（AC-15。[security.md](../../dev/security.md) §6）。
-   報告された入力と §1 で観測した入力の全体を `testdata/` に保存しない（AC-16。[security.md](../../dev/security.md) §7）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   パネル全体の選択（前置き・チャプターの見出し行・末尾のボタンを含む形 A の入力）が受理され、`invalid_transcript` で拒否されない（AC-01・AC-07・AC-19・AC-28）。
-   末尾に空行が入った入力が受理され、`invalid_transcript` で拒否されない（AC-21〜AC-23）。
-   前置きを読み飛ばしても、時刻の文法に合わない時刻をもつセグメントを黙って失わない（AC-30）。
-   前置き・見出し行・末尾の領域を含まない入力の解析結果を変えない（AC-18）。

### 4.4. 互換性 (Compatibility)

-   `transcript.CopiedSource`・`CopiedInput`・`NewCopiedSource`・`Fetch` のシグネチャと契約を変えない。
-   `ErrCopiedTranscriptFormat` と、非公開の理由の番兵の集合（0015 §4.1）を変えない。新しい、`internal/transcript` の外から観測できる番兵エラーを追加しない（AC-14）。
-   `internal/transcript` の公開の型・関数の集合を変えない。
-   `internal/pipeline` の guard（`TestCommonTypesFieldSets`）が固定する型のフィールド集合を変えない。
-   拡張とサーバの変更を要求しない。

### 4.5. 保守性 (Maintainability)

-   読み飛ばす行の形（見出しの形と操作ラベルの一覧）と前置きの拒否の規則を、`internal/transcript` の 1 か所に定数として置く。呼び出し側（サーバ・拡張）に同じ規則を持たせない。
-   新しい末尾の操作ラベルが観測されたときに、一覧に 1 行を加えるだけで対応できる形にする。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」と [CLAUDE.md](../../../CLAUDE.md) に従う。外部ライブラリを追加しない。
-   [CLAUDE.md](../../../CLAUDE.md) の「Reject, don't normalize」に従う。最初のセグメントの行より後で読み飛ばすのは、明示的に定義した見出しの形と末尾の領域に当たる行だけであり、ほかのセグメントでない行を読み飛ばさない。前置きは、F-007 の拒否の規則に当たる行を読み飛ばさない。
-   タスク `0015_copied_transcript_source` の書式の定義（形 A・形 B、時刻の文法、読み上げ用ラベル、行の区切り、本文の規則、禁止の入力の一覧）のうち、本タスクが変えるのは、読み飛ばす行の種類（前置き・形 A の見出し行・末尾の領域）、入力の末尾の区切りの数（0015 §3.2.1）、形の判定の位置（0015 §3.2.5）だけである。それ以外を変えない。0015 の文書は履歴として変更しない（本タスクが上書きする）。
-   拡張（#111）の「選択範囲をそのまま送り、DOM の構造に依存しない」方針を変えない。
-   ユニットテストは、実際の `yt-dlp` も LLM の API も Webhook もブラウザも呼ばない（[CLAUDE.md](../../../CLAUDE.md)「Testing Strategy」）。報告された実データでの確認（AC-19）だけを手動で行う。

## 6. 用語集 (Glossary)

-   **形 A・形 B:** 0015 §3.2.4 と同じ。形 A は 1 セグメントが 1 行で、時刻・読み上げ用ラベル・本文が区切りなしに連結される。形 B は時刻の行と本文の行が分かれる。
-   **最初のセグメントの行:** 入力の先頭から見て、行の先頭から時刻を読める最初の行（F-007）。形の判定はこの行で行う。
-   **前置き:** 最初のセグメントの行より前の行。F-007 で、実害のない範囲で読み飛ばす。
-   **セグメントでない行:** 形 A の入力の行のうち、時刻で始まらない行。0015 はすべて拒否する。本タスクは、前置きと、見出しの形と末尾の領域に当たる行を読み飛ばす。
-   **チャプターの見出し行:** 文字起こしパネルが、動画のチャプターを表すためにセグメントの間に差し込む行（0015 §1.4.1）。
-   **見出しの形:** 本書 F-001 で定める、チャプターの見出し行を認識する形（`チャプター`・`Chapter` + 番号 + `: ` + タイトル）。
-   **パネルの操作ラベル:** パネルが持つ、タイトル・検索欄・末尾のボタンのラベル。末尾のボタンのラベルを F-002 の一覧で定める。先頭のタイトル・検索欄のラベルは前置きとして扱う。
-   **末尾の領域:** 入力の末尾に続く、0 文字の行・Unicode の White_Space だけからなる行・操作ラベル行（いずれも制御文字を含まないもの）の並び。F-006 で無視する。
-   **読み飛ばす:** その行をセグメントにせず、`Segments` に含めないこと。入力全体を拒否しない。
-   **読み上げ用ラベル:** 0015 §3.2.3 と同じ。日本語 UI の `24 秒`・`1 分 6 秒` と、英語 UI の `24 seconds`。
-   用語は [translation_glossary.md](../../translation_glossary.md) と統一する。

## 7. 未解決の点（レビューで決める）(Open Questions)

- **英語 UI の見出し。** 見出しの `Chapter`（F-001）を対称性で受理する案をレビューで決める。英語 UI の末尾のボタンは `Sync to video time` と確認し、F-002 の一覧に加えた。
-   **形 B の 2 つ目以降のチャプターの見出し。** 形 B の見出しは内容から区別できない（§2.3）。将来のタスクにまとめて委ねる案である。
-   **末尾の領域を一覧の外にも広げるか。** 前置きは任意の行を読み飛ばすが、末尾の領域は空白行と一覧の操作ラベル行に限る。§1 の観測ではボタンより後の行は選択に入らないので、本書は狭い規則とした。末尾にも、前置きと同様の任意の行の読み飛ばしを適用するかをレビューで決める。
