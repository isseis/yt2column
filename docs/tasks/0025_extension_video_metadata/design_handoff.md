# 設計への申し送り：ブラウザ拡張による動画タイトル・チャンネル名・概要欄の取得と送信

本書は、[01_requirements.md](01_requirements.md) の起草（とレビュー）で挙がった事項のうち、設計の段階で決めるものを集める。`02_architecture.md` は、各項目について、採った方針か、当てはまらない理由を記録する。

## H-01: 動画ページのセレクタと、概要欄の折りたたみの判定

-   **事項:** 動画タイトル・チャンネル名・概要欄を読むセレクタを確定する。概要欄が折りたたまれているか（「…もっと見る」が開かれていないか）を判定する手段を決める。値が取れない・複数一致する・想定外の要素に当たる場合の扱いを決める。
-   **理由:** 0007 §3.12.2 の観測では、チャンネル名は `ytd-channel-name a` と `#owner #channel-name #text`、概要欄は `#expanded yt-attributed-string`（全文）と `#attributed-snippet-text`（冒頭）にある。いずれも `ytd-watch-metadata` の下の要素である。動画タイトルのセレクタは観測していない。これらは YouTube が独自に定義した要素（カスタム要素）で、公開の仕様ではなく予告なく変わりうる。取れない場合を拒否の理由にしないこと（F-001・F-004）が要件である。
-   **候補の方針:** セレクタと読み取りを 1 つの小さな関数にまとめ、ユニットテストでは fake の DOM（または fake の読み取り）で確かめる。ページ内の移動の後に古い値を残す `window.ytInitialPlayerResponse` は使わない（0007 §3.12.2）。「…もっと見る」の開閉は、`ytd-text-inline-expander` の展開の要素（`#expand` など）または `#expanded` の有無で判定し、実装のときに実際のページで確かめる。動画タイトルのセレクタも、実際のページで確かめる。概要欄が短く冒頭だけで全文になる動画で、促しのメッセージ（F-003）が出るかを確かめ、出る場合の扱いを決める。
-   **観測の記録（2026-10-17）:** 設計の段階で、macOS の Chrome 155.0.8059.40 と Brave 1.97.57（Chromium 155.0.8059.80）で、ログインしていない状態の動画ページを DevTools のコンソールで観測した。1 本目は直接開き、ページ内の関連動画のリンクから 2 本目に移動した後も観測した。両方のブラウザで共通の結果は次のとおりである（一致数は `document.querySelectorAll` の結果）。

    | 項目 | セレクタ | 一致数 | 観測 |
    |---|---|---|---|
    | 動画タイトル | `ytd-watch-metadata #title h1` | 1 | `textContent` は前後に空白と改行を含む |
    | 動画タイトル | `ytd-watch-metadata #title h1 yt-formatted-string` | 1 | 値は動画タイトルそのもの（前後の空白を含まない）。`document.title` は「動画タイトル + ` - YouTube`」 |
    | チャンネル名 | `ytd-channel-name a` | 41 | 単独では使えない（ページ内の別の要素にも一致する） |
    | チャンネル名 | `#owner #channel-name #text` | 1 | 値はチャンネル名そのもの |
    | チャンネル名 | `ytd-video-owner-renderer #channel-name a` | 1 | 上と同じ値 |
    | 概要欄の要素 | `ytd-watch-metadata #description-inline-expander` | 1 | 本当の概要欄。`ytd-text-inline-expander` はページ内に 2 つあり、もう 1 つ（`#inline-expander`、watch メタデータの外）は隠れている |
    | 概要欄（折りたたみ時） | `#attributed-snippet-text` | 1 | 動画によって中身が違う。1 本は 253 文字で全文と一致し、別の 1 本は 37 文字で冒頭のみ（全文は 1,295 文字） |
    | 概要欄（開いた後） | `#expanded yt-attributed-string` | 1 | 全文が入る。折りたたみ時は空 |
    | 折りたたみの状態 | `ytd-watch-metadata #description-inline-expander` の `is-expanded` 属性 | - | 折りたたみ時は属性がなく、開いた後に付く。ボタン（`#expand`・`#collapse`）の可視状態より確実だった |

    -   ページ内の移動の後は、3 つの値が移動先の値に変わり、概要欄は折りたたみに戻った（`is-expanded` が外れ、`#expanded` が空になった）。
    -   概要欄の領域には「文字起こし」「動画の詳細」などが自動的に付くため、概要欄が短くても「…もっと見る」が出る。「概要欄が短く、ボタンも出ない」動画は見つからなかった。
    -   ログインした状態は観測していない（`#owner` の周りに登録・メンバーシップなどの要素が増えうる）。
-   **関連:** F-001、F-003、AC-01〜AC-03、AC-12

## H-02: 読み取りの場所と、注入する関数の分け方

-   **事項:** メタデータの読み取りを、選択範囲を読む既存の注入する関数（`SelectionReader` の `readSelection`）に含めるか、別の読み取りの interface にするかを決める。注入の戻り値の形と、境界での検査の方法を決める。
-   **理由:** 0007 §3.12.2 と §3.12.3 は、チャンネル名・概要欄を収集する場合は「`SelectionReader` の注入する関数を広げるか別の読み取りの interface を加える」としている。注入する関数は `chrome.scripting` がソースを直列化してページで実行するので、外の名前を参照できない（`chromeDeps.ts:56-61`）。選択範囲はブラウザの選択の API で取り、DOM には依存しない。
-   **候補の方針:** 同じ起動で 1 回の注入にまとめるか、読み取りを 2 つに分けるかを、注入の失敗の扱いと取得できる値の独立性から決める。どちらでも、戻り値の形が合わない場合は読み取りの失敗として扱い、起動を失敗させない（F-004・AC-20）。
-   **関連:** F-001、F-004、AC-01、AC-04、AC-20

## H-03: 取得した値を収集の結果に持たせるか、送信のときに渡すか

-   **事項:** 取得した 3 つの値を、`CollectedInput`・`CollectOutcome` に省略可能な項目として持たせるか、表示と送信のときに別に読むかを決める。`ArticleMetadata`（0020 が受け取れる型）へ渡す形を決める。
-   **理由:** `collect` は選択範囲・URL・タブのタイトルから `CollectedInput` を作る（`collect.ts:86-90`）。表示（F-003）と送信（F-002）の両方が値を使う。`CollectedInput` は起動の確認を通った入力だけを表す型で、0007 のガード（`core/collect.ts` とテスト以外での `CollectedInput` への型の表明の禁止）がその境界を守っている。`title` は既存ではタブのタイトルなので、名前の衝突に注意する。
-   **候補の方針:** メタデータは `collect` の結果に省略可能な項目として加え、`CollectedInput` の境界を通す。表示はポップアップだけに使い、結果ウィンドウへは渡さない（0020 の表示を変えない）。送信時は `prepareSend` の `metadata` 引数（既存）に渡す。
-   **関連:** F-001、F-002、F-003、AC-06、AC-11

## H-04: ポップアップの表示への統合

-   **事項:** ポップアップの収集内容の表示（`renderSummary`・`OutcomeSummary`）に、メタデータと促しのメッセージを加える形を決める。文言と配置を決める。
-   **理由:** 既存の表示は `OutcomeSummary`（タイトル・URL・文字数の要約）を `renderSummary` で描く。メタデータは要約より長くなりうる。不採用の表示（拒否の理由）や送信のボタンとの前後関係を決める必要がある。
-   **候補の方針:** 取得した値をそのまま（補正せず）テキストとして示す。促しのメッセージは固定の文言にする。表示はブラウザなしでユニットテストできるようにする（jsdom）。
-   **関連:** F-003、AC-11〜AC-15

## H-05: 開発者向けのログに残す内容

-   **事項:** 省略したフィールドの名前と省略の理由を、開発者向けのログにどの形式で残すか（ラベル、既存のログとの関係）を決める。
-   **理由:** 要件（F-004）は、省略の理由（欠落・空白文字のみ・対になっていないサロゲート・読み取りの失敗）にかかわらず、フィールドの名前と省略の理由の型の値をログに残し、読み取った値そのものは含めないと決めている。既存の経路は、収集の結果（選択範囲とタブのタイトルを含む）を `menuLogLabel`・`popupLogLabel` でログに出している（`launch.ts:168-172`・`255-257`）。共有トークンはログに出してはならない（0020 4.2）。
-   **候補の方針:** 既存のラベルの下に、フィールドの名前と省略の理由の列挙の値だけを出す。ページの文字列に依存しない固定の情報だけにする。
-   **関連:** F-004、AC-10、AC-16、AC-16a
