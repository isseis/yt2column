## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張が動画ページの DOM から動画タイトル・チャンネル名・概要欄を読み取り、API の任意フィールド（`title`・`channelName`・`description`）に値を渡して送る部分の要件を定義する。記事生成のプロンプトにより豊かなメタデータを渡すことを目的とする。

**背景:**
`0011_localhost_server`（[#109](https://github.com/isseis/yt2column/issues/109)）の API は、ブラウザの安定な API から常に取得できる `videoUrl` と `transcript` を必須、YouTube のサイトの DOM に依存する `title`・`channelName`・`description` を任意とした（API の要件書 F-002）。任意フィールドは欠落・空でも記事の生成を続行する（同 AC-06）。

`0020_extension_send`（[#111](https://github.com/isseis/yt2column/issues/111)）は、収集した選択範囲とタブの URL を送信し、応答を表示する送信のクライアントを実装した。送信のクライアントは任意の 3 フィールドを受け取れる形にしてあり、本タスクは値を DOM から取って渡すだけで、送信のクライアント自体（本文の形・送信・応答の表示）を変更しない（0020 F-002）。

`0007_browser_extension_skeleton/02_architecture.md` §3.12.2 の調査で、次を記録した。

-   チャンネル名は `ytd-channel-name a`・`#owner #channel-name #text` から読める。
-   概要欄は、折りたたみ時は冒頭（`#attributed-snippet-text`）のみ。全文は「…もっと見る」を開いた後に `#expanded yt-attributed-string` に入る。
-   これらのセレクタは、いずれも `ytd-watch-metadata` の下の要素を指す。

タブのタイトルは動画タイトルではない（`"<動画タイトル> - YouTube"` になる）。動画タイトルは `ytd-watch-metadata` の中から取る。ただし、動画タイトルのセレクタは 0007 §3.12.2 では観測していないので、設計で実際のページで確かめる（[design_handoff.md](design_handoff.md) H-01）。

取得する 3 つの値は、動画ページの DOM 由来の untrusted テキストで、記事生成のプロンプトに埋め込まれる。`docs/dev/security.md` §8 の攻撃ベクタの観点で扱う（§4.2）。

対応 issue: [#170](https://github.com/isseis/yt2column/issues/170)（親: [#105](https://github.com/isseis/yt2column/issues/105)、[#43](https://github.com/isseis/yt2column/issues/43)）

**本書の記述範囲:** 本書は、観測できる振る舞い（何を読み、何を送り、利用者に何を示すか）を定める。セレクタとその安定性、折りたたみの判定の手段、読み取りを行う場所、表示の正確な文言と配置、テストの手段は設計（`02_architecture.md`）で決める。要件のレビューで挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #170 の「決めること」への決定:**

-   **概要欄の全文:** 拡張はページを操作しない。DOM にある値だけを送る。折りたたまれているときは冒頭のみを送り、その場合はポップアップに「…もっと見る」を開くよう促すメッセージを表示する（F-003）。拡張はこれまで起動したタブを読むだけで、ページを操作していない（0007 4.2 は「利用者が起動するまでページを読まない」とし、起動で読むのは起動したタブだけとする）。ページを操作すると、この読むだけの振る舞いが変わるため、操作は行わない。
-   **値の整形:** DOM から読んだ値を補正しない。前後の空白・改行を保つ。空白文字のみの値は省略する（CLAUDE.md「Reject, don't normalize」）。
-   **追加の権限:** 不要。既存の `scripting` の注入で DOM を読むだけで、新しい権限を加えない（F-004・§4.2）。
-   **読み取りの関数の分け方:** 設計で決める（[design_handoff.md](design_handoff.md) H-02）。
-   **取得した値の表示:** ポップアップの収集内容の表示に加える。結果ウィンドウと送信の応答の表示は変えない（F-003）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   動画ページで拡張を起動すると、動画タイトル・チャンネル名・（取れれば）概要欄が収集され、API の任意フィールドとして送られる。記事生成のプロンプトに、選択範囲に加えてこれらのメタデータが渡る。
-   動画タイトルを、タブのタイトルではなく動画ページの DOM から取る。
-   概要欄の全文を取るためにページを操作せず、取れる範囲を送る。概要欄が折りたたまれていて全文が取れないときはポップアップで利用者に促し、利用者が「…もっと見る」を開いてから起動し直せば全文を送れるようにする。
-   DOM の構造の変化などで取得に失敗しても、起動を失敗させず、そのフィールドを省略して送る。
-   既存の収集（選択範囲・タブの URL・タブのタイトル）と、送信のクライアント（本文の形・送信・応答の表示）の振る舞いを変えない。

### 2.2. スコープ (In Scope)

-   起動したタブの動画ページの DOM から、動画タイトル・チャンネル名・概要欄を読み取ること（F-001）。
-   読み取った値を、送信のクライアントの任意の 3 フィールドとして渡すこと（F-002）。
-   ポップアップの収集内容の表示へのメタデータの追加と、概要欄が折りたたまれているときの促しのメッセージ（F-003）。
-   取得に失敗したとき、および値を省略したときの扱い（フィールドの省略と、省略の理由の開発者向けのログ）（F-004）。
-   文書: README、`security.md` §8・§8.1（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   送信のクライアント（本文の形・送信・応答の解釈と表示）の変更（0020）。本タスクは値を渡すだけである。
-   サーバと API の変更（#109 で完了）。API の設計書 §3.4 に従い、サーバ側を変更しない。
-   既存の収集（選択範囲・タブの URL・タブのタイトル）と拒否の理由（対象外のページ、収集の失敗、選択範囲が空、タイトルが空）の変更（0007 F-005）。タブのタイトルは確認の対象として残し、本文には入れない。
-   ページを操作して概要欄の「…もっと見る」を開くこと。拡張はクリックしない（1. 概要の決定）。
-   動画ページの DOM 以外からのメタデータの取得。`window.ytInitialPlayerResponse` は使わない（0007 §3.12.2。ページ内の移動の後に古い値を残すため）。
-   取得したメタデータの、結果ウィンドウへの受け渡しと表示（0020 の表示を変えない）。
-   メタデータの検証・整形（前後の空白の除去、値の切り詰め、値の大きさの独自の上限）。
-   動画タイトル・チャンネル名・概要欄の取得のための新しい権限。
-   表示する文言の多言語化。Chrome と Brave 以外のブラウザ（0007 2.3 と同じ）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 動画ページからのメタデータの取得

-   拡張は、起動（右クリックメニューとポップアップの両方）のときに、起動したタブの動画ページの DOM から次を読む。既存の収集（選択範囲・タブの URL・タブのタイトル。0007 F-005）と同じ起動で読む。
    -   **動画タイトル:** `ytd-watch-metadata` の中のタイトル（タブのタイトルではない）。
    -   **チャンネル名:** `ytd-channel-name a` または `#owner #channel-name #text`。
    -   **概要欄:** 開かれていれば全文（`#expanded yt-attributed-string`）。折りたたまれていれば DOM にある冒頭（`#attributed-snippet-text`）。
-   読み取った値は補正しない。前後の空白・改行・全角空白・サロゲートペアの文字を保つ。値が DOM にない場合、および空白文字のみの場合は、その値を取得できなかったものとして省略する（`null` も空文字列も使わない）。空白文字は、既存の収集の `empty-selection`・`empty-title` の判定（0007 F-005）と同じく Unicode の `White_Space` の文字とする（全角空白を含む）。
-   概要欄が折りたたまれているか（「…もっと見る」が開かれていないか）を判定し、表示（F-003）に渡す。判定の手段は設計で決める（[design_handoff.md](design_handoff.md) H-01）。
-   セレクタは YouTube が独自に定義した要素に依存する。取得に失敗しても起動を失敗させない（F-004）。
-   既存の収集の判定・順序・拒否の理由を変えない。読み取りを既存の注入する関数に含めるか、別の読み取りにするかは設計で決める（H-02）。

**Acceptance Criteria**:
- **AC-01**: 動画ページで起動すると、動画タイトル・チャンネル名・概要欄が、ページの DOM の文字列とそのまま一致して取得される。値の前後の空白・改行・全角空白・サロゲートペアの文字が保たれる（ユニットテスト。fake の読み取り）。
- **AC-02**: 動画タイトル・チャンネル名・概要欄のそれぞれが DOM にない場合、および空白文字だけの場合、その値は省略され、起動は成功する（ユニットテスト）。
- **AC-03**: 概要欄が開かれているときは全文を、折りたたまれているときは DOM にある冒頭を取得する。折りたたまれているかどうかが表示（F-003）へ渡される（ユニットテスト）。
- **AC-04**: 3 つの値のいずれかの読み取りが失敗しても、選択範囲・タブの URL・タブのタイトルの収集は成功し、取得できた値だけが使われる（ユニットテスト）。
- **AC-05**: 既存の収集の結果（選択範囲・タブの URL・タブのタイトル）と、拒否の理由とその順序が変わらない。タブのタイトルは API の `title` に入れず、動画タイトルを `title` に使う（ユニットテスト）。

#### F-002: 任意フィールドとしての送信

-   取得した動画タイトル・チャンネル名・概要欄を、送信のクライアント（0020 F-002）が受け取れる任意の 3 フィールドに渡す。送信のクライアントの本文の形（メンバ）、送信、応答の解釈と表示を変更しない。
-   本文には、取得できた（空でない）値だけを入れる。取得できなかった値、空白文字のみの値、空文字列は本文に含めない（`null` も空文字列も入れない）。
-   本文に、宣言したメンバ（`videoUrl`・`transcript`・`title`・`channelName`・`description`）以外のメンバを入れない。タブのタイトルを本文に入れない。
-   **対になっていないサロゲート:** 値が、本文に入れることでサーバに拒否される形（対になっていないサロゲート。`JSON.stringify` が `\ud800` などのエスケープにし、サーバが `invalid_body` で拒否する）を含む場合は、その値を送らずに省略する。任意のメタデータが、記事の生成そのものを失敗させないようにするためである。対になったサロゲート（サロゲートペア）は保つ。
-   本文の大きさの確認（0020 F-004）は、メタデータを含めた本文に適用する。

**Acceptance Criteria**:
- **AC-06**: 取得した動画タイトル・チャンネル名・概要欄が、本文の `title`・`channelName`・`description` の値と一致する（送信のクライアントを変更せずに）。送られる本文は、宣言したメンバだけを持ち、メタデータを渡さない場合の本文（0020 AC-07）と同じ形になる（ユニットテスト）。
- **AC-07**: 取得できなかった値、空白文字のみの値、空文字列は本文に含まれない（`null` のメンバも空文字列も現れない）。3 つのうち一部だけが取得できた場合、その値だけが含まれる（ユニットテスト）。
- **AC-08**: メタデータを含めた本文の UTF-8 のバイト数が 4,194,304 を超える場合は送らず、既存の「送る内容が大きすぎる」が表示される（ユニットテスト）。
- **AC-09**: 本文に、タブのタイトルが入らない（動画タイトルとは別の第 4 のメンバとしても現れない）（ユニットテスト。識別できる文字列を使い、本文の文字列に現れないことを確かめる）。
- **AC-10**: 対になっていないサロゲートを含む値（`"\uD800"`・`"a\uDC00b"`）はそのフィールドが省略され、省略の理由（対になっていないサロゲート）が開発者向けのログに記録される（F-004）。対になったサロゲート（`"\uD83D\uDE00"`）を含む値は保たれる（ユニットテスト）。

#### F-003: ポップアップでの表示と「…もっと見る」の促し

-   ポップアップの収集内容の表示（0007 F-006）に、取得した動画タイトル・チャンネル名・概要欄を加える。値を HTML やほかのマークアップとして解釈せず、テキストとして表示する。
-   概要欄が折りたたまれている（「…もっと見る」が開かれていない）とき、ポップアップに、その旨と「…もっと見る」を開いてからポップアップを開き直す手順を示す、固定のメッセージを表示する。概要欄が開かれているとき、および概要欄がないときは表示しない。
-   促しのメッセージは送信を止めない。折りたたまれていても送信のボタンは押せ、DOM にある冒頭のみで送る。
-   右クリックメニューの経路では促しのメッセージを出さない。確認を挟まずに送る（0020 F-005）。結果ウィンドウの表示は変えない。
-   促しのメッセージは固定の文言とし、ページの文字列（概要欄など）を含めない。正確な文言と配置は設計で決める（[design_handoff.md](design_handoff.md) H-04）。

**Acceptance Criteria**:
- **AC-11**: ポップアップに、取得した動画タイトル・チャンネル名・概要欄が表示される（ユニットテスト。jsdom）。
- **AC-12**: 概要欄が折りたたまれているとき、促しのメッセージがポップアップに表示される。開かれているとき、および概要欄がないときは表示されない（ユニットテスト）。
- **AC-13**: 促しのメッセージが表示されていても、送信のボタンは押せ、DOM にある冒頭のみで送られる（ユニットテスト）。
- **AC-14**: 表示されるメタデータに `<img src=x onerror=alert(1)>` のような文字列を含めても、要素にならない（`querySelector("img")` が `null` で、`textContent` に元の文字列が含まれる）。促しのメッセージは固定の文言で、概要欄の文字列を含まない（ユニットテスト）。
- **AC-15**: 右クリックメニューの経路では促しのメッセージを出さず、確認を挟まずに送る（ユニットテスト。既存の経路の確認）。

#### F-004: 取得に失敗したときの扱い

-   動画タイトル・チャンネル名・概要欄の取得に失敗した場合、起動を失敗させない。失敗した値を省略する。
-   値を省略したときは、理由（欠落・空白文字のみ・対になっていないサロゲート・読み取りの失敗。§4.5）にかかわらず、省略したフィールドの名前と省略の理由を開発者向けのログに残す。読み取りの失敗だけでなく、受理の検査による省略も残すのは、DOM の変化によるセレクタの失敗と、値の形による省略を、ログから区別できるようにするためである。
-   ログには省略の理由の型（列挙）の値を残し、読み取った値そのものは含めない。
-   メタデータの取得の失敗を、拒否の理由（`RejectionReason`）にしない。収集の失敗（`collection-failed`）として扱わず、起動を止めない。
-   新しい権限を加えない。既存の `scripting` の注入で DOM を読むだけで、ページを操作しない（§4.2）。
-   ログの形式（ラベル、既存の `menuLogLabel`・`popupLogLabel` のログとの関係）は設計で決める（[design_handoff.md](design_handoff.md) H-05）。

**Acceptance Criteria**:
- **AC-16**: 3 つの値のいずれかの読み取りが失敗した場合、起動は成功し、その値は省略され、フィールドの名前と省略の理由（読み取りの失敗）が開発者向けのログに記録される。利用者への拒否の理由は新たに増えない（ユニットテスト）。
- **AC-16a**: 値が欠落・空白文字のみ・対になっていないサロゲートを含むために省略された場合も、フィールドの名前と、それぞれの省略の理由が開発者向けのログに記録される。ログには読み取った値が含まれない（ユニットテスト。識別できる文字列を値に使い、ログに現れないことを確かめる）。
- **AC-17**: メタデータの取得の失敗が、既存の拒否の理由（`not-watch-page`・`collection-failed`・`empty-selection`・`empty-title`）にならない（起動を止めない）（ユニットテスト。失敗した読み取りで、収集が成功して送信に進むことを確かめる）。

#### F-005: 文書

-   README: 拡張が動画タイトル・チャンネル名・概要欄を収集して送ることを反映する。動画ページで起動して送る手順に、概要欄が折りたたまれているときの促しのメッセージ（「…もっと見る」を開いてからポップアップを開き直す）を加える。取得できない値があることを記す。
-   `security.md` §8・§8.1: 拡張が動画ページの DOM から動画タイトル・チャンネル名・概要欄を読むことを反映する。読み取る値は untrusted テキストとして扱い、HTML として解釈せず、本文へは JSON の文字列として入れること。新しい権限を加えないこと（既存の `scripting` の注入で DOM を読むだけで、ページを操作しないこと）。取得に失敗しても起動を失敗させないことを記す。
-   0007・0011・0020 の文書のうち、#170 で決めるとした記述は、それぞれのタスクの記録として残し、変更しない。

**Acceptance Criteria**:
- **AC-18**: 上記の各文書に、上記の内容が記載されている（静的な確認）。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

動画ページの DOM から読む 3 つの値は、記事生成のプロンプトに埋め込まれる untrusted テキストである（`docs/dev/security.md` §6・§8）。

| 境界 | 受理する形 | 上限 | 失敗・拒否時の扱い | 主な AC |
|---|---|---|---|---|
| 注入した読み取りの結果（各値と折りたたみの印） | 受理するメンバーは動画タイトル・チャンネル名・概要欄と折りたたみの印に限る。動画タイトル・チャンネル名・概要欄は、それぞれ文字列または欠落とし、折りたたみの印は真偽値とする。未知または重複するメンバーを含む結果、または形が合わない結果は受理しない（許可するメンバーは閉じた集合であり、拡張可能と宣言しない） | -（形で決まる） | 読み取りの失敗と同じ扱いにし、値を省略する。起動は続行する | AC-01・AC-04・AC-20 |
| 動画タイトル・チャンネル名・概要欄の値 | 動画ページの DOM の文字列（UTF-16）。補正しない | 本文の上限（0020 F-004 の 4 MiB）に含む | 値がない・空白文字のみ・対になっていないサロゲートを含む場合は省略する。起動は続行する | AC-02・AC-07・AC-10 |

-   値を本文へ入れるときは `JSON.stringify` を使い、エスケープを正しく行う。DOM の値を JSON の構文として解釈しない。
-   `JSON.stringify` は、対になっていないサロゲートを `\ud800` などのエスケープにし、サーバはこれを `invalid_body` で拒否する（API の設計書 F-003・AC-13）。任意のメタデータが記事の生成を失敗させないよう、その値は送らずに省略する（F-002）。
-   値は、表示（F-003）でも HTML やほかのマークアップとして解釈せず、テキストとしてのみ表示する。促しのメッセージは固定の文言で、ページの文字列を含めない。
-   本タスクの既存の境界（選択範囲の文字列、タブの URL、タブのタイトル）は、0007・0020 の境界をそのまま使う。変更しない。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)
-   メタデータの読み取りと本文への追加は、送信そのものに比べて無視できる時間で終わればよい。性能のための仕組みは設けない（[CLAUDE.md](../../../CLAUDE.md)「Performance」）。

### 4.2. セキュリティ (Security)
-   **権限:** 新しい権限を加えない。既存の `scripting` の注入（`activeTab` で起動したタブ）で DOM を読むだけとする。新しいホストの権限、`tabs` などの閲覧内容全般に及ぶ権限を加えない。
-   **ページを操作しない:** 概要欄を開くためにページを操作（クリック）しない。起動したタブの DOM を読むだけとする（0007 4.2）。
-   **untrusted テキストの扱い:** 動画タイトル・チャンネル名・概要欄は untrusted な入力である。HTML やほかのマークアップとして解釈せず、`textContent` だけで表示する。本文へは JSON の文字列として入れる。値からコードを実行しない。`eval`・`new Function` を使わない（既存の制約を保つ）。
-   **秘密の扱い:** 共有トークンを、読み取る値、本文、開発者向けのログ、ポップアップの表示、促しのメッセージに出さない（0020 4.2 と同じ）。
-   **プロンプトへの埋め込み:** 3 つの値は記事生成のプロンプトに埋め込まれる。プロンプトインジェクションによって生成記事の内容が操作されうることを前提とする（`security.md` §6）。本タスクは値を渡すだけで、生成結果を実行しない。
-   **既存の制約の維持:** `content_scripts` を宣言しない、利用者が起動するまでページを読まない、Manifest V3 の既定の Content Security Policy を緩めない、実行時に npm の依存パッケージを読み込まない（0007 4.2）。

**Acceptance Criteria**:
- **AC-19**: manifest の権限（ホストの権限を含む）が、0020 の権限から変わらない（新しい権限を加えない）（静的な確認。既存の manifest のガードのテストを変えない）。読み取りは、起動したタブへの既存の注入だけで行い、ページを操作するコードを持たない（静的な確認）。
- **AC-20**: 注入した読み取りの結果が期待する形に合わない場合、または未知もしくは重複するメンバーを含む場合、値をそのまま使わずに省略する（`null`・数値・オブジェクトなどの値、未知のメンバー、重複したメンバーで、起動が失敗しない）（ユニットテスト）。
- **AC-21**: 動画タイトル・チャンネル名・概要欄を `<img src=x onerror=alert(1)>` を含む値にして送ると、本文にはその文字列が文字列として入り、ポップアップの表示では要素にならない（AC-14 と同じ。ユニットテスト）。

### 4.3. 信頼性・可用性 (Reliability/Availability)
-   DOM の構造の変化などによる取得の失敗は、利用者への拒否ではなく、フィールドの省略と開発者向けのログとして扱う。失敗した後も、次の起動は通常どおり動作する（0007 4.3 と同じ）。
-   取得の失敗によって、選択範囲と URL の送信（記事の生成）を止めない。

### 4.4. 互換性 (Compatibility)
-   利用時: macOS 上の Chrome と Brave の、本タスクの作業時点の安定版で動作すること（0007 4.4 と同じ）。セレクタは 0007 §3.12.2 の観測（Chrome 154・Brave 1.96）に基づく。DOM の構造は YouTube が予告なく変えうることを前提とする。
-   API: API の設計書 §3.4 の API（サーバの現在の実装）と組み合わせて動作すること。任意フィールドの欠落を受理する（API の要件書 AC-06）。

### 4.5. 保守性 (Maintainability)
-   メタデータの読み取り（セレクタの知識と、折りたたみの判定）は、ブラウザの API から分離し、ブラウザなしでユニットテストできるようにする。読み取りはテストで fake に置き換えられるようにする（0007 4.5 と同じ）。
-   取得した値の省略の理由（欠落・空白文字のみ・対になっていないサロゲート・読み取りの失敗）と、概要欄が折りたたまれているかは、読み取りの段階で型（列挙・真偽値）として決める。表示・送信・ログは、その型で振る舞いを選び、値の文字列の内容から改めて推し量らない（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」）。省略の判定そのもの（空白文字のみ・対になっていないサロゲート）は、値を受理するかの検査で、既存の `empty-selection` の判定と同じ扱いである。
-   送信のクライアント（本文の形・送信・応答の解釈と表示。0020）を変更しない。値は 0020 が受け取れる任意の 3 フィールドとして渡す（0020 4.5）。
-   収集（0007 の `collect`）の判定・順序・拒否の理由を変更しない。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」に従う。
-   API の設計書 §3.4 と API の要件書 F-002 に従う。サーバ側（Go のコード、API）を変更しない。
-   拡張の実行時に読み込むコードは、本リポジトリで書いたコードだけとする。npm の依存パッケージを実行時に加えない（0007 F-001）。
-   ユニットテストは、実際のブラウザも実際のサーバも起動しない。動画ページの読み取りは fake に置き換える。実際の YouTube の動画ページとの組み合わせは手動で確認する。
-   動画ページの HTML 全体のスナップショットは、リポジトリに保存しない（`security.md` §7）。必要なら、リポジトリの外の `${YT2COLUMN_SNAPSHOT_DIR:-...}` にあるスナップショットを使う。

## 6. 用語集 (Glossary)

-   **API の設計書**: `docs/tasks/0011_localhost_server/02_architecture.md`。「API の設計書 §N」はその節を指す。
-   **API の要件書**: `docs/tasks/0011_localhost_server/01_requirements.md`。「API の要件書 F-NNN」「AC-NN」はその項番を指す。
-   **0007**: ブラウザ拡張の骨格のタスク（`docs/tasks/0007_browser_extension_skeleton/`）。「0007 F-NNN」はその要件書の項番、「0007 §N」はその設計書の節を指す。
-   **0020**: ブラウザ拡張からサーバへの送信のタスク（`docs/tasks/0020_extension_send/`）。「0020 F-NNN」「AC-NN」はそれを指す。
-   **動画タイトル**: 動画ページの DOM（`ytd-watch-metadata`）から取る、動画のタイトル。API の `title` に入る。タブのタイトルとは別。
-   **タブのタイトル**: ブラウザのタブのタイトル。`"<動画タイトル> - YouTube"` などになる。既存の収集の確認（0007 F-005 の `empty-title`）にだけ使い、本文には入れない。
-   **チャンネル名**: 動画ページの DOM（`ytd-channel-name`）から取る、動画を投稿したチャンネルの名前。API の `channelName` に入る。
-   **概要欄**: 動画ページの DOM（`ytd-text-inline-expander`）から取る、動画の説明。開かれていれば全文、折りたたまれていれば冒頭のみ。API の `description` に入る。
-   **促しのメッセージ**: 概要欄が折りたたまれているときに、ポップアップに表示する固定の文言。「…もっと見る」を開いてからポップアップを開き直す手順を示す。
-   **送信のクライアント**: 本文の組み立て、送信、応答の解釈を行う部分（0020 F-002・F-003・F-006・F-007）。本タスクはこれを変更しない。
-   **メタデータ**: 動画タイトル・チャンネル名・概要欄の 3 つ。API の任意フィールドの値。
-   用語は [translation_glossary.md](../../translation_glossary.md) と統一する。
