## 1. 概要 (Overview)

**目的:** 本書は、README の「ブラウザ拡張」節にある表示の言語の段落を、拡張の今の振る舞いに合わせるための要件を定義する（[#719](https://github.com/isseis/yt2column/issues/719)）。今の段落はポップアップの表示の言語しか述べていないが、拡張はビューアの文言も同じ規則で選んだ言語で表示している。

**背景:**

`README.md` の「ブラウザ拡張」節（`README.md:526` から）の表示の言語の段落（`README.md:574-575`）は、次の 3 文からなる。

1.  ポップアップは、ブラウザの UI の言語が日本語のときは日本語で、それ以外のときは英語で表示する。
2.  拡張に言語の設定はない。
3.  この README が引用するポップアップの文言（概要欄が折りたたまれているときのメッセージなど）は日本語の版である。

issue は 3 つ目の文を「段落の 2 文目」と呼んでいるが、指しているのは同じ文である。英語版の `README.en.md:786-789` も同じ内容で、3 文目は「英語の版である」となっている。どちらの版も、ビューアの表示の言語には触れていない。

一方、今のコードでは、ビューアもポップアップと同じ規則で表示の言語を選ぶ。

-   ビューアの入口は、ブラウザの UI の言語を読む（`extension/src/viewer.ts:19`）。
-   ビューアは、ポップアップと同じ `resolveLocale` で言語を決め、ページの `lang` をその言語にする（`extension/src/viewerApp.ts:178-179`）。ポップアップの同じ処理は `extension/src/launch.ts:681-682` にある。
-   `resolveLocale` は、UI の言語の最初の `-` より前の部分を小文字にして、それが `ja` のときだけ日本語を選ぶ。それ以外の値は、値がない場合も含めて英語になる（`extension/src/core/i18n/locale.ts:28-35`）。
-   ビューアの文言は、ポップアップと共通のメッセージカタログ（英語と日本語の 2 つ。`extension/src/core/i18n/catalog.ts:148`）から、選んだ言語の文言を取る（`extension/src/ui/renderJob.ts:51`・`:109`）。

ただし、選んだ言語に切り替わるのは画面の文言である。ビューアの記事の本文は、UI の言語によらず `lang="ja"` を持つ。これは記事の内容の言語であり、UI の表示の言語ではない（`docs/tasks/0063_viewer_markdown/01_requirements.md`「要件定義の際に決めたこと（2026-11-05）」）。

ビューアを 2 言語にしたのはタスク 0050 である（`docs/tasks/0050_viewer_tab/01_requirements.md` の「issue #503 で決めたこと」の「多言語（#506 の決定）」と AC-49）。段落のもとの英語の文は、ビューアがまだなかったタスク 0043 で書かれた（#529）。その後、タスク 0048 で、日本語の `README.md` を正とする形に移った（#586）。ビューアを加えたときに、この段落は直されなかった。

README は、ポップアップの文言だけでなく、ビューアの文言も太字で引用している。「ブラウザ拡張」節の中では、たとえば **記事が失われた**（`README.md:609`・`:632`）と **Slack に投稿する**（`README.md:628`）である。節の外にも、「Webhook への投稿」節の **Slack に投稿する**（`README.md:189`）と、「サーバの停止」節の **記事が失われた**（`README.md:245`）がある。ビューアの投稿・保存・コピーの名前は、拡張の node のテストがカタログと照合している（`extension/test/metadataDocs.test.ts:58-60`）。3 文目は README 全体の引用について述べる文なので、ポップアップの文言だけを挙げていると、これらのビューアの引用がどちらの言語の版なのかが README に書かれないことになる。

タスク 0065 は、拡張の UI の言語の ADR として [ADR-0029](../../dev/adr/0029-extension-ui-languages.md) を書き、#722 で `main` に入れた。その「決定」の最後の項目（`docs/dev/adr/0029-extension-ui-languages.md:24`）は、README の段落がポップアップの言語だけを述べていて、ビューアに触れていないことを本 issue で扱う、と記す（以下、この記述を「ずれの記述」と呼ぶ。6 章も参照）。README を直すと、ずれの記述は事実でなくなる。

**軽量プロセスを取らない理由:** 変更量は軽量プロセスの上限に収まる見込みである。ただし、この変更は、README の記述にビューアの事実を加えて文の意味を変え、利用者に見える文言も誤字の修正を超えて変える。この 2 点は、どちらも「常に通常プロセスになる変更」に当たる（`docs/dev/conventions/requirements_process.md`「Changes that always take the normal process」）。

対応 issue: [#719](https://github.com/isseis/yt2column/issues/719)（関連: [ADR-0029](../../dev/adr/0029-extension-ui-languages.md)）

**本書の記述範囲:** 本書は、直した後の段落が述べる内容、英語版への写し、ADR のずれの記述の扱いを定める。段落の正確な文面は、実装で決める。英語版の文面は `/mktrans` が決める。

**issue #719 で決めたこと:**

-   **直す対象:** README の「ブラウザ拡張」節の表示の言語の段落が、ビューアの表示の言語に触れていないこと。直し方は、issue では未決の案として挙がっている。

**要件定義の際に決めたこと（2026-11-09）:**

-   **直す箇所:** `README.md` の段落を、ポップアップとビューアの両方に触れる形に改め、`/mktrans README.md` で `README.en.md` に写す（F-001・F-002）。issue が案として挙げた方向である。日本語を正とし、英語版は `/mktrans` で写すのが README の規則でもある（`CLAUDE.md`「Translation Guidelines」）。ADR：なし。README の 1 段落の直しで、このタスクの中で閉じるので、`CLAUDE.md`「Design decisions (ADR)」の基準で major ではない。
-   **3 文目をビューアにも広げる:** 「この README が引用する文言は日本語の版である」という 3 文目を、ポップアップとビューアの両方の文言に当てはめる（F-001）。README はビューアの文言も引用しているので、3 文目がポップアップに限られていると、ビューアの引用がどの版なのかを読み手が判断できないからである。ADR：なし。README の 1 文の範囲の決定で、このタスクの中で閉じるので、major ではない。
-   **記事の本文の言語には触れない:** 段落が述べるのは、ポップアップとビューアの文言が選んだ言語で表示されることである。記事の本文の言語（いつも `ja`）に段落で触れることは、スコープ外にする（2.3）。issue が求めているのは、画面の文言の言語についての記述をコードに合わせることだからである。ADR：なし。README の記述の範囲の決定で、このタスクの中で閉じるので、major ではない。
-   **ADR のずれの記述は、本タスクの実装の PR が消す（ADR の規約の例外）:** README の段落を直す実装の PR が、同じ PR で、ADR-0029 の「決定」の最後の項目を 1 文目（「表示の言語の決まり方を利用者に説明するのは README の「ブラウザ拡張」節の段落である。」）だけにし、ずれの記述の 3 文を消す（F-003）。
    -   **例外とする規約:** ADR の規約は、ADR の決定を作るか変える PR 以外は、ADR を追加も変更もしないと定める（`docs/dev/conventions/adr.md:214-218`「Approval and the PR」）。この削除は、事実でなくなった記述を消す編集上の修正で、ADR の決定を変えない。それでも、決定を作りも変えもしない本タスクの PR が ADR を変えるので、規約の例外になる。
    -   **理由:** ADR-0029 を書いたタスク 0065 の側では消せないからである。0065 の最後の PR（[#727](https://github.com/isseis/yt2column/pull/727)）は、マージされるまで ADR-0029 の「決定」が #719 にリンクしていることを確かめる 1 回限りの検査を実行するので、その PR では消せない。また、0065 には #727 の後に PR が残らない。README を直す PR と同じ PR で消せば、ずれの記述が事実でない期間が生じない。
    -   **範囲:** ADR-0029 の、ずれの記述の 3 文の削除だけに限る。ADR-0029 のほかの記述と、ほかの ADR は変えない。決定を変えないので、経緯の項目は足さない。
    -   **順序の条件:** #727 がマージされる前には、ADR-0029 の削除をマージしない。実装の PR が #727 より先にマージされそうなときは、ADR の削除を PR から外し、利用者に確かめる。
    -   この決定は、タスク 0065 からの申し送り（2026-11-09）を受けて、当初の「ADR に触れず、0065 が消す」決定を改めたものである。当初の決定は、issue #713 と ADR-0020 の扱い（`docs/tasks/0068_strictjson_package_reference/01_requirements.md:44`）にならっていた。
    -   ADR の判断：ADR は作らず、変えない（ずれの記述の削除は決定の変更ではない）。規約の例外は、本タスクの 1 回の削除に限るもので、規約そのものを変えないので、`CLAUDE.md`「Design decisions (ADR)」の基準で major ではない。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   README の読み手が、ポップアップとビューアの文言が、ブラウザの UI の言語に合わせて日本語か英語で表示されることを、README から知ることができる。
-   README が引用するポップアップとビューアの文言が、どちらの言語の版なのかが README に書かれている。

### 2.2. スコープ (In Scope)

-   `README.md` の「ブラウザ拡張」節の、表示の言語の段落（F-001）。
-   その変更の `README.en.md` への写し（F-002）。
-   ADR-0029 のずれの記述の削除（F-003）。

### 2.3. スコープ外 (Out of Scope)

-   拡張のコードとメッセージカタログ。表示の言語の振る舞いは変えない。issue が求めているのは、README の記述をコードに合わせることだからである。
-   記事の本文の言語（いつも `ja`）を段落に書き足すこと。1 章の「要件定義の際に決めたこと」のとおりである。
-   数と日時の書式（`Intl.NumberFormat` と `Intl.DateTimeFormat` を、選んだ言語で使うこと）を README に書き足すこと。issue が求めていないからである。
-   表示の言語の段落の外にある README の記述。issue が挙げているのはこの段落だけだからである。
-   ADR-0029 の、ずれの記述の外にある記述と、ほかの ADR の編集。1 章の「要件定義の際に決めたこと」の例外の範囲の外だからである。
-   表示の言語を確かめる新しい文書のテスト。段落の文の意味は PR のレビューで読んで確かめる、というのが文書のテストの方針だからである（`CLAUDE.md`「Testing Strategy」の「Document tests check values, structure, and executable examples, never prose.」、[ADR-0016](../../dev/adr/0016-document-test-policy.md)）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: `README.md` の表示の言語の段落

`README.md` の「ブラウザ拡張」節の表示の言語の段落を、ポップアップとビューアの両方に触れる形に改める。

**Acceptance Criteria**:
- **AC-01**: 段落は、ポップアップとビューアの文言が、ブラウザの UI の言語が日本語のときは日本語で、それ以外のときは英語で表示されることを述べる。段落は、記事の本文が選んだ言語で表示されるとは述べない。
- **AC-02**: 段落は、拡張に言語の設定がないことを、今と同じく述べる。
- **AC-03**: 段落は、この README が引用するポップアップとビューアの文言が日本語の版であることを述べる。
- **AC-04**: 変更前と比べて、`README.md` の変更は表示の言語の段落の中だけにある。

#### F-002: `README.en.md` への写し

F-001 の変更を `/mktrans README.md` で `README.en.md` に写す。

**Acceptance Criteria**:
- **AC-05**: `README.en.md` の「Browser extension」節の対応する段落は、AC-01 と AC-02 の内容を英語で述べ、この README が引用するポップアップとビューアの文言が英語の版であることを述べる。
- **AC-06**: `README.en.md` の 1 行目の同期の目印は、変更後の `README.md` を指し、`make readme-sync-check` が通る。
- **AC-07**: 変更前と比べて、`README.en.md` の変更は、1 行目の同期の目印と、表示の言語の段落の中だけにある。

#### F-003: ADR-0029 のずれの記述の削除

README の段落を直す実装の PR が、同じ PR で、ADR-0029 のずれの記述を消す（1 章の「要件定義の際に決めたこと」の、ADR の規約の例外）。

**Acceptance Criteria**:
- **AC-08**: 実装の PR の後の ADR-0029 の「決定」の最後の項目は、1 文目の「**表示の言語の決まり方を利用者に説明するのは [README.md](../../../README.md) の「ブラウザ拡張」節の段落である。**」だけからなる。その後にあった、段落がポップアップの言語だけを述べ、ビューアに触れていないことを #719 で扱うとする 3 文はない。
- **AC-09**: 変更前と比べて、実装の PR の `docs/dev/adr/` の下の変更は、AC-08 の 3 文の削除だけにある。経緯の項目は足さない。
- **AC-10**: 実装の PR の、ADR-0029 を変えるコミットのメッセージと PR の説明は、この削除を編集上の修正として、決定を変えないことと合わせて記す（`docs/dev/conventions/requirements_process.md`「Recording in the PR description」の形）。
- **AC-11**: ADR-0029 の削除を含む実装の PR は、[#727](https://github.com/isseis/yt2column/pull/727) がマージされた後にだけマージされる。

#### F-004: 既存の検査

**Acceptance Criteria**:
- **AC-12**: 変更後に `make test` と `make ext-test` が通る。どちらも README を読む既存の文書のテストを含む（`CLAUDE.md`「Development Notes」）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   README の「ブラウザ拡張」節は拡張の node のテストが読むので、変更の後に `make ext-test` を実行する（`CLAUDE.md`「Development Notes」）。
-   ADR は、その決定を作るか変える PR だけが変える（`docs/dev/conventions/adr.md`「Approval and the PR」）。本タスクの例外は、1 章の「要件定義の際に決めたこと」の F-003 の削除に限る。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。
-   **ビューア**（viewer）: 記事の状態と記事を表示する拡張のページ（`viewer.html`）。用語集の定義に従う。
-   **ポップアップ**（popup）: 拡張のツールバーのアイコンをクリックして開く画面。
-   **表示の言語**: 拡張が画面の文言を表示する言語。ブラウザの UI の言語から、日本語か英語のどちらかに決まる。記事の本文の言語ではない。
-   **ずれの記述**: ADR-0029 の「決定」にある、README の段落がビューアに触れていないことの記述。タスク 0065 の要件定義書 AC-03 は、同じものを「食い違い」と呼ぶ。
