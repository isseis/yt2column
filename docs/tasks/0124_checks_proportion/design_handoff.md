# 設計への申し送り（タスク 0124）

`/mkreq` の作成時に出た、設計で決める事項である。`02_architecture.md` は、各項目について採る方針か、当てはまらない理由を記録する。

## H-01: 規約の中の置き場所と、`diff` の確かめの「Proportion」との関係

**内容:** 一時スクリプトの定義・比例原則・設計水準・テストの基準（F-001〜F-003）を、`requirements_process.md` のどこに置くかを決める。§4 の「`diff` verification」の下には「Proportion」の項目がある（`requirements_process.md:838`）。新しい基準と、その項目をどう関係づけるかも決める。候補は 2 つある。

-   §4 に `_checks/` の一時スクリプト全般の小節を設け、「Proportion」をそこへの参照にする。
-   「Proportion」を残し、新しい小節から参照する。

**理由:** 基準の正本を 1 か所に置かないと、2 つの記述が食い違う（4.5 節）。

**関係する ID:** F-001、F-002、F-003、AC-01〜AC-08。

## H-02: チェックリストの既存の `diff` の確かめの項目との統合

**内容:** 過大な `diff` の確かめを指摘する既存の項目がある（`mkplan.md:164`、`runplan.md:226`、`_lib/high-review.md:647-654`）。新しい項目（AC-09）を、これらに統合して一時スクリプト全般に広げるか、別の項目として足すかを決める。統合する場合は、既存の項目の適用の範囲の文（「この項目が `main` に入る前に承認された計画には当てはめない」）が、0080 で足した部分と本タスクで足す部分の両方に正しく効くようにする（AC-12）。各チェックリストが規約の正本を参照する形も決める。

**理由:** 似た項目が 2 つ並ぶと、レビュアーが片方だけを見る。統合すると、既存の部分の適用の範囲が変わりうる。

**関係する ID:** F-004、F-005、AC-09、AC-12。

## H-03: 文書を読む既存の guard への影響

**内容:** 変更するコマンドの定義と規約を読む既存の Go の guard（`cmd/yt2column`・`cmd/fixprguard`・`internal/chief` などの文書のテスト）があるかを調べる。見出しや表の構造を変えて落ちるものがあれば、その扱いを決める。

**理由:** 文書だけの変更でも `doc-guard` の CI ジョブが guard を実行するため、見出しの変更で guard が落ちうる。

**関係する ID:** F-001〜F-004。

## H-04: `CLAUDE.md` と `dev_tools.md` との整合

**内容:** `CLAUDE.md`「Testing Strategy」は、`_checks/` を `diff` の確かめの置き場所として述べている。`docs/dev/conventions/dev_tools.md` は、開発ツールを `cmd/` と `internal/` の組と定める。一時スクリプトの定義（AC-01）と食い違う記述や、追記の要る記述がないかを確かめる。要るなら、変える場所を決める。`CLAUDE.md` の規則の写しを変えるときは、正本を先に変える。

**理由:** 一時スクリプトと常設のツールの区別が、文書の間で食い違わないようにするためである。

**関係する ID:** F-001、AC-01。

## H-05: `/weakreview` など、チェックリストを共有するコマンドへの波及

**内容:** `_lib/high-review.md` のチェックリストは `/weakreview` も使う。AC-09 の項目が、`/weakreview` の実行（承認済みの計画がない範囲を見る場合を含む）でも意味をなすかを確かめる。適用の範囲の文（AC-12）が、計画のない範囲でどう読まれるかも決める。

**理由:** 共有のチェックリストに足した項目は、呼び出すすべてのコマンドに効くためである。

**関係する ID:** F-004、F-005、AC-09、AC-12。
