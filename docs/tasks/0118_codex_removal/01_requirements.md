## 1. 概要 (Overview)

**目的:** 本書は、Codex の PR レビュー（GitHub の連携）と Codex CLI をレビューの体制から外し、Codex なしで PR が回るようにするための要件を定義する。

対応 issue: [#1059](https://github.com/isseis/yt2column/issues/1059)（関連: [#1057](https://github.com/isseis/yt2column/issues/1057)）

**背景:**

利用者は Codex の契約を終えることにした。今のレビューの体制は、次の 2 か所で Codex に依存している（[ADR-0013](../../dev/adr/0013-review-setup.md)）。

-   **Codex の PR レビュー:**
    -   **開いたときの依頼:** PR を開くコマンドは、Codex の自動レビューが始まらなければ `@codex review` で 1 回だけ依頼する（`.claude/commands/_lib/task-pr-handoff.md:301`）。
    -   **`/runpr` の待機:** `/runpr` の step 3 は、Codex の要約コメントが PR をレビューし終えるまで待つ（`.claude/commands/runpr.md:392`、`runpr.md:401`）。要約コメントが結果のない完了を示したときは、受領コメントで利用者に確かめる（用語は 6 節。`docs/tasks/0108_codex_null_findings_receipt/01_requirements.md`）。
    -   **追加の依頼:** 最後の PR レビューの後の変更が基準に当たれば、PR レビューを自動でもう一度頼む（`.claude/commands/_lib/pr-review-escalation.md:34`）。以下、この判定をエスカレーションと呼ぶ。マージの質問は「先に PR レビューを依頼」を選択肢に持つ（`runpr.md:1412`）。
-   **Codex CLI:** ローカルの CLI レビューは、CodeRabbit CLI が失敗したときに `codexreview` を通して Codex CLI を走らせる（`.claude/commands/_lib/local-cli-review.md:155`）。両方が失敗すると `Local CLI review: not run` を記録して進む（`local-cli-review.md:287`）。

判断の材料は #1057 の集計にある。47 件の PR（#984〜#1054）で、Codex の PR レビューのインラインの指摘は計 4 件だった。そのうち 1 件は誤読として退けたので、本物は 3 件（#1033、#1040、#1054）である。指摘の大半は、PR を開く前の Fable の部分レビュー（[ADR-0050](../../dev/adr/0050-fable-partial-review.md)）が出している。

CodeRabbit の PR レビューについて、分かっていることは次のとおりである。

-   **自動レビュー:** 今は `.coderabbit.yaml` で止めている（`.coderabbit.yaml:9-14`）。以前は割り当てを頻繁に使い切り、機能していなかった（`docs/tasks/0031_codex_pr_review/01_requirements.md` の 1 節）。
-   **0031 より前の判定:** `StatusContext` の `CodeRabbit` が `SUCCESS` であることと、本文の「between `<sha>` and `<headRefOid>`.」の行がそろったときに、レビュー済みとしていた（同上）。
-   **最近の例:** PR #852（2026-11-11）の CodeRabbit の PR レビューの記録が、chief のテストのサンプルにある（`internal/chief/testdata/gh/pr-view-852-reviews.json`）。その記録では、本文に「between」の行が残り、割り当てを「1 時間に 1 回」と示している。指摘をスレッドにせず本文だけに書いたもの、大きすぎてレビューしなかったファイルの知らせ、PR の説明への要約の書き込み、指摘を直す commit を求める選択肢もある。

**本書の記述範囲:** 本書は、観測できる振る舞いを定める。いつ誰に PR レビューを頼むか、`/runpr` が何を待ち何を読むか、CodeRabbit CLI が失敗したときにどう進むか、どのメンションを拒否するか、何を撤去するか、である。次の事項は設計（`02_architecture.md`）で決める。設計は、F-001 の観測の記録がそろってから始める。

-   CodeRabbit の PR レビューの完了を判定する具体的な方法（どの API のどの値を見るか）と、待つ時間の上限。
-   コマンドの文書・道具・ガードテストのどこをどう変えるか、どの PR に分けるか（4.4 の順序の制約の中で）。

要件の起草とレビューで挙がった設計の事項は、[design_handoff.md](design_handoff.md) に申し送る。

**issue #1059 で決めたこと:**

-   **Codex の PR レビューと Codex CLI の両方を外す:** 契約を終えるためである。
-   **順序:** このタスクの変更を入れてから、利用者が GitHub の連携を切り、契約を終える。このタスク自身の PR は、Codex の PR レビューが動いている間の `/runpr` で回す。先に連携を切ると、今の `/runpr` の step 3 が依頼の投稿と待機を繰り返すためである。連携を切る時点は、下の「要件定義の際に決めたこと」で改めた。
-   **`docs/tasks/` は変えない:** タスク文書は、各タスクが何を決めたかの記録だからである。

**要件定義の際に決めたこと（2026-11-20）:**

-   **プロセスは `full` にする:** 簡易プロセスの除外に当たると判断したため、推奨は `full` で、利用者もそれを選んだ。このタスクは、開発用の道具の信頼の境界を変える（レビューの関門、`fixprguard` のメンションの拒否、自動レビュアーの一覧）。ほかにも、10 を超えるコマンドと道具に及び、既存の ADR の決定を変える。
-   **PR レビューは、利用者が選んだときだけ CodeRabbit に手動で頼む（F-002〜F-004）:** PR を開いたときにも、`/runpr` の中でも、自動では頼まない。マージの質問で利用者が「先に PR レビューを依頼」を選んだときだけ、`@coderabbitai review` で頼む。推奨は外部の PR レビューをなくすことだったが、利用者は、信頼の境界を変える PR などで外部の目を足す手段を残すことを選んだ。CodeRabbit の自動レビューを有効に戻す案は採らない。割り当てを頻繁に使い切って機能しなかった実績があるためである。ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する。
-   **CodeRabbit の振る舞いは、設計の前に観測する（F-001）:** 0031 より前の判定（`StatusContext` と「between」の行）を、観測せずにそのまま使う案は採らない。利用者は、割り当てを使い切っても CheckRun が `pass` になるのを PR #404 で見ている（リポジトリに記録はなく、F-001 で確かめる）。0031 の観測の記録も 1 か月前のものである。そのため、形が変わっていれば `/runpr` が止まるか、誤ってレビュー済みとしうるためである。ADR の判断: ADR なし。観測は判断の材料で、決定そのものではないためである。
-   **書き込み権限のない人の `@coderabbitai` は観測せず、interaction limits に頼る:** 推奨に従って利用者が選んだ。今の interaction limits の確かめ（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）が、書き込み権限のない人のコメントを止めているためである。観測するには制限を一時的に外す必要がある。ADR の判断: ADR なし。今の決定（ADR-0015）を変えないためである。
-   **エスカレーションは、勧めるだけにする（F-005）:** 判定は残し、当たれば、マージの質問で「先に PR レビューを依頼」を推奨にする。自分では依頼しない。範囲は、最後に完了した手動の PR レビューの後とし、それがなければ PR の全体とする。PR レビューを手動に限る決定に合わせつつ、信頼の境界を変える PR で利用者の目を引くためである。撤去する案は採らない。どの PR でもレビューを推奨しなくなり、判断の材料が減るためである。ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) と [ADR-0047](../../dev/adr/0047-runpr-merge-question.md) を更新する。ADR-0047 は、エスカレーションの判定が `ask` のときだけ「先に PR レビューを依頼」を推奨にすると決めている。今回は、信頼の境界の基準に当たるとき（今は自動で依頼する）にも推奨にするので、その決定が変わる。
-   **CodeRabbit CLI が失敗したら `not run` を記録して進む（F-006）:** 代わりのレビューは置かない。今も両方の CLI が失敗したときはこの形なので、新しい仕組みが要らないためである。見ていない範囲は、今と同じく PR の説明とマージの質問に出る。Opus のサブエージェントを代わりに置く案は採らない。#1057 の Opus への置き換えと重なるためである。止めて利用者に聞く案も採らない。人を待たせずに進め、見ていない範囲を PR の説明とマージの質問で示せば足りるためである。ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する。
-   **Fable が走らない PR の危険は受け入れる:** OpenCode で実装した PR と単独の PR では、外部のレビューが CodeRabbit CLI だけになる（CLI が失敗すればなくなる）。#1057 の集計では、Codex の本物の指摘 3 件のうち 2 件がこの種類の PR だった。それでも、補う仕組みは #1057 の並走の結果を見てから、別のタスクで決めたほうが手戻りが少ない。そのため、この危険を受け入れて記録する。ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) の「受け入れた危険」に加える。
-   **Fable の部分レビューは PR を開く前に続け、理由を改める:** [ADR-0050](../../dev/adr/0050-fable-partial-review.md) は、PR を開く前に行う理由を「Codex の最初の PR レビューが修正を見るため」としている。この理由はなくなる。新しい理由は、PR を開く前に直せば、直しがローカルの CLI レビューを通り、人のレビューは直した後の PR から始まること、とする。記録の後に `origin/main` を merge したときの意味の衝突は、今は「CHECKS と Codex の PR レビュー」に任せている。これを CHECKS だけに任せる危険として受け入れる。推奨に従って利用者が選んだ。ADR の判断: [ADR-0050](../../dev/adr/0050-fable-partial-review.md) を更新する。
-   **PR を開く前に、まだ見ていない commit をまとめてローカルの CLI レビューにかける（F-007）:** 最後のローカルの CLI レビューより後にできた commit は、今は「最初の Codex の PR レビューが見る」ことを理由に、かけ直していない。Opus のレビューの直し（[ADR-0042](../../dev/adr/0042-implementation-model-tiers.md)）、`/runplan` の green gate と終わりの確かめの直し（`runplan.md` の「Before the PR」）、`_lib/task-pr-handoff.md` Part B step 2 の CHECKS の直し、0114 の Fable の記録の後の commit（`docs/tasks/0114_fable_record_after_merge/01_requirements.md`）がそれに当たる。この理由はなくなり、かけないと、これらを Claude 以外の系統のレビューが一度も見ないことになる。そのため、PR を開く前に、どのローカルの CLI レビューも見ていない commit を、まとめてもう 1 回かける。最初の案は Opus の直しだけだったが、Fable の部分レビューの指摘を受けて利用者が広げた（推奨どおり）。CodeRabbit CLI の割り当ては PR レビューとは別で（[0031 要件定義書](../0031_codex_pr_review/01_requirements.md) の「issue #403 で決めたこと」）、増えるのは 1 PR に多くて 1 回である。ADR の判断: [ADR-0042](../../dev/adr/0042-implementation-model-tiers.md) と [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する。
-   **`@codex` と `@coderabbitai` の両方を拒否する（F-009）:** 利用者のアカウントからの投稿には、依頼の文面のほかは、どちらのメンションも含めない。推奨は `@coderabbitai` に移すことだったが、利用者は両方を選んだ。連携を切った後に `@codex` が何かを動かすことはないと見込めるが、拒否を残しても費用はほとんどないためである。CodeRabbit も、利用者のアカウントからのメンションに応じて動く（`@coderabbitai review` で PR レビューを始めるのがその例である）。`/runpr` が確かめる利用者以外のメンションも両方を対象にし、interaction limits の確かめも残す。ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する。
-   **信頼する自動レビュアーの一覧から `chatgpt-codex-connector` を外す（F-010）:** 連携を切った後は Codex のスレッドはできないので、使っていない Bot を信頼したままにしないためである。ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する（上の項目と同じ更新）。
-   **連携を切る時点を、F-002・F-003 を入れる PR のマージの直後にする（4.4）:** issue では、このタスクの最後の PR がマージされてから切るとしていた。その理由は、先に切ると今の `/runpr` の step 3 が待ち続けることで、F-003 が入れば成り立たない。最後の PR まで待つと、その間に F-009・F-010 が入った後の PR では、Codex のスレッドが想定外の著者のスレッドとして、Codex の投稿の `@codex` がメンションとして、毎回利用者への確認の対象になる。そのため、F-009・F-010 は F-002・F-003 と同じ PR か、それより後の PR に入れる。推奨に従って利用者が選んだ。ADR の判断: ADR なし。このタスクの中の作業の順序であるためである。
-   **`codexreview` は、プロトコル番号ごと撤去する（F-008）:** Codex CLI を走らせる道具なので、Codex CLI を外せば要らなくなる。番号を持つ道具は `fixprguard`・`chief`・`mergepr` の 3 つになる。ほかの道具の番号を上げるかは、`CLAUDE.md` の「Protocol numbers」の規則に従って設計で決める（[design_handoff.md](design_handoff.md) の H-03）。ADR の判断: [ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md) を更新する。
-   **chief の読み取りのサンプルは残す（F-012）:** chief の製品のコードは Codex の文言で分岐しない（`git grep -il codex internal/chief` が当たるのは `_test.go` と `testdata/` だけである）。サンプルは実際の画面の記録である。`/runpr` の報告の形が変わって読み取りの形が変わるときだけ、新しいサンプルを足す。ADR の判断: ADR なし。このタスクの中で閉じるためである。
-   **Codex のために足した `/runpr` の仕組みは撤去する（F-003）:** 要約コメントの待機、受領コメント（0108）による利用者の確認がそれに当たる。Codex にしかない形の仕組みなので、PR レビューを CodeRabbit に移すと要らなくなるためである。ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（上の PR レビューの項目と同じ更新）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   Codex の GitHub の連携を切り、Codex CLI がなくなっても、タスクの PR と単独の PR を、作成からマージまで回せる。
-   PR を開いた後の外部のレビューを、利用者が選んだときだけ CodeRabbit に頼める。
-   Codex への依存を、コマンドの定義・道具・設定・現在の仕様を書く文書から除く。

### 2.2. スコープ (In Scope)

-   CodeRabbit の PR レビューの観測（F-001）。
-   PR を開くコマンドと `/runpr` から、Codex の PR レビューの依頼・待機・判定を除くこと（F-002、F-003）。
-   マージの質問から CodeRabbit の PR レビューを手動で頼み、完了を待つこと（F-004）。
-   エスカレーションを、勧めるだけにすること（F-005）。
-   ローカルの CLI レビューから Codex CLI を除くこと（F-006）。
-   PR を開く前に、まだ見ていない commit をローカルの CLI レビューにかけること（F-007）。
-   `codexreview` の撤去（F-008）。
-   メンションの拒否と、利用者以外のメンションの確かめを、2 つのメンションに広げること（F-009）。
-   信頼する自動レビュアーの一覧と、完了を待つ PR レビュアーの変更（F-010）。
-   現在の仕様を書く文書と ADR の更新（F-011）。
-   chief の読み取りの扱い（F-012）。

### 2.3. スコープ外 (Out of Scope)

-   **GitHub の連携を切ることと、Codex の契約を終えること:** リポジトリの外で、利用者が行う。時点は 4.4 で定める。
-   **`docs/tasks/` の文書:** 各タスクの記録なので変えない（issue #1059 で決めたこと）。
-   **Fable が走らない PR を補う仕組み:** 受け入れる危険として記録する（要件定義の際に決めたこと）。補うかは、#1057 の並走の後に別のタスクで決める。
-   **#1057 の Fable から Opus への置き換え:** 別のタスクで行う。並走期間は、このタスクの後に始める。
-   **CodeRabbit の自動の PR レビュー:** 有効に戻さない（要件定義の際に決めたこと）。
-   **書き込み権限のない人の `@coderabbitai` の観測:** interaction limits に頼る（要件定義の際に決めたこと）。
-   **`docs/research/` の記録:** 調べた時点の記録なので変えない。
-   **`AGENTS.md`:** 変えない。その `## Code Review Rules` の節は Codex が読むものとして置いた（`docs/tasks/0031_codex_pr_review/observations.md` の項目 6）が、中身はこのリポジトリのレビューの規則で、ほかの自動のエージェントへの指示として残しても害がないためである。CodeRabbit が読むかは F-001 で確かめる（AC-01 の 11）。読まないと分かったときの扱いは設計で決める（[design_handoff.md](design_handoff.md) の H-09）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 用語

-   **PR レビュー:** GitHub の PR の上で、自動レビュアーが PR に対して行うレビュー（[ADR-0013](../../dev/adr/0013-review-setup.md) の「背景」）。
-   **ローカルの CLI レビュー:** PR のブランチの手元で、CLI で行うレビュー（`.claude/commands/_lib/local-cli-review.md`）。このタスクの後は CodeRabbit CLI だけを使う。
-   **手動の PR レビュー:** 依頼のコメントで始まる CodeRabbit の PR レビュー。依頼のコメントは、利用者のアカウントが書いた、本文が `_context.md` の「PR review request」の値（AC-46）とちょうど等しいコメントである。`/runpr` が F-004 で投稿したものも、利用者が手で書いたものも含む。依頼のコメントなしに始まった CodeRabbit のレビュー（Web から頼んだものなど）は手動の PR レビューではない。その投稿は AC-41 の Bot の投稿として、そのスレッドは AC-10 のとおり扱い、その完了の印は数えない。
-   **完了の印:** 手動の PR レビューが、あるコミットまでのレビューを終えたことを示す、CodeRabbit の投稿の値。どの値を使うかは F-001 の観測の後に設計で決める。
-   **応答を待つ依頼のコメント:** 依頼のコメントのうち、次のどれもまだ起きていないもの。(1) その後に投稿された、PR の head かその祖先を示す完了の印が届く。(2) その後に、割り当てやエラーの知らせ（AC-18）が届く。(3) 待つ時間の上限が過ぎる。
-   **割り当て:** 用語集の定義のとおり、自動レビュアーが一定時間に受け付けるレビューの回数の上限。
-   **メンションの対象:** GitHub のメンションのうち、`@codex` と `@coderabbitai` の 2 つ（F-009）。用語集の「メンション」（Mattermost の通知）とは別のものである。
-   **現在の仕様を書く文書:** `CLAUDE.md`、`.claude/commands/` の下のコマンドの定義（`_context.md` と `_lib/` を含む）、`docs/dev/` の下の文書（ADR を含む）、`docs/translation_glossary.md`、設定ファイル（`.coderabbit.yaml`、`.claude/settings.json`、`Makefile`、`.github/workflows/`）。`docs/tasks/` と `docs/research/` は含まない。

### 3.2. 機能一覧

#### F-001: CodeRabbit の PR レビューの観測

設計の前に、試験の PR で CodeRabbit の PR レビューの振る舞いを観測し、記録する。

**Acceptance Criteria**:
- **AC-01**: 観測の記録がある。記録は、次の各項目について、観測した日付、PR の番号、観測した値（API の応答の該当する欄）を持つ。観測できなかった項目は、そのことと、代わりに CodeRabbit の公式の文書から分かることを出典とともに記録する。
    1. 依頼のコメントから、レビューが終わるまでに CodeRabbit が投稿・変更するもの（コメント、レビュー、スレッド、`StatusContext` や CheckRun、PR の説明の書き込み）と、その順序。
    2. 完了したことと、レビューしたコミットを示す値。指摘がないときとあるときの両方。
    3. 割り当てを使い切ったときと、エラーのときに、CodeRabbit が示すもの。
    4. スレッドとコメントの著者の値（GraphQL の `author.__typename` と `author.login`、REST の `user.type` と `user.login`）。
    5. `.coderabbit.yaml` の自動レビューが止まったまま、PR を開いたときと push したときに、CodeRabbit が自分でレビューを始めるか、何かを投稿するか。
    6. CodeRabbit の投稿と PR の説明の書き込みに、`@coderabbitai` または `@codex` の文字列が含まれるか。
    7. 指摘をスレッドにせず本文だけに書くことがあるか。あるなら、本文を読まずにその有無や数が分かる値。
    8. 一部のファイルをレビューしなかったことを示す値。
    9. 指摘を直す commit を PR のブランチに作る機能が、今のブランチの push の制限の下で働くか。
    10. レビューが終わった後に、利用者のアカウントがスレッドに返信したとき（`/fixpr` の返信。メンションを含まない）に、CodeRabbit が投稿するもの（返信、レビュー）と、それがコミットを示すか。
    11. CodeRabbit の PR レビューと CodeRabbit CLI が `AGENTS.md` を読むか（公式の文書から）。
- **AC-02**: 試験の PR への依頼のコメントは利用者が投稿し、エージェントは投稿しない。記録には、誰が投稿したかを書く。
- **AC-03**: 記録は、本タスクのディレクトリの `observations.md` に置き、`02_architecture.md` と同じ PR で commit する。試験の PR はマージせずに閉じる。試験の PR に Codex の自動レビューも投稿されたときは、それを記録に書き、CodeRabbit の観測と分ける。
- **AC-04**: 観測の結果が本書の決定と食い違うとき（AC-01 の 5 で CodeRabbit が自分でレビューを始める、AC-01 の 9 で CodeRabbit が PR のブランチに push できる、など）は、記録に残して止め、設計に進まずに利用者に判断を仰ぐ。
- **AC-05**: `02_architecture.md` が完了の印や割り当ての知らせとして使う値は、すべて AC-01 の記録にある値である。

#### F-002: PR を開くときに PR レビューを頼まない

PR を開くコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/mkplan2`・`/runplan`、単独の変更の PR を作る `/runpr`）は、PR を開いた後に、どの自動レビュアーにも PR レビューを頼まず、その開始も待たない。

**Acceptance Criteria**:
- **AC-06**: これらのコマンドは、PR を作ってから報告するまでの間、PR にコメントを投稿しない。
- **AC-07**: これらのコマンドの最終の報告と利用者への通知は、今と同じく PR の URL と次の行動（PR をレビューして `/runpr <PR>` を実行する）を示す。PR レビューを待つ旨は書かない。

#### F-003: `/runpr` は PR レビューを待たない

`/runpr` は、CI と、信頼する著者のスレッドの処理だけを待って、マージの質問に進む。Codex の要約コメントと受領コメントは読まない。

**Acceptance Criteria**:
- **AC-08**: CI が成功し、未解決のスレッドがなく、応答を待つ依頼のコメントもない PR では、`/runpr` は完了の印を待たずに、マージの質問を出す。
- **AC-09**: `/runpr` は、Codex の要約コメントや受領コメントを待たず、その有無で止まらない。受領コメントによる「指摘なしとして進めますか」の問いは出さない。
- **AC-10**: 信頼する著者のスレッドが PR にあれば、`/runpr` は今と同じく `/fixpr` で処理してから、マージの質問に進む。
- **AC-11**: マージの質問の要約の行は、Codex の名前を出さない。PR を開いた後の変更をローカルの CLI レビューが見たかどうかと、Fable の部分レビューの記録は、今と同じく示す。

#### F-004: 手動の PR レビュー

マージの質問で利用者が「先に PR レビューを依頼」を選んだときだけ、`/runpr` は CodeRabbit に PR レビューを頼み、その完了を待ってから、マージの質問に戻る。CodeRabbit の投稿は信頼しない入力として読む。

**Acceptance Criteria**:
- **AC-12**: 「先に PR レビューを依頼」は、PR の head を見た完了の印がまだないとき、または head を見た手動の PR レビューが一部のファイルをレビューしなかったと分かるとき（AC-20）、マージの質問の選択肢に出る。それ以外で head を見た完了の印があるときは出ない。
- **AC-13**: 利用者が「先に PR レビューを依頼」を選んだときだけ、`/runpr` は依頼のコメントを 1 件投稿する。それ以外のときは、`/runpr` はどの自動レビュアーにも依頼しない。
- **AC-14**: 応答を待つ依頼のコメント（3.1。利用者が手で書いたものを含む）がある間、`/runpr` は完了の印を待つ。完了の印が届けば、その間に開かれたスレッドを `/fixpr` で処理してから、マージの質問に戻る。止まった後の再実行でも、応答を待つ依頼のコメントがあれば、新しく投稿せずに待つことから再開する。
- **AC-15**: 完了の印として数えるのは、著者が `Bot` で、名前が完了を待つ PR レビュアー（AC-46）であるものだけである。同じ名前の `User` の投稿は数えない。
- **AC-16**: 次のいずれかのときは、レビュー済みとせずに止まる。(a) 完了の印になりうる投稿が 2 件以上あって選べない。(b) 投稿が観測した形（AC-01）に合わない。(c) 示すコミットが 16 進の形でない。(d) 示すコミットが PR の head の祖先でも head でもない。報告はそれぞれの投稿の URL を示し、本文は示さない。形を直したり読み替えたりして完了とはしない。
- **AC-17**: 完了の印は、それが示すコミットとその祖先だけをレビュー済みにする。依頼のコメントより前に投稿された完了の印は、その依頼の応答として数えない。依頼のコメントの時点の head は GitHub から確実には求められない（[0031 要件定義書](../0031_codex_pr_review/01_requirements.md) の「要件定義の際に決めたこと」の 2026-10-22 の項目）ので、それとは比べない。
- **AC-18**: 次のいずれかのときは、レビュー済みとせずに止まる。(a) 割り当てを使い切った知らせを受けた。(b) エラーの知らせを受けた（(a) と (b) は AC-01 の 3 で観測した形）。(c) 待つ時間の上限を過ぎても完了の印がない。報告は、そのことと依頼のコメントの URL、次の手（割り当てが戻ってから `/runpr` を再実行して選び直す、またはレビューなしでマージに進む）を示す。(a)〜(c) に当たった依頼は終わったものとし、利用者が再び選べば新しく依頼する。
- **AC-19**: 手動の PR レビューが指摘をスレッドにせず本文だけに書いたことが、本文を読まずに分かるとき（AC-01 の 7）、マージの質問の要約は、そのことと、そのレビューの URL を示す。本文はセッションに出さない。
- **AC-20**: 手動の PR レビューが一部のファイルをレビューしなかったことが分かるとき（AC-01 の 8）、マージの質問の要約は、そのことと、そのレビューの URL を示す。
- **AC-52**: 本文だけにある指摘の有無が本文を読まずには分からないとき（AC-01 の 7 で、そのような値がないと分かったとき）、手動の PR レビューが完了した PR のマージの質問の要約は、そのレビューの URL と、本文に指摘がありうることを示す。
- **AC-53**: 再実行で、最新の依頼のコメントが AC-18 の (a)〜(c) で終わっていて、その後に完了の印がないときは、マージの質問の要約は、そのことと依頼のコメントの URL を示す。
- **AC-54**: AC-01 の 10 で観測した、スレッドへの返信に応じた CodeRabbit の投稿は、完了の印として数えない。

#### F-005: エスカレーションは勧めるだけにする

エスカレーションの判定は残す。その結果は、マージの質問の推奨を決めるだけにし、PR レビューを依頼しない。

**Acceptance Criteria**:
- **AC-21**: エスカレーションが判定する範囲は、最後の完了の印が示すコミットから head までとする。完了の印がないときは、PR の全体（`origin/main` との merge-base から head まで）とする。
- **AC-22**: 範囲の変更が信頼の境界・セキュリティ・耐久性の基準に当たるとき、マージの質問は「先に PR レビューを依頼」を推奨にする。
- **AC-23**: ほかの基準にだけ当たり、その範囲のすべての commit をローカルの CLI レビューが見たと記録から分からないとき、マージの質問は「先に PR レビューを依頼」を推奨にする。すべて見たと分かるときは、「マージ」を推奨にする。
- **AC-24**: エスカレーションの判定が、どの基準にも当たらないと決まった形で答えたときだけ、「マージ」を推奨にする。
- **AC-55**: エスカレーションの判定が迷って `ask` と答えたとき、答えが決まった形でないとき、判定を走らせられなかったときは、今と同じく「先に PR レビューを依頼」を推奨にする（`runpr.md` の step 3 の規則と同じく、安全側に倒す）。
- **AC-25**: どの判定の結果のときも、`/runpr` はエスカレーションの結果だけで PR レビューを依頼しない（依頼は AC-13 だけ）。

#### F-006: ローカルの CLI レビューは CodeRabbit CLI だけにする

ローカルの CLI レビューは CodeRabbit CLI だけで行う。失敗したときは、代わりのレビューを走らせず、`not run` を記録して進む。

**Acceptance Criteria**:
- **AC-26**: CodeRabbit CLI が失敗したとき、ローカルの CLI レビューは Codex CLI を含むほかのレビューを走らせない。見ていない範囲を `not run` の記録の行に残し、呼び出し元の手順を止めずに進む。
- **AC-27**: 見ていない範囲は、今と同じく PR の説明（レビューを受けていない commit の一覧）とマージの質問の要約の行に出る。
- **AC-28**: このタスクの変更がマージされる前の commit にある `Codex local review:` の行と、`(codex)` を持つ `Local CLI reviewed:` の行は、それを持つブランチで今と同じ意味に読まれる。すなわち、レビューした範囲と指摘として読まれ、見ていない範囲として扱われない。

#### F-007: PR を開く前に、まだ見ていない commit をローカルの CLI レビューにかける

PR を開くコマンドは、PR を開く前に、どのローカルの CLI レビューも見ていない commit を、まとめてローカルの CLI レビューにかける。

**Acceptance Criteria**:
- **AC-29**: PR を開く直前に、ブランチに、どのローカルの CLI レビューの見た範囲（`Local CLI reviewed:` の行）にも入らない中身のある commit があるとき、ローカルの CLI レビューがそれらを含む範囲をレビューし、その結果をほかのローカルの CLI レビューと同じ形でブランチに記録する。Opus のレビューの直し、green gate・終わりの確かめ・CHECKS の直し、Fable の記録の後の commit を含む。
- **AC-30**: そのレビューで CodeRabbit CLI が失敗したときは、F-006 のとおり `not run` を記録して PR を開く。PR の説明は、その範囲をレビューを受けていない commit として示す。
- **AC-31**: そのような commit がないとき、このためのローカルの CLI レビューは走らない。中身のない commit（空の commit、記録だけの commit、計画書の PR の進み具合のチェックボックスだけを変える commit）は、それだけでは走らせない。

#### F-008: `codexreview` の撤去

`codexreview` の道具と、それを使う・確かめる・許可するものを撤去する。

**Acceptance Criteria**:
- **AC-32**: リポジトリに `cmd/codexreview` と `internal/codexreview` がない。
- **AC-33**: `Makefile` に `install-codexreview` のターゲットがない。
- **AC-34**: `.claude/settings.json` の許可に、`codexreview` を実行する規則がない。
- **AC-35**: マージの前のプロトコル番号の確かめ（`mergepr`）と、`CLAUDE.md` の「Protocol numbers」が番号を持つ道具として挙げるものは、`fixprguard`・`chief`・`mergepr` の 3 つであり、`codexreview` を含まない。
- **AC-36**: Go のソースのコメントと許可の一覧（`internal/config/envaccess_test.go` の表など）は、`codexreview`・`cmd/codexreview`・`internal/codexreview` を名指さない。
- **AC-37**: CI の `doc-guard` のジョブと `make test`・`make lint`・`make deadcode` は、撤去の後も成功する。

#### F-009: 2 つのメンションの拒否と確かめ

利用者のアカウントから投稿する文面は、依頼のコメントのほかは、`@codex` も `@coderabbitai` も含まない。`/runpr` は、利用者以外が書いたどちらのメンションも確かめる。

**Acceptance Criteria**:
- **AC-38**: `fixprguard` は、今の `@codex` の拒否と同じ入力（レビューのスレッドへの返信、`edit-pr` の PR のタイトルと説明、`append-pr` の後の PR の説明、`finish` の commit メッセージの本文）で、`@codex` または `@coderabbitai` を含む文面を、GitHub への書き込みと commit の前に拒否する。判定は、今と同じく大文字と小文字を区別せず、文面のどこにあっても当たるものとして拒否する（`internal/fixprguard/write.go:91`）。
- **AC-39**: 今の PR の説明（ほかの人や CodeRabbit が書いた部分を含む）にメンションの対象が含まれるために `append-pr` が拒否されたときは、その手順は止まって報告する。報告は、原因が今の PR の説明にあることを示す。手順は同じ書き込みを繰り返さない。
- **AC-40**: コマンドの定義が投稿の前に行うメンションの確かめは、2 つのメンションのどちらかを含む文面を通さず、投稿させない。例外は、AC-13 の依頼のコメントだけである。
- **AC-41**: `/runpr` は、PR のコメントとレビューにあるメンションの対象を、著者の種類で扱う。今の `@codex` の扱い（`runpr.md` の「Mentions by other accounts」）を 2 つのメンションに広げたものである。
    1. 利用者のもの: 止まる理由にならない。
    2. 利用者以外の `User` のもの: 止まり、URL を示す（本文は示さない）。
    3. 完了を待つ PR レビュアー（AC-46）の投稿で、AC-01 で観測した形に合うもの: メンションとして扱わない。
    4. それ以外の `Bot` のもの（完了を待つ PR レビュアーの、観測した形に合わない投稿と、Codex の投稿を含む）: 続けるかを利用者に尋ね、URL を示す（本文は示さない）。
- **AC-42**: interaction limits の確かめ（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）は、今と同じく行う。
- **AC-56**: 投稿するすべての経路がメンションの確かめを通ることと、`.coderabbit.yaml` が自動の PR レビューを止めていることを確かめる今のガードテスト（`cmd/yt2column/codex_review_docs_test.go` にあるもの）は残り、2 つのメンションを対象にする。文書がメンションの対象を書いてよい場所は、依頼のコメントの本文の行と、拒否するメンションを定める場所だけである。

#### F-010: 自動レビュアーの一覧と完了を待つ PR レビュアー

信頼する自動レビュアーを CodeRabbit だけにし、完了を待つ PR レビュアーも CodeRabbit にする。

**Acceptance Criteria**:
- **AC-43**: 信頼する自動レビュアーの一覧（`.claude/commands/_context.md` の「Automated reviewer list」）は `coderabbitai` だけである。
- **AC-44**: `chatgpt-codex-connector` のスレッドは、ほかの想定外の著者のスレッドと同じく扱われる（`runpr.md` の「Untrusted threads」）。
- **AC-45**: AC-43・AC-44 を入れる PR は、F-002・F-003 を入れる PR と同じか、それより後にマージされる。F-004・F-006・F-007 と AC-46 を入れる PR は、F-002・F-003 を入れる PR と同じか、それより前にマージされる（4.4）。
- **AC-46**: 完了を待つ PR レビュアー（`_context.md` の「Awaited PR reviewer」）は `coderabbitai` であり、依頼のコメントの本文（「PR review request」）は `@coderabbitai review` である。

#### F-011: 現在の仕様を書く文書と ADR

現在の仕様を書く文書と ADR を、このタスクの決定に合わせる。

**Acceptance Criteria**:
- **AC-47**: 現在の仕様を書く文書（3.1）は、Codex の PR レビュー、Codex CLI、`codexreview`、受領コメントを、今の振る舞いとして書かない。次のものは、これに当たらない。過去の決定・採らなかった案・受け入れた危険の出典として名前を挙げること。F-009 の `@codex` の拒否と扱い。AC-28 の古い記録の行の読み方。確かめは、PR のレビューで読むこと（`manual`）とする。
- **AC-48**: 用語集は、Codex CLI を含む定義（「試行」など）を、CodeRabbit CLI だけの定義に改める。
- **AC-49**: ADR-0013・0014・0015・0042・0047・0050 の `## 決定` は、本書の決定と一致する。実装が終わるまで残る食い違いは、各 ADR の `## 決定` に、#1059 で解く食い違いである旨の記述として示す。実装が食い違いを解いた PR で、その記述を外す。

#### F-012: chief の読み取り

chief の読み取りのサンプルは残し、`/runpr` の報告の形が変わるときだけサンプルを足す。

**Acceptance Criteria**:
- **AC-50**: `internal/chief/testdata/` の今のサンプルは残り、chief のテストはそれで成功する。
- **AC-51**: このタスクが `/runpr` の報告または NEXT 行の形を変え、chief の読み取りの形に当たるときは、変えた後の `/runpr` の実際の報告を新しいサンプルとして足し、chief がそれを読めることをテストで確かめる。形が変わらないときは、サンプルを足さない。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。待つ時間が短くなる変更で、性能の要件はない。手動の PR レビューを待つ時間の上限は、F-001 の観測を見て設計で決める。

### 4.2. セキュリティ (Security)

-   条件付きのガイド（`docs/dev/security.md`）のきっかけ（外部のコマンドの起動、API キー、キャッシュ、LLM API への送信、信頼しないテキストのプロンプトへの埋め込み）に当たる機能はない。N/A。
-   開発用の道具の信頼の境界を、次のように変える。
    -   **投稿する文面:** 利用者のアカウントからの投稿が自動レビュアーを動かさないよう、F-009 で拒否するメンションを 2 つにする。ただし、メンションのないスレッドへの返信にも CodeRabbit が応じうる（PR #852 の記録の、返信の 70 秒後の CodeRabbit のレビューから推測される。AC-01 の 10 で確かめる）ので、拒否はメンションによる依頼を防ぐものにとどまる。
    -   **信頼する著者:** F-010 で自動レビュアーの一覧を 1 つにする。
    -   **外部の人の入口:** interaction limits の確かめは残す（AC-42）。
    -   **PR のブランチに書く者:** CodeRabbit が PR のブランチに push できるかを観測し、できるなら設計に進まない（AC-01 の 9、AC-04）。
    -   **外部へ送るもの:** Codex CLI がなくなるので、ローカルの CLI レビューが差分を OpenAI のサービスへ送ることはなくなる。CodeRabbit CLI が CodeRabbit のサービスへ送ることは変わらない。
-   **CodeRabbit の投稿の扱い:** 信頼しない入力として読む。完了の印の著者・数・形・示すコミットの条件は AC-15〜AC-17 で定め、形に合わない投稿は完了とせずに止めて報告する。今の原則（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）を保ち、本文はセッションに出さない（AC-16、AC-19）。どの値をどう読むかは設計で決める（[design_handoff.md](design_handoff.md) の H-01）。
-   受領コメント（0108）の本文を出さない絞り込みは、受領コメントの読み取りごと撤去する。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   手動の PR レビューが届かないときは、止めて報告し、レビュー済みとしない（AC-18）。
-   CodeRabbit CLI が失敗しても、手順を止めない（AC-26）。

### 4.4. 互換性 (Compatibility)

-   **移行の順序:**
    1.  このタスクの PR は、F-002・F-003 を入れる PR がマージされるまで、Codex の連携が動いている間に、その時点の `main` の `/runpr` で回す。
    2.  F-009 と AC-43・AC-44 は、F-002・F-003 と同じ PR か、それより後の PR に入れる。F-004・F-006・F-007 と AC-46 は、F-002・F-003 と同じ PR か、それより前の PR に入れる（AC-45）。連携を切ると同時に Codex の契約も終わり、ローカルの CLI レビューが `codexreview` を呼んでも失敗するだけになるためである。
    3.  利用者は、F-002・F-003 を入れる PR がマージされた直後に、Codex の連携を切り、契約を終える（要件定義の際に決めたこと）。
    4.  それより後の PR は、Codex の投稿なしで回る。連携を切る前に開いた PR に Codex の投稿が残っていれば、AC-41 の 4 と AC-44 のとおり、利用者に確認することになる。
-   **コマンドの定義を読む場所:** コマンドの定義は、そのブランチの作業ツリーから読まれる（`origin/main` から取り出すのはスクリプトだけである）。そのため、F-002・F-003 を入れる PR は、自分の新しい定義の `/runpr` で回り、Codex の PR レビューを待たない。
-   **ほかのタスクのブランチ:** 連携を切った後は、ほかのタスクのブランチは、`main` を取り込んでから `/runpr` を走らせ、PR を開く。取り込まないと、古い定義が `@codex review` を投稿して待ち続ける。このタスクの変更がマージされる前に作られ、`Codex local review:` などの行を持つブランチも、取り込んだ後の `/runpr`・`/fixpr`・`/runplan` で回せる（AC-28）。
-   **入れ直す道具:** 番号を変えた道具は、マージの後に利用者が `main` から入れ直す（`CLAUDE.md` の「Protocol numbers」）。利用者の環境に残った `codexreview` のバイナリは、どのコマンドからも呼ばれない。消すかは利用者に任せる。

### 4.5. 保守性 (Maintainability)

-   Codex に固有の判定（要約コメント、受領コメント、`codexreview` の最終メッセージの解析）を保守しなくてよくなる。
-   CodeRabbit の完了の判定は、F-001 の記録に依存する。形が変わったときは、`/runpr` が止まり（AC-16、AC-18）、設計を直す。
-   CodeRabbit の PR レビューの割り当ては「1 時間に 1 回」と示されている（PR #852 の記録）。並行するタスクで手動の PR レビューを続けて選ぶと、割り当てを使い切って止まりうる（AC-18）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   `CLAUDE.md` の「Protocol numbers」に従う。タスク文書には上げた後の番号を書かず、「`main` の値 + 1」と書く。
-   `CLAUDE.md` の「Tool Execution Safety」に従う。試験の PR への依頼のコメントは、利用者が投稿する（AC-02）。試験の PR の作成や閉じる操作など、ネットワークに触れるほかの操作は、利用者の承認を得て行う。
-   テストの削除は、`CLAUDE.md` の「Testing Strategy」の「Deleting a test is a claim that must be checked」に従う。撤去する道具そのものの `_test.go` を、その製品のコードと一緒に消す場合の確かめ方は設計で決める（[design_handoff.md](design_handoff.md) の H-04）。
