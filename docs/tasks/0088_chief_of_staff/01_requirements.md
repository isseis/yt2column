## 1. 概要 (Overview)

**目的:** 本書は、複数の Herdr の workspace で並行して進むタスクを見渡し、人の判断を待つものを選択式で示し、人の判断が要らない操作を自動で行うコーディネーター（以下 chief）の要件を定義する。

**背景:**

このリポジトリでは、タスクごとに git の worktree を作り、それを Herdr の workspace で開いて、シェル、OpenCode、Claude Code の pane で作業している。タスクは、`/mkreq` → `/mkarch` → `/mkplan` → `/runplan`（計画の PR の数だけ）の順に、それぞれが PR を作り、人がレビューしてから `/runpr` を実行し、`/runpr` がマージの確認を人に尋ねてマージする（[CLAUDE.md](../../../CLAUDE.md)「Claude Commands」）。

workspace が増えると、次のことが起きる。

-   どの workspace が人を待っているか（エージェントの質問、レビュー待ちの PR、マージの確認）が見えない。
-   人の判断が要らない操作にも人の手がかかる。`/runpr` はマージの後に次のコマンド（NEXT）を示すが、走らせるかは人が選ぶ（[runpr.md](../../../.claude/commands/runpr.md) の step 4、783〜786 行）。次のコマンドを正しいモデルで走らせるには、人がその pane で `/clear` と `/model` を打ってからコマンドを打つ。
-   送り先のエージェントとモデルを人が毎回選ぶので、取り違えが起きる。`/runplan` のモデルは実装計画書の PR マーカーの `**実装モデル要件**` で決まる（[_context.md](../../../.claude/commands/_context.md) 62 行、[ADR-0042](../../dev/adr/0042-implementation-model-tiers.md)）。

2026-11-11 に、chief の試作（コマンドの定義 `chief.md` と `.claude/chief/` のシェルスクリプト。リポジトリには入れていない）を 6 つの workspace で動かした。分かったことは親 issue [#836](https://github.com/isseis/yt2column/issues/836) の「試作で分かったこと」にあり、本書の要件はそれを踏まえる。

対応 issue: [#837](https://github.com/isseis/yt2column/issues/837)・[#838](https://github.com/isseis/yt2column/issues/838)（親: [#836](https://github.com/isseis/yt2column/issues/836)、関連: [#839](https://github.com/isseis/yt2column/issues/839)・[#840](https://github.com/isseis/yt2column/issues/840)・[#760](https://github.com/isseis/yt2column/issues/760)・[#790](https://github.com/isseis/yt2column/issues/790)）

**本書の記述範囲:** 本書は、chief が何を示し、何を誰に送り、何を送らないかという観測できる振る舞いを定める。chief の作り（コマンドの定義だけか、Go の道具を足すか）、Herdr の出力の読み方、エージェントが質問で止まっていることの見分け方、モデルの切り替えの確かめ方、待ち受けの仕組み、表と選択肢の文言、テストの手段は、設計（`02_architecture.md`）で決める。要件の段階で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #836・#837・#838 で決めたこと:**

-   **#837 と #838 を 1 つのタスクにする。** 状況の表と自動の進行は、同じ状況の読み取りと同じ送信の経路を使うためである。worktree と workspace の作成と削除（#839）と、`/runpr` の Opus への切り替え（#840）は、別のタスクにする。
-   **コマンドごとのエージェントとモデル:** `/mkreq`・`/mkarch`・`/mkplan` は Claude Code・Opus、`/runplan` は実装計画書の PR マーカーの `**実装モデル要件**` が指すもの、`/runpr` は OpenCode・DeepSeek V4.1 Flash で走らせる。
-   **実装の後の Opus のレビューは、`/runplan` が PR を開く前に行う仕組み（ADR-0042）を前提にする。** chief はそのためのコマンドを送らない。
-   **`/runpr` は人がレビューした後に送る。** PR を開いたことだけを理由に、chief が `/runpr` を送ることはしない。
-   **実装計画書の PR のレビューは、不要と判断できれば省いてよい。** chief が「レビュー省略可」と示し、人が決める。
-   **試作のコードは参考にとどめる。** 試作で分かったことは #836 に残し、実装は作り直す。

**要件定義の際に決めたこと（2026-11-11）:**

-   **プロセスは通常のプロセスにする。** chief はほかのエージェントのセッションに入力を送る。開発用ツールの信頼の境界に当たるので、簡易プロセスの対象外である（[requirements_process.md](../../dev/conventions/requirements_process.md)「Simple Process」の「Excluded changes」）。新しい仕組みで、コマンドの定義、ルーティング、`/runpr`・`/mkplan` との接点という複数の場所に及ぶことも、通常のプロセスを選んだ理由である。ADR は要らない（プロセスの選択はこのタスクの中で閉じるため）。
-   **止まっているエージェントの質問には、人が chief の選択肢で選んだ答えだけを中継する（F-005）。** chief 自身は答えを選ばない。送る直前に、質問と選択肢が人に示したときと同じであることを確かめ、変わっていれば送らない。人の判断であることを保ったまま、pane を移る手間をなくすためである。ADR は [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を作る。
-   **権限の確認（コマンドを実行してよいか）は中継しない（F-005）。** 中身を示すだけで、答えは人がその pane で直接入れる。chief 越しに答えると、実行されるコマンドを見ないまま許可しやすくなるためである。ADR-0046 に含める。
-   **自由に書く答えは中継しない。中継するのは、質問が示す選択肢だけにする（F-005）。** 自由な文を送れると、chief が送る入力が人の書いた任意の文まで広がるためである。ADR-0046 に含める。
-   **マージの後の自動送信を止める例外は、実装計画書の PR マーカーに欄を足して宣言し、`/mkplan` が書く（F-008）。** chief の手元のファイルに人が書く案は採らない。途中で対話のセッションを挟むこと（例：0084 の PR-1 の後）は計画を作るときに決まる事柄で、計画書に置けば別の場所へ書き写さずに済むためである（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」）。ADR-0046 に含める。
-   **自動送信の欄がない計画書は、自動送信してよいものとして扱う（F-008）。** 欄がないのは、この決定より前に書かれた計画書の正しい形だからである（ADR-0042 の旧い値の扱いと同じ考え方）。自動で送るのは次の `/runplan` だけで、`/runplan` は計画に沿って止まれる。進行中の 0084 の PR-1 の後を止める必要があれば、その計画書を直す PR で欄を足す。ADR-0046 に含める。
-   **人の判断を待つものは、種類の順に並べ、同じ種類の中では待っている時間の長い順に並べる（F-003）。** 種類の順は、エージェントを止めている質問、マージの確認、レビュー待ちの PR、そのほかの提案である。エージェントが止まっている間はそのタスクが進まないためである。issue の優先度ラベルを先に見る案は採らない。ADR は要らない（並べ方はこのタスクの中で閉じるため）。
-   **自動の進行は、chief のセッションが待ち受けている間だけ行う（F-010）。** セッションと別に常駐するプロセスは置かない。止まっている間に溜まったものは、次に状況の表を出したときに拾う。常駐のプロセスは、エージェントのいないところでほかのセッションへ入力を送ることになり、信頼の境界が広がるためである。ADR-0046 に含める。
-   **人の判断を待つものが新しく増えたときに通知する。種類は問わない（F-010）。** レビュー待ちの PR もマージの確認も、気づかなければタスクが止まるためである。ADR は要らない。
-   **実装計画書の PR を「レビュー省略可」と示す基準は、設計で決める（F-004）。** 要件では、基準を満たすときに示すことと、示しても人が決めることだけを定める。ADR は要らない。
-   **chief は `/weakreview` を送らない（F-006）。** Opus のレビューは `/runplan` が PR を開く前に行う（ADR-0042）ので、chief が送る場面がないためである。ADR-0046 の「送るコマンド」に含める。
-   **chief は、人が issue を示したときに、タスクのない空いた workspace へ `/mkreq` を送る（F-006）。** issue を選ぶのは常に人である。workspace を作る仕組み（#839）ができるまで、`/mkreq` を走らせる workspace は人が用意する。ADR-0046 の「送るコマンド」に含める。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   すべての workspace の状況を 1 つの表で見られるようにする。
-   人の判断を待つものを優先度の順に選択式で示し、人が選ぶだけで次の操作に進めるようにする。
-   マージの後の次のコマンドを、人の手を介さずに、決まったエージェントとモデルで送る。
-   chief がほかのエージェントへ送る入力を決まった範囲に限り、chief が人の代わりに判断しないようにする。

### 2.2. スコープ (In Scope)

-   状況の表（F-001）
-   人の判断を待つものの検出（F-002）
-   選択式の提示と優先度（F-003）
-   PR の詳細と「レビュー省略可」の提示（F-004）
-   エージェントの質問の中継（F-005）
-   送り先とモデルの決定、送信（F-006）
-   マージの後の自動送信（F-007）
-   実装計画書の PR マーカーの自動送信の欄（F-008）
-   役目を終えた pane の文脈のリセット（F-009）
-   待ち受けと通知（F-010）
-   送信の結果の報告（F-011）

### 2.3. スコープ外 (Out of Scope)

-   タスク用の worktree と workspace の作成と削除。#839 で扱う。
-   `/runpr` を Flash で動かし、難度の高い修正を求められたら Opus でやり直すこと。#840 で扱う。
-   chief のセッションと別に常駐するプロセス。要件定義の際に決めたことのとおり置かない。
-   レビュー待ちの PR への `/runpr` の自動送信。人がレビューした後に人が選ぶ。
-   chief が自分で質問への答えを選ぶこと。権限の確認と自由に書く答えの中継。
-   `/weakreview` の送信。
-   OpenCode のモデルの切り替え。OpenCode はコマンドでモデルを切り替えられないので、chief はモデルが合わないことを示し、人がその pane で切り替える（F-006）。
-   issue の作成。人が Opus と対話して作る。
-   進行中の計画書（0081・0083・0084・0085）に自動送信の欄を書き足すこと。必要になったときに、その計画書を直す PR で行う。

## 3. 機能要件 (Functional Requirements)

本書でいう **chief の workspace** は、chief のセッションが動いている workspace である。**タスクの workspace** は、それ以外の Herdr の workspace のうち、このリポジトリの worktree を開いているものである。**エージェント**は、タスクの workspace の pane で動く Claude Code か OpenCode である。

### 3.1. 機能一覧

#### F-001: 状況の表

人が求めたとき（1 回の呼び出しで）と、待ち受けの中で状況が変わったときに、タスクの workspace の状況を 1 つの表で示す。

**Acceptance Criteria**:
-   **AC-01**: 表は、タスクの workspace ごとに 1 行を持ち、chief の workspace の行を持たない。
-   **AC-02**: 各行は、workspace の名前、タスクの番号（タスクがないときはそれと分かる表示）、状態、次にやることを持つ。状態は「質問で停止」「レビュー待ち」「実行中」「完了」「要確認」のどれかである。「実行中」の行は、走っているコマンドとモデルが分かるときはそれを示す。
-   **AC-03**: 人の判断を待つ行（「質問で停止」と「レビュー待ち」）は、それ以外の行より上に並ぶ。
-   **AC-04**: 表は、PR の詳細（F-004）を集め終わるのを待たずに示される。
-   **AC-05**: 表の下に、「質問で停止」の行ごとに、質問の要点と pane が示される。続けて、chief がこのセッションで人に尋ね、まだ答えを得ていない判断が 1 行ずつ示される。
-   **AC-06**: タスクの状態（文書の承認、計画の PR のマージ）を読めない workspace、または状態がどの区分にも当たらない workspace は「要確認」とし、読めない理由か当たらない状態を示す。推し量って別の状態として扱わない。

#### F-002: 人の判断を待つものの検出

次のものを、人の判断を待つものとして見分ける。

-   エージェントを止めている質問（決める点、権限の確認を含む）
-   `/runpr` のマージの確認
-   レビュー待ちの PR（PR が開いていて、その PR の `/runpr` がまだ走っていないもの）
-   そのほかの提案（マージの後の自動送信の条件を満たさなかった次のコマンドなど）

**Acceptance Criteria**:
-   **AC-07**: Claude Code のエージェントが質問で止まっているとき、その workspace は「質問で停止」になる。
-   **AC-08**: OpenCode のエージェントが質問を示して入力を待っているとき、Herdr がそのエージェントを `blocked` と報告していなくても、その workspace は「質問で停止」になる。
-   **AC-09**: `/runpr` がマージの確認で止まっている workspace は、PR が開いていても「レビュー待ち」にならず、その workspace へ `/runpr` を送る選択肢は示されない。
-   **AC-10**: PR が開いていて、その PR の `/runpr` がまだ走っていない workspace は「レビュー待ち」になる。

#### F-003: 選択式の提示と優先度

人の判断を待つものと提案を、選択式で 1 回尋ねる。人は選ぶだけで、次の操作（PR の詳細を見る、質問に答える、コマンドを送る、何もしない）に進める。

**Acceptance Criteria**:
-   **AC-11**: 選択肢は、エージェントを止めている質問（マージの確認を除く）、マージの確認、レビュー待ちの PR、そのほかの提案の順に並ぶ。同じ種類の中では、待っている時間の長いものが先に並ぶ。選択肢には常に「何もしない」が含まれる。
-   **AC-12**: 1 回の問いで示せる数を超えるときは、先頭から示せるだけ示し、示さなかったものを問いの中で名前で挙げる。人はその名前を答えに書いて選べる。
-   **AC-13**: 人が選ぶまで、chief はどのエージェントにも入力を送らない（F-007 の自動送信を除く）。

#### F-004: PR の詳細と「レビュー省略可」の提示

人がレビュー待ちの PR を選んだとき、`/runpr` を送るかを決める材料を示し、送るかを尋ねる。

**Acceptance Criteria**:
-   **AC-14**: PR の詳細は、タスク、PR の番号・タイトル・URL、規模（変えたファイルの数、足した行と消した行の数、コミットの数）、CI の各ジョブの結果、PR レビューの書き手と状態、PR を作ったコマンドのまとめを持つ。
-   **AC-15**: CI のジョブのうち実行されなかったもの（skipping）は、通ったもの（pass）と区別して示される。実行されなかったジョブがあるとき、「CI は通った」とだけ示さない。
-   **AC-16**: PR を作ったコマンドのまとめが pane に残っていないとき（スクロールで消えた、`/clear` で消した）は、PR の説明からまとめを示し、どちらから示したかが分かる。
-   **AC-17**: PR レビューの本文は示さない（書き手と状態だけを示す）。
-   **AC-18**: PR の詳細を示した後に、「`/runpr` を送る」「送らない」「ほかの PR を見る」を尋ねる。「`/runpr` を送る」には送り先のエージェントとモデルが示される。
-   **AC-19**: 実装計画書の PR が設計で決める基準を満たすとき、その PR の選択肢と詳細に「レビュー省略可」が示される。示しても、`/runpr` を送るかは人が選ぶ。
-   **AC-20**: 人が「`/runpr` を送る」を選んだとき、chief は送信の終わりを待たずに次の問いか報告に進み、送信の結果は F-011 で示す。

#### F-005: エージェントの質問の中継

エージェントを止めている質問を人に示し、人が chief の選択肢で選んだ答えだけをその pane へ送る。

**Acceptance Criteria**:
-   **AC-21**: 質問を示すときは、workspace の名前、pane、質問、すべての選択肢を示す。1 つの画面に複数の問い（タブ）があるときは、すべての問いを示す。
-   **AC-22**: 人が chief の選択肢で答えを選んだとき、chief は、送る直前に、その pane の質問と選択肢が人に示したときと同じであることを確かめ、同じときだけ、その選択肢を選ぶ入力を送る。違うとき（質問が変わった、答えられた、エージェントが動き出した）は何も送らず、そのことを示す。
-   **AC-23**: chief は、人が選んでいない答えを送らない。人が選んだ答えも、質問が示す選択肢のどれかに当たらないときは送らない。
-   **AC-24**: 権限の確認（コマンドやツールを実行してよいか）は、中身を示すだけで、答えを中継する選択肢を示さない。人がその pane で直接答えることを示す。
-   **AC-25**: 自由に書く答え（選択肢にない答え）は中継しない。人がその pane で直接入れることを示す。
-   **AC-26**: `/runpr` のマージの確認を示すときは、「NEXT をこのセッションで実行する」答えを選ぶと次のコマンドが `/runpr` のモデルで走り、「NEXT を実行しない」答えを選ぶと chief が F-007 で決まったモデルで送る（自動送信の条件を満たすとき）ことを示す。

#### F-006: 送り先とモデルの決定、送信

コマンドごとに送り先のエージェントとモデルを決め、決まった手順でだけ送る。

chief がタスクの workspace へ送る入力は、次のものだけである。

| 入力 | 送る場面 |
|---|---|
| `/clear`・`/model <モデル>`（Claude Code） | コマンドを送る前（F-006）、pane のリセット（F-009） |
| `/new`（OpenCode） | コマンドを送る前（F-006）、pane のリセット（F-009） |
| `/mkreq <issue>` | 人が issue を示し、送り先を選んだとき |
| `/mkarch <タスク>`・`/mkplan <タスク>`・`/runplan <タスク>` | 人が選んだとき、またはマージの後の自動送信（F-007） |
| `/runpr <PR>` | 人が PR の詳細を見て選んだとき（F-004） |
| 質問の選択肢を選ぶ入力 | 人が選んだ答えの中継（F-005） |

**Acceptance Criteria**:
-   **AC-27**: chief は、上の表にない入力（`git` のコマンド、`gh pr merge`、自由な文、`/weakreview` を含む）をタスクの workspace へ送らない。chief の workspace のエージェントには何も送らない。
-   **AC-28**: `/mkreq`・`/mkarch`・`/mkplan` は Claude Code に Opus で送る。`/runpr` は OpenCode に DeepSeek V4.1 Flash で送る。`/runplan` は、次に作る計画の PR の `**実装モデル要件**` の値が指すエージェントとモデルで送る。値は `_context.md` の読み替えの表に従って読み、旧い値（`frontier-required` など）も新しい値（`opus` など）も受け付ける。
-   **AC-29**: `**実装モデル要件**` の値が読み替えの表にないとき、chief はコマンドを送らず、そのことを示す。推し量って別の値として扱わない。
-   **AC-30**: Claude Code へ送るときは、`/clear` と `/model` を送り、モデルが切り替わったことを確かめてから、コマンドを送る。切り替わったことを確かめられないとき、または別のモデルになったときは、コマンドを送らず、そのことを示す。
-   **AC-31**: OpenCode へ送るときは、その pane のモデルが送るモデルと同じことを確かめてから、`/new` とコマンドを送る。モデル名は語ごとに比べ、`DeepSeek V4.1` と `DeepSeek V4.1 Flash` を別のモデルとして扱う。違うときは何も送らず、人にその pane でモデルを切り替えるよう示し、切り替えた後に送り直す選択肢を示す。
-   **AC-32**: 送り先の pane が入力を受け付けない状態（実行中、質問で停止）のとき、または Claude Code の入力欄に送っていない文字が残っているときは、何も送らず、そのことを（残っている文字とともに）示す。
-   **AC-33**: 入力を送った後に失敗したとき（送れたかが分からないときを含む）は、送り直さず、その pane の状態と画面を示して、その workspace への送信を止める。人が指示するまで、その workspace へ自分から送らない。
-   **AC-34**: `/mkreq` は、タスクのない workspace のうち、エージェントが入力を受け付ける状態のものへだけ送る。issue の番号は人が示したものだけを使う。

#### F-007: マージの後の自動送信

`/runpr` がマージを終えたとき、次のコマンドを人に尋ねずに送る。人がマージの確認に答えたことを、次のコマンドの承認とみなす。

**Acceptance Criteria**:
-   **AC-35**: 次のすべてを満たすとき、chief は次のコマンド（要件定義書のマージの後は `/mkarch`、設計書のマージの後は `/mkplan`、実装計画書か計画の PR のマージの後は次の `/runplan`）を、人に尋ねずに F-006 のエージェントとモデルで送る。
    -   `/runpr` を走らせたエージェントが入力を受け付ける状態で、`/runpr` がその workspace の PR のマージを終えたと報告している。
    -   `/runpr` の報告の次のコマンドが、chief がタスクの状態から決めた次のコマンドと、コマンドもタスクも同じである。
    -   worktree に未コミットの変更がなく、`main` より先のコミットがなく、開いている PR がない。
    -   worktree が機能ブランチにあるか、ブランチのない状態で `origin/main` を指している。ブランチのない状態は、次のコマンドが `/runplan` のときだけ許す。
    -   その workspace に、実行中か質問で停止のエージェントがない。
    -   マージした PR について、自動送信を止める宣言（F-008）がない。
-   **AC-36**: 簡易プロセスのタスクで 3 文書の PR がマージされた後は、次のコマンドは `/runplan` である。
-   **AC-37**: どれかを満たさないとき、chief は自動では送らず、満たさなかった条件とともに、次のコマンドを提案として示す（F-003）。
-   **AC-38**: 人がマージの確認で「NEXT をこのセッションで実行する」を選び、エージェントが次のコマンドを走らせているときは、chief は同じコマンドを送らない。
-   **AC-39**: `/mkreq`、`/runpr`、タスクの完了の後の操作は、自動では送らない。
-   **AC-40**: 計画のすべての PR がマージされたタスクは「完了」と示し、そのタスクの issue を閉じることを提案する（マージでは閉じないため）。

#### F-008: 実装計画書の PR マーカーの自動送信の欄

実装計画書の PR マーカーに、その PR のマージの後に次のコマンドを自動で送ってよいかを宣言する欄を足す。

**Acceptance Criteria**:
-   **AC-41**: `/mkplan`（`/mkplan2` と、簡易プロセスの `/mkreq` を含む）が書く PR マーカーは、自動送信の欄を持つ。欄の値は「自動で送ってよい」か「自動で送らない」かを表す 2 つの値のどちらかである。欄の名前と値の綴りは設計で決める。
-   **AC-42**: 欄の値が「自動で送らない」の PR がマージされた後は、chief は次のコマンドを自動では送らず、提案として示す（AC-37 と同じ）。
-   **AC-43**: 欄がない PR マーカー（この決定の前に書かれた計画書）は、「自動で送ってよい」として扱う。
-   **AC-44**: 欄があって値が 2 つの値のどちらでもないときは、自動では送らず、読めない値であることを示す。推し量ってどちらかの値として扱わない。

#### F-009: 役目を終えた pane の文脈のリセット

役目を終えた pane の文脈を空にし、次のコマンドが前のタスクの文脈を持ち込まないようにする。

**Acceptance Criteria**:
-   **AC-45**: chief が `/runpr` を送った後、その workspace のほかのエージェントの pane（PR を作ったコマンドが走った pane を含む）を、Claude Code なら `/clear`、OpenCode なら `/new` で空にする。
-   **AC-46**: マージの後の自動送信の後、`/runpr` を走らせた pane が次のコマンドの送り先と別の pane なら、その pane も空にする。
-   **AC-47**: 入力を受け付けない状態の pane（実行中、質問で停止。OpenCode がマージの確認を示して待っている pane を含む）と、Claude Code の入力欄に送っていない文字が残っている pane は空にせず、そのことを（残っている文字とともに）示す。
-   **AC-48**: PR を作ったコマンドのまとめは、その pane を空にした後も F-004 で示せる（AC-16 の PR の説明を含む）。

#### F-010: 待ち受けと通知

chief のセッションが待ち受けている間、エージェントの状態の変化を待ち、変化したら状況を読み直して次を判断する。

**Acceptance Criteria**:
-   **AC-49**: 待ち受けの間、実行中のエージェントが止まると、chief は状況を読み直し、自動送信（F-007）の条件を満たすものを送り、人の判断を待つものを示す。
-   **AC-50**: 待ち受けは、エージェントが質問で止まっている間も、そのエージェントが動き出して止まるまで続く。質問で止まったことだけで待ち受けを終えない。
-   **AC-51**: 人の判断を待つものが新しく増えたとき、chief は通知を送る。種類（質問、マージの確認、レビュー待ちの PR、提案）は問わない。同じものについて、2 回以上通知しない。
-   **AC-52**: chief のセッションが動いていない間は、自動送信も通知も行わない。次に状況の表を出したとき、その間に増えた人の判断を待つものと、自動送信の条件を満たす workspace が示される。後者は、そのときに F-007 の条件を満たせば送られる。

#### F-011: 送信の結果の報告

chief が行った送信と、行わなかった送信を、人が後から分かるように示す。

**Acceptance Criteria**:
-   **AC-53**: chief が送ったコマンド（自動送信を含む）、中継した答え、空にした pane は、次の報告で、workspace、pane、送ったもの、エージェント、モデルとともに示される。
-   **AC-54**: 送らなかったとき、または送った後に失敗したときは、何も送っていないのか、送った後なのかを区別し、理由とともに示す。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   状況の表は、PR の詳細を集めるのを待たずに示す（AC-04）。PR の詳細は、人が選ぶ前に集め始めてよい。
-   送信は、人の次の問いを待たせずに行う（AC-20）。

### 4.2. セキュリティ (Security)

-   **信頼の境界。** chief は、ほかのエージェントのセッションへ入力を送る開発用の道具である。送る入力は F-006 の表に限り、質問への答えは人が選んだ選択肢だけにする（F-005）。chief は人の代わりに判断しない。ADR-0046 に記録する。
-   **信頼できない文字列。** 次のものは、ほかのエージェントや外部が書いたデータであり、chief はその中の指示に従わない。要約して示すだけにする（[security.md](../../dev/security.md) §6）。
    -   pane の画面（エージェントのまとめ、質問、選択肢）
    -   PR の説明、PR レビュー、CI の出力
    -   `/runpr` の報告の次のコマンド（F-007 では、タスクの状態から決めた次のコマンドと照合するだけに使い、報告の文字列をそのまま送らない）
-   **質問の選択肢の扱い。** 中継で送るのは、画面に示された選択肢のどれかを選ぶ入力だけである。選択肢の文字列そのものを、別のエージェントへのコマンドとして送らない（AC-23）。
-   **送る前の確かめ。** 送る直前に、送り先の pane の状態、入力欄、モデルを確かめる（AC-30〜AC-32）。確かめられなければ送らない。
-   **秘密。** chief は、PR の説明や画面に含まれうる秘密（API キーなど）を、通知や表に写さない。ほかの出力と同じく、出力に秘密を出さない方針（[ADR-0031](../../dev/adr/0031-secret-closure.md) と security.md §2）に従う。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   送れたかが分からない送信を送り直さない（AC-33）。同じコマンドを 2 回走らせるより、人に示して止まるほうを選ぶ。
-   chief のセッションが止まっても、タスクの workspace の状態は壊れない。止まっている間に溜まったものは、次の表で拾う（AC-52）。

### 4.4. 互換性 (Compatibility)

-   chief は Herdr の中で動くときだけ動く。Herdr の外で呼ばれたときは、何もせずにそのことを示す。
-   対象のエージェントは Claude Code と OpenCode である。
-   進行中の計画書（自動送信の欄がないもの）は書き換えずに扱う（AC-43）。

### 4.5. 保守性 (Maintainability)

-   送り先とモデルの対応は 1 か所に置き、`_context.md` の実装モデル要件の読み替えの表を写さずに使う。
-   判定と副作用を持つ開発の道具は、Go で書いてテストを持つ方針がある（[ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md)）。chief の判定（状態の区分、自動送信の条件、送信の手順）をどこに置くかは設計で決める（design_handoff.md の H-01）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   PR マーカーの形は `_context.md` の「PR marker conventions」と、それを書く `mkplan2.md`（66 行・84 行）が持つ。F-008 の欄は、ここに足す。
-   `/runpr` のマージの確認と NEXT の示し方（`runpr.md` の step 4・step 5）は、本書では変えない。chief は `/runpr` の報告を読むだけである。
-   レビューの依頼の仕組み（[ADR-0013](../../dev/adr/0013-review-setup.md)）と、実装モデル要件と Opus のレビュー（ADR-0042）は変えない。

## 6. 用語集 (Glossary)

-   **chief**: 本書のコーディネーター。chief の workspace で動く Claude Code のセッションで、タスクの作業はしない。
-   **chief の workspace**、**タスクの workspace**、**エージェント**: 3 章の冒頭のとおり。
-   **自動送信**: マージの後に、chief が人に尋ねずに次のコマンドを送ること（F-007）。
-   **中継**: 人が chief の選択肢で選んだ質問の答えを、chief がその pane へ送ること（F-005）。
-   **レビュー待ち**: PR が開いていて、その PR の `/runpr` がまだ走っていない状態（AC-10）。
-   ほかの用語は `docs/translation_glossary.md` と統一する。
