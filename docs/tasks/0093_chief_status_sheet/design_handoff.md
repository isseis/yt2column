# 設計への申し送り（0093）

要件定義の時点で挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目にとった方針か、当てはまらない理由を記録する。

## H-01: 道具の出力の形、対応表の置き場所、`--protocol` の番号

**懸念:** 決まっていないことが 3 つある。
-   行ごとの急ぎの度合い、番、文書、進み具合（AC-20）を、道具の出力（`internal/chief/output.go` の `RowOutput`）にどの名前と値で加えるか。
-   対応表（3.1）を道具のどこに置くか。
-   定義が知らない値を道具が返したとき、どう示すか。

`/chief` の定義と道具は、`--protocol` の番号で版を照合する（`.claude/commands/chief.md:52-56`）。

**なぜ重要か:** 出力を変えても番号を変えなければ、古い定義が新しい道具の出力を読み、印を示さない。逆の組み合わせでも同じことが起きる。対応表が複数の場所に分かれると、印と並べ方が食い違いうる。

**候補:**
-   値は ASCII の列挙の名前にし（たとえば `urgency: now|later|wait`、`turn: human|ai|none`）、日本語の表示は定義が対応させる。
-   対応表は、急ぎの度合いと番を 1 つの関数で決め、並べ替えもその結果を使う。
-   出力を変えるので、番号を上げる。

**関連:** F-001・F-002・F-006、AC-02・AC-15・AC-20・AC-21

## H-02: Claude Code の pane のセッションの記録を見つけられないとき

**懸念:** AC-11 は、実行中の Claude Code の pane について、セッションの記録の人の最後の入力を読む。今、記録の場所は worktree のパスとセッションの識別から作り（`internal/chief/transcript.go:47-69`）、作れないパスでは `unsupported_path` で送らない。セッションの識別が Herdr から読めないこともありうる。

**なぜ重要か:** 記録を見つけられないことを送信の失敗と同じに扱うと、表示のためだけの読み取りで、行の状態や送信が変わりうる。

**候補:** 見つけられないときは、AC-11 の「決まらない」にし、行の状態、`problems`、送信の判断を変えない。

**関連:** F-003、AC-11、4.2

## H-03: 絵文字の幅と表の列のそろえ方

**懸念:** 🔴・🟡・🟢 は、端末によって 1 文字分にも 2 文字分にも描かれ、表の列がずれうる。

**なぜ重要か:** 列がずれると、一目で見分けるという目的（2.1）を損なう。

**候補:** 印の列を表の最初の列に置き、ずれが後ろの列だけに及ぶようにする。Claude Code の端末で Markdown の表として描かれるときの見た目を、実地の確かめで見る。

**関連:** F-001、AC-01

## H-04: 自動送信の周の行と進行の位置

**懸念:** `tick` は、自動送信を送った周の行を、その場で「実行中」に書き換え、送ったコマンドを `Running` に入れる（`internal/chief/tick.go:85-96`）。送った後で確かめに失敗した行は、「要確認」に書き換える（同じ箇所）。進行の位置（AC-10）と急ぎの度合いは、この書き換えの後に決める必要がある。

**なぜ重要か:** 書き換えの前に決めると、同じ行が「作成待ち」と「実行中」を同時に示しうる。

**候補:** 急ぎの度合い、番、進行の位置を、行の状態と記録が出そろった最後に 1 か所で決める。並べ替え（AC-15）もその後に行う。

**関連:** F-001・F-003・F-004、AC-10・AC-15

## H-05: 0092 の削除の提案との実装の順

**懸念:** AC-05 と AC-07 の規則 2 は、0092 の削除の提案に依る。0092 とこのタスクのどちらを先に実装するかは決まっていない。0092 の行は、HEAD が detached なので、今の規則（`internal/chief/state.go:434`）では使っていないか残った worktree の行（`Idle`）になりうる。

**なぜ重要か:** 後に実装する方がこの AC を確かめないと、削除の提案の行が表の最後に「待つ」として並ぶ。

**候補:** 0092 が先に入ったときは、このタスクで、削除の提案の行を使っていないか残った worktree の行から外し、印を付ける。このタスクが先に入ったときは、0092 の計画書に、AC-05 を満たす手順と確かめを足す。

**関連:** F-001・F-003・F-004、AC-05・AC-07・AC-15

## H-06: 書き足し中のセッションの記録による表示の入れ替わり

**懸念:** 実行中の Claude Code の記録は書き足されている途中でありうる。今の読み取り（`internal/chief/screen_transcript.go:160-170`）は、1 つの JSON の値でない行があれば、記録全体を読めないものとする。書きかけの最後の行も、これに当たりうる（4.3）。

**なぜ重要か:** 周ごとに「作成中」と「実行中」が入れ替わると、一目で分かるという目的（2.1）を損なう。ただし、受け付ける形を広げて書きかけの行を飛ばすと、0088 の境界（人の入力でありうる行を飛ばさない）を緩めることになる。

**候補:** 改行で終わっていない最後の行は、まだ書かれていない行として読む前に除く。改行で終わる行には、今の規則をそのまま当てる。これが境界を広げないかを、0088 の境界と比べて決める。

**関連:** F-003、AC-11、4.3
