## 1. 設計の全体像

本タスクは文書だけを変える。用語集に 5 つの語を足し（[01_requirements.md](01_requirements.md)（以下、要件書）F-001）、その語で chief のガイドの 3.1 を書き直す（F-002）。ADR-0046 の決定とサンプルの説明（F-003）と、0102・0105 の承認済みの文書（F-004）の古い用語は、編集上の訂正として直す。chief の道具、`/chief` の定義、protocol 番号は変えない（F-005）。

**設計原則:**

-   **語の置き換えは、決まった対応の表に従う（3.2 節）。** 文書ごとに言い換えを考えると、同じ概念が文書ごとに違う語になるためである。言い回しは、置き換えた語が日本語として自然に読める範囲でだけ変える。
-   **意味は変えない。** 値の集合、各値の決まり方、表示する文字列、例外の範囲、決定は変えない。変えるのは呼び名だけである。
-   **直す場所は中身で示す。** 0102 の PR-1（#1012）が同じファイルを変えるので、行番号は実装の時点でずれうる。本書の行番号は、コミット `910bb12b`（`origin/main`）での目安であり、実装では、本書が示す文の中身で場所を探す。

**設計の際に決めたこと（2026-11-19）:**

-   なし。人に聞くべき未決の判断はなかった。変える文書とその範囲、語の名前は、要件定義で人が選んだ（要件書 1 章の「要件定義の際に決めたこと」）。英語の訳語（3.1 節）は、用語集の既存の訳語と重ならないものを選んだ。置き換えの対応（3.2 節）は、要件書 F-001 の定義から決まる。
    -   ADR: なし。本タスクの中で閉じる。

概念モデルとシステム構成の Mermaid の図は省く。文書の用語を変えるだけで、コンポーネントの関係は変わらない（`docs/dev/conventions/requirements_process.md`「Simple Process」の「May be omitted」）。

### 3.2. 古い用語の置き換えの対応

すべての文書で、次の対応で置き換える（AC-11・AC-12・AC-13・AC-15）。0102 は、道具の出力の値（「文書」と「進み具合」）と、表に示す語（「文書の段」と「状態の文字列」）を分けて呼ぶ。対応も、この 2 つの層を分けて保つ。

| 古い用語（chief の状況の表の意味） | 新しい用語 |
|---|---|
| 進行の位置（組） | 作業項目の表示と状態の詳細 |
| 進行の位置の文書、行の値を指す「文書」（例：`Row.Position.Document` を指す「行の文書」） | 作業項目の表示 |
| 文書の段（0102 とガイドで、表に示す語を指すもの。例：0102 の AC-13 の表、AC-26 の例外の範囲） | 作業項目の文字列 |
| 上の 2 つのうち、作業項目でない値（-・なし・要確認）を含まない箇所（例：「文書の段と違うコマンドを人が打っている」の「文書の段」。ここは作業項目だけを指す） | 今の作業項目 |
| 進み具合 | 状態の詳細 |
| 英語（CLAUDE.md・`chief.md` の文）で、上を訳した語（例：document stage） | work item display、work item string、current work item、state detail |

-   作業項目でない値を含むかで迷ったときは、「今の作業項目」にせず、「作業項目の表示」か「作業項目の文字列」にする。範囲が広い側に倒せば、例外の範囲などを狭めずに済むためである（AC-16）。値か表に示す語かは、0102 の文書が書き分けているとおりに保つ。
-   表の列の見出し「文書」「状態」は、表の見出しの文字列なので置き換えない（要件書 1 章）。「『文書』の列」のように列を名指す箇所も、そのまま残す。
-   コードの名前と出力の項目（`PositionDocument`・`position.document`・`chief.md` の英語の "position" など）は置き換えない（F-005）。
-   「進み具合」は、chief の状況の表の意味の箇所だけを置き換える。計画書の PR の進み具合のチェックボックス（`docs/dev/adr/0013-review-setup.md:24`・`docs/dev/adr/0035-language-policy.md:71` など）や、拡張の工程の進み具合は置き換えない（要件書 2.3 節）。
-   「文書」も、chief の行の値を指す箇所だけを置き換える。タスクの文書（要件定義書など）を指す「文書」はそのまま残す。
-   0102 の設計書の用語の段落（今の `02_architecture.md:15`）は、0093 設計書の用語を「同じ意味で使う」と述べ、その中に「進行の位置・文書の段・進み具合」を挙げる。「進行の位置」と「進み具合」は新しい用語に置き換える。「文書の段」は、0093 設計書の内部の段（`docStage`）を指すので、置き換えない（AC-15 の除外）。

「進行の位置」の段落に替える 3 つの段落の中身：

1.  **タスクの進行。** タスクは、決まった順の作業項目を 1 つずつ進む。通常の進め方では、要件定義書の作成 → アーキテクチャ設計書の作成 → 実装計画書の作成 → 計画書の PR-1 → PR-2 → … と進む。簡易な進め方では、3 つの文書を 1 つの作業項目で作り、その後に計画書の PR が続く。PR マーカーのない計画書の PR は PR-1 である（AC-06）。
2.  **作業項目の表示。** 今の作業項目（まだ終わっていない最初の作業項目）か、作業項目でない値で、`origin/main` のタスクの文書から決まる。今の作業項目は、要件定義書・設計書・計画書・PR-N（計画書の PR のうち、まだマージされていない最初のもの）のどれかである。作業項目でない値は 3 つある。-（タスクのないブランチ）、なし（すべての作業項目が終わった）、要確認（今の作業項目を決められない。fetch や文書の読み取りに失敗した、HEAD が detached など）である（AC-07）。簡易な進め方のタスクは、3 つの文書の PR がマージされるまで「要件定義書」と示される。`origin/main` の文書からは、マージの前に進め方が分からないためである（AC-08）。
3.  **状態の詳細。** 行の状態を、実行中のコマンドやマージの確認かどうかで細かくしたもので、作業項目のない行にも示す。値は、今の「進行の位置」の段落の後半と同じ（作成待ち（表では「次を提案」と示す）・作成中・`/runpr` 実行中・実行中・マージの確認待ち・質問で停止・レビュー待ち・タスク完了・要確認）である（AC-09）。

「調べ方」に足す文：作業項目の表示は出力の `position.document`（PR-N の N は `position.plan_pr`）に、状態の詳細は `position.progress` に入る（AC-10）。

段落の言い回しは、実装で整えてよい。ただし、値の集合と各値の決まり方は、今の「進行の位置」の段落から変えない（AC-07・AC-09）。

**先に変わったときの扱い（AC-11・AC-18）。** 実装の PR を作るときに、0102 の PR-3（ガイドの 3.1 と 8 章）か 0105 の実装（AC-12 の書き足し）が先にマージされていれば、3.1 の構成が上の表の想定と違っている。そのときは、その時点の 3.1 に同じ内容（タスクの進行、作業項目の表示、状態の詳細、出力の項目の対応）を入れ、3.2 節の対応で古い用語を置き換える。0102 が書いた表の形（5 つの列と 2 行目）や 0105 が書き足した 4 点は、用語だけを替えて残す。
