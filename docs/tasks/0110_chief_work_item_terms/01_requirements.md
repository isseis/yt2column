## 1. 概要 (Overview)

**目的:** 本書は、chief の状況の表が示すタスクの進み方の用語を、「タスクの進行」と「作業項目」を土台に定義し直し、その用語を今の仕様を持つ文書と用語集にそろえる要件を定める。

**背景:**

-   タスク 0093 は、状況の表の各行に「進行の位置（文書 × 進み具合）」を示すことにした（[0093 要件定義書](../0093_chief_status_sheet/01_requirements.md)、`docs/dev/guides/chief_guide.md:82`）。この用語には、次の問題がある（issue #1006「背景」）。
    -   「進行の位置」は 2 つの値の組の名前である。その元になる「タスクがどう進むか」は、どこにも定義されていない。
    -   組の前半の「文書」は、要件定義書・設計書・計画書のほかに、PR-N（実装の PR）・なし・-・要確認の値もとる。文書でない値を「文書」と呼んでいる。ガイドは同じものを「文書の段」とも呼ぶ（`chief_guide.md:63`）。
    -   タスク 0105 の要件定義書のレビューでは、「文書の位置」がファイルのパスとも読めることが分かった。0105 では「進行の位置の文書」と呼んで定義するにとどめ、用語の整理はこの issue に回した（[0105 要件定義書](../0105_chief_post_merge_next_command/01_requirements.md) の 6 章、#996、PR #999）。
-   古い用語を、今の仕様として使っている文書は次のとおりである（コミット `910bb12b` の `origin/main` で確かめた）。
    -   `docs/dev/guides/chief_guide.md:57`・`:63`・`:64`・`:82`（3.1「状況の表の見方」）
    -   `docs/dev/adr/0046-chief-of-staff.md:79`・`:175`・`:182`（決定）と `:396`（経緯）
    -   `docs/dev/adr/0035-language-policy.md:72`（経緯。0102 が足す CLAUDE.md の例外の範囲を「文書の段など」と書く）
    -   `internal/chief/testdata/README.md:151`（サンプルの説明）
-   承認済みでまだ終わっていない 2 つのタスクの文書も、古い用語を使っている。
    -   タスク 0102（状況の表を道具が組む）は、計画書まで承認済みで、実装はまだ始まっていない（`03_implementation_plan.md` の PR-1〜PR-3 の「PR を作成した」がどれも未完了）。0102 は「文書」の列をなくし、その値を「タスク」の列の 2 行目に「要件」「設計」「計画」などの短い形で示す（[0102 要件定義書](../0102_chief_text_table/01_requirements.md) の AC-09・AC-13）。そのうえで、ガイドの 3.1 と CLAUDE.md の「Go Idioms」の例外の範囲に「文書の段」を書く（同 AC-24・AC-26）。何もしなければ、0102 の実装が、廃止したい語を今の仕様を持つ文書に書き込む。
    -   タスク 0105（`main` をチェックアウトした worktree のタスク）は、要件定義書が承認済みで、設計はまだである。AC-12 で、ガイドの進行の位置の説明（`chief_guide.md:82`）に 4 点を書き足す。用語は「進行の位置の文書」である（0105 要件定義書の 6 章）。
-   chief の道具と `/chief` の定義は、次の名前を使う。
    -   道具の出力：行の `position` の `document`・`plan_pr`・`progress`（`internal/chief/output.go:56-62`）
    -   コード：型 `PositionDocument`・`Progress`・`Position`（`internal/chief/position.go:35-87`）
    -   `/chief` の定義：表の列の見出し「文書」「状態」と、値の対応の表（`.claude/commands/chief.md:165-191`）
-   簡易な進め方のタスクは、3 つの文書の PR がマージされるまで、`origin/main` に要件定義書がない。そのため、表は「要件定義書」と示す（`internal/chief/position.go:256` の `stageNoRequirements` の規則）。マージの前は、`origin/main` を読んでも、タスクの進め方が分からない。

対応 issue: [#1006](https://github.com/isseis/yt2column/issues/1006)（関連: [#996](https://github.com/isseis/yt2column/issues/996)、タスク 0093・0102・0105）

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   chief の状況の表の行が何を示すかを、タスクの進行という土台から説明できる用語にする。
-   今の仕様を持つ文書と、これから実装する 0102・0105 の文書で、同じ概念を同じ語で呼ぶ。

### 2.2. スコープ (In Scope)

-   用語集への 3 つの語の追加と、古い用語の旧称の記載（F-001）
-   `docs/dev/guides/chief_guide.md` の 3.1 の書き直し（F-002）
-   ADR-0046・ADR-0035・`internal/chief/testdata/README.md` の用語の訂正（F-003）
-   0102 と 0105 の承認済みの文書の用語の、編集上の訂正（F-004）

### 2.3. スコープ外 (Out of Scope)

-   道具の出力の項目、コードの名前、`/chief` の定義、表の列の見出し、表の示し方、protocol 番号の変更（F-005）。理由は 1 章の「要件定義の際に決めたこと」にある。
-   簡易な進め方のタスクを、3 つの文書の PR のマージの前に、要件定義書と区別して示すこと。ブランチの文書を読む新しい仕組みが要る（1 章）。
-   マージ済みで終わったタスク（0092・0093）の文書と、`internal/chief/testdata/` の実際のサンプル（transcript など）の変更。その時点の記録である。
-   「進み具合」を、chief の状況の表の外の意味（拡張の工程、計画書のチェックボックスなど）で使う箇所の変更。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 用語集に語を足す

`docs/translation_glossary.md` に、次の 3 つの語を足す。

**Acceptance Criteria**:
- **AC-01**: 用語集に「タスクの進行」がある。定義は次の 3 点を述べる。タスクは、決まった順の作業項目を 1 つずつ進む。通常の進め方の順は、要件定義書の作成 → 設計書の作成 → 計画書の作成 → 計画書の PR-1 → PR-2 → … である。簡易な進め方では、3 つの文書を 1 つの作業項目（3 つの文書の作成）で作り、その後に計画書の PR が続く。
- **AC-02**: 用語集に「作業項目」がある。定義は、タスクの進行の 1 つの単位であることと、「今の作業項目」がまだ終わっていない最初の作業項目であることを述べる。備考に、旧称として「進行の位置の文書」と「文書の段」を記す。
- **AC-03**: 用語集に「作業項目の状態」がある。定義は、今の作業項目がどこまで進んだか（作成待ち・作成中・レビュー待ち・マージの確認待ち・質問で停止など）であることを述べる。備考に、旧称として、chief の状況の表での意味に限った「進み具合」を記す。行が示す今の作業項目とその状態の組の旧称「進行の位置」も、3 つの語のどれかの備考に記す。
- **AC-04**: 3 つの語は、用語集の既存の語（ステージ・工程・フェーズなど）と同じ英語の訳語を持たない。

#### F-002: ガイドの 3.1 を新しい用語で書き直す

`docs/dev/guides/chief_guide.md` の 3.1「状況の表の見方」を、F-001 の用語で書き直す。

**Acceptance Criteria**:
- **AC-05**: 3.1 は、タスクの進行（作業項目の順）を、通常の進め方と簡易な進め方のそれぞれについて述べる。
- **AC-06**: 3.1 は、表の「文書」の列が今の作業項目を示し、それが `origin/main` のタスクの文書から決まることを述べる。値は、要件定義書・設計書・計画書・PR-N（計画書の PR のうち、まだマージされていない最初のもの）と、作業項目でない 3 つの値である。3 つの値とその意味は、-（タスクのないブランチ）、なし（すべての作業項目が終わった）、要確認（今の作業項目を決められない。fetch や文書の読み取りに失敗した、HEAD が detached など）とする。示す値の集合と各値の決まり方は、書き直す前の `chief_guide.md:82` と同じである。
- **AC-07**: 3.1 は、簡易な進め方のタスクで、3 つの文書の PR がマージされるまで、今の作業項目が「要件定義書」と示されること、およびそのわけ（`origin/main` の文書からは進め方が分からない）を述べる。
- **AC-08**: 3.1 は、表の「状態」の列が作業項目の状態を示すことを述べる。値の集合と決まり方は、書き直す前の `chief_guide.md:82` と同じである。
- **AC-09**: 3.1 の「調べ方」は、今の作業項目が道具の出力の `position.document`（PR-N の N は `position.plan_pr`）に、作業項目の状態が `position.progress` に入ることを述べる。
- **AC-10**: 実装の PR のマージの時点で、ガイドに、chief の状況の表の意味での「進行の位置」「文書の段」「進み具合」が、今の用語として残らない。0105 の AC-12 や 0102 の AC-24 による書き足しが先にマージされていれば、その部分も含む。

#### F-003: ADR とサンプルの説明の用語を直す
