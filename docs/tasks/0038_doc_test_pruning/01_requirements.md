## 1. 概要 (Overview)

**目的:** 本書は、文書のテストのうち、自然言語の文の意味を確かめようとするものと、固定しても防げる誤りのない文言を固定するものを削除するための要件を定義する（[#455](https://github.com/isseis/yt2column/issues/455)）。あわせて、文書のテストを述べる記述を削除の結果に合わせ、同じ種類のテストを今後足さないための方針と手順の規則を定める。

**背景:**

このプロジェクトには、文書（`README.md`、`CLAUDE.md`、`AGENTS.md`、`docs/`、`.claude/commands/`、`prompts/README.md` など）を読んで、その内容を確かめるテストが多くある。その一部は、自然言語の文に特定の文字列が含まれる、または含まれないことを確かめている。

この形の確かめには、2 つの問題がある（issue #455）。

-   **意味を保証できない。** 必須の語が含まれることしか確かめないので、意味を反転させた文（「比べない」→「比べる」）でも通る。
-   **言い換えで壊れる。** 意味が同じでも、文言を直すとテストが落ちる。文書を直すたびに、テストのリテラルも直すことになる。

タスク 0035 の PR #438 のレビューで、同じ理由から、AC-17 の検証方法を `static` から `manual`（PR のレビューでの読み合わせ）に改めた（`docs/tasks/0035_fixprguard_branch_config/03_implementation_plan.md` の `Comments`、2026-10-22 (decision)）。同じ種類のテスト `TestGuideDescribesConfigScope`（`cmd/fixprguard/docs_test.go:526`。0035 AC-18 の検証方法）は残っており、[#440](https://github.com/isseis/yt2column/issues/440) がその削除を求めている。本タスクは、この判断を文書のテスト全体に広げる。

今の手順の規則は、自然言語の記述を定める AC にも `test` か `static` の検証方法を求めている。

-   `.claude/commands/mkplan.md:74`: AC ごとに `test` か `static` を 1 つ以上求め、`manual` は「補うだけで代わりにならない」とする。
-   `.claude/commands/mkplan.md:88`: 文書だけの AC に、`rg` で語の有無を確かめる検証の作業を求める。
-   `.claude/commands/mkplan.md:122`: 計画のレビューの確認項目で、同じ規則を確かめる。
-   `.claude/commands/runplan.md:78`・`:158`・`:213`: PR グループの確認と、タスクの最後の確認で、同じ規則を確かめる。
-   `docs/dev/developer_guide/requirements_process.md:239`: 同じ規則を述べる。

そのため、文書の記述を定める AC にも、語の有無を確かめる `static` の文書のテストが書かれてきた。

2026-10-23 の `7b26533` で調べた、文書のテストのあるファイルは次のとおりである。issue #455 の一覧にないものには「（追加）」と記す。

-   Go: `cmd/fixprguard/docs_test.go`、`cmd/yt2column/docs_test.go`、`cmd/yt2column/copied_transcript_docs_test.go`、`cmd/yt2column/extension_docs_test.go`、`cmd/yt2column/fixpr_docs_test.go`、`cmd/yt2column/output_layout_docs_test.go`、`cmd/yt2column/codex_review_docs_test.go`（追加）、`cmd/yt2column/run_test.go` の `TestRunEvaluationProcedureFlags`（`:2614`。追加）、`cmd/yt2column-server/docs_test.go`、`cmd/yt2column-nmhost/main_test.go` の `TestReadmeHostExitCodes`（`:408`）、`internal/pipeline/pipeline_test.go` の `TestPackageReferenceListsPackages`（`:671`）・`TestPromptsREADMEMatchesContract`（`:755`）、`internal/pipeline/relay_guard_test.go` の `TestSharedTokenRemoved`（`:397`。追加）
-   拡張（node）: `extension/test/metadataDocs.test.ts`、`extension/test/serverReasons.test.ts`。`extension/test/ciChanges.test.ts` は文書を読まないが、拡張の CI ジョブを起動する条件として `README.md`・`docs/dev/security.md` を確かめている（`:27-28`）。この条件は、node のテストがこの 2 つの文書を読むことに対応する（`extension/scripts/has-extension-changes.sh:8-10`・`:17`）。

同じ時点で、これらのテストを検証方法として挙げている行は、`docs/tasks/*/02_architecture.md`・`03_implementation_plan.md` の AC の表に 120 行あった（24 の承認済みのタスクと、取り下げたタスク 0029）。

承認済みでまだ実装していない計画にも、文書のテストを加えると定めたものがある。タスク 0034 の `03_implementation_plan.md` は、次の 3 つを定めている。`passage`・`checkPassages` で語の有無を確かめる `TestGuideDescribesIgnoredFiles` を加えること（`:357`）。`TestFixprDocContract` に `requirePhrases` の行を加えること（`:324`）。`TestGuideDescribesConfigScope` が確かめる語句を保つこと（`:335`）。

文書のテストを述べる記述には、次のものがある。

-   `doc-guard` CI ジョブの対象パッケージ（`.github/workflows/ci.yml:183-184`、`CLAUDE.md:311-315`）
-   `fixprguard_guide.md`・`fixprguard_guide.ja.md` の 10 章で、文書のテストに言及する箇所（`fixprguard_guide.ja.md:350-357`）

`docs/dev/developer_guide/test_organization.md` の節の見出しは、`testutil/`・`test_helpers.go`・新しい補助の指針・golden files である（同 `:5`・`:43`・`:65`・`:107`）。文書のテストは扱っていない。

対応 issue: [#455](https://github.com/isseis/yt2column/issues/455)（関連: [#440](https://github.com/isseis/yt2column/issues/440)。タスク 0035・[#431](https://github.com/isseis/yt2column/issues/431)）

**本書の記述範囲:** 本書は、どの確かめを残し、どれを削除するかの基準と、削除に伴って変わる文書・手順の規則・CI の振る舞いを定める。基準をテストごとに当てはめた結果（残す・削除する・一部を削除する、とその理由の一覧）、補助の型・関数の整理の手段、削除の順序、PR の分け方は、設計（`02_architecture.md`）と実装計画で決める。要件の段階で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #455 で決めたこと:**

-   **削除するもの:** 自然言語の文の意味を確かめようとするテスト（否定や言い換えを見分けられない）と、文言を固定しているが、固定しても防げる誤りのないテスト。
-   **残すもの:** 文書の中の値をコードや設定の値と照合するテスト（フラグの一覧、終了コード、プロトコル番号、拡張機能の ID、権限、`make` のターゲット、拒否理由の表など）、見出しの構造を確かめるテスト、文書から実行可能な例を取り出して実際に解析・実行するテスト。自然言語の意味ではなく、機械的に照合できる値を確かめるからである。
-   **補助の削除:** 削除したテストだけが使っていた補助の型・関数も取り除く。ほかのテストが使うものは残す。
-   **カバレッジの確認:** 削除のたびに `go tool cover -func` の関数ごとの結果が変わらないことを確かめ、記録する（`CLAUDE.md`「Deleting a test is a claim that must be checked」）。
-   **タスクの文書:** 削除したテストをタスクの文書が AC の検証方法として挙げている場合は、その AC の検証方法を `manual` に改め、記録する。
-   **一覧:** テストごとに「残す／削除する／一部を削除する」と理由を一覧にし、PR の説明に載せる。
-   **方針:** 同じ種類のテストを今後足さないよう、`CLAUDE.md` の「Testing Strategy」に方針を一項加える。

**要件定義の際に決めたこと（2026-10-23）:**

-   **#440 を取り込む:** `TestGuideDescribesConfigScope` の削除と、タスク 0035 の AC-18 の検証方法の改訂を、本タスクで行う。本タスクの基準にそのまま当たり、分けると同じ判断を 2 回レビューすることになるためである。#440 は本タスクの完了時に閉じる（F-008）。
-   **直書きのリテラルの存在の確かめは削除する:** 文書が、テストに直書きした識別子（テスト名を含む）・パス・リンク・値・エラーの文言・コマンドや jq の断片を含むこと、またそれらの語の順序を確かめるもののうち、期待値をコードや設定から導いていないものは削除する。直書きのリテラルの存在の確かめは、文言の固定と変わらないためである。期待値をコードや設定から導いているものだけを、値の照合として残す（F-001 の D2）。
-   **タスクの記録の確かめは削除する:** 手動の確認の表が埋まっている、記入待ちの印が残っていない、評価の記録の行が揃っている、`Status`・`Comments` の記録やほかの文書へのリンクがある、といったタスクの記録の確かめは削除する。記録はタスクの完了後に変わらず、確かめに意味があるのは実施の間だけだからである（F-001 の D4）。
-   **文書の側の不在の確かめは削除する:** 削除した識別子・古い語・使わなくなったコマンドが文書に含まれないことを確かめるものは削除する。「〜は使わない」という禁止の文と、本当に使っている箇所を区別できないためである。Go のコードや拡張のソースに識別子が含まれないことを確かめる、コードの確かめは残す（F-001 の D3）。ただし、エージェントが実行する手順についての例外（K5）がある。
-   **自動レビュアーの一覧の確かめは例外として残す:** `.claude/commands/_context.md` の自動レビュアーの一覧と、完了を待つ PR レビュアーの名前を、テストに直書きした期待値（`cmd/yt2column/fixpr_docs_test.go` の `wantReviewers` など）と照合する確かめは、直書きの期待値でも残す。この一覧は、`/fixpr`・`/runpr` がどの著者のスレッドを信頼するかを決める、設定に当たる値である。`fixprguard_guide.ja.md:350-355` は、一覧を変えるときは `_context.md` とテストの期待値を同じコミットで変え、期待値の確かめを緩めないよう定めている。本タスクはこの手順を保つ（F-001 の K4）。
-   **エージェントが実行する手順を守る確かめは例外として残す:** `.claude/commands/` の手順について、次の 2 つの確かめは、直書きのリテラルや文書の側の不在に当たる場合でも残す。1 つは、ガードツール `fixprguard` の呼び出しが決められた場所にあることの確かめである（`TestFixprguardCallSites`、`TestDocumentedInvocationsParse` の呼び出しの一覧）。もう 1 つは、ガードツールを迂回するコマンド（`git commit -m`、`git add -A` など）がないことの確かめである（`TestRemovedCommandLiterals` の該当する部分）。これらは自然言語の説明ではなく、エージェントが実行する手順の中身である。誤って消えると、`/fixpr`・`/runpr` の信頼の境界が実行時に働かなくなる。一方、手順の中の文の固定（`TestPostingPathsCheckMention` の文など）と、`Authorization` の節のコマンド名の一覧は削除する（F-001 の K5）。
-   **手順の規則を改める:** 背景に挙げた `mkplan.md`・`runplan.md`・`requirements_process.md` の規則を改め、文書の自然言語の記述を定める AC は、`manual` だけで確かめてよいとする。今の規則のままでは、これからの計画でも同じ種類の文書のテストが書かれ、過去のタスクの文書を `manual` に改めることとも矛盾するためである（F-007）。
-   **承認済みの文書は `approved` のまま記録する:** タスクの文書で AC の検証方法を `manual` に改めるときは、Status を `approved` のまま変えず、`Comments` に `(decision)` として本タスクでの変更を記録する。検証方法を変える決定は本タスクの要件で定め、本書の承認がその再承認に当たるためである。0035 の 2026-10-22 の記録が先例である。取り下げたタスク 0029 の文書は書き換えない（F-005）。
-   **承認済みで未実装の計画は、本タスクの実装の時点で扱う:** 本タスクの実装の時点で、承認済みの計画が次のどちらかを定めている場合を扱う。(a) F-001 の D1〜D4 だけに当たる文書のテストを加える。(b) 本タスクが削除するテストを保つ（今はタスク 0034）。そのテストがすでに実装されていれば、削除の対象に含める。まだ実装されていなければ、その計画から当該の作業を除き、対応する AC の検証方法を `manual` にして、`Comments` に `(decision)` を記録する。F-001 の K1〜K5 と D1〜D4 の両方に当たるテストは、D の部分を除いた形で加える。作ってすぐ削除する手間と、承認済みの計画が実行できなくなることの両方を避けるためである（F-006）。
-   **拡張の CI ジョブの起動条件を合わせる:** 削除の結果、node のテストが読まなくなった文書は、拡張の CI ジョブを起動する条件から外す。読まない文書の変更で拡張のジョブを走らせる理由がないためである（F-009）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   文書のテストに、自然言語の意味を確かめようとするものと、固定しても防げる誤りのない文言を固定するものを残さない。
-   コードや設定から導いた値との照合、見出しの構造、実行可能な例の解析・実行、という機械的に確かめられる文書のテストと、K4・K5 の例外を保つ。
-   見出しとコードから導いた値以外の文を、意味を変えずに言い換えるとき、テストを直さずに済むようにする。
-   削除したテストを挙げているタスクの文書、文書のテストを述べる記述、拡張の CI ジョブの起動条件を、削除の結果と一致させる。
-   同じ種類のテストを今後足さないよう、方針と手順の規則を改める。

### 2.2. スコープ (In Scope)

-   1 章の背景に挙げたファイルにあるすべての文書のテストに基準を当てはめ、削除または一部を削除すること（F-001・F-002）。
-   削除した確かめだけが使っていた補助の型・関数と、その単体テストの削除（F-003）。
-   カバレッジの確認の記録と、テストごとの一覧（F-004）。
-   削除した確かめを AC の検証方法として挙げている、承認済みのタスクの文書の改訂（F-005）。
-   承認済みで未実装の計画の扱い（F-006）。
-   文書のテストを述べる記述の更新と、`CLAUDE.md`「Testing Strategy」の方針の追加、手順の規則の改訂（F-007）。
-   #440 を閉じること（F-008）。
-   拡張の CI ジョブの起動条件の更新（F-009）。

### 2.3. スコープ外 (Out of Scope)

-   **直書きの期待値をコードから導く形に書き換えること、削除した確かめの代わりのテストを書くこと。** 新しいテストを書く作業になり、issue #455 の「洗い出して削除する」を超える。必要なら別の issue で扱う。
-   **文書を読まない確かめ。** 文書のテストの中にあっても、Go のコード・拡張のソース・設定ファイル（`.coderabbit.yaml` の値など）・`manifest.json`・プログラムの出力（`TestArtifactDocsContract`（`cmd/yt2column/docs_test.go:527`）の `run -h` の出力など）を確かめる部分は変えない。
-   **`doc-guard` CI ジョブの対象パッケージを増やすこと。** `cmd/yt2column-nmhost` の `TestReadmeHostExitCodes` は `doc-guard` ジョブの対象外である（`.github/workflows/ci.yml:184`）。この欠けは本タスクの削除とは関わりがないので扱わない。
-   **取り下げたタスク 0029 の文書の書き換え。** 取り下げた文書は記録として残す。
-   **過去のタスクの文書の、AC の検証方法を述べる箇所以外の本文。** 本文の作業の記録（実装のステップ、経緯）は記録として残す（F-005）。
-   **本タスクが削除しない確かめを指す、以前からある古い参照。** たとえばタスク 0010 の計画の `cmd/docs_test.go::TestReviewEvaluationRecords` のような古いパスの行は、本タスクの削除と関わる場合にだけ改める。
-   **用語集（`docs/translation_glossary.md`）の行の追加・削除。** 用語集の行を確かめるテストを削除しても、用語集そのものは変えない。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 残す確かめと削除する確かめの基準

文書のテストの各確かめを、次の基準で「残す」か「削除する」かに分ける。1 つのテストが両方を含む場合は、削除する確かめだけを取り除く（一部の削除）。

**値の出どころ:** K1 の「コードや設定から導いた値」は、テストが次のものから得た値をいう。

-   製品のコード（`_test.go` 以外の Go のコード、`extension/src/`）の定数・関数・パーサの結果
-   設定ファイルとリポジトリの構成（`Makefile`、`go.mod`、`.github/workflows/`、`extension/manifest.json`、`.coderabbit.yaml`、`testdata/` などのファイルやディレクトリの一覧）

文書（`_context.md` を含む）、テストのソース、テストに直書きしたリテラルは、値の出どころに当たらない。ただし、テストがコードの値と等しいことを確かめたリテラルは、コードから導いた値として扱う。

**残す確かめ:**

-   (K1) **値の照合:** 文書の中の値を、コードや設定から導いた値と照合する確かめ。照合の向きは問わない。値を文書から取り出すための手がかりの語（見出しや決まった言い回し）は、K1 の確かめの一部とする。
-   (K2) **見出しの構造:** 見出しのレベルと、文書にあるべき見出し・表の列の見出しを確かめるもの。ただし、ほかの確かめの対象の位置を探すためだけに見出しを使う場合、その見出しの確かめは、対象の確かめと同じ扱いにする。タスクの文書の記録の表の見出しは、D4 として扱う。
-   (K3) **実行可能な例:** 文書からコマンドの呼び出し例・出力の例・コードの断片を取り出し、製品のパーサやプログラムで解析・実行・生成して確かめるもの。
-   (K4) **自動レビュアーの一覧:** `_context.md` の自動レビュアーの一覧と完了を待つ PR レビュアーの名前を、テストに直書きした期待値と照合する確かめ。および、一覧の行をわざと壊した写しを使い、その照合が働くことを確かめるもの（`TestContextReviewerRowsMalformed`）。
-   (K5) **エージェントが実行する手順:** `.claude/commands/` の手順に、ガードツールの呼び出しが決められた場所にあることと、ガードツールを迂回するコマンドがないことの確かめ。

**削除する確かめ:**

-   (D1) **自然言語の意味:** 文書の節・行・表のセルが特定の語句を含むことで、記述の意味を確かめようとする確かめ。
-   (D2) **直書きのリテラルの存在:** 文書が、テストに直書きした識別子（テスト名を含む）・パス・リンク・値・エラーの文言・コマンドや jq の断片を含むこと、またそれらの語の順序を確かめる確かめ。
-   (D3) **文書の側の不在:** 文書に、削除した識別子・古い語・使わなくなったコマンドが含まれないことを確かめる確かめ。
-   (D4) **タスクの記録:** タスクの文書の記録（手動の確認の表、記入待ちの印、評価の記録の行、`Status`・`Comments` の記録、ほかの文書へのリンク）が揃っていることを確かめる確かめ。

**重なるときの扱い:**

-   K4・K5 に当たる確かめは、D2・D3 にも当たる場合でも残す。
-   1 つの確かめが、コードから導いた値と自然言語の語句の両方を確かめる場合（たとえば、コードの定数の値と「読まない」の語が同じ行にあること）は、K1 の値の部分を残し、D1 の語句の部分を削除する。同じ行にあることの制約は失われてよい。

## 6. 用語集 (Glossary)

-   **文書のテスト:** 文書（`README.md`、`CLAUDE.md`、`AGENTS.md`、`docs/`、`.claude/commands/`、`prompts/README.md` など）を読み、その内容を確かめるテスト。`CLAUDE.md` の text-sync guards と、`doc-guard` CI ジョブが走らせるテストを含む。
-   **確かめ:** 1 つのテストの中の、1 つの条件の検査。1 つのテストは複数の確かめを含みうる。
-   **AC の検証方法:** 計画が AC ごとに定める確かめ方（`test`・`static`・`manual`）。`mkplan.md:74` の分類に従う。
-   **カバレッジの確認:** テストの削除の前後で、`go tool cover -func` の関数ごとの結果を比べること。
-   **値の照合:** 文書の中の値を、コードや設定から導いた値と比べること（F-001 の K1）。
-   **一部の削除:** 1 つのテストから、削除する確かめだけを取り除き、残す確かめを保つこと。
-   **読み合わせ:** PR のレビューで、レビュアーが文書の記述を読んで確かめること。AC の検証方法では `manual` に当たる。
-   その他の用語は `docs/translation_glossary.md` と統一する（受け入れ基準 = acceptance criteria、ガードツール = guard tool、自動レビュアーの一覧 = automated reviewer list、完了を待つ PR レビュアー = awaited PR reviewer）。
