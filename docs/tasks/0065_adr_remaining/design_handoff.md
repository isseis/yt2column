# 設計への申し送り：ADR の残りの候補 20 件と、0058・0059 の決定の反映

要件定義（[01_requirements.md](01_requirements.md)）の作成とレビューで挙がった、設計で決める事項。`02_architecture.md` は、各項目にどう対応したか、または対応しない理由を記録する。

## H-01: 候補の振り分けと、ADR の本数・番号

AC-01 は、20 件の主題をそれぞれ、新しい ADR か同じ主題の既存の ADR のどちらか 1 本に含めることを求める。候補ごとに、既存の ADR と同じ主題か（既存の ADR を更新する）、重なるが別の主題か（新しい ADR を作り、互いにリンクする）、重ならないか、を判断し、その理由を記録する。要件の作成の時点で重なりが見つかっているのは、A1・A2（ADR-0001）、A11（ADR-0003・ADR-0004）、B9・C1（ADR-0011）、B6（ADR-0005・ADR-0011）、D7（ADR-0014）である。ほかの候補にも重なりがないかを確かめる。

新しい ADR の番号の割り当ての順と、新しい ADR を作ったことで既存の ADR の「決定」から除く部分（AC-02）を決める。除いたことを既存の ADR の「経緯」に項目として残すかも決める。規約の経緯の項目は「決定を下したとき、または変えたとき」の記録であり（`docs/dev/conventions/adr.md`「History entries」）、決定の置き場所を移すことがそれに当たるかは、規約が定めていない。

## H-02: 0058・0059 の照合の記録

AC-11 は、ADR-0001〜ADR-0017 のそれぞれについて、0058・0059 の決定がその主題の決定を下したか変えたかの判断と理由を、設計書に挙げることを求める。照合に使う 0058・0059 の文書の範囲（要件定義書・設計書のどの節か）と、判断を挙げる表の形を決める。0058・0059 の決定のうち B6 の主題に属するものは、B6 の ADR の経緯に入る（AC-05）。それと既存の ADR の経緯とで、同じ決定を 2 本の ADR の経緯に書くかも決める。

## H-03: 受け入れ基準を確かめる方法

AC-01・AC-02・AC-04・AC-05・AC-12 は、ADR と出典の文書を突き合わせる確認である。`manual` の読み合わせで確かめるか、本タスクの `_checks/` の確認（`static` か `diff`）で確かめるかを決める（`docs/dev/conventions/requirements_process.md` §4）。0060 は同じ種類の基準を `_checks/` で確かめた（`docs/tasks/0060_adr_records/_checks/`）ので、その再利用を検討する。CLAUDE.md の文書のテストの方針に従い、恒久的なテストは足さない前提とする（要件 2.3）。

## H-04: PR の分け方

本タスクの変更は、20 件の主題の ADR（F-001）と、0058・0059 の反映（F-002）からなり、量が多い。0060 は「規約」「構成と拡張の ADR」「プロセスの ADR」の 3 つの PR に分けた。主題の分類（A・B・C・D）で分けるか、F-002 を独立の PR にするかを決める。並行するタスクが ADR を足した場合の番号の衝突は、規約「Taking in `main`」に従う。
