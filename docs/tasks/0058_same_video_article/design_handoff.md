# 設計への申し送り（0058_same_video_article）

要件定義（`01_requirements.md`）の際に挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目の扱い（採った方法、または当てはまらない理由）を記録する。

-   **H-01: 照会の指定を置く場所と形、版の食い違いの見分け方（F-001・F-002・3.2、AC-12〜AC-14・AC-31）。**
    -   照会の指定を、ホストの新しい形のメッセージに置くか（新しいメンバ、新しい `op` の値、`v` の値を上げるなど）、生成の開始の入力（サーバの本文）に置くかを決める。名前と値の集合（真偽値か列挙か）を決める。
    -   今のホストは、新しい形の最上位の宣言していないメンバと知らない `op` を、`protocol_error` で拒否する（`internal/nmhost/relay.go` の `route`）。今のサーバは、本文の宣言していないメンバを無視して受理する（`internal/server/request.go:67`、`0044` 3.2）。F-002 の 3 つの版の組み合わせのすべてで黙って生成しない置き方を選ぶ。新しいホストが前の版のサーバに照会付きの生成の開始を伝えたときに、サーバが無視して生成しない伝え方（パス、ヘッダ、本文）を含める。
    -   拡張が、版の食い違いをほかの結果（想定外の応答など）と見分ける方法を決める（ホストの `protocol_error` を照会付きの生成の開始に限って版の食い違いとするか、など）。
    -   コミット `54bca194` のホストとサーバに対して AC-12 をどう確かめるか（記録した入力と期待する結果、そのコミットのコードへのテストなど）を決める。
    -   ホストに置く場合は、ホストの判定の例外（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」の `route` の例外）の範囲を広げないことと、#526 での今の形の削除との関係を決める。
-   **H-02: 同じ動画の応答の形とサーバの記録（F-001、AC-01〜AC-11・AC-32）。**
    -   状態コード（`202` か `200` か）、`status` の値、キー以外のメンバ、`requestId` を決め、`docs/dev/guides/development.md`「ジョブの API」「ジョブの API のコード」に加える。キー以外のメンバには、既存の記事の状態を含めるかを含む。含めない場合、ポップアップは状態の取得で知る。
    -   記録が動画 ID を持つ方法（`articlecache` の `Begin` に渡す値、記録の項目）を決める。
    -   同じ動画の記事を探す処理と生成を始める処理を、同じ錠の中で行う方法を決める（AC-08）。
    -   最新の 1 件の選び方を決める。受け付けの時刻が同じ記録の順序も含める。
    -   `Begin` の結果の列挙に値を加えるかを決める。加える場合も、その零値は何も始めない値のままにする。
-   **H-03: ポップアップと Service Worker の分担（F-003、AC-15〜AC-24・AC-33）。**
    -   `0046` `02_architecture.md` 9 章と `0050` の設計の方針（画面の内容の判別共用体に種類を加える）に沿って、次の状態の種類と、主ボタン・副次のボタンの操作を決める。
        -   選択の状態
        -   選択の状態を終えた後の状態（既存の記事が使えなくなった）
        -   版の食い違い
    -   F-003 の表の、取得中の表示と、状態を取得できないことの通知の出し方を、`0050` の読み込み中と通知に合わせる。
    -   ポップアップから Service Worker への、照会の有無を持つ生成の開始の求めの形と、送り手の検査（`0050` AC-05）を決める。
    -   「やり直す」が送る種類（照会の有無）を、ポップアップの状態に持たせる方法を決める。
    -   「既存の記事を表示する」で新しいタブを開くときに、ポップアップが Service Worker を通さずにビューアの URL を作るか、`0050` の「ビューアを開く」の処理を使うかを決める（4.5）。
-   **H-04: 文言（F-002〜F-004、AC-14・AC-16・AC-20・AC-28・AC-30）。**
    -   決める文言は次のとおり。どれも、同じ動画の記事がないことを断定しない（AC-30）。
        -   選択の状態の文言
        -   2 つのボタンの英語と日本語の名前（日本語は issue の「既存の記事を表示する」「現在の選択範囲で生成する」）
        -   既存の記事の状態の文言
        -   既存の記事が使えなくなったことの文言
        -   版の食い違いの文言
        -   既存の記事のビューアの表示と手順の文言
    -   主ボタンの名前を README の手順の名前と突き合わせるガード（`metadataDocs.test.ts`）に、新しい名前を加えるかを決める。
-   **H-05: 既存の記事のビューア（F-004・3.2、AC-25〜AC-28・AC-33）。**
    -   Service Worker が、ビューアに同じ動画の応答と版の食い違いをどう渡すかを決める（`0050` の生成の開始の結果の渡し方を広げる）。
    -   引き継ぐ既存のビューアに、既存の記事を表示していることを伝えるメッセージの形を決める。
    -   ビューアの URL に加える、既存の記事を表示していることを示す値の形と、その長さの上限を決める。それを `0050` 3.2 のビューアの URL の受理する形に加える方法も決める。
    -   処理中の経過時間を示さないことと、`0050` の経過時間の表示の関係を決める。
-   **H-06: ログ（4.2、AC-34）。**
    -   生成の開始のログの結果のコード（`outcome`）に加える値を決める。
    -   同じ動画の応答で返した既存の記事のキーをログに出すかを決める。出す場合も、`0044` 4.2 の固定の属性の方針に従う。
-   **H-07: テスト（5.、AC-08・AC-12）。**
    -   同時に来る照会付きの生成の開始のテストの組み立てを決める（`0044` AC-09b のテストに合わせる）。
    -   版の食い違いのテストの組み立てを決める（H-01）。
    -   ポップアップとビューアのテストの fake を決める（`0050` の `launch.test.ts`・`startCoordinator` のテストに合わせる）。
-   **H-08: `0044` の T-10 の再評価の記録（5. 制約条件、4.2）。**
    -   `02_architecture.md` のセキュリティの節に、`0044` の T-10 の再評価（信頼の境界の内側で受け入れるリスクとしたこと）、照会付きの生成の開始が既存の記事のキーを返す範囲、キーを秘密から計算することを保つ理由を記録する。承認済みの `0044` `02_architecture.md` は変えず、本タスクの記述が T-10 の記事の有無の照会について優先することを書く。
