# 設計への申し送り（0058_same_video_article）

要件定義（`01_requirements.md`）の際に挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目の扱い（採った方法、または当てはまらない理由）を記録する。

-   **H-01: 宣言を置く場所と形（F-001・F-002・3.2、AC-11・AC-25）。** 宣言を、ホストの新しい形のメッセージに置くか（新しいメンバ、新しい `op` の値、`v` の値を上げるなど）、生成の開始の入力（サーバの本文）に置くかを決める。名前、値の集合（真偽値か列挙か）、零値の解釈（4.5）を決める。今のホストは新しい形の最上位の宣言していないメンバと知らない `op` を `protocol_error` で拒否し（`internal/nmhost/relay.go` の `route`）、今のサーバは本文の宣言していないメンバを無視して受理する（`internal/server/request.go:67`、`0044` 3.2）。AC-11（版の食い違いで黙って生成しない）を満たす置き方を選び、本書の作成の時点の版のホストとサーバに対して、それをどう確かめるか（記録した入力と期待する結果、今のコードへのテストなど）を決める。ホストに置く場合は、ホストの判定の例外（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」の `route` の例外）の範囲を広げないこと、サーバへの伝え方（パス、ヘッダ、本文）、#526 での今の形の削除との関係を決める。
-   **H-02: 確認の応答の形とサーバの記録（F-001、AC-01〜AC-10・AC-26）。** 状態コード（`202` か `200` か）、`status` の値、キー以外のメンバ（既存の記事の状態を含めるか。含めない場合、ポップアップは状態の取得で知る）、`requestId` を決め、`docs/dev/guides/development.md`「ジョブの API」「ジョブの API のコード」に加える。記録が動画 ID を持つ方法（`articlecache` の `Begin` に渡す値、記録の項目）、同じ動画の記事を探す処理と生成を始める処理を同じ錠の中で行う方法（AC-08）、最新の 1 件の選び方（受け付けの時刻が同じ記録の順序を含む）を決める。`Begin` の結果の列挙に値を加えるかを決め、その零値が何も始めない値のままであることを保つ。
-   **H-03: ポップアップと Service Worker の分担（F-003、AC-12〜AC-19・AC-27）。** `0046` `02_architecture.md` 9 章と `0050` の設計の方針（画面の内容の判別共用体に種類を加える）に沿って、確認の状態と、確認の状態を終えた後の状態（既存の記事が使えなくなった）の種類と、主ボタン・副次のボタンの操作を決める。確認の状態の最初の状態を取得するまでの表示と、状態を取得できないときの通知の出し方を `0050` の読み込み中と通知に合わせる。ポップアップから Service Worker への、宣言の有無を持つ生成の開始の求めの形と、送り手の検査（`0050` AC-05）を決める。「やり直す」が送る種類（宣言の有無）をポップアップの状態に持たせる方法を決める。
-   **H-04: 文言（F-003・F-004、AC-13・AC-16・AC-22・AC-24）。** 確認の状態の文言、2 つのボタンの英語と日本語の名前（日本語は issue の「既存の記事を表示する」「現在の選択範囲で生成する」）、既存の記事の状態の文言、既存の記事が使えなくなったことの文言、ビューアの「既存の記事を表示している」ことと手順の文言を決める。どれも、同じ動画の記事がないことを断定しない（AC-24）。主ボタンの名前を README の手順の名前と突き合わせるガード（`metadataDocs.test.ts`）に、新しい名前を加えるかを決める。
-   **H-05: ビューアの表示（F-004、AC-20〜AC-22）。** 確認の応答を受け取ったビューアに、Service Worker がその応答をどう渡すか（`0050` の生成の開始の結果の渡し方を広げる）、引き継いだ既存のビューアに「既存の記事を表示している」ことを伝える方法、この表示を再読み込みや履歴から開いた後も残すか（ビューアの URL に値を加えるか。加えるなら `0050` 3.2 のビューアの URL の受理する形に加える）を決める。
-   **H-06: ログ（4.2）。** 生成の開始のログの結果のコード（`outcome`）に加える値を決め、確認の応答で返した既存の記事のキーをログに出すかを決める。出す場合も、`0044` 4.2 の固定の属性の方針に従う。
-   **H-07: テスト（5.、AC-08・AC-11）。** 同時に来る宣言付きの生成の開始のテストの組み立て（`0044` AC-09b のテストに合わせる）、版の食い違いのテストの組み立て（H-01）、ポップアップとビューアのテストの fake（`0050` の `launch.test.ts`・`startCoordinator` のテストに合わせる）を決める。
