## 1. 概要 (Overview)

**目的:** 本書は、開発の道具を足すときや変えるときにエージェントが従う規則を、英語の規約 `docs/dev/conventions/dev_tools.md` に移す要件を定める。あわせて、エージェントが道具をインストールもビルドもしない規則を、利用者が `main` から入れる道具（「入れる」と「入れる道具」の意味は 6 章）のすべてに広げる要件を定める。

**背景:**

-   開発の道具の規則は、今は [ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md)（決定的な判定はエージェントに任せず、テストのある Go の開発ツールに置く）の「決定」に、規則の本文のまま書かれている（`docs/dev/adr/0014-deterministic-checks-in-go.md:17-25`）。規則の全体を持つ文書は、ADR-0014 のほかにない。`CLAUDE.md` は、後述の規則 5（1 章の「issue #1014 で決めたこと」）の一部だけを持つ（この下の 2 項目、すなわち特定の道具についてインストールもビルドもしないと明記した項目と、道具を入れる手順の項目）。`docs/dev/conventions/` には、この規則はない。
-   ADR の規約 `docs/dev/conventions/adr.md` は、正本の文書がある主題では、ADR は決定を要約して正本へリンクすると定め、正本の文書の例に `CLAUDE.md` と `.claude/commands/_context.md` を挙げている（同「Writing an ADR」）。既存の決定を正本の文書に書き移すことは決定を変えない（同「Editorial corrections」）。エージェントが従う規則は英語で書く（`CLAUDE.md`「Document language」の原則 (b)）。今の形では、道具を足すエージェントが従う規約がなく、日本語の ADR を指示として読むことになる。
-   ADR-0014 を規則の置き場所として指している文書は、次の 3 つである。
    -   `docs/dev/guides/chief_guide.md:22`（「ADR-0014 の『道具は `main` からインストールして使う』」）
    -   `docs/dev/guides/numreserve_guide.md:11`（同じ）
    -   `.claude/commands/_lib/adr-correction-candidates.sh:62-64` のコメント（Go に置く道具の規則の置き場所として ADR-0014 を名指す）

    ほかに ADR-0014 を指している文書は、ADR-0014 の決定とその理由を指していて、規則の置き場所を指してはいない。ADR-0013（`:36`）、ADR-0015（`:21`）、ADR-0037（`:21`・`:44`）、ADR-0046（`:70`・`:133`）、ADR-0051（`:18`）、ADR-0053（`:18`）、`docs/dev/guides/chief_guide.md:3` である。ADR-0051 の「ADR-0014 の開発の道具として `main` から入れる」も、道具が ADR-0014 の決定に従うことを述べている。`docs/dev/conventions/package_reference.md` は ADR-0014 を指していない。
-   「エージェントは道具をインストールもビルドもしない」と明記している道具は、今は 3 つだけである。`CLAUDE.md`「Tool Execution Safety」が `codexreview`（`CLAUDE.md:1006-1007`）・`numreserve`（`CLAUDE.md:1015-1016`）・`chief`（`CLAUDE.md:1032`）について書き、`.claude/commands/_lib/local-cli-review.md:91-93` と `docs/dev/guides/numreserve_guide.md:11` も同じことを書いている。ADR-0014 の「道具は `main` からインストールして使う」（`docs/dev/adr/0014-deterministic-checks-in-go.md:22`）は、エージェントについては何も書いていない。
-   道具を入れる手順の書き方は、誰が入れるかについて揃っていない。
    -   利用者に案内している箇所：`.claude/commands/fixpr.md:42`・`:72`・`:863`、`.claude/commands/runpr.md:199-202`、`.claude/commands/chief.md:99-100`、`.claude/commands/mergepr.md:22-26`。
    -   PR のブランチから入れ直す手順で、主語のない箇所：プロトコル番号を上げる PR の手順である。`CLAUDE.md:816-819`（「Protocol numbers」の「reinstall the tool from the branch」）、`docs/dev/guides/mergepr_guide.md:48`、同 7 章の手順 5（`:286`）、`docs/dev/guides/fixprguard_guide.md:54`、`docs/dev/guides/chief_guide.md:30` である。`mergepr.md` はエージェントに `mergepr_guide.md` を読ませる（`CLAUDE.md`「Document language」の例外）。
    -   `main` から入れる手順で、主語のない箇所：`.claude/commands/mergepr.md:18-19`（「Install it with `make install-mergepr` from an up-to-date `main` checkout」）。このほか、マージの後に `main` から入れ直す説明が、`CLAUDE.md:182-185`（「Build Commands」）、`.claude/commands/_context.md:301`、`docs/dev/guides/mergepr_guide.md:46`・`:48`・`:258-259`、`docs/dev/guides/fixprguard_guide.md:46`・`:55`・`:603`、`docs/dev/guides/chief_guide.md:22`・`:35`・`:40`・`:241` にある。
-   `coveragecompare` は、インストールせずに使う。`make coverage-compare` と `make ext-coverage-compare` が、そのつど一時ディレクトリにビルドして走らせる（`docs/dev/adr/0014-deterministic-checks-in-go.md:22`）。この 2 つは、エージェントがテストの削除を確かめるときに走らせる（`CLAUDE.md`「Testing Strategy」）。
-   道具を変えるタスクでは、エージェントが道具をソースから走らせて確かめることがある。たとえば、タスク 0053 の計画は `go run ./cmd/fixprguard` を走らせた（`docs/tasks/0053_status_comments_policy/03_implementation_plan.md:399`）。
-   エージェントが道具を入れることを技術的に止める仕組みはない。`.claude/settings.json` の許可の規則には、`go install`・`make install-*`・`go run ./cmd/*` を拒む項目がない。
-   cloud のセッションでは、`main` から道具を入れることはできる（`docs/dev/guides/numreserve_guide.md` 4 章）。

**本書の記述範囲:** 本書は、規約が持つ規則、ADR-0014 の書き直しの範囲、`CLAUDE.md` とガイドとコマンドの定義で変えるもの、参照の付け替え、変えないものを定める。規約の節の構成と見出し、ADR-0014 から外す本文の行き先、各文書の書き方は `02_architecture.md` で、確かめ方は `03_implementation_plan.md` で定める。`design_handoff.md` と `implementation_handoff.md` に、要件定義の際に人が確かめた設計と計画の決定と、レビューで出た設計と計画の懸念を置く。

**issue #1014 で決めたこと:**

-   **規約に移す規則は、次の 6 つとする。規則の内容は変えない（ただし、下の「要件定義の際に決めたこと」が規則 5 を広げる）。** 本書でも、規則はこの番号で呼ぶ。各規則は ADR-0014 の項目の条件をそのまま持つ。
    1.  判定と副作用を持つ開発の道具は Go で書き、テストを持つ。形は `cmd/<名前>` と `internal/<名前>` の組とし、製品のバイナリには入れない（ADR-0014 `:17`）。
    2.  道具は、判定に使う基準値を状態のファイルから読み返さない。基準値と判定した集合はサブコマンドの出力として返し、セッションが次の呼び出しの引数で渡す。chief の例外は範囲を ADR-0014 と ADR-0046 に残し、規約は例外があることだけをリンクで示す（ADR-0014 `:18`・`:19`）。
    3.  処理の順序は、コマンドの定義ではなく道具のコードで強制する。コマンドの定義には、サブコマンドを呼ぶ順序と利用者への確認だけを書く（ADR-0014 `:20`）。
    4.  道具の引数・出力・終了コードは、コマンドの定義と文書のガードが読む契約である。変えるときは、道具と、それを呼ぶ文書と、ガードを同じ PR で変える（ADR-0014 `:24`）。
    5.  道具は `main` からインストールして使い、道具を変えたマージの後は入れ直す。エージェントは道具をインストールもビルドもしない（`CLAUDE.md`「Tool Execution Safety」と重なる部分は、そちらへリンクする）（ADR-0014 `:22`）。
    6.  例外として、記録の行を読んで判定するだけで副作用を持たない判定は、コマンドの定義から独立したシェルスクリプトにしてよい。条件は、`.claude/commands/_lib/` に置くこと、`origin/main` の commit から作業ツリーの外に取り出して走らせること、失敗は安全な側の判定とすること、規則の全体を常設の Go のテストで確かめ、規則を壊したときにそのテストが失敗することを確かめることの 4 つである（ADR-0014 `:25`）。

    理由：エージェントが従う規則の正本を、英語の規約に置くためである（背景）。
    -   ADR: ADR-0014 の「決定」を、要約と規約へのリンクに書き直す。規則の置き場所を正本の文書に移すことは決定を変えないので、編集上の訂正（`docs/dev/conventions/adr.md`「Editorial corrections」の 1 つ目の種類）として記録する（背景）。新しい ADR は作らない。
-   **ADR-0014 には、理由・採らなかった案・経緯を残す。** ADR が持つものは理由・採らなかった案・経緯であり、仕様は正本の文書が持つためである（`docs/dev/conventions/adr.md`「Writing an ADR」）。
    -   ADR: 上と同じ（ADR-0014 の編集上の訂正）。
-   **`CLAUDE.md` の「Quick Links」の「Development Guides」に、規約へのリンクを足す。** 規約へたどれるようにするためである。
    -   ADR: なし。リンクの追加で、決定を変えない。
-   **ADR-0014 を規則の置き場所として指している文書を、規約を指すように直す。** 規則の置き場所を 1 つにするためである。
    -   ADR: なし。参照の付け替えで、決定を変えない。
-   **プロトコル番号の規則は対象外とする。** 正本が `CLAUDE.md` の「Protocol numbers」にすでにあるためである。ただし、その手順の主語は本タスクで直す（下の「要件定義の際に決めたこと」）。
    -   ADR: なし。
-   **ADR-0024（環境変数を読む場所）と ADR-0019（`context.Context` を第 1 引数にする規則など）の規則を規約に移すかは、別の issue で扱う。**
    -   ADR: なし。

**要件定義の際に決めたこと（2026-11-19）:**

-   **進め方は通常の進め方（`full`）とする。最初は簡易な進め方を選んだが、3 文書を書いたあとで通常の進め方に切り替えた。** 2026-11-19 に人が選んだ。経緯は次のとおりである。
    -   最初の判断：変更は文書だけで、新しい仕組みを作らないので、簡易な進め方を推奨し、人が選んだ。
    -   除外の判断：規則 5 を `fixprguard` と `mergepr` に広げることに決まった（下の項目）。この 2 つは、開発の道具の信頼境界を守る道具である（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）。エージェントが道具を入れないという規則はその境界に影響するので、除外に当たると判断し直した（`docs/dev/conventions/requirements_process.md`「Simple Process」の「Excluded changes」）。人は、コマンドの定義がすでに利用者に入れ直しを案内している運用を規則として書くだけだと考え、除外に当たるというこの判断を上書きした。
    -   切り替え：3 文書のレビューで、上書きの前提の一部が誤っていると分かった。`mergepr.md:18-19` の指示には主語がなく、利用者への案内になっていない（背景）。また、プロトコル番号を上げる PR の入れ直しの手順を直すことになり、範囲が、信頼境界を守る道具のコマンドの定義とガイドに広がった（下の項目）。迷う場合は通常の進め方を推奨するという規約に従って切り替えを推奨し、人が切り替えを選んだ。要件定義の際に人が確かめた設計と計画の決定は、`design_handoff.md` と `implementation_handoff.md` の確かめ済みの項目に置いた。この切り替えは、規約が定める切り替えの時点（`.claude/commands/_lib/simple-process.md`「When an excluded decision appears」の、設計と計画の決定を確かめている間）より後の、3 文書をコミットしてレビューしたあとに行った。そのため、`/runpr` が通常の進め方へ戻したあとと同じ状態（要件定義書だけ、`Process` は `full`、確かめ済みの項目と、レビューの懸念のふつうの項目）にした。
    -   ADR: なし。本タスクの中で閉じる、進め方の選択である。
-   **規則 5 の「エージェントは道具をインストールもビルドもしない」は、利用者が `make install-<名前>` で `main` から入れる道具（以下、入れる道具）のすべてに当てはめる。今は `mergepr`・`fixprguard`・`codexreview`・`chief`・`numreserve` の 5 つである。** 2026-11-19 に人が選んだ。理由は 2 つある。1 つ目は、エージェントが PR のブランチから `fixprguard` や `mergepr` を入れ直すか走らせると、そのブランチが変えた判定で `/fixpr`・`/runpr`・`/mergepr` が動き、`main` の判定を迂回できることである。2 つ目は、入れ直しの手順の多くがすでに利用者が入れる形で書かれており（背景）、案内していない箇所も同じ形に揃えられることである。make のターゲットがそのつどビルドして走らせる道具（以下、そのつどビルドする道具。今は `coveragecompare`）は、インストールしないので、この規則の対象ではない。
    -   採らなかった案：`CLAUDE.md` がすでに明記している 3 つ（`codexreview`・`numreserve`・`chief`）だけに当てはめる案。規則の内容は変わらないが、`fixprguard` と `mergepr` について規則がないままになる。
    -   ADR: ADR-0014 を更新する。決定の変更なので、「決定」に項目を足し、「採らなかった案」「結果」「経緯」に項目を足す（本 PR の [ADR-0014](../../dev/adr/0014-deterministic-checks-in-go.md)）。
-   **規則 5 の「ビルドする」は、道具を走らせるためのバイナリを作ること、またはソースから走らせることを指す。** 例は `make install-<名前>`、`go install`、`go build ./cmd/<名前>`、`go run ./cmd/<名前>` である。`make test`・`make lint`・`go test`・`go vet` のように、テストや lint のために道具のパッケージをコンパイルすることは含まない。2026-11-19 に人が選んだ。「ビルドする」を言葉どおりに読むと、規則がエージェントの日々のテストと lint まで禁じることになり、逆にインストールだけを禁じると、`go run` でブランチの判定を走らせる抜け道が残るためである。
    -   採らなかった案：インストール（`make install-*` と `go install`）だけを禁じる案。`go run` や `go build` で作ったバイナリでブランチの判定を走らせられる。
    -   ADR: ADR-0014 の更新（上の項目）に含める。
-   **例外として、エージェントは、道具を開発するため、または調べるために、ソースから道具をビルドして走らせてよい。条件は 3 つある。1 つ目は、作ったバイナリを `PATH` の通った場所（`$(go env GOPATH)/bin` を含む）に置かないこと。2 つ目は、`/fixpr`・`/runpr`・`/mergepr`・`/chief`・`/mkreq` などの手順で、入れた道具の代わりに使わないこと。3 つ目は、外に副作用を持たない走らせ方に限ることである。走らせてよいのは、テスト、`--help`、手元の入力やコピーに対する実行で、ネットワークへの書き込み、GitHub への書き込み、記録の tag の作成、ほかのエージェントの pane への入力、外のサービス（LLM の API や Codex CLI を含む）への送信をする走らせ方は含まない。`CLAUDE.md`「Tool Execution Safety」のほかの規則は、この例外の中でも効く。** 2026-11-19 に人が選んだ（3 つ目の条件は、Fable の部分レビューの指摘を受けて 2026-11-19 に人が選んだ）。道具を変えるタスクで実装を確かめるために道具を走らせること（背景のタスク 0053 の例、`_checks` のスクリプト）は、入れた道具を置き換えず、手順の判定にも使われず、外に副作用もないので、信頼境界に及ばないためである。3 つ目の条件がないと、たとえば `numreserve` を変えるタスクで、ソースから走らせた道具が取り消せない記録の tag を作りうる。この例外は、`codexreview`・`numreserve`・`chief` について今は条件なしに「インストールもビルドもしない」としている文（背景）を緩めるので、それらの文も例外を指すように直す。
    -   採らなかった案：ソースから走らせることをすべて禁じ、必要なら利用者が走らせる案。道具を変えるタスクの実装の確かめが、利用者頼みになる。
    -   採らなかった案：例外を、`codexreview`・`numreserve`・`chief` を除くほかの道具だけに認める案。道具によって規則が変わる。
    -   ADR: ADR-0014 の更新（上の項目）に含める。
-   **プロトコル番号を上げる PR のブランチで道具を入れ直すのも、利用者とする。エージェントは、道具を入れるかビルドする手順に差しかかったとき、または道具が見つからない、あるいは番号が合わないためにコマンドが失敗したときは、そこで作業を止めて利用者に頼み、実行するコマンドを示す。示すのは最新の `main` の作業ツリーで入れるコマンドで、PR のブランチで入れ直すように頼むのは、その PR がプロトコル番号を上げる場合だけである。ただし、手順が別の扱いを定めている場合は、その手順に従う（今は、`codexreview` が見つからないか番号が合わないとき、`.claude/commands/_lib/local-cli-review.md` の手順 3 が `not run` を記録して進む）。PR のブランチから入れ直す主語のない手順と、`mergepr.md:18-19`（背景）を、利用者が入れる形に直す。** 2026-11-19 に人が選んだ（入れる場所と、手順が別の扱いを定める場合の扱いは、Fable の部分レビューの指摘を受けて、人の決定に揃えて書き足した）。主語がないままだと、「エージェントは入れない」とぶつかり、どちらが優先するかが分からないためである。`make install-<名前>` は、走らせた作業ツリーのコードを入れる（`Makefile` の `install-*` は `go install ./cmd/<名前>`）。cloud のセッションでも同じく作業を止めて頼み、利用者は最新の `main` の作業ツリーで自分で入れる。
    -   受け入れる危険：プロトコル番号を上げる PR では、利用者が入れ直したあと、その PR の `/runpr` が終わるまで、道具はブランチの判定で動く。入れ直すのは、その PR の変更を見たうえでの利用者自身なので、この危険は受け入れる。`/runpr` が途中で止まるか、PR をやめたときも、利用者が `main` から入れ直すまで、ブランチの道具がすべての worktree で使われる。利用者は、マージの直後か PR をやめたときに `main` から入れ直す（`fixprguard_guide.md:55` はマージの直後の入れ直しを案内している）。
    -   採らなかった案：主語の直しを範囲外にし、別の issue で扱う案。規則と手順がぶつかったまま `main` に入る。
    -   ADR: ADR-0014 の更新（上の項目）に含める。

`docs/dev/security.md` の条件（外部コマンドの起動、API キー、キャッシュ、ネットワーク、信頼できない文字列の埋め込み）には当たらない。信頼できない入力は読まない。ただし、規則 5 を広げることは、開発の道具の信頼境界（ADR-0015）に関わるので、次を定める。

-   **守るもの:** 入れる道具が `main` の判定で動くこと。とくに、`/fixpr`・`/runpr` の `fixprguard` と `/mergepr` の `mergepr` の判定である。ほかの道具も同様である。`numreserve` は取り消せない記録の tag を作り、`codexreview` は Codex CLI を走らせ、`chief` はほかのエージェントに入力を送る。
-   **脅威:** 信頼できないレビューの本文を読んだエージェントが、PR のブランチから道具を入れるか走らせ、そのブランチが変えた判定で手順を進める。
-   **影響の範囲:** `$(go env GOPATH)/bin` の道具は、同じ利用者のすべての worktree とその後のセッションで共有される（`docs/dev/guides/fixprguard_guide.md` 3 章）。置き換えは、利用者が `main` から入れ直すまで続く。
-   **守り:** 規約と、Claude Code が毎回読み込む `CLAUDE.md`「Tool Execution Safety」の指示の文、そして `.claude/settings.json` の `make install-*` と `go install` を拒む規則（F-006）である。拒否の規則はコマンドの前方一致なので迂回でき、Claude Code にだけ効く。`go build` と `go run` は指示の文だけで守る。今の `.claude/settings.json` は `make` と `go` を許可の規則にも拒否の規則にも挙げておらず、利用者の設定や許可のモードによっては、確認なしで実行されうる。
-   **受け入れる危険:**
    -   エージェントが指示に従わない危険（1 章）。
    -   プロトコル番号を上げる PR で、利用者が入れ直したあと、その道具がブランチの判定で動くこと。`/runpr` が途中で止まるか PR をやめたときも、利用者が `main` から入れ直すまで続くこと（1 章）。
    -   テストや lint はブランチのコードを走らせるので、そのコードが `$(go env GOPATH)/bin` を書き換えうること。この危険は本タスクの前からあり、本タスクは変えない。
    -   `CLAUDE.md` を毎回読み込むのは Claude Code である。`/runpr` などを走らせる OpenCode が同じように読むかは確かめておらず、読まない場合の危険を受け入れる（1 章、人の決定）。
-   **気づき方と戻し方:** `PATH` にある道具のビルド元のコミットは `go version -m "$(command -v <道具>)"` の `vcs.revision` で確かめられる（`fixprguard_guide.md` 3 章、`chief_guide.md:22`）。分かるのはそのバイナリのコミットだけである。コミットしていない変更から入れたことは `vcs.modified` にしか出ず、`-buildvcs=false` で作ったバイナリには記録がない。`go run` や別の場所に作ったバイナリでの実行は、`PATH` の道具に跡を残さない。また、ブランチのコミットからは、利用者が許された入れ直しをしたのか、エージェントが入れたのかは分からない。違いに気づいたら、利用者が `main` から入れ直す。

### 4.3. 信頼性・可用性 (Reliability/Availability)
-   N/A。道具とコマンドの振る舞いを変えない。エージェントが止まって利用者に頼む場面は、今も `fixpr.md` などで利用者に案内している場面と同じである（1 章の背景）。`codexreview` が見つからないか番号が合わないときは、今と同じく `local-cli-review.md` の手順に従い、止まらずに `not run` を記録して進む。

### 4.4. 互換性 (Compatibility)
-   どの道具のプロトコル番号も変えない。道具を入れ直す必要はない。
-   本 PR のマージから実装の PR のマージまでの間、ADR-0014 は広げた規則を持つが、`CLAUDE.md` はまだ 3 つの道具についてしか書いていない。その間にエージェントの振る舞いが今より緩むことはない。

### 4.5. 保守性 (Maintainability)
-   規約は道具の名前の一覧を持たない（AC-03）。道具を足しても、規約を直す必要はない。
-   規約は理由を持たない（AC-06）。理由の正本は ADR-0014 の 1 か所である。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   規約とコマンドの定義は英語で、ADR、ガイド、タスク文書は日本語で書く（`CLAUDE.md`「Document language」）。
-   ADR-0014 の書き直しは、ADR の規約 `docs/dev/conventions/adr.md`（「Writing an ADR」「Editorial corrections」）に従う。ADR から規約の節を指すときは、アンカーを使わず、見出しの名前を本文で示す（同「Links」）。
-   文書のテストは文の意味を確かめない（`CLAUDE.md`「Testing Strategy」）。規約の文は PR のレビューで読む。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。
-   **開発の道具:** `cmd/<名前>` と `internal/<名前>` の組で作る、開発の手順のための Go の道具。製品のバイナリには入らない（規則 1）。
-   **規約:** 本書では `docs/dev/conventions/dev_tools.md` を指す。ADR の書き方の規約は「ADR の規約 `docs/dev/conventions/adr.md`」と呼んで区別する。
-   **規則 1〜6:** 1 章の「issue #1014 で決めたこと」に挙げた 6 つの規則。
-   **入れる道具:** 利用者が `make install-<名前>` で `main` から入れる開発の道具。
-   **そのつどビルドする道具:** make のターゲットが、走らせるたびに一時ディレクトリにビルドする開発の道具。
-   **入れる・入れ直す:** インストールする・再インストールすると同じ意味で使う。
-   **ビルドする:** 規則 5 では、道具を走らせるためのバイナリを作ること、またはソースから走らせること（1 章の「要件定義の際に決めたこと」）。
