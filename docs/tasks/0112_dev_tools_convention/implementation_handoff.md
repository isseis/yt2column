# 実装計画への引き継ぎ：開発の道具の規則を ADR-0014 から規約 dev_tools.md に移す

`03_implementation_plan.md` が扱う項目。I-01 は要件定義の際に人が確かめた計画の決定で、通常の進め方への切り替えに伴って置いた（[01_requirements.md](01_requirements.md) 1 章の「要件定義の際に決めたこと」）。I-02 以降は、簡易な進め方で書いた実装計画書のレビューで出た懸念である。

## I-01: 実装モデル要件は sonnet とする（確かめ済み）

**決定:** 実装の PR（文書だけ、1 本）の実装モデル要件は `sonnet` とする。
**理由:** `mkplan2.md` の基準のどのトリガーにも当たらないためである。変更は文書だけで、方式の選択も危険度の高いステップもない。
**決めた日:** 2026-11-19
**人の答え:** sonnet
**ADR:** なし。本タスクの中で閉じる。

人が答えたときの範囲は、規約、ADR-0014、`CLAUDE.md` の 2 項目、参照の 3 か所だった。その後、`mergepr.md` とガイドの主語の直し（F-004）が加わった。

## I-02: 差分の範囲の確かめ方

**懸念:** 変わるファイルを限る AC（AC-21）は、記録した diff を読む場合、比べるパスの差分だけでなく、diff 全体のファイルの一覧を持つ必要がある（`docs/dev/conventions/requirements_process.md` §4「Compared paths」）。また、ほかの AC の記録を借りて確かめると、確かめる対象が混ざる。

**案:** 差分の範囲の AC（AC-10、AC-18、AC-21、AC-22）は、AC ごとに記録を持つ。AC-21 の記録はファイルの一覧を持ち、PR の最後のコミットで取る。スクリプトのコメントだけが変わること（AC-20）にも、そのパスの記録を持たせる。

**関連:** AC-10、AC-18、AC-20、AC-21、AC-22

## I-03: 訂正行に `<` を書かない

**懸念:** 訂正行は `@` と `<` を含まない（`requirements_process.md`「Recording in the PR description」）。ADR-0014 の項目は `make install-<名前>` のように `<` を含むので、文を写すと形に反する。

**案:** 実装のステップに、訂正行は文を写さず自分の言葉で書き、`<` と `@` を含めないことを書く。

**関連:** AC-11

## I-04: ステップごとの確かめに、ガイドを読むテストを入れる

**懸念:** `cmd/chief/docs_test.go` と `cmd/numreserve/docs_test.go` はガイドを読み、`cmd/mergepr` のテストは `mergepr.md` と `mergepr_guide.md` を読む。`./cmd/yt2column` だけを走らせるステップの確かめでは、これらの失敗に気づくのが最後になる。

**案:** ガイドとコマンドの定義を変えるステップの完了の条件に、それらを読むパッケージのテストを入れる。

**関連:** AC-15〜AC-17、AC-19
