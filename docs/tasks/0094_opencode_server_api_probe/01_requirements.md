## 1. 概要 (Overview)

**目的:** 本書は、chief による OpenCode の pane の判定と送信を、画面の読み取りとキー入力から OpenCode のサーバの API へ移せるかを実地で確かめる調査の要件を定める。成果は、`docs/research/` の下の調査記録である。後続の [#906](https://github.com/isseis/yt2column/issues/906)（API による送信）と [#907](https://github.com/isseis/yt2column/issues/907)（質問の判定と中継）は、この記録を設計の前提として引用する。chief のコードと設定は変えない。

**背景:**

chief は、OpenCode の pane に対して次のことを、画面とキー入力で行っている。

-   コマンドを送るときは、キー入力で `/new` を打ち、続けて送るコマンドを打つ（`internal/chief/send.go:425`〜`427`）。送る前に画面のモデルの行を読み、送り先の表に書かれたモデルと違えば送らない（`internal/chief/send.go:351`〜`352`）。OpenCode はコマンドでモデルを切り替えられないので、モデルが合わないときは人がその pane で切り替える（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)「結果」）。
-   質問は画面から読む（`internal/chief/screen_opencode.go:121` の `openCodeQuestion`）。OpenCode は、質問を示しても Herdr に `blocked` と報告しないためである（ADR-0046「背景」）。
-   chief のセッションが道具を通さずに入力を送らないよう、リポジトリの `.claude/settings.json` で herdr の呼び出しを拒む。拒むのは herdr の呼び出しだけで、`opencode` の呼び出しと `curl` は拒んでいない（`.claude/settings.json:8`〜`33`）。

OpenCode v2.2.6 の TUI は、既定で裏で動くサーバ（`opencode service`）につながる。`opencode api GET /openapi.json` を読むと、このサーバには `session.switchModel`・`session.command`・`session.prompt`・`session.create`・`session.form.list`・`session.form.reply`・`permission.request.list`・`session.permission.list`・`session.permission.reply`・`session.message.list`・`session.get`・`session.active`・`event.subscribe` がある。これは、issue #903 が 2026-11-16 に読み取りだけで確かめたものである。一方で、Herdr の `agent list` は OpenCode の pane の `agent_session` を `null` で返すので、pane とセッションの対応を Herdr からは決められない。また、API の説明には "Experimental HttpApi surface" とある（issue #903 の確認）。

対応 issue: [#903](https://github.com/isseis/yt2column/issues/903)（親: [#902](https://github.com/isseis/yt2column/issues/902)、後続: [#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907)）

**本書の記述範囲:** 本書は、調査で答える問い、答えとして記録する内容、実験の守り（書き込む先の限定、記録に残さないもの）を定める。実験を行う環境、記録の置き場所、問いごとの手順は、[02_architecture.md](02_architecture.md) が定める。

**issue #903 で決めたこと:**

-   **問いは 6 つとする（§3 の F-002〜F-007）。** 問い 1：質問ツールの問いが `form` として現れるか。問い 2：権限の確認が `permission.request.list` に現れるか。問い 3：`session.switchModel`・`session.command`・`/new` に当たる操作が TUI の pane に効くか。問い 4：pane とセッションの対応を宣言された値で決められるか。問い 5：API に版の情報があり、版が変わったときに失敗として分かるか。問い 6：chief のセッションが API で入力を送る呼び出しを `.claude/settings.json` でどこまで拒めるか。後続の 2 件の設計は、これらの答えに左右されるためである。ADR: なし（決定を変えるのは #906・#907 で、それぞれが ADR-0046 を更新する）。
-   **結果は `docs/research/` の下に記録する。** 後続の 2 件が引用できるようにするためである。ADR: なし。
-   **chief のコードは変えない。** 移す作業は #906・#907 が行うためである。ADR: なし。
-   **完了の条件は、6 つの問いに、確かめた結果と再現の手順が記録されていることとする。** ADR: なし。

**要件定義の際に決めたこと（2026-11-16）:**

-   **進め方は簡易な進め方（`simple`）とする。** 変更が及ぶのは `docs/research/` の下の調査記録 1 つで、既存の ADR の決定を変えず、新しい仕組みも作らない。決めることも、実験の環境・記録の置き場所・PR の構成に限られるためである。この変更は、簡易な進め方から除外する変更には当たらないと判断した。問い 6 は拒めるかを確かめるだけで、拒否を足すのは #906 である。そのため、開発用の道具の信頼の境界は変わらない。使う OpenCode とその送り先の DeepSeek は ADR-0046 ですでに受け入れており、外部の依存も足さない。ADR: なし（このタスクの進め方の決定で、タスクの外に及ばない）。
-   **問い 3 で `/runpr` を比べる場所は、PR のない使い捨ての worktree とする（AC-09）。** 実際の PR で比べると、その PR を進めてしまうためである。`/runpr` は、`git fetch origin main` と、PR を探す `gh pr view`・`gh pr list` を行った後、PR がなく、ブランチが detached の `HEAD` なら止まる（`.claude/commands/runpr.md` の 1 章、104〜128 行）。そのため、API で送った `/runpr` も TUI で打った `/runpr` も、この読み取りだけのネットワークの呼び出しの後に止まる見込みである。止まらずに先へ進んだときは、その時点で比べるのをやめ、観測として記録する。確かめられるのは、コマンドが同じように展開されて走るかどうかまでで、実際の PR での振る舞いは確かめない。ADR: なし。
-   **問い 6 は、呼び出しの形を挙げたうえで、拒否の候補を一時的な設定で実際に試す（AC-14・AC-15）。** 形を挙げるだけでは、拒否が効くかどうかを #906 があらためて確かめなければならないためである。`curl` で直接呼べるかを判断するために、サーバへの届き方（TCP かソケットか）と認証の有無も記録する。ADR: なし（拒否の規則を決めるのは #906 で、ADR-0046 を更新する）。
-   **`event.subscribe` も確かめる（F-008）。** #907 は、待ち受けに `event.subscribe` を使うのは「必要なら」としている。問い 1 の実験の中で、質問と権限の確認が現れたときと閉じたときに何が流れるかを見るだけなので、追加の手間は小さいためである。issue の 6 つの問いの外にあるので、記録では「問い 7」として分けて書く。ADR: なし。
-   **記録には、API の形と再現の手順だけを残し、セッションの中身は残さない（AC-17）。** API の応答には、セッションのプロンプト、リポジトリのコード、モデルの出力が入りうるためである（[security.md](../../dev/security.md) §6 の信頼できない文字列）。実験のために本書の手順が書いた決まったプロンプトは、再現に要るので記録に残す。ADR: なし。

**要件定義の際に決めたこと（2026-11-17）:**

-   **問い 6 の「拒んだ」の条件を 3 つにし、挙げる形を 5 つに広げる（AC-15）。** #911 のマージの後に、インストールされた `claude`（2.1.326）と `opencode`（v2.2.6）の `--help` と実行ファイルを読み取りだけで確かめたレビューで、次の 2 点が分かったためである。`claude -p` は検査で退けた設定ファイルを黙って無視し、許可の拒否の記録は拒否の理由を持たない。そのため、2 つの条件だけでは、拒否の候補が効いたことと、許可の規則が読まれずに拒まれたことを区別できない。また、`opencode` には `--prompt`・`acp`・`run --continue`・`session.shell`、サブコマンドの前に置ける大域のフラグ、別の名前の `opencode2` がある。ADR: なし（拒否の規則を決めるのは #906 である）。
-   **サーバの資格情報は、`claude -p` のプロンプトにも設定にも書かない（4.2 節）。** 問い 6 で認証が要ると分かったときに、資格情報が Anthropic の API とファイルに渡るのを防ぐためである。ADR: なし。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   問い 1〜6 と問い 7（`event.subscribe`）に、実地で確かめた答えを出す。
-   答えごとに、読み手が同じ観測を繰り返せる再現の手順を残す。
-   #906・#907 が、答えを記録の節の単位で引用できるようにする。

### 2.2. スコープ (In Scope)

-   OpenCode v2.2.6 の裏で動くサーバ（`opencode service`）に対する、問い 1〜7 の実地の確かめ。
-   拒否の候補を、一時的な設定ファイルで試すこと（問い 6）。
-   `docs/research/` の下の調査記録の作成。

### 2.3. スコープ外 (Out of Scope)

-   chief のコード（`internal/chief`・`cmd/chief`）、コマンドの定義、`.claude/settings.json` の変更。移す作業と拒否の追加は #906・#907 が行う（issue #903「範囲」）。
-   ADR-0046 と `CLAUDE.md` の例外の更新。決定を変える #906・#907 が行う（親 issue #902「方針」）。
-   実際の PR での `/runpr` の振る舞いの確かめ（要件定義の際に決めたこと）。
-   Claude Code の transcript による判定（#904・#905 の範囲）。
-   OpenCode の v2.2.6 以外の版での確かめ。版の情報の有無と、版が違うときの失敗の見え方は問い 5 で確かめるが、別の版を入れて試すことはしない。外部の依存を変えることになるためである。

## 3. 機能要件 (Functional Requirements)

本書の「記録」は、F-001 の調査記録を指す。「実験のセッション」は、実験の手順が使い捨ての worktree で作った OpenCode のセッションを指す（§6）。

### 3.1. 機能一覧

#### F-001: 調査記録

問いへの答えを、`docs/research/` の下の 1 つの調査記録にまとめる。

**Acceptance Criteria**:
- **AC-01**: 記録は、確かめた日付と、`opencode --version` が示した OpenCode の版を書き、時点の記録であること（版が変われば成り立たない場合があること）を述べる。
- **AC-02**: 記録は、問い 1〜7 のそれぞれに節を持つ。各節は、答え（「はい」「いいえ」「一部」「確かめられなかった」のいずれか。操作の名前や版の値を問う項目では、その名前や値）、答えの根拠にした観測、再現の手順（`opencode api` などのコマンドと、人が TUI で行う操作）を書く。
- **AC-03**: 確かめられなかった問いと、答えが「一部」の問いは、その節に、確かめられなかった部分と理由を書く。問いの節を省かない。
- **AC-04**: 記録は、確かめていない事項と、答えが前提にする条件（"Experimental" とされる API であること、確かめた版、使い捨ての worktree で確かめたこと）を 1 つの節にまとめる。

#### F-002: 問い 1：質問ツールの問いと `form`

OpenCode の質問ツールの問いが、サーバの API にどう現れ、API で答えると TUI の問いがどうなるかを確かめる。

**Acceptance Criteria**:
- **AC-05**: 1 つを選ぶ問い、複数を選ぶ問い、タブのある問いの 3 つのそれぞれについて、記録は、その問いが `session.form.list` に現れるか、現れるならどの型とどのフィールドで表されるか（`Form.Field` の型の名前、選択肢、タブの表し方）を書く。現れないなら、ほかに問いが現れた API の操作があればそれを書き、なければ「現れない」と書く。
- **AC-06**: `form` に現れた問いのそれぞれについて、記録は、`session.form.reply` で答えた後に TUI の問いが閉じるか、TUI に答えがどう示されるかを、TUI の画面の観測として書く。あわせて、人が選んでいない選択肢を API で送れてしまうかを判断できる観測（API が答えの値を検査するか）を書く。

#### F-003: 問い 2：権限の確認

**Acceptance Criteria**:
- **AC-07**: 記録は、OpenCode が権限の確認を示したときに、それが `permission.request.list` と `session.permission.list` のどちらに現れるか（両方か、どちらにも現れないか）を書き、現れるなら、確認がどのセッションのものかを示すフィールドと、確認の中身（実行しようとしたコマンドなど）を示すフィールドの名前を書く。

#### F-004: 問い 3：モデルの切り替え・コマンドの送信・新しいセッション

**Acceptance Criteria**:
- **AC-08**: 記録は、`session.switchModel` で実験のセッションのモデルを切り替えた後に、TUI の pane のモデルの行が変わるか、その pane での次の実行がどのモデルで走ったか（`session.message.list` が示すモデル）を書く。
- **AC-09**: 記録は、PR のない使い捨ての worktree で、`session.command` で送った `/runpr` と、人が TUI で打った `/runpr` を比べ、コマンドの展開（コマンドの定義が読まれたか）と、最初に止まった箇所が同じかを書く。違えば、違いを書く。
- **AC-10**: 記録は、`/new` に当たる API の操作（`session.create` など）を挙げ、その操作の後に、TUI の pane が新しいセッションに移るか、それとも元のセッションに留まるかを書く。

#### F-005: 問い 4：pane とセッションの対応

**Acceptance Criteria**:
- **AC-11**: 記録は、pane が使うセッションを宣言された値で決める方法の候補ごとに、決められるかどうかと、決められない場合を書く。候補には少なくとも、pane を `opencode --session <id>` で起動する方法と、`session.list` を作業ディレクトリで絞る方法を含める。同じ作業ディレクトリに OpenCode の pane が 2 つあるとき、TUI でセッションを切り替えたとき、`/new` の後の 3 つの場合に、それぞれの候補がどうなるかを書く。

#### F-006: 問い 5：API の版

**Acceptance Criteria**:
- **AC-12**: 記録は、サーバの API が版の情報を持つか（`/openapi.json` の `info.version`、応答のヘッダ、版を返す操作など）と、その値を書く。持たないなら「持たない」と書く。
- **AC-13**: 記録は、版が変わったときに読み違えずに失敗として分かるかを判断するために、次の 2 つを書く。(a) 存在しない操作への要求に対するサーバの応答（状態コードと応答の形）。(b) `/openapi.json` のスキーマが、定義にないフィールドを応答に含めることを許すか（`additionalProperties` の宣言の有無）と、実在する読み取りの操作の 1 つの応答に、スキーマにないフィールドがあったか。

#### F-007: 問い 6：API で入力を送る呼び出しの拒否

**Acceptance Criteria**:
- **AC-14**: 記録は、サーバへの届き方（TCP のアドレスとポートか、Unix ドメインソケットか、その場所をどこから知るか）と、要求に認証が要るかを書く。
- **AC-15**: 記録は、Claude Code のセッションが Bash で OpenCode のサーバへ入力を送りうる呼び出しの形を挙げ、形ごとに次を書く。
    -   挙げる形には、少なくとも次の 5 つを含める。(a) `opencode api` の書き込みの呼び出し（`session.shell` のように、セッションの場所でコマンドを走らせる操作を含む）。(b) `curl` などでサーバを直接呼ぶ呼び出し。(c) 入力を送るか、セッションを変える `opencode` のほかのサブコマンドとフラグ（`opencode run`（`--continue` を含む）・`opencode --prompt`・`opencode --continue`・`opencode mini --prompt`・`opencode mini --continue`・`opencode acp`・`opencode session delete`・`opencode session import` など、該当するもの）。(d) パスで書いた `opencode` の呼び出しと、`opencode` を呼ぶ別の名前のコマンド（`~/.opencode/bin/opencode2` など）。(e) サブコマンドの前に大域のフラグを置いた呼び出し（`opencode --log-level error api …` など）。
    -   `--help` に現れるサブコマンドとフラグのうち、入力を送らないと判断して挙げなかったもの（`opencode serve`・`opencode pair` など）は、その理由とともに書く。
    -   宛先を指定できない形（`--continue`・`acp` など）は、実験のセッションの外へ書き込みうるので試さず、「確かめられなかった」とその理由を書く。
    -   形ごとに、`.claude/settings.json` の拒否の候補と、その候補を一時的な設定ファイルで与えた Claude Code のセッションがその形の呼び出しを拒んだかどうかを書く。
    -   拒んだと書けるのは、次の 3 つがそろったときだけとする。(1) 許可の規則だけを与え、拒否の候補を与えない対照の試行で、同じ形の呼び出しが実際に走った。走ったことは、Claude Code の構造化された出力の、ツールの実行の記録か、実験のセッションに起きた変化で確かめ、許可の拒否がないことだけからは判断しない。(2) 拒否の候補を与えた試行で、Claude Code が、対照の試行と同じ文字列のコマンドを、許可の拒否として報告した（モデルの文ではなく、Claude Code の構造化された出力で読む）。(3) 同じ試行で、一時的な設定ファイルが読まれたことを示した（その設定ファイルにだけある許可の規則が効いたことで確かめる。その規則で許すコマンドは、規則がなければ拒まれることを確かめたものに限る）。設定ファイルが検査で退けられると、拒否の候補ごと黙って無視されるためである。
    -   試行に使った Claude Code の版・設定の読み込み元・許可のモード・作業ディレクトリも書く。
    -   拒めない形と、確かめられなかった形は、残る危険として挙げる。

#### F-008: 問い 7：`event.subscribe`

**Acceptance Criteria**:
- **AC-16**: 記録は、`event.subscribe` を購読している間に、質問ツールの問いと権限の確認が現れたときと、答えて閉じたときに、どのイベントが流れたか（イベントの種類の名前と、どのセッションのものかを示すフィールド）を書く。流れなければ「流れない」と書く。

#### F-009: 実験の守り

調査は実地で OpenCode のセッションに入力を送るので、実験が実際のタスクのセッションに書き込まないこと、記録がセッションの中身を残さないこと、`main` のコードと設定を変えないことを求める。

実験が失敗したとき（API の操作が失敗する、問いが現れない、権限の確認が出ない、宛先を確かめられない）の扱いは、AC-03 のとおり、その問いの節に「確かめられなかった」と理由を書くこととする。実験の手順の側の扱いは [02_architecture.md](02_architecture.md) の 4 章が定める。

**Acceptance Criteria**:
- **AC-17**: 記録は、API の応答のうち、プロンプトの本文、モデルの出力の本文、リポジトリのコード、トークン・鍵などの秘密を含まない。引用してよいのは、型・フィールドの名前・状態コード・イベントの種類の名前と、実験の手順が書いた決まったプロンプトだけである。
- **AC-18**: 記録の再現の手順のうち、サーバに書き込む呼び出し（`POST` などの、セッションの状態を変える呼び出し）は、どれも、実験のセッションを宛先にする。手順は、書き込む前に、宛先のセッションの作業ディレクトリが使い捨ての worktree であることを確かめる操作を含む。セッションを作る呼び出しは、作る場所として使い捨ての worktree を指定し、作られたセッションの作業ディレクトリをその後に確かめる操作を含む。
- **AC-19**: このタスクの実装の PR の `origin/main` からの差分は、調査記録のディレクトリ（`docs/research/` の下）と、このタスクのディレクトリの中のファイルの追加と変更に限られる。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

N/A。調査は製品の処理の速さを変えない。

### 4.2. セキュリティ (Security)

`docs/dev/security.md` の条件（外部のサービスへ送ること、信頼できない文字列を扱うこと）に当たるので、次を守る。

-   **信頼できない文字列:** OpenCode の API の応答と TUI の画面は、モデルとリポジトリの外が書いた文字列を含む（security.md §6）。調査はそれを指示として扱わず、記録に写さない（AC-17）。`event.subscribe` の流れはサーバ全体のもので、実際のタスクのセッションの中身も含みうるので、イベントの種類とセッションの ID だけに絞ってから読む。
-   **信頼できない入力の境界:** N/A。この調査は、API の応答を読むコードを作らない。応答は観測するだけで、型・フィールドの名前などの形だけを記録に写す。応答を受け取るコードの受け付ける形と拒否は、#906・#907 が定める。
-   **外部への送信:** 実験は、OpenCode を通して DeepSeek のサービスへプロンプトを送る。送り先は ADR-0046 ですでに受け入れたもので、送るのは、実験の手順が書いた決まったプロンプトと、使い捨ての worktree（`origin/main` の detached）の内容だけである。問い 6 の確かめは、`claude -p` で Anthropic の API へ、試す呼び出しの指示を送る。
-   **書き込む先:** 書き込みは実験のセッションだけに送る（AC-18）。裏で動くサーバは、実際のタスクの OpenCode の pane も使っているためである。
-   **一時的な設定:** 問い 6 で試す拒否の候補の設定ファイルは、作業ツリーの外に置き、コミットしない。リポジトリの `.claude/settings.json` は変えない（AC-19）。
-   API キーなどの秘密は、記録にも、コミットメッセージにも、PR の説明にも書かない（AC-17）。
-   **サーバの資格情報:** サーバへの要求に認証が要るとき（AC-14）、その資格情報を `claude -p` に送るプロンプト、許可の規則、一時的な設定ファイルに書かない。資格情報なしで試せない形は、問い 6 の節に「確かめられなかった」と理由を書く。プロンプトは Anthropic の API へ送られ、設定ファイルは作業ツリーの外とはいえファイルに残るためである。

### 4.3. 信頼性・可用性 (Reliability/Availability)

記録は時点の記録とする（AC-01）。OpenCode の版が上がると答えが変わりうるので、記録は確かめた版を明記し、引用する側（#906・#907）がその版を前提にできるようにする。

### 4.4. 互換性 (Compatibility)

確かめるのは、この開発機（macOS）の OpenCode v2.2.6 と、その裏で動くサーバだけとする（§2.3）。

### 4.5. 保守性 (Maintainability)

記録は、問いごとの節に分け、#906・#907 が節の単位で引用できるようにする（AC-02）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   chief のセッションへの拒否（ADR-0046、`.claude/settings.json`）は緩めない。調査の中で、エージェントは pane へ入力を送らない。TUI への入力と pane の起動は人が行う。
-   LLM の呼び出し（OpenCode を通した DeepSeek、`claude -p`）は費用がかかるので、実験を始める前に人の承認を得る（`CLAUDE.md`「Tool Execution Safety」）。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。本書だけで使う語は次のとおりである。

-   **OpenCode のサーバ:** OpenCode の TUI が既定でつながる、裏で動くサーバ（`opencode service`）。`opencode api` はこのサーバに要求を送る。
-   **実験のセッション:** 実験の手順が、使い捨ての worktree で作った OpenCode のセッション。実際のタスクのセッションとは別である。
-   **使い捨ての worktree:** 調査のためだけに `origin/main` から detached で作り、調査の後に消す worktree。HEAD が detached で PR がないので、`/runpr` は PR を探した後に止まる（要件定義の際に決めたこと）。
-   **書き込みの呼び出し:** サーバのセッションの状態を変える呼び出し（プロンプトやコマンドの送信、シェルのコマンドの実行、モデルの切り替え、セッションの作成と削除、実行の中断、問いや権限の確認への答え）。読み取りの呼び出しと区別する。
-   **`form`:** OpenCode のサーバが、セッションが答えを待っている入力の欄として返すもの（`session.form.list`）。
