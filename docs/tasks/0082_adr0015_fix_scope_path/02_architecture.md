## 1. 設計の全体像

本タスクでは、ADR-0015（`docs/dev/adr/0015-untrusted-review-threads.md`）を文書の上で直すだけで、コードは変えない（[01_requirements.md](01_requirements.md) F-001〜F-004）。直すのは次の 3 か所である。

-   「決定」の修正の範囲の項目 1 行を書き換える。
-   「採らなかった案」の最後に項目を 1 つ足す。
-   「経緯」の最後に項目を 1 つ足す。

直しは決定の変更なので、ADR-0015 の変更は本書と同じ 3 文書の PR で行う（[01_requirements.md](01_requirements.md) 1 章）。実装の PR は、その変更を確かめる `_checks/` のスクリプトを足すだけである。

**設計原則:**

-   **ADR に新しい規則を足さない。** 書き換えた項目が述べる規則は、タスク 0036 が決め、ガイドの 6 章とコードがすでに従っているものに限る（[01_requirements.md](01_requirements.md) 1 章）。
-   **ADR-0015 のほかの部分には触れない（AC-05・AC-06）。** 変更を 3 行に限れば、ほかの部分が変わらないことをレビュアーが diff で確かめやすい。

**設計の際に決めたこと（2026-11-10）:**

-   **ADR-0015 の変更を確かめるのは、実装の PR で足す `_checks/` のシェルスクリプトとする。スクリプトは、本書の PR のスカッシュのコミットとその親を比べる（7 章）。** 前例のタスク 0078 と同じ形である（`docs/tasks/0078_adr0024_server_env_result/02_architecture.md` 7 章）。
    -   理由：ADR-0015 の変更は本書の PR で入る。規約の `diff` の確かめ（スクリプトと記録した diff の読み取り）は、PR のブランチの上でマージベースと比べる。そのため、実装の PR では ADR-0015 の変更が見えない。記録した diff の読み取りも、`/runpr` がマージベースで再確認するので、この形では成り立たない（`docs/dev/conventions/requirements_process.md`「`diff` verification」）。
    -   採らなかった案：差分の AC を置かず、AC を内容だけ（`manual`）にして、範囲は本書の PR のレビューで diff を読んで確かめる案。実装の PR は要らなくなる。しかし、前後の関係を差分の AC として書くという規約（`docs/dev/conventions/requirements_process.md` §1）を省くことになる。
    -   ADR：なし。本タスクの確かめ方の選択で、本タスクの中で閉じる。

概念モデルの Mermaid の図は省く。変わるのは 1 つの文書の 3 行だけで、コンポーネントの関係がない（`docs/dev/conventions/requirements_process.md`「Simple Process」の「May be omitted」）。

## 7. テスト戦略

ADR-0015 の変更は本書の 3 文書の PR に入る。そのため、確かめる変更の前と後は、その PR が `main` に入ったスカッシュのコミットの親と、そのスカッシュのコミットである。

-   **書き換えた項目の内容（AC-01）、「採らなかった案」の項目の内容（AC-03）、「経緯」の項目の要旨（AC-04）:** 自然言語の内容なので、本書の PR のレビューで読んで確かめる（`manual`）。
-   **構造の確かめ（AC-02・AC-05・AC-06、AC-03・AC-04 の位置とリンク先・AC-04 の形）:** 変更の前と後の関係なので、タスクの `_checks/` に置くシェルスクリプトで上の 2 つのコミットを比べる（`diff`。`docs/dev/conventions/requirements_process.md`「4. Acceptance Tests」）。スクリプトは 2 つのコミットを引数で受け取る。日本語の見出しの文字列は使わず、節の位置は `## ` の見出しの順序で決める（ADR の節の順序は `docs/dev/conventions/adr.md`「Template」にある）。
    -   AC-02 のうち、1 行の中の差分が太字の文の書き換えと 1 か所の挿入に限ることは、スクリプトで確かめる。挿入の位置が許可リストの中身を述べる文の直後であることは、本書の PR のレビューで読んで確かめる（`manual`）。
-   恒久のテストは足さない。文の言い回しを確かめる文書テストは、`CLAUDE.md`「Testing Strategy」が禁じる。

**規約の例外：`diff` の確かめを、変更の PR の上ではなくマージの後に行う。**

-   **元の規約:** `diff` の確かめは、PR のブランチの上で 1 回行い、マージベースと PR のコミットを比べる（`docs/dev/conventions/requirements_process.md`「`diff` verification」）。
-   **例外にする理由:** 2 つの規約が両立しないためである。
    -   ADR の決定を変える変更は、その決定をする PR が行う（`docs/dev/conventions/adr.md`「Approval and the PR」）。本タスクでは、それは本書の 3 文書の PR である。
    -   簡易な進め方では、3 文書が承認されるまで実装の成果物を書かない（`docs/dev/conventions/requirements_process.md`「Simple Process」）。
    -   そのため、スクリプトは 3 文書の PR の中には書けない。
-   **代わりの手当て:** 3 文書の PR の ADR-0015 の差分は 3 行なので、その PR のレビューで読んで確かめる（`manual`）。マージの後のスクリプトがずれを見つけたときは、ADR-0015 を直す PR を別に作る。
-   **この例外が及ぶ既存のテスト:** ない。
