## 2. 実装のステップ (Implementation Steps)

### フェーズ 1: ADR-0015 の直しの確かめ（設計書 7 章、AC-02〜AC-06）

3 文書の PR のマージの後に `/runplan` で行う。

**変更するファイル:** `docs/tasks/0082_adr0015_fix_scope_path/_checks/check.sh`（新規）、本計画（§7 の記録）

-   [ ] **ステップ 1-1**: 確認のスクリプトを `_checks/check.sh` に書く（手本は §1.3）。コミットを 2 つ（変更の前と後）引数で受け取り、ADR-0015 をその 2 つのコミットで読んで、次を確かめる。節の位置は `## ` の見出しの順序で決め、日本語の文字列は使わない。
    -   2 つのコミットの間で追加・削除・変更されたファイルが、ADR-0015 と本タスクのディレクトリの下だけである（AC-06）。
    -   後の版から、5 つ目の `## ` の見出しの 2 行上の行（「採らなかった案」の最後の項目）と最後の行を除くと、前の版と行の数が同じで、違う行はちょうど 1 行である。その行は 3 つ目と 4 つ目の `## ` の見出しの間（「決定」）にある（AC-02 の 1 行の部分・AC-05）。
    -   違う 1 行の、先頭の `-   **` で始まり `**` で終わる太字の部分を除いた残りについて、前の版の残りが、後の版の残りの先頭の部分と末尾の部分をつなげたものになっている。つまり、後の版は前の版に 1 か所だけ挿入したものである（AC-02 の 1 行の中の部分）。
    -   除いた「採らなかった案」の項目が `-   **` で始まり、本タスクの要件定義書（`../../tasks/0082_adr0015_fix_scope_path/01_requirements.md`）にリンクする。前の版の同じ位置（5 つ目の `## ` の見出しの 2 行上）は空行でなく、項目が足されたのはその後ろである（AC-03 の位置とリンク先）。
    -   後の版の最後の行が `- YYYY-MM-DD ` で始まる「経緯」の項目で、本タスクの要件定義書にリンクする（AC-04 の形とリンク先）。

    違反があれば 0 でない終了コードで終わり、違反の内容と、確かめた 2 つのコミットの完全な ID と、`check.sh` の blob の ID を出力する。コメントと文字列リテラルは英語で書く。
-   [ ] **ステップ 1-2**: スクリプトが狙った理由で失敗できることを確かめる。3 文書の PR のスカッシュのコミットから使い捨てのブランチを作り、次の壊し方を 1 件ずつ一時的なコミットにする。スカッシュのコミットの親とその一時的なコミットを引数にして走らせ、狙った項目で失敗することを確かめる。
    -   AC-06：索引 `docs/dev/adr/README.md` の 1 行を変える。
    -   AC-02・AC-05：「背景」の 1 行を変える。「決定」のほかの項目の 1 行を変える。
    -   AC-02（1 行の中）：書き換えた項目の、太字の部分の後ろにある既存の文を 1 つ消す。
    -   AC-03：足した「採らなかった案」の項目のリンク先をほかの文書にする。
    -   AC-04：足した「経緯」の項目を消す。

    使い捨てのブランチは push せず、確かめた後に消す。壊し方ごとの結果は、ステップ 1-3 のコミットのメッセージに書く。
-   [ ] **ステップ 1-3**: 確認のスクリプトを、3 文書の PR のスカッシュのコミットの親とそのスカッシュのコミットを引数にして実行する。出力・終了コード・2 つのコミットの完全な ID を本計画 §7 に書き、本計画の進み具合とともにコミットする。確かめる 2 つのコミットは `main` の上で決まっているので、この後に実装のブランチにコミットが増えても §7 の記録は変わらない。`make test` と `make lint` を通す。

**PR を作る直前の確かめ直し。** ステップ 1-3 の後で `_checks/` を変えるコミットが入ったときは、ステップ 1-2 と 1-3 をやり直して §7 の記録を改める。対象は、`/runplan` のレビュー（手順 6〜7.7）の後、PR を作る前のコミットで、`.claude/commands/_lib/task-pr-handoff.md` Part B の手順 1・2 の修正も含む。`/runplan` がこれを実装のまとまりとして拾わないよう、チェックボックスにはしない。

**完了の条件:** 確認のスクリプトが終了コード 0 で終わり、その記録が本計画 §7 にある。壊し方ごとの結果が、ステップ 1-3 のコミットのメッセージにある。`make test` と `make lint` が通る。
