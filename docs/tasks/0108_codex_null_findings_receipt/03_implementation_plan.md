## 1. 実装の概要 (Implementation Overview)

### 1.1. 目的

`.claude/commands/runpr.md` の step 3〜5 を設計書 3.1〜3.4 のとおりに書き換え、Codex の要約コメントが結果のない完了のときに、受領コメントで利用者に確かめて進めるようにする。あわせて、ガードテスト `TestRunprDocContract` の `listings_print_no_body` を設計書 3.5 のとおりに広げ、ADR-0013 の「決定」から食い違いの記述を消す（設計書 3.6）。

### 1.2. 実装の原則

-   **絞り込みとガードテストを先に固める。** 設計書 8 章の優先順位 1 のとおり、一覧の絞り込みが本文を出さないことを、ガードテストを広げて確かめてから、規則の文を書く。偽のデータと期待する値を先に足し、今の絞り込みでテストが落ちることを確かめてから、絞り込みを書き換える。
-   **`runpr.md` の文は英語で書く**（`CLAUDE.md`「Document language」の原則 (b)）。利用者に示す問いの文、選択肢、要約の行の決まった文は、今の `runpr.md` の問いと要約の行と同じく日本語で書く。
-   **テストのコメント・識別子・文字列のリテラルは英語で書く**（`CLAUDE.md`「Go Idioms」）。偽の受領コメントの本文も英語の観測の形（要件書 1 章の背景）で、日本語の文字列のリテラルはない。
-   **止まる側に倒す。** 設計書 1.1 のとおり、崩れたものは補わずに Indeterminate にするか判定をやり直す。文を書くときも、迷ったら止まる側の書き方を選ぶ。
-   **今の振る舞いは、結果のない完了と受領コメントに関わる所のほかは変えない**（AC-04、設計書 1.1）。

-   **ユニットテスト:** 製品の Go のコードを足さないので、新しいユニットテストはない（設計書 7.1）。

-   **後方互換:** 今の偽の要約コメントの項目は、期待する状態を変えずに通ることで、AC-04 の今の振る舞いを確かめる（設計書 3.7）。
-   **結合テスト:** コマンドの定義の手順は自動の結合テストを持たない（設計書 7.4）。実装の PR を `/runpr` で進めるとき（1.3 の決定 3）に、新しい絞り込みが gojq で動くことを観察できる。
