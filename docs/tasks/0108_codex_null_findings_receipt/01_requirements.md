## 1. 概要 (Overview)

**目的:** 本書は、Codex の要約コメントが `completed` なのに `has_any_findings` が `null` のとき、`/runpr` が受領コメントを使って利用者に確かめ、利用者が認めたときに次の段階へ進むようにする要件を定義する。

**背景:**

本書の用語（要約コメント、状態の行、完了の印、結果のない完了、受領コメント、断りのコメント、利用者が認めた完了）は 6 章で定義する。「規則 1」〜「規則 6」は、`runpr.md` step 3 の「State of the latest request」の規則の番号で、規則 1 は判定できない状態（Indeterminate）、規則 2 は完了（Completed）、規則 3 は想定外の投稿（Ended (unexpected post)）である（`.claude/commands/runpr.md:535-555`）。「依頼」は同じ step 3 の最新の依頼（latest request）、「依頼したコミット」はその依頼が対象とするコミット（requested commit）である。

-   `/runpr` の step 3 は、Codex の要約コメントの 2 行目（状態の行）だけを `--jq` で読む。`completed` で `has_any_findings` が JSON の真偽値のときだけ完了の印とし、`completed` で真偽値でないものは `indeterminate` とする（`.claude/commands/runpr.md:416-457`）。要約コメントの状態が `indeterminate` なら、規則 1 で判定できない状態として止まる（`.claude/commands/runpr.md:537-539`、`:599-617`）。真偽値を求めるのは、タスク 0031 の観測で、完了したレビューでは必ず真偽値、途中では `null` だったためである（[0031 設計書](../0031_codex_pr_review/02_architecture.md) 1.2・3.2）。
-   PR #998 の `/runpr` は、この規則で止まった。2026-11-18T13:51:47Z の手動の依頼に対し、Codex は要約コメントを `completed` に更新したが、`has_any_findings` は `null` だった。レビューの結果は、Codex が投稿した受領コメント（1 行目が `<!-- codex-review-receipt:v1 -->`）のほうにあった（issue #1005）。
-   受領コメントは、今は `codex` の種類のコメントとして数えるだけで、本文は読まない（`.claude/commands/runpr.md:430-436`）。依頼の後に作られた `codex` の種類のコメントは、規則 3 で想定外の投稿（Ended (unexpected post)）になる。ただし、規則 1・2 が先に当たるときは規則 3 に進まない（`.claude/commands/runpr.md:537-549`）。step 3 の一覧の絞り込みは、要約コメントの最初の 2 行のほかは本文をセッションに出さない（`.claude/commands/runpr.md:413-414`）。ガードテスト `TestRunprDocContract` の `listings_print_no_body` は、絞り込みを偽の本文で実行して、本文が出ないことを確かめる（`cmd/yt2column/fixpr_docs_test.go:187-189`）。
-   本書の作成にあたり、PR #998 の Codex のコメントを読み、受領コメント 2 件を確かめた（[2026-11-18 の受領コメント](https://github.com/isseis/yt2column/pull/998#issuecomment-6980619384)、[2026-11-19 の受領コメント](https://github.com/isseis/yt2column/pull/998#issuecomment-6996903008)）。どちらも、1 行目が `<!-- codex-review-receipt:v1 -->`、2 行目と 4 行目が空、3 行目が結果の行、5 行目が ``**Reviewed commit:** `<短い SHA>` `` だった。結果の行は、1 件目が `Codex Review: Didn't find any major issues. :+1:`、2 件目（要約コメントの `has_any_findings` が `false` だった手動の依頼のレビュー）が `Codex Review: Didn't find any major issues. Already looking forward to the next diff.` で、`Didn't find any major issues.` の後ろの文が違った。短い SHA は、どちらも 10 桁だった。2 件目のとおり、受領コメントは結果が真偽値のレビューでも投稿される。
-   `codex-review-state:v1` の行にも受領コメントにも、OpenAI の公式の文書はない（issue #1005）。

対応 issue: [#1005](https://github.com/isseis/yt2column/issues/1005)（関連: PR [#998](https://github.com/isseis/yt2column/pull/998)（止まった PR）、PR [#984](https://github.com/isseis/yt2column/pull/984)（受領コメントのない `null`）、タスク 0031（今の判定の規則の元）、openai/codex#57326、openai/codex#57619）

本書は、`/runpr` が利用者に尋ねる条件、受領コメントの受け入れる形と読む範囲、人の答えの扱い、エスカレーションとの関係、ガードテストの対象、ADR を決める。規則を `runpr.md` の判定の規則のどこに置くか、`--jq` の絞り込みの書き方、ガードテストの偽のデータの作り方は、`02_architecture.md` が決める（`design_handoff.md`）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   Codex が要約コメントに結果を書かずに完了し、受領コメントに指摘なしの結果を書いたとき、`/runpr` が止まらず、利用者の確認を経て次の段階へ進めるようにする。
-   受領コメントの本文をセッションに出さないまま、受け入れる形を決まった形に限る。

### 2.2. スコープ (In Scope)

-   `.claude/commands/runpr.md` の step 3 の、レビューの状態の判定と停止の報告（F-001〜F-004）。
-   `.claude/commands/runpr.md` の、利用者が認めた完了の LAST_REVIEWED への算入、step 4 のマージの質問の要約と詳細ファイル、最後の報告（F-005）。
-   ガードテスト `TestRunprDocContract`（`cmd/yt2column/fixpr_docs_test.go`）の、受領コメントの絞り込みへの拡張（F-006）。
-   ADR-0013 の更新（F-007）。

### 2.3. スコープ外 (Out of Scope)

-   Codex の状態の行の、ほかの形の変化への対応（`status: failed` など）（issue #1005）。
-   指摘ありの形の受領コメントの受け入れ（要件定義の際に決めたこと）。
-   利用者が認めたことの永続的な記録（squash コミット、PR へのコメント）と、実行をまたいでの引き継ぎ（要件定義の際に決めたこと）。
-   受領コメントのない `null` の完了（#984 の形）を進めること。今までどおり止める。
-   `_lib/task-pr-handoff.md` Part B step 5（PR を開いた直後の開始の印の確かめ）。要約コメントの更新の時刻だけを見て、状態の行の形を確かめないので、影響を受けない（`.claude/commands/_lib/task-pr-handoff.md:301-326`）。
-   `mergepr`・`fixprguard`・`codexreview`・`pr-review-escalation.md`・`review-records.sh` の変更。LAST_REVIEWED は `runpr.md` が決めて渡す値で、その渡し方は変えない（`.claude/commands/runpr.md:563-575`）。
-   chief の変更。chief の画面の読み取りが `/runpr` の問いとして特別に読むのはマージの質問だけで（`internal/chief/screen.go:111-117`）、step 3 にはすでにほかの `AskUserQuestion` の問いがある（`.claude/commands/runpr.md:510`・`:757`）。新しい問いも、それらと同じくマージの質問でない問いとして扱われる。
-   リアクション（👍）を読むこと。今も読まない（`.claude/commands/runpr.md:497-498`）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

本章の用語は 6 章と 1 章の背景の冒頭で定義する。

#### F-001: 結果のない完了で利用者に尋ねる条件

最新の依頼について、次のすべてが成り立つとき、`/runpr` は判定できない状態として止まる代わりに、利用者に尋ねる（F-003）。

1.  要約コメントがちょうど 1 件で、依頼の後に更新されている。
2.  その要約コメントの状態の行が、結果のない完了である。
3.  依頼の後に作られた `codex` の種類のコメントのうち、断りのコメントの例外（`.claude/commands/runpr.md:544-549`）に当たるものを除いたもの（以下、数える `codex` のコメント）が、受領コメント 1 件だけである。受領コメントは、断りのコメントの例外に当たらないものとして数える。
4.  その受領コメントが、受け入れる形（F-002）に合う。
5.  受領コメントの短い SHA が、要約コメントの `commit_sha` の先頭と一致する。
6.  要約コメントの `commit_sha` が、依頼したコミットである。

**Acceptance Criteria**:
- **AC-01**: `runpr.md` の step 3 は、上の 1〜6 がすべて成り立つとき、判定できない状態として止まらず、F-003 の問いを出す、と述べる。
- **AC-02**: `runpr.md` の step 3 は、1 と 2 が成り立ち、数える `codex` のコメントが依頼の後に 1 件もなく、依頼から約 15 分たっていないときは、止まらず、依頼もせずにポーリングを続ける、と述べる。この待ちは、「Never post while ... Waiting or Indeterminate」の Waiting に当たる。今の待ちと同じく、依頼の時刻から数える期限を延ばさない。
- **AC-03**: `runpr.md` の step 3 は、受領コメント（AC-05）を規則 3 の想定外の投稿に数えない、と述べる。要約コメントが `running` の間や、まだ依頼の後に更新されていない間に受領コメントが届いても、止まらずに、要約コメントの完了か依頼から約 15 分の期限まで待つ。
- **AC-04**: `runpr.md` の step 3 は、結果のない完了でない要約コメント（`completed` で `has_any_findings` が真偽値、`running`、ほかの判定できない形）と、要約コメントが 2 件以上ある場合の判定を変えない。`completed` で `has_any_findings` が真偽値なら、受領コメントの有無によらず今までどおり完了の印である。

#### F-002: 受領コメントの受け入れる形と読む範囲

受領コメントは GitHub の応答から読む、信頼できない入力である。`/runpr` は、要約コメントと同じ一覧の読み取りの中で、受領コメントの形を `--jq` の絞り込みで判定し、判定の結果だけをセッションに出す。

**Acceptance Criteria**:
- **AC-05**: 受領コメントとみなすのは、著者が `Bot` の種類で名前が `<awaited-reviewer>[bot]` で、本文の 1 行目がちょうど `<!-- codex-review-receipt:v1 -->` のコメントだけである。`runpr.md` の step 3 はこの定義を述べる。
- **AC-06**: 受け入れる形は、本文を改行（LF）で分けた行が次のとおりのものだけである。`runpr.md` の step 3 は、この形と、ほかの形の受領コメントは受け入れる形に合わないとすることを述べる。
    -   1 行目がちょうど `<!-- codex-review-receipt:v1 -->`。
    -   2 行目と 4 行目が空。
    -   3 行目が `Codex Review: Didn't find any major issues.` で始まる。後ろの文は問わない。
    -   5 行目が、ちょうど `` **Reviewed commit:** ` `` と、小文字の 16 進の 7〜40 桁と、`` ` `` を並べたもの。

    6 行目から後は読まず、形を問わない（後から行が増えてもよい）。行の終わりに CR がある行、5 行に満たない本文、大文字の 16 進、桁数が範囲の外の SHA は、補わずに受け入れる形に合わないとする。
- **AC-07**: 受領コメントについてセッションに出るのは、URL・`created_at`・受け入れる形に合うかの真偽値・形に合ったときの短い SHA だけである。結果の行の後ろの文を含め、本文の文字列は出さない。形に合わないときは、短い SHA も出さない。`runpr.md` の step 3 の絞り込みと、それを述べる文がこれを満たす。
- **AC-08**: 受領コメントの読み取りで使うのは、コメントの `user.type`・`user.login`・`body`（絞り込みの中で 1〜5 行目だけ）・`html_url`・`created_at` だけである。ほかのメンバーは使わない。
- **AC-09**: 受け入れる形に合わない受領コメントは、F-004 の判定できない状態（規則 1）として扱う。コマンドの定義の手順でありコードではないので、番兵のエラー（sentinel error）は定義しない。本文の大きさの上限は設けない。読むのは 1〜5 行目だけで、6 行目から後を読まないためである。コメントの件数の上限も、今の一覧と同じく設けず、最後のページまで読む。`html_url` と `created_at` は、今の一覧のほかのコメントと同じ規則で読む（`.claude/commands/runpr.md:407-415`）。

**Acceptance Criteria**:

- **AC-11**: `runpr.md` の step 3 は、利用者が「指摘なしとして進む」を選ぶと、その要約コメントの `commit_sha` の完了の印があるものとして、最新の依頼を Completed と同じに扱い、step 3 の続き（スレッドの処理、エスカレーション、CI）へ進む、と述べる。
- **AC-12**: `runpr.md` の step 3 は、利用者がそれ以外を答えたとき（「止める」と自由記述を含む）は、今の判定できない状態と同じく止まり、同じ報告に受領コメントの URL を加える、と述べる。
- **AC-13**: `runpr.md` の step 3 は、次のことを述べる。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   受領コメントを待つ間（AC-02・AC-03）は、今の約 30 秒ごとのポーリングを続ける（`.claude/commands/runpr.md:581-583`）。受領コメントの読み取りは、今の一覧の読み取りと同じ API の呼び出しの中で行い、呼び出しの回数を増やさない。
-   #984 の形は、すぐに止まる代わりに、依頼から約 15 分たってから止まる（要件定義の際に決めたこと）。

### 4.2. セキュリティ (Security)

-   受領コメントは、GitHub の応答から読む信頼できない入力である。著者が `Bot` の種類で名前が `<awaited-reviewer>[bot]` のコメントだけを受領コメントとし（AC-05）、決まった形に合うものだけを受け入れ、補わない（AC-06）。
-   本文の文字列はセッションに出さない（AC-07）。セッションはファイルを編集できるエージェントなので、Bot の本文に書かれた指示がエージェントに届かないようにするためである。この点で、要約コメントの最初の 2 行のほかは本文を出さないという今の原則（`.claude/commands/runpr.md:413-414`）と、[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) の考え方を保つ。
-   受領コメントだけでは完了としない。利用者が URL から GitHub で本文を確かめ、「指摘なしとして進む」を選んだときだけ進む（AC-10・AC-11）。`/runpr` が自動で進むことはない。
-   受け入れる危険：完了を待つ PR レビュアーの名前の `Bot` が書いた受領コメントの形を、利用者の確認を経て信じる。Codex 自身が実際にはレビューしていないのに指摘なしの受領コメントを投稿した場合は、利用者の確認でも見分けられない。これは、`completed` と真偽値がそろっても中身のあるレビューを保証しない、今の危険（[0031 設計書](../0031_codex_pr_review/02_architecture.md) 5 章）と同じ種類である。
-   本変更はレビューの関門（LAST_REVIEWED の定義）を変えるので、実装の PR は Escalation の基準で PR レビューの追加の依頼の対象になる（[ADR-0013](../../dev/adr/0013-review-setup.md)）。
-   条件付きのガイド（`docs/dev/security.md`）：N/A。`docs/dev/security.md` の規則と前提は変えない。条件付きのガイドの適用条件（外部コマンド `yt-dlp`、API キー、キャッシュ、LLM API への送信、信頼できないテキストのプロンプトや記事への埋め込み）にはどれも当たらない。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   形の合わないもの、そろわないものは、補わずに今までどおり止める（AC-14）。Codex が受領コメントの形を変えたときも、止まる側に倒れる。
-   止まったときの回避の手段（GitHub で Codex のレビューを確かめて `/mergepr` で直接マージする、手で依頼を投稿して再実行する）は、今のまま使える（`.claude/commands/runpr.md:619-629`）。

### 4.4. 互換性 (Compatibility)

-   `completed` で `has_any_findings` が真偽値の要約コメントでの振る舞いは変わらない（AC-04）。受領コメントがあっても、今までどおり完了の印で判定する。
-   利用者が認めたことは実行の中だけで持つので、古い実行の記録や、ほかのコマンドとの間の新しい約束はできない（AC-17）。

### 4.5. 保守性 (Maintainability)

-   受領コメントの受け入れる形（1 行目の印、結果の行の前方、5 行目の形）は、`runpr.md` の step 3 の絞り込みとそれを述べる文、ガードテストの偽のデータの 3 か所にある。Codex が形を変えたときは、3 つとも変える。
-   `codex-review-state:v1` の行と受領コメントには公式の文書がない。観測に基づく規則であり、形が変われば止まる（ADR-0013 の「結果」）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   CLAUDE.md の「Reject, don't normalize」に従い、受領コメントの形を補わずに拒む。
-   CLAUDE.md の「Document tests check values, structure, and executable examples, never prose」に従う。ガードテストは、本文を出してはならない `--jq` の絞り込み（信頼の境界で実行するコマンドの例外）を実行して確かめる。`runpr.md` の文の中身は、PR のレビューで読んで確かめる。
-   CLAUDE.md の「Keep internals unobservable」の考え方に従い、利用者が認めた完了の記録を、ほかのコマンドが読む値にしない。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。
-   **要約コメント:** 完了を待つ PR レビュアー（Codex）の要約コメント。著者が `Bot` の種類で名前が `<awaited-reviewer>[bot]`、1 行目がちょうど `<!-- codex-pull-request-review-summary -->` のコメント（`.claude/commands/runpr.md:446-448`）。
-   **状態の行:** 要約コメントの 2 行目。`<!-- codex-review-state:v1 <JSON> -->` の形をとる。
-   **完了の印:** 状態の行の `status` が `completed` で `has_any_findings` が JSON の真偽値のもの（`.claude/commands/runpr.md:451-453`）。
-   **結果のない完了:** 状態の行が、`runpr.md` の step 3 の状態の行の形（`code_review` がオブジェクトで、`status` が文字列、`commit_sha` が小文字の 16 進の 40 桁）に合い、`status` が `completed` で、`has_any_findings` が JSON の `null` のもの。`has_any_findings` が欠けているものや、ほかの型のものは含まない。
-   **受領コメント:** 完了を待つ PR レビュアーが投稿した、本文の 1 行目がちょうど `<!-- codex-review-receipt:v1 -->` のコメント（AC-05）。
-   **断りのコメント:** ほかのアカウントのメンションから数秒のうちに Codex が投稿する、誰も名指さないコメント。`runpr.md` の step 3 は、作られた時刻の 1 分前より後からその時刻までに、3 つの一覧のどれかのメンションが作られたか更新された `codex` の種類のコメントを、想定外の投稿に数えない（断りのコメントの例外。`.claude/commands/runpr.md:544-549`）。
-   **利用者が認めた完了:** 結果のない完了の要約コメントについて、受領コメントで利用者が「指摘なしとして進む」を選んだもの（AC-11）。その実行の中だけで完了の印として扱う。
