## 1. 概要 (Overview)

**目的:** 本書は、記事をブラウザ拡張だけで作る経路（以下、拡張だけの経路）を実装し、localhost サーバと Native Messaging のホストを撤去するタスクの要件を定める。構成は、タスク 0090 の[要件定義書](../0090_extension_only_architecture/01_requirements.md)（以下、0090 要件書）と[設計書](../0090_extension_only_architecture/02_architecture.md)（以下、0090 設計書）が決めた。本書は、その構成をコードが満たすことを確かめる受け入れ基準と、0090 設計書が本タスクの要件定義に委ねた事項を定める。

**背景:**

今の主経路は、拡張が集めた字幕を Native Messaging のホストが localhost サーバへ中継し、サーバが記事を作る構成である（[project_overview.md](../../dev/project_overview.md)「決定済みの方針」）。タスク 0090 は、この構成を拡張だけの構成に改めることを決め、その決定を ADR に記録した（[ADR-0048](../../dev/adr/0048-extension-only-generation.md)・[ADR-0049](../../dev/adr/0049-wasm-core-sharing.md) ほか）。コードと仕様の文書は、まだ今の構成のままである。

-   拡張の権限は `activeTab`・`scripting`・`nativeMessaging` の 3 つで、拡張は API キーを持たない（`extension/static/manifest.json:16`、`extension/test/secretsAbsent.test.ts:15`）。
-   拡張が要求する Chrome の最小の版は 110 である（`extension/static/manifest.json:8`）。
-   ビューアのページのタイトルは、固定の `yt2column` である（`extension/static/viewer.html:5`）。
-   `make build` は、`yt2column`・`yt2column-server`・`yt2column-nmhost` の 3 つのバイナリを作る（`Makefile:65-70`）。開発用のサーバ（`cmd/yt2column-devserver`）は `make build-dev` で作る（`Makefile:76-78`）。
-   `make wasm-check` は、`internal/transcript`・`internal/writer`・`internal/llm/claude`・`internal/pricing`・`internal/llm/devfake` を WASM でビルドするだけである（`Makefile:328`）。記事を作る処理を拡張から呼ぶ入口（記事生成モジュール）はない。
-   ADR のうち 25 本は、決定がコードと仕様の文書とまだ食い違っていることを、#773 にリンクする食い違いの記述（§6）で述べている（[0090 実装計画書](../0090_extension_only_architecture/03_implementation_plan.md) §1.4）。

対応 issue: [#773](https://github.com/isseis/yt2column/issues/773)（親: [#769](https://github.com/isseis/yt2column/issues/769)、前提: [#772](https://github.com/isseis/yt2column/issues/772)（タスク 0090）、関連: [#869](https://github.com/isseis/yt2column/issues/869)（Web Store の掲載と申請）、[#874](https://github.com/isseis/yt2column/issues/874)（シークレットモード））

**本書の記述範囲:** 本書は、拡張だけの経路で利用者と開発者が観測できる振る舞い、利用者に示す状態ごとの内容、アクセシビリティ、撤去するもの、書き換える文書と ADR、一部の受け入れ基準の確かめ方を定める。構成の手段（記事生成モジュールの関数、ジョブの記録の形、Service Worker（以下、SW）の調停、ページの間のメッセージ、権限と CSP の値など）は、0090 設計書が決めたものを前提にし、本書はその節を挙げて参照する。0090 設計書が決めていない手段（ファイルの分け方、ビルドタグの付け方、PR の区切りなど）は、本タスクの `02_architecture.md` と `03_implementation_plan.md` で決める。要件定義の過程で挙がった手段の注意点は、[design_handoff.md](design_handoff.md) に申し送る。

-   **CLI は残し、拡張と同じ記事を作る処理を使う（#773）。** ADR: なし（ADR-0048 と ADR-0049 に記録済みである）。

-   **ADR の食い違いの記述を、実装の PR で、解消した範囲で除く（#773）。** 対象の ADR は、issue #773 の本文の「食い違いの記述を置いた ADR」の節が挙げる。ADR: 各 PR が、解消した ADR の記述を除く。

**要件定義の際に決めたこと（2026-11-15）:**

-   **進め方は通常の進め方（`full`）とする。** 変更が、拡張、Go のコア、CI、仕様の文書、25 本の ADR に及び、新しい仕組み（記事生成モジュール、オプションページ、ジョブの記録、SW の調停）を作るからである。簡易な進め方から除外する変更に当たるかどうかは、当たると判断した。security.md の前提（拡張は API キーを持たず、ネットワークへ送らない）と脅威モデルを変え、信頼の境界を変えるためである。人は通常の進め方を選び、この判断を覆していない。ADR: なし（このタスクの進め方の決定で、タスクの外に及ばない）。
-   **0090 設計書 §3.12 の出典は、この PR のレビューで人が開いて確かめ直す。** 0090 設計書 §3.14.1 は、本タスクの要件定義の前に、人が各ページを開いて確かめ直すとした。出典はサブエージェントが WebFetch で読み、要約を通して得たものだからである。本書を書く作業を止めないために、確かめ直しは本書の PR のマージの前に行い、結果を §5 に日付とともに書く。条件の記述が 0090 設計書と食い違っていたときは、その条件に関わる決定を人と決め直す。人が開くページは、下読みで補足か疑問が出た条件に絞り、ほかの条件は下読みで足りるとした（2026-11-15）。下読みは、出典を WebFetch で改めて取得し、条件ごとにページの文を原文のまま抜き出して、0090 設計書の記述と並べたものである。抜き出した文が条件と合う条件まで人が開き直しても、得るものが少ないためである。ADR: なし（確かめの時期と範囲の決定で、本タスクの中で閉じる）。
-   **ポップアップに、オプションページへのリンクをいつも置く（F-001）。** 0090 設計書 §3.5 は、API キーが設定されていないときだけ、オプションページを開く操作を示すとした。それだけでは、API キーを変えたいか消したい利用者は、ブラウザの拡張のメニューからオプションページを探すことになる。採らなかった案は、0090 設計書のとおり API キーがないときだけ示す案である。ポップアップの操作が 1 つ増えるが、設定の画面を見つけやすくすることを選んだ。ADR: なし（ポップアップの表示の決定で、[ADR-0008](../../dev/adr/0008-launch-path.md) の起動の経路を変えない）。
-   **ビューアのページのタイトルは「`<動画のタイトル> - yt2column`」とし、動画のタイトルがないときは見出しを使う（F-003）。** 0090 設計書 §1.2 は、ページのタイトルに動画のタイトルを出すとし、拡張の名前を添えるかどうかを本タスクに委ねた。YouTube の履歴の項目は「`<動画のタイトル> - YouTube`」の形なので、拡張の名前を添えると、ブラウザの履歴で、動画のページと記事のページを見分けられる。開発用のビルドは、`yt2column` の代わりに、開発用の印の付いた拡張の名前（AC-17）を添える。履歴で公開用のビルドの記事と見分けるためである。採らなかった案は、動画のタイトルだけにする案である。履歴の中で YouTube の項目と区別しにくい。ADR: なし（ビューアの表示の決定で、0090 設計書 §1.2 が #773 の要件で扱うとした）。
-   **ジョブの記録がないビューアも、空でないタイトルを持つ。履歴の項目の動画のタイトルが上書きされると分かったときは、短く切った動画のタイトルを URL に加える（F-003）。** 0090 設計書 §3.13 は、記録がないビューア（ブラウザを再起動して復元したビューアなど）が固定のタイトルを出すと、Chrome が履歴の項目の動画のタイトルを書き換えうるとし、確かめた結果に応じて、まず「ページのタイトルを書き換えない（空のままにするなど）」、それでも上書きされるなら URL にタイトルを加える、とした。本書は、このうち空のタイトルを採らない。タイトルのないページは WCAG 2.4.2（ページのタイトル、レベル A）を満たさず、CLAUDE.md「Accessibility」はビューアに WCAG 2.2 AA を求めるためである。記録がないビューアは、状態の分かる固定のタイトルを出す。開始の文脈が残っているビューア（入力を受け取れなかった、開始が拒否された）は、開始の文脈の動画のタイトルを使う。URL に加えたときは、記録も開始の文脈もないビューアも、URL の動画のタイトルをページのタイトルにする。上書きされるかどうかの手動の確認は、ページのタイトルを実装する PR より前に行う（[design_handoff.md](design_handoff.md) H-05）。採らなかった案は 3 つである。0090 設計書の手順にそのまま戻す案は、空のタイトルを採りうる。上書きを受け入れる案は、0090 設計書 §3.14.3 が受け入れ基準にした「履歴の項目の動画のタイトルが失われない」を捨てる。初めから URL にタイトルを加える案は、上書きされると分かる前に、0090 設計書 §1.2 と [ADR-0010](../../dev/adr/0010-extension-stores-nothing.md) の決定（URL から動画のタイトルを除く）を変える。ADR: なし（URL にタイトルを加えることになったときは、その PR で ADR-0010 を改める）。
-   **API キーの経路（AC-20）、料金のかかる生成の始まり方（AC-07）、止まった実行と記事の残り方（AC-08・AC-09）、料金を不明と示す状態（AC-11）は、単体テストと、開発用のビルドでの手動の確認の両方で確かめる（§5）。** 0090 設計書 §3.14.3 が、確かめる手段を本タスクの要件定義で決めるとしたものである。単体テストは `chrome.*` の fake で各経路の判定と表示を確かめる。閉じたタブの復元、履歴からの表示、ブラウザの再起動、実行中のタブを閉じる操作は、ブラウザの振る舞いに依存し、fake では再現できないので、料金のかからない開発用のビルドで手で確かめる。採らなかった案は、単体テストだけにする案と、手動の確認だけにする案である。前者はブラウザに依存する経路を確かめられず、後者は変更のたびに確かめ直す手間が大きく、壊れたことに気づくのが遅れる。ADR: なし（受け入れ基準の確かめ方で、本タスクの中で閉じる）。
-   **画面の文言は、状態ごとに示す内容を本書で定め、文字列そのものは実装で書く（F-003）。** [0050 要件定義書](../0050_viewer_tab/01_requirements.md)の「本書の記述範囲」と同じ分け方である。0090 要件書 §2.3 は、画面の配置も #773 の要件定義で決めるとした。本書は、新しく加える要素（オプションページへのリンク、新しい状態の表示と操作、開発用のビルドの印）を、今の画面の節の構成を保ったまま加えることと、AC-18 の条件だけを定め、置き場所は設計で決める（[design_handoff.md](design_handoff.md) H-04）。配置は文言と同じく、実物を見て決める方が確かなためである。文言は英語と日本語の両方を持つ（CLAUDE.md「Go Idioms」の拡張の項目、[ADR-0029](../../dev/adr/0029-extension-ui-languages.md)）。文字列は、PR のレビューで読んで確かめる。ADR: なし（文書の書き分けの決定で、本タスクの中で閉じる）。
-   **オプションページと、ポップアップとビューアに加える要素は、CLAUDE.md「Accessibility」のすべての項目を満たし、どの項目も先送りしない（F-003）。** 試作でも、機能を確かめるだけの最小の画面でもなく、利用者が使う画面だからである。ADR: なし（CLAUDE.md の規則を当てるだけである）。
-   **撤去するパッケージは、0090 設計書 §2.3 の一覧から、残るコードが import するものを除いたものとする。`internal/job` と `internal/privatefile` は撤去しない（F-006）。** issue #773 の本文は、サーバだけが使うパッケージの例に `internal/job` を挙げるが、`internal/job` を import するのは CLI（`cmd/yt2column/run.go:15`）で、サーバは使わない。0090 設計書 §2.3 は `internal/privatefile` を撤去するパッケージに挙げるが、その一覧は 2026-11-12 の `main`（`ca0570c6`）で調べたもので、その後に `internal/chief` が `internal/privatefile` を import した（`internal/chief/records.go:19`、#876）。どちらも 2026-11-15 の `main`（`0347321c`）に対して `git grep` と `go list` で確かめた。0090 設計書 §2.3 も、撤去の前に `go list -deps` で確かめるとしている。撤去するテストの補助も、同じく import の有無で決める（`internal/llm/claude` などのテストの補助は `internal/loopbacktest` を使う）。ADR: なし（事実の訂正で、ADR-0049 と ADR-0045 の決定は撤去するパッケージの一覧を持たない）。
-   **書き換える文書に、0090 設計書 §3.14.2 の表にない文書とコマンドの定義を加える（F-007）。** 加えるのは、`docs/translation_glossary.md`、`docs/dev/guides/cli.md`、`docs/dev/guides/fixprguard_guide.md`、`.claude/commands/_lib/task-pr-handoff.md`、`.claude/commands/_lib/simple-process.md` である。用語集は「主経路」「ビューアの URL」「記録」「ジョブの状態」などをサーバとホストの意味で定義する（`docs/translation_glossary.md:46-47,55,91`）。cli.md は localhost サーバとその設定ファイルを述べる。残りの 3 つは、文書のガードのコマンドに `./cmd/yt2column-server` を含む（`.claude/commands/_lib/task-pr-handoff.md:40`、`.claude/commands/_lib/simple-process.md:429`、`docs/dev/guides/fixprguard_guide.md:595`）。パッケージを撤去すると、エージェントが実行するそのコマンドが失敗するためである。ADR: なし（書き換える文書の範囲の決定で、本タスクの中で閉じる）。
-   **開発用のビルドの fake に、API キーが拒まれる結果と、設定の検査の結果を加える（F-005）。** 料金を不明と示す状態（AC-11）を開発用のビルドで手で確かめると決めたので、401 で拒まれる結果が要る。今の fake のシナリオは、空の応答、打ち切り、API の失敗、期限切れだけである（`internal/llm/devfake/scenario.go:42-48`）。0090 設計書 §3.9 は開発用のビルドが Anthropic の API を呼ばないとし、§3.6 は Models API の結果で保存を決めるので、開発用のビルドのオプションページで設定の検査の結果（AC-02 の 200・401・ほかの結果）を出す fake も要る。ADR: [ADR-0045](../../dev/adr/0045-dev-fake-llm.md) を更新した（fake の振る舞いを、生成のジョブに加えて設定の検査でも、ビルドのときに選んだシナリオだけで決め、入力した値の中身からは決めない）。
-   **オプションページは、記事生成モジュールか Worker を読み込めず検査できないときは、保存しない（F-001）。** 0090 設計書 §3.6 は、`checkSettings` が `ok` か `unverified` を返したときだけ保存するとしている。読み込めなければどちらの結果もないので、保存しない。Models API の呼び出しの期限切れは、これと分け、確かめられなかった（`unverified`）として保存する（0090 設計書 §3.6）。ADR: なし（0090 設計書 §3.6 の規則を当てるだけである）。
-   **API キーか保存した設定が原因で、LLM の API を呼ぶ前に失敗した実行は、料金に触れず、API キーの設定が要ることを示す（F-002・F-003）。** 当たるのは、予約の後、`generate` を呼ぶ前に API キーがなかった実行（`api_key_missing`）と、保存した設定が形に合わなかった実行（`settings_invalid`、次の項目）である。どちらも、0090 設計書 §3.8 の「API キーが設定されていない」の状態で示す。[ADR-0022](../../dev/adr/0022-cost-estimate.md) は、記事が完成しなかった実行の料金を一律に不明と示す。その理由は、記事が完成しなくても料金がかかりうることを示すためで、API を呼んでいない実行には当てはまらない。採らなかった案は 2 つである。不明と示す案は、料金がかかっていないと確かめられる実行を不明と示し、0090 設計書 §3.8 の「API キーが設定されていない」の行に料金の表示を加えることになる。料金がかかっていないと明示する案は、同じジョブ ID で作り直した実行では前の実行の料金がかかっていることがあり、どの実行の料金かが伝わりにくい。ほかの失敗（`transcript_too_long` や `internal` など）は、最初の呼び出しの前に起きるものがあっても、記録からは呼び出しがあったかを見分けられないので、不明と示すままにする。ADR: ADR-0022 を更新した（料金を不明と示す実行から、この 2 つの失敗を除く）。
-   **保存した設定が形に合わないときは、新しい失敗の値 `settings_invalid` にし、API キーが設定されていない状態として、設定し直す手順を示す（F-001・F-003）。** 0090 設計書 §5.2 は、読み戻した設定が形に合わないときを「API キーが設定されていない状態として扱い、設定し直す手順を示す」とした。一方で、拒否の値を `internal` としたので、ビューアはほかの内部の失敗と見分けられず、その手順を示せない（`InternalDetail` は記録とログにだけ置く。0090 設計書 §4.1）。そこで、0090 設計書 §4.1 の `WasmFailure` に `settings_invalid` を加える。記事生成モジュールの `generate` が、LLM の API を呼ぶ前の設定の検査で拒否したときに返す。文言は、未設定とは分け、保存した設定が使えないので設定し直すことを示す。採らなかった案は 2 つである。記事の生成が失敗した状態に手順を添えて示す案は、0090 設計書の §4.1 と §5.2 の両方から外れ、料金の示し方も決め直すことになる。`internal` のまま示す案は、設定し直せば直ることが利用者に分からない。ADR: なし（値の集合を持つ ADR はない。0090 設計書 §4.1 の変更で、本タスクの中で閉じる）。
-   **オプションページは、API キーとワークスペース ID を、保存も削除もそれぞれ 1 回の書き込みで行う。ワークスペース ID の項目はいつも書き、空の文字列を「指定なし」とする（F-001）。** 0090 設計書 §3.6 は、2 つの値を 1 回の書き込みで保存し、ワークスペース ID は空でないときだけ保存し、欄が空なら保存済みのワークスペース ID を消す、とした。欄を空にして保存するには、値を書く呼び出しと項目を消す呼び出しの 2 回が要り、2 回目だけが失敗すると、新しい API キーに古いワークスペース ID が残る。ワークスペース ID の項目をいつも書けば、1 回の書き込みで済む。ワークスペース ID の指定なしは、誤りではなく正当な使い方である。ワークスペースに属する API キーなら、API キーだけで、そのワークスペースで API を使える（ワークスペースに属さないキーは `anthropic-workspace-id` が要る。`internal/llm/claude/errors.go` の `statusGuidance`）。月ごとの利用の上限を設けた専用のワークスペースで API キーを作れば、ワークスペース ID は要らない（AC-34）。複数の項目を書く 1 回の書き込みが、両方とも反映されるか、どちらも反映されないかは、Chrome の文書に書かれていない。1 回の書き込みの一部だけが反映されることはないものとして受け入れる。採らなかった案は 2 つである。0090 設計書のとおり 2 回に分けて、途中の失敗を受け入れる案は、意図しないワークスペース ID で API を呼びうる。2 つの値を 1 つの項目にまとめる案は、項目の名前、SW が API キーの有無を見る規則、読み戻す値の検査が変わり、まれな失敗に対して変える量が大きい。ADR: [ADR-0003](../../dev/adr/0003-llm-config-contract.md) を更新した（拡張は、ワークスペース ID が指定なしのとき、その名前を未設定として返す）。
-   **ワークスペースに属さない API キーを、ワークスペース ID なしで保存したときも、0090 設計書 §3.6 の判定の表のとおりにする（F-001）。** Anthropic の認証の頁によると、ワークスペースに属さない API キーでワークスペース ID を省くと、API は 400 を返す。このとき、保存の前の Models API の確かめは「ほかの結果」なので、保存したうえで確かめられなかったと示し、その後の記事の生成は 400 で失敗する。採らなかった案は、Models API の 400 で保存しない案と、保存したうえでワークスペース ID を確かめるよう示す案である。400 にはワークスペース ID の欠け以外の原因もあり、状態コードだけではワークスペース ID の欠けと決められない。示す状態も 1 つ増える。代わりに、README で、ワークスペースに属さない API キーにはワークスペース ID が要ることを述べる（AC-34）。ADR: なし（0090 設計書の決定を変えない）。
-   **開発用のビルドで手で出せない状態と場合は、単体テストで確かめる（F-005）。** 0090 設計書 §7.2 は、開発用のビルドで §3.8 のすべての状態を確かめるとした。しかし、fake の結果でもブラウザの操作でも出せないものがある。結果不明（60 秒たっても予約の結果がない）、「入力を受け取れなかった」のうち、入力を受け取る前に SW が止まった場合、「完成したが保持できなかった」（`chrome.storage.session` への書き込みの失敗）、「開始が拒否された」のうち内部の失敗（Worker の読み込みの失敗など）、予約から `generate` の呼び出しまでの短い間に API キーが消された場合である。これらは、`chrome.*` と Worker の fake に失敗を注入する単体テストで確かめる（AC-29、[design_handoff.md](design_handoff.md) H-06）。ADR: なし（受け入れ基準の確かめ方で、本タスクの中で閉じる）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   利用者が、拡張のほかに何も導入せず、自分の API キーで記事を作れるようにする。
-   サーバとホスト、それだけが使うコード、開発用のサーバを撤去する。
-   仕様の文書と ADR を、拡張だけの経路に合わせる。

### 2.2. スコープ (In Scope)

-   0090 設計書 §3.11 の表のすべて（加えるもの、変えるもの、撤去するもの）と、同じ節のテストの扱い。ただし、撤去するパッケージは §1「要件定義の際に決めたこと」のとおり、残るコードが import するものを除く。
-   開発用のビルドの fake に、API キーが拒まれる結果と、設定の検査の結果を加えること（§1「要件定義の際に決めたこと」）。
-   仕様の文書の書き換え（0090 設計書 §3.14.2）と、§1「要件定義の際に決めたこと」で加えた文書とコマンドの定義の書き換え。
-   ADR の食い違いの記述の削除（issue #773 の本文が挙げる ADR）。
-   本番の構成での手動の確認（Chrome と Brave で 1 本ずつ）と、開発用のビルドでの手動の確認。

### 2.3. スコープ外 (Out of Scope)

-   Web Store の掲載の文面、プライバシーポリシーの本文、申請、manifest の `key` の Web Store の公開鍵への置き換え。#869 が扱う（0090 設計書 §3.12）。

-   古い版の拡張が保存した値（`sharedToken`・`serverPort`）を消す仕組み（0090 設計書 §3.6）。

### 3.1. 機能一覧

#### F-001: 導入と API キーの設定

拡張のほかに何も導入せず、利用者が自分の API キーを設定できるようにする。

**Acceptance Criteria**:

-   **AC-01**: 記事の生成のために、拡張のほかに何も導入する必要がない。Native Messaging のホストの manifest を登録せず、サーバも動かしていないブラウザのプロファイルで、拡張だけで記事が完成する。`make build` は `yt2column` だけを作り、拡張の manifest は `nativeMessaging` の権限を持たない。
-   **AC-02**: オプションページは、API キーの欄、ワークスペース ID の欄、保存のボタン、削除のボタンと、記事生成モジュールのビルドの情報（コミットと Go の版）を持つ（0090 設計書 §3.6）。ワークスペース ID の欄は任意で、空は指定なし（API キーが属するワークスペースを使う）として受理する。公開用のビルドの保存のボタンは、形の検査を通った値で Models API を 1 回呼び、結果に応じて次のとおりにする（0090 設計書 §3.6・§6.4）。開発用のビルドは、Models API を呼ばず、fake のシナリオの結果で同じとおりにする（AC-29）。
    -   形が合わない：保存せず、どの欄が合わないかを示す。前後の空白を除くなどの補正をしない。
    -   200：API キーとワークスペース ID を保存し、設定されていることを示す。
    -   401：保存せず、キーが拒まれたことを示す。
    -   ほかの結果（通信の失敗、Models API の呼び出しの期限切れ、403、429、5xx、読めない応答）：保存したうえで、確かめられなかったことを示す。
    -   記事生成モジュールか Worker を読み込めないか、検査の途中で Worker が異常終了したか、オプションページの検査の全体の期限を過ぎた：保存せず、検査できなかったことを示す。全体の期限は、Models API の呼び出しの期限切れが先に「確かめられなかった」になるよう、呼び出しの期限より長くする（[design_handoff.md](design_handoff.md) H-09）。
    -   `chrome.storage.local` への書き込みが失敗した：保存できなかったことと、保存をやり直す手順を示す。
    -   保存も削除も、API キーとワークスペース ID を 1 回の書き込みで書くか消し、2 回に分けない（§1「要件定義の際に決めたこと」）。
    -   保存しなかったとき（形が合わない、401、検査できない）は、前に保存した値を変えない。API キーの欄が空のときは形が合わないとして扱うので、ワークスペース ID だけを変えるときも、API キーを入力し直す。
-   **AC-03**: オプションページは、保存した API キーを画面に再び示さず、設定されているかどうかだけを示す。API キーの欄は、入力した文字を伏せて示す。保存の後、API キーの欄を空にする。ログインして同期を有効にしたプロファイルで、ブラウザが API キーの欄の値をパスワードとして保存するよう勧めない。
-   **AC-04**: 保存した API キーとワークスペース ID は、ブラウザを再起動した後も残る。削除のボタンは両方を消す。ワークスペース ID の欄を空にして保存すると、ワークスペース ID は指定なしになり、前に保存したワークスペース ID は使われない。
-   **AC-05**: 拡張の設定の項目は、API キーとワークスペース ID だけである。プロバイダ、モデル、effort を選ぶ設定はない。拡張の記事の生成は、3 つの工程とも本番の構成（[production_profile.md](../../dev/production_profile.md)）で API を呼ぶ。
-   **AC-06**: ポップアップは、いつもオプションページを開くリンクを持つ。API キーが設定されていないときにポップアップのボタンを押すと、API キーの設定が要ることとオプションページを開く操作を示し、ビューアを開かず、LLM の API を呼ばない。予約の後、LLM の API を呼ぶ前に API キーがなかったとき（`api_key_missing`）と、保存した設定が形に合わなかったとき（`settings_invalid`）は、ビューアが、同じく設定が要ることとオプションページを開く操作を示し、料金に触れない。`settings_invalid` の文言は、保存した設定が使えないので設定し直すことを示す。

#### F-002: 生成の開始・実行・停止と、記事の残り方

記事の生成を、ポップアップのボタンで始め、ビューアのタブの寿命に従わせ、完成した記事をブラウザを終了するまで持つ。

**Acceptance Criteria**:

-   **AC-07**: 料金のかかる記事の生成は、利用者がポップアップのボタンを押したときだけ始まる。拡張のページ（ポップアップ、ビューア、オプションページ）を開くこと、ビューアの URL を開くこと、ビューアの再読み込み、閉じたタブの復元、履歴からの表示では始まらない。失敗した実行と、結果の分からない実行を、自動ではやり直さない（[ADR-0028](../../dev/adr/0028-no-automatic-resend.md)）。
-   **AC-08**: 記事の生成は、ポップアップのボタンで背面に開いたビューアのタブの中で行われ、一度も前面にしなくても完成する。そのタブを閉じるか読み込み直すと、生成は止まり、ほかの場所で続かない。止まった実行は、完成した記事として残らず、ビューアは記事の生成がページとともに止まった状態を示す（0090 設計書 §6.3）。記事の生成の実行中に、利用者がそのビューアのページを操作した後は、再読み込みやタブを閉じる操作の前に、ブラウザが確かめの表示を出す。一度も操作していないビューアでは表示が出ないことを受け入れる（0090 設計書 §3.4）。
-   **AC-09**: 完成した記事は、ブラウザを終了するまで、ビューアの再読み込みと閉じたタブの復元の後も表示できる。ブラウザを終了するまでの間に拡張の再読み込みか更新があったとき、および上限で捨てたときは除く。ブラウザの終了、拡張の再読み込みと更新、上限で捨てた後は、ビューアは記事が失われたことと、動画を開いて作り直すためのリンクを示す。完成した記事は `chrome.storage.local` にもディスクにも書かず、ジョブの記録はコピーした字幕と概要欄を持たない。上限は、記録 50 件、記録の大きさの合計 8 MiB、記事 1 本 256 KiB とし、捨てる順と、上限で開始を拒否する条件は 0090 設計書 §3.2.3 のとおりにする。
-   **AC-10**: 同じ動画の照会は、今と同じ範囲で働く。API キーが設定されているときの生成の開始は、照会付きでもそうでなくても、同じ入力のジョブが処理中か完成していれば、記事の生成を始めずにそのジョブを示す。同じ入力のジョブが失敗したか止まっていれば、同じジョブ ID のまま記事の生成をやり直す。照会付きの生成の開始は、同じ動画の別のジョブが処理中か完成していれば、既存の記事を表示するか、現在の選択範囲で生成するかを選ばせる。対象は、ブラウザを終了するまでに拡張が持つジョブの記録である（0090 設計書 §3.3）。API キーが設定されていないときは、同じ入力のジョブが完成していても、AC-06 のとおり設定が要ることを示し、ビューアを開かない（0090 設計書 §3.3 は、生成の開始で API キーの有無を先に確かめる）。
-   **AC-11**: ビューアは、完成した記事の推定の料金を示す。記事が完成しなかった実行のうち、API が API キーを拒んだ実行（`api_key_rejected`）、記事の生成が失敗した実行（`api_key_missing` と `settings_invalid` を除く失敗。`run_timeout` を含む）、記事の生成がページとともに止まった実行では、料金を一律に不明と示す。0 を含め、どの金額も、工程ごとにも合計でも示さない。LLM の API を一度も呼ばずに失敗した実行（`api_key_missing`・`settings_invalid`）は、料金に触れない（AC-06、[ADR-0022](../../dev/adr/0022-cost-estimate.md)）。
-   **AC-12**: 記事の生成のどの工程のリクエストでも API が 401 を返したとき、ビューアは、API キーが拒まれたこと（期限切れ、失効、誤り、またはブラウザからの呼び出しを許さない組織である可能性）、オプションページを開く操作、作り直す手順を示す。示した手順のとおりに新しいキーを保存し、YouTube のタブで同じ選択範囲のままポップアップのボタンをもう一度押すと、同じジョブ ID のまま記事の生成をやり直す（0090 設計書 §3.3・§3.8）。
-   **AC-13**: 同時に走る記事の生成は 2 つまでとする。3 つ目の開始は、生成を始めずに拒否され、ポップアップは開始が拒否された状態を示す（0090 設計書 §3.2.3）。

#### F-003: 画面の表示とアクセシビリティ

利用者に示す状態ごとの内容と、画面のアクセシビリティを定める。

**Acceptance Criteria**:

-   **AC-14**: ポップアップとビューアは、0090 設計書 §3.8 の各状態を、同じ表の「示すもの」の内容で示す。ただし、本書が変えた点（AC-06・AC-11 の `api_key_missing` と `settings_invalid`）は本書のとおりにする。再読み込みの後に示すかどうかは、表の「ビューアの再読み込みの後」の列のとおりにする。示す文は、状態と失敗の値ごとの固定の文言だけで、Go のエラーの文、Anthropic の応答の本文、ブラウザの例外の文を含まない。文言は英語と日本語の両方を持つ。
-   **AC-15**: 0090 設計書 §3.8 の「結果不明」の文言は、もう一度押しても二重に生成されないのが、同じ入力の記事が処理中か完成しているときに限られることを示す。それ以外のときも二重に生成されない、とは述べない。「入力を受け取れなかった」の文言は、料金がかかっていないことと、もう一度ボタンを押す手順を示す。「完成したが保持できなかった」の文言は、読み込み直すと記事が失われることを示す。
-   **AC-16**: ビューアのページのタイトルは、「`<動画のタイトル> - yt2column`」である。動画のタイトルがないときは、動画のタイトルの代わりに見出しを使う。ブラウザの履歴のページとタブに、このタイトルが出る。開始の文脈が残っているビューア（入力を受け取れなかった、開始が拒否された）は、開始の文脈の動画のタイトルを使う。ジョブの記録も開始の文脈もないビューア（記事が失われた状態と、開始の文脈が消えた後の入力を受け取れなかった状態）は、URL が動画のタイトルを持つとき（§1「要件定義の際に決めたこと」で URL に加えることになったとき）はそれを使い、持たないときは状態の分かる、空でない固定のタイトルを持つ。どのビューアも、ページのタイトルを空にしない。ブラウザを再起動してビューアを復元した後も、履歴の項目の動画のタイトルが失われない。開発用のビルドは、`yt2column` の代わりに、開発用の印の付いた拡張の名前（AC-17）を添える。
-   **AC-17**: 開発用のビルドは、ポップアップとビューアで、開発用のビルドであることを目に見える印で示し、拡張の名前に開発用の印を持つ。公開用のビルドと別の拡張の ID を持ち、開発用のビルドで保存した値は、公開用のビルドの保存した値を上書きしない（0090 設計書 §3.9）。
-   **AC-18**: オプションページと、ポップアップとビューアに加える要素（オプションページへのリンク、§3.8 の新しい状態の表示と操作、開発用のビルドの印）は、CLAUDE.md「Accessibility」の各項目を満たす。キーボードだけで操作でき、フォーカスが見える。各操作は、画面に見えるラベルと一致するアクセシブルな名前を持つ。状態と結果は、フォーカスを動かさずに支援技術へ知らせる。明るいテーマと暗いテーマの両方でコントラストを満たし、状態を色だけで示さない。ページの `lang` は表示の言語と一致し、押せる領域は 44×44 CSS ピクセル以上である。`prefers-reduced-motion` のもとでは動きを止める。オプションページの表示の言語は、ほかの画面と同じく `resolveLocale` で決める（ADR-0029）。
-   **AC-19**: 0090 要件書・0090 設計書と本書が変えると定めたもののほか、利用者から見えるポップアップとビューアの機能と、有効な ADR の決定は変わらない。0090 要件書・0090 設計書と本書のどれも挙げていない決定を変えるときは、設計か計画の際に人と決めて記録する。ビューアが表示しコピーする無効化した表示用の Markdown、保存するファイルのバイト列、推定の料金の 3 つは、同じ入力と同じ LLM の出力に対して、2026-11-15 の `main`（`0347321c`）の `internal/server/status_test.go` が期待する値と同じである。生成の開始の入力を受理するかどうかは、同じ `main` の `internal/server/request_test.go` が期待するとおりである。完了の時点の検査と失敗の分類は、同じ `main` の `internal/server/generation_test.go` が期待するとおりである（ただし、失敗の値は 0090 設計書 §4.1 と本書の値の集合にする）。

#### F-004: API キーと送信の守り

API キーを出さず、送り先を Anthropic の API に限る。

**Acceptance Criteria**:

-   **AC-20**: API キーが通る経路は、0090 設計書 §5.4 の経路（オプションページの入力の欄、`chrome.storage.local`、実行するビューアとオプションページから Worker への受け渡し、`https://api.anthropic.com` へのリクエストの `x-api-key` のヘッダ）だけである。API キーは、少なくとも次の先に出ない：開発者向けのログ、エラーの表示、ビューアの URL、保存するファイル、コピーする文章、LLM に送るプロンプト、`chrome.storage.sync`、`chrome.storage.session`、SW へのメッセージ、`BroadcastChannel`、記事生成モジュールの結果と進み具合、ポップアップ・表示するビューア・SW が受け取る `chrome.storage` の変更の知らせ。保存した API キーを画面に再び示さない（AC-03）。SW は API キーの値を読まず、項目の名前だけで API キーの有無を判断する。
-   **AC-21**: 拡張のページと Worker は、拡張自身のファイルと `https://api.anthropic.com` のほかへリクエストを送らない。LLM の API の呼び出しは、リダイレクトに従わず、応答の本文を 8 MiB で読むのをやめ、1 回ごとに、応答のヘッダが届くまで 15 分の期限を持つ。オプションページの Models API の呼び出しは、リダイレクトに従わず、応答の本文を読まず、15 分以下の期限を持つ（値は設計で決める。[design_handoff.md](design_handoff.md) H-09）。実行するビューアは、記事の生成の全体に 50 分の期限を持ち、過ぎたら生成を止めて `run_timeout` の失敗にする（0090 設計書 §5.3）。
-   **AC-22**: 公開用のビルドの manifest は、権限 `activeTab`・`scripting`・`storage` だけを持ち、`host_permissions`・`content_scripts`・`web_accessible_resources`・`externally_connectable` を持たない。拡張のページの CSP は 0090 設計書 §3.7.2 の値、`incognito` は `"not_allowed"`、`minimum_chrome_version` は `"142"` である。今の `key` を持ち、オプションページをタブで開く（0090 設計書 §3.7）。
-   **AC-23**: ポップアップが YouTube のタブに注入する関数と、そのタブのページのスクリプトは、`chrome.storage.local` の値を読めない。ブラウザを再起動した後も同じである。注入の前に、注入したスクリプトから読めないようにする設定が失敗したときは、ポップアップは関数を注入せず、開始が拒否された状態を示す（0090 設計書 §3.6・§5.1.4）。
-   **AC-24**: SW は、生成の開始を拡張自身のポップアップからだけ受け付ける。注入した関数とほかのタブからのリクエストを受け付けない。入力の受け取り、検査の拒否、予約は、開始の文脈のタブのビューアからだけ受け付ける。進み具合、結果、実行の Port は、ジョブの記録の `runner` と一致するページからだけ受け付ける。受け付けないリクエストと Port では、ジョブの記録を変えない（0090 設計書 §5.2「送り手の確かめ」）。
-   **AC-25**: 公開用のビルドの成果物（`extension/dist/`）は、`tsc` の出力、`static/` の写し、`cmd/yt2column-wasm` からビルドした記事生成モジュール、`go.mod` が定める Go の版のツールチェーンと中身が一致する `wasm_exec.js` だけを持つ。実行時にネットワークからコードを取得しない。公開する成果物（`yt2column` と公開用の記事生成モジュール）は、fake の LLM の部品を含まない（[ADR-0045](../../dev/adr/0045-dev-fake-llm.md)）。

**Acceptance Criteria**:

-   **AC-30**: CI は、拡張の検査で記事生成モジュールをビルドし、Go のファイルだけの変更でも、記事生成モジュールとその依存が変われば拡張の検査を走らせる。CI と lint の設定（`.github/workflows/ci.yml`・`extension/scripts/has-extension-changes.sh`・`.golangci.yml`）は、撤去したパッケージを対象にしない（0090 設計書 §3.11）。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

本タスクのコードは、次の信頼できない入力を受け取る。受理する形、拒否の理由、大きさの上限、構造を持つ入力の扱い、拒否したときに利用者に示すものは、0090 設計書 §5.2 の表の各行のとおりにする。どの境界でも、受理する形に合わない値を補正して使わない（CLAUDE.md「Reject, don't normalize」）。Go の側の拒否は番兵のエラー（`prepare` の拒否は `ErrInvalidInput` に包む。0090 設計書 §3.1.2）に、拡張の側の拒否は 0090 設計書 §4.1 の閉じた値の集合に対応させる。

| 境界 | 受理する形と拒否 | 上限 |
|---|---|---|
| コピーした字幕と動画メタデータ | 今のサーバの生成の開始の本文と同じ規則（security.md §8.2「受け取る入力の境界」）。合わなければ `invalid_body`。`PrepareRequest` は閉じたメンバの集合で、知らないメンバと重複したメンバを拒否する | 本文全体で 4 MiB |
| LLM の API の応答 | 今のアダプタと同じ。空の応答と打ち切りは失敗（CLAUDE.md「Empty is an error」）、`usage` は信頼しない。401 は `api_key_rejected`、ほかは今の失敗の値 | 8 MiB |
| Models API の応答 | 状態コードだけを読み、本文を読まない | ― |
| 利用者が入力する API キーとワークスペース ID | API キーは空でない印字可能な ASCII（0x21〜0x7E）、ワークスペース ID は空か `claudeparam.ParseWorkspaceID` の規則。前後の空白を除かない。`SettingsCheckRequest` は閉じたメンバの集合で、知らないメンバと重複したメンバを拒否する。合わなければ欄の名前を返して保存しない | 設けない（CLI と同じ） |
| `chrome.storage.local` から読み戻す設定 | 上と同じ規則で、記事生成モジュールが LLM の API を呼ぶ前に検査し直す。ワークスペース ID の空の文字列は指定なしである。オプションページは 2 つの項目をいつも一緒に書くので、API キーの項目があってワークスペース ID の項目がないときは、形に合わないとして扱う。読む項目は `anthropic.apiKey`・`anthropic.workspaceId` だけ。実行するビューアが読むときに API キーがなければ `api_key_missing`、記事生成モジュールが形に合わないと判断すれば `settings_invalid` の失敗にする。どちらも補正して使わず、利用者には API キーが設定されていない状態と、設定し直す手順を示し、料金に触れない（0090 設計書 §5.2、AC-06） | 設けない |
| `chrome.storage.session` のジョブの記録と開始の文脈 | 0090 設計書 §3.2.1 と §3.3 の形。`version` が 1、閉じたメンバの集合、状態ごとのメンバ。合わない記録はないものとして扱い、記事が失われた状態を示す | 記録 1 つ 512 KiB |
| ビューアの URL | クエリの名前は `r`・`k`・`u`・`e` の閉じた集合で、重複を拒否する。生成の入力にしない。合わなければ記事を表示せず何も送らない | `u` は今の上限（2,097,152 コードポイント。`extension/src/core/viewerUrl.ts:73`） |
| ページの間のメッセージと実行の Port | 0090 設計書 §3.3.1 の型。閉じたメンバの集合と送り手の確かめ（AC-24）。合わなければ受け付けない | 生成の開始の入力は 4 MiB |
| `BroadcastChannel` のメッセージ | 今の規則（`extension/src/viewerQuery.ts`）で、問いの値を記事のキーからジョブ ID に替える。合わなければ何もしない | 今と同じ |
| 記事生成モジュールの結果と進み具合 | 0090 設計書 §3.1.2 と §3.3.1 の形。閉じたメンバの集合で、知らないメンバと重複したメンバを拒否する。合わなければ `internal`（`result_shape`）の失敗 | 512 KiB |
| 開発用のコマンド（AC-28）が読む JSON のファイル | `PrepareRequest` と同じ規則で、記事生成モジュールと同じ処理が検査する。合わなければ拒否の理由を出して終わる。API キーは CLI と同じく環境変数から読み、出力に出さない（0090 設計書 §7.2） | 生成の開始の入力と同じ 4 MiB |

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   WASM のサイズと読み込みの時間に閾値を設けない。0090 設計書 §1.2 が、調査記録の値（17,300,194 バイト、読み込み 49.9〜206.5 ms）を受け入れた。
-   同時に走る記事の生成は 2 つまでである（AC-13）。

### 4.2. セキュリティ (Security)

[security.md](../../dev/security.md) を当てはめる。本タスクのコードは、API キーを扱い、LLM の API へデータを送り、字幕と動画メタデータ（信頼できないテキスト）をプロンプトと表示する記事に入れるので、条件つきのガイドの対象である。

-   **保つ規則。** API キーを、送信先へのリクエストを除くどの出力にも出さない（security.md §2、[ADR-0031](../../dev/adr/0031-secret-closure.md)、AC-20）。LLM に送るデータは今と同じにし、API キーをプロンプトに入れない（security.md §4）。記事と動画メタデータを、信頼できないテキストとして扱い、HTML を解釈しない（security.md §6、[ADR-0017](../../dev/adr/0017-viewer-markdown-rendering.md)、[ADR-0043](../../dev/adr/0043-copy-mention-neutralization.md)）。料金のかかる記事の生成を、利用者の明示の操作のときだけ始める（ADR-0008・ADR-0028、AC-07）。
-   **変える方針。** 0090 要件書 §4.2 の「変える方針」と 0090 設計書 §5.5 の方針の例外を、コードと security.md に入れる。拡張が API キーを `chrome.storage.local` に保存して使い、`storage` の権限を持ち、`nativeMessaging` を持たず、Anthropic の API へリクエストを送り、CSP に `'wasm-unsafe-eval'` を加え、成果物に `wasm_exec.js` を入れる。security.md の書き換えの要点は 0090 設計書 §3.14.2 にある。
-   **脅威モデル。** 0090 設計書 §5.1 の脅威モデルを、security.md §8 に書く。受け入れるリスクは 0090 設計書 §5.1.4 のとおりである。
-   **送信の守り。** AC-21 のとおりである。API キーを、リダイレクトの先を含め、Anthropic の API のほかの先へ送らない。これは受け入れるリスクにしない（0090 要件書 AC-19）。
-   **実データ。** 開発用のコマンド（AC-28）の入力のファイルは、利用者がコピーした字幕を含みうるので、リポジトリに入れない（security.md §7）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   失敗を成功として扱わない。空の応答と打ち切りは失敗である（CLAUDE.md「Empty is an error」）。
-   記事の生成の途中でビューアのタブが閉じられると、その生成は失われる。これは受け入れ、止まった状態として示す（AC-08、ADR-0048）。
-   一度も操作していないビューアが、確かめの表示なしで止まりうることは受け入れる（AC-08、0090 設計書 §3.4）。

### 4.4. 互換性 (Compatibility)

-   対象のブラウザは Chrome と Brave で、Chrome の最小の版は 142 である（[ADR-0026](../../dev/adr/0026-extension-platform.md)、[ADR-0030](../../dev/adr/0030-minimum-chrome-version.md)、AC-22）。
-   今の構成との互換の仕組みは設けない（AC-32）。

### 4.5. 保守性 (Maintainability)

-   記事を作る規則は Go の 1 か所に置き、Go と TypeScript の両方に書かない（AC-27）。
-   Go のモジュールも拡張の npm のパッケージも加えない。成果物に入れる外部のファイルは、Go のツールチェーンの `wasm_exec.js` だけである（0090 設計書 §5.5、CLAUDE.md「Dependencies」）。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」に従う。本タスクが変える方針は、§4.2 の「変える方針」と、0090 要件書 §4.2 に挙げたものである。
-   実 API の呼び出しと、ネットワークを使う操作は、その都度、人の承認を得る（CLAUDE.md「Tool Execution Safety」）。本番の構成での手動の確認は、Chrome と Brave で 1 本ずつ、背面のまま記事を完成させるもので、費用の目安は 1 本あたり約 0.33〜0.46 USD である（0090 設計書 §7.2）。あわせて、保存の前のキーの確かめに料金がかからないことを、Console の使用量で確かめる（0090 設計書 §3.13）。
-   テストを削除するときは、CLAUDE.md「Testing Strategy」の手順でカバレッジを比べる。
-   **受け入れ基準の確かめ方（要件定義の際に決めたこと）。** AC-07・AC-08・AC-09・AC-11・AC-20 は、単体テストと、開発用のビルドでの手動の確認の両方で確かめる。
    -   単体テスト：`chrome.storage`・`chrome.tabs`・Port・Worker の fake で、各経路の判定と記録の書き込み、状態ごとの表示を確かめる。開発用のビルドで出せない状態（AC-29）も、ここで確かめる。AC-20 は、0090 設計書 §7.3「API キーの経路」の lint かソースの検査も使う。
    -   開発用のビルドでの手動の確認：ビューアの URL を開く、再読み込み、閉じたタブの復元、履歴からの表示で生成が始まらないこと（AC-07）。実行中のタブを閉じる、読み込み直す操作で止まった状態になること（AC-08）。再読み込み、閉じたタブの復元、ブラウザの再起動、拡張の再読み込みの後の記事の表示（AC-09）。料金を不明と示す 3 つの状態（AC-11。API が API キーを拒んだ状態は、fake の 401 で出す）。開発者ツールのログ、ビューアの URL、`chrome.storage.session` に API キーが現れないこと（AC-20）。記録がないビューアの固定のタイトルで、履歴の項目の動画のタイトルが書き換わるか（AC-16）。これは、ページのタイトルを実装する PR より前に確かめる（[design_handoff.md](design_handoff.md) H-05）。
    -   ほかの受け入れ基準の確かめ方は、`03_implementation_plan.md` で決める。
-   **0090 設計書 §3.12 の出典の確かめ直し。** 2026-11-15 に行った。C-01〜C-18 の出典を WebFetch で改めて取得し、条件ごとにページの文を抜き出して下読みした。そのうえで、下読みで補足か疑問が出た C-05・C-12・C-13・C-14・C-17 を、人がページを開いて確かめた。ほかの条件は下読みで足りるとした（§1）。条件が変わったときに変わる決定に当たる食い違いはなかった。補足は次のとおりである。
    -   C-05：「`'wasm-unsafe-eval'` は 102 から使え、103 から明示が要る」は、Chrome の 2 つの出典にはない。[Mozilla の Bug 1766027](https://bugzilla.mozilla.org/show_bug.cgi?id=1766027) が、Chrome 102 は拡張に無条件で wasm を許し、103 からは `content_security_policy` に `'wasm-unsafe-eval'` を加えた拡張だけが wasm を使える、と記録している。最小の版は 142 なので、決定は変わらない。
    -   C-12：ブラウザから呼ぶには `anthropic-dangerous-direct-browser-access: true` のヘッダが要り、ZDR か Compliance API を有効にした組織では 401 になることを、人が確かめた。
    -   C-13：人が確かめ、問題はなかった。
    -   C-14：条件は合う。出典は新しく、一部のモデル（Covered Models）に 30 日の保持が要ると書くが、本番の構成のモデル（`claude-opus-5-5`）は当たらない。
    -   C-17：出典が通常とシークレットモードで共有すると書くのは `chrome.storage.sync` と `local` だけで、`session` には触れていない。`spanning` ではプロセスが 1 つなので `session` も 1 つの領域になり、`split` ではシークレットモードのプロセスが別なので分かれると考えられるが、公式の文書に明記はない。`not_allowed` にする決定は変わらない。シークレットモードの扱いを決め直すとき（#874）は、実機で確かめる。
    -   C-11：出典は、Port を開くだけでは SW の停止のタイマーが延びないと書く。0090 設計書は、SW が止まって Port が切れた場合をつなぎ直しで扱う（§3.3・§6.3）ので、決定は変わらない。
-   多くの受け入れ基準は、0090 設計書の節を手段と値の正本として参照する。0090 設計書は承認済みで、本タスクの設計が手段を変えるときは、変える箇所を `02_architecture.md` に挙げ、人と決める。

## 6. 用語集 (Glossary)

用語は [docs/translation_glossary.md](../../translation_glossary.md) と統一する。0090 要件書 §6 と 0090 設計書 §1 の用語（拡張だけの構成、記事生成モジュール、本番の構成、3 つの工程、記事の生成、実行、SW、ジョブ、ジョブの記録、ジョブ ID、実行するビューア、表示するビューア、予約）を、同じ意味で使う。加えて、次の語を使う。

-   **拡張だけの経路:** 拡張だけの構成で記事を作る経路。本タスクの後の主経路である。
-   **オプションページ:** API キーとワークスペース ID を設定・変更・削除する拡張のページ（0090 設計書 §3.6）。
-   **開発用のビルド:** `make ext-build-dev` が作る、fake の LLM を使う拡張（0090 設計書 §3.9）。
-   **公開する成果物:** 利用者に配る成果物。`yt2column` と、公開用のビルドの記事生成モジュールである（ADR-0045）。
-   **Worker:** 実行するビューアとオプションページが起動し、記事生成モジュールを動かす専用の Web Worker（0090 設計書 §1）。
-   **公開用のビルド:** `make ext-build` が作る、利用者に配る拡張。
-   **仕様の文書:** 0090 設計書 §3.14.2 の表の各文書。
-   **記録・ジョブの状態:** 本書では、ジョブの記録（0090 設計書 §3.2.1）と、その `state` の値（`running`・`done`・`failed`・`stopped`）を指す。用語集の「記録」（記事のキャッシュの値の組）と「ジョブの状態」（`unknown` を含む）は今のサーバの意味で、本タスクで改める（AC-33）。
-   **食い違いの記述:** ADR の決定が、仕様の文書やコードとまだ食い違っていることを述べ、それを解消する issue にリンクする記述（[adr.md](../../dev/conventions/adr.md)「Writing an ADR」）。
