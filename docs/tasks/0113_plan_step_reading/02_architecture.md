## 1. 設計の全体像

本タスクは、`internal/chief/task.go` の計画書の読み取り（`ParsePlan`）を変える。ステップを形 A・形 B・形 C から読み（[01_requirements.md](01_requirements.md) 3 章の冒頭、F-001）、読み取りの問題を計画書の中に持たせる。ステップを使う 2 つの判定（`state.go` の `nextFromPlan` と、`snapshot.go` の引き継ぎの判定）は、その問題を要確認の理由として示す（F-002・F-003）。`CLAUDE.md` の例外の文言にも 1 語を足す（AC-15）。

**設計原則:**

-   **読み取りの問題は、計画書全体ではなく、ステップを使う判定だけに出す。** PR の進み具合と完了の判定（`NextPR`・`Done`）はステップを使わないので、ステップを読めなくても今のまま動く（AC-11）。PR マーカーの対象ステップの読み取りの誤り（`task.go:497-499` の `stepsErr`）と同じ持ち方にする。
-   **ステップの数が 0 件であることと、読めないことと、残りがないことを、呼び出し側が区別できる形で返す。** 理由の文を分けるためである（AC-03・AC-07・AC-12）。
-   **形 A の読み方は変えない。** 正規表現（`task.go:522` の `stepBox`）も、読む範囲（文書全体）もそのままにする（AC-13）。

**設計の際に決めたこと（2026-11-19）:**

-   人に聞いた設計の判断は、次の 5 つである。どれも観測できる振る舞いを決めるので、要件書 1 章の「要件定義の際に決めたこと（2026-11-19）」に、理由と ADR の判断とともに記録した。
    -   形 B・形 C を 2 章の中だけで読むこと。
    -   ステップの行に似た行を、読めないものとすること。
    -   別の形のチェックボックスを、読めないものとすること。
    -   protocol 番号を上げないこと。
    -   `CLAUDE.md` の例外に 1 語を足すこと。
-   **ステップの読み取りの結果は、`Plan` の非公開のフィールドに、ステップの表と読み取りの誤りの組として持つ。`ParsePlan` は、ステップの問題では誤りを返さない。** 理由: AC-11 のとおり、完了の判定をステップの問題から切り離すためである。`ParsePlan` の呼び出し側（`Tasks` の読み込み、`snapshot.go:327` の `BranchPlan`）は、今のまま、PR の読み取りの誤りでだけ止まる。
    -   ADR: なし。本タスクの中で閉じる。
-   **`StepsLeft` は、真偽値と誤りを返す形に変える。ステップが 0 件のときは、専用の番兵の誤り（`errNoSteps`）を返す。** 理由: `nextFromPlan` が、0 件（AC-12）、読めない（AC-07）、残りなし（AC-03）の 3 つを分けて理由を選べるようにするためである。`errors.Is` で見分ける（`CLAUDE.md`「Error Testing」）。
    -   ADR: なし。本タスクの中で閉じる。

### 3.2. ステップの読み取り

`ParsePlan` は、フェンスの外の行（今の `fencedLines`、`task.go:193`）を上から 1 度なめ、次のことを行う。

-   **2 章の判定。** レベル 2 の見出しで `## 2.` と空白で始まる行から、次のレベル 1 かレベル 2 の見出しの前までを 2 章とする。
-   **形 A。** どの章でも、今の `stepBox` に合う行をステップとして読む。状態はその行の印で決める（今のまま）。
-   **形 B・形 C。** 2 章の中で、要件書 3 章の冒頭の形に合う行をステップの始まりとする。範囲の中のステップのチェックボックスの印を集め、範囲の終わりで状態を決める。
    -   チェックボックスが 0 個なら、誤りとする。
    -   すべて `x` か `-` なら、済みとする。
    -   それ以外は、残りとする。
-   **ステップの行に似た行と、別の形のチェックボックス。** 2 章の中で、要件書 F-002 の形に合い、受け入れる形に合わない行を見つけたら、その行を示す誤りとする。別の形のチェックボックスは、形 B・形 C の範囲の中でだけ判定する。
-   **重複。** 同じステップ ID が形を問わず 2 度現れたら、その ID を示す誤りとする。

誤りは最初の 1 つを持ち、`Plan` のステップの読み取りの誤りとする。誤りがあるときは、ステップの表を使わない。誤りの文は `errTaskDocument`（`task.go` の既存の番兵）で包み、どの条件かと、ステップ ID か行を含める（AC-07）。

形 B・形 C の正規表現の日本語のリテラル（`ステップ`）は、`CLAUDE.md`「Go Idioms」の `task.go` の例外の範囲に入る。形 B は見出しのテキストの固定部分に当たる。形 C は、AC-15 で足すステップの太字の行の頭に当たる。

### 3.4. 理由の文

`nextFromPlan` は、`StepsLeft` の結果で次の理由を返す。どれも次のコマンドを決めず、行は要確認になる（`state.go:455-461`）。

| `StepsLeft` の結果 | 理由 |
|---|---|
| 残りなし（今のまま） | `the plan has a PR left to create but no step left to do`（AC-03） |
| `errNoSteps` | 「PR が残っているが、ステップを 1 つも読めなかった」ことを示す文（AC-12） |
| ほかの誤り | 「計画書のステップを読めない」ことと、誤りの文（条件と ID か行）を示す文（AC-07） |

文は英語で書く（`CLAUDE.md`「Go Idioms」）。文言は実装で決める。テストは、文の一部の一致ではなく、どの理由かを見分けられる形で確かめる（7 章）。
