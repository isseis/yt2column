### 1.2. 実装の原則

-   **実装の PR が変えるのは、本タスクのディレクトリの下のファイルだけである。** ADR、調査記録、用語集は変えない。製品のコードと仕様の文書も変えない（要件書 §2.3・AC-27）。
-   **新しい恒久のテストは足さない。** スクリプトは 1 回走らせて結果を記録するもので、`make test` にも CI にも組み込まない（`requirements_process.md` §4「`diff` verification」）。
-   **issue の本文の編集は、ネットワークを使う操作として、その場で人の承認を得てから行う**（CLAUDE.md「Tool Execution Safety」、要件書 5 章）。

**記録の確かめ直し。** §7 の記録は、それを書くコミットで `HEAD` が進むので、PR の先頭のコミットとは一致しない。記録は、記録した実装の PR の組の後のコミット（§7 に書いたもの）から PR の先頭までの間に、本タスクのディレクトリの外のファイルと `_checks/` が変わらず、`main` も取り込んでいない間、有効とする。スクリプトが読む ADR とファイルの一覧の判定は、その間に変わらないためである。PR を作る直前に、`/runplan` はこの条件を `git diff --name-only <記録したコミット> HEAD` で確かめる。条件が崩れていれば、ステップ 1-4 の実装の PR の組をやり直して §7 の記録を改める。`_checks/` を変えたときは、ステップ 1-2 もやり直す。PR を作った後に実装の PR へコミットを足したときや `main` を取り込んだときも、同じ確かめが要る。やり直しでは、人の承認を得て本文を書き出し直し、`git fetch origin main` をし直す。`/runpr` はマージの前に `_checks/` のスクリプトを走らせない（`requirements_process.md` §4「Recheck」）。そのため PR の説明には、マージの前に人がこの条件を見ることを書く。この確かめ直しは、`/runplan` が実装のまとまりとして拾わないよう、チェックボックスにはしない。

**完了の条件:** #773 の本文の `ADR-0047` が `ADR-0048` になり、ほかが変わっていないことを `diff` で確かめ、その出力が §7 にある。確認のスクリプトが 4 つの組のすべてで終了コード 0 で終わり、その記録が本計画 §7 にある。壊し方ごとの結果が、ステップ 1-4 のコミットのメッセージにある。`make test` と `make lint` が通る。
