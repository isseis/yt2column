# 設計への申し送り（0099）

要件定義の時点で挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目にとった方針か、当てはまらない理由を記録する。

## H-01: マージの時点の確かめの置き場所と、確かめ直しで止まったときの承認の commit

**懸念:** 確かめ（F-003）を、Go の道具 `mergepr` に置くか、`/mergepr` と `/runpr` の手順に置くか。マージの直前の確かめ直し（AC-16）で止まったとき、`/runpr` がすでに push した承認の commit（文書の `approved` への書き換えや計画書の記録）をどう扱うか。

**なぜ重要か:** ADR-0014 は、決定的な判定をテストのある Go の道具に置くと定める。`/runpr` と `/mergepr` の両方の経路で止めるには、両方が通る `mergepr` に置くのが自然である。一方、`mergepr merge` は今、`origin` を取り直さない（`internal/mergepr/mergepr.go:248`）。取り直しを足すと、`mergepr_guide.md` §4 のネットワーク操作の表が変わる。PR の head は、`--match-head-commit` で `prepare` の時点のものに固定される（`internal/mergepr/mergepr.go:254`）ので、確かめた後に push された head はマージされない。確かめ直しも、この固定された head について行う。承認の commit が残ったまま `/runpr` をやり直すと、承認済みの文書を持つブランチで、もう一度マージの質問をすることになる。

**候補:** `mergepr prepare` で確かめ、`merge` で `git fetch origin main` の後にもう一度確かめる。`/runpr` は、マージの質問の前に `prepare` の結果を読む（AC-14）。確かめ直しで止まったときの承認の commit は、`/runpr` のやり直しでそのまま使えるかを、`runpr.md` の手順で確かめる。

**関連:** F-003（AC-06〜AC-16）

## H-02: 番号を変えた PR の見分け方

**懸念:** 3 章の「番号を変えた PR」（マージのコミットでないコミットは親と比べ、マージのコミットはどの親とも違うときだけ数える）を、どう見分けるか。

**なぜ重要か:** ブランチに `main` を取り込んだ後は、`origin/main` との差分（3 点の差分）に番号の変更が残らないことがある（AC-08）。差分だけで見分けると、この場合を見落とす。逆に、マージのコミットを親の 1 つとだけ比べると、`main` を取り込んだだけの PR を止める（AC-09）。

**候補:** `git rev-list origin/main..<head>` の各コミットで、親ごとに定数の値を読んで比べる。

**関連:** AC-06、AC-08、AC-09、AC-15

## H-03: 対象の道具の一覧と、番号の読み方

**懸念:** 確かめの対象の道具（`internal/<名前>` の `Protocol` 定数）をどう列挙するか。定数をどう読むか。

**なぜ重要か:** 新しい道具を足したときに、対象から漏れないようにする（AC-19）。定数が見つからないか、受け付ける形でないときは止まる（AC-13）。Go の整数の書き方には、先頭の `0`（8 進数）、区切りの `_`、型を付けた定数があり、どれを受け付けるかを決める必要がある。

**候補:** `internal/*/` の `const Protocol = <整数>` を、決まった形の行として読む。`cmd/*/main.go` の `--protocol` を持つ道具と一覧が合うことを、テストで確かめる。

**関連:** AC-01、AC-10、AC-13、AC-19

## H-04: CLAUDE.md の中の置き場所と、手引きからの参照の形

**懸念:** CLAUDE.md のどの節に規則を書くか。`fixprguard_guide.md` §9 と §3 から、どう参照するか。

**なぜ重要か:** 規則の正本を 1 か所に置く（AC-17・AC-18）。ADR-0014 の決定は、その節の見出しを挙げてリンクする（ADR の規約の「Writing an ADR」）。

**候補:** 「Development Notes」に「Protocol numbers」の項を足し、ADR-0014 の決定の項にその見出しを書き足す。

**関連:** F-001、F-002、F-004

## H-05: テストの手段

**懸念:** AC-06〜AC-16 を、どう確かめるか。

**なぜ重要か:** 2 つのブランチの衝突（AC-08）や、`main` を取り込んだだけの PR（AC-09）は、実際の git の履歴でしか作れない。

**候補:** 一時ディレクトリの実際の git リポジトリで、それぞれの履歴を作って確かめる（`fixprguard` のテストと同じ形）。

**関連:** F-003
