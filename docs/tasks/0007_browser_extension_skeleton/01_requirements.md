## 1. 概要 (Overview)

**目的:** 本書は、ブラウザ拡張の開発環境と、拡張のうちサーバとの API に依存しない部分の要件を定義する。API に依存しない部分とは、拡張の骨格と、利用者が選択した字幕の文字列・ページの URL・タブのタイトルの収集を指す。

**背景:**
`yt-dlp` による字幕の取得は、YouTube から HTTP 429 を繰り返し受けることがある。そこで、ブラウザ拡張と localhost のサーバを組み合わせ、ワンクリックで記事の生成と投稿を始められるようにする（#43）。字幕の取得は利用者に任せる。利用者が YouTube の「文字起こしを表示」パネルで字幕を選択し、拡張がその文字列を URL・タブのタイトルとともにサーバへ送る。

#43 は、localhost のサーバ（#104）とブラウザ拡張（#105）に分かれている。サーバのうち、コピーした字幕の書式を検証して解析する部分は #107 で扱う。ブラウザ拡張はさらに、サーバとの API の定義に依存しない部分（#110、本タスク）と、API の定義に従って送信し結果を表示する部分（#111）に分かれている。サーバとの API は #109 で定義する。本タスクは #109 の要件定義と並行して進める。本タスクで固定する拡張 ID と、本タスクで調べる事項（F-007）は #109 の API の定義の入力になる。

本リポジトリは Go のプロジェクトであり、ブラウザ拡張の開発環境（TypeScript のビルド、型検査、lint、テスト、CI）は何も用意されていない。本タスクで開発環境から用意する。

本タスクで次のことを決める。

-   **対象のブラウザ:** Chrome と、その派生ブラウザの Brave。Manifest V3 の拡張とする。
-   **言語:** TypeScript。
-   **配布:** ストアには公開しない。利用者は、ビルドした拡張を「パッケージ化されていない拡張機能を読み込む」で読み込む。
-   **起動の手段:** 次の 2 つを設け、役割を分ける。どちらの手段でも、収集と送る前の確認（F-005）は同じものを使う。キーボードショートカットは設けない（2.3）。
    -   **右クリックメニュー（コンテキストメニュー）:** ページで文字列を選択して右クリックし、拡張の項目を選ぶ。選択と同じ操作の流れで起動でき、送る意図がはっきりしているので、手早く送る手段とする。#111 では、確認を挟まずに送る。
    -   **ツールバーのアイコン:** クリックするとポップアップを開き、送る内容を表示する。#111 では、ポップアップに送信のボタンを加え、内容を確かめてから送る手段とする。送ると LLM API の費用が生じ、Slack に投稿される。一方、ツールバーのアイコンは用途を意識せずにクリックされやすい。そのため、確認を挟む。選択範囲が空のときや動画ページ以外では、ポップアップで理由と操作の手順を示す。利用者が字幕の送信で最もつまずきやすいのは、文字起こしパネルを開いて字幕を選択する手順だからである。

拡張は、YouTube のページという信頼できない内容を読み取る。ページの文字列（選択範囲・タイトル）は、動画の投稿者を含む第三者が決められる。拡張のページは通常のウェブページより強い権限を持つため、読み取った文字列を拡張のページで HTML として解釈すると、その権限を第三者に渡すことになる。

**本書の記述範囲:** 本書は、観測できる振る舞い（何を収集し、何を拒否し、利用者に何を示すか）と、開発環境が満たす条件を定める。実現の手段（ビルドツール・テストランナー・lint の選択、ディレクトリの名前、Makefile のターゲット名、manifest の具体的な記述、拒否の検出の手段、表示の正確な書式など）は設計（`02_architecture.md`）で決める。

対応 issue: #110（親: #105、#43）

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   ブラウザ拡張を TypeScript で開発し、型検査・lint・テスト・ビルドを、ローカルと CI の両方で同じ手順で実行できる。
-   Chrome と Brave に、ビルドした拡張を読み込める。拡張 ID は、読み込む環境によらず同じになる。
-   YouTube の動画ページで字幕を選択し、右クリックメニューまたはツールバーのアイコンから拡張を起動すると、選択範囲の文字列・ページの URL・タブのタイトルが、補正されずに集まる。
-   ツールバーのアイコンのポップアップで、送る内容を確かめられる。送れない状況では、理由と操作の手順が分かる。
-   送る対象にならない状況（選択範囲が空、動画ページ以外など）では、そのことを利用者に示す。
-   拡張が要求する権限を、上記の動作に必要なものに限る。利用者が起動するまで、拡張はページを読まない。
-   #109 の API の定義に必要な事項（拡張 ID、拡張が取れる項目、共有トークンの受け渡し方法。詳細は F-007）を調べて記録する。

### 2.2. スコープ (In Scope)

-   ブラウザ拡張の開発環境: リポジトリ内の置き場所、TypeScript のビルド、型検査、lint、フォーマット、ユニットテスト、Node.js と依存パッケージの版の固定、Makefile のターゲット、CI のジョブ（F-001・F-002）。
-   Manifest V3 の拡張の骨格と、拡張 ID の固定（F-003）。
-   右クリックメニューとツールバーのアイコン（ポップアップ）からの起動（F-004）。
-   選択範囲の文字列・ページの URL・タブのタイトルの収集と、送る前の確認（F-005）。
-   収集した内容と拒否の理由の、利用者への表示（F-006）。
-   #109 への入力の調査と記録（F-007）。
-   文書: README・CLAUDE.md・[project_overview.md](../../dev/project_overview.md)・[security.md](../../dev/security.md) の更新（F-008）。

### 2.3. スコープ外 (Out of Scope)

-   localhost のサーバへの送信、共有トークンの設定画面と保存、サーバの応答の表示（#111）。本タスクの拡張は、ネットワークにアクセスしない。
-   字幕の書式の検証（#107・#109）。拡張は、選択範囲が文字起こしパネルの字幕かどうか、書式に合うかどうかを確かめない。
-   送る文字列の大きさの上限（#109 で決め、#111 で適用する）。
-   タブのタイトルの加工（末尾の ` - YouTube` や、先頭の通知件数 `(3) ` の除去など）と、URL の正規化（`t`・`list` などのパラメータの除去）。どちらも #109 の API の定義で扱いを決める。本タスクでは、タブのタイトルと URL をそのまま収集する。
-   チャンネル名・概要欄の収集の実装。本タスクでは、収集できるかを調べて記録するだけとする（F-007）。
-   ページの DOM から字幕を自動で取り出すこと（#43 で不採用とした）。
-   キーボードショートカット。
-   ポップアップの送信のボタン（#111）。
-   動画ページ以外でツールバーのアイコンを無効（グレー表示）にすること。判定のために権限が増えるため、行わない。押したときに理由を示せば足りる（F-006）。
-   Chrome と Brave 以外のブラウザ（Firefox、Safari、Edge など）。Edge は Chromium 系のため動作する可能性があるが、確認しない。
-   ストアへの公開、`.crx` へのパッケージ化、自動更新。
-   シークレットモード（プライベートウィンドウ）での動作。
-   `www.youtube.com` 以外の YouTube のページ（`m.youtube.com`、`music.youtube.com`、`youtu.be` の短縮 URL、埋め込みプレーヤー）と、Shorts（`/shorts/`）・ライブ（`/live/`）の URL。
-   表示する文言の多言語化。
-   拡張のアイコンのデザイン。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 開発環境

-   拡張のソース、設定、テストは、リポジトリ内の 1 つのディレクトリにまとめる。ディレクトリの名前は設計で決める。
-   TypeScript は、型検査の厳格な設定（`strict` 相当）で検査する。型検査のエラーがある状態ではビルドを成功させない。
-   型検査、lint、フォーマットの確認、ユニットテスト、ビルドを、それぞれ Makefile のターゲットから実行できる。ターゲット名は設計で決める。
-   Node.js の版と、依存パッケージ（パッケージマネージャを含む）の版を固定する。依存パッケージは lockfile に従ってインストールする。lockfile と異なる版をインストールしうる手順を用いない。
-   拡張の実行時に読み込まれるコードは、本リポジトリで書いたコードだけとする。npm の依存パッケージは、開発用（ビルド・型検査・lint・テスト）に限る。依存パッケージを加える場合は、`02_architecture.md` に理由を書く（CLAUDE.md「Dependencies」の考え方を拡張にも適用する）。
-   ビルドの成果物と依存パッケージのインストール先は、git の管理対象から外す。
-   拡張のディレクトリと依存パッケージがあっても、Go の既存の手順（`make test`・`make lint`・`make deadcode`・`make build`）の結果は変わらない。Go の手順は Node.js を必要としない。
-   拡張のソースのコメント、識別子、文字列リテラルは英語とする（CLAUDE.md の Go の規則と同じ）。利用者に表示する文言も英語とする（Go の CLI のエラーメッセージと同じ）。

**Acceptance Criteria**:
- **AC-01**: Node.js と依存パッケージを固定した版でインストールした状態で、Makefile の型検査・lint・フォーマットの確認・ユニットテスト・ビルドのターゲットがそれぞれ成功する。
- **AC-02**: 型検査のエラーを含むソース（型の合わない代入を 1 つ加えたもの）では、型検査のターゲットとビルドのターゲットが失敗する。
- **AC-03**: lockfile がリポジトリに含まれ、インストールの手順が lockfile と異なる版をインストールしない（lockfile と `package.json` が食い違う場合にインストールが失敗する）。
- **AC-04**: 拡張のビルドの成果物に、npm の依存パッケージのコードが含まれない（静的な確認。確認の手段は設計で決める）。
- **AC-05**: 依存パッケージをインストールし、拡張をビルドした状態で、`make test`・`make lint`・`make deadcode`・`make build` の結果が、拡張のディレクトリがない場合と変わらない。
- **AC-06**: `git status` に、ビルドの成果物と依存パッケージのインストール先が現れない。

#### F-002: CI

-   拡張のディレクトリの下のファイル、Makefile、CI の定義（`.github/workflows/` の下）のいずれかを変更する PR では、CI で、固定した版のインストール、型検査、lint、フォーマットの確認、ユニットテスト、ビルドを実行する。
-   拡張のディレクトリの下のファイルだけを変更する PR で、Go のジョブを実行するかどうかは設計で決める。
-   Go のファイルだけを変更する PR で、拡張のジョブを実行するかどうかは設計で決める。

**Acceptance Criteria**:
- **AC-07**: 拡張のディレクトリの下のファイル、Makefile、CI の定義（`.github/workflows/` の下）のいずれかを変更する PR で、CI が、固定した版のインストール・型検査・lint・フォーマットの確認・ユニットテスト・ビルドの 6 つのステップを実行し、6 つのいずれかが失敗すると CI が失敗する（次の 2 つで確認する。(1) 本タスクの PR の CI の結果、(2) 6 つのステップのそれぞれを失敗させる変更を 1 つずつ加えたコミットでの CI の結果。型検査を失敗させる変更は AC-02 のものを使う）。

#### F-003: 拡張の骨格と拡張 ID

-   Manifest V3 の拡張とする。
-   拡張 ID を固定する。ビルドした拡張を、異なるマシン・異なるディレクトリから読み込んでも、拡張 ID が同じになる。この ID は、#109 でサーバが `Origin` ヘッダを確かめるときに使う。
-   拡張 ID を固定するために秘密鍵を使う場合、秘密鍵はリポジトリに含めない。リポジトリに含めるのは、拡張 ID を決める公開の情報だけとする。
-   固定した拡張 ID を文書に記録する（F-008）。

**Acceptance Criteria**:
- **AC-08**: ビルドした拡張を、2 つの異なるディレクトリに置いて Chrome に読み込むと、拡張 ID がどちらも記録した値と同じになる（手動確認）。Brave に読み込んだ場合も同じ値になる（手動確認）。
- **AC-09**: リポジトリに、秘密鍵（PEM の `PRIVATE KEY` ブロックなど）が含まれない（静的な確認）。

#### F-004: 起動

拡張は、右クリックメニューとツールバーのアイコンの 2 つの手段で起動する（1. 概要の「起動の手段」）。以下、メニューの項目を選ぶことと、アイコンをクリックすることを「起動」と呼ぶ。

-   **右クリックメニュー:** 拡張は、ページで文字列を選択して右クリックしたときに表示されるメニューに、項目を 1 つ加える。項目の文言は設計で決める。メニューの項目は、`www.youtube.com` の動画ページ（パスが `/watch` のページ）で文字列を選択したときにだけ表示する。この表示の条件は、3.2 の受理する URL より緩くてよい。メニューの表示の条件に使えるブラウザの URL のパターンは、クエリのパラメータの個数や値を表せないためである。収集の可否は F-005 の確認で決まる。
-   **ツールバーのアイコン:** アイコンをクリックすると、ポップアップを開く。どのページでも開き、動画ページ以外では F-006 の表示を行う。ポップアップを開くことで、ページの選択範囲が解除されてはならない。
-   YouTube はページを再読み込みせずに表示する動画を切り替える。動画ページかどうかの判断は、起動した時点のタブの URL で行う（F-005）。メニューの項目を表示するかどうかも、切り替え前の URL ではなく、右クリックした時点のタブの URL で判断する。したがって、トップページから動画ページへ再読み込みせずに移った場合も、移った先の動画ページで項目が表示される（収集の可否は F-005 の確認で決まる）。
-   利用者が起動するまで、拡張はページのスクリプトの注入も、ページの内容の読み取りも行わない。起動で読み取るのは、起動したタブだけとする。

**Acceptance Criteria**:
- **AC-10**: `https://www.youtube.com/watch?v=<ID>` のページで文字列を選択して右クリックすると、拡張の項目が表示される（手動確認。Chrome と Brave）。
- **AC-11**: YouTube 以外のページ（`https://example.com/` など）で文字列を選択して右クリックしても、拡張の項目が表示されない（手動確認）。
- **AC-12**: 拡張の manifest は、ページの読み込み時に自動で実行されるスクリプト（content script）を宣言しない（静的な確認）。
- **AC-28**: `https://www.youtube.com/watch?v=<ID>` のページで文字列を選択した状態でツールバーのアイコンをクリックすると、ポップアップが開き、F-005 で収集した内容が表示される。ポップアップを閉じた後も、ページの選択範囲は残っている（手動確認。Chrome と Brave）。
- **AC-29**: YouTube 以外のページ（`https://example.com/` など）でツールバーのアイコンをクリックすると、ポップアップが開き、「対象外のページ」の理由と操作の手順が表示される（手動確認）。

#### F-005: 入力の収集と送る前の確認

利用者が起動すると（F-004。右クリックメニューとツールバーのアイコンのどちらでも）、拡張は次の 3 つを収集する。

-   **選択範囲の文字列:** 利用者が選択した文字列。改行を保ち、前後の空白の除去、空白の連続の圧縮、改行の置き換えなどの補正をしない。文字起こしパネルの選択範囲は時刻の行と本文の行からなり（#43）、行の区切りが #107 の解析に必要なためである。ブラウザによっては、右クリックメニューの API が渡す選択範囲の文字列が改行を空白に置き換えたものになる。その場合はその値を使わず、改行を保つ手段で選択範囲を取得する（手段は設計で決める）。
-   **ページの URL:** 起動した時点の、起動したタブの URL。そのまま収集する。
-   **タブのタイトル:** 同じ時点のタブのタイトル。そのまま収集する。ページを再読み込みせずに動画を切り替えた直後は、タブのタイトルが切り替え前の動画のものである場合がある。拡張は、URL とタイトルが同じ動画のものかどうかを確かめない（確かめるにはページの DOM に依存するため。5. 制約条件）。

収集した内容が 3.2 の受理する形に合わない場合は、拒否する。拒否の理由は次のとおりで、互いに区別でき、利用者への表示（F-006）で異なる文言になる。

-   **対象外のページ:** URL が 3.2 の受理する形に合わない。
-   **選択範囲が空:** 選択範囲の文字列が空、または空白文字（改行と全角空白 U+3000 を含む、Unicode の空白文字）だけからなる。
-   **タイトルが空:** タブのタイトルが空、または空白文字（「選択範囲が空」と同じ定義）だけからなる。
-   **収集の失敗:** 選択範囲を取得できなかった（ページへのスクリプトの注入が許可されない、タブが閉じられたなど）。

確認の順序は、対象外のページ、収集の失敗、選択範囲が空、タイトルが空の順とする。対象外のページでは選択範囲を読み取らない。

選択範囲が文字起こしパネルの字幕かどうか、字幕の書式に合うかどうかは確かめない（2.3）。

**Acceptance Criteria**:
- **AC-13**: 動画ページの文字起こしパネルで複数の行を選択して起動すると、収集した選択範囲の文字列が、選択した範囲を `window.getSelection().toString()` で取得した値と一致し、時刻の行と本文の行が改行で区切られている（手動確認。Chrome と Brave）。
- **AC-14**: 選択範囲の文字列の前後に空白文字や空行がある場合、収集した文字列はそれらを含む（ユニットテスト。収集した値を加工しうる経路で、補正が行われないことを確かめる）。
- **AC-15**: 3.2 の受理しない URL の例（下記）のそれぞれで、拒否の理由が「対象外のページ」になる（ユニットテスト）。
- **AC-16**: 選択範囲の文字列が空文字列、空白だけ、改行だけ、全角空白（U+3000）だけ、空白と改行だけのそれぞれの場合に、拒否の理由が「選択範囲が空」になる（ユニットテスト）。
- **AC-17**: タブのタイトルが空文字列、空白だけ、全角空白（U+3000）だけの場合に、拒否の理由が「タイトルが空」になる（ユニットテスト）。
- **AC-18**: 選択範囲の取得が失敗した場合に、拒否の理由が「収集の失敗」になる（ユニットテスト。ブラウザの API を fake に置き換えて失敗させる）。
- **AC-19**: URL が対象外のページの場合に、選択範囲の取得を行わない（ユニットテスト。fake で取得が呼ばれないことを確かめる）。
- **AC-20**: YouTube のトップページから、ページ内のリンクで（再読み込みせずに）動画ページへ移ってから起動すると、移った先の URL とタイトルが収集される（手動確認。タブのタイトルが移った先の動画のものに変わってから起動する。右クリックメニューとツールバーのアイコンのそれぞれで確かめる）。
- **AC-30**: 右クリックメニューからの起動とツールバーのアイコンからの起動で、同じ収集と確認の処理が使われる（ユニットテスト。2 つの起動の経路のそれぞれから、同じ fake の入力で同じ収集の結果または拒否の理由になることを確かめる）。

#### F-006: 収集した内容と拒否の理由の表示

本タスクの拡張は送信しないので、収集した内容を表示して終わる。#111 で、右クリックメニューからの起動では表示をサーバへの送信と応答の表示に置き換え、ポップアップでは送信のボタンと応答の表示を加える。

-   収集に成功した場合、利用者に次を示す: タブのタイトル、URL、選択範囲の文字列の文字数と行数、選択範囲の先頭の一部。表示する文字数の上限と書式は設計で決める。
-   拒否した場合、利用者に拒否の理由を示す。ポップアップでは、「対象外のページ」と「選択範囲が空」の場合に、送るための操作の手順（動画ページを開く、文字起こしパネルを開いて字幕を選択する）もあわせて示す。
-   ツールバーのアイコンからの起動では、ポップアップに表示する。右クリックメニューからの起動での表示の手段（通知、拡張のページ、アイコンのバッジなど）は設計で決める。手段に必要な権限は F-004・4.2 の制約に従う。
-   選択範囲の文字列とタブのタイトルは、HTML やほかのマークアップとして解釈せず、テキストとして表示する。
-   開発者が、収集した内容の全体（選択範囲の文字列を含む）を確認できる手段を設ける（拡張の service worker のコンソールなど）。AC-13 の確認に使う。

**Acceptance Criteria**:
- **AC-21**: 収集に成功すると、タイトル、URL、文字数と行数、選択範囲の先頭の一部が表示される（手動確認。右クリックメニューとツールバーのアイコンのそれぞれで確かめる）。
- **AC-22**: 拒否の理由のそれぞれについて、互いに異なる文言が表示される（ユニットテストで理由と文言の対応を確かめ、「対象外のページ」と「選択範囲が空」は手動でも確認する）。
- **AC-23**: 選択範囲の文字列またはタイトルに `<img src=x onerror=alert(1)>` を含む場合、その文字列がそのまま文字として表示され、要素として解釈されない（ユニットテスト。ポップアップと、右クリックメニューからの起動の表示の手段のそれぞれで確かめる。確かめる手段は設計で決める）。
- **AC-31**: ポップアップで「対象外のページ」と「選択範囲が空」を示すときに、操作の手順もあわせて表示される（ユニットテストで理由と表示の対応を確かめ、手動でも確認する）。

#### F-007: #109 への入力の調査と記録

#109 の API の定義に使うため、次を調べて `02_architecture.md` に記録する。#109 のアーキテクチャ文書は、この記録を参照する。

-   **拡張 ID:** F-003 で固定した値と、その値で `Origin` ヘッダがどうなるか（`chrome-extension://<ID>`）。#111 では、右クリックメニューからの起動とポップアップの送信のボタンで、送信を行う場所が異なりうる。そのため、拡張の service worker とポップアップのそれぞれから localhost へ送ったときに、Chrome と Brave で `Origin` ヘッダが付くかを確かめる。確認に使うサーバと、確認のために拡張に加える一時的な変更（localhost へのホストの権限、送信のコードなど）は、リポジトリに含めない。
-   **チャンネル名・概要欄:** 動画ページの DOM から、チャンネル名と概要欄を取り出せるか。取り出せる場合は、どのページの構造に依存するか、その構造がどの程度安定しているか。本タスクでは実装しない。
-   **共有トークンの受け渡し:** サーバが起動時に生成するトークンを拡張に渡す方法の候補（利用者がオプションページに貼り付けるなど）と、拡張内の保存先の候補（`chrome.storage.local` など）。それぞれの候補で、トークンがほかの拡張やページから読めるかどうか。

**Acceptance Criteria**:
- **AC-24**: `02_architecture.md` に、上記の 3 項目の調査の結果が記録されている（静的な確認）。

#### F-008: 文書

-   README に、拡張の開発環境の用意（Node.js の版、依存パッケージのインストール）、ビルド、Chrome と Brave への読み込みの手順（開発者モードの有効化、「パッケージ化されていない拡張機能を読み込む」）、2 つの起動の手段（右クリックメニューとツールバーのアイコン）の使い方、本タスクの時点では拡張が送信しないことを記す。
-   CLAUDE.md に、拡張の Makefile のターゲット、拡張を変更した後に実行する確認、拡張のソースの言語の規則（F-001）、拡張の依存パッケージの方針（F-001）を加える。
-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」の「言語: Go」に、ブラウザ拡張は TypeScript で書くことを加える。「想定ディレクトリ構成」に拡張のディレクトリを加える。
-   [security.md](../../dev/security.md) に、ブラウザ拡張の節を加え、次を記す: 要求する権限とその理由、利用者が起動するまでページを読まず、起動したタブだけを読むこと、読み取った文字列をテキストとして表示すること、拡張 ID の固定に秘密鍵を使う場合も、秘密鍵をリポジトリに含めないこと、依存パッケージを lockfile で固定し実行時に読み込まないこと。
-   固定した拡張 ID を、README と security.md に記す。

**Acceptance Criteria**:
- **AC-25**: 上記の各文書に、上記の内容が記載されている（静的な確認）。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

選択範囲の文字列、タブの URL、タブのタイトルは、YouTube のページから得る信頼できない入力である。本タスクの拡張は、これらを表示するだけで、送信も保存もしない。

| 境界 | 受理する形 | 上限 | 拒否時の理由 | 主な AC |
|---|---|---|---|---|
| タブの URL | 下記の「受理する URL」 | - | 対象外のページ | AC-15・AC-19 |
| 選択範囲の文字列 | 空白文字以外の文字を 1 つ以上含む文字列。内容は問わず、補正しない | 本タスクでは設けない（下記） | 選択範囲が空、収集の失敗 | AC-13・AC-14・AC-16・AC-18 |
| タブのタイトル | 空白文字以外の文字を 1 つ以上含む文字列。内容は問わず、補正しない | 本タスクでは設けない（下記） | タイトルが空 | AC-17 |

**受理する URL:** URL として解析でき、次をすべて満たすもの。

-   スキームが `https`。
-   ホストがちょうど `www.youtube.com`。解析した URL のポートが空（既定のポート 443 以外の指定がない）。ユーザ名・パスワードを含まない。
-   パスがちょうど `/watch`。
-   クエリのパラメータ `v` がちょうど 1 つあり、値が空でない。`v` の値が動画 ID の形式に合うかは確かめない（サーバが #109 で確かめる）。
-   `v` 以外のクエリのパラメータ（`t`・`list` など）とフラグメントは、受理し、収集する URL にそのまま残す（2.3）。

受理しない URL の例（AC-15）: `http://www.youtube.com/watch?v=abc`、`https://youtube.com/watch?v=abc`、`https://m.youtube.com/watch?v=abc`、`https://music.youtube.com/watch?v=abc`、`https://www.youtube.com.example/watch?v=abc`、`https://www.youtube.com:8443/watch?v=abc`、`https://user@www.youtube.com/watch?v=abc`、`https://www.youtube.com/`、`https://www.youtube.com/watch`、`https://www.youtube.com/watch?v=`、`https://www.youtube.com/watch?v=abc&v=def`、`https://www.youtube.com/watch/?v=abc`、`https://www.youtube.com/shorts/abc`、`https://youtu.be/abc`、`chrome://extensions/`。この例は網羅を意図しない。

**上限:** 本タスクでは、選択範囲の文字列とタイトルの大きさの上限を設けない。拡張は収集した内容を送らず保存もせず、表示するのは先頭の一部に限るためである（F-006）。送る大きさの上限は #109 で決め、#111 で送る前に適用する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)
-   収集と表示は、利用者が起動してから待たされたと感じない時間で終わればよい。性能のための仕組みは設けない（[CLAUDE.md](../../../CLAUDE.md)「Performance」）。

### 4.2. セキュリティ (Security)
-   要求する権限を、F-004〜F-006 の動作に必要なものに限る。閲覧内容全般に及ぶ権限（すべてのサイトへのホストの権限、`tabs`、`history`、`cookies`、`webRequest` など）を要求しない。要求する権限ごとに、必要な理由を `02_architecture.md` に書く。
-   利用者が起動するまでページを読まず、起動で読むのは起動したタブだけとする（F-004）。
-   本タスクの拡張は、ネットワークにアクセスしない。
-   読み取った文字列を、HTML やほかのマークアップとして解釈しない（F-006）。
-   拡張のページで、外部から取得したスクリプトや、文字列から生成したコード（`eval` など）を実行しない。Manifest V3 の既定の Content Security Policy を緩めない。
-   秘密鍵をリポジトリに含めない（F-003）。
-   依存パッケージは lockfile で版を固定し、開発用に限る（F-001）。依存パッケージのインストール時のスクリプト（`postinstall` など）を実行するかどうかは、設計で決め、理由を書く。

**Acceptance Criteria**:
- **AC-26**: manifest が要求する権限（ホストの権限を含む）が、`02_architecture.md` に理由とともに挙げたものと一致し、閲覧内容全般に及ぶ権限を含まない（静的な確認）。
- **AC-27**: manifest が Content Security Policy を変更せず、拡張のソースが `eval`・`new Function` を使わない（静的な確認。lint で検出できる場合は lint で確かめる）。

### 4.3. 信頼性・可用性 (Reliability/Availability)
-   収集の失敗（F-005）は、拒否の理由として利用者に示し、拡張の service worker を止めない。失敗した後も、次の起動は通常どおり動作する。

### 4.4. 互換性 (Compatibility)
-   利用時: macOS 上の Chrome と Brave の、本タスクの作業時点の安定版で動作すること。拡張が必要とする Chrome の最小の版は設計で決め、manifest に記す。
-   開発時: macOS と Linux（CI の実行環境）で、F-001 の手順が動作すること。

### 4.5. 保守性 (Maintainability)
-   URL の判定、送る前の確認、拒否の理由と表示の文言の対応は、ブラウザの API から分離し、ブラウザなしでユニットテストできるようにする。ブラウザの API を呼ぶ部分は fake に置き換えられるようにする（CLAUDE.md「Interface-based Design」と同じ考え方）。
-   収集と確認の処理は、2 つの起動の手段で共有し、複製しない（AC-30）。
-   #111 で送信を加えるときに、収集と確認の部分を変更せずに済むこと。
-   拒否の理由は、文字列の内容から推し量らず、型で表す（[CLAUDE.md](../../../CLAUDE.md)「Declare, don't infer」）。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」に従う。本タスクで変更する方針は「言語: Go」だけで、ブラウザ拡張を TypeScript で書くことを加える（F-008）。
-   Go のソースと、Go の既存の Makefile のターゲット・CI のジョブの振る舞いを変更しない（F-001・F-002）。
-   ユニットテストは、実際のブラウザを起動しない。ブラウザの API は fake に置き換える。Chrome と Brave での動作は手動で確認する。
-   ページの DOM の構造に依存する実装をしない。選択範囲は、ブラウザの選択の API で取得する（F-005）。チャンネル名・概要欄の DOM の調査（F-007）は、記録だけで実装しない。
-   テストで使う YouTube のページの実データは、[security.md](../../dev/security.md) §7 に従う。本タスクのユニットテストは合成した文字列を使い、実データを新たに加えない。

## 6. 用語集 (Glossary)

-   **Manifest V3**: Chrome の拡張の現行の形式。拡張のバックグラウンドの処理は、常駐するページではなく、必要なときに立ち上がる service worker で行う。
-   **拡張 ID**: Chrome が拡張ごとに割り当てる 32 文字の識別子。拡張のページの `Origin` は `chrome-extension://<拡張 ID>` になる。パッケージ化されていない拡張の ID は、既定では読み込んだディレクトリのパスから決まるため、環境ごとに異なる。manifest の `key` に公開鍵を記すと、その公開鍵から決まる値に固定される。
-   **パッケージ化されていない拡張機能を読み込む**: Chrome・Brave の拡張機能の管理ページで、開発者モードを有効にすると使える機能。ディレクトリに置いた拡張を、ストアを経ずに読み込む。
-   **content script**: 拡張がページの中で実行するスクリプト。manifest で宣言してページの読み込み時に自動で実行する方法と、拡張が必要なときに注入する方法がある。本タスクでは前者を使わない（F-004）。
-   **service worker**: Manifest V3 の拡張のバックグラウンドの処理を行うスクリプト。
-   **ポップアップ**: ツールバーの拡張のアイコンをクリックしたときに、アイコンの下に開く拡張のページ。ほかの場所をクリックすると閉じる。
-   **起動**: 本書では、右クリックメニューの拡張の項目を選ぶことと、ツールバーの拡張のアイコンをクリックすることを指す（F-004）。
-   **派生ブラウザ**: Chromium をもとにした、Chrome 以外のブラウザ。本タスクでは Brave を対象とする。
-   用語は [translation_glossary.md](../../translation_glossary.md) と統一する。
