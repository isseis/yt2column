## 1. 実装の概要 (Implementation Overview)

### 1.1. 目的

負荷の高いときに対象のテストが遅くなる原因を、手元の macOS で計測して記録する（F-003）。その後、対象のテストの期限を 2 秒から 30 秒に延ばし（F-001）、テストが本来の理由で失敗できることと、`make test` と並行する負荷の下で失敗しないことを確かめて記録する（F-002）。

### 1.2. 実装の原則

-   **計測を先に、変更を後に**（設計書 1.1）。フェーズ 1 は対象のテストを変える前のコミットで行う。30 秒を超える待ちを観察したら、フェーズ 2 に進まずに止まる。
-   **調査のためのコードはコミットしない**（設計書 1.1）。計測用のテストと、AC-05 のために壊した `exec.go` は、どのコミットにも入れない。
-   **止まる条件では、人間のレビュアーに問う**（設計書 4 章の表）。`/runplan` は、その場で作業を止めて問う。
-   **ネットワークに触れる操作は、その都度人間の承認を得る**（`CLAUDE.md`「Tool Execution Safety」）。本タスクで該当するのは、AC-07 で提案する issue の作成と、AC-04 の実行中にほかのテストが失敗した場合の issue の作成だけである。

### 1.3. 計画の際に決めたこと（2026-11-06）

人間のレビュアーが決めたもの:

-   **PR は 1 つにする:** 設計書 8 章が実装計画に委ねた PR の区切りである。計測と記録、期限の変更、壊して失敗することの確認、負荷の下の確認を、1 つの PR（PR-1。本計画 §3.2）にまとめる。変えるコードは対象のテストの定数とそのコメントだけで、残りは記録である。止まる条件（30 秒を超える待ち、50 回のうちの失敗、壊した形が見込みと違う結果）は、どれも `/runplan` がその場で止まって問えば扱える。分けると、PR のレビューと Codex の PR のレビューが 1 回ずつ増える。タスク 0039 は調査の記録を先の PR に分けたが、それは CI での計測があり、人間の判断を要する止まる条件の比重も大きかったためである。本タスクには CI での計測がない。ADR: 作らない。本タスクの PR の区切りがほかのタスクを縛らないためである。

計画で決めたもの（人間のレビュアーに諮らず、理由とともに記す）:

-   **記録を求める AC は `manual` で確かめる:** AC-04・AC-06・AC-07 は、手元での実行と計測の結果を調査の記録に書くことを求める。AC-05 は、壊して確かめた結果をコミットのメッセージに書くことを求める。これらに `test`・`static`・`diff` は付けない。記録があることを確かめる文書のテストは、`CLAUDE.md`「Testing Strategy」が禁じる「タスク自身の記録の確認」（"check a task's own record"）に当たる。しかも、そのテストは記録の中身の正しさを確かめられない。設計書 7.1 が実装計画に委ねた判断で、先例はタスク 0039 の実装計画 §1.3・§5 である。本計画 §5 に、mkplan の規則の例外として記す。
-   **AC-01 の `static` と、AC-02・AC-03 の `diff` を、1 つの Go のプログラムで確かめる:** プログラムは `docs/tasks/0064_stderr_drain_test_deadline/_checks/drain_test_unchanged.go` に置き、`go run` で実行する（ステップ 2-4・3-4）。merge-base と PR の先頭のそれぞれで、対象のテストの関数を `go/parser` で読み、期限の定数を除いて比べる。同じ読み取りで、PR の先頭の期限の定数の値が `30 * time.Second` であることも確かめる。Go にするのは、関数の範囲と定数の宣言を構文で特定でき、行の形の違いに左右されないからである。開発環境に Go があることが保証されている点も理由である。先例はタスク 0051 の `_checks/no_effort_compat.go` である。AC-01 を常設のテストにしないのは、定数がその字面と等しいことを確かめるテストを `CLAUDE.md`「Testing Strategy」が禁じている（"Do not assert that a constant equals its own literal"）ためである。
-   **比べるのはコメントを除いたコードとする:** 設計書 3.2 は、期限の定数の宣言とそのコメントを除いて比べるとしている。プログラムは、関数をコメントなしで出力して比べる。そのため、関数の中のほかのコメントの違いも比べない。merge-base の対象のテストの関数には、ほかのコメントがない（`internal/transcript/exec_test.go:62-83`、`9a059de3`）。AC-02・AC-03 が求めるもの（`burst`、スクリプトの内容、2 つの確認、失敗のメッセージ）は、どれもコードと文字列のリテラルなので、比べる範囲に入る。
