## 1. 概要 (Overview)

**目的:** 本書は、Sourcery AI（`sourcery-ai`）を信頼する自動レビュアー一覧（`Automated reviewer list`）に加え、拒否メンションと `/runpr` のメンション検査を拡張し、CodeRabbit と Sourcery AI を併用する PR レビュー体制を実現するための要件を定義する。

対応 issue: [#1095](https://github.com/isseis/yt2column/issues/1095)（関連: [#405](https://github.com/isseis/yt2column/issues/405)（タスク `0033_multiple_trusted_reviewers`）、[#629](https://github.com/isseis/yt2column/issues/629)（タスク `0057_reviewer_relay_guard`）、[#1059](https://github.com/isseis/yt2column/issues/1059)（タスク `0118_codex_removal`）、[#1072](https://github.com/isseis/yt2column/issues/1072)（タスク `0120_harness_independent_commands`））

**背景:**

現在、`.claude/commands/_context.md:298` の `Automated reviewer list` は `coderabbitai` だけである（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）。そのため、`sourcery-ai` が PR に開いたレビュースレッドは、`fixprguard` の判定で `untrusted`（理由 `other-bot`、`account: sourcery-ai`）として隔離される。`/fixpr` や `/runpr` で自動処理するには、毎回スレッドごとに `--accept <threadId>=<fingerprint>` を指定する必要がある（例: PR [#1094](https://github.com/isseis/yt2column/pull/1094)）。

また、現在の `Rejected mentions`（`.claude/commands/_context.md:301`）と `fixprguard.RejectedMentions()`（`internal/fixprguard/errors.go:79-81`）は `@codex` と `@coderabbitai` の 2 つである。`/runpr` は、PR の会話コメント・行コメント・PR レビューに含まれるこれらのメンションを検査し、利用者以外の `User` なら停止、`Bot` なら続行確認を出す（CodeRabbit の定型 2 種 `cr_observed` のみ除外。`.claude/commands/runpr.md:441-537`）。一方、`/runpr` の手動 PR レビューと `fixprguard review-state` は、単一の `Awaited PR reviewer`（`coderabbitai`）と単一の `PR review request`（`@coderabbitai review`）を前提にしており（`.claude/commands/_context.md:299-300`、`internal/fixprguard/review_state.go:44-50,655-679`、`runpr.md:1277-1310`）、Sourcery AI の完了待機や手動依頼には対応していない。

要件定義の際に PR [#1094](https://github.com/isseis/yt2column/pull/1094) の API 読み取りと Sourcery AI の公式文書を確認したところ、次の事実が分かった（2026-11-23）。

-   **アカウントと CheckRun の識別子:** GraphQL のスレッドでは `author.__typename: "Bot"`・`author.login: "sourcery-ai"`、REST のコメント・レビューでは `user.type: "Bot"`・`user.login: "sourcery-ai[bot]"`、CheckRun は `checkSuite.app.slug: "sourcery-ai"`・`name: "Sourcery review"` であった。成功完了時は `status: "COMPLETED"`・`conclusion: "SUCCESS"`・`title: "✅ Completed successfully"` を観測した（コミット `86a8f476`・`2ee50010`）。
-   **メンションへの反応:** Sourcery AI は `@sourcery-ai` と `@sourceryai`（ハイフンなし）の両方のメンションで `review`・`summary`・`guide`・`title`・`resolve`・`dismiss`・`create issue` およびチャットを起動する（公式文書、および PR #1094 で利用者 `isseis` が投稿した `@sourceryai review` の 7 秒後に `Sourcery review` CheckRun が始まったことを観測）。PR タイトルの `@sourcery-ai` や PR 本文の `@sourcery-ai summary` でも動作する。
-   **Sourcery AI 自身の投稿のメンション含有:** レビューガイドコメント（1 行目: `<!-- Generated by sourcery-ai[bot]: start review_guide -->`）はコマンド案内として `@sourcery-ai` を複数含む。一方、`linked_issues` コメント（1 行目: `<!-- Generated by sourcery-ai[bot]: start linked_issues -->`）、PR レビュー本文 2 件、行コメント 11 件、PR 本文に追記された `## Sourcery による概要` / `## Summary by Sourcery` には `@sourcery-ai`・`@sourceryai` は含まれなかった。
-   **自動レビューと制限:** PR #1094 のコミット `2ee50010` では、依頼コメントなしの push で `Sourcery review` CheckRun が自動実行・完了した。公式文書では、レート制限や再レビュー上限時は CheckRun が `SKIPPED` になるとされるが、その正確な `output.title`、エラー時の `conclusion`・`title`、スレッド返信時の応答、push 制限下での挙動、`AGENTS.md` の参照可否は未観測である。

**本書の記述範囲:** 本書は、観測可能な振る舞いを定める。具体的には、設計前の観測項目、信頼する自動レビュアー一覧と拒否メンションの対象、`/runpr` のメンション除外と自動・手動 PR レビューの待機・完了判定・マージの質問の振る舞い、文書と ADR の更新範囲である。次の事項は設計（`02_architecture.md`）で決める。設計は F-001 の観測記録がそろってから始める。

-   `_context.md` で複数の PR レビュアーと依頼文面を表す表の行構成とパース規則
-   `fixprguard review-state` の複数レビュアー・自動レビュー対応のコマンド契約（引数、出力 JSON、CheckRun 分類表、競合判定）
-   `fixprguard` の `Protocol` 番号（現在 `internal/fixprguard/types.go:21` は `8`）を `main` の値 + 1 に上げる設計と PR の分割順序
-   `/runpr` のメンション除外フィルタの実装形と、マージの質問の要約行・`chief` 読み取りの整合

要件定義の時点で挙がった設計の事項は、[design_handoff.md](design_handoff.md) に申し送る。

**issue #1095 で決めたこと:**

-   **信頼一覧への追加:** `.claude/commands/_context.md` の `Automated reviewer list` に `sourcery-ai`（GraphQL の `author.login` 形式）を追加し、名指しなしで処理できるようにする。
-   **拒否メンションの確認:** `Rejected mentions` に `@sourcery-ai` を追加する必要があるか（利用者アカウントからのメンションへの反応、interaction limits や `/runpr` のメンション検査への影響）を確認する。
-   **関連文書とテストの更新:** [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)、`docs/dev/guides/fixprguard_guide.md`、関連テストを更新する。

**要件定義の際に決めたこと（2026-11-23）:**

本節では、進め方、検証手順、信頼境界、および `/runpr` 統合に関する要件上の決定を記録する。

-   **進め方の選択:** 通常の進め方（`full`）にする。
    -   除外判定: 除外対象（`excluded`）。開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）を変える変更であり、既存の ADR の決定も変わるため、推奨どおり `full` を選んだ。
    -   ADR の判断: ADR なし（進め方の選択はこのタスク内に閉じるため）。
-   **事前確認と設計前観測:** 要件定義の場で PR #1094 と Sourcery AI の公式文書を確認し、未観測項目（レート制限・エラー時の CheckRun の `output.title`、スレッド返信時の応答、push 制限下での挙動等）は 0118 の F-001 と同様に設計前の観測要件（F-001）として `observations.md` に記録してから設計を始める。
    -   理由: 推測で CheckRun の分類や除外条件を固定すると、実装後に誤判定や停止を招くためである。
    -   ADR の判断: ADR なし（観測は判断材料の収集であり、決定そのものではないため）。
-   **信頼一覧の拡張:** `Automated reviewer list` を `coderabbitai` と `sourcery-ai` の 2 つにする（F-002）。
    -   理由: issue #1095 の目的であり、PR #1094 で GraphQL の著者が `Bot`・`sourcery-ai` であることを確認したためである。
    -   ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する（開発ツールの信頼境界を変える主要決定）。
-   **拒否メンションと `/runpr` の除外:** `Rejected mentions` に `@sourcery-ai` と `@sourceryai` の両方を追加して計 4 つとし、`/runpr` のメンション検査からは `sourcery-ai[bot]` の観測済みレビューガイドコメント（1 行目 `<!-- Generated by sourcery-ai[bot]: start review_guide -->`）を除外する（F-003）。
    -   理由: 公式文書と PR #1094 の観測から、Sourcery AI は `@sourcery-ai` と `@sourceryai` の両方に反応するため、両方とも利用者アカウントからの誤投稿と外部アカウントからの起動を抑止する必要がある。一方、Sourcery AI 自身のレビューガイドコメントはコマンド案内として `@sourcery-ai` を含むため、除外しないと通常の PR ごとに `/runpr` が Bot メンション確認で止まる。
    -   ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する（投稿拒否と `/runpr` のメンション検査の対象を広げる主要決定）。
-   **`/runpr` の手動 PR レビュー対象での併用:** `Awaited PR reviewer` を `coderabbitai` のままスコープ外とせず、CodeRabbit と Sourcery AI の両方を `/runpr` の PR レビュー依頼・完了待機の対象として併用する（F-004）。
    -   理由: 利用者が、信頼一覧への追加と合わせて `/runpr` からも Sourcery AI の完了待機と手動依頼を行えるようにすることを選んだためである。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（PR レビューの体制を変える主要決定）。
-   **Sourcery AI の自動 PR レビューの扱い:** Sourcery AI の自動 PR レビューは有効のまま設定を変えず、自動実行された `Sourcery review` CheckRun が進行中なら `/runpr` が完了まで待機し、成功完了すれば `LAST_REVIEWED` に数える。一方、自動レビューがスキップ・失敗・時間切れになっても `/runpr` は停止せず、完了の印に数えないまま要約に状態と URL を示してマージの質問へ進む。手動で依頼したレビューの失敗・スキップ・時間切れ時だけ停止する（F-004）。
    -   理由: すでに動いている Sourcery AI の自動レビューの結果を活かして二重依頼を避けつつ、自動レビューの週間枠や再レビュー上限でマージが塞がれるのを防ぐためである。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（自動 PR レビューの完了判定と停止条件を定める主要決定）。
-   **複数レビュアー併用時のマージの質問と `LAST_REVIEWED`:** どちらか 1 社でも完了していればそのコミットをレビュー済みとして `LAST_REVIEWED` を算出する。マージの質問は 4 択上限（[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を保つため「先に PR レビューを依頼」を 1 択のまま維持し、`head` を未レビューのレビュアーが 1 社以上残っていれば（`LAST_REVIEWED == head` でも）表示する。エスカレーションの推奨は `LAST_REVIEWED` に基づくため、`LAST_REVIEWED == head` なら推奨は「マージ」とする。「先に PR レビューを依頼」を選んだ直後に、単一選択の 1 問（「CodeRabbit」「Sourcery AI」「マージの質問に戻る」）で依頼先を選ぶ（F-004）。
    -   理由: 4 択上限と `chief` の単一選択中継（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)）を保ちつつ、Sourcery AI の自動レビュー完了後に信頼境界の変更などで CodeRabbit のレビューを追加依頼できる手段を残すためである。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) と [ADR-0047](../../dev/adr/0047-runpr-merge-question.md) を更新する（完了判定とマージの質問の遷移を変える主要決定）。
-   **Sourcery AI の手動依頼コメント文面:** `/runpr` が投稿する文面は公式正規形の `@sourcery-ai review` のみとし、利用者が手で書いた依頼コメントの認識には `@sourcery-ai review` と `@sourceryai review` の両方を含める（F-004）。
    -   理由: コマンドが投稿する文面は正規形に統一しつつ、利用者が GitHub 上でハイフンなしの `@sourceryai review` を手入力した場合（PR #1094 の実例あり）も応答待ちの手動依頼として正しく拾うためである。
    -   ADR の判断: ADR なし（依頼文字列の認識詳細は [ADR-0013](../../dev/adr/0013-review-setup.md) の手動依頼の決定の範囲内に閉じるため）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   Sourcery AI（`sourcery-ai`）が開いたレビュースレッドを、`/fixpr`・`/runpr` で名指しなしに信頼する著者のスレッドとして処理できるようにする。
-   利用者のアカウントからの誤投稿による Sourcery AI の意図しない起動、および書き込み権限のない第三者による `@sourcery-ai`・`@sourceryai` メンション経由の誘導を抑止する。
-   `/runpr` が Sourcery AI の自動・手動 PR レビューの進行中待機と完了判定を行え、マージの質問から CodeRabbit と Sourcery AI のどちらかを選んで手動 PR レビューを依頼できるようにする。

### 2.2. スコープ (In Scope)

-   Sourcery AI の PR レビュー挙動の設計前観測と `observations.md` の記録（F-001）。
-   `_context.md` の `Automated reviewer list` への `sourcery-ai` 追加とガードテストの更新（F-002）。
-   `_context.md`・`fixprguard`・コマンド文書・`/runpr` のメンション検査への `@sourcery-ai`・`@sourceryai` 追加と、Sourcery AI 定型レビューガイドコメントの除外（F-003）。
-   `_context.md`・`fixprguard`・`/runpr` の複数 PR レビュアー対応（CodeRabbit と Sourcery AI の併用、Sourcery AI 自動レビューの待機・完了判定、依頼先選択の単一選択質問）（F-004）。
-   現在の仕様を書く文書（`docs/dev/guides/fixprguard_guide.md`・ADR-0013・ADR-0015・ADR-0047 等）と `chief` 互換性の更新（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   **ローカルの CLI レビューの変更:** CodeRabbit CLI のまま変更しない。
-   **Sourcery AI の自動レビュー無効化やリポジトリ設定ファイルの追加:** `.sourcery.yaml` の作成や Sourcery ダッシュボード上の自動レビュー停止は行わない（1 章の決定）。
-   **`fixprguard` の変更範囲規則と監視一覧:** `docs/dev/guides/fixprguard_guide.md` 6 章の範囲の規則と 7.1 の監視の一覧は変えない。
-   **過去のタスク文書（`docs/tasks/`）の変更:** 各タスクの決定記録なので変えない。
-   **製品のセキュリティ文書（`docs/dev/security.md`）の変更:** 製品を対象にした文書であり、本タスクは開発ツールの境界を対象とするため変えない（タスク 0030・0057・0118 と同じ扱い）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: Sourcery AI の PR レビュー挙動の観測（設計前）

設計を始める前に、試験の PR と公式文書で Sourcery AI の未観測の振る舞いを確認し、PR #1094 で観測済みの結果と合わせて記録する。

**Acceptance Criteria**:
- **AC-01**: 観測の記録（`observations.md`）がある。記録は、次の各項目について、観測した日付、PR 番号（PR #1094 または試験の PR）、観測した API の値を持つ。観測できなかった項目は、その旨と公式文書から分かる内容を出典とともに記録する。
    1. 手動依頼（`@sourcery-ai review`・`@sourceryai review`）および push による自動レビューの開始から完了までに Sourcery AI が投稿・変更するもの（コメント、レビュー、スレッド、CheckRun、PR 説明の追記）と順序。
    2. 完了とレビュー対象コミットを示す値（指摘なし・指摘ありの両方）。
    3. 割り当て切れ・再レビュー上限・スキップ・エラー時の CheckRun の `status`・`conclusion`・`output.title` とコメントの形。
    4. スレッド・コメント・レビュー・CheckRun の著者と App 識別子（GraphQL `author.__typename`・`author.login`・`checkSuite.app.slug`、REST `user.type`・`user.login`）。
    5. Sourcery AI の各種投稿（レビューガイド、`linked_issues`、PR レビュー、行コメント、PR 説明の追記、スレッド返信等）に `@sourcery-ai`・`@sourceryai`・`@coderabbitai`・`@codex` が含まれるか、および各投稿の 1 行目ヘッダーの形。
    6. 指摘をスレッドにせず本文だけに書く場合、本文を読まずにその有無や数が分かる API 値があるか。
    7. 一部のファイルをレビューしなかったことを示す API 値があるか。
    8. 現在のブランチの push の制限（`docs/dev/guides/fixprguard_guide.md` 10 章）の下で、Sourcery AI が PR のブランチへ commit を push できるか。
    9. レビュー完了後に利用者が Sourcery AI のスレッドへ返信したとき（`/fixpr` の返信。メンションなし）の Sourcery AI の応答（返信コメント・リアクション・PR レビュー・CheckRun の有無）。
    10. Sourcery AI が `AGENTS.md`・`CLAUDE.md` を読むか（公式文書から）。
- **AC-02**: 試験の PR への手動依頼コメントは利用者が投稿し、エージェントは投稿しない。記録には投稿者を明記する。
- **AC-03**: 記録は `docs/tasks/0122_sourcery_trusted_reviewer/observations.md` に置き、`02_architecture.md` と同じ PR で commit する。試験の PR はマージせずに閉じる。
- **AC-04**: 観測結果が本書の前提と食い違う場合（例: 現在の push 制限下で Sourcery AI が PR ブランチに push できる、PR 説明への追記に拒否メンションが含まれる、`/fixpr` の返信に対して完了の印と紛れる CheckRun を作る等）は、記録に残して停止し、設計に進まず利用者に判断を仰ぐ。
- **AC-05**: `02_architecture.md` が完了の印・スキップ・エラー・メンション除外コメントの判定に使う値は、すべて AC-01 の記録にある値である。

#### F-002: 信頼する自動レビュアー一覧への `sourcery-ai` 追加

`_context.md` の `Automated reviewer list` に `sourcery-ai` を追加し、`fixprguard`・コマンド文書・ガードテストが `coderabbitai` と `sourcery-ai` の 2 つを信頼する自動レビュアーとして扱うようにする。

**Acceptance Criteria**:
- **AC-06**: `.claude/commands/_context.md` の `Automated reviewer list` の値が、GraphQL の `author.login` の形（`[bot]` なし）で、ちょうど `coderabbitai` と `sourcery-ai` の 2 つである。
- **AC-07**: `fixprguard` の `list`・`begin`・`inspect`・`reply` に `--reviewer coderabbitai --reviewer sourcery-ai` を渡したとき、次の振る舞いになる。
    - 著者の種類が `Bot` かつ `login` が `sourcery-ai`（大文字小文字を区別した完全一致）のコメントは、権限照会なしで信頼する著者となる。すべてのコメントが信頼する著者であるスレッドは名指しなしで処理対象となり、`begin` 出力の `authorType` は `Bot` である（`/fixpr` のラウンド上限が働く）。
    - `coderabbitai` と `sourcery-ai`、または書き込み権限を持つ `User` が混在するスレッドも、すべてのコメントが信頼する著者であれば信頼する著者のスレッドとなる。
    - 大文字小文字が異なる `Bot`（例: `Sourcery-AI`）、`[bot]` 付きの `sourcery-ai[bot]`、一覧にない `Bot` は `other-bot` で信頼しない。`User` で `login` が `sourcery-ai` のアカウントは自動レビュアーとして扱わず権限照会で判定する。
- **AC-08**: `.claude/commands/fixpr.md`・`.claude/commands/runpr.md`・`.claude/commands/mkreq.md`・`.claude/commands/_lib/task-pr-handoff.md` は、`sourcery-ai` および `sourcery-ai[bot]` を直書きせず、`_context.md` の `Automated reviewer list` を参照して全名前を 1 つずつ `--reviewer` で渡す。
- **AC-09**: `cmd/yt2column/fixpr_docs_test.go` の期待一覧（`wantReviewers`）が `coderabbitai` と `sourcery-ai` の 2 つに一致し、一覧の欠落・重複・不正文法・予期しない追加・コマンド文書への直書きに対してテストが失敗する。

#### F-003: 拒否メンションの拡張と `/runpr` の除外

利用者のアカウントからの投稿とコミット本文で `@sourcery-ai`・`@sourceryai` も拒否し、`/runpr` の他アカウントメンション検査を 4 つのメンションへ広げたうえで、Sourcery AI 自身の観測済み定型コメントを除外する。

**Acceptance Criteria**:
- **AC-10**: `.claude/commands/_context.md` の `Rejected mentions` の値と `fixprguard.RejectedMentions()` の返す一覧が、`@codex`・`@coderabbitai`・`@sourcery-ai`・`@sourceryai` の 4 つで一致している。
- **AC-11**: `fixprguard` の `reply`（本文）・`edit-pr`（タイトル・本文）・`append-pr`（追記ファイル・追記後の PR 本文）・`finish`（コミット本文ファイル）は、これら 4 つのいずれかを ASCII の大文字小文字を区別せず部分文字列として含む入力を、GitHub への書き込みまたは commit の前に拒否する。既存 PR 本文にいずれかが含まれる場合の `append-pr` は `current-body-mention` で停止し、同じ書き込みを繰り返さない。
- **AC-12**: コマンド定義の投稿前メンション検査（`<mention-check>`）は 4 つすべてのメンションを拒否し、例外は手動 PR レビュー依頼コメントの投稿（F-004）のみとする。コマンド文書と `CLAUDE.md` でこれら 4 つのメンションを書いてよい場所は、`_context.md` の手動 PR レビュー依頼の行と `Rejected mentions` の行だけである。
- **AC-13**: `/runpr` の PR 会話コメント・行コメント・PR レビューに対するメンション検査（`<rejected-mentions>`）は 4 つすべてを対象とし、著者の種類で次のように扱う。
    1. 利用者本人（`User` かつ認証済みアカウント）: 停止理由にしない。
    2. 利用者以外の `User`: 停止し、該当コメントの URL だけを示す（本文は出さない）。
    3. 観測済みの定型コメント（`coderabbitai[bot]` の既存 2 種、および `sourcery-ai[bot]` の 1 行目（末尾 CR を除く）が `<!-- Generated by sourcery-ai[bot]: start review_guide -->` であるコメント。F-001 で他に定型ヘッダーが観測された場合は設計で加える）: メンションとして扱わない。
    4. それ以外の `Bot`（観測済み定型に合わない `sourcery-ai[bot]`・`coderabbitai[bot]` の投稿を含む）: 続行するかを利用者に単一選択で尋ね、該当 URL だけを示す（本文は出さない）。
- **AC-14**: `/runpr` の `interaction-limits` の確認は従来どおり行う。

#### F-004: `/runpr` と `fixprguard` の複数 PR レビュアー対応

CodeRabbit（手動）と Sourcery AI（自動・手動）を併用し、`/runpr` が両者の完了判定・待機と、マージの質問からの依頼先選択を行えるようにする。

**Acceptance Criteria**:
- **AC-15**: `.claude/commands/_context.md` に、PR レビューの待機・依頼の対象となる自動レビュアー（`coderabbitai` と `sourcery-ai`）と、各レビュアーへの手動依頼文面（CodeRabbit は `@coderabbitai review`、Sourcery AI は投稿用 `@sourcery-ai review`、および利用者の手動投稿認識用として `@sourceryai review` も受理する定義）が 1 か所で定められている。コマンド文書（`runpr.md`・`fixpr.md` 等）はこれらの名前や依頼文面を直書きせず、`_context.md` を参照する。
- **AC-16**: Sourcery AI の自動 PR レビューが有効な状態で、`/runpr` が step 3 に入った時点で依頼コメントがなくても `sourcery-ai` の `Sourcery review` CheckRun が進行中（未完了）であれば、`/runpr` はその完了（または待機上限の 15 分）まで待機してから、スレッド処理とエスカレーションへ進む。
- **AC-17**: 完了の印の判定は、信頼しない入力として厳密に行う。
    - **CodeRabbit:** 従来どおり、利用者本人（`User`）の `@coderabbitai review` 依頼コメント後に始まった `app.slug == "coderabbitai"` の CheckRun `CodeRabbit` で、観測済みの完了形（`COMPLETED`・`SUCCESS`・`Finished`）に一致するものだけを完了の印とする。
    - **Sourcery AI:** `app.slug == "sourcery-ai"` の CheckRun `Sourcery review` のうち、F-001 の観測記録に合う成功完了の形（PR #1094 時点では `COMPLETED`・`SUCCESS`・`"✅ Completed successfully"`）に一致するものを完了の印とする。自動実行された完了と、利用者本人（`User`）が投稿した `@sourcery-ai review` または `@sourceryai review`（前後の空白を除いて完全一致）に応答した完了のどちらも完了の印に数える。
    - どちらのレビュアーについても、同じ名前の `User` による投稿、観測した形に合わない CheckRun、PR の `head` にもその祖先にも当たらないコミットの CheckRun は完了の印に数えない。本文はセッションに出さない。
- **AC-18**: `LAST_REVIEWED` は、CodeRabbit と Sourcery AI の完了の印の和集合から、他のすべての完了コミットを祖先とする最新のコミット（`head` に完了の印があれば `head`）とする。いずれか 1 社でも `head` を完了していれば `LAST_REVIEWED == head` となる。
- **AC-19**: Sourcery AI の自動レビュー（手動依頼コメントなし）が、スキップ・割り当て切れ・エラー・未認識の形・待機上限時間超過（15 分）で終わったとき、`/runpr` は停止せず、その実行を完了の印に数えないままマージの質問へ進み、要約にその状態と URL（本文は出さない）を示す。
- **AC-20**: 利用者が手動で依頼した PR レビュー（CodeRabbit への `@coderabbitai review`、または Sourcery AI への `@sourcery-ai review`・手動投稿の `@sourceryai review`）が、割り当て切れ・スキップ・エラー・未認識の形・待機上限時間超過（15 分）・判定不能（`indeterminate`）になったときは、レビュー済みとせずに停止し、状態・依頼コメントの URL・次の行動を示す（本文は出さない）。応答待ちの手動依頼がある状態で `/runpr` を再実行したときは、新しい依頼を投稿せず待機から再開する。
- **AC-21**: マージの質問は、引き続き最大 4 択の単一選択（[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を保つ。「先に PR レビューを依頼」は、`head` を未レビューのレビュアー（CodeRabbit または Sourcery AI）が 1 社以上残っているときに 1 つの選択肢として表示し、両社とも `head` を完了済みのときは表示しない。
- **AC-22**: マージの質問の推奨（エスカレーション）は `LAST_REVIEWED` に基づく。`LAST_REVIEWED == head` のときは「未レビューの変更: なし」とし、「先に PR レビューを依頼」が表示されていても推奨は「マージ」とする。`LAST_REVIEWED` が `head` より後ろまたは `none` のときは既存の基準（[0118 要件定義書](../0118_codex_removal/01_requirements.md) の F-005）に従い、推奨が `PR レビュー` なら「先に PR レビューを依頼」を先頭・推奨に、推奨が `マージ` なら「マージ」を先頭・推奨にする。
- **AC-23**: マージの質問で利用者が「先に PR レビューを依頼」を選んだとき、`/runpr` は直後に単一選択の 1 問で依頼先レビュアーを選ばせる。選択肢は依頼可能なレビュアー（`CodeRabbit`・`Sourcery AI`、各社が `head` レビュー済みか未レビューかを併記）と `マージの質問に戻る` の最大 3 択とする。`マージの質問に戻る` を選べば何も投稿せずマージの質問に戻る。`CodeRabbit` を選べば `@coderabbitai review` を、`Sourcery AI` を選べば `@sourcery-ai review` を 1 件だけ投稿し、完了を待ってからスレッド処理・マージの質問へ戻る。
- **AC-24**: マージの質問の要約は、CodeRabbit と Sourcery AI それぞれの PR レビュー状態（完了コミット・URL・本文に指摘や未レビューファイルがありうる旨、またはスキップ・失敗・上限超過の状態）を、本文をセッションに出さずに示す。
- **AC-25**: PR を開くコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/mkplan2`・`/runplan`、単独変更の `/runpr`）は、従来どおり PR 作成後にどの自動レビュアーにも依頼コメントを投稿しない。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

本タスクが変更または拡張する信頼できない入力の境界は、次の 2 つである。いずれも標準ライブラリやツールが黙って修復・破棄・無視する入力（不正な UTF-8、対になっていないサロゲート、重複メンバーの後勝ち、後続データ）を受け入れず拒否する。

1. **GitHub API のレビュースレッドの著者（F-002）:**
   - **受け入れる形:** 既存の 0030・0033 と同じ（`__typename` が `Bot` または `User`、`login` が英数字先頭・英数字と `-` のみ・39 文字以内。`internal/fixprguard/types.go:24,64-74`）。自動レビュアー判定は `Bot` かつ `--reviewer` で渡された名前との大文字小文字を区別した完全一致のみとし、`[bot]` の付け外しや正規化はしない。
   - **拒否の扱い:** 一覧にない `Bot` はエラーではなく信頼しない理由 `other-bot` に分類する（センチネルエラーは使わない）。応答の JSON 構造不正は既存と同じく `ErrResponseRejected` にまとめる。
   - **使うメンバーと上限:** 既存の `__typename`・`login` のみで追加メンバーはない。権限照会の上限（100 回）およびスレッド件数上限（2000 件）は変えない。

2. **GitHub API の PR レビュー状態・メンション一覧の応答（F-003・F-004）:**
   - **受け入れる形:**
     - `review-state` が読む REST（PR head・ユーザー・会話コメント・PR レビュー）と GraphQL（PR コミット・CheckSuite・CheckRun）の応答は、既存の厳格な JSON 検査（`internal/fixprguard/review_state.go`）とサイズ上限（16 MiB）を通る単一のトップレベル値のみとする。
     - CheckRun は `checkSuite.app.slug` が対象レビュアー（`coderabbitai` または `sourcery-ai`）に完全一致し、CheckRun 名・`status`・`conclusion`・`output.title` が F-001 の観測に基づく分類表に完全一致するものだけを分類する。表にない `COMPLETED` CheckRun は完了とみなさず未認識（`unrecognized`）とする。
     - 依頼コメントは `user.type == "User"` かつ認証済み利用者の `login` と完全一致し、`body` が前後空白除去後に定義された依頼文字列（CodeRabbit は `@coderabbitai review`、Sourcery AI は `@sourcery-ai review` または `@sourceryai review`）と完全一致するものだけとする。
     - `/runpr` の 3 つのメンション一覧（会話コメント・行コメント・PR レビュー）で除外する定型コメントは、`user.type == "Bot"` かつ `user.login == "<対象>[bot]"` かつ本文の 1 行目（末尾 CR を除く）が観測済みヘッダーと完全一致するものだけとする。
   - **拒否の扱い:** `review-state` の応答不正・上限超過・呼び出し失敗は、既存の `unreadable` 状態（`reason`: `rejected`・`limit`・`call-failed`）にまとめ、部分的な結果を使わない（Go 内部では既存の `ErrResponseRejected` 相当の拒否として扱い、本文や未検証値は出力しない）。`/runpr` のメンション一覧取得失敗は既存の再試行・15 分停止ルールに従う。
   - **使うメンバーと拡張可能メンバー:** `review-state` が使うメンバーは既存の `id`・`user.login`・`user.type`・`body`・`created_at`・`updated_at`・`html_url`・`head.sha`・`headRefOid`・`oid`・`app.slug`・`name`・`status`・`conclusion`・`title`・`startedAt`・`completedAt`・`url`・`commit_id`・`submitted_at`・`pageInfo` である（`name` は複数 CheckRun を扱う場合に設計で確定する）。これら以外の GitHub API メンバーは、GitHub が追加しうるため拡張可能として無視する。使うメンバーの欠落・型違い・重複は拒否する。
   - **上限:** 既存の固定上限（コメント 3000 件、レビュー 3000 件、PR コミット 1000 件、CheckSuite 50 件、CheckRun 100 件、応答 16 MiB、待機上限 15 分）を維持する（`internal/fixprguard/review_state.go:59-67`）。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。`--reviewer` の比較対象が 1 つから 2 つになるだけで、スレッド判定の GitHub 問い合わせ回数は増えない。`review-state` のポーリング間隔（約 30 秒）と待機上限（15 分）は既存どおりとする。

### 4.2. セキュリティ (Security)

-   条件付きのセキュリティガイド（`docs/dev/security.md`）のトリガー（`yt-dlp` の起動、LLM の API キー、キャッシュ、LLM API への送信、製品プロンプト・記事への信頼しないテキスト埋め込み）に当たる機能はない。**N/A。**
-   開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）を次のとおり変更し、残余リスクを `docs/dev/guides/fixprguard_guide.md` 7.2 に記録する（AC-26）。
    -   **信頼する著者の拡大:** `sourcery-ai` のスレッドは名指しなしで利用者確認前にトリアージ・修正エージェントに渡り、信頼する著者の変更範囲（同じディレクトリの `.go` 等）が適用される。本文は従来どおり区切りのブロックでデータとして扱い、実行関連ファイルは常に範囲外とする。
    -   **外部の人による誘導の残余リスク:** Sourcery AI は外部の人の `@sourcery-ai`・`@sourceryai` メンションに応じうるものとして扱う。入口の守りはアカウントの `interaction-limits`（`collaborators_only`）と `/runpr` の状態確認・他アカウントメンション検出（AC-13・AC-14）に頼る。`interaction-limits` が外れている間に外部の人が指示したスレッド、および `/fixpr` を単独実行した場合の経路は、CodeRabbit と同じく残余リスクとする。
    -   **PR ブランチへの書き込み:** 現在の push の制限（ruleset、`fixprguard_guide.md` 10 章）下で Sourcery AI が PR ブランチに push できないことを F-001（AC-01 の 8）で確かめる。push できると分かった場合は設計に進まず停止する（AC-04）。
    -   **投稿文面の保護:** 利用者アカウントからの投稿・コミット本文で `@sourcery-ai`・`@sourceryai` を拒否し（AC-11・AC-12）、エージェントの返信や PR 説明更新が意図せず Sourcery AI のコマンド（`title`・`summary`・`review`・`resolve` 等）を起動するのを防ぐ。ただし Sourcery AI は自身が開始したスレッドへのメンションなし返信にもチャットとして応答しうるため（公式文書）、拒否はメンションによるコマンド起動を防ぐものにとどまる（実際の返信時の挙動は AC-01 の 9 で観測する）。
    -   **Bot の同一性:** `sourcery-ai` の判定も `__typename` と `login`（CheckRun は `app.slug`）に依存する。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   Sourcery AI の自動レビューがスキップ・割り当て切れ・失敗・時間切れになっても、`/runpr` はマージの進行を止めず、要約に状態を示して利用者が判断できるようにする（AC-19）。
-   利用者が手動で依頼したレビューが届かない・失敗した・形が認識できない場合は、誤ってレビュー済みとせず安全側に停止して報告する（AC-20）。

### 4.4. 互換性 (Compatibility)

-   **`fixprguard` のプロトコル互換性:** `review-state` の契約が変わる場合、古いバイナリと新しい文書の組み合わせが誤動作しないよう、`CLAUDE.md` の「Protocol numbers」と `docs/dev/guides/fixprguard_guide.md` 9 章に従い、`Protocol` を `main` の値 + 1 へ引き上げるかを設計で確定する（[design_handoff.md](design_handoff.md) の H-03）。
-   **既存の CodeRabbit 手動 PR レビュー:** CodeRabbit に対する手動依頼・完了判定・割り当て切れ判定・`cr_observed` 除外の振る舞いは維持する。
-   **`chief` との互換性:** マージの質問の 4 択制約と単一選択形式を維持し、依頼先選択の質問も単一選択とすることで、`chief` の中継と読み取り（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)・[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を壊さない（AC-28）。

### 4.5. 保守性 (Maintainability)

-   信頼する自動レビュアーの一覧、拒否メンション、PR レビュー待機対象と依頼文面は、いずれも `.claude/commands/_context.md` の 1 か所で管理し、コマンド文書に名前やメンションを散在させない（AC-08・AC-12・AC-15）。
-   `_context.md` の値と `fixprguard`・テスト・ガイドの整合は `go test -tags test` の文書ガードで機械的に検証する（AC-09・AC-29）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」と `CLAUDE.md` の規約に従う。
-   `fixprguard` バイナリは `_context.md` を直接読まない（タスク 0030 の設計方針を維持）。
-   開発ツール（`fixprguard` 等）のインストール・ビルドは利用者が行い、エージェントは行わない（`CLAUDE.md`「Tool Execution Safety」）。
-   `Protocol` 番号を上げる場合、タスク文書には引き上げ後の具体的な番号を書かず「`main` の値 + 1」と記す（`CLAUDE.md`「Protocol numbers」）。
-   F-001 の観測記録（`observations.md`）がそろう前に、`02_architecture.md` で CheckRun の分類値や除外ヘッダーを確定しない（AC-05）。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。本書で使う主な用語は次のとおりである。

-   **自動レビュアー:** PR にレビューのスレッドを投稿する Bot。本タスクでは CodeRabbit（`coderabbitai`）と Sourcery AI（`sourcery-ai`）を対象とする。英語では automated reviewer。
-   **自動レビュアーの一覧:** `.claude/commands/_context.md` の `Automated reviewer list` に定める、スレッドを信頼する自動レビュアーの名前（GraphQL の `author.login` の形）の一覧。英語では automated reviewer list。
-   **信頼する著者:** リポジトリへの書き込み権限（write・maintain・admin）を持つ Bot でないアカウントと、自動レビュアーの一覧のどれかの名前の Bot。英語では trusted author。
-   **拒否メンション:** 利用者のアカウントからの投稿とコミット本文に含めてはならず、`/runpr` が他アカウントからの投稿も検査するメンションの一覧（`_context.md` の `Rejected mentions`）。本タスクで `@codex`・`@coderabbitai`・`@sourcery-ai`・`@sourceryai` の 4 つとする。
-   **完了の印:** PR レビューがあるコミットまで完了したことを示す、対象 GitHub App の CheckRun の値。CodeRabbit は手動依頼後の完了、Sourcery AI は自動実行または手動依頼後の完了を対象とする。
-   **手動の PR レビュー:** 利用者本人の依頼コメント（`@coderabbitai review`・`@sourcery-ai review`、または手動投稿の `@sourceryai review`）で始まる PR レビュー。
-   **自動の PR レビュー:** 依頼コメントなしで、PR 作成や push に応じて Sourcery AI の GitHub App が自律的に実行する PR レビュー。
