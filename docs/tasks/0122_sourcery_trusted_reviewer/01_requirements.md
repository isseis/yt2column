## 1. 概要 (Overview)

**目的:** 本書は、Sourcery AI（`sourcery-ai`）を自動レビュアーの一覧（`Automated reviewer list`）に加え、拒否するメンションと `/runpr` のメンション検査を拡張し、CodeRabbit（手動）と Sourcery AI（自動・手動）を併用する PR レビュー体制を実現するための要件を定義する。

対応 issue: [#1095](https://github.com/isseis/yt2column/issues/1095)（関連: [#405](https://github.com/isseis/yt2column/issues/405)（タスク `0033_multiple_trusted_reviewers`）、[#629](https://github.com/isseis/yt2column/issues/629)（タスク `0057_reviewer_relay_guard`）、[#1059](https://github.com/isseis/yt2column/issues/1059)（タスク `0118_codex_removal`）、[#1072](https://github.com/isseis/yt2column/issues/1072)（タスク `0120_harness_independent_commands`））

**背景:**

現在、`.claude/commands/_context.md:298` の `Automated reviewer list` は `coderabbitai` だけである（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）。そのため、`sourcery-ai` が PR に開いたレビュースレッドは、`fixprguard` の判定で想定外の著者のスレッド（理由 `other-bot`、`account: sourcery-ai`）として隔離される。`/fixpr` や `/runpr` で自動処理するには、毎回スレッドごとに `--accept <threadId>=<fingerprint>` を指定する必要がある（例: PR [#1094](https://github.com/isseis/yt2column/pull/1094)）。

また、現在の `Rejected mentions`（`.claude/commands/_context.md:301`）と `fixprguard.RejectedMentions()`（`internal/fixprguard/errors.go:79-81`）は `@codex` と `@coderabbitai` の 2 つである。`/runpr` は、PR の会話コメント・行コメント・PR レビューに含まれるこれらのメンションを検査し、利用者以外の `User` なら停止、`Bot` なら続行確認を出す（CodeRabbit の定型 2 種 `cr_observed` のみ除外。`.claude/commands/runpr.md:441-537`）。一方、`/runpr` の手動の PR レビューと `fixprguard review-state` は、単一の `Awaited PR reviewer`（`coderabbitai`）と単一の `PR review request`（`@coderabbitai review`）を前提にしており（`.claude/commands/_context.md:299-300`、`internal/fixprguard/review_state.go:44-50,655-679`、`runpr.md:1277-1310`）、Sourcery AI の完了待機や手動依頼には対応していない。さらに、`.claude/commands/runpr.md:710-713` の CI 待機では、`gh pr checks <number> --watch --fail-fast` により `head` コミットの全 CheckRun が完了して成功するまで待つ。

要件定義の際に PR [#1094](https://github.com/isseis/yt2column/pull/1094) の API 読み取りと Sourcery AI の公式文書（`https://docs.sourcery.ai/`、2026-11-23 確認）を調べたところ、次の事実が分かった。

-   **アカウントと CheckRun の識別子:** GraphQL のスレッドでは `author.__typename: "Bot"`・`author.login: "sourcery-ai"`、REST のコメント・レビューでは `user.type: "Bot"`・`user.login: "sourcery-ai[bot]"`、CheckRun は `checkSuite.app.slug: "sourcery-ai"`・`name: "Sourcery review"` であった。成功完了時は `status: "COMPLETED"`・`conclusion: "SUCCESS"`・`title: "✅ Completed successfully"` を観測した（コミット `86a8f476`・`2ee50010`）。
-   **メンションへの反応:** Sourcery AI は `@sourcery-ai` と `@sourceryai`（ハイフンなし）の両方のメンションで `review`・`summary`・`guide`・`title`・`resolve`・`dismiss`・`create issue` およびチャットを起動する（公式文書、および PR #1094 で利用者 `isseis` が投稿した `@sourceryai review` の 7 秒後に `Sourcery review` CheckRun が始まったことを観測）。PR タイトルの `@sourcery-ai` や PR の説明の `@sourcery-ai summary` でも動作する。
-   **Sourcery AI 自身の投稿のメンション含有:** レビューガイドコメント（1 行目: `<!-- Generated by sourcery-ai[bot]: start review_guide -->`）はコマンド案内として `@sourcery-ai` を複数含む。一方、`linked_issues` コメント（1 行目: `<!-- Generated by sourcery-ai[bot]: start linked_issues -->`）、PR レビュー本文 2 件、行コメント 11 件、PR の説明に追記された `## Sourcery による概要` / `## Summary by Sourcery` には `@sourcery-ai`・`@sourceryai` は含まれなかった。
-   **自動の PR レビューと制限:** PR #1094 のコミット `2ee50010` では、依頼コメントなしの push で `Sourcery review` CheckRun が自動実行・完了した。公式文書では、割り当て切れや再レビュー上限時は CheckRun が `SKIPPED` になるとされるが、その正確な `output.title`、エラー時の `conclusion`・`title`、スレッド返信時の応答、push の制限下での挙動、`AGENTS.md` の参照可否は未観測である。

**本書の記述範囲:** 本書は、観測可能な振る舞いを定める。具体的には、設計前の観測項目、自動レビュアーの一覧と拒否するメンションの対象、`/runpr` のメンション除外・CI 待機・自動および手動の PR レビューの待機と完了判定・マージの質問の振る舞い、文書と ADR の更新範囲である。次の事項は設計（`02_architecture.md`）で決める。設計は F-001 の観測記録がそろってから始める。

-   `_context.md` で複数の PR レビュアーと依頼文面を表す表の行構成とパース規則
-   `fixprguard review-state` の複数レビュアー・自動の PR レビュー対応のコマンド契約（引数、出力 JSON、CheckRun 分類表、競合判定）
-   `fixprguard` の `Protocol` 番号（現在 `internal/fixprguard/types.go:21` は `8`）を `main` の値 + 1 に上げる設計と PR の分割順序
-   `/runpr` のメンション除外フィルタ・CI 待機フィルタの実装形と、マージの質問の要約行・`chief` 読み取りの整合

要件定義の時点で挙がった設計の事項は、[design_handoff.md](design_handoff.md) に申し送る。

**issue #1095 で決めたこと:**

-   **自動レビュアーの一覧への追加:** `.claude/commands/_context.md` の `Automated reviewer list` に `sourcery-ai`（GraphQL の `author.login` 形式）を追加し、名指しなしで処理できるようにする。
-   **拒否するメンションの確認:** `Rejected mentions` に `@sourcery-ai` を追加する必要があるか（利用者アカウントからのメンションへの反応、interaction limits や `/runpr` のメンション検査への影響）を確認する。
-   **関連文書とテストの更新:** [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)、`docs/dev/guides/fixprguard_guide.md`、関連テストを更新する。

**要件定義の際に決めたこと（2026-11-23）:**

本節では、進め方、検証手順、信頼の境界、および `/runpr` 統合に関する要件上の決定を記録する。

-   **進め方の選択:** 通常の進め方（`full`）にする。
    -   除外判定: 除外対象（`excluded`）。開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）を変える変更であり、既存の ADR の決定も変わるため、推奨どおり `full` を選んだ。
    -   ADR の判断: ADR なし（進め方の選択はこのタスク内に閉じるため）。
-   **事前確認と設計前観測:** 要件定義の場で PR #1094 と Sourcery AI の公式文書を確認し、未観測項目（割り当て切れ・エラー時の CheckRun の `output.title`、スレッド返信時の応答、push の制限下での挙動等）は 0118 の F-001 と同様に設計前の観測要件（F-001）として `observations.md` に記録してから設計を始める。
    -   理由: 推測で CheckRun の分類や除外条件を固定すると、実装後に誤判定や停止を招くためである。
    -   ADR の判断: ADR なし（観測は判断材料の収集であり、決定そのものではないため）。
-   **自動レビュアーの一覧の拡張:** `Automated reviewer list` を `coderabbitai` と `sourcery-ai` の 2 つにする（F-002）。
    -   理由: issue #1095 の目的であり、PR #1094 で GraphQL の著者が `Bot`・`sourcery-ai` であることを確認したためである。
    -   ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する（開発ツールの信頼の境界を変える主要決定）。
-   **拒否するメンションと `/runpr` の除外:** `Rejected mentions` に `@sourcery-ai` と `@sourceryai` の両方を追加して計 4 つとし、`/runpr` のメンション検査からは `sourcery-ai[bot]` の観測済みレビューガイドコメント（1 行目 `<!-- Generated by sourcery-ai[bot]: start review_guide -->`）を除外する（F-003）。
    -   理由: 公式文書と PR #1094 の観測から、Sourcery AI は `@sourcery-ai` と `@sourceryai` の両方に反応するため、両方とも利用者アカウントからの誤投稿と外部アカウントからの起動を抑止する必要がある。一方、Sourcery AI 自身のレビューガイドコメントはコマンド案内として `@sourcery-ai` を含むため、除外しないと通常の PR ごとに `/runpr` が Bot メンション確認で止まる。
    -   ADR の判断: [ADR-0015](../../dev/adr/0015-untrusted-review-threads.md) を更新する（投稿拒否と `/runpr` のメンション検査の対象を広げる主要決定）。
-   **`/runpr` の手動の PR レビュー対象での併用:** `Awaited PR reviewer` を `coderabbitai` のままスコープ外とせず、CodeRabbit と Sourcery AI の両方を `/runpr` の PR レビュー依頼・完了待機の対象として併用する（F-004）。
    -   理由: 利用者が、自動レビュアーの一覧への追加と合わせて `/runpr` からも Sourcery AI の完了待機と手動依頼を行えるようにすることを選んだためである。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（PR レビューの体制を変える主要決定）。
-   **Sourcery AI の自動の PR レビューの扱いと CI 待機の分離:** Sourcery AI の自動の PR レビューは有効のまま設定を変えない。`head` コミット上で自動実行された `Sourcery review` CheckRun が進行中なら、`/runpr` は完了まで待機し（待機上限は CodeRabbit の `reviewWaitLimit` と同じ 15 分とする。`internal/fixprguard/review_state.go:59`）、開かれたスレッドを処理してからマージの質問へ進む。自動の PR レビューの完了は、成功しても最新のレビュー済みコミット（`LAST_REVIEWED`、定義は後述の AC-18）の算出対象に含めない（2026-11-25 に改めた。後述の「issue #1140 で決めたこと（2026-11-25）」）。自動の PR レビューがスキップ・割り当て切れ・失敗・未認識・時間切れになっても `/runpr` は停止せず、完了の印に数えないまま要約に状態と URL を示してマージの質問へ進む。`/runpr` の CI 待機はリポジトリの CI チェックのみを成否判定の対象とし、`Sourcery review` の失敗・未完了を CI 失敗として止めない。手動で依頼した PR レビューの失敗・スキップ・割り当て切れ・時間切れ時だけ停止する（F-004）。
    -   理由: すでに動いている Sourcery AI の自動の PR レビューの指摘を活かして二重依頼を避けつつ、自動の PR レビューの割り当て切れ・再レビュー上限・一時失敗でマージが塞がれるのを防ぐためである。CI 待機に `Sourcery review` の成否を含めると自動の PR レビュー失敗時に停止して矛盾するため、CI チェックと分離する。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（自動の PR レビューの完了判定・待機上限・停止条件と CI 待機との分離を定める主要決定）。
-   **複数レビュアー併用時のマージの質問と `LAST_REVIEWED`:** どちらか 1 社でも利用者の依頼に応じた PR レビューが完了していれば、そのコミットをレビュー済みとして `LAST_REVIEWED` を算出する（自動の PR レビューの完了は数えない。後述の「issue #1140 で決めたこと（2026-11-25）」）。マージの質問は 4 択上限（[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を保つため「先に PR レビューを依頼」を 1 択のまま維持し、`head` を未レビューのレビュアーが 1 社以上残っていれば（`LAST_REVIEWED == head` でも）表示する。エスカレーションの推奨は `LAST_REVIEWED` に基づくため、`LAST_REVIEWED == head` なら推奨は「マージ」とする。「先に PR レビューを依頼」を選んだ直後に、単一選択の 1 問（「CodeRabbit」「Sourcery AI」「マージの質問に戻る」の 3 択、各社の `head` レビュー済み／未レビューを併記）で依頼先を選ぶ（F-004）。
    -   理由: 4 択上限と `chief` の単一選択中継（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)）を保ちつつ、Sourcery AI の手動の PR レビュー完了後に信頼の境界の変更などで CodeRabbit のレビューを追加依頼できる手段を残すためである。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) と [ADR-0047](../../dev/adr/0047-runpr-merge-question.md) を更新する（完了判定とマージの質問の遷移を変える主要決定）。
-   **Sourcery AI の手動依頼コメント文面:** `/runpr` が投稿する文面は公式正規形の `@sourcery-ai review` のみとし、利用者が手で書いた依頼コメントの認識には `@sourcery-ai review` と `@sourceryai review` の両方を含める（F-004）。
    -   理由: コマンドが投稿する文面は正規形に統一しつつ、利用者が GitHub 上でハイフンなしの `@sourceryai review` を手入力した場合（PR #1094 の実例あり）も応答待ちの手動依頼として正しく拾うためである。
    -   ADR の判断: ADR なし（依頼文字列の認識詳細は [ADR-0013](../../dev/adr/0013-review-setup.md) の手動依頼の決定の範囲内に閉じるため）。

**issue #1140 で決めたこと（2026-11-25）:**

本節は、#1098 のクロスチェックの部分レビューの再レビュー（タスク 0123）で挙がった issue [#1140](https://github.com/isseis/yt2column/issues/1140) について、利用者と決めたことを記録する。

-   **Sourcery AI の自動の PR レビューの完了を `LAST_REVIEWED` に数えない:** `LAST_REVIEWED` は、利用者の依頼に応じた PR レビュー（CodeRabbit と Sourcery AI の手動の PR レビュー）の完了の印だけから決める。Sourcery AI の自動の PR レビューは、これまでどおり進行中なら待ち、開かれたスレッドを `/fixpr` で処理し、状態と URL をマージの質問の要約に示すが、成功して完了しても完了の印に数えない。したがって、自動の PR レビューが `head` を完了していても、依頼に応じた完了の印が `head` になければ、エスカレーションの判定と要約の「未レビュー分」の行（ローカルの CLI レビューの範囲とクロスチェックの記録）は 0118 までと同じく働く（AC-17・AC-18・AC-21・AC-22・AC-24）。
    -   理由: 自動の PR レビューの完了を数えると、Sourcery AI が push のたびに自動でレビューするので、ほとんどの PR で `LAST_REVIEWED == head` となり、エスカレーションの判定が飛ばされる。レビューの関門そのもの（`_lib/pr-review-escalation.md` の基準 4）を書き換える PR でも推奨が「マージ」になり、`high` 役割のワーカーが一度も判定しない。また、自動の PR レビューは 7 日間の予算を使い切るとスキップされ（観測の記録の 7 件の PR のうち 4 件）、関門が働くかどうかが変更の中身ではなく予算の残りで決まる。利用者が依頼しておらず、品質も測っていないレビューを、エスカレーションの代わりにしないためである。
    -   採らなかった案: (1) 自動の PR レビューの完了も数え、要件定義の際の決定（2026-11-23）のままにする。上の理由で関門がほとんど働かなくなる。(2) 自動の PR レビューの完了を数えないが、`head` を完了していれば、ローカルの CLI レビューがすべてを見たとき（`COVERAGE` が `ALL`）と同じに扱い、基準 1・2・3・5 だけに当たる変更を「マージ」推奨にする。`COVERAGE` はふだん `ALL` なので、この案と採った案とで結果が変わる場面はほとんどなく、規則だけが増える。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（「レビュー済みの判定」の決定を変える主要決定）。[ADR-0047](../../dev/adr/0047-runpr-merge-question.md) と [ADR-0050](../../dev/adr/0050-fable-partial-review.md) の決定は変わらない（`LAST_REVIEWED` の求め方に依らず成り立つ）。
-   **ADR-0013 の CodeRabbit の応答の選び方の規則を戻す:** #1098 で ADR-0013 の「レビュー済みの判定」を書き換えたとき、CodeRabbit の依頼の応答の選び方（依頼の後、次の依頼より前に始まった最初の CheckRun だけを数える）と、選べないとき（同じ秒に始まった、実行が重なった）に完了とせずに止まる規則、およびその理由（`output.title` を読む理由、「between」の行を使わない理由、止まる理由）が、経緯の行なしに消えた。これを決定の変更として ADR-0013 に戻し、経緯に記録する。
    -   理由: 4.4 は CodeRabbit の振る舞いを保つと定め、`internal/fixprguard/review_state.go` もその規則を実装したままであり、消えていたのは ADR の記述だけだったためである。編集上の訂正か迷う変更は決定の変更として扱う（`docs/dev/conventions/adr.md`「Editorial corrections」）。
    -   ADR の判断: [ADR-0013](../../dev/adr/0013-review-setup.md) を更新する（規則を決定に戻し、経緯に記録する）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   Sourcery AI（`sourcery-ai`）が開いたレビュースレッドを、`/fixpr`・`/runpr` で名指しなしに信頼する著者のスレッドとして処理できるようにする。
-   利用者のアカウントからの誤投稿による Sourcery AI の意図しない起動、および書き込み権限のない第三者による `@sourcery-ai`・`@sourceryai` メンション経由の誘導を抑止する。
-   `/runpr` が Sourcery AI の自動・手動の PR レビューの完了待機と、手動の PR レビューの完了判定を行え、マージの質問から CodeRabbit と Sourcery AI のどちらかを選んで手動の PR レビューを依頼できるようにする。

### 2.2. スコープ (In Scope)

-   Sourcery AI の PR レビュー挙動の設計前観測と `observations.md` の記録（F-001）。
-   `_context.md` の `Automated reviewer list` への `sourcery-ai` 追加と文書ガードの更新（F-002）。
-   `_context.md`・`fixprguard`・コマンド文書・`/runpr` のメンション検査への `@sourcery-ai`・`@sourceryai` 追加と、Sourcery AI 定型レビューガイドコメントの除外（F-003）。
-   `_context.md`・`fixprguard`・`/runpr` の複数 PR レビュアー対応（CodeRabbit と Sourcery AI の併用、Sourcery AI 自動の PR レビューの待機・完了判定、CI 待機との分離、依頼先選択の単一選択質問）（F-004）。
-   現在の仕様を書く文書（`docs/dev/guides/fixprguard_guide.md`・`CLAUDE.md`・`docs/translation_glossary.md`・ADR-0013・ADR-0015・ADR-0047）と `chief` 互換性の更新（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   **ローカルの CLI レビューの変更:** CodeRabbit CLI のまま変更しない。
-   **Sourcery AI の自動の PR レビューの無効化やリポジトリ設定ファイルの追加:** `.sourcery.yaml` の作成や Sourcery ダッシュボード上の自動レビュー停止は行わない（1 章の決定）。
-   **`fixprguard` の変更範囲規則と監視の一覧:** `docs/dev/guides/fixprguard_guide.md` 6 章の範囲の規則と 7.1 の監視の一覧は変えない。
-   **過去のタスク文書（`docs/tasks/`）の変更:** 各タスクの決定記録なので変えない。
-   **製品のセキュリティ文書（`docs/dev/security.md`）の変更:** 製品を対象にした文書であり、本タスクは開発ツールの境界を対象とするため変えない（タスク 0030・0057・0118 と同じ扱い）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: Sourcery AI の PR レビュー挙動の観測（設計前）

設計を始める前に、試験の PR と公式文書で Sourcery AI の未観測の振る舞いを確認し、PR #1094 で観測済みの結果と合わせて記録する。

**Acceptance Criteria**:
- **AC-01**: 観測の記録（`observations.md`）がある。記録は、次の各項目について、観測した日付、PR 番号（PR #1094 または試験の PR）、観測した API の値を持つ。観測できなかった項目は、その旨と公式文書から分かる内容を出典とともに記録する。
    1. 手動依頼（`@sourcery-ai review`・`@sourceryai review`）および push による自動の PR レビューの開始から完了までに Sourcery AI が投稿・変更するもの（コメント、レビュー、スレッド、CheckRun、PR の説明の追記）と順序。これには、完了済みまたは進行中の自動の PR レビュー（`Sourcery review` CheckRun）がすでにあるコミットへ手動依頼を投稿したとき、新しい CheckRun が作られるか既存の CheckRun が更新されるか、および `startedAt`・`completedAt` がどう変化するかも含む。
    2. 完了とレビュー対象コミットを示す値（指摘なし・指摘ありの両方）。
    3. 割り当て切れ・再レビュー上限・スキップ・エラー時の CheckRun の `status`・`conclusion`・`output.title` とコメントの形。
    4. スレッド・コメント・レビュー・CheckRun の著者と App 識別子（GraphQL `author.__typename`・`author.login`・`checkSuite.app.slug`、REST `user.type`・`user.login`）。
    5. Sourcery AI の各種投稿（レビューガイド、`linked_issues`、PR レビュー、行コメント、PR の説明の追記、スレッド返信等）に `@sourcery-ai`・`@sourceryai`・`@coderabbitai`・`@codex` が含まれるか、および各投稿の 1 行目ヘッダーの形。
    6. 指摘をスレッドにせず本文だけに書く場合、本文を読まずにその有無や数が分かる API 値があるか。
    7. 一部のファイルをレビューしなかったことを示す API 値があるか。
    8. 現在のブランチの push の制限（`docs/dev/guides/fixprguard_guide.md` 10 章）の下で、Sourcery AI が PR のブランチへ push できるか。
    9. レビュー完了後に利用者が Sourcery AI のスレッドへ返信したとき（`/fixpr` の返信。メンションなし）の Sourcery AI の応答（返信コメント・リアクション・PR レビュー・CheckRun の有無）。
    10. Sourcery AI が `AGENTS.md`・`CLAUDE.md` を読むか（公式文書から）。
- **AC-02**: 試験の PR への手動依頼コメントは利用者が投稿し、エージェントは投稿しない。記録には投稿者を明記する。
- **AC-03**: 記録は `docs/tasks/0122_sourcery_trusted_reviewer/observations.md` に置き、`02_architecture.md` と同じ PR でコミットする。試験の PR はマージせずに閉じる。
- **AC-04**: 観測結果が本書の前提と食い違う場合（例: 現在の push の制限下で Sourcery AI が PR ブランチに push できる、PR の説明への追記に拒否するメンションが含まれる、`/fixpr` の返信に対して完了の印と紛れる CheckRun を作る等）、または現在の push の制限下で Sourcery AI が PR ブランチへ push できないことを確かめられない場合（AC-01 の 8）は、記録に残して停止し、設計に進まず利用者に判断を仰ぐ。
- **AC-05**: `02_architecture.md` が完了の印・スキップ・エラー・メンション除外コメントの判定に使う値は、すべて AC-01 の記録にある値である。

#### F-002: 自動レビュアーの一覧への `sourcery-ai` 追加

`_context.md` の `Automated reviewer list` に `sourcery-ai` を追加し、`fixprguard`・コマンド文書・文書ガードが `coderabbitai` と `sourcery-ai` の 2 つを信頼する自動レビュアーとして扱うようにする。

**Acceptance Criteria**:
- **AC-06**: `.claude/commands/_context.md` の `Automated reviewer list` の値が、GraphQL の `author.login` の形（`[bot]` なし）で、ちょうど `coderabbitai` と `sourcery-ai` の 2 つである。
- **AC-07**: `fixprguard` の `list`・`begin`・`inspect`・`reply` に `--reviewer coderabbitai --reviewer sourcery-ai` を渡したとき、次の振る舞いになる。
    - 著者の種類が `Bot` かつ `login` が `sourcery-ai`（大文字小文字を区別した完全一致）のコメントは、権限照会なしで信頼する著者となる。すべてのコメントの著者が信頼する著者であるスレッドは名指しなしで処理対象となり、`begin` 出力の `authorType` は `Bot` である（`/fixpr` のラウンド上限が働く）。
    - `coderabbitai` と `sourcery-ai`、または書き込み権限を持つ `User` が混在するスレッドも、すべてのコメントの著者が信頼する著者であれば信頼する著者のスレッドとなる。
    - 大文字小文字が異なる `Bot`（例: `Sourcery-AI`）、`[bot]` 付きの `sourcery-ai[bot]`、一覧にない `Bot` は `other-bot` で信頼しない。`User` で `login` が `sourcery-ai` のアカウントは自動レビュアーとして扱わず権限照会で判定する。
- **AC-08**: `.claude/commands/fixpr.md`・`.claude/commands/runpr.md`・`.claude/commands/mkreq.md`・`.claude/commands/_lib/task-pr-handoff.md` は、`sourcery-ai` および `sourcery-ai[bot]` をどこにも直書きせず（メンション除外ヘッダーの表現を含む）、`_context.md` の定義を参照して `Automated reviewer list` にあるすべての名前を 1 つずつ `--reviewer` で渡す。
- **AC-09**: 文書ガードが `_context.md` の `Automated reviewer list` の期待値を `coderabbitai` と `sourcery-ai` の 2 つとして照合し、コマンド文書に一覧の名前が直書きされていないことの確認も含めて `make test` が成功する。

#### F-003: 拒否するメンションの拡張と `/runpr` の除外

利用者のアカウントからの投稿とコミット本文で `@sourcery-ai`・`@sourceryai` も拒否し、`/runpr` の他アカウントメンション検査を 4 つのメンションへ広げたうえで、Sourcery AI 自身の観測済み定型コメントを除外する。

**Acceptance Criteria**:
- **AC-10**: `.claude/commands/_context.md` の `Rejected mentions` の値と、ガードツールが拒否するメンションの一覧が、`@codex`・`@coderabbitai`・`@sourcery-ai`・`@sourceryai` の 4 つで一致している。
- **AC-11**: `fixprguard` の `reply`（本文）・`edit-pr`（タイトル・本文）・`append-pr`（追記ファイル・追記後の PR の説明）・`finish`（コミット本文ファイル）は、これら 4 つのいずれかを ASCII の大文字小文字を区別せず部分文字列として含む入力を、GitHub への書き込みまたはコミットの前に拒否する。既存の PR の説明にいずれかが含まれる場合の `append-pr` は `current-body-mention` で停止し、同じ書き込みを繰り返さない。
- **AC-12**: コマンド定義の投稿前メンション検査（`<mention-check>`）は 4 つすべてのメンションを拒否し、例外は手動の PR レビューの依頼コメント投稿（F-004）のみとする。コマンド文書と `CLAUDE.md` でこれら 4 つのメンションを書いてよい場所は、`_context.md` の手動の PR レビューの依頼の定義箇所と `Rejected mentions` の行だけである。
- **AC-13**: `/runpr` の PR 会話コメント・行コメント・PR レビューに対するメンション検査（`<rejected-mentions>`）は 4 つすべてを対象とし、著者の種類で次のように扱う。
    1. 利用者本人（`User` かつ認証済みアカウント）: 停止理由にしない。
    2. 利用者以外の `User`: 停止し、該当コメントの URL だけを示す（本文は出さない）。
    3. 観測済みの定型コメント（`coderabbitai[bot]` の既存 2 種、および `sourcery-ai[bot]` の 1 行目（末尾 CR を除く）が `<!-- Generated by sourcery-ai[bot]: start review_guide -->` であるコメント。F-001 で他に定型ヘッダーが観測された場合は設計で加える）: メンションとして扱わない。
    4. それ以外の `Bot`（観測済みの定型コメントに合わない `sourcery-ai[bot]`・`coderabbitai[bot]` の投稿を含む）: 続行するかを利用者に単一選択で尋ね、該当 URL だけを示す（本文は出さない）。
- **AC-14**: `/runpr` は step 1 で、PR の `head` 確認後・`gh pr checkout` の前に `interaction-limits` の状態を読み、`none`・`weak`・`predates`・`unverifiable` のときはレビューを待たずに停止する。

#### F-004: `/runpr` と `fixprguard` の複数 PR レビュアー対応

CodeRabbit（手動）と Sourcery AI（自動・手動）を併用し、`/runpr` が両者の完了判定・待機、CI 待機との分離、およびマージの質問からの依頼先選択を行えるようにする。

**Acceptance Criteria**:
- **AC-15**: `.claude/commands/_context.md` に、PR レビューの待機・依頼の対象となる自動レビュアー（`coderabbitai` と `sourcery-ai`）と、各レビュアーへの手動依頼文面（CodeRabbit は `@coderabbitai review`、Sourcery AI は投稿用 `@sourcery-ai review`、および利用者の手動投稿認識用として `@sourceryai review` も受理する定義）が 1 か所で定められている。コマンド文書（`runpr.md`・`fixpr.md` 等）はこれらの名前や依頼文面を直書きせず、`_context.md` を参照する。
- **AC-16**: Sourcery AI の自動の PR レビューが有効な状態で、`/runpr` が step 3 に入った時点（および `/fixpr` が新しいコミットを push した後の再確認時）に、依頼コメントがなくても PR の `head` コミット上で `sourcery-ai` の `Sourcery review` CheckRun が進行中（未完了）であれば、`/runpr` は完了または待機上限の 15 分まで待機してからスレッド処理とエスカレーションへ進む。待機上限の起点は CheckRun の開始時刻とし、開始時刻がない未開始状態では `/runpr` が待機を始めた時刻とする。祖先コミットの未完了 CheckRun では待機しない。また、15 分の上限に達して終了扱いとした同一 `head`・CheckRun については、step 4 の再読込で待機へ戻らない。
- **AC-17**: 完了の印の判定は、信頼しない入力として厳密に行う。
    - **CodeRabbit:** 利用者本人（`User`）の `@coderabbitai review` 依頼コメント後に始まった `app.slug == "coderabbitai"` の CheckRun `CodeRabbit` のうち、観測済みの完了形（`COMPLETED`・`SUCCESS`・`Finished`、`internal/fixprguard/review_state.go:44-48`）に一致するものだけを完了の印とする。
    - **Sourcery AI:** `app.slug == "sourcery-ai"` の CheckRun `Sourcery review` のうち、F-001 の観測記録に合う成功完了の形（PR #1094 時点では `COMPLETED`・`SUCCESS`・`"✅ Completed successfully"`）に一致するものを完了の印とする。利用者本人（`User`）が投稿した `@sourcery-ai review` または `@sourceryai review`（前後の空白を除いて完全一致）に応答した完了だけを完了の印に数え、依頼に応答しない自動実行の完了は数えない（自動の PR レビューの扱いは AC-16・AC-19・AC-24）。
    - どちらのレビュアーについても、同じ名前の `User` による投稿、観測した形に合わない CheckRun、PR の `head` にもその祖先にも当たらないコミットの CheckRun は完了の印に数えない。本文はセッションに出さない。
- **AC-18**: `LAST_REVIEWED` は、CodeRabbit と Sourcery AI の完了の印（AC-17。どちらも利用者の依頼に応じた PR レビューの完了だけ）の和集合から、他のすべての完了コミットを祖先とする最新のコミット（`head` に完了の印があれば `head`）とする。いずれか 1 社でも依頼に応じた PR レビューで `head` を完了していれば `LAST_REVIEWED == head` となる。Sourcery AI の自動の PR レビューが `head` を完了していても、それだけでは `LAST_REVIEWED == head` とならない。和集合が空、または他のすべてを祖先とする唯一のコミットが存在しない場合（履歴分岐・force push 等）は `none` とする。片方のレビュアーが `unreadable (limit)` の場合はもう片方の有効な完了の印から算出し、両方とも `unreadable (limit)` なら `none` とする。
- **AC-19**: Sourcery AI の自動の PR レビュー（手動依頼コメントなし）が、スキップ・割り当て切れ・失敗・未認識の形・待機上限（15 分）の時間切れで終わったとき、`/runpr` は停止せず、その実行を完了の印に数えないままマージの質問へ進み、要約にその状態と URL（本文は出さない）を示す。成功して完了した自動の PR レビューも、完了の印には数えない（AC-17）。また、`/runpr` の CI 待機はリポジトリの CI チェックのみを成否判定の対象とし、`Sourcery review` CheckRun の失敗・時間切れ・未完了を CI 失敗として `/runpr` を止めない。
- **AC-20**: 手動の PR レビューおよび複数レビュアーの異常系は、次のとおり扱う（いずれも本文はセッションに出さない）。
    - 利用者が手動で依頼した PR レビュー（CodeRabbit への `@coderabbitai review`、または Sourcery AI への `@sourcery-ai review`・手動投稿の `@sourceryai review`）が割り当て切れ・スキップ・失敗・未認識の形・待機上限（15 分）の時間切れで終わったとき、この `/runpr` の実行がその依頼を待機していた場合はレビュー済みとせずに停止し、状態・依頼コメントの URL・次の行動を示す。すでに前回の実行以前に終わっていた場合は停止せず、マージの質問の要約にその状態と依頼コメントの URL を示して進む。
    - いずれかのレビュアーについて `fixprguard review-state` が `indeterminate`（判定不能）または `unreadable (rejected)`（§3.2 項目 2）を返した場合は、もう一方の状態にかかわらず停止して報告する。`unreadable (call-failed)` は約 30 秒間隔で最大 15 分再試行し、回復しなければ停止する。`unreadable (limit)` はそのレビュアーの手動依頼を待機していた場合のみ停止し、それ以外は要約に `読めない（上限）` を示して続ける。
    - 複数のレビュー（例: CodeRabbit の手動依頼と Sourcery AI の自動の PR レビュー）が同時に進行中の場合は、すべてが完了または終了条件に達するまで待機する。応答待ちの手動依頼がある状態で `/runpr` を再実行したときは、新しい依頼を投稿せず待機から再開する。
- **AC-21**: マージの質問は、引き続き最大 4 択の単一選択（[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を保つ。「先に PR レビューを依頼」は、`head` を未レビューのレビュアー（CodeRabbit または Sourcery AI のうち、`head` に完了の印（AC-17）がないもの）が 1 社以上残っているときに 1 つの選択肢として表示し、両社とも `head` を完了済みのときは表示しない。
- **AC-22**: マージの質問の推奨（エスカレーション）は `LAST_REVIEWED` に基づく。`LAST_REVIEWED == head` のときは「未レビューの変更: なし」とし、「先に PR レビューを依頼」が表示されていても推奨は「マージ」とする。`LAST_REVIEWED` が `head` より古いコミット（`head` に達していない）または `none` のときは、Sourcery AI の自動の PR レビューが `head` を完了していても「未レビューの変更: あり」とし、要約の「未レビュー分」の行（ローカルの CLI レビューの範囲とクロスチェックの記録）を示したうえで、既存の基準（[0118 要件定義書](../0118_codex_removal/01_requirements.md) の F-005）に従い、推奨が `PR レビュー` なら「先に PR レビューを依頼」を先頭・推奨に、推奨が `マージ` なら「マージ」を先頭・推奨にする。
- **AC-23**: マージの質問で利用者が「先に PR レビューを依頼」を選んだとき、`/runpr` は直後に単一選択の 1 問で依頼先レビュアーを選ばせる。選択肢は「CodeRabbit」「Sourcery AI」「マージの質問に戻る」の 3 択とし、各レビュアーが `head` レビュー済みか未レビューかを併記する。`マージの質問に戻る` を選べば何も投稿せずマージの質問に戻る。レビュアーを選んだときは、投稿前にそのレビュアーの最新状態を確かめ、`indeterminate`・`unreadable` なら停止して報告する。すでに AC-16 の待機上限（15 分）の時間切れとして終了扱いとした同一 `head`・CheckRun がまだ進行中であれば、再待機や重複投稿をせず時間切れの状態と URL を報告してマージの質問に戻る。それ以外ですでに手動依頼が `waiting` であるか、`head` 上で自動の PR レビューが進行中であれば重複投稿せずに待機に入る。いずれにも当たらなければ、`CodeRabbit` には `@coderabbitai review`、`Sourcery AI` には `@sourcery-ai review` を 1 件だけ投稿し、完了を待ってからスレッド処理・マージの質問へ戻る。
- **AC-24**: マージの質問の要約は、CodeRabbit と Sourcery AI それぞれの PR レビュー状態（完了コミット・URL・本文に指摘や未レビューファイルがありうる旨、または割り当て切れ・スキップ・失敗・未認識・時間切れ・読めない（上限）の状態）を、本文をセッションに出さずに示す。Sourcery AI の自動の PR レビューが成功して完了したときは、その完了コミットと URL に加えて、レビュー済みには数えないことを示す。
- **AC-25**: PR を開くコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/mkplan2`・`/runplan`、単独変更の `/runpr`）は、PR を作ってから報告するまでの間、どの自動レビュアーにも PR レビューの依頼コメントを投稿しない。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

本タスクが変更または拡張する信頼できない入力の境界は、次の 4 つである。1〜3 の Go による検査では、標準ライブラリが黙って修復・破棄・無視する入力（不正な UTF-8、対になっていないサロゲート、重複メンバーの後勝ち、後続データ）を受け入れず拒否する。4 は既存の `gh api --paginate --jq` 経路を引き継ぐ例外である。

1. **GitHub API のレビュースレッドの著者（F-002）:**
   - **受け入れる形:** 既存の 0030・0033 と同じ（`__typename` が `Bot` または `User`、`login` が英数字先頭・英数字と `-` のみ・39 文字以内。`internal/fixprguard/types.go:24-25,64-74`）。自動レビュアー判定は `Bot` かつ `--reviewer` で渡された名前との大文字小文字を区別した完全一致のみとし、`[bot]` の付け外しや正規化はしない。
   - **拒否の扱い:** 一覧にない `Bot` は信頼しない理由 `other-bot` に分類する。応答の JSON 構造不正や取得失敗は `ErrResponseRejected`、スレッド上限超過は `ErrLimitExceeded`、呼び出し元の `--reviewer` 不正は `ErrInvalidInput` に写す（`internal/fixprguard/errors.go:18,41,44,68`、`types.go:54,91`）。
   - **使うメンバーと上限:** 既存の `__typename`・`login` とスレッド構造メンバーのみを使い、それ以外の GitHub API メンバーは拡張可能として無視する。権限照会の上限は 100 回（`internal/fixprguard/trust.go:19`）、スレッド件数上限は 2000 件（`internal/fixprguard/threads.go:23`）、1 スレッドあたりコメント上限は 100 件（超過は `incomplete-comments`、`threads.go:19`）、1 応答の上限は 16 MiB（`threads.go:26`）を維持する。

2. **GitHub API の PR レビュー状態（`fixprguard review-state`、F-004）:**
   - **受け入れる形:** REST（PR head・ユーザー・会話コメント・PR レビュー）と GraphQL（PR コミット・CheckSuite・CheckRun）の応答は、既存の厳格な JSON 検査（`internal/fixprguard/review_state.go:437-1049`）とサイズ上限（16 MiB、`internal/fixprguard/threads.go:26`）を通る単一のトップレベル値のみとする。CheckRun については、`checkSuite.app.slug` が対象レビュアー（`coderabbitai` または `sourcery-ai`）に完全一致し、CheckRun 名・`status`・`conclusion`・`output.title` が F-001 の観測に基づく分類表に完全一致するものだけを分類対象とする（表にない `COMPLETED` の CheckRun は完了とみなさず未認識とする）。依頼コメントは `user.type == "User"` かつ認証済み利用者の `login` と完全一致し、`body` が前後空白除去後に定義された依頼文字列（`@coderabbitai review`・`@sourcery-ai review`・`@sourceryai review`）と完全一致するものだけとする。
   - **拒否の扱い:** 呼び出し元引数の不正のみ番兵エラー `ErrInvalidInput` を返す。信頼できない入力のすべての失敗（応答不正・上限超過・呼び出し失敗）は Go の番兵エラーを返さず、`PRReviewState` の `State: RequestUnreadable`（`Reason`: `rejected`・`limit`・`call-failed`）にまとめる。その際、部分結果は使わず、本文や未検証値も出力しない（`internal/fixprguard/review_state.go:281-283,368-391`）。
   - **使うメンバーと上限:** 使うメンバーは `nameWithOwner`（リポジトリ解決）、`login`（認証済み利用者）、`id`・`user.login`・`user.type`・`body`・`created_at`・`updated_at`・`html_url`（会話コメント）、`head.sha`（PR head）、`data`・`repository`・`pullRequest`・`headRefOid`・`commits`・`nodes`・`commit`・`oid`・`checkSuites`・`app.slug`・`checkRuns`・`name`（設計で確定）・`status`・`conclusion`・`title`・`startedAt`・`completedAt`・`url`・`errors`・`pageInfo.hasNextPage`・`pageInfo.endCursor`（GraphQL）、`user.login`・`user.type`・`commit_id`・`submitted_at`・`html_url`（PR レビュー）である。これら以外の GitHub API メンバーは拡張可能として無視する。使うメンバーの欠落・型違い・重複は拒否する。固定上限はコメント 3000 件、レビュー 3000 件、PR コミット 1000 件、CheckSuite 50 件、CheckRun 100 件、応答 16 MiB、待機上限 15 分を維持する（`internal/fixprguard/review_state.go:59-67`、`threads.go:26`）。

3. **`fixprguard` の書き込み入力と `append-pr` の既存の PR の説明読み取り（F-003）:**
   - **受け入れる形:** 呼び出し元ファイル（`reply`・`edit-pr`・`append-pr`・`finish`）は通常ファイル・64 KiB 以下・非空白・NUL なし・有効な UTF-8 であり、4 つの拒否するメンションのいずれも含まないこと（`internal/fixprguard/write.go:18,28-97`）。`append-pr` が GitHub から読む既存の PR の説明は、16 MiB 以下の厳格な JSON オブジェクトで文字列の `body` メンバーをちょうど 1 つ持つこと（`write.go:385-436`、`threads.go:26`）。追記後の PR の説明も 64 KiB 以下かつ 4 つの拒否するメンションを含まないこと。
   - **拒否の扱い:** 呼び出し元ファイルの違反および追記後 64 KiB 超過は `ErrInvalidInput`、既存の PR の説明の応答不正は `ErrResponseRejected`、既存の PR の説明に 4 つの拒否するメンションのいずれかが含まれる場合は `ErrCurrentBodyMention`（停止種類 `current-body-mention`）で書き込み前に停止する（`internal/fixprguard/errors.go:18-23,95`）。
   - **使うメンバーと上限:** `append-pr` の PR の説明取得で使うメンバーは `body` のみとし、それ以外は拡張可能として無視する。上限はファイルおよび追記後の PR の説明 64 KiB、GitHub 応答 16 MiB。

4. **`/runpr` の PR メンション一覧（F-003）:**
   - **受け入れる形:** 会話コメント・行コメント・PR レビューの 3 つの REST 一覧から、`user.type`・`user.login`・`body`・`html_url`・`created_at`・`updated_at`・`submitted_at` のみを使う（それ以外は拡張可能として無視）。本文はセッションに出さない。除外する定型コメントは `user.type == "Bot"` かつ対象 Bot の REST `user.login` と完全一致し、本文 1 行目（末尾 CR を除く）が観測済みヘッダーと完全一致するものだけとする。
   - **拒否の扱い:** 終了コード非 0 または標準エラー非空の失敗は読み取り結果を破棄し、約 30 秒間隔で最大 15 分再試行して回復しなければ停止する（`.claude/commands/runpr.md:505-517`）。
   - **方針の例外:** この 3 つの一覧は 0057・0118 から引き継ぐ既存の `gh api --paginate --jq` 経路であり、`jq` は重複した JSON メンバーを黙って後勝ちにするため、`docs/dev/conventions/requirements_process.md` §1 の厳格 JSON 規則の例外となる。`interaction-limits` と `review-state` の重要判定のみ Go で厳格検査する既存方針を維持するためであり、設計で Go 化する場合はこの例外を解消する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。`--reviewer` の比較対象が 1 つから 2 つになるだけで、スレッド判定の GitHub 問い合わせ回数は増えない。`review-state` のポーリング間隔（約 30 秒、`.claude/commands/runpr.md:540`）と待機上限（15 分、`internal/fixprguard/review_state.go:59`）は既存どおりとする。

### 4.2. セキュリティ (Security)

-   条件付きのセキュリティガイド（`docs/dev/security.md`）のトリガー（`yt-dlp` の起動、LLM の API キー、キャッシュ、LLM API への送信、製品プロンプト・記事への信頼しないテキスト埋め込み）に当たる機能はない。N/A。
-   開発ツールの信頼の境界（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）を次のとおり変更し、残余リスクを `docs/dev/guides/fixprguard_guide.md` 7.2 に記録する（AC-26）。
    -   **信頼する著者の拡大:** `sourcery-ai` のスレッドは名指しなしで利用者確認前にトリアージ・修正エージェントに渡り、信頼する著者の変更範囲（同じディレクトリの `.go` 等）が適用される。本文は区切りのブロックでデータとして扱い、実行関連ファイルは常に範囲外とする。
    -   **外部の人による誘導の残余リスク:** Sourcery AI は外部の人の `@sourcery-ai`・`@sourceryai` メンションに応じうるものとして扱う。入口の守りはアカウントの `interaction-limits`（`collaborators_only`）と `/runpr` の状態確認・他アカウントメンション検出（AC-13・AC-14）に頼る。`interaction-limits` が外れている間に外部の人が指示したスレッド、および `/fixpr` を単独実行した場合の経路は、CodeRabbit と同じく残余リスクとする。
    -   **PR ブランチへの書き込み:** 現在の push の制限（ruleset、`fixprguard_guide.md` 10 章）の下で Sourcery AI が PR ブランチに push できないことを F-001（AC-01 の 8）で確かめる。push できると分かった場合、または push できないことを確かめられない場合は設計に進まず停止する（AC-04）。
    -   **投稿文面の保護:** 利用者アカウントからの投稿・コミット本文で `@sourcery-ai`・`@sourceryai` を拒否し（AC-11・AC-12）、エージェントの返信や PR の説明の更新が意図せず Sourcery AI のコマンド（`title`・`summary`・`review`・`resolve` 等）を起動するのを防ぐ。ただし Sourcery AI は自身が開始したスレッドへのメンションなし返信にもチャットとして応答しうるため（公式文書）、拒否はメンションによるコマンド起動を防ぐものにとどまる（実際の返信時の挙動は AC-01 の 9 で観測する）。
    -   **Bot の同一性:** `sourcery-ai` の判定も `__typename` と `login`（CheckRun は `app.slug`）に依存する。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   Sourcery AI の自動の PR レビューがスキップ・割り当て切れ・失敗・時間切れになっても、`/runpr` はマージの進行を止めず、要約に状態を示して利用者が判断できるようにする（AC-19）。
-   利用者が手動で依頼した PR レビューが届かない・失敗した・形が認識できない場合は、誤ってレビュー済みとせず、安全側に倒して停止し報告する（AC-20）。

### 4.4. 互換性 (Compatibility)

-   **`fixprguard` のプロトコル互換性:** `review-state` の契約が変わる場合、古いバイナリと新しい文書の組み合わせが誤動作しないよう、`CLAUDE.md` の「Protocol numbers」と `docs/dev/guides/fixprguard_guide.md` 9 章に従い、`Protocol` を `main` の値 + 1 へ引き上げるかを設計で確定する（[design_handoff.md](design_handoff.md) の H-03）。
-   **既存の CodeRabbit 手動の PR レビュー:** CodeRabbit に対する手動依頼・完了判定・割り当て切れ判定・`cr_observed` 除外の振る舞いは維持する。
-   **`chief` との互換性:** マージの質問の 4 択制約と単一選択形式を維持し、依頼先選択の質問も単一選択とすることで、`chief` の中継と読み取り（[ADR-0046](../../dev/adr/0046-chief-of-staff.md)・[ADR-0047](../../dev/adr/0047-runpr-merge-question.md)）を壊さない（AC-28）。

### 4.5. 保守性 (Maintainability)

-   自動レビュアーの一覧、拒否するメンション、PR レビュー待機対象と依頼文面は、いずれも `.claude/commands/_context.md` の 1 か所で管理し、コマンド文書に名前やメンションを散在させない（AC-08・AC-12・AC-15）。
-   `_context.md` の値と `fixprguard`・テスト・ガイドの整合は `go test -tags test` の文書ガードで機械的に検証する（AC-09・AC-31）。

## 6. 用語集 (Glossary)

用語は `docs/translation_glossary.md` と統一する。本書で使う主な用語は次のとおりである。

-   **自動レビュアー:** PR にレビューのスレッドを投稿する Bot。本タスクでは CodeRabbit（`coderabbitai`）と Sourcery AI（`sourcery-ai`）を対象とする。英語では automated reviewer。
-   **自動レビュアーの一覧:** `.claude/commands/_context.md` の `Automated reviewer list` に定める、スレッドを信頼する自動レビュアーの名前（GraphQL の `author.login` の形）の一覧。英語では automated reviewer list。
-   **信頼する著者:** リポジトリへの書き込み権限（write・maintain・admin）を持つ Bot でないアカウントと、自動レビュアーの一覧のどれかの名前の Bot。英語では trusted author。
-   **想定外の著者のスレッド:** コメントの 1 件以上が信頼する著者のものでない、または著者を確かめられないレビュースレッド。英語では untrusted thread。
-   **拒否するメンション:** 利用者のアカウントからの投稿とコミット本文に含めてはならず、`/runpr` が他アカウントからの投稿も検査する GitHub のメンション（`_context.md` の `Rejected mentions`）。本タスクで `@codex`・`@coderabbitai`・`@sourcery-ai`・`@sourceryai` の 4 つとする。用語集の「メンション」（Mattermost の通知）とは別のものである。
-   **完了の印:** PR レビューがあるコミットまで完了したことを示す、対象 GitHub App の CheckRun の値。CodeRabbit と Sourcery AI のどちらも、利用者の手動依頼に応じた完了だけを対象とする（Sourcery AI の自動の PR レビューの完了は含めない）。
-   **手動の PR レビュー:** 利用者本人の依頼コメント（`@coderabbitai review`・`@sourcery-ai review`、または手動投稿の `@sourceryai review`）で始まる PR レビュー。
-   **自動の PR レビュー:** 依頼コメントなしで、PR 作成や push に応じて Sourcery AI の GitHub App が自動で実行する PR レビュー。
-   **割り当て:** 自動レビュアーが一定時間に受け付けるレビューの回数の上限。英語では quota。
