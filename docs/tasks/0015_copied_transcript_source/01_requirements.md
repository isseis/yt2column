## 1. 概要 (Overview)

**目的:** 本書は、利用者が YouTube の「文字起こしを表示」パネルからコピーした字幕の文字列を解析し、`transcript.Transcript` にする `TranscriptSource` の要件を定義する。

**背景:**
`yt-dlp` による字幕の取得は、YouTube から HTTP 429 を繰り返し受けることがある（[#43](https://github.com/isseis/yt2column/issues/43)）。そこで、字幕の取得を利用者に任せ、利用者が YouTube の文字起こしパネルで選択・コピーした字幕の文字列を、ブラウザ拡張が localhost のサーバへ送り、サーバが記事を生成して Slack へ投稿する方式にした（[#104](https://github.com/isseis/yt2column/issues/104)）。

#104 は、本タスク（コピーした字幕のパーサと `TranscriptSource`、[#107](https://github.com/isseis/yt2column/issues/107)）、失敗を Slack へ投稿する仕組み（[#108](https://github.com/isseis/yt2column/issues/108)）、サーバ本体と API（[#109](https://github.com/isseis/yt2column/issues/109)）に分かれている。本タスクは、#109 が定義する HTTP API が受け取る字幕の文字列を、既存のパイプライン（`ArticleWriter`・`Publisher`）で使える `Transcript` に変換する部分を担う。

`0011_localhost_server/02_architecture.md` §3.7 が、#109 の設計として本タスクの `TranscriptSource` に求める契約（入力の型、解析の時点、番兵エラー、`VideoURL` の導出、メタデータの扱い、上限と計算量）を定めている。名前は本タスクで変えてよいが、性質は守る。本タスクは同節を起点にする。

対応 issue: #107（親: #104、#43）。後続: #109。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   利用者が実際にコピーした字幕の文字列を集め、その書式を明示的に定義する（F-001）。
-   定義した書式を解析し、`transcript.Transcript` にするパーサを実装する。書式に合わない入力は補正せずに拒否する（F-002）。
-   受け取った字幕から `Transcript` を作る新しい `TranscriptSource` を実装する（F-003）。
-   受け取った文字列の中身を解析する点を、CLAUDE.md「Declare, don't infer」の例外として、範囲と理由つきで文書化する（F-004）。

### 2.2. スコープ (In Scope)

-   事前調査: 実際にコピーした字幕の文字列を集めて書式を列挙し、`testdata/` に保存する（F-001）。
-   字幕書式の定義と、その書式を解析するパーサ（F-002）。`internal/transcript` に置く。
-   コピーした字幕から `Transcript` を作る `TranscriptSource` の実装（F-003）。
-   CLAUDE.md への例外の記載（F-004）。
-   `testdata/README.md` への出典・ライセンス・取得方法の記載（F-001）。

### 2.3. スコープ外 (Out of Scope)

-   localhost サーバ本体、HTTP API の定義、安全性の対策、応答の仕方（#109）。
-   ブラウザ拡張が選択範囲を取得・送信する部分（#110・#111）。
-   失敗を Slack へ投稿する仕組み（#108）。
-   `yt-dlp` による字幕の取得、json3・info.json の解析、キャッシュ（既存の `YtDlpSource`）。本タスクはそれらを変更しない。
-   字幕の本文の整形・要約・翻訳。書式に合わない入力の補正（行の折り返しの結合、句読点の付与、空白の正規化など）は行わない。
-   形 A と形 B の相互変換。両方を「文字起こしパネルの出力」としてそれぞれ定義し、どちらも解析するが、一方から他方へ変換・正規化はしない（CLAUDE.md「Reject, don't normalize」）。
-   ライブ配信・プレミア公開の動画。利用者が視聴中の通常の動画（VOD）の文字起こしをコピーする用途だけを対象とし、ライブ配信・プレミア公開は対象にしない（F-001 の列挙の対象からも除く）。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 事前調査と書式の定義

-   実際に YouTube の文字起こしパネルからコピーした字幕の文字列を、**複数の動画で集めて書式を列挙する**。パネルの書式が動画によって異なる（少なくとも 2 つの形がある）ことが分かっているので、少なくとも次の組み合わせを 1 本ずつ調べる。
    -   字幕の言語と種類の組み合わせ: 日本語の自動・日本語の手動・英語の自動・英語の手動（手動のサンプルが得られない場合は、得られなかったことを記録する）。
    -   長さ: 1 時間未満・1 時間以上（`h:mm:ss`。`nv94SmoSPQA` で `2:10:26` を確認済み）。
    -   ブラウザ: Chrome・Brave（書式が変わるかを記録する）。
    -   YouTube の表示言語: 日本語・英語（形 A の画面読み上げ用のラベルは字幕の言語ではなく表示言語に従う。確認済み。日本語 UI で `24 秒`、英語 UI で `24 seconds`）。
-   各書式について、次を記録する。時刻・本文の並び（1 セグメントが 1 行か、時刻と本文が別の行か）、画面読み上げ用の所要時間のラベルの有無と形、時刻の文法、行の区切り、空行の有無、本文の行数、前後の空白や末尾の改行、先頭・内部に混じる表示項目（`タイムライン`・`文字起こし`・`動画内を検索` など）。
    -   書式は、動画ごとの属性（動画 ID・字幕の言語・自動/手動・長さ・ライセンス・ブラウザ・YouTube の表示言語）とともに 02_architecture.md の表にまとめる。
    -   長い動画でパネル全体を選択できるか（選択できる長さの上限を含む）と、選択できない場合に利用者が取れる手段も記録する。
-   列挙した書式のうち、**パーサ（F-002）が受理する書式を形 A と形 B の 2 つに確定する**（AC-02）。列挙で、この 2 つのどちらにも一致しない書式が見つかった場合は、本書を改訂する。
-   集めた文字列は `testdata/` に保存する。[security.md](../../dev/security.md) §7 の条件に従い、再配布が許諾されたライセンスの動画からのものだけを保存し、取得者を特定できる情報を取り除く。出典・ライセンス・取得日・取得方法・加工内容を `testdata/README.md` に記録する。
    -   調査に使った動画が再配布不可のライセンス（標準の YouTube ライセンス）の場合、その文字列は書式の確認にだけ使い、`testdata/` には保存しない。保存する実データは再配布可能なライセンスの動画（既存の `testdata/` の CC BY 3.0 の動画など）から取る。
-   調査で確定した書式を 02_architecture.md に明記する。書式の定義は、パーサ（F-002）が受理する形の唯一の根拠となる。

**Acceptance Criteria**:
- **AC-01**: 再配布可能なライセンス（CC BY など）の動画で、文字起こしパネルからコピーできるものの、実際にコピーした文字列が `testdata/` に保存され、`testdata/README.md` に出典・ライセンス・取得日・取得方法・加工内容が記録されている。security.md §7 を満たす（取得者を特定できる情報を除去）。**形 A と形 B の両方のサンプルを含む**（形 A は `IkngpxCMmRQ`、形 B は `Yoboo9g7saY`。どちらも CC BY）。サンプルは、**セグメントの行だけ**を含み、先頭の見出し（`タイムライン`・`文字起こし`・`動画内を検索`／`文字音声変換を検索`）とチャプターの見出しの行を含まない（チャプターのない動画を選ぶ）。既存の `testdata/` の CC BY 3.0 の動画 `2tcCWM-sRBw` は YouTube 側で文字起こしを取得できなくなっているため、別の動画を選ぶ。
- **AC-01a**: 1 時間を超える動画の時刻の表記（`h:mm:ss`）を確認する（`nv94SmoSPQA` で `2:10:26`、形 B の `mbyG85GZ0PI` で `1:00:07` を確認済み）。
- **AC-01b**: 複数の動画でコピーした書式を列挙した表が 02_architecture.md にある。表は、動画ごとに 動画 ID・字幕の言語・自動/手動・長さ・ライセンス・ブラウザ・YouTube の表示言語 と、観測した書式（時刻・本文の並び、読み上げ用ラベルの有無と形、時刻の文法、行の区切り、空行、本文の行数、前後の空白と末尾の改行、先頭・内部に混じる表示項目）を含む。日本語の自動・日本語の手動・英語の自動・英語の手動のうちサンプルが得られなかったものは、得られなかったことを記録する。
- **AC-02**: パーサ（F-002）が受理する書式は、形 A と形 B の 2 つとする（どちらも明示的に定義し、両方を受理する）。AC-01b の列挙で得た各動画の書式が、この 2 つのどちらかに一致する。定義は 02_architecture.md に明記する。`testdata/` の各ファイルが定義した書式に一致する（静的な確認）。形 A・形 B のどちらにも合わない入力は、誤りとして拒否し、利用者に分かる案内を出す。
- **AC-03**: 長い動画でパネル全体を選択できるか（選択できる長さの上限を含む）と、選択できない場合に利用者が取れる手段が 02_architecture.md に記録されている。

#### F-002: 字幕書式のパーサ

-   パーサは、`internal/transcript` に置き、F-001 で定義した書式を解析して `transcript.Transcript` の `Segments` を組み立てる。
-   書式を明示的に定義して解析する。書式に合わない入力は補正せずに拒否する（CLAUDE.md「Reject, don't normalize」）。
-   受理する書式は、次の 2 つ（形 A・形 B）とする。事前調査（F-001）で、パネルの書式が動画によってこの 2 つに分かれることが分かった。**字幕の言語・自動/手動では説明できない**（日本語の自動 `BkaUHsH_mkw` が形 B、日本語の自動 `nv94SmoSPQA`・`IkngpxCMmRQ` が形 A）。観測では、パネルの検索欄のラベルと相関している（`文字音声変換を検索`＝形 A、`動画内を検索`＝形 B）ので、YouTube のパネルの UI 変種（A/B テストや、動画・ページごとの配信の差）とみられる。同じブラウザ（Brave）でも動画によって形が変わるので、ブラウザの差ではない（同じ動画は Chrome でも Brave でも同じ形になることを確認済み）。**どちらの形も「文字起こしパネルの出力」として明示的に定義し、両方を受理する。** 1 つの入力は、形 A か形 B のどちらか一方として解析する（2 つの形が混在する入力は拒否する）。
    -   **形 A（`nv94SmoSPQA`・`IkngpxCMmRQ`・`LR6mhKRKX9Q` で観測）:** 1 セグメントが 1 行で、`<時刻>`、画面読み上げ用の所要時間のラベル、本文が、区切り文字なしで連結されている。例: `<時刻>` `0:24` の直後に `24 秒` が続く。パネルの DOM では時刻・読み上げ用ラベル・本文が別の要素であり、コピー時に連結されるために起こる（DevTools で確認）。
    -   **形 B（`Yoboo9g7saY`・`W6srShxBCrk`・`mbyG85GZ0PI`・`BkaUHsH_mkw`・`9nx455-_h68` で観測）:** `<時刻>` の行と本文の行が分かれ、画面読み上げ用のラベルを含まない。時刻は `m:ss`・`mm:ss`・`h:mm:ss`（`1:00:07` を確認）。本文が空の時刻の行もある。
    -   セグメントの先頭に来るべき行（形 A の各行、形 B の時刻の行の位置にある行）が時刻で始まらない場合、その行はセグメントではないため拒否する。これには、文字起こしパネルの直前の表示項目（`タイムライン`・`文字起こし`・`動画内を検索`／`文字音声変換を検索` など）と、セグメントの間に差し込まれるチャプターの見出し（`BkaUHsH_mkw` の `存在感のある声` など）の両方を含む。
    -   時刻は `m:ss`・`mm:ss`・`h:mm:ss` とする（確認済み）。例: `0:24`、`10:08`、`1:00:07`、`2:10:26`。
    -   形 B の本文の行は、時刻の文法に一致する文字列（例: `1:30`）で始まりうる。時刻の行と本文の行をどう区別するか（本文が空の時刻の行との組み合わせを含む）を 02_architecture.md で定め、区別できない入力は推測で受理せずに拒否する。ただし、次の 2 つの場合は、区別できないが特別には拒否せず、形 B の通常の規則で解析する。本文が空の時刻の行が実在し（`mbyG85GZ0PI`）、これらを特別に拒否すると正しい入力も拒否するためである。
        -   本文の行が時刻の文法だけの文字列（例: `1:30`）の場合。その行は時刻の行として扱い、本文は失われる。この時刻にも時刻の順序の規則が適用され、前後の時刻と矛盾すれば拒否される。
        -   本文が空の時刻の行の直後に、チャプターの見出しがある場合。見出しは、その時刻の本文になる。
    -   形 A の読み上げ用ラベルは、**YouTube の表示言語に従う**（字幕の言語ではない。日本語 UI で `24 秒`、英語 UI で `24 seconds` を確認済み）。**日本語 UI と英語 UI の両方を受理する。** どちらも 0 の単位を省く（例: `1:00` は日本語 UI で `1 分`、英語 UI で `1 minute`。`1:00:30` は `1 時間 30 秒`・`1 hour, 30 seconds`）。ただし、すべての単位が 0 の時刻（`0:00`）は秒を残す（日本語 UI で `0 秒`、英語 UI で `0 seconds`。`LR6mhKRKX9Q` で確認済み）。
        -   日本語 UI: 単位を空白で区切る。`N 秒`・`N 分`・`N 分 N 秒`・`N 時間 …`。例: `0 秒`（`0:00`）、`3 秒`、`11 秒`、`1 分`（`1:00`）、`1 分 6 秒`、`5 分 12 秒`、`1 時間 9 分`（`1:09:00`）、`2 時間 10 分 26 秒`。
        -   英語 UI: 単位を `, `（カンマと空白）で区切る。`N second(s)`・`N minute(s)`・`N hour(s)` …（単数・複数は数に従い、0 は複数形）。例: `0 seconds`（`0:00`）、`1 second`、`24 seconds`、`1 minute`、`1 minute, 6 seconds`、`1 hour, 9 minutes`（`1:09:00`）、`2 hours, 10 minutes, 26 seconds`（`IkngpxCMmRQ`・`nv94SmoSPQA` を英語 UI で確認済み）。
    -   ラベルは直前の時刻から一意に決まる。パーサは、時刻から日本語 UI・英語 UI それぞれのラベルを導き、行のラベルがどちらかと一致することを確かめ、一致しない行を拒否する（本文が数字や `秒`・`seconds` などで始まる場合に、ラベルと本文の境界を推測しないため）。
    -   日本語 UI・英語 UI のどちらでもないラベルは拒否する（対象外。README などで「YouTube の表示言語を日本語か英語にする」と案内する）。
    -   **本文が空のセグメント:** セグメントの本文が空の場合（形 B で時刻の行の直後が次の時刻の行か入力の終わりである場合、形 A で `<時刻><ラベル>` までで本文が無い場合）は、そのセグメントを作らない（`Segments` に含めない）。受理して読み飛ばす。入力全体で本文のあるセグメントが 1 つも無い場合は、空の字幕として拒否する（CLAUDE.md「Empty is an error」）。
    -   本文には `[拍手]`・`[笑い]` などの角括弧の表記を含みうる。
    -   **チャプターの見出しの行:** 文字起こしパネルは、動画のチャプターの見出しを、セグメントの間に時刻のない行として差し込むことがある（形 B の `BkaUHsH_mkw` で `存在感のある声`・`ストレスのリズムの安定`・`間を大切にする`、形 B の `9nx455-_h68` で `What is symmetry in physics?` など 7 行、形 A の `LR6mhKRKX9Q` で `チャプター 2: 通常スピード` を観測）。パネルに見えていない見出しも、選択範囲に含まれてコピーされる（`BkaUHsH_mkw`・`9nx455-_h68` で確認）。これはセグメントではないので拒否する（本文が空の時刻の行の直後にある場合を除く。前項）。位置で見出しを推測して無視する形にはしない。拡張（#111）は、選択範囲をそのまま送り、見出しを除かない（[security.md](../../dev/security.md) §8.1 のとおり、ページの DOM の構造に依存しない）。見出しを含めないことは、利用者への案内で求める。
-   形 A・形 B のどちらにも合わない入力（時刻で始まらない行、時刻・ラベル・本文の連結が規約と異なる行、宣言していない種類の行、2 つの形の混在、空、空白のみ、本文のあるセグメントが 1 つも無い入力、など）は補正せずに拒否する。
-   解析は、`NewCopiedSource`（F-003）の構築の中で行う。`Fetch` は解析済みの値を返すだけにする（0011 §3.7。書式の誤りを `202` の前に `400` で返すため）。
-   解析の時間とメモリは入力の長さに比例させる。サーバの本文の上限（4 MiB。`0011_localhost_server/02_architecture.md` §3.5.3。[design_handoff.md](../0011_localhost_server/design_handoff.md) H-01 が決め方を定める）の入力で確かめる。
-   書式の誤りのエラーは、番兵 `ErrCopiedTranscriptFormat`（`errors.New` で作る。名前は変えてよい）を包む。エラーメッセージに入力の字幕の文字列を含めない（行番号まではよい）。
-   入力は有効な UTF-8 とする。無効な UTF-8 を含む入力を拒否する。
-   **行の区切り:** 1 つの入力の中で、行の区切りはすべて LF（`\n`）か、すべて CRLF（`\r\n`）のどちらかとする。どちらも受理し、同じ `Segments` にする。LF と CRLF が混在する入力と、CRLF の一部でない CR を含む入力は拒否する（混在を黙って揃えない。CLAUDE.md「Reject, don't normalize」）。F-001 の調査で得た文字列はすべて LF だったが、Windows のクリップボードを経由した文字列は CRLF になるため、書式の一部として定義する。
-   **入力の末尾:** 末尾の行の区切りは 0 個か 1 個まで受理する（F-001 の調査で得た文字列は末尾に改行が無く、AC-04a の例は末尾に改行が 1 つある）。2 個以上続く場合は空行として拒否する。

**Acceptance Criteria**:
- **AC-04**: `testdata/` の実データを正しく解析し、期待する `Transcript.Segments`（各要素の `StartMs` と `Text`）にする。
- **AC-04a**: 本文が空のセグメントは `Segments` に含めない。例: 形 B の入力 `0:00\n0:05\nこんにちは\n` を解析すると、`Segments` は `StartMs` が 5000 で `Text` が `こんにちは` の 1 つだけになる（`0:00` の時刻の行からはセグメントを作らない）。本文のあるセグメントが 1 つも無い入力（例: `0:00\n0:05\n`）は `ErrCopiedTranscriptFormat` を包むエラーで拒否する。
- **AC-04b**: 形 A の読み上げ用ラベルは、日本語 UI（`24 秒`）と英語 UI（`24 seconds`）の両方を受理する。例: `0:2424 secondsHello` を解析すると `StartMs` が 24000 で `Text` が `Hello` の 1 セグメントになる。`1:251 minute, 25 secondsHello` は `StartMs` が 85000 で `Text` が `Hello`。`0:000 秒Hello` は `StartMs` が 0 で `Text` が `Hello`。カンマのない `1:251 minute 25 secondsHello` は拒否する。どちらの言語のラベルとも一致しない行（例: `0:24abc…`）は `ErrCopiedTranscriptFormat` を包むエラーで拒否する。
- **AC-05**: 書式に合わない入力（時刻で始まらない行、時刻の文法が不正な行、時刻と画面読み上げ用のラベルの連結が規約と異なる行、時刻と一致しない読み上げ用のラベル、宣言していない種類の行が混じる、形 A と形 B が混在する、空、空白のみ、本文のあるセグメントが 1 つも無い入力、など。文字起こしパネルの直前の表示項目だけを含む入力を含む）を拒否し、補正しない。拒否のエラーは `ErrCopiedTranscriptFormat` を包む（`errors.Is` が真）。
- **AC-06**: 拒否のエラーとそのメッセージに、入力の字幕の文字列（本文・メタデータ）を含めない。行番号は含めてよい。
- **AC-07**: 無効な UTF-8 を含む入力、および空白文字以外の文字を 1 つも含まない入力を拒否する。
- **AC-07a**: 行の区切りが CRLF の入力を、同じ内容で区切りが LF の入力と同じ `Segments` にする（例: `0:05\r\nこんにちは` と `0:05\nこんにちは`）。末尾の行の区切りが 0 個の入力と 1 個の入力を、どちらも受理して同じ `Segments` にする。LF と CRLF が混在する入力、CRLF の一部でない CR を含む入力、末尾に行の区切りが 2 個以上続く入力は `ErrCopiedTranscriptFormat` を包むエラーで拒否する。
- **AC-08**: サーバの本文の上限と同じ大きさ（4 MiB）の入力で解析が完走する。解析の時間とメモリは入力の長さに比例する（大きさに対して非線形に増えない）。

#### F-003: コピーした字幕から `Transcript` を作る `TranscriptSource`

-   `transcript.TranscriptSource`（`internal/transcript/transcript.go:26-28`）を実装する新しい型を `internal/transcript` に置く。0011 §3.7 の契約に従う。
-   入力の型は、次の値を持つ（名前は変えてよい。0011 §3.7）。
    -   `VideoID`: 呼び出し側が `transcript.ValidateVideoURL` で検証済みの動画 ID。
    -   `Raw`: コピーした字幕の文字列。補正しない生の値。
    -   `Title`・`ChannelName`・`Description`: メタデータ。
-   構築の時点で `Raw` を解析する。書式が合わなければ `ErrCopiedTranscriptFormat` を包むエラーを返す。`VideoID` が `transcript.NormalizedVideoURL` で正規化 URL を導けない値なら、`ErrCopiedTranscriptFormat` を包まないエラーを返す（呼び出し側の誤りであり、サーバは `reasonInternal` に対応させる。0011 §3.7）。`Fetch` は解析済みの `Transcript` を返すだけにする。
-   返す `Transcript` の `VideoID` は入力の `VideoID`、`VideoURL` は `VideoID` から `transcript.NormalizedVideoURL` で導出した正規化 URL とする。リクエストの URL 文字列をそのまま使わない。
-   `Fetch(ctx, videoURL)` は、`videoURL` が導出した正規化 URL と一致するときだけ `Transcript` を返し、一致しなければエラーを返す。
-   `Title`・`ChannelName`・`Description` は、入力の値をそのまま `Transcript` に入れる（空を許す）。
-   1 つの source は 1 つのジョブだけが使う（サーバはリクエストごとに source を作る。0011 §3.7）。`Fetch` の並行の呼び出しは考えない。

**Acceptance Criteria**:
- **AC-09**: 書式に合う `Raw` から新しい source を作ると成功し、書式に合わない `Raw` では `ErrCopiedTranscriptFormat` を包むエラーを返す。`transcript.NormalizedVideoURL` が拒否する `VideoID` では、`ErrCopiedTranscriptFormat` を包まないエラーを返す。`Fetch` は解析をやり直さず、構築時に得た `Transcript` を返す。
- **AC-10**: `Fetch(ctx, videoURL)` は、`videoURL` が入力の動画 ID の正規化 URL（`transcript.NormalizedVideoURL`）と一致するときだけ `Transcript` を返し、一致しなければ（空文字列、別の動画の URL、正規化されていない URL を含む）エラーを返す。
- **AC-11**: 返る `Transcript` の `VideoID` は入力の `VideoID` と一致し、`VideoURL` は `VideoID` から導出した正規化 URL と一致する。入力の別の文字列が `VideoURL` にそのまま入ることはない。
- **AC-12**: 返る `Transcript` の `Title`・`ChannelName`・`Description` は、入力の値とそのまま一致する（空の場合を含む）。
- **AC-13**: 返る `Transcript` の `Segments` は、F-002 のパーサが F-001 の書式に従って `Raw` から作った値と一致する。

#### F-004: CLAUDE.md への例外の記載

-   CLAUDE.md の「Declare, don't infer」に、例外として、受け取った字幕の文字列の中身を解析することを明記する。次を含む。
    -   **範囲:** 解析するのは、コピーした字幕の書式（形 A・形 B の、時刻の文法、ならびに時刻・読み上げ用ラベル・本文の並び）に限る。この解析でセグメントの境界と `Segments` を組み立てる。解釈（推測）で振る舞いを選ぶのはこの範囲に限る。
    -   **理由:** この文字列は、YouTube の文字起こしパネルが生成し、利用者がコピーした外部の値であり、呼び出し側（拡張・サーバ）が型で表現できない。書式は YouTube の UI の契約であり、こちらが型を変えても入力は変わらない。
    -   **境界:** この例外は、コピーした字幕のパーサと `TranscriptSource` の `Raw` の解析だけに限る。書式に合わない入力は、解釈を広げて受理せずに拒否する。

**Acceptance Criteria**:
- **AC-14**: CLAUDE.md に、上記の範囲・理由・境界が記載されている（静的な確認）。

### 3.2. 信頼できない入力の境界 (Untrusted Input Boundaries)

コピーした字幕の文字列（`Raw`）は、利用者が選択した値であり、信頼できない入力である（[security.md](../../dev/security.md) §6）。本タスクのパーサは、この値の境界でもある。

| 境界 | 受理する形 | 上限 | 拒否時の理由 | 主な AC |
|---|---|---|---|---|
| `Raw`（コピーした字幕） | 有効な UTF-8。行の区切りはすべて LF かすべて CRLF（末尾は 0 個か 1 個）。形 A（1 セグメント 1 行で `<時刻><画面読み上げ用のラベル><本文>` が区切り文字なしで連結）または形 B（`<時刻>` の行と本文の行）のいずれかに一致（F-002）。空白文字以外の文字を 1 つ以上含む | なし（本パーサは独自の上限を設けない。呼び出し側のサーバが本文を 4 MiB で拒否する。0011 H-01） | `ErrCopiedTranscriptFormat` を包むエラー | AC-05・AC-06・AC-07・AC-07a |
| `VideoID` | 呼び出し側が `transcript.ValidateVideoURL` で検証済みの 11 文字の `[A-Za-z0-9_-]` | なし | 検証は呼び出し側の責務。ただし `NewCopiedSource` は `transcript.NormalizedVideoURL` が拒否する値を、`ErrCopiedTranscriptFormat` を包まないエラーで拒否する | AC-09・AC-11 |
| `Title`・`ChannelName`・`Description` | 任意の文字列（空を許す）。値としてそのまま `Transcript` に入れる | なし | なし（本タスクは検査しない） | AC-12 |

標準ライブラリが黙って修復・破棄・無視すれば受理できてしまう入力は、受理せず拒否する。補正しない。拒否した場合、部分的な結果を返さない（`Segments` の一部だけを返さない）。

無効な UTF-8 の扱いについて: `Raw` はサーバでは `strictjson` の検査を通過した JSON の文字列として届き、その時点で有効な UTF-8 である（0011 AC-13）。本パーサは単体でも使われるため、`Raw` が有効な UTF-8 であることを前提にせず、無効なら拒否する。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   解析の時間とメモリは、入力の長さに比例する。入力の大きさに対して非線形に増えない。
-   サーバの本文の上限（4 MiB）の入力で、サーバの `WriteTimeout` の中で完走する（0011 §3.7）。
-   `Fetch` は解析をやり直さない（構築時に 1 回だけ解析する）。

### 4.2. セキュリティ (Security)

-   コピーした字幕・メタデータは、プロンプトに埋め込まれる信頼できない入力として扱う（security.md §6）。生成結果を他のコマンドやコードとして実行しない。
-   エラーメッセージに、入力の字幕の文字列（本文・メタデータ）を含めない。行番号は含めてよい（0011 AC-24 と整合）。
-   番兵 `ErrCopiedTranscriptFormat` を使い、呼び出し側が型で拒否の理由を判定できるようにする（CLAUDE.md「Declare, don't infer」）。
-   `testdata/` に保存する実データは、security.md §7 に従う。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   パーサと `TranscriptSource` は決定的である。同じ入力に対して同じ結果を返す。
-   拒否した場合、部分的な結果を返さない。例外を投げない。
-   ネットワークにも `yt-dlp` にも触れない。パーサと `TranscriptSource` は入力の文字列だけで決まる（#104 の依存「なし」を満たす）。

### 4.4. 互換性 (Compatibility)

-   Go の標準ライブラリだけで実装する。外部ライブラリを追加しない。
-   macOS と Linux で同じ振る舞いをする（OS 依存の処理を持たない）。

### 4.5. 保守性 (Maintainability)

-   パーサと `TranscriptSource` は `internal/transcript` に置き、既存の json3・info.json のパーサと同じ規約（番兵エラー、上限、計算量、テストの置き方）に従う。
-   `transcript.Transcript`・`transcript.Segment` の exported フィールドを変更しない（`internal/pipeline` の `TestCommonTypesFieldSets` が固定している。0011 の制約と同じ）。
-   公開する型と関数は、#109 §3.7 が必要とするものに限る。使われない拡張点を先回りして公開しない（CLAUDE.md「Enforce invariants with the type」）。

## 5. 制約条件 (Constraints)

-   [project_overview.md](../../dev/project_overview.md) の「決定済みの方針」「前提・制約」と CLAUDE.md に従う。外部ライブラリを追加しない。
-   依存: なし。HTTP もネットワークも使わないため、他のタスクと並行して進められる（#107）。
-   本タスクは、`0011_localhost_server/02_architecture.md` §3.7 の契約（`CopiedInput`、`NewCopiedSource`、`Fetch`、`ErrCopiedTranscriptFormat` の性質）に従う。名前は変えてよいが、性質は変えない。性質を変える場合は #109 に知らせ、#109 の設計書の修正と再承認を要する。
-   `transcript.Transcript` の `Segments` への入れ方（時刻を `StartMs` に保持し、本文を `Text` に入れること）は、F-002 の書式の定義とあわせて 02_architecture.md で確定する。`StartMs` の単位は既存の `Segment.StartMs`（ミリ秒）に合わせる。
-   実際に使うブラウザと YouTube の表示言語は、事前調査（F-001）で使った条件を 02_architecture.md に記録する。形 A の読み上げ用ラベルは YouTube の表示言語に従うので、**受け付けるのは日本語 UI と英語 UI のラベル**とする（それ以外の表示言語のラベルは拒否し、README などで案内する）。表示言語や YouTube の UI が変わって形 A・形 B 以外の書式になった場合は、本タスクの範囲では補正せず、書式の再定義（F-001）として扱う。

## 6. 用語集 (Glossary)

-   **コピーした字幕 / 生の字幕:** 利用者が YouTube の「文字起こしを表示」パネルで選択・コピーした文字列。形 A と形 B の 2 つがある。補正しない。
-   **形 A:** 1 セグメントが 1 行で、時刻・画面読み上げ用の所要時間のラベル・本文が区切り文字なしで連結された書式。ラベルは YouTube の表示言語に従い、日本語 UI・英語 UI を受理する。
-   **形 B:** 時刻の行と本文の行が分かれた書式。
-   **時刻の行:** パネルの各セグメントの先頭に表示される時刻（例: `0:04`、`1:02:03`）。
-   **本文の行:** 時刻の行に続く、そのセグメントの本文（形 B）。
-   **字幕書式:** コピーした字幕の取り決め（形 A・形 B の、時刻の文法、時刻・ラベル・本文の並び、行の区切りなど）。F-001 で定義する。
-   **`CopiedSource` / `CopiedInput`:** 本タスクで実装する `TranscriptSource` の型とその入力（0011 §3.7。名前は変えてよい）。
-   **`ErrCopiedTranscriptFormat`:** 字幕の書式に合わない入力を拒否するときに包む番兵エラー。
-   **メタデータ:** `Title`・`ChannelName`・`Description`。
-   用語は [translation_glossary.md](../../translation_glossary.md) と統一する。
