## 1. 概要 (Overview)

**目的:** 本書は、chief（[0088 要件定義書](../0088_chief_of_staff/01_requirements.md)）がリセット（Claude Code の pane への `/clear`、OpenCode の pane への `/new`）を、報告が読めないために見送ったとき、そのリセットを人の選択肢として示し、人が選んだときだけ送るための要件を定義する。

**背景:**

chief は、次の 2 つの場面で pane をリセットする。

| 記号 | 場面 | 空にする pane | 今の実装 |
|---|---|---|---|
| ① | `/runpr` を送った後（0088 要件定義書の AC-52） | PR を作ったコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/runplan`）が走った pane | `internal/chief/reset.go:94-143` |
| ② | マージの後の自動送信で次のコマンドを送った後（同 AC-53） | `/runpr` が走った pane | `internal/chief/autosend.go:728-777` |

どちらも、そのコマンドの報告が pane の最後の報告として残っていることを、リセットの条件の 1 つにしている（[ADR-0046](../../dev/adr/0046-chief-of-staff.md) の決定）。報告を確かめられないときは `no_report` で見送る（①は `internal/chief/reset.go:118-120`・`internal/chief/reset.go:135-137`、②は `internal/chief/autosend.go:769-771`）。

報告は画面から読むので、画面より長い報告は読めない（[chief 利用ガイド](../../dev/guides/chief_guide.md) の「8. 既知の制限」の「長い報告は画面から読めない」）。また、PR を作ったのが OpenCode の pane のときは、人の最後の入力を確かめる記録がないため、①は必ず `no_report` で見送られる（`internal/chief/reset.go:52-54`）。

issue #919 によれば、2026-11-16〜17 の chief のセッションでは、②の OpenCode の `/new` が 3 回とも `no_report` で見送られた。①の Claude Code の `/clear` は 9 回のうち 5 回が見送られ、内訳は `no_report` 4 回、`other_input` 1 回だった。見送られた pane は前のコマンドの文脈を持ったまま残る。人は手で空にするか、そのまま pane を使い続けることになる。

①の Claude Code の pane の報告を transcript から読むことは、タスク [0095](../0095_chief_transcript_report/01_requirements.md)（[#905](https://github.com/isseis/yt2column/issues/905)）が扱う。OpenCode の pane の報告は [#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907) が扱う。本書の選択肢はそれまでのつなぎであり、その後も、報告が読めないときの受け皿として残る。

対応 issue: [#919](https://github.com/isseis/yt2column/issues/919)（親: [#902](https://github.com/isseis/yt2column/issues/902)、関連: [#892](https://github.com/isseis/yt2column/issues/892)・[#905](https://github.com/isseis/yt2column/issues/905)・[#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907)）

**本書の記述範囲:** 本書は、どの見送りを選択肢にするか、選択肢に何を示し、いつ消すか、人が選んだときに何を確かめて送るか、という観測できる振る舞いを定める。見送りの記録の形、人の選択を道具に渡す口、確かめの値の作り方は、設計（[02_architecture.md](02_architecture.md)）で決める。

**issue #919 で決めたこと:**

-   **リセットが `no_report` で送られなかったとき、chief の選択肢に「リセットを送る」項目を加える（F-001）。** 人の会話を守るというリセットの条件のねらいは保ったまま、報告が読めないだけで pane が文脈を持ち続けることをなくすためである。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する。
-   **人が選んだとき、その時点で送ってよいかを確かめ直してから送り、結果をほかの送信と同じ形で示す（F-002）。** 選んでから送るまでの間に、人が pane を使い始めることがあるためである。ADR: ADR-0046 を更新する。
-   **`other_input`（人の入力があった）で見送ったリセットは、選択肢にしない。** 人が同じ pane で始めた会話を守る規則なので、これまでどおり送らない。ADR: ADR-0046 を更新する（採らなかった案に書く）。
-   **判定の情報源を transcript や OpenCode の API に移すことは扱わない。** #905・#906・#907 が扱うためである。ADR: なし（作業の分け方で、決定を変えないため）。

**要件定義の際に決めたこと（2026-11-17）:**

-   **進め方は簡易な進め方にする。対象外の判断は「対象外」で、人がそれを上書きした。** この変更は、chief が pane に入力を送る条件を変える。これは開発用の道具の信頼の境界に触れるので、簡易な進め方の対象外と判断した（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Simple Process」の「Excluded changes」）。人は、変える範囲が chief の 2 か所のリセットに限られ、送る入力の種類（`/clear`・`/new`）も増えないことから、判断を上書きして簡易な進め方を選んだ。ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
-   **選択肢にするのは `no_report` の見送りのすべてとする。PR を作ったのが OpenCode の pane で、人の入力の記録がないために見送った①も含める（AC-01）。** どちらも、人が pane を見て決めれば足りるためである。エージェントの種類で分けると、OpenCode の pane が PR を作ったときは、①が一度も行われないまま残る。報告が読めない場合だけに限る案は採らない。ADR: ADR-0046 を更新する。
-   **見送ったときに、報告以外の条件をすべて満たしていた見送りだけを選択肢にする（AC-02）。人が選んだときは、送る直前に条件を確かめ直す（AC-08）。** 選択肢に出すのは、報告が読めないことだけが理由の見送りに限る。そうでないと、人が同じ pane で始めた会話を守る確かめ（`other_input` など）を、人の選択で越えることになる。見送りを `no_report` で選択肢に出しておいて、送る直前にだけ確かめる案は採らない。この案では、送れない項目を人が選んでから断られることになる。ADR: ADR-0046 を更新する。
-   **項目を選んだら、確かめの問いを挟まずに送る。項目を取り下げる選択肢は設けない（AC-07・AC-05）。** ほかの提案と同じく、選ぶこと自体が人の判断である。項目は pane の状態が変わると消える。人が手で pane を空にしたときも消えるので、取り下げの選択肢は要らない。確かめの問いを挟む案と、「送らない」を選べる案は採らない。ADR: なし（`/chief` の選択肢の振る舞いの細部で、このタスクの中で閉じるため）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   報告が読めないために見送ったリセットを、人が chief の選択肢から送れるようにする。
-   人が同じ pane で始めた会話を守る確かめを、選択肢を出すときにも送るときにも外さない。

### 2.2. スコープ (In Scope)

-   `no_report` で見送ったリセットを、chief の選択肢として示す（F-001）
-   人が選んだときに確かめ直して送り、結果を示す（F-002）
-   見送らなかったリセットと、`no_report` 以外で見送ったリセットの振る舞いを変えない（F-003）
-   ADR-0046、`/chief` の定義、chief 利用ガイドの更新（F-004）

### 2.3. スコープ外 (Out of Scope)

-   判定の情報源を transcript や OpenCode の API に移すこと。理由: #905・#906・#907 が扱う。
-   `other_input` など、`no_report` 以外の理由で見送ったリセットを選択肢にすること。理由: 人の会話を守る規則を人の選択で越えないため（「要件定義の際に決めたこと」の 3 つ目の項）。
-   リセットの 2 つの場面（①②）のほかに、pane を空にする場面を足すこと。理由: issue #919 の範囲外である。
-   0088 要件定義書の書き換え。理由: 完了したタスクの文書は書き換えない。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 見送ったリセットを選択肢として示す

①または②のリセットを `no_report` で見送ったとき、そのリセットを、後の round の人の判断を待つもの（`pending`）に項目として加える。

**Acceptance Criteria**:
-   **AC-01**: ①または②のリセットが `no_report` で見送られ、AC-02 の条件を満たすとき、その後の `snapshot` と `tick` の結果の `pending` に、そのリセットの項目が 1 つ含まれる。PR を作ったのが OpenCode の pane で、人の入力の記録がないために見送った①も、これに当たる。
-   **AC-02**: 見送ったときに、そのリセットの報告以外の条件をすべて満たしていたときだけ、項目にする。報告以外の条件とは次のものである。
    -   候補の pane が、workspace の中で、そのエージェントの種類のただ 1 つの pane である。
    -   候補の pane が、直前に送った pane（①では `/runpr` を送った pane、②では次のコマンドを送った pane）と別である。
    -   候補の pane が、読み直したときも同じ workspace の同じエージェントである。
    -   ①で、PR の詳細が報告を控えていたとき、控えたときから pane の状態が変わっていない。
    -   ①で、候補が Claude Code の pane のとき、そのセッションの transcript で人が最後に入力した行が PR を作ったコマンドである（名前と引数を比べる今の確かめのとおり）。

    `no_report` 以外の理由（`other_input`・`pane_changed`・`same_pane`・`pane_ambiguous`・`no_transcript`・`path_unsupported`・`unreadable`・`stopped` など）で見送ったリセットは、項目にしない。
-   **AC-03**: 項目は次のものを持つ。workspace の名前、pane、送る入力（`/clear` か `/new`）、エージェントの種類、その pane で走ったコマンド（①では PR を作ったコマンド、②では `/runpr`）、報告が読めずに見送ったこと。`/chief` は項目を `` `<入力>` を送る: <workspace の名前> `` の形で示し、その pane の文脈が消えることを添える。
-   **AC-04**: 項目は、0088 要件定義書の AC-13 の「そのほかの提案」に並び、同じ種類の中では待っている時間の長いものが先に並ぶ。番号の付け方と通知は、ほかの項目と同じである。
-   **AC-05**: 項目は、次のすべてが成り立つ間だけ `pending` に含まれる。chief を起動し直しても、成り立つ間は含まれる。
    -   workspace がタスクの workspace として残り、送信が止められていない。
    -   見送ったときの pane が、workspace の中で、そのエージェントの種類のただ 1 つの pane である。
    -   その pane のセッションが、見送ったときと同じである。
    -   その pane の状態が、見送ったときから変わっていない（Herdr の状態の変化の番号が同じ）。

    どれかが成り立たなくなった項目は、その後に条件がもう一度そろっても、`pending` に戻らない。
-   **AC-06**: 同じ pane・同じセッション・同じ状態について見送りが 2 回あっても、項目は 1 つである。
-   **AC-07**: 見送りの記録が読めないとき、または決まった形に合わないときは、項目にしない。そのことを round の結果の `problems` に示す。

#### F-002: 人が選んだときだけ、確かめ直して送る

人が項目を選んだとき、そのリセットの入力を、確かめ直してから送る。人が選ばない限り、項目のリセットは送らない。

**Acceptance Criteria**:
-   **AC-08**: 人が項目を選ぶと、`/chief` は確かめの問いを挟まずに、そのリセットの送信を道具に頼む。道具は workspace の排他を取ってから、次のすべてを確かめ、すべて成り立つときだけ、その pane に `/clear`（Claude Code）か `/new`（OpenCode）を 1 回送る。
    -   人が選んだ項目が、今もそのまま `pending` に含まれる（AC-05 の条件を満たし、示したときと同じ pane・セッション・状態である）。
    -   エージェントが入力を待っている（実行中でも、質問で止まってもいない）。
    -   pane の入力欄に、送られていない文字が残っていない。
    -   Claude Code の pane では、そのセッションの transcript で人が最後に入力した行が、その pane で走ったコマンドである。①では PR を作ったコマンド（名前と引数）、②では `/runpr` であることを確かめる。
    -   chief のロックとセッションが、ほかの送信と同じく保たれている。
-   **AC-09**: AC-08 の確かめのどれかが成り立たないときは、何も打たない。結果は送らなかった（`not_sent`）とし、理由を示す。人が選んだ項目が、変わったか消えていたときは、示したときと違うことを理由として示す。
-   **AC-10**: 送った結果は、ほかの送信と同じ形（workspace、pane、入力の種類 `reset`、打った入力、エージェント、結果、理由、入力欄に残った文字）で示す。送信の記録にも、ほかの送信と同じく残す。打った後に確かめが失敗したときは、ほかの送信と同じく、その workspace への送信を止める。
-   **AC-11**: 送った後、その項目は `pending` から消える。
-   **AC-12**: `snapshot` と `tick` は、項目のリセットを送らない。人が項目を選ばない限り、そのリセットは送られない。

#### F-003: 今のリセットの振る舞いを保つ

**Acceptance Criteria**:
-   **AC-13**: ①②のリセットを送るかどうか、送らないときの理由、送った結果は、今と同じである。この変更で増えるのは、`no_report` で見送ったときの見送りの記録と、F-001 の項目と、F-002 の送信だけである。

#### F-004: 決定と文書の更新

**Acceptance Criteria**:
-   **AC-14**: ADR-0046 の決定に、`no_report` で見送ったリセットを人の選択肢として示し、人が選んだときだけ確かめ直して送ることを書く。記録の使い道に、人に示すリセットの候補を名指すことを足す。採らなかった案と経緯も更新する。
-   **AC-15**: `/chief` の定義（`.claude/commands/chief.md`）は、リセットの項目の示し方（AC-03）と、選んだときの道具の呼び出し、結果の示し方、送らなかった理由の説明を持つ。
-   **AC-16**: chief 利用ガイド（`docs/dev/guides/chief_guide.md`）は、リセットを送るサブコマンド、見送りの記録、見送ったリセットが選択肢になることを持つ。既知の制限「長い報告は画面から読めない」は、リセットが選択肢として示されることを書く。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。項目を示すために読むのは、Herdr のエージェントの一覧と状態のディレクトリの記録で、今の round が読むものと変わらない。

### 4.2. セキュリティ (Security)

-   `docs/dev/security.md` の条件付きの手引きの引き金（外部のコマンドの実行、API キー、キャッシュ、LLM への送信、信頼できない文字列の埋め込み）には当たらないので N/A とする。
-   開発用の道具の信頼の境界について: 見送りの記録は、同じ利用者のプロセスが書ける状態のディレクトリに置く。偽られた記録は、人に示すリセットの候補を名指しうる。ただし、送るには人の選択と、Herdr と transcript による確かめ直し（AC-08）が要る。送る入力は `/clear`・`/new` に限られ、ADR-0046 の送る入力の範囲を広げない。これを残る危険として受け入れる（ADR-0046 の記録の決定と同じ扱い）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   見送りの記録を書けないときは、項目にしない。リセットの結果（`not_sent`・`no_report`）は今と同じに示す（AC-13）。

### 4.4. 互換性 (Compatibility)

-   道具の出力の protocol は `1` のままとし、同じ PR で `/chief` の定義を直す。利用者は 1 人で、道具と定義は同じ `main` から入れるためである。

### 4.5. 保守性 (Maintainability)

-   #905・#906・#907 が報告の情報源を移した後も、報告を確かめられない見送りの受け皿として、この選択肢が働く。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   [ADR-0046](../../dev/adr/0046-chief-of-staff.md) の、送る入力の範囲と送り先の pane の選び方に従う。

## 6. 用語集 (Glossary)

-   **リセット**: pane のエージェントの文脈を空にする入力。Claude Code では `/clear`、OpenCode では `/new` である。
-   **見送り**: chief がリセットの条件を確かめて、送らなかったこと。
-   **見送りの記録**: `no_report` の見送りを後の round で項目にするために、状態のディレクトリに残す記録。形は設計で決める。
