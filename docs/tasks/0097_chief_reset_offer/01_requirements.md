## 1. 概要 (Overview)

**目的:** 本書は、chief（[0088 要件定義書](../0088_chief_of_staff/01_requirements.md)）がリセット（Claude Code の pane への `/clear`、OpenCode の pane への `/new`）を、報告が読めないために見送ったとき、そのリセットを人の選択肢として示し、人が選んだときだけ送るための要件を定義する。

**背景:**

chief は、次の 2 つの場面で pane をリセットする。

| 記号 | 場面 | 空にする pane | 今の実装 |
|---|---|---|---|
| ① | `/runpr` を送った後（0088 要件定義書の AC-52） | PR を作ったコマンド（`/mkreq`・`/mkarch`・`/mkplan`・`/runplan`）が走った pane | `internal/chief/reset.go:94-143` |
| ② | マージの後の自動送信で次のコマンドを送った後（同 AC-53） | `/runpr` が走った pane | `internal/chief/autosend.go:728-777` |

どちらも、そのコマンドの報告が pane の最後の報告として残っていることを、リセットの条件の 1 つにしている（[ADR-0046](../../dev/adr/0046-chief-of-staff.md) の決定）。その条件を満たさないとき、chief は `no_report` で見送る。`no_report` には、報告が見つからないか読めない場合と、報告は読めたが別のものだった場合の両方が含まれる（コミット `97ca1fc7` で確かめた）。

| 箇所 | 報告が見つからないか読めない | 報告は読めたが別のもの |
|---|---|---|
| ① `internal/chief/reset.go:118-120` | PR の詳細を控えたが、どの pane からも報告を控えていない（PR の説明から要約した）。PR の詳細を控えられなかったときも、ここで見送る | PR の詳細が、別の pane から報告を控えた |
| ① `internal/chief/reset.go:135-137` | 報告を控えた pane の状態は変わっていないが、その画面から報告が読めない | — |
| ① `internal/chief/reset.go:52-54` | — （OpenCode の pane には人の入力の記録がない、という理由の見送り） | — |
| ② `internal/chief/autosend.go:769-771` | 最後のメッセージが `/runpr` の報告として読めない。OpenCode の pane では、最後のメッセージの始まりが画面の外に出ていても、見えている残りを報告として読む（`internal/chief/screen_report.go:264-289`）ので、PR 番号が画面の外にあると次の列の場合と区別できない | `/runpr` の報告だが、マージした PR を名指さないか、NEXT が送ったコマンドと違う |

報告は画面から読むので、画面より長い報告は読めない（[chief 利用ガイド](../../dev/guides/chief_guide.md) の「8. 既知の制限」の「長い報告は画面から読めない」）。

issue #919 によれば、2026-11-16〜17 の chief のセッションでは、②の OpenCode の `/new` が 3 回とも `no_report` で見送られた。①の Claude Code の `/clear` は 9 回のうち 5 回が見送られ、内訳は `no_report` 4 回、`other_input` 1 回だった。見送られた pane は前のコマンドの文脈を持ったまま残る。人は手で空にするか、そのまま pane を使い続けることになる。

①の Claude Code の pane の報告を transcript から読むことは、タスク [0095](../0095_chief_transcript_report/01_requirements.md)（[#905](https://github.com/isseis/yt2column/issues/905)）が扱う。OpenCode の pane の報告は [#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907) が扱う。本書の選択肢はそれまでのつなぎであり、その後も、報告が読めないときの受け皿として残る。

対応 issue: [#919](https://github.com/isseis/yt2column/issues/919)（親: [#902](https://github.com/isseis/yt2column/issues/902)、関連: [#892](https://github.com/isseis/yt2column/issues/892)・[#905](https://github.com/isseis/yt2column/issues/905)・[#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907)）

**本書の記述範囲:** 本書は、どの見送りを選択肢にするか、選択肢に何を示し、いつ消すか、人が選んだときに何を確かめて送るか、という観測できる振る舞いを定める。見送りの記録の形、人の選択を道具に渡す口、確かめの値の作り方は、設計（[02_architecture.md](02_architecture.md)）で決める。

**issue #919 で決めたこと:**

-   **リセットを報告が読めないために見送ったとき、chief の選択肢に「リセットを送る」項目を加える（F-001）。** 報告が読めないだけで、pane が前のコマンドの文脈を持ち続けることをなくすためである。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する。
-   **人が選んだとき、その時点で送ってよいかを確かめ直してから送り、結果をほかの送信と同じ形で示す（F-002）。** 選んでから送るまでの間に、人が pane を使い始めることがあるためである。ADR: ADR-0046 を更新する。
-   **`other_input`（人の入力があった）で見送ったリセットは、選択肢にしない。** 人が同じ pane で始めた会話を守る規則なので、これまでどおり送らない。ADR: ADR-0046 を更新する（採らなかった案に書く）。
-   **判定の情報源を transcript や OpenCode の API に移すことは扱わない。** #905・#906・#907 が扱うためである。ADR: なし（作業の分け方で、決定を変えないため）。

**要件定義の際に決めたこと（2026-11-17）:**

-   **進め方は簡易な進め方にする。簡易な進め方の対象外と判断したが、人がその判断を上書きした。** この変更は、chief が pane に入力を送る条件を変える。これは開発用の道具の信頼の境界に触れるので、簡易な進め方の対象外と判断した（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Simple Process」の「Excluded changes」）。人は、変える範囲が chief の 2 か所のリセットに限られ、送る入力の種類（`/clear`・`/new`）も増えないことから、判断を上書きして簡易な進め方を選んだ。ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
-   **選択肢にするのは、`no_report` のうち、報告が見つからないか読めない見送りだけとする（AC-02）。報告は読めたが別のものだった見送り（別の PR の報告、NEXT が違う報告、別の pane から控えた報告）は選択肢にしない。** 報告が別のものだと読めたことは、pane が別の作業に移ったか、PR を作ったのが候補の pane でないことの証拠である。そのリセットを選択肢にすると、人の会話を消す方へ人を誘うことになる。`no_report` のすべてを選択肢にする案は、最初に選んだが、設計のレビューで `no_report` の中身が分かったので、人と確かめて採らないことにした。ADR: ADR-0046 を更新する。
-   **OpenCode の pane の②で、最後のメッセージの始まりが画面の外に出ていて、見えている部分が PR を名指さないときは、報告が読めない見送りとして扱う。NEXT が違うときは扱わない（AC-02）。** OpenCode の画面の読み取りは、始まりが画面の外に出たメッセージも、見えている残りを報告として返す（`internal/chief/screen_report.go:264-289`）。長い報告では、PR 番号が画面の外に出て「PR を名指さない」と判定されうる。これは報告が別のものだった証拠ではなく、報告の一部が読めないだけである。一方、NEXT は報告の終わりにあって画面に残るので、NEXT が違うことは先頭が切れたことでは説明できず、報告が別のものだった証拠として扱う。issue #919 の OpenCode の 3 件が、`autosend.go:769` のどの条件で見送られたかは記録に残っていない（3 つの条件が同じ `detail` を返す）。そのため、AC-07 の `detail` で条件を見分けられるようにする。ADR: ADR-0046 を更新する（報告が読めない見送りの範囲に含まれる）。
-   **①は Claude Code の pane だけを選択肢にする。OpenCode の pane が PR を作った①は選択肢にしない（AC-02）。** OpenCode の pane の①の見送りは、報告が読めないためではなく、人の入力の記録がないためである（`internal/chief/reset.go:52-54`）。その pane で PR を作ったコマンドが走った証拠も、人の会話を確かめる手段もない。また、今の送り先の表（`.claude/commands/_context.md` の「Command routing」）では `/runpr` も OpenCode に送られるので、この場合の①は `same_pane`（`internal/chief/reset.go:115-117`）で見送られるので、`no_report` の見送りとしては現れない。含める案は、最初に選んだが、この理由で人と確かめて採らないことにした。ADR: ADR-0046 を更新する。
-   **見送ったときに、報告以外の条件をすべて満たしていた見送りだけを選択肢にする（AC-02）。人が選んだときは、送る直前に条件を確かめ直す（AC-08）。** 送れない項目を、人が選んでから断られることのないようにするためである。見送りを選択肢に出しておいて、送る直前にだけ確かめる案は採らない。ADR: ADR-0046 を更新する。
-   **OpenCode の pane の②では、人の会話を機械で確かめられないことを受け入れ、項目でそのことを人に示す（AC-03）。** 画面の読み取りだけでは、報告が長くて読めないのか、報告の後に人が同じ pane で会話を続けたのかを区別できない。OpenCode には transcript がなく、確かめられるのは、見送った後に pane の状態が変わっていないことだけである。②を Claude Code の pane に限ると、issue #919 の主な事例（OpenCode の `/new` の 3 件）が救えない。そこで、項目に「pane を見てから選ぶこと」を添え、人の目で確かめることにした。ADR: ADR-0046 を更新する（結果に残る危険として書く）。
-   **項目を選んだら、確かめの問いを挟まずに送る。項目を取り下げる選択肢は設けない（AC-08・AC-05）。** ほかの提案と同じく、選ぶこと自体が人の判断である。Claude Code の pane は、人が手で `/clear` するとセッションが変わり、項目が消える。OpenCode の pane は、`/new` ではセッションも Herdr の状態の変化の番号も変わらない（[0088 実装計画書](../0088_chief_of_staff/03_implementation_plan.md) の PR-7 の実地の確かめ）。このため、人が手で `/new` しても項目は残るが、選んでも空の pane に `/new` が送られるだけである。確かめの問いを挟む案と、「送らない」を選べる案は採らない。ADR: なし（`/chief` の選択肢の振る舞いの細部で、このタスクの中で閉じるため）。
-   **項目は、chief を起動し直しても条件を満たす間は示す。見送りの記録は、その pane へ chief がコマンドかリセットを送れたときと、14 日たった後の chief の起動のときに消す（AC-05）。** 見送った後に `/chief` のセッションが替わっても、pane は文脈を持ったまま残るためである。OpenCode の pane はセッションを報告せず、`/new` でも状態の変化の番号が変わらないので、条件を外れた記録が後で再び条件を満たすことがある。その pane へ次の入力を送れたときと、一定の期間の後に記録を消して、古い見送りが示され続けないようにする。ADR: なし（同上）。
-   **出力の protocol は `1` のままとし、同じ PR で `/chief` の定義を直す（4.4）。** 利用者は 1 人で、道具と定義は同じ `main` から入れるためである。入れ直した後は `/chief` を起動し直す。ADR: なし（同上）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   報告が見つからないか読めないために見送ったリセットを、人が chief の選択肢から送れるようにする。
-   人が同じ pane で始めた会話を守る今の確かめ（`other_input` など）を、選択肢を出すときにも送るときにも緩めない。機械で確かめられない部分（OpenCode の pane の②）は、項目でそのことを示し、人の判断に任せる。

### 2.2. スコープ (In Scope)

-   報告が見つからないか読めずに見送ったリセットを、chief の選択肢として示す（F-001）
-   人が選んだときに確かめ直して送り、結果を示す（F-002）
-   リセットを送るかどうかと、見送るときの理由を変えない（F-003）
-   ADR-0046、`/chief` の定義、chief 利用ガイドの更新（F-004）

### 2.3. スコープ外 (Out of Scope)

-   判定の情報源を transcript や OpenCode の API に移すこと。理由: #905・#906・#907 が扱う。
-   `no_report` 以外の理由で見送ったリセットと、報告は読めたが別のものだった見送りを選択肢にすること。理由: 「要件定義の際に決めたこと」の 2 つ目の項。
-   OpenCode の pane が PR を作った①を選択肢にすること。理由: 同 3 つ目の項。
-   リセットの 2 つの場面（①②）のほかに、pane を空にする場面を足すこと。理由: issue #919 の範囲外である。
-   0088 要件定義書の書き換え。理由: 完了したタスクの文書は書き換えない。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 見送ったリセットを選択肢として示す

①または②のリセットを、報告が見つからないか読めないために見送ったとき、そのリセットを、人の判断を待つもの（`pending`）に項目として加える。

**Acceptance Criteria**:
-   **AC-01**: AC-02 の条件を満たす見送りの後、`snapshot` と `tick` の結果の `pending` に、そのリセットの項目が 1 つ含まれる。②の見送りをした `tick` 自身の結果の `pending` に含まれるかどうかは問わない。その次の round からは含まれる。
-   **AC-02**: 見送ったときに、次の表の「選択肢にする見送り」に当たり、その場面の「そのほかの条件」をすべて満たしていたときだけ、項目にする。

    | 場面 | 候補の pane | 選択肢にする見送り | そのほかの条件 |
    |---|---|---|---|
    | ① | Claude Code | PR の詳細を控えたが、どの pane からも報告を控えていない | 共通の条件。transcript で人が最後に入力した行が、PR を作ったコマンド（名前と引数）である |
    | ① | Claude Code | PR の詳細が候補の pane から報告を控え、その後 pane の状態が変わっていないが、画面から報告が読めない | 同上 |
    | ② | Claude Code | 最後のメッセージが `/runpr` の報告として読めない | 共通の条件。排他の下で読んだときから pane の状態が変わっていない。transcript で人が最後に入力した行が `/runpr` である（名前だけを比べる） |
    | ② | OpenCode | 最後のメッセージが `/runpr` の報告として読めないか、最後のメッセージの始まりが画面の外に出ていて、見えている部分がマージした PR を名指さない（NEXT は送ったコマンドと違わない） | 共通の条件。排他の下で読んだときから pane の状態が変わっていない |

    共通の条件は次のとおりである。

    -   候補の pane が、workspace の中で、そのエージェントの種類のただ 1 つの pane である。
    -   候補の pane が、直前に送った pane（①では `/runpr` を送った pane、②では次のコマンドを送った pane）と別である。
    -   候補の pane が、読み直したときも同じ workspace の同じエージェントで、入力を待っている（実行中でも、質問で止まってもいない）。

    次の見送りは項目にしない。OpenCode の pane の①、PR の詳細を控えられなかった①、PR の詳細が別の pane から報告を控えた①、最後のメッセージの全体が画面にあり、マージした PR を名指さない②、NEXT が送ったコマンドと違う②。`no_report` 以外の理由（`other_input`・`pane_changed`・`same_pane`・`pane_ambiguous`・`no_transcript`・`path_unsupported`・`unreadable`・`stopped` など）の見送り。
-   **AC-03**: 項目は次のものを持つ。workspace の名前、pane、送る入力（`/clear` か `/new`）、エージェントの種類、その pane で走ったコマンド（①では PR を作ったコマンド、②では `/runpr`）、場面（①か②）。`/chief` は項目を `` `<入力>` を送る: <workspace の名前> `` の形で示し、次の 3 点を添える。(1) その pane の文脈が消えること。(2) 報告が読めずに見送ったものなので、選ぶ前に pane を見て、前のコマンドの報告の後に会話が続いていないことを確かめること。(3) OpenCode の pane では、chief が、その pane で `/runpr` が走ったことも、その後に人の会話がないことも確かめられないこと。
-   **AC-04**: 項目は、0088 要件定義書の AC-13 の「そのほかの提案」と同じ順位に並ぶ。待っている時間は、ほかの項目と同じく、chief のセッションが項目を初めて見つけたときから数える。番号の付け方と通知も、ほかの項目と同じである。
-   **AC-05**: 項目は、次のすべてが成り立つ間だけ `pending` に含まれる。chief を起動し直しても、成り立つ間は含まれる。
    -   workspace がタスクの workspace として残り、状況の表で「要確認」でなく、送信が止められていない。
    -   見送ったときの pane が、同じ Herdr の workspace の中で、そのエージェントの種類のただ 1 つの pane である。
    -   その pane のセッションと Herdr の状態の変化の番号が、見送ったときと同じである。
    -   その pane のエージェントが入力を待っている。
    -   送り先の表で、その場面のコマンドの送り先が、見送ったときと同じ種類のエージェントである。
    -   その項目のリセットが、F-002 で送られていない。

    見送りの記録は、chief がその pane へコマンドかリセットを送れたとき、または見送りから 14 日（PR の詳細の控えを残す期間と同じ）たった後の chief の起動のときに消え、その後その見送りの項目は示されない。それまでは、条件を満たさない間は示さず、条件を再び満たせば示す。
-   **AC-06**: 同じ pane・同じセッション・同じ状態の変化の番号について見送りが 2 回あっても、項目は 1 つである。
-   **AC-07**: ①②の結果の `detail` は、今の文言に加えて、その見送りを項目にしたか、しなかったときはどの条件で外れたか、見送りの記録を書けなかったかを示す。②の `no_report` の `detail` は、報告として読めなかったか、メッセージの始まりが画面の外に出ていたか、PR を名指さなかったか、NEXT が違ったかを見分けられるようにする。

#### F-002: 人が選んだときだけ、確かめ直して送る

人が項目を選んだとき、そのリセットの入力を、確かめ直してから送る。人が選ばない限り、項目のリセットは送らない。

**Acceptance Criteria**:
-   **AC-08**: 人が項目を選ぶと、`/chief` は確かめの問いを挟まずに、そのリセットの送信を道具に頼む。道具は workspace の排他を取ってから、次のすべてを確かめ、すべて成り立つときだけ、その pane に `/clear`（Claude Code）か `/new`（OpenCode）を 1 回送る。
    -   人が選んだ項目が、今もそのまま `pending` に含まれる（AC-05 の条件を満たし、示したときと同じ pane・セッション・状態の変化の番号・場面・コマンドである）。
    -   pane の入力欄に、送られていない文字が残っていない。
    -   Claude Code の pane では、transcript で人が最後に入力した行が、項目が示すその pane で走ったコマンドである（①は名前と引数を比べ、引数を文書から決められない `/mkreq` は引数があることだけを確かめる。②は名前だけを比べる）。
    -   chief のロックをこの `/chief` のセッションが持ち、chief の pane のセッションが変わっていない（ほかの送信と同じ確かめ）。
-   **AC-09**: AC-08 の確かめのどれかが成り立たないときは、何も打たない。結果は送らなかった（`not_sent`）とし、理由を示す。人が選んだ項目が、変わったか消えていたときは、示したときと違うこと（`check_mismatch`）を理由として示す。
-   **AC-10**: 送った結果は、ほかの送信と同じ形（workspace、pane、入力の種類 `reset`、打った入力、エージェント、結果、理由、入力欄に残った文字）で示す。送信の記録にも、ほかの送信と同じく残す。打った後に確かめが失敗したときは、ほかの送信と同じく、その workspace への送信を止める。
-   **AC-11**: 道具は、最初の入力を打つ前に、その項目を使い済み（`pending` に二度と戻らない状態）にする。使い済みにできなかったときは何も打たない。送った（`sent`）か、打った後に失敗した（`sent_then_failed`）項目は、その後 `pending` に戻らない（その後に同じ pane で新しく見送れば、それは新しい項目である）。何も打たなかった（`not_sent`）項目は、AC-05 の条件を満たす間、`pending` に残る。ただし、使い済みにした後に、送信の記録を書けないなどで何も打たなかった項目は、戻らない。
-   **AC-12**: `snapshot` と `tick` は、項目のリセットを送らない。人が項目を選ばない限り、そのリセットは送られない。

#### F-003: 今のリセットの判定を保つ

**Acceptance Criteria**:
-   **AC-13**: ①②のリセットを送るかどうか、送らないときの理由（`reason`）、送った結果は、今と同じである。今と変わるのは次のものだけである。
    -   ①②の結果の `detail` に、AC-07 の文言が加わる。
    -   F-001 の項目と、F-002 の送信。
    -   人が選んだリセットの送信は、ほかの送信と同じく、送信の記録に残る。このため、PR のマージを chief が見た後に人がリセットを選ぶと、その workspace の自動送信の条件「マージを見た後にその workspace へ送っていない」（0088 要件定義書の F-007）が満たされなくなる。その結果、次のコマンドは自動では送られず、提案として示される。

#### F-004: 決定と文書の更新

**Acceptance Criteria**:
-   **AC-14**: ADR-0046 の決定に、報告が見つからないか読めずに見送ったリセットを人の選択肢として示し、人が選んだときだけ確かめ直して送ることを書く。記録の使い道に、人に示すリセットの候補を名指すことを足す。採らなかった案、結果、経緯も更新する。
-   **AC-15**: `/chief` の定義（`.claude/commands/chief.md`）は、リセットの項目の示し方（AC-03）と、選んだときの道具の呼び出し、結果の示し方、送らなかった理由の説明を持つ。
-   **AC-16**: chief 利用ガイド（`docs/dev/guides/chief_guide.md`）は、リセットを送るサブコマンド、見送りの記録、見送ったリセットが選択肢になることを持つ。既知の制限「長い報告は画面から読めない」は、リセットが選択肢として示されることを書く。

### 3.2. 信頼できない入力の境界

| 入力 | 受け付ける形 | 受け付けないときの振る舞い |
|---|---|---|
| 見送りの記録（状態のディレクトリのファイル。同じ利用者のプロセスが書ける） | 1 つの JSON のオブジェクトで、設計が決める欄だけを持ち、後ろに続きのデータがない。大きさはほかの記録と同じ上限まで。pane は Herdr の pane ID の形、エージェントと場面は決まった値、コマンドは決まった名前で、引数はタスクの番号か PR の番号の形（`/mkreq` は引数なし）。知らない欄、重なった欄、決まった値でないものは、直さずに受け付けない | 項目にしない。round の結果の `problems` に、その記録のパスと読めない理由を示す（round は消さない。14 日たった後の chief の起動のときに消す） |
| 人の選択（`/chief` が道具に渡す確かめの値） | 道具が `pending` で示した形の値 | 形に合わないときは使い方の誤り（終了コード `2`）。形に合うが今の項目のどれにも当たらないときは `not_sent`・`check_mismatch`（AC-09） |
| Herdr のエージェントの一覧、画面、transcript | 0088・0095 で受け付ける形のまま | 今の読み取りと同じ（読めないときは項目にせず、送らない） |

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   N/A。項目を示すために読むのは、Herdr のエージェントの一覧と状態のディレクトリの記録で、今の round が読むものに見送りの記録が加わるだけである。

### 4.2. セキュリティ (Security)

-   `docs/dev/security.md` の条件付きの手引きの引き金（外部のコマンドの実行、API キー、キャッシュ、LLM への送信、信頼できない文字列の埋め込み）には当たらないので N/A とする。
-   開発用の道具の信頼の境界について、次の 2 つを残る危険として受け入れる。
    -   **偽られた記録。** 見送りの記録は、同じ利用者のプロセスが書ける状態のディレクトリに置く。偽られた記録は、人に示すリセットの候補を名指しうる。Claude Code の pane では、記録のコマンドを人の最後の入力と同じに偽れば、transcript の確かめも通りうる。ただし、送るには人の選択と、Herdr と transcript を読み直す道具の確かめ直し（AC-08）が要る。送る入力は `/clear`・`/new` に限られ、ADR-0046 の送る入力の範囲を広げない（ADR-0046 の記録の決定と同じ扱い）。
    -   **OpenCode の pane の②。** その pane で `/runpr` が走ったことも、報告の後に人が同じ pane で会話を続けたかも、機械で確かめられない。項目でそのことを示し、人の目に任せる（AC-03）。
    -   **OpenCode の pane の古い記録。** OpenCode の pane は、pane と状態の変化の番号でしか見分けられない。記録が消えるまでの間に、Herdr が pane ID を使い回すなどで別の会話の pane が記録と同じ値を持つと、古い見送りが示されうる（AC-05）。送るには人の選択が要るので、これを受け入れる。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   見送りの記録を書けないときは、項目にしない。リセットの結果の `outcome` と `reason` は今と同じに示し、`detail` に書けなかったことを添える（AC-07・AC-13）。

### 4.4. 互換性 (Compatibility)

-   道具の出力の protocol は `1` のままとし、同じ PR で `/chief` の定義を直す。入れ直した後は `/chief` を起動し直す。古い道具と新しい定義の組み合わせでは、定義が呼ぶリセットのサブコマンドが使い方の誤りで拒まれ、何も送られない。

### 4.5. 保守性 (Maintainability)

-   #905・#906・#907 が報告の情報源を移した後も、報告が見つからないか読めない見送りの受け皿として、この選択肢が働く。そのとき、選択肢にするのは「報告がない」と判定した見送りだけで、情報源そのものを読めなかった見送り（transcript を読めないなど）は選択肢にしない、という AC-02 の区別を保つ。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   [ADR-0046](../../dev/adr/0046-chief-of-staff.md) の、送る入力の範囲と送り先の pane の選び方に従う。
-   0088 要件定義書の AC-52 は、PR を作ったコマンドの後に pane が再び実行中になったときは空にしないとしている。①の項目では、この条件を、transcript で人が最後に入力した行が PR を作ったコマンドであること（今の①の確かめと同じ）と、入力を待っていることで確かめる。

## 6. 用語集 (Glossary)

-   **リセット**: pane のエージェントの文脈を空にする入力。Claude Code では `/clear`、OpenCode では `/new` である。
-   **見送り**: chief がリセットの条件を確かめて、送らなかったこと。
-   **見送りの記録**: 見送りを後の round で項目にするために、状態のディレクトリに残す記録。形は設計で決める。
-   **状態の変化の番号**: Herdr がエージェントの pane ごとに報告する `state_change_seq`。
