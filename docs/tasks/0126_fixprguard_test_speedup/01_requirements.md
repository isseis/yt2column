## 1. 概要 (Overview)

**目的:** 本書は、`internal/fixprguard` と `cmd/fixprguard` のテストを並列に実行できるようにし、テストの git フィクスチャの費用を下げて、2 つのパッケージのテストの実行時間を短くするための要件を定義する（[#1167](https://github.com/isseis/yt2column/issues/1167)）。

**背景:**

issue #1167 の計測（`go test -tags test -race -count=1 ./...`）では、`internal/fixprguard` が全パッケージの中で最も遅く（壁時計で 493.0 秒）、`cmd/fixprguard` も 88.0 秒かかる。`make test` はパッケージを並列に走らせる（`Makefile:93-95`）ので、全体の時間は最も遅いパッケージの時間で決まる。この 2 つのパッケージがテスト全体のボトルネックになっている。

遅い原因は 2 つある。

-   **並列に実行できない:** テストのリポジトリを作る `newTestRepo` は、`t.Setenv("HOME", ...)`・`t.Setenv("XDG_CONFIG_HOME", ...)` と `t.Chdir` を呼ぶ（`internal/fixprguard/test_helpers_git.go:127-155`、`cmd/fixprguard/test_helpers.go:52-77`）。Go では、この 2 つを呼ぶテストは `t.Parallel()` にできない。そのため、2 つのパッケージのテストは 1 つずつ順に実行される。
-   **テストごとに多くの git を起動する:** `newTestRepo` は 1 回の呼び出しで、`git init` を 2 回、`git config` を 7 回、`git remote add`・`git add`・`git commit`・`git push` を 1 回ずつ実行する（`internal/fixprguard/test_helpers_git.go:127-169,237-241`。`cmd/fixprguard/test_helpers.go:52-94` も同じ形である）。

`t.Chdir` をやめられないのは、製品コードがプロセスの作業ディレクトリを前提にしているからである。fixprguard は、作業ディレクトリが作業ツリーの最上位であることを前提に動き、`.git` を作業ディレクトリからの相対パスで読む（`internal/fixprguard/gitstate.go:182-204`、`internal/fixprguard/worktree.go:48-49`、[fixprguard_guide.md](../../dev/guides/fixprguard_guide.md) の「作業ディレクトリ」の行）。子のコマンドは、プロセスから引き継いだ環境変数から `GIT_*` を除いた環境で起動する（`cmd/fixprguard/main.go:172-190`）。テストが `HOME` を差し替えるには、今はプロセスの環境変数を変えるしかない。

対応 issue: [#1167](https://github.com/isseis/yt2column/issues/1167)

**本書の記述範囲:** 本書は、観測できる結果を定める。どのテストが並列に動くか、製品の外から見た振る舞いを変えないこと、フィクスチャが作るリポジトリの状態、実行時間の目標、検証範囲を保ったことの確かめ方である。作業ツリーと環境変数を受け渡す API の形、フィクスチャを速くする手段（ひな形のコピーか、設定ファイルへの直接の書き込みか）、直列のまま残すテストの一覧、計測の手順の細部は、設計（`02_architecture.md`）で決める。要件の段階で挙がった設計の事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #1167 で決めたこと:**

-   **並列化の方針:** fixprguard のワークツリーの操作と環境変数の参照を、作業ディレクトリと環境変数の注入で完結させる。`newTestRepo` から `t.Chdir` と `t.Setenv` への依存をなくし、`t.Parallel()` を使えるようにする（F-001、F-002）。
-   **フィクスチャの軽量化:** テストのリポジトリ 1 つあたりの git の起動の回数を減らす。手段の候補は、初期状態のリポジトリ（`work` と `remote.git`）をひな形として 1 回だけ作って各テストでコピーすることと、`git config` の連続した呼び出しを `.git/config` への直接の書き込みに置き換えることである（F-003）。
-   **完了の条件:** 2 つのパッケージの主要なテストが `t.Parallel()` で安全に並列に動き、`-race` で通ること。テストの検証範囲を保ったまま、2 つのパッケージの実行時間が大幅に短くなること。`make test` と `make lint` が通ること（F-001、F-004、F-005）。

**要件定義の際に決めたこと（2026-11-26）:**

-   **プロセス:** フルプロセスで進める。fixprguard の製品コードを変えるので、簡易プロセスの除外（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Excluded changes」の、開発ツールの信頼の境界の変更。[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）に当たると判断した。外から見た振る舞いは変えないが、境界を守るツールのコードに手を入れることには変わりないためである。人はフルプロセスを選んだ。ADR: なし（タスクのプロセスの選択で、ほかのタスクを縛らない）。
-   **製品の変更を範囲に含める:** テストだけを変える案（製品は変えず、フィクスチャを軽くするだけで並列化しない）は採らなかった。並列にできなければ短縮の幅が小さく、issue の完了の条件に届かないためである。製品のコードを、作業ツリーのディレクトリと子のコマンドの環境変数を呼び出し元から受け取る形に変える（F-002）。ADR: なし（fixprguard の内部の構造の変更で、外から見た契約は変えず、ほかの構成要素やタスクを縛らない）。
-   **CLI の契約とプロトコル番号を変えない:** CLI は今までどおりプロセスの作業ディレクトリを作業ツリーとし、引き継いだ環境変数から子のコマンドの環境を作る。サブコマンド・引数・出力・終了コードは変えない（F-002）。[dev_tools.md](../../dev/conventions/dev_tools.md) は、開発ツールの引数・出力・終了コードを契約として保つよう求めている。契約を変えないので、プロトコル番号（`CLAUDE.md`「Protocol numbers」）も上げない。ADR: なし（既存の規則をそのまま当てはめる）。
-   **短縮の目標は、同じ機械での前後の比で 50% 以下:** 変更の前と後で、同じ機械と同じコマンドで 2 つのパッケージを計り、それぞれ前の時間の 50% 以下になることを目標にする（F-004）。絶対の秒数を目標にすると、機械の性能で結果が変わるためである。数値の目標を置かない案は、「大幅に」を確かめられないので採らなかった。ADR: なし（このタスクの完了の条件で、ほかのタスクを縛らない）。
-   **直列のまま残してよいテスト:** プロセス全体の状態そのものを確かめるテストに限り、`t.Parallel()` にしなくてよい。例は、引き継いだ `GIT_DIR` が子のコマンドに届かないことや、`PATH` からコマンドを探すこと、本物のプロセスの作業ディレクトリでの振る舞いを確かめるテストである（F-001）。これらは確かめる対象がプロセスの状態なので、注入の形に書き直すと、確かめたいことを確かめられなくなるためである。例外を認めない案は、この理由で採らなかった。直列のまま残すテストの一覧とそれぞれの理由は、設計で決めて記録する。ADR: なし（このタスクのテストの扱いで、ほかのタスクを縛らない）。
-   **検証範囲の保ち方:** 2 つで確かめる。1 つは、変更の前を基準にした `make coverage-compare` が `PASS` で終わることである。もう 1 つは、2 つのパッケージのテストとサブテストの名前の集合が、前後で同じことである（F-005）。テストを削除したときだけ比較を求める今の規則（[ADR-0037](../../dev/adr/0037-test-deletion-coverage.md)）では、テストを書き直して確かめる範囲が狭まっても見つけられないためである。カバレッジだけでは、同じ行を通る別のテストに置き換わったことが分からない。テストの名前だけでは、テストの中身が減ったことが分からない。そのため 2 つを組み合わせる。PR のレビューで差分を読むだけにする案は、機械的に確かめられないので採らなかった。ADR: なし（このタスクの確かめ方で、ADR-0037 の決定は変えない）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   `internal/fixprguard` と `cmd/fixprguard` のテストを並列に実行できるようにし、`-race` で安全に通るようにする。
-   2 つのパッケージのテストの実行時間を、それぞれ変更の前の 50% 以下にする。
-   fixprguard の外から見た振る舞い（CLI の契約と、信頼の境界の確かめ）を変えない。
-   テストが確かめる範囲を狭めない。

### 2.2. スコープ (In Scope)

-   `internal/fixprguard` の製品コードを、作業ツリーのディレクトリと子のコマンドの環境変数を呼び出し元から受け取る形に変えること（F-002）。
-   `cmd/fixprguard` の製品コードを、上の形に合わせて変えること。CLI としての振る舞いは変えない（F-002）。
-   2 つのパッケージのテストとテストの補助（`test_helpers*.go`）を、`t.Chdir` と `t.Setenv` を使わずに `t.Parallel()` で動く形に書き直すこと（F-001）。
-   テストのリポジトリを作るフィクスチャの git の起動の回数を減らすこと（F-003）。
-   変更の前後の実行時間の計測と記録（F-004）、検証範囲を保ったことの確かめ（F-005）。

### 2.3. スコープ外 (Out of Scope)

-   **ほかのパッケージのテストの高速化:** `internal/mergepr`・`internal/chief` などの遅いテストは扱わない。issue #1167 が対象にしているのは fixprguard の 2 つのパッケージだけである。
-   **`make test`・CI の設定の変更:** `-race` を外すこと、パッケージを分割すること、テストの対象を絞ることはしない。テストの実行のしかたを変えずに、テストそのものを速くするのが issue の方針だからである。
-   **fixprguard の CLI の契約とプロトコル番号の変更:** 1 の「要件定義の際に決めたこと」のとおり変えない。
-   **[fixprguard_guide.md](../../dev/guides/fixprguard_guide.md) の変更:** CLI の振る舞いが変わらないので、利用者向けの説明も変わらない（AC-08）。
-   **`internal/cmdrunner` の振る舞いの変更:** `cmdrunner.Options` は作業ディレクトリ（`Dir`）と環境（`Env`）をすでに受け取れる（`internal/cmdrunner/runner.go:35-62`）。このタスクはそれを使う側を変えるだけで、`cmdrunner` の振る舞いは変えない。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: テストの並列実行

2 つのパッケージのテストを、直列のまま残してよいテスト（AC-03）を除いて、並列に実行する。

**Acceptance Criteria**:
- **AC-01**: `internal/fixprguard` と `cmd/fixprguard` の `_test.go` にあるすべてのテスト関数（`func TestXxx(t *testing.T)`）とすべてのサブテスト（`t.Run` に渡す関数）は、AC-03 の例外を除き、`t.Parallel()` を呼ぶ。
- **AC-02**: `go test -tags test -race -count=3 ./internal/fixprguard ./cmd/fixprguard` が、データ競合の報告も失敗もなく通る。
- **AC-03**: `t.Parallel()` を呼ばないテストは、プロセス全体の状態（引き継いだ環境変数、`PATH` からのコマンドの探索、本物のプロセスの作業ディレクトリ）そのものを確かめるテストだけである。直列のまま残すテストは、それぞれの名前と理由とともに、設計書か実装計画書に一覧として記録されている。一覧にないテストが `t.Parallel()` を呼ばないことはない。
- **AC-04**: AC-03 の一覧にないテストとテストの補助は、`t.Chdir`・`t.Setenv`・`os.Chdir`・`os.Setenv`・`os.Unsetenv` を呼ばない。

#### F-002: 作業ツリーと環境変数の受け渡し

`internal/fixprguard` の、作業ツリーを読み書きする操作と子のコマンドを起動する操作は、作業ツリーのディレクトリと子のコマンドの環境変数を呼び出し元から受け取る。CLI は、その値をプロセスの作業ディレクトリと環境変数から作り、外から見た振る舞いを変えない。

**Acceptance Criteria**:
- **AC-05**: `internal/fixprguard` の操作に作業ツリーのディレクトリを渡すと、プロセスの作業ディレクトリが別の場所（別のリポジトリ、または `.git` のないディレクトリ）であっても、渡したディレクトリの作業ツリーに対して動く。読むファイル、書くファイル、起動する git の対象は、渡した作業ツリーのものである。
- **AC-06**: `internal/fixprguard` の操作が起動する子のコマンドは、呼び出し元が渡した環境変数で動く。プロセスの環境変数（`HOME`・`XDG_CONFIG_HOME` など）を差し替えなくても、テストは子のコマンドに自分の `HOME` を渡せる。
- **AC-07**: `fixprguard` の CLI は、変更の前と同じく、プロセスの作業ディレクトリを作業ツリーとし、プロセスから引き継いだ環境変数から `GIT_*` を除いた環境で子のコマンドを起動する。どのサブコマンドでも、同じ引数・同じ作業ツリーの状態・同じ外部のコマンドの応答に対して、標準出力・標準エラー・終了コード・起動する外部のコマンドとその引数が、変更の前と同じである。[fixprguard_guide.md](../../dev/guides/fixprguard_guide.md) の「作業ディレクトリ」の行の振る舞い（最上位でないときの終了コード `2` と `git-state-changed`（`config`）、`.git` がないときの `check`・`push-review` の終了コード `2`）も変わらない。
- **AC-08**: マージベースに対する `docs/dev/guides/fixprguard_guide.md` の差分は空である。`internal/fixprguard` の `const Protocol = <整数>` の行の差分も空である。

#### F-003: フィクスチャの軽量化

テストのリポジトリを作るフィクスチャが起動する git の回数を減らす。作られるリポジトリの状態は変えない。

**Acceptance Criteria**:
- **AC-09**: `internal/fixprguard` と `cmd/fixprguard` のそれぞれで、テストのリポジトリを 1 つ作るときに起動する git のプロセスの数が、変更の前より少ない。前後の数は、実装計画書か PR の説明に記録されている。
- **AC-10**: フィクスチャが作るリポジトリは、変更の前と同じ状態にある。ブランチ（`feature`）、最初のコミットのファイルとその内容、リポジトリの設定の値（利用者名・メールアドレス・署名の無効化・`core.excludesFile`・`core.ignorecase`・`core.precomposeunicode`）、`origin` のリモートと上流の追跡、空の大域の除外ファイル、テストごとに分かれた `HOME` が変わらない。あるテストがリポジトリを変えても、ほかのテストのリポジトリは変わらない。

#### F-004: 実行時間の短縮

**Acceptance Criteria**:
- **AC-11**: 同じ機械で、`go test -tags test -race -count=1 ./internal/fixprguard ./cmd/fixprguard` を変更の前（マージベース）と後でそれぞれ実行する。`go test` がパッケージごとに報告する時間は、2 つのパッケージのそれぞれで、前の時間の 50% 以下である。
- **AC-12**: AC-11 の計測は、機械（OS と CPU のコア数）、Go の版、前後のコミット、パッケージごとの時間とともに、実装計画書か PR の説明に記録されている。計測を繰り返したときは、目標に届かなかった回も含めてすべての回を記録する。

#### F-005: 検証範囲の維持

**Acceptance Criteria**:
- **AC-13**: 実装の PR ごとに、その PR のマージベースを `BASE` にした `make coverage-compare BASE=<マージベース>` が、最後の行に `coverage-compare: PASS` を出して終わる。出力は最後の行まで PR の説明に記録されている。
- **AC-14**: `internal/fixprguard` と `cmd/fixprguard` のテストとサブテストの名前の集合（`go test -json` が報告する `Test` の値）は、実装の PR ごとに、マージベースと PR の先頭で同じである。PR が足したテストの名前は、その理由とともに PR の説明に記録されている。名前が消えたテストはない。テストを削除するときは、`CLAUDE.md`「Testing Strategy」の削除の規則に従う。
- **AC-15**: 実装の PR ごとに、`make test` と `make lint` が通る。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)
-   F-004 のとおり、2 つのパッケージのテストの時間を、それぞれ変更の前の 50% 以下にする。製品の実行時間は目標にしない。CLI の実行時間は git と gh の呼び出しで決まり、このタスクの変更で意味のある差は生じないためである（`CLAUDE.md`「Performance」）。

### 4.2. セキュリティ (Security)
-   [security.md](../../dev/security.md) の条件付きの指針は当てはまらない（N/A）。このタスクは `yt-dlp` を起動せず、API キーもキャッシュのディレクトリも扱わず、LLM の API にも送らず、信頼できないテキストをプロンプトや記事に埋め込まないためである。
-   fixprguard は、レビューのスレッドを信頼しないための境界を守るツールである（[ADR-0015](../../dev/adr/0015-untrusted-review-threads.md)）。このタスクは、その境界の確かめ（作成者の判定、範囲の規則、git の状態の確かめ、`GIT_*` を除いた子のコマンドの環境）の振る舞いを変えない（AC-07）。

### 4.3. 信頼性・可用性 (Reliability/Availability)
-   並列のテストは、互いのリポジトリ・`HOME`・一時ファイルを共有しない（AC-10）。1 つのテストの失敗や変更が、ほかのテストの結果に影響しない。
-   並列のテストが、プロセスの作業ディレクトリ（パッケージのディレクトリ）にある本物のリポジトリを読んだり書いたりしない（AC-05）。

### 4.4. 互換性 (Compatibility)
-   macOS（大文字と小文字を区別しないボリュームを含む）と Linux の CI の両方で通る。今のフィクスチャが固定している無視の規則と名前の比較（`internal/fixprguard/test_helpers_git.go:157-169`）は保つ（AC-10）。

### 4.5. 保守性 (Maintainability)
-   テストを書く人が、新しいテストを `t.Parallel()` で書けるようにする。テストの補助は、`t.Chdir`・`t.Setenv` を使わずにリポジトリと `HOME` を用意できる（AC-04、AC-06）。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   開発ツールの引数・出力・終了コードは契約として保つ（[dev_tools.md](../../dev/conventions/dev_tools.md)）。
-   エージェントは fixprguard をインストールもビルドもしない（`CLAUDE.md`「Tool Execution Safety」）。テストと lint のためのパッケージのコンパイルは、ビルドに当たらない。
-   テストを削除するときは、削除だけのコミットでカバレッジを比べる（`CLAUDE.md`「Testing Strategy」、[ADR-0037](../../dev/adr/0037-test-deletion-coverage.md)）。

## 6. 用語集 (Glossary)

-   **作業ツリー:** git のリポジトリのファイルを置く最上位のディレクトリ。fixprguard が確かめて commit と push をする対象である。
-   **作業ディレクトリ:** プロセスのカレントディレクトリ。今の CLI は、作業ディレクトリが作業ツリーの最上位であることを前提にしている。
-   **フィクスチャ:** テストのために用意する、作業ツリーとローカルの bare リポジトリ（`origin`）の組。今は `newTestRepo` が作る。
-   **直列のまま残すテスト:** `t.Parallel()` を呼ばないテスト。AC-03 の条件に当たるものだけである。
-   (用語は `docs/translation_glossary.md` と統一する)
