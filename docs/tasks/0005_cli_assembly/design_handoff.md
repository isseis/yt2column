## H-01: 統合テストのオプトインの変数と、実行条件の判定の共有

-   **事項:** F-009 の統合テストの実行条件（オプトインの変数の値がちょうど `1`、テスト用の API キーがある、`GODEBUG` が `http2debug=1`・`http2debug=2` を含まない）は、既存の DeepSeek の統合テスト（`internal/llm/deepseek` の `integrationSettingsFrom`）と同じである。設計では次の 2 点を決める。
    -   オプトインの変数を、既存の `YT2COLUMN_DEEPSEEK_INTEGRATION` と共有するか、本タスクの統合テスト専用の変数を設けるか。
    -   実行条件の判定を共有するか、本タスクの統合テストで書き直すか。既存の判定は `internal/llm/deepseek` のテスト用のファイルにある非公開の関数であり、`cmd/yt2column` のテストからは使えない。
-   **理由:** 判定を 2 か所で別々に書くと、一方だけが変わったとき（たとえば `GODEBUG` の検出の対象を広げたとき）に、もう一方の統合テストが料金の発生する呼び出しや API キーの出力を防げなくなる。変数を共有すると、`make test-integration-deepseek` を意図して設定したオプトインで、より多くの呼び出しを行う本タスクの統合テストも走る。
-   **手段の候補:** オプトインの変数は、実行する make のターゲットと 1 対 1 に対応させるため、本タスク専用のものを設ける。実行条件の判定は、`test` または `integration` のビルドタグでだけビルドされる共有のテスト用パッケージ（例: `internal/testutil/integration`）に移し、変数名を引数で受け取る形にして、既存の DeepSeek の統合テストと本タスクの統合テストの両方から使う。
-   **関連:** F-009・AC-40
