## 1. 設計の全体像

本タスクは、ADR-0024（`docs/dev/adr/0024-env-access-in-config.md`）の「結果」の最後の項目 1 つを文書の上で書き直し、「経緯」の最後に項目を 1 つ足すだけである（[01_requirements.md](01_requirements.md) F-001・F-002）。コードは変えない。直しは決定の変更なので、ADR-0024 の変更は本書と同じ 3 文書の PR（#780）で行う（[01_requirements.md](01_requirements.md) 1 章）。実装の PR は、その変更を確かめる `_checks/` のスクリプトを足すだけである。

**設計原則:**

-   **書き直しは、未実装を述べる部分を除くことにとどめ、新しい事実を足さない。** 項目がすでに述べている内容のほかに事実を足さないと、要件定義の際に決めたためである（[01_requirements.md](01_requirements.md) 1 章）。
-   **ADR-0024 のほかの部分には触れない（AC-02・AC-03）。** 変更を「結果」の 1 項目と「経緯」の 1 項目に限ると、ほかの部分が変わらないことをレビュアーが diff で確かめやすい。

**設計の際に決めたこと（2026-11-10）:**

-   要件が開いたままにした設計の選択はない。書き直した文の形は、要件定義の際に決めたことで決まっている（[01_requirements.md](01_requirements.md) 1 章）。書き直した文と「経緯」の項目は、本書と同じ PR で ADR-0024 に入れた。

概念モデルの Mermaid の図は省く。変わるのは 1 つの文書の 1 項目だけで、コンポーネントの関係がない（`docs/dev/conventions/requirements_process.md`「Simple Process」の「May be omitted」）。
