### 3.4. `japrose`（AC-08〜AC-11・AC-17）

#### 3.4.1. 確かめる行を決める

「Preparation」（`.claude/commands/japrose.md:38-54`）に、次の手順を足す。

1.  `git rev-parse --show-toplevel` でリポジトリの最上位を求め、対象の文書のパスを最上位からの相対パスにする。対象が最上位の外にあるときは、決められなかったものとする（AC-10）。以下の `git` は、すべて `git -C <最上位> --literal-pathspecs -c core.quotePath=false` の形で呼ぶ。`git ls-tree` と `git diff` のパスは作業ディレクトリから解かれるので、`japrose` がサブディレクトリから呼ばれても、パスが最上位から解かれるようにするためである。`--literal-pathspecs` は、`[` などを含む文書名がパターンとして読まれ、あるパスをないと誤らないようにするためである。`core.quotePath=false` は、パスの引用で出力の形が変わらないようにするためである。
2.  `git merge-base origin/main HEAD` で merge-base を求める。`git fetch` はしない。呼び出し元のコマンドは、ブランチを用意するときに `origin/main` を取ってきている（`_lib/task-pr-handoff.md` の Part A）。
3.  `git ls-tree --name-only <base> -- <path>` で、merge-base に対象のパスがあるかを確かめる。出力が空なら、パスはない。出力がそのパスの 1 行なら、パスはある。
4.  パスがないときは、`git diff --name-status --no-renames --no-color <base> --` で、ブランチが消したファイル（`D` の行）があるかを確かめる。1 つでもあれば、対象の文書は動かした先かもしれないので、決められなかったものとする（AC-10）。名前の変更の検出（`-M`）に頼らないのは、中身を大きく書き換えた移動や、検出の上限を超えた移動が、名前の変更として報告されないためである。`git add` していない `mv` も、元のパスの `D` として現れる。消したファイルがなければ、すべての行を足した行とみなす。
5.  パスがあるときは、`env -u GIT_DIFF_OPTS git --no-pager diff --no-color --no-ext-diff --no-textconv --text --unified=0 --inter-hunk-context=0 <base> -- <path>` の、行頭が `@@ -a[,b] +c[,d] @@` の行から、作業ツリーの側の範囲を読む（2 つ目の `@@` の後の文字は読まない）。`d` がないときは 1 行、`d` が 0 のときは行がない（削除だけ）。それらの行を、足した行と変えた行とする。これらの引数は、git の設定や環境変数で、色・外部の差分の道具・前後の行数・近いハンクのまとめ方・バイナリの扱いが変わらないようにするためで、`docs/dev/conventions/requirements_process.md`「Fixed commands」と同じ考えである。
6.  1〜5 の `git` は、どれも終了状態 0 を想定する。0 以外で終わったとき、または 3〜5 で想定しない形の出力を出したときは、決められなかったものとする（AC-10）。

この手順は、`japrose` が直しを入れる前に 1 回だけ行い、太字の項目は 1 回目の確認でだけ確かめる（`japrose.md:122-123` の 2 回目以降は、直しの確かめである）。`japrose` 自身の表現の直しが変えた行は、ブランチで足した行と変えた行ではないので、太字の確認をかけない（AC-09）。

`git diff` は作業ツリーとの差分を出すので、まだコミットしていない変更も含む。`japrose` は、呼び出し元がコミットした後にも、単独でも呼ばれる（`japrose.md:125-134`）。どちらでも、同じ手順で行を決められる。`main` の上で単独で呼ぶと、merge-base が `HEAD` になり、コミットしていない変更のほかは確かめる行がない。そのときは、0 行だったと報告する（AC-17）。

本書を書く前に、コミット `21aef492` で次を確かめた。

-   `git ls-tree --name-only` は、最上位から呼ぶと、あるパスで終了状態 0 とそのパス、ないパスで終了状態 0 と空の出力を返し、存在しない rev では 128 を返した。サブディレクトリから最上位からのパスで呼ぶと、あるパスでも空の出力を返した（1 で `-C` を使う理由）。
-   `git cat-file -e <base>:<絶対パス>` は 128 を返した（1 で最上位からの相対パスにする理由）。リポジトリの外では、`git ls-tree` は 128 を返した。
-   `-c diff.interHunkContext=5` の下では、`--unified=0` でも 2 つのハンクが 1 つにまとめられ、`--inter-hunk-context=0` を付けると 2 つに分かれた。

#### 3.4.2. サブエージェントに渡す

「Review」の FILES（`japrose.md:76-82`）に、書式の規約と、確かめる行の範囲と 5 の差分のハンクを書いたファイル（スクラッチパッドに置く）を足す（AC-08・AC-09）。ハンクを渡すのは、変えた行の変更がリンク・名前・見出し・誤字の直しだけかを、レビュアーが前の行と比べて判断できるようにするためである。範囲を決められなかったときは、範囲の代わりに、決められなかったこととその理由を書く。

#### 3.4.3. 基準の項目

「Prose-quality checklist」（`japrose.md:90-98`）に、次の内容の項目を日本語で 1 つ足す。

-   確かめる行の中で、太字が規約の太字の規則に合っている。文全体と、文より長いまとまりを太字にしていない。
-   規則の外の固定のラベルは対象外である。
-   確かめる行の外の太字は、指摘しない。太字のまとまりが確かめる行の外の行にまたがるときも、指摘しない（印を外すと、変えていない行を変えるか、片方の印だけが残るため）。変えた行のうち、変更がリンク・名前・見出し・誤字の直しだけの行の太字も、指摘しない。範囲を決められなかったときは、この項目を確かめない。
-   README（`README.md`・`README.en.md`）は規約の対象でないので、この項目を確かめない（AC-01）。

「Purpose」の問題の一覧（`japrose.md:14-36`）にも、太字の使いすぎを 1 つ足す。

#### 3.4.4. 直し方

「Apply Fixes」（`japrose.md:106-123`）に、次の内容を足す。

-   太字の指摘を直すときは、`**` の印だけを外し、文字は変えない（AC-11）。
-   固定のラベルの太字は外さない。
-   確かめる行の外は変えない。
-   範囲を決められなかったときは、確かめなかったことと理由を報告に書く（AC-10）。
-   太字の項目で確かめた行の数を報告に書き、0 行のときはそう書く（AC-17）。

太字の印を外すことは「表現だけを直す」の範囲にあり、Hard constraints（`japrose.md:100-104`）と食い違わない。構造を変える直し（小見出しを足すなど）はしない。
