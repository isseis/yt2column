## 1. 設計の全体像

本タスクでは、書式の規約 `docs/dev/conventions/document_formatting.md` を新しく作り、`CLAUDE.md` と `adr.md` からリンクする。あわせて、`japrose` に太字の確認を 1 項目足す（[01_requirements.md](01_requirements.md) F-001〜F-003）。プログラムのコードは変えない。

設計原則は次の 3 つである。

-   規則は規約の 1 か所に書く。`CLAUDE.md` と `adr.md` には、リンクと、どこに当てはまりやすいかだけを書く（AC-06・AC-07）。同じ規則を 2 か所に持つと、片方だけが直されるためである。
-   `japrose` が太字を確かめる範囲は、ブランチの差分から決める（AC-09）。対象の範囲を、書き手やサブエージェントの判断に任せず、`git` の出力で決めるためである。
-   範囲を決められないときは、確かめない側に倒す（AC-10）。文書全体を確かめると、変えない部分の太字まで外し、「変える部分だけに当てる」決定（AC-02）を破るためである。

**設計の際に決めたこと（2026-11-19）:**

-   設計で新たに人に確かめた判断はない。項目の中の形を規約で決めない判断は、規則の中身なので要件定義書に記録した（[01_requirements.md](01_requirements.md)「要件定義の際に決めたこと」）。

本書の行番号は、コミット `21aef492`（`origin/main`）で確かめた。

概念モデルとシステム構成の Mermaid の図は省く。変わるのは文書と、1 つのコマンドの定義の手順だけで、コンポーネントの関係は変わらない（`docs/dev/conventions/requirements_process.md`「Simple Process」の「May be omitted」）。

### 3.1. 書式の規約（AC-01〜AC-05）

英語で書き、次の節を持つ。見出しの文言は実装で決めてよい。

-   冒頭：規約の目的と、対象の文書。対象は `CLAUDE.md`「Document language」の原則 (a) の日本語の文書で、英語の文書は対象でない（AC-01）。
-   当てる範囲：新しく書く文書と、変更が足すか変える部分に当てる。変えない部分を書き直すことは求めない（AC-02）。
-   太字：太字にしてよいもの、太字にしないもの、規則の外にある固定のラベル（AC-03）。固定のラベルの例として、計画書の `**実装モデル要件**:`、受け入れ基準の `**AC-01**`、handoff の `**扱った箇所:**` を挙げる。例は網羅ではないと書く。
-   項目の多い節：まとめを 1〜2 文で先に書くこと、小見出しか入れ子の箇条書きで構造化すること、項目の中の形は書き手に任せること（AC-04）。短い節の扱いと、テンプレートが決める形の扱い（AC-05）。

規約は、ADR-0013 などの特定の文書を例として名指ししない。名指しした文書が後で変わると、例が古くなるためである。

### 3.4. `japrose`（AC-08〜AC-11）

#### 3.4.1. 確かめる行を決める

「Preparation」（`.claude/commands/japrose.md:38-54`）に、次の手順を足す。

1.  `git merge-base origin/main HEAD` で merge-base を求める。`git fetch` はしない。呼び出し元のコマンドは、ブランチを用意するときに `origin/main` を取ってきている（`_lib/task-pr-handoff.md` の Part A）。
2.  merge-base に対象の文書がなければ（`git cat-file -e <base>:<path>` が失敗すれば）、すべての行を足した行とみなす。
3.  対象の文書があれば、`git diff --unified=0 <base> -- <path>` の出力の `@@` の行から、作業ツリーの側の行番号の範囲を読む。それらの行を、足した行と変えた行とする。
4.  1〜3 のどれかの `git` が、ここに書いた終了状態以外で終わったときは、確かめる行を決められなかったものとする（AC-10）。

`git diff` は作業ツリーとの差分を出すので、まだコミットしていない変更も含む。`japrose` は、呼び出し元がコミットした後にも、単独でも呼ばれる（`japrose.md:125-134`）。どちらでも、同じ手順で行を決められる。

#### 3.4.2. サブエージェントに渡す

「Review」の FILES（`japrose.md:76-82`）に、確かめる行の範囲を書いたファイル（スクラッチパッドに置く）を足す。範囲を決められなかったときは、範囲の代わりにそのことを書く。

#### 3.4.3. 基準の項目

「Prose-quality checklist」（`japrose.md:90-98`）に、次の内容の項目を日本語で 1 つ足す。

-   確かめる行の中で、太字が規約の太字の規則に合っている。文全体と、文より長いまとまりを太字にしていない。
-   規則の外の固定のラベルは対象外である。
-   確かめる行の外の太字は、指摘しない。範囲を決められなかったときは、この項目を確かめない。

「Purpose」の問題の一覧（`japrose.md:14-36`）にも、太字の使いすぎを 1 つ足す。

#### 3.4.4. 直し方

「Apply Fixes」（`japrose.md:106-123`）に、次の内容を足す。

-   太字の指摘を直すときは、`**` の印だけを外し、文字は変えない（AC-11）。
-   固定のラベルの太字は外さない。
-   確かめる行の外は変えない。
-   範囲を決められなかったときは、確かめなかったことを報告に書く（AC-10）。

太字の印を外すことは「表現だけを直す」の範囲にあり、Hard constraints（`japrose.md:100-104`）と食い違わない。構造を変える直し（小見出しを足すなど）はしない。

### 3.5. 変えないもの

-   テンプレート（`docs/tasks/0000_template/`）と、コマンドの定義が書く固定のラベル。
-   既存の文書の、変えない部分。本タスクのほかの文書も含む。
-   `japrose` のほかの基準の項目、Hard constraints、呼び出し元のコマンド。

## 7. テスト戦略

-   規約の中身と、`CLAUDE.md`・`adr.md`・`japrose.md` に足す文の中身（AC-01〜AC-11）は、PR のレビューで読んで確かめる（`manual`）。文書のテストは文の意味を確かめない（`CLAUDE.md`「Testing Strategy」）。
