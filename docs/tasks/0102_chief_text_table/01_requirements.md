## 1. 概要 (Overview)

**目的:** 本書は、chief の状況の表（[0088 要件定義書](../0088_chief_of_staff/01_requirements.md) の F-001、[0093 要件定義書](../0093_chief_status_sheet/01_requirements.md)）を、道具 `chief` が等幅のテキストとして組み、`/chief` のセッションがそれを code block にそのまま貼る形に変える要件を定義する。あわせて、急ぎの度合いの印と状態の文字列を変え、PR の列を足し、質問の pane をタブのラベルで示す。

**背景:**

今の状況の表は次のように作られている。

-   道具は、行ごとの値（`rows` の `urgency`・`position`・`questions`・`running` など）を JSON で返す（`internal/chief/output.go:30-50`）。急ぎの度合いの値は `now`・`later`・`wait` である（`internal/chief/output.go:340-344`）。
-   `/chief` のセッションは、定義の値の表を引いてその値を写し、急・名前・タスク・文書・状態・内容の 6 つの列の Markdown の表にする（`.claude/commands/chief.md:131-202`）。印は「🔴 今」「🟡 後」「🟢 待」である（同 :152-154）。内容の列の文の値は、セッションが「20 文字ほど」で切る（同 :181-187）。
-   「質問で停止」の行の内容の列には、質問ごとに、セッションが質問の文から書いた要点と pane を示し、マージの確認である質問には「マージの確認」を添える（同 :188-190）。pane は `w3:p1` のような Herdr の pane の ID である（形は `internal/chief/herdr.go:62` の例のとおり）。
-   状態の詳細が「マージの確認待ち」になるのは、質問がすべてマージの確認のときだけである。マージの確認とほかの質問が同じ行にあれば「質問で停止」になる（`internal/chief/position.go:255-259`・`:279-282`）。
-   ブランチに開いた PR が 1 つあれば、行の状態によらず `rows[].pr` に入る（`internal/chief/snapshot.go:281-289`、`internal/chief/output.go:242`）。ただし表には、レビュー待ちの行の内容の列にしか示さない（`.claude/commands/chief.md:195`）。
-   Go の文字列の literal は英語である（CLAUDE.md の「Go Idioms」の「Go comments, identifiers, and string literals are English」の項）。chief の道具については、同じ節の 2 つの例外の項が、どちらも道具が出力する文字列を英語のままとする（「the text the tool prints stay English」）。画面の読み取りの例外の項と、タスクの読み取り（`internal/chief/task.go`）の例外の項である。日本語の語は、`/chief` の定義の値の表にある（`.claude/commands/chief.md:149-178`）。
-   CLAUDE.md の「Key Design Patterns」の「Declare, don't infer」は、呼び出し元から来た文字列の中身を調べて振る舞いを選ぶことを禁じ、例外を列挙する。chief の例外は画面の読み取りのファイルに限り、ほかのファイルは画面の読み取りが返す型だけで振る舞いを選ぶと定める。
-   `Sanitize` は、端末を書き換えうる文字を見える形に置き換えるが、改行とタブは残す（`internal/chief/sanitize.go:52-75`・`:86-87`）。
-   `/chief` の定義と道具は、protocol 番号 3 で版を照合する（`internal/chief/records.go:29`、`.claude/commands/chief.md:98`）。

実際に使うと、issue #982 の「背景」のとおり、次の問題がある。

1.  1 行に収まらず、意図しない形で折り返す。絵文字と文字が分かれ、状態とモデル名が折り返す。
2.  Claude Code は Markdown の表の行ごとに区切り線を引くので、罫線が多く、読みにくい。
3.  Claude Code の表では `<br>` がそのまま文字で出るので、セルの中で改行できない。
4.  コマンド名が状態と内容の両方に出る一方、PR の番号はレビュー待ちの行でしか示されない。
5.  「🟢 待」は「人は待っていてよい」の意味だが、「人の対応を待っている」とも読める。
6.  質問の pane が `w3:p1` のような ID で、どのタブか分からない。

対応 issue: [#982](https://github.com/isseis/yt2column/issues/982)（関連: [#890](https://github.com/isseis/yt2column/issues/890)・タスク [0093](../0093_chief_status_sheet/01_requirements.md)、[ADR-0046](../../dev/adr/0046-chief-of-staff.md)）

**本書の記述範囲:** 本書は、表に何をどの形で示すか、どの幅に収めるか、道具と `/chief` の定義の役割の分け方を定める。次の事項は設計（`02_architecture.md`）で決める。

-   道具の出力に足す項目の名前と形
-   文字ごとの表示幅の判定の規則の細部
-   Claude Code が code block の左に取る余白の値と、内容の列の最小の幅
-   herdr のタブの一覧と pane の配置の読み方
-   表が code block を閉じないことを保つ方法
-   テストの手段

要件の段階で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #982 で決めたこと:**

-   **表は道具が組んで出力に含め、`/chief` のセッションは code block にそのまま貼る。値の表を引いて写すことはしない（F-001）。** セッションが写す今の形では、罫線・折り返し・セルの中の改行を思うように扱えないためである。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する（状況の表を道具が組むことは、「道具が値を決め、セッションはそのまま示す」の範囲を広げるため）。
-   **列を罫線で区切らず、空白でそろえ、workspace ごとに 2 行で示し、workspace の間を空行で区切る（F-002）。** 罫線を減らして読みやすくし、セルの中の改行の代わりに 2 行目を使うためである。ADR: ADR-0046 を更新する（上の項にまとめる）。
-   **列は、状態・名前・タスク・PR・内容の 5 つで、この順に並べる。急の列は独立させず、状態の頭に印を付ける。タスクの列の 2 行目に作業項目の文字列を示す（F-002）。** 行は急ぎの度合いの順に並ぶので、状態を左端に置けば印が左端にそろうためである。ADR: なし（表示の細部のため）。
-   **列は文字ごとの表示幅（全角と絵文字は 2）でそろえ、その判定は道具が自前で行う（F-002）。** 外部のモジュールを使えない（CLAUDE.md の「Dependencies」）ためである。ADR: なし（表示の細部のため）。
-   **急ぎの度合いの印を、すぐ「🛑」、あとで「🔶」、待つ「🟢」にし、表の上に凡例を 1 行置く（F-003）。** 色だけでなく形（八角形・菱形・円）でも区別できるようにするためである。CLAUDE.md の「Accessibility」はブラウザ拡張の UI が対象で chief の端末の表示は対象外だが、同じ原則（WCAG 1.4.1、色だけに頼らない）を当てはめる。「⭕」は日本語で「正解・OK」と読まれるので使わない。「⚠️」は異体字セレクタ（U+FE0F）を伴い、端末によって表示幅が変わるので使わない。印だけでは意味が分からないので、凡例を置く。ADR: ADR-0046 を更新する（決定に印の形が書かれているため）。
-   **状態の文字列を縮める。「マージの確認待ち」は「マージ確認」に、「作成中」「`/runpr` 実行中」「実行中」はまとめて「作業中」にする。作業項目の文字列は「要件」「設計」「計画」にし、「（後に指示あり）」は「＋指示」にする（F-003・F-004）。** 幅を詰めるためである。「作業中」にまとめるのは、今は `/runplan` が「作成中」で `/runpr` が「`/runpr` 実行中」と、コマンド名が入るかどうかが非対称で、`/runpr` は作成をしないためである。どのコマンドかは内容の列で、PR を作る前か後かは PR の列で分かる。ADR: なし（表示の細部のため）。
-   **内容の列は、内容を 1 つの文字列に組み、列の幅で折り返して 2 行に流し込む。2 行に収まらなければ、2 行目の末尾を … で切る。英数字の語は、なるべく空白の位置で折り返す（F-004）。** 「20 文字ほど」で切る今のやり方より、2 行を使って多くを示せるためである。ADR: なし（表示の細部のため）。
-   **他の列で分かる PR の番号は、内容の列に添えない。コマンドは引数ごと内容の列に残す（例: `/runpr 981`）（F-004）。** 同じ情報を 2 回示さないためである。コマンドの引数は、issue #982 の目標の画面のとおり、コマンドの一部として残す。コマンドを残すのは、今の作業項目と違うコマンドを人が打っていることに気づけるようにするためである。ADR: なし（表示の細部のため）。
-   **質問の pane は、タブのラベルで `[claude]` のように示す。タブのラベルは `Sanitize` を通す（F-004・F-005）。** pane の ID ではどのタブか分からないためである。タブのラベルは人が変えられる文字列なので、ほかの外から来る値と同じく扱う。初めはタブの番号も添える `[3 claude]` の形にしたが、設計の際にラベルだけに改めた（下の「設計の際に決めたこと」）。ADR: なし（表示の細部のため）。
-   **CLAUDE.md に、道具が日本語を出力してよい例外を足す。ADR-0046 を更新する。protocol 番号を上げるかを決める（F-006）。** 範囲・理由・境界と、protocol 番号は、下の「要件定義の際に決めたこと」で決めた。

**要件定義の際に決めたこと（2026-11-18）:**

-   **進め方は通常の進め方にする。対象外の判断は「対象外ではない」で、上書きはない。** ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
    -   対象外ではない理由: (1) chief が送る入力の範囲も、送る判断の条件も、`.claude/settings.json` の拒否も変えない。外から来る文字列（タブのラベル）が 1 つ増えるが、ほかの値と同じく `Sanitize` を通して表示にだけ使う。(2) `docs/dev/security.md` の規則と前提を変えない。(3) 外部の依存を足さない。表示幅の判定は自前で書く（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Simple Process」の「Excluded changes」）。
    -   それでも通常の進め方にする理由: (1) ADR-0046 の決定（状況の表の項）を変える。(2) 表示幅の判定と折り返しという新しい仕組みを作る。(3) 変更が、道具、`/chief` の定義、chief 利用ガイド、CLAUDE.md、herdr のタブの読み取りの 5 か所に及ぶ。(4) 決める点が多い。
-   **CLAUDE.md の例外の範囲は、状況の表の決まった語（見出し、凡例、状態の文字列、作業項目の文字列、実行中のコマンドが決まらない理由、「＋指示」、件数と「マージ確認」の添え書き、行がないときに示す語）に限る。道具の JSON の表のほかの値、エラーのメッセージ、ほかのサブコマンドの出力、表に入る外から来る値は、英語のままか、来たままにする（AC-26）。** 例外の範囲を、日本語でなければならない表示の語に絞り、境界をはっきりさせるためである。chief の出力全体を日本語にしてよいとする案は、範囲が広く境界があいまいになるので採らない。日本語の語をデータのファイルに置いて Go の literal にしない案は、ファイルが増え、語を誤ったときに気づきにくくなるので採らない。ADR: [ADR-0035](../../dev/adr/0035-language-policy.md) を更新する（経緯。「Go Idioms」の例外を足すたびに経緯に記録してきたため。初めは「なし」と判断したが、Fable の部分レビューの指摘を受け、人が更新に改めた）。
-   **protocol 番号を上げる。値は、実装のときの `main` の値 + 1 とする（AC-25）。** `/chief` の定義が道具の組んだ表を前提にするので、古い道具のままではセッションは表を示せない。番号を上げれば、古い道具は `protocol_mismatch` で断り、入れ直しを促せる（`.claude/commands/chief.md:77-79`）。上げない案は採らない。ADR: なし（このタスクの中で閉じるため）。
-   **表の 1 行の幅は、chief の pane の幅から決める。Herdr から chief の pane の幅を読み、Claude Code が code block の左に取る余白を引いた幅に収める。幅を読めないときは pane の幅を 80 桁とみなす（AC-04・AC-05）。** 道具は `/chief` のセッションの Bash ツールから呼ばれ、標準出力はパイプで、端末ではない。このため、端末の大きさを通常の方法では取れない（2026-11-18 に確かめた。`tty` は `not a tty`、`$COLUMNS` は `0`、`/dev/tty` は開けず、`tput cols` は既定の 80 を返すだけだった）。一方、`herdr pane layout --pane <ID>` は pane の幅（`rect.width`）を返す（同日に確かめた）。80 桁に固定する案は、狭い pane では行が折り返して崩れるので採らない。`/chief` が引数で幅を渡す案は、呼び方と許可の規則が増えるので採らない。ADR: ADR-0046 を更新する（状況の表の項にまとめる）。
    -   受け入れること: 内容の列が最小の幅（設計で決める）を取れないほど pane が狭いときは、最小の幅のまま組み、行が pane からはみ出すことを受け入れる。ラウンドの後に人が pane の幅を変えた表は、次のラウンドまで古い幅のままである（AC-24 で chief 利用ガイドの既知の制限に書く）。
-   **名前の列の幅は、表の行のうち最も長い名前に合わせ、20 桁を上限とする。20 桁を超える名前は … で切る（AC-08）。** 名前の長い workspace が 1 つあるだけで内容の列が狭くなるのを防ぐためである。切らない案は採らない。ADR: なし（表示の細部のため）。
-   **1 つのタブに pane が 2 つ以上あっても、pane の ID も順番も添えず、`[claude]` のまま示す（AC-18）。** 人が選んだ。どの pane かは、質問を選んだときの示し方（0088 要件定義書の AC-25）で分かる。pane の ID を添える案と、タブの中の順番を示す案（タブの番号を示していたときの形では `[3.2 claude]`）は採らない。ADR: なし（表示の細部のため）。
-   **タブが引けないとき（タブの一覧を読めない、pane のタブが一覧にない）は、今の pane の ID を `[w3:p1]` のように示し、行の状態は変えない（AC-19）。** タブは表示にだけ使い、何を送るかも行の状態も左右しないためである。ADR: なし（表示の細部のため）。
-   **表の中の値に含まれる改行とタブは、表の中でだけ空白 1 つにする（AC-17）。** 質問の文は複数行になりえ、そのままでは表の行が崩れる。全文は、今までどおり道具の出力と、質問を選んだときの示し方にある。`\n` のような見える形にする案は、読みにくいので採らない。ADR: なし（表示の細部のため）。
-   **1 つの行に質問が 2 つ以上あるときは、道具の順で最初の質問だけを示し、件数を頭に添える（例: `2 件 [claude] …`）（AC-16）。** 2 行に収めつつ、ほかにも質問があることを示すためである。すべての質問を続けて流し込み … で切る案は採らない。2 つ目以降の質問が、切られて分からなくなるためである。ADR: なし（表示の細部のため）。
-   **マージの確認とほかの質問が同じ行にあるときは、道具の順で最初のマージの確認を先に示し、頭に「マージ確認」を添える（AC-16）。** 状態の列は「質問で停止」になるので（`internal/chief/position.go:279-282`）、添えないとマージの確認が表から消えうる。0093 要件定義書の AC-18 の、マージの確認であることを添える決まりを保つためである。添える印をやめる案は採らない。ADR: なし（表示の細部のため）。
-   **質問の要点は、質問の文（道具の出力の `questions[].text`）をそのまま流し込み、2 行に収まらない分を … で切る。質問の種類によらず同じにする（AC-14）。** これまで要点はセッションが書いていたが、道具は要約しない。文の 1 行目だけを示す案は採らない。ADR: なし（表示の細部のため）。
-   **表示幅の数え方と内容の列の折り返しは、値の中身で振る舞いを選ぶので、CLAUDE.md の「Declare, don't infer」に例外を足し、範囲・理由・境界を書く（AC-28）。** 配置はこの規則の対象外だと述べて例外の文を直す案は採らない。外から来る値の中身で振る舞いを選ぶ場所は、例外として名指して範囲を限るのがこの規則の書き方だからである。ADR: ADR-0046 を更新する（chief の「Declare, don't infer」の例外を決定に記録しているため。初めは「なし」と判断したが、Fable の部分レビューの指摘を受け、人が更新に改めた）。
-   **`/chief` の定義は、道具の表の文字を変えずに示すと定め、それでも写しが機械的には保証されないことを、残る危険として受け入れる（AC-03、4.3）。** 表を人に示すのはセッションで、道具はセッションの写しを確かめられない。写し違いを見つける仕組みを求める案は採らない。ADR: ADR-0046 を更新する（結果に残る危険を書く）。

**設計の際に決めたこと（2026-11-18）:**

-   **質問の pane がどのタブにあるかは、`herdr agent list` の出力から読み、その境界を 4.2 に足す。AC-19 の「タブが引けないとき」に、pane がどのタブにあるかを読めないときを加える（AC-18・AC-19・AC-23）。** 人が選んだ。呼び出しを増やさず、読めなくても表示が pane の ID に戻るだけにするためである。ADR: なし（読み取りの細部のため）。
-   **Herdr の pane の配置から読む幅に、上限 1000 を設ける（4.2）。** 形の正しい出力でも、とても大きな幅が来ると、区切り線が巨大になり、道具がメモリーを使い切ってラウンドが失敗しうる（4.3 に反する）。1000 はふつうの端末の幅を十分に超える。ADR: なし（読み取りの細部のため）。
-   **タブの表示から、タブの番号を除き、ラベルだけを `[claude]` のように示す（AC-18）。** Herdr の画面にはタブの番号が出ないので、人は番号でタブを探せない。そのうえ、Herdr のタブの一覧の `number` は、タブを作った順の通し番号で、画面での並びの位置とは限らない（2026-11-18 に herdr 0.9.1 で確かめた。chief の workspace では、`tab_id` が `wC:t1` と `wC:tG` の 2 つのタブの `number` が 1 と 16 だった）。番号をそのまま示す案と、workspace の中での並びの位置を示す案は採らない。前者は画面と対応しない番号を示すことになり、後者はタブの一覧の並びが画面の並びと同じかを確かめていないためである。ADR: なし（表示の細部のため）。

**実装の際に決めたこと（2026-11-19）:**

-   **使える幅から引く余白は、chief のタブを分割していなければ 2 桁、分割していれば 4 桁とする。分割しているかは、Herdr の pane の配置の `splits` が空かどうかで読む（AC-04・4.2）。** 人が選んだ。実物の確かめ（[03_implementation_plan.md](03_implementation_plan.md) §7「PR-1 の実行の記録」）で、分割していない pane では「pane の幅 − 2」の行が収まったが、分割した pane では、Herdr が pane の枠を `rect` の中に描くので、「pane の幅 − 4」までしか収まらなかった。拡大（zoom）したときは、`rect.width` が分割したときの幅のままで、描かれる幅はそれより広かった。分割しない使い方が主なので、そのときの幅は変えずに最適にし、分割したときもはみ出さないようにする。いつも 4 桁を引く案は、主な使い方で右の 2 桁が空くので採らない。分割したときのはみ出しを既知の制限とする案は、分割した chief で長い行が毎回折り返すので採らない。拡大したときに `area` の幅を読む案は、読むメンバーが増え、拡大の規則が 1 回の観測にしか拠らないので採らない。拡大したときは、表が画面より狭く組まれるが、はみ出さないので受け入れる。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する（決定が「Claude Code の code block の余白を引いた幅」と述べているため）。
-   **タスク完了の行のうち、chief が workspace の削除を提案している行は、内容に決まった語 `削除を提案` を示す。AC-14 のタスク完了の行と、AC-26 の例外の語の範囲をこの形に改めた（AC-14・AC-26）。** 人が選んだ。0092 要件定義書の AC-20 は、chief が作った workspace のタスクが完了した行に「削除を提案」と示すことを求め、`/chief` の定義もそれを示していた。本書の AC-14 は、その示し方が定義に入る前の定義（タスク完了は何も示さない）に合わせて書かれ、取りやめを人が決めた記録はなかった（Fable の部分レビューの指摘）。削除の提案は一覧に残るが、表で完了したタスクのどれが消せるかを読めるように残す。表から除く案は、承認済みの 0092 の AC-20 の示し方を理由なく変えるので採らない。ADR: なし（表示の細部のため）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   状況の表を、意図しない折り返しも罫線の重なりもなく、workspace ごとに 2 行で一覧できるようにする。
-   急ぎの度合いを色だけでなく形でも見分けられ、その意味を表の上で読めるようにする。
-   PR の番号と、質問を待っているタブを、表から直接読めるようにする。
-   表を組む判断を道具に置き、セッションが値を写したり切ったりしないようにする（ADR-0046 の「道具が決め、セッションは示す」を保つ）。

### 2.2. スコープ (In Scope)

-   道具が表を組んで出力に含めること（F-001）
-   表の形、列、幅（F-002）
-   急ぎの度合いの印と状態の文字列（F-003）
-   内容の列（F-004）
-   表に入る外から来る値の扱い（F-005）
-   `/chief` の定義、chief 利用ガイド、CLAUDE.md、ADR-0046 の更新と、protocol 番号（F-006）

### 2.3. スコープ外 (Out of Scope)

-   モデル名の短縮。道具の側で短い名前を宣言する別の作業である。内容を 2 行に流し込むので、急ぎは下がる（issue #982 の「対象外」）。
-   経過時間（最後の動きからの時間）の列（issue #982 の「対象外」）。
-   人の判断を待つものの一覧（選択肢）、通知、表の下の項目（送信の結果、引き継ぎ、送信の停止、まだ答えのない問い、`problems`）の形。pane の示し方（`w3:p1`）も、これらの中では変えない（issue #982 の「対象外」）。
-   道具が返す読めなかったもの（`unreadable`）と、送れない提案の理由（`problem`）の文字列の言葉。今のまま英語で示す（「要件定義の際に決めたこと」の例外の範囲の項）。
-   急ぎの度合いの判定、行の並べ方、作業項目の表示と状態の詳細の決め方（0093 要件定義書の F-001〜F-004）。本書は、それらの値の示し方だけを変える。
-   `/chief once` で表が見えないこと（[#968](https://github.com/isseis/yt2column/issues/968) で扱う）。

## 3. 機能要件 (Functional Requirements)

本書の用語は、0088 要件定義書と 0093 要件定義書の 3 章に従う。加えて、本書では次の用語を使う。

-   **表**: 道具が組む状況の表のテキスト全体。凡例、見出し、区切り線、workspace ごとの 2 行からなる。
-   **表示幅**: 等幅の端末で文字が占める桁の数。全角の文字と絵文字は 2 桁、ASCII の文字は 1 桁である。細部の規則は設計で決める（design_handoff.md の H-02）。
-   **使える幅**: 表の 1 行が収まるべき表示幅（AC-04）。
-   **状態の文字列**: 状態の列に印と並べて示す語（AC-12）。0088 要件定義書の「状態」（行の `state`）とは別で、状態の詳細から決まる。
-   **タブの表示**: 質問の pane を示す `[<タブのラベル>]` の形（AC-18）。

### 3.1. 機能一覧

#### F-001: 道具が表を組み、`/chief` はそのまま示す

道具が組み上がった表を出力に含め、`/chief` のセッションはそれを手を加えずに示す。

**Acceptance Criteria**:
-   **AC-01**: 道具 `chief` の `snapshot` と `tick` の出力は、今の項目に加えて、組み上がった表を持つ。表の workspace の並びは、`rows` の並びと同じである。
-   **AC-02**: 道具の出力の `rows` の各項目（急ぎの度合い、作業項目の表示と状態の詳細、番、質問、実行中のコマンドなど）の値と意味は変わらない。表に示す値は、同じ出力の `rows` の値と食い違わない。
-   **AC-03**: `/chief` の定義は、ラウンドごとに、道具が返した表を code block に入れ、表の文字を 1 文字も変えずに示すと定める。値の表を引いて値を写すこと、値を切ること、行を並べ替えること、列を足すか除くこと、空白を詰めるか足すことは、手順に含めない。`/chief` の定義の手順 2（One round）の差分は、表の示し方（項目 2）を、道具の表を code block で示すことに置き換えることと、`--protocol` の値（AC-25）だけである。送信の結果（項目 1）、表の下（項目 3）、通知（項目 4）は変わらない。

#### F-002: 表の形と幅

表の行の並び、列、幅を定める。

**Acceptance Criteria**:
-   **AC-04**: 表のどの行も、表示幅が使える幅以下である。使える幅は、chief の pane の幅（Herdr から読む）から余白を引いた値である。余白は、Claude Code が code block の左に取る余白に、chief のタブを分割しているときは Herdr が分割した pane に描く枠を加えたものである。ただし AC-05 の内容の列の最小の幅を守るために、使える幅を超えることがある（AC-05）。
-   **AC-05**: chief の pane の幅を読めないとき（Herdr の失敗、読めない形）は、pane の幅を 80 桁とみなして使える幅を決める。この場合も、表は示され、ラウンドは失敗しない。内容の列が最小の幅（設計で決める）を取れないほど使える幅が狭いときは、内容の列を最小の幅として表を組み、行が使える幅を超えることを受け入れる。
-   **AC-06**: 表は、上から次の順に並ぶ。
    1.  凡例の 1 行: `🛑 すぐ  🔶 あとで  🟢 待つ`
    2.  空行
    3.  見出しの 1 行: 状態・名前・タスク・PR・内容
    4.  区切り線の 1 行（`─` を並べたもの）
    5.  workspace ごとの 2 行。workspace と workspace の間に空行を 1 行置く
-   **AC-07**: 列は、状態・名前・タスク・PR・内容の順に並び、罫線で区切らず、空白でそろえる。同じ列は、見出しとすべての行で、同じ表示幅の位置から始まる。全角の文字と絵文字は 2 桁として数える。
-   **AC-08**: 名前の列の幅は、表のすべての名前と見出しのうち最も長いものの表示幅で、20 桁を上限とする。20 桁を超える名前は、末尾を … にして 20 桁以内に切る。
-   **AC-09**: workspace ごとの 2 行は、次の値を持つ。値のない欄は空白である。

    | 列 | 1 行目 | 2 行目 |
    |---|---|---|
    | 状態 | 急ぎの度合いの印と状態の文字列（AC-11・AC-12） | 空 |
    | 名前 | workspace の名前（AC-08） | 空 |
    | タスク | タスク番号。タスクがなければ `-` | 作業項目の文字列（AC-13） |
    | PR | ブランチで開いている PR の番号を `#980` の形で。なければ `-`。開いた PR が 2 つ以上あるときも `-` で、その行は読めなかったものとして要確認になる（`internal/chief/snapshot.go:283-286`） | 空 |
    | 内容 | 内容の文字列の 1 行目（AC-14・AC-15） | 内容の文字列の 2 行目 |

-   **AC-10**: 行が 1 つもないときも、表は示される。その形は設計で決める（design_handoff.md の H-06）。

#### F-003: 急ぎの度合いの印と状態の文字列

状態の列と、タスクの列の 2 行目に示す語を定める。

**Acceptance Criteria**:
-   **AC-11**: 状態の列は、急ぎの度合いの印と状態の文字列を、空白 1 つで区切って示す。印は、急ぎの度合いが「すぐ」なら `🛑`、「あとで」なら `🔶`、「待つ」なら `🟢` である。急ぎの度合いは道具が今決めている値（0093 要件定義書の F-001）である。
-   **AC-12**: 状態の文字列は、状態の詳細（0093 要件定義書の AC-09）から次のように決まる。

    | 状態の詳細 | 状態の文字列 |
    |---|---|
    | 要確認 | 要確認 |
    | 作成待ち | 次を提案 |
    | 作成中、`/runpr` 実行中、実行中 | 作業中 |
    | マージの確認待ち | マージ確認 |
    | 質問で停止 | 質問で停止 |
    | レビュー待ち | レビュー待ち |
    | タスク完了 | タスク完了 |

-   **AC-13**: 作業項目の文字列は、0093 要件定義書の AC-07 の作業項目の表示から次のように決まる。

    | 作業項目の表示 | 示し方 |
    |---|---|
    | 要件定義書 | 要件 |
    | 設計書 | 設計 |
    | 計画書 | 計画 |
    | PR-N | PR-N |
    | なし | なし |
    | 要確認 | 要確認 |
    | -（タスクがない） | - |

#### F-004: 内容の列

内容の列に示す文字列と、その流し込み方を定める。

**Acceptance Criteria**:
-   **AC-14**: 内容の文字列は、状態の文字列（AC-12）ごとに次のように組む。PR の番号を別に添えることはしない。コマンドは引数ごと示す（例: `/runpr 981`。0093 要件定義書の AC-13）。値がない（null か空の）部分は示さず、モデルが空なら括弧も示さない。

    | 状態の文字列 | 内容の文字列 |
    |---|---|
    | マージ確認、質問で停止 | 質問のタブの表示（AC-18・AC-19）と質問の文（`questions[].text`）を、空白 1 つで区切ったもの。質問の種類（1 つを選ぶ問い、複数を選ぶ問い、タブのある問い、権限の確認）によらず同じ。示す質問と添え書きは AC-16 |
    | レビュー待ち | PR の題名。PR がなければ空 |
    | 次を提案 | 提案するコマンドと、モデルを括弧に入れたもの。送れない提案なら、送れない理由（`problem`）。提案がなければ空 |
    | 作業中 | 実行中のコマンド。後の指示があれば「＋指示」を添え、モデルが決まれば括弧に入れて添える（0093 要件定義書の AC-14 のモデルの条件）。実行中のコマンドが決まらなければ、決まらない理由（AC-20） |
    | 要確認 | 読めなかったもの（`unreadable`） |
    | タスク完了 | chief が削除を提案している行（0092 要件定義書の AC-20）なら `削除を提案`、そうでなければ空 |

-   **AC-15**: 内容の文字列は、内容の列の幅で折り返して 2 行に流し込む。各行の表示幅は内容の列の幅以下である。2 行に収まらないときは、2 行目の末尾を … にして、2 行目の表示幅が内容の列の幅以下になるように切る。ここで語とは、空白を含まない ASCII の印字できる文字の並び（`/runpr`・`feat(chief):`・`#980` など）である。語は、その語が 1 行に収まる限り、語の途中で折り返さない。空白の位置で折り返したときは、その空白を 2 行目の頭に示さない。語の直前が空白でないとき（ASCII でない文字との境目）の扱いは設計で決める（design_handoff.md の H-06）。1 行に収まらない語は、語の途中で折り返す。表示幅 2 の文字が 1 行目の残りの幅に入らないときは、その文字から 2 行目に送る。`Sanitize` が作るエスケープ（`\x1b`・`\\` など）の途中では、折り返しも切りもしない。
-   **AC-16**: 示す質問は 1 つで、マージの確認である質問があれば道具の順で最初のマージの確認、なければ道具の順で最初の質問である。状態の文字列が「質問で停止」で、示す質問がマージの確認なら、頭に `マージ確認` を置く。1 つの行に質問が 2 つ以上あるときは、さらにその前に `<件数> 件` を置く。それぞれ空白 1 つで区切る（例: 状態の文字列が「質問で停止」の行では `2 件 マージ確認 [claude] …`、「マージ確認」の行では `2 件 [claude] …`）。示さない質問は、表に示さない。
-   **AC-17**: 表に入る値に含まれる改行とタブは、表の中でだけ、それぞれ空白 1 つとして示す。道具の出力の `rows` の値は変わらない。
-   **AC-18**: 質問のタブの表示は `[<タブのラベル>]` である。タブのラベルは、Herdr のタブの一覧の、その pane のタブのものである。タブの番号は示さない。1 つのタブに pane が 2 つ以上あっても、同じ形で示し、pane の ID も順番も添えない。タブのラベルが空のときの形は設計で決める（design_handoff.md の H-06）。
-   **AC-19**: タブが引けないとき（タブの一覧を読めない、読めない形である、pane がどのタブにあるかを読めない、pane のタブが一覧にない）は、タブの表示の代わりに `[<pane の ID>]`（例: `[w3:p1]`）を示す。この場合も、行の状態、急ぎの度合い、送れるかどうかは変わらず、ラウンドは失敗しない。
-   **AC-20**: 実行中のコマンドが決まらない理由（`running_unknown`）は、今の `/chief` の定義の示し方（`.claude/commands/chief.md:171-178`）と同じ次の言葉で示す: `no_session` はセッション不明、`unsupported_path` は記録の場所が不明、`unreadable` は記録を読めない、`over_cap` は記録が大きすぎる、`partial_line` は記録の書き込み中、`not_task_command` は読めるタスクのコマンドなし、`no_sent_command` は送ったコマンドの記録なし（OpenCode）、`panes_disagree` は pane ごとに異なる。後の指示は「（後に指示あり）」ではなく「＋指示」と示す。

#### F-005: 表に入る外から来る値

表に入る信頼できない値と、Herdr から読む値の扱いを定める。

**Acceptance Criteria**:
-   **AC-21**: 表に入る外から来る値（workspace の名前、PR の題名、質問の文、送れない理由、読めなかったもの、モデルの名前、タブのラベル、pane の ID）は、どれも `Sanitize` を通した後のものである。
-   **AC-22**: 表に入る値がどんな文字列でも（バッククォートの並び ```` ``` ```` やチルダの並び `~~~` を含む行、空白で始まる値、`#`・`|`・`-` で始まる値を含む）、`/chief` の定義の示し方で貼った code block は、表の終わりより前で閉じず、表のどの行も code block の外の Markdown として描かれない。
-   **AC-23**: Herdr のタブの一覧と pane の配置の出力は、信頼できない入力として扱う。受け付ける形、使うメンバー、上限、形に合わないときの扱いは、4.2 のとおりである。形に合わない出力は、直したり一部だけを使ったりせず、AC-05 と AC-19 の「読めない」として扱う。

#### F-006: 文書、規則、版の更新

表の変更に合わせて更新する文書、規則、protocol 番号を定める。

**Acceptance Criteria**:
-   **AC-24**: chief 利用ガイド（`docs/dev/guides/chief_guide.md`）の 3.1 は、本書の表の形（凡例、5 つの列、2 行目、幅の決め方、内容の列の流し込みと切り方、タブの表示）を説明する。同じガイドの 8 章（既知の制限）は、次を挙げる。Claude Code の code block の余白が変わると表が折り返しうること、pane の幅を変えた表は次のラウンドまで古い幅のままであること、狭い pane では行がはみ出しうること、セッションの写しは機械的には保証されないこと。
-   **AC-25**: 道具の protocol 番号、`/chief` の定義が渡す `--protocol` の値、chief 利用ガイドの 2 章の今の番号は、どれも実装のときの `main` の値 + 1 である。
-   **AC-26**: CLAUDE.md の「Go Idioms」に、chief の道具が状況の表の決まった語を日本語で出力してよい例外が、範囲・理由・境界とともにある。範囲は、表の見出し、凡例、状態の文字列、作業項目の文字列、実行中のコマンドが決まらない理由、「＋指示」、件数と「マージ確認」の添え書き、「削除を提案」、行がないときに示す語（AC-10）に限る。これらは表の文字列として道具の出力に入る。道具の出力のほかの値、エラーのメッセージ、ほかのサブコマンドの出力、表に入る外から来る値は、範囲に含めない。これは「Go Idioms」の「Go comments, identifiers, and string literals are English」の項（Go の文字列の literal は英語）の例外である。chief の画面の読み取りの例外の項と、タスクの読み取りの例外の項の「道具が出力する文字列は英語」の文は、どちらもこの例外と食い違わない。
-   **AC-27**: ADR-0046 の決定（状況の表の項）は、表を道具が組み、`/chief` のセッションがそのまま示すことと、印が `🛑`・`🔶`・`🟢` であることを述べ、経緯にその変更がある。
-   **AC-28**: CLAUDE.md の「Declare, don't infer」に、chief の表を組む処理が表に入る値の中身を調べて振る舞いを選ぶ例外が、範囲・理由・境界とともにある。範囲は、文字ごとの表示幅の数え方と、内容の列と名前の列の折り返しと切る位置に限る。境界は、その結果を表の配置にだけ使い、何を送るか、行の状態、急ぎの度合いを左右しないことである。chief の画面の読み取りの例外の項の、ほかのファイルは型だけで振る舞いを選ぶという文は、この例外と食い違わない。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   ラウンドごとに、Herdr への読み取りの呼び出しが 2 つ増える（タブの一覧と、chief の pane の配置）。どちらもローカルのソケットへの問い合わせで、ネットワークの操作ではない。今のラウンドでも Herdr の pane の一覧などを読んでいる（`internal/chief/herdr.go:627-680`）。そのため、CLAUDE.md の「Performance」の基準で、仕組みを足して減らすほどの費用ではないとみなす。
-   表を組む処理は、行の数と値の長さに比例する時間で終わる。

### 4.2. セキュリティ (Security)

-   N/A。条件付きのガイド（`docs/dev/security.md`）の適用条件のどれにも当たらない。適用条件は、外部コマンド `yt-dlp` の呼び出し、API キー、キャッシュのディレクトリ、LLM API へのネットワークの送信、信頼できない文字列のプロンプトや記事への埋め込みである。
-   chief が送る入力の範囲、送る判断の条件、`.claude/settings.json` の拒否は変えない。表と、タブと pane の幅の読み取りは、表示にだけ使い、何を送るかを左右しない。
-   **表に入る値の境界（AC-21・AC-22）:** 表に入る値は、ほかのエージェント、GitHub、Herdr、人が書いた信頼できない文字列を含む（ADR-0046 の背景）。端末を書き換えうる文字は、今と同じく `Sanitize` で見える形にする。改行とタブは表の中で空白にする（AC-17）。値の中身がどうであっても、code block を閉じたり、表の外の Markdown として描かれたりしない（AC-22）。
-   **Herdr のタブの一覧の境界（AC-18・AC-19・AC-23）:** `herdr tab list` の出力は、Herdr が書く外部の値である。
    -   受け付ける形: 今の Herdr の出力の読み取り（`internal/chief/herdr.go:190-230`）と同じく、正しい UTF-8 の、ちょうど 1 つの JSON のオブジェクトで、後ろに続くデータがなく、文字列に対になっていないサロゲートのエスケープ（`\uD800`〜`\uDFFF`）を含まず、`error` のメンバーを持たず、`id` がタブの一覧の呼び出しのものと等しく、`result` がオブジェクトで、`result` の `type` がタブの一覧の種類と等しく、タブの配列を持つ形。
    -   使うメンバー: 封筒（`id` と `result` を持つ最上位のオブジェクト）の `id` と `result`、`result` の `type` とタブの配列、各タブの `tab_id`（今の pane の一覧の読み取りと同じ形、`internal/chief/herdr.go:658`）と `label`（文字列）。封筒、`result`、各タブのほかのメンバー（`number`・`agent_status`・`focused`・`pane_count` など）は使わず、Herdr が足すことを見込んで拡張できるものとする。使うメンバーが欠けているか、重なっているか、型か形が違うとき、同じ `tab_id` のタブが 2 つ以上あるときは、一覧全体を読めないものとする。
    -   拒否の対応: 今の Herdr の出力の読み取りと同じく、読めない Herdr の出力の sentinel error（`internal/chief/herdr.go:19`）にする。
    -   上限: 今の外部コマンドの出力の上限（`internal/chief/runner.go:52`、4 MiB）をそのまま使い、超えた出力は読めないものとする。
    -   読めないとき: 新しい拒否の理由やエラーにせず、AC-19 のとおり pane の ID を示す。
-   **Herdr の pane の配置の境界（AC-04・AC-05・AC-23）:** `herdr pane layout --pane <ID>` の出力は、Herdr が書く外部の値である。
    -   受け付ける形: タブの一覧と同じ封筒の形で、`id` が pane の配置の呼び出しのものと等しく、`result` の `type` が pane の配置の種類と等しく、chief の pane の配置を持つもの。
    -   使うメンバー: 封筒の `id` と `result`、`result` の `type`、chief の pane の ID と、その幅（1 以上 1000 以下の整数。とても大きな幅で表が巨大にならないようにするため）、タブの分割の一覧（配列。空かどうかだけを使い、要素は読まない。AC-04 の余白を決めるため）。どのメンバーの幅を使うかは設計で決める（design_handoff.md の H-04）。ほかのメンバーは使わず、拡張できるものとする。使うメンバーが欠けているか、重なっているか、型が違うとき、chief の pane を表す項目がちょうど 1 つでないときは、読めないものとする。
    -   拒否の対応: タブの一覧と同じ sentinel error にする。
    -   上限: タブの一覧と同じ。
    -   読めないとき: 新しい拒否の理由やエラーにせず、AC-05 のとおり 80 桁とみなす。
-   **Herdr のエージェントの一覧の pane とタブの対応の境界（AC-18・AC-19・AC-23）:** 質問の pane がどのタブにあるかは、ラウンドが今も読んでいる `herdr agent list` の出力から読む。呼び出しは増やさない。
    -   受け付ける形: 今のエージェントの一覧の読み取りと同じ封筒の形。
    -   使うメンバー: 各エージェントの `pane_id` と `tab_id`（どちらも今の Herdr の出力の読み取りと同じ ID の形）。同じ `pane_id` が 2 つ以上あるとき、使うメンバーが欠けているか型か形が違うときは、対応全体を読めないものとする。
    -   拒否の対応・上限: タブの一覧と同じ。
    -   読めないとき: エージェントの一覧の読み取り（今のまま）は失敗させず、AC-19 のとおり pane の ID を示す。
-   読み方の細部（`type` の値、配置のどのメンバーの幅を使うか）は、設計で実物の出力から決める（design_handoff.md の H-04）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   タブの一覧か pane の配置を読めないラウンドでも、表は示され、ラウンドは失敗しない（AC-05・AC-19）。
-   表を組めないことで、自動送信、中継、リセットが止まることはない。表は表示にだけ使う。
-   **残る危険（受け入れる）:** 表を人に示すのは `/chief` のセッションで、道具はセッションが表を変えずに写したかを確かめられない。`/chief` の定義は表の文字を変えないと定める（AC-03）が、写し違いは機械的には防げない。全文の値は道具の出力にある。

### 4.4. 互換性 (Compatibility)

-   protocol 番号を上げる（AC-25）。古い道具は `/chief` の新しい定義の呼び出しを `protocol_mismatch` で断り、`/chief` は `make install-chief` での入れ直しを促す（`.claude/commands/chief.md:77-79`）。
-   出力の `rows` の項目は変えない（AC-02）。`rows` を読むのは `/chief` の定義（`.claude/commands/chief.md:104-218`）だけである。

### 4.5. 保守性 (Maintainability)

-   表の決まった語は道具の中にあり、変えるには道具を直して入れ直す（ADR-0046 の結果に足す）。
-   日本語の literal を置く範囲は、CLAUDE.md の例外（AC-26）で限る。どのファイルに置くかは、設計で決める（design_handoff.md の H-07）。
