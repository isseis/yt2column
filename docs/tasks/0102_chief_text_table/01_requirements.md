## 1. 概要 (Overview)

**目的:** 本書は、chief の状況の表（[0088 要件定義書](../0088_chief_of_staff/01_requirements.md) の F-001、[0093 要件定義書](../0093_chief_status_sheet/01_requirements.md)）を、道具 `chief` が等幅のテキストとして組み、`/chief` のセッションがそれを code block にそのまま貼る形に変える要件を定義する。あわせて、急ぎの度合いの印と状態の文字列を変え、PR の列を足し、質問の pane をタブの番号とラベルで示す。

**背景:**

今の状況の表は次のように作られている。

-   道具は、行ごとの値（`rows` の `urgency`・`position`・`questions`・`running` など）を JSON で返す（`internal/chief/output.go:30-50`）。急ぎの度合いの値は `now`・`later`・`wait` である（`internal/chief/output.go:340-344`）。
-   `/chief` のセッションは、定義の値の表を引いてその値を写し、急・名前・タスク・文書・状態・内容の 6 つの列の Markdown の表にする（`.claude/commands/chief.md:131-202`）。印は「🔴 今」「🟡 後」「🟢 待」である（同 :152-154）。内容の列の文の値は、セッションが「20 文字ほど」で切る（同 :181-187）。
-   「質問で停止」の行の内容の列には、質問の要点と pane を示す（同 :189-191）。pane は `w3:p1` のような Herdr の pane の ID である（`internal/chief/herdr.go:69`）。
-   ブランチに開いた PR が 1 つあれば、行の状態によらず `rows[].pr` に入る（`internal/chief/snapshot.go:281-289`、`internal/chief/output.go:242`）。ただし表には、レビュー待ちの行の内容の列にしか示さない（`.claude/commands/chief.md:195`）。
-   道具が人に示す文字列は英語である（CLAUDE.md の「Go Idioms」の、chief の画面の読み取りの例外の項。「the text the tool prints stay English」）。日本語の語は、`/chief` の定義の値の表にある。
-   `Sanitize` は、端末を書き換えうる文字を見える形に置き換えるが、改行とタブは残す（`internal/chief/sanitize.go:52-75`・`:86-87`）。
-   `/chief` の定義と道具は、protocol 番号 3 で版を照合する（`internal/chief/records.go:29`、`.claude/commands/chief.md:98`）。

実際に使うと、issue #982 の「背景」のとおり、次の問題がある。

1.  1 行に収まらず、意図しない形で折り返す。絵文字と字が分かれ、状態とモデル名が折り返す。
2.  Claude Code は Markdown の表の行ごとに区切り線を引くので、罫線が多く、読みにくい。
3.  Claude Code の表では `<br>` がそのまま文字で出るので、セルの中で改行できない。
4.  コマンド名が状態と内容の両方に出る一方、PR の番号はレビュー待ちの行でしか示されない。
5.  「🟢 待」は「人は待っていてよい」の意味だが、「人の対応を待っている」とも読める。
6.  質問の pane が `w3:p1` のような ID で、どのタブか分からない。

対応 issue: [#982](https://github.com/isseis/yt2column/issues/982)（関連: [#890](https://github.com/isseis/yt2column/issues/890)・タスク [0093](../0093_chief_status_sheet/01_requirements.md)、[ADR-0046](../../dev/adr/0046-chief-of-staff.md)）

**本書の記述範囲:** 本書は、表に何をどの形で示すか、どの幅に収めるか、道具と `/chief` の定義の役割の分け方を定める。次の事項は設計（`02_architecture.md`）で決める。

-   道具の出力に足す項目の名前と形
-   文字ごとの表示幅の判定の規則の細部
-   Claude Code が code block の左に取る余白の値と、内容の列の最小の幅
-   herdr のタブの一覧と pane の配置の読み方
-   表が code block を閉じないことを保つ方法
-   テストの手段

要件の段階で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #982 で決めたこと:**

-   **表は道具が組んで出力に含め、`/chief` のセッションは code block にそのまま貼る。値の表を引いて写すことはしない（F-001）。** セッションが写す今の形では、罫線・折り返し・セルの中の改行を思うように扱えないためである。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する（状況の表を道具が組むことは、「道具が値を決め、セッションはそのまま示す」の範囲を広げるため）。
-   **罫線を使わず、列を空白でそろえ、workspace ごとに 2 行で示し、workspace の間を空行で区切る（F-002）。** 罫線を減らして読みやすくし、セルの中の改行の代わりに 2 行目を使うためである。ADR: ADR-0046 を更新する（上の項にまとめる）。
-   **列は、状態・名前・タスク・PR・内容の 5 つで、この順に並べる。急の列は独立させず、状態の頭に印を付ける。タスクの列の 2 行目に文書の段を示す（F-002）。** 行は急ぎの度合いの順に並ぶので、状態を左端に置けば印が左端にそろうためである。ADR: なし（表示の細部のため）。
-   **列は文字ごとの表示幅（全角と絵文字は 2）でそろえ、その判定は道具が自前で行う（F-002）。** 外部のモジュールを使えない（CLAUDE.md の「Dependencies」）ためである。ADR: なし（表示の細部のため）。
-   **急ぎの度合いの印を、すぐ「🛑」、あとで「🔶」、待つ「🟢」にし、表の上に凡例を 1 行置く（F-003）。** 色だけでなく形（八角形・菱形・円）でも区別できるようにするためである。CLAUDE.md の「Accessibility」はブラウザ拡張の UI が対象で chief の端末の表示は対象外だが、同じ原則（WCAG 1.4.1、色だけに頼らない）を当てはめる。「⭕」は日本語で「正解・OK」と読まれるので使わない。「⚠️」は異体字セレクタ（U+FE0F）を伴い、端末によって表示幅が変わるので使わない。印だけでは意味が分からないので、凡例を置く。ADR: ADR-0046 を更新する（決定に印の形が書かれているため）。
-   **状態の文字列を縮める。「マージの確認待ち」は「マージ確認」に、「作成中」「`/runpr` 実行中」「実行中」はまとめて「作業中」にする。文書の段は「要件」「設計」「計画」にし、「（後に指示あり）」は「＋指示」にする（F-003・F-004）。** 幅を詰めるためである。「作業中」にまとめるのは、今は `/runplan` が「作成中」で `/runpr` が「`/runpr` 実行中」と、コマンド名が入るかどうかが非対称で、`/runpr` は作成をしないためである。どのコマンドかは内容の列で、PR を作る前か後かは PR の列で分かる。ADR: なし（表示の細部のため）。
-   **内容の列は、内容を 1 つの文字列に組み、列の幅で折り返して 2 行に流し込む。2 行に収まらなければ、2 行目の末尾を … で切る。英数字の語は、なるべく空白の位置で折り返す（F-004）。** 「20 文字ほど」で切る今のやり方より、2 行を使って多くを示せるためである。ADR: なし（表示の細部のため）。
-   **他の列で分かる PR の番号は、内容の列に入れない。コマンドは内容の列に残す（F-004）。** 同じ情報を 2 回示さないためである。コマンドを残すのは、文書の段と違うコマンドを人が打っていることに気づけるようにするためである。ADR: なし（表示の細部のため）。
-   **質問の pane は、タブの番号とラベルで `[3 claude]` のように示す。タブのラベルは `Sanitize` を通す（F-004・F-005）。** pane の ID ではどのタブか分からないためである。タブのラベルは人が変えられる文字列なので、ほかの外から来る値と同じく扱う。ADR: なし（表示の細部のため）。
-   **CLAUDE.md に、道具が日本語を出力してよい例外を足す。ADR-0046 を更新する。protocol 番号を上げるかを決める（F-006）。** 範囲・理由・境界と、protocol 番号は、下の「要件定義の際に決めたこと」で決めた。

**要件定義の際に決めたこと（2026-11-18）:**

-   **進め方は通常の進め方にする。対象外の判断は「対象外ではない」で、上書きはない。** ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
    -   対象外ではない理由: (1) chief が送る入力の範囲も、送る判断の条件も、`.claude/settings.json` の拒否も変えない。外から来る文字列（タブのラベル）が 1 つ増えるが、ほかの値と同じく `Sanitize` を通して表示にだけ使う。(2) `docs/dev/security.md` の規則と前提を変えない。(3) 外部の依存を足さない。表示幅の判定は自前で書く（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Simple Process」の「Excluded changes」）。
    -   それでも通常の進め方にする理由: (1) ADR-0046 の決定（状況の表の項）を変える。(2) 表示幅の判定と折り返しという新しい仕組みを作る。(3) 変更が、道具、`/chief` の定義、chief 利用ガイド、CLAUDE.md、herdr のタブの読み取りの 5 か所に及ぶ。(4) 決める点が多い。
-   **CLAUDE.md の例外の範囲は、状況の表の決まった語（見出し、凡例、状態の文字列、文書の段、実行中のコマンドが決まらない理由、「＋指示」、件数の添え書き）に限る。道具の JSON の値、エラーのメッセージ、ほかのサブコマンドの出力、表の下に示す値は、英語のままにする（AC-26）。** 例外の範囲を、日本語でなければならない表示の語に絞り、境界をはっきりさせるためである。chief の出力全体を日本語にしてよいとする案は、範囲が広く境界があいまいになるので採らない。日本語の語をデータのファイルに置いて Go の literal にしない案は、ファイルが増え、語を誤ったときに気づきにくくなるので採らない。ADR: なし（CLAUDE.md の規則は ADR にしないため。CLAUDE.md の「Design decisions (ADR)」）。
-   **protocol 番号を上げる。値は、実装のときの `main` の値 + 1 とする（AC-25）。** `/chief` の定義が道具の組んだ表を前提にするので、古い道具のままではセッションは表を示せない。番号を上げれば、古い道具は `protocol_mismatch` で断り、入れ直しを促せる（`.claude/commands/chief.md:77-79`）。上げない案は採らない。ADR: なし（このタスクの中で閉じるため）。
-   **表の 1 行の幅は、chief の pane の幅から決める。Herdr から chief の pane の幅を読み、Claude Code が code block の左に取る余白を引いた幅に収める。幅を読めないときは 80 桁とする（AC-04・AC-05）。** 道具は `/chief` のセッションの Bash ツールから呼ばれ、標準出力はパイプで、端末ではない。このため、端末の大きさを通常の方法では取れない（2026-11-18 に確かめた。`tty` は `not a tty`、`$COLUMNS` は `0`、`/dev/tty` は開けず、`tput cols` は既定の 80 を返すだけだった）。一方、`herdr pane layout --pane <ID>` は pane の幅（`rect.width`）を返す（同日に確かめた）。80 桁に固定する案は、狭い pane では行が折り返して崩れるので採らない。`/chief` が引数で幅を渡す案は、呼び方と許可の規則が増えるので採らない。ADR: ADR-0046 を更新する（状況の表の項にまとめる）。
    -   受け入れること: 内容の列が最小の幅（設計で決める）を取れないほど pane が狭いときは、最小の幅のまま組み、行が pane からはみ出すことを受け入れる。ラウンドの後に人が pane の幅を変えた表は、次のラウンドまで古い幅のままである。
-   **名前の列の幅は、表の行のうち最も長い名前に合わせ、20 桁を上限とする。20 桁を超える名前は … で切る（AC-08）。** 名前の長い workspace が 1 つあるだけで内容の列が狭くなるのを防ぐためである。切らない案は採らない。ADR: なし（表示の細部のため）。
-   **1 つのタブに pane が 2 つ以上あっても、pane の ID も順番も添えず、`[3 claude]` のまま示す（AC-18）。** 人が選んだ。どの pane かは、質問を選んだときの示し方（0088 要件定義書の AC-25）で分かる。pane の ID を添える案と、タブの中の順番（`[3.2 claude]`）を示す案は採らない。ADR: なし（表示の細部のため）。
-   **タブが引けないとき（タブの一覧を読めない、pane のタブが一覧にない）は、今の pane の ID を `[w3:p1]` のように示し、行の状態は変えない（AC-19）。** タブは表示にだけ使い、何を送るかも行の状態も左右しないためである。ADR: なし（表示の細部のため）。
-   **表の中の値に含まれる改行とタブは、表の中でだけ空白 1 つにする（AC-17）。** 質問の文は複数行になりえ、そのままでは表の行が崩れる。全文は、今までどおり道具の出力と、質問を選んだときの示し方にある。`\n` のような見える形にする案は、読みにくいので採らない。ADR: なし（表示の細部のため）。
-   **1 つの行に質問が 2 つ以上あるときは、道具の順で最初の質問だけを示し、件数を頭に添える（例: `2 件 [3 claude] …`）（AC-16）。** 2 行に収めつつ、ほかにも質問があることを示すためである。すべての質問を続けて流し込み … で切る案は採らない。2 つ目以降の質問が、切られて分からなくなるためである。ADR: なし（表示の細部のため）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   状況の表を、意図しない折り返しも罫線の重なりもなく、workspace ごとに 2 行で一覧できるようにする。
-   急ぎの度合いを色だけでなく形でも見分けられ、その意味を表の上で読めるようにする。
-   PR の番号と、質問を待っているタブを、表から直接読めるようにする。
-   表を組む判断を道具に置き、セッションが値を写したり切ったりしないようにする（ADR-0046 の「道具が決め、セッションは示す」を保つ）。

### 2.2. スコープ (In Scope)

-   道具が表を組んで出力に含めること（F-001）
-   表の形、列、幅（F-002）
-   急ぎの度合いの印と状態の文字列（F-003）
-   内容の列（F-004）
-   表に入る外から来る値の扱い（F-005）
-   `/chief` の定義、chief 利用ガイド、CLAUDE.md、ADR-0046 の更新と、protocol 番号（F-006）

### 2.3. スコープ外 (Out of Scope)

-   モデル名の短縮。道具の側で短い名前を宣言する別の作業である。内容を 2 行に流し込むので、急ぎは下がる（issue #982 の「対象外」）。
-   経過時間（最後の動きからの時間）の列（issue #982 の「対象外」）。
-   人の判断を待つものの一覧（選択肢）、通知、表の下の項目（送信の結果、引き継ぎ、送信の停止、まだ答えのない問い、`problems`）の形。pane の示し方（`w3:p1`）も、これらの中では変えない（issue #982 の「対象外」）。
-   道具が返す読めなかったもの（`unreadable`）と、送れない提案の理由（`problem`）の文字列の言葉。今のまま英語で示す（「要件定義の際に決めたこと」の例外の範囲の項）。
-   急ぎの度合いの判定、行の並べ方、進行の位置の決め方（0093 要件定義書の F-001〜F-004）。本書は、それらの値の示し方だけを変える。
-   `/chief once` で表が見えないこと（[#968](https://github.com/isseis/yt2column/issues/968) で扱う）。

## 3. 機能要件 (Functional Requirements)

本書の用語は、0088 要件定義書と 0093 要件定義書の 3 章に従う。加えて、本書では次の用語を使う。

-   **表**: 道具が組む状況の表のテキスト全体。凡例、見出し、区切り線、workspace ごとの 2 行からなる。
-   **表示幅**: 等幅の端末で文字が占める桁の数。全角の文字と絵文字は 2 桁、ASCII の文字は 1 桁である。細部の規則は設計で決める（design_handoff.md の H-02）。
-   **使える幅**: 表の 1 行が収まるべき表示幅（AC-04）。
-   **タブの表示**: 質問の pane を示す `[<タブの番号> <タブのラベル>]` の形（AC-18）。

### 3.1. 機能一覧

#### F-001: 道具が表を組み、`/chief` はそのまま示す

**Acceptance Criteria**:
-   **AC-01**: 道具 `chief` の `snapshot` と `tick` の出力は、今の項目に加えて、組み上がった表を持つ。表の workspace の並びは、`rows` の並びと同じである。
-   **AC-02**: 道具の出力の `rows` の各項目（急ぎの度合い、進行の位置、番、質問、実行中のコマンドなど）の値と意味は変わらない。表に示す値は、同じ出力の `rows` の値と食い違わない。
-   **AC-03**: `/chief` の定義は、ラウンドごとに、道具が返した表を code block に入れてそのまま示すと定める。値の表を引いて値を写すこと、値を切ること、行を並べ替えること、列を足すか除くことは定めない。`/chief` の定義の手順 2（One round）の差分は、表の示し方（項目 2）を、道具の表を code block で示すことに置き換えることだけである。送信の結果（項目 1）、表の下（項目 3）、通知（項目 4）は変わらない。

#### F-002: 表の形と幅

**Acceptance Criteria**:
-   **AC-04**: 表のどの行も、表示幅が使える幅以下である。使える幅は、chief の pane の幅（Herdr から読む）から、Claude Code が code block の左に取る余白を引いた値である。ただし AC-07 の最小の幅を守るために、使える幅を超えることがある（AC-05）。
-   **AC-05**: chief の pane の幅を読めないとき（Herdr の失敗、読めない形）は、pane の幅を 80 桁とみなして使える幅を決める。この場合も、表は示され、ラウンドは失敗しない。内容の列が最小の幅（設計で決める）を取れないほど使える幅が狭いときは、内容の列を最小の幅として表を組み、行が使える幅を超えることを受け入れる。
-   **AC-06**: 表は、上から次の順に並ぶ。
    1.  凡例の 1 行: `🛑 すぐ  🔶 あとで  🟢 待つ`
    2.  空行
    3.  見出しの 1 行: 状態・名前・タスク・PR・内容
    4.  区切り線の 1 行（`─` を並べたもの）
    5.  workspace ごとの 2 行。workspace と workspace の間に空行を 1 行置く
-   **AC-07**: 列は、状態・名前・タスク・PR・内容の順に並び、罫線で区切らず、空白でそろえる。同じ列は、見出しとすべての行で、同じ表示幅の位置から始まる。全角の文字と絵文字は 2 桁として数える。
-   **AC-08**: 名前の列の幅は、表のすべての名前と見出しのうち最も長いものの表示幅で、20 桁を上限とする。20 桁を超える名前は、末尾を … にして 20 桁以内に切る。
-   **AC-09**: workspace ごとの 2 行は、次の値を持つ。値のない欄は空白である。

    | 列 | 1 行目 | 2 行目 |
    |---|---|---|
    | 状態 | 急ぎの度合いの印と状態の文字列（AC-11・AC-12） | 空 |
    | 名前 | workspace の名前（AC-08） | 空 |
    | タスク | タスク番号。タスクがなければ `-` | 文書の段（AC-13） |
    | PR | ブランチで開いている PR の番号を `#980` の形で。なければ `-` | 空 |
    | 内容 | 内容の文字列の 1 行目（AC-14・AC-15） | 内容の文字列の 2 行目 |

-   **AC-10**: 行が 1 つもないときも、表は示される。その形は設計で決める（design_handoff.md の H-06）。

#### F-003: 急ぎの度合いの印と状態の文字列

    | 質問で停止 | 質問で停止 |
    | レビュー待ち | レビュー待ち |
    | タスク完了 | タスク完了 |

    | 文書 | 示し方 |

    | 要件定義書 | 要件 |

#### F-004: 内容の列

**Acceptance Criteria**:
-   **AC-14**: 内容の文字列は、行の状態から次のように組む。PR の番号は入れない。

    | 状態 | 内容の文字列 |
    |---|---|
    | マージ確認、質問で停止 | 質問のタブの表示（AC-18・AC-19）と質問の要点を、空白 1 つで区切ったもの。質問が 2 つ以上なら AC-16 |
    | レビュー待ち | PR の題名 |
    | 次を提案 | 提案するコマンドと、モデルを括弧に入れたもの。送れない提案なら、送れない理由（`problem`） |
    | 作業中 | 実行中のコマンド。後の指示があれば「＋指示」を添え、モデルが決まれば括弧に入れて添える（0093 要件定義書の AC-14 のモデルの条件）。実行中のコマンドが決まらなければ、決まらない理由（AC-20） |
    | 要確認 | 読めなかったもの（`unreadable`） |
    | タスク完了 | 空 |

-   **AC-15**: 内容の文字列は、内容の列の幅で折り返して 2 行に流し込む。各行の表示幅は内容の列の幅以下である。2 行に収まらないときは、2 行目の末尾を … にして、2 行目の表示幅が内容の列の幅以下になるように切る。英数字の語は、その語が 1 行に収まる限り、語の途中ではなく空白の位置で折り返す。1 行に収まらない語は、語の途中で折り返す。
-   **AC-16**: 1 つの行に質問が 2 つ以上あるときは、`<件数> 件` を頭に置き、空白 1 つの後に、道具の順で最初の質問のタブの表示と要点を続ける（例: `2 件 [3 claude] …`）。2 つ目以降の質問は、表に示さない。
-   **AC-17**: 表に入る値に含まれる改行とタブは、表の中でだけ、それぞれ空白 1 つとして示す。道具の出力の `rows` の値は変わらない。
-   **AC-18**: 質問のタブの表示は `[<タブの番号> <タブのラベル>]` である。タブの番号とラベルは、Herdr のタブの一覧の、その pane のタブのものである。1 つのタブに pane が 2 つ以上あっても、同じ形で示し、pane の ID も順番も添えない。タブのラベルが空なら `[<タブの番号>]` とする。
-   **AC-19**: タブが引けないとき（タブの一覧を読めない、読めない形である、pane のタブが一覧にない）は、タブの表示の代わりに `[<pane の ID>]`（例: `[w3:p1]`）を示す。この場合も、行の状態、急ぎの度合い、送れるかどうかは変わらず、ラウンドは失敗しない。
-   **AC-20**: 実行中のコマンドが決まらない理由は、今の `/chief` の定義の示し方（`.claude/commands/chief.md:171-178`）と同じ言葉で示す。後の指示は「（後に指示あり）」ではなく「＋指示」と示す。

#### F-005: 表に入る外から来る値

**Acceptance Criteria**:
-   **AC-21**: 表に入る外から来る値（workspace の名前、PR の題名、質問の要点、送れない理由、読めなかったもの、タブのラベル、pane の ID）は、どれも `Sanitize` を通した後のものである。
-   **AC-22**: 表に入る値がどんな文字列でも（バッククォートの並び ```` ``` ```` やチルダの並び `~~~` を含む行、空白で始まる値、`#`・`|`・`-` で始まる値を含む）、`/chief` の定義の示し方で貼った code block は、表の終わりより前で閉じず、表のどの行も code block の外の Markdown として描かれない。
-   **AC-23**: Herdr のタブの一覧と pane の配置の出力は、信頼できない入力として扱う。受け付ける形、使うメンバー、上限、形に合わないときの扱いは、4.2 のとおりである。形に合わない出力は、直したり一部だけを使ったりせず、AC-05 と AC-19 の「読めない」として扱う。

#### F-006: 文書、規則、版の更新

**Acceptance Criteria**:
-   **AC-24**: chief 利用ガイド（`docs/dev/guides/chief_guide.md`）の 3.1 は、本書の表の形（凡例、5 つの列、2 行目、幅の決め方、内容の列の流し込みと切り方、タブの表示）を説明する。
-   **AC-25**: 道具の protocol 番号と、`/chief` の定義が渡す `--protocol` の値は、実装のときの `main` の値 + 1 である。
-   **AC-26**: CLAUDE.md の「Go Idioms」に、chief の道具が状況の表の決まった語を日本語で出力してよい例外が、範囲・理由・境界とともにある。範囲は、表の見出し、凡例、状態の文字列、文書の段、実行中のコマンドが決まらない理由、「＋指示」、件数の添え書きに限る。道具の JSON の値、エラーのメッセージ、ほかのサブコマンドの出力、表に入る外から来る値は、範囲に含めない。chief の画面の読み取りの例外の項の「道具が出力する文字列は英語」の文は、この例外と食い違わない。
-   **AC-27**: ADR-0046 の決定（状況の表の項）は、表を道具が組み、`/chief` のセッションがそのまま示すことと、印が `🛑`・`🔶`・`🟢` であることを述べ、経緯にその変更がある。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   ラウンドごとに、Herdr への読み取りの呼び出しが 2 つ増える（タブの一覧と、chief の pane の配置）。どちらもローカルのソケットへの問い合わせで、ネットワークの操作ではない。今のラウンドも Herdr の pane の一覧などを読んでいる（`internal/chief/herdr.go:627-680`）。そのため、CLAUDE.md の「Performance」の基準で、仕組みを足して減らすほどの費用ではないとみなす。
-   表を組む処理は、行の数と値の長さに比例する時間で終わる。

### 4.2. セキュリティ (Security)

-   N/A。条件付きのガイド（`docs/dev/security.md`）の適用条件のどれにも当たらない。適用条件は、外部コマンド `yt-dlp` の呼び出し、API キー、キャッシュのディレクトリ、LLM API へのネットワークの送信、信頼できない文字列のプロンプトや記事への埋め込みである。
-   chief が送る入力の範囲、送る判断の条件、`.claude/settings.json` の拒否は変えない。表と、タブと pane の幅の読み取りは、表示にだけ使い、何を送るかを左右しない。
-   **表に入る値の境界（AC-21・AC-22）:** 表に入る値は、ほかのエージェント、GitHub、Herdr、人が書いた信頼できない文字列を含む（ADR-0046 の背景）。端末を書き換えうる文字は、今と同じく `Sanitize` で見える形にする。改行とタブは表の中で空白にする（AC-17）。値の中身がどうであっても、code block を閉じたり、表の外の Markdown として描かれたりしない（AC-22）。
-   **Herdr のタブの一覧の境界（AC-18・AC-19・AC-23）:** `herdr tab list` の出力は、Herdr が書く外部の値である。
    -   受け付ける形: 今の Herdr の出力の読み取り（`internal/chief/herdr.go:190-230`）と同じく、1 つの JSON のオブジェクトで、`id` と `result` を持ち、`result` がタブの配列を持つ形。
    -   使うメンバー: 各タブの `tab_id`、`number`（0 以上の整数）、`label`（文字列）。ほかのメンバー（`agent_status`・`focused`・`pane_count` など）は使わず、Herdr が足すことを見込んで拡張できるものとする。使うメンバーが欠けているか、重なっているか、型が違うときは、一覧全体を読めないものとする。
    -   上限: 今の外部コマンドの出力の上限（`internal/chief/runner.go:52`、4 MiB）をそのまま使い、超えた出力は読めないものとする。
    -   読めないとき: 新しい拒否の理由やエラーにせず、AC-19 のとおり pane の ID を示す。
-   **Herdr の pane の配置の境界（AC-04・AC-05・AC-23）:** `herdr pane layout --pane <ID>` の出力は、Herdr が書く外部の値である。
    -   受け付ける形: タブの一覧と同じ封筒の形で、chief の pane の配置を持つもの。
    -   使うメンバー: chief の pane の ID と、その幅（1 以上の整数）。ほかのメンバーは使わず、拡張できるものとする。使うメンバーが欠けているか、重なっているか、型が違うか、返った pane が chief の pane でないときは、読めないものとする。
    -   上限: タブの一覧と同じ。
    -   読めないとき: 新しい拒否の理由やエラーにせず、AC-05 のとおり 80 桁とみなす。
-   読み方の細部（封筒の `type` の値、配置のどのメンバーの幅を使うか）は、設計で実物の出力から決める（design_handoff.md の H-04）。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   タブの一覧か pane の配置を読めないラウンドでも、表は示され、ラウンドは失敗しない（AC-05・AC-19）。
-   表を組めないことで、自動送信、中継、リセットが止まることはない。表は表示にだけ使う。

### 4.4. 互換性 (Compatibility)

-   protocol 番号を上げる（AC-25）。古い道具は `/chief` の新しい定義の呼び出しを `protocol_mismatch` で断り、`/chief` は `make install-chief` での入れ直しを促す（`.claude/commands/chief.md:77-79`）。
-   出力の `rows` の項目は変えない（AC-02）。`rows` を読む利用者は `/chief` の定義だけである。

### 4.5. 保守性 (Maintainability)

-   表の決まった語は道具の中にあり、変えるには道具を直して入れ直す（ADR-0046 の結果に足す）。
-   日本語の literal を置く範囲は、CLAUDE.md の例外（AC-26）で限る。どのファイルに置くかは、設計で決める（design_handoff.md の H-07）。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。`/chief` が状況を読み取って示す 1 回分は「ラウンド」と書き、「周」とは書かない。
-   **表示幅**: 等幅の端末で文字が占める桁の数（3 章）。
-   **使える幅**: 表の 1 行が収まるべき表示幅（AC-04）。
-   **タブの表示**: 質問の pane を示す `[<タブの番号> <タブのラベル>]` の形（AC-18）。
-   **凡例**: 表の上に置く、印と急ぎの度合いの対応を示す 1 行（AC-06）。
