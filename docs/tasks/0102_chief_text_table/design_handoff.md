# 設計への申し送り（0102）

要件定義の時点で挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目にとった方針か、当てはまらない理由を記録する。

## H-01: 道具の出力に足す表の形

**懸念:** 組み上がった表（AC-01）を、道具の出力にどの名前と形で足すかが決まっていない。1 つの文字列にするか、行の配列にするかで、`/chief` の定義が code block に入れる手順と、テストの書き方が変わる。

**なぜ重要か:** 文字列の終わりの改行や、行の中の空白の扱いがあいまいだと、セッションが貼るときに列がずれうる。

**候補:**
-   1 つの文字列（行を `\n` で結んだもの）にし、`/chief` の定義は、それを手を加えずに code block に入れると定める。
-   行の配列にし、定義が 1 行ずつ並べる。

**関連:** F-001、AC-01・AC-03・AC-25

## H-02: 表示幅の判定の規則

**懸念:** 列をそろえるには、文字ごとの表示幅を道具が数える（AC-07）。外部のモジュールは使えないので、判定を自前で書く。次の文字の扱いを決める必要がある。
-   East Asian Width が W・F の文字（全角の文字）と、絵文字（`🛑`・`🔶`・`🟢` を含む）
-   East Asian Width が A（曖昧）の文字。表が自分で使う `…`（U+2026）と `─`（U+2500）も曖昧な文字で、日本語の端末の設定によっては 2 桁で描かれる
-   結合文字、異体字セレクタ、ゼロ幅の文字。`Sanitize` はゼロ幅の書式文字を見える形（`\u200b` など）に置き換える（`internal/chief/sanitize.go:52-100`）
-   `Sanitize` が作るエスケープ（`\x1b` など）の幅と、エスケープの途中で切ること。`\\` や `\x1b` を途中で切ると、ただの `\` が残り、別のエスケープと読み違えうる（AC-15）

**なぜ重要か:** 判定が端末の描き方と食い違うと、その行だけ列がずれる。名前の列は 2 列目なので、名前の幅を誤ると、その行の後ろの列がすべてずれる。

**候補:**
-   Unicode の East Asian Width の表のうち、W と F の範囲と絵文字の範囲だけを道具に持ち、ほかは 1 桁とする。曖昧な文字は 1 桁とし、表が自分で使う記号は、曖昧な文字でないものに替えるかを検討する。
-   判定の表の範囲を、実物の端末（Herdr の pane の中の Claude Code）で確かめる。

**関連:** F-002、AC-04・AC-07・AC-08・AC-15

## H-03: Claude Code の code block の余白と、内容の列の最小の幅

**懸念:** 使える幅は、chief の pane の幅から、Claude Code が code block の左に取る余白を引いた値である（AC-04）。余白の値は確かめていない。内容の列の最小の幅（AC-05）も決まっていない。状態・タスク・PR の列の幅と、列と列の間の空白の数も決まっておらず、これらが内容の列の幅を決める。

**なぜ重要か:** 余白を少なく見積もると、どの行も pane の右端で折り返して、表が崩れる。多く見積もると、内容の列が不必要に狭くなる。

**候補:**
-   実物の Claude Code（Herdr の pane の中）で、幅の分かっている行を code block に入れて描かせ、余白の桁の数を確かめる。Claude Code の版によって変わりうるので、値の出どころを設計書に記録する。
-   最小の幅は、`[3 claude]` と数文字の要点が入る程度（たとえば 16 桁）とする。

**関連:** F-002、AC-04・AC-05

## H-04: Herdr のタブの一覧と pane の配置の読み方

**懸念:** `herdr tab list` と `herdr pane layout --pane <ID>` を読むのは、chief では初めてである。2026-11-18 に手元で見た出力では、`herdr tab list` の `result` は `tabs` を持ち、各タブは `tab_id`・`workspace_id`・`number`・`label`・`pane_count`・`agent_status`・`focused` を持っていた。`result` の `type` は `tab_list` で、`herdr pane layout` の `type` は `pane_layout` だった（herdr 0.9.1）。`herdr pane layout` は `layout.area` と `layout.panes[].rect` の両方に幅を持つ。一方、同じ workspace の 2 つのタブの `number` が 1 と 16 だった（`tab_id` は `wC:t1` と `wC:tG`）。`number` はタブの並びの位置ではなく、作った順の番号でありうる。Herdr のタブの並びにどちらの番号が出るかは確かめていない。

**なぜ重要か:** 封筒の形が今の読み取りと違うと、どのラウンドでもタブが引けず、表は pane の ID のまま（AC-19）で、幅も 80 桁（AC-05）になる。`number` が Herdr の画面のタブの番号と違うと、`[16 claude]` が人の見るどのタブを指すか分からず、タブの表示（AC-18）の目的を果たさない。どちらの幅を使うかで、分割したタブでの使える幅が変わる。

**候補:**
-   実物の出力をサンプルとして `internal/chief/testdata/` に採る。
-   Herdr の画面のタブの番号が `number` と同じかを、タブを消した workspace で確かめる。違えば、`number` の代わりに示す番号を設計で決め、要件と食い違うなら要件を直す。
-   幅は、chief の pane の `rect.width` を使う。`area` はタブ全体の大きさで、pane を分割したときに広すぎる。
-   pane の配置を読む pane は、chief がすでに知っている自分の pane（`HERDR_PANE_ID` から確かめたもの）とする。

**関連:** F-002・F-004・F-005、AC-04・AC-05・AC-18・AC-19・AC-23

## H-05: 表が code block を閉じないことを保つ方法

**懸念:** AC-22 は、値がどんな文字列でも、貼った code block が表の終わりより前で閉じないことを求める。保つ方法が決まっていない。

**なぜ重要か:** code block が閉じると、その後の行が Markdown として描かれ、外から来た文字列が見出しやリンクとして示される。

**候補:**
-   表のどの行も、外から来た値で始まらないように組む。1 行目は印で始まり、2 行目は状態の列の空白（4 桁以上）で始まる。CommonMark では、4 桁以上の字下げのある行は囲いの閉じにならない。
-   `/chief` の定義で、表の中のどのバッククォートの並びよりも長い囲いを使うと定める。
-   どちらか、または両方を採り、値に ```` ``` ```` や `~~~` を含む表のテストで確かめる。

**関連:** F-005、AC-22

## H-06: 行が 1 つもないときの表の形と、細部の示し方

**懸念:** 次の形が決まっていない。
-   行が 1 つもないときの表（AC-10）。凡例と見出しだけを示すか、決まった 1 行（例: workspace がない）を示すか。
-   読めなかったもの（`unreadable`）が 2 つ以上あるときに、内容の文字列をどう結ぶか（AC-14）。
-   タブのラベルが空のときのタブの表示（AC-18）。
-   折り返しで、語（AC-15）の直前が空白でない ASCII でない文字のとき（例: `表の幅をresizeに合わせる`）に、その境目で折り返すか。全角の空白（U+3000）を AC-15 の空白に含めるか。
-   急ぎの度合い、進み具合、文書、`running_unknown` の値のうち、表に対応のない値の示し方。今の定義は「（定義にない値）」を添えて示す（`.claude/commands/chief.md:180-181`）。道具が組むと起こらないはずだが、起こったときに推し量らずに示す形を決める。

**なぜ重要か:** 表の形がラウンドごとに変わると、人が読み違えやすい。

**候補:**
-   行がないときは、凡例と見出しと区切り線だけを示す。
-   読めなかったものは、道具の順に `, ` で結ぶ。
-   ラベルが空のタブは `[3]` と示す。
-   語と ASCII でない文字の境目も、空白と同じく折り返してよい位置とする（空白を落とさない）。全角の空白は空白に含めない。
-   対応のない値は、決まった 1 つの語（例: `?`）で示し、ほかの値から推し量らない。

**関連:** F-002・F-004、AC-10・AC-14

## H-07: 日本語の literal を置くファイル

**懸念:** CLAUDE.md の例外（AC-26）は、表の決まった語に範囲を限る。その語を置くファイルを決め、例外の文がそのファイルを名指せるようにする必要がある。

**なぜ重要か:** 置き場所が散らばると、例外の範囲を確かめられず、ほかの出力に日本語が入っても気づかない。

**候補:**
-   表を組むコードを `internal/chief` の 1 つのファイル（たとえば `table.go`）に置き、日本語の literal はそのファイルとそのテストだけに置く。例外の文は、そのファイルを名指す。

**関連:** F-006、AC-26
