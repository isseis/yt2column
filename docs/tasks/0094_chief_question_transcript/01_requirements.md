## 1. 概要 (Overview)

**目的:** 本書は、chief（[0088 要件定義書](../0088_chief_of_staff/01_requirements.md)）が Claude Code の pane について行う次の 3 つの処理の情報源を、pane の画面から Claude Code の transcript に移す要件を定義する。3 つとは、質問で止まっているかどうかの判定、問いの形と選択肢の読み取り、人が選んだ答えを中継する直前の照合である。

**背景:**

chief の今の振る舞いは次のとおりである。

-   Claude Code の pane の質問は、画面から読み取っている。`parseClaudeScreen` が、1 つを選ぶ問い、複数を選ぶ問い、タブのある問いとその確認のページ、権限の確認を、Claude Code 2.1.322 の実画面のサンプルの形で読み取る（`internal/chief/screen_claude.go:69`・`:228`・`:350`・`:389`）。どの形にも合わない画面は「要確認」になる（`internal/chief/state.go:392-410`）。状況の表を作るたびに、すべての pane の画面を読む（`internal/chief/snapshot.go:237`）。
-   画面の形は Claude Code の版で変わる。版が上がると、サンプルを採り直すまで、その workspace は「要確認」になり、答えの中継もできない（[ADR-0046](../../dev/adr/0046-chief-of-staff.md) の「結果」、[chief 利用ガイド](../../dev/guides/chief_guide.md) の 1 章の表）。
-   答えの中継では、照合値を、画面から読んだ問いの文・選択肢・カーソルの位置と、Herdr の `agent_session` と `state_change_seq` から作る（`internal/chief/relay.go:35`）。キーを送る直前に画面を読み直し、照合値が変わっていないことを確かめてから、選択肢の番号から決まったキー入力だけを送る（`internal/chief/relay.go:247`）。Herdr がエージェントを `blocked` と報告していなければ送らない（`internal/chief/relay.go:226`）。
-   `/runpr` のマージの確認は、問いの文の形で見分ける（`internal/chief/screen.go:113`）。
-   chief は、Herdr の `agent_session` と作業ディレクトリから Claude Code の transcript の場所を決め（`internal/chief/transcript.go:53`）、すでに 2 つのことに使っている。1 つは `/model` で切り替えたモデルの記録、もう 1 つは人が最後に入力した行である（`internal/chief/screen_transcript.go:46`・`:170`）。どちらの読み取りも、JSON の 1 つのオブジェクトとして読めない行が 1 行でもあれば、transcript 全体を読めないとする（`internal/chief/screen_transcript.go:54`・`:178`）。読む量の上限は、`/model` の確かめで 1 MiB、リセットの判定で 64 MiB である（`internal/chief/transcript.go:29-30`）。

transcript には、`AskUserQuestion` の呼び出しが、答えを待っている間から構造化されて書かれている（issue #904。2026-11-16 確認：呼び出しの行が 03:23、答えの行が 08:01）。本書を書く際に、手元の transcript で次のことを確かめた（2026-11-16）。

-   呼び出しは、`type` が `assistant` の行の `message.content` の要素（`type` が `tool_use`）に書かれる。要素には、呼び出しの ID（`id`）、道具の名前（`name`）、入力（`input`）がある。`AskUserQuestion` の入力は `questions` の配列で、問いごとに問いの文（`question`）、見出し（`header`）、複数を選ぶ問いかどうか（`multiSelect`）、選択肢（`options` の各要素の `label` と `description`）を持つ。1 回の呼び出しに問いが 2 つあるものもあった。
-   答えは、`type` が `user` の行の `message.content` の要素（`type` が `tool_result`）に、呼び出しの ID（`tool_use_id`）とともに書かれる。人が Esc で拒んだときも、`is_error` が `true` の答えとして書かれる。
-   同じ呼び出しの ID は、`type` が `api-request-blob` の行にも書かれる。その行の中身は、`assistant` の行と異なることがある。直近の 300 ファイルでは、`assistant` の行どうしで同じ呼び出しの ID が 2 度書かれたことはなく、`user` の行どうしで同じ答えが 2 度書かれたこともなかった。
-   人が答えた権限の確認では、許可したか拒んだかが、答えの行の `permissionDecision` に書かれていた。それより前に、権限の確認を示す行は見当たらなかった。
-   1 時間以上書かれていない 281 ファイルでは、答えのないまま残った呼び出しはなかった。
-   どの transcript も改行で終わっていた。

次の 2 点は、答えを待っている間の transcript と Herdr の状態で確かめていない前提である。設計の最初にサンプルで確かめる（design_handoff.md の H-05）。前提が成り立たないと分かれば、本書を `draft` に戻して決め直す。

-   権限の確認を待っている間、transcript には答えのない呼び出しが残るだけで、権限の確認を示す行は書かれない。
-   Herdr は、Claude Code が権限の確認を示している間、エージェントを `blocked` と報告する（0088 の採取で確かめたのは質問の画面だけである。`internal/chief/relay.go:223-225`）。成り立たないときは、AC-13 のとおり権限の確認は示されないが、送るものは増えない。

対応 issue: [#904](https://github.com/isseis/yt2column/issues/904)（親: [#902](https://github.com/isseis/yt2column/issues/902)、関連: [#905](https://github.com/isseis/yt2column/issues/905)・[#906](https://github.com/isseis/yt2column/issues/906)・[#907](https://github.com/isseis/yt2column/issues/907)・[#908](https://github.com/isseis/yt2column/issues/908)）

**本書の記述範囲:** 本書は、Claude Code の pane について、chief が何を質問として示し、何を中継し、何を送らずに止めるかという観測できる振る舞いを定める。次の事項は設計（`02_architecture.md`）で決める。

-   transcript の読み方（毎回すべてを読むか、前回の続きから読むか）と、その費用
-   照合値の作り方
-   送る直前の画面と transcript の問いの比べ方
-   画面の質問の読み取りのうち、使わなくなる部分を、このタスクで消すか #908 に残すか
-   示す文言、送らなかった理由の値の綴り
-   テストの手段と、サンプルの採り方

要件の段階で挙がった設計事項は [design_handoff.md](design_handoff.md) に申し送る。

**issue #904 で決めたこと:**

-   **Claude Code の pane の質問の有無、問いの形、選択肢は、答えの `tool_result` がまだない `AskUserQuestion` の呼び出しから判定する。** 画面の形は Claude Code の版で変わり、読み違えや「要確認」の原因になる。transcript には同じ中身が構造化されて書かれている。ADR: [ADR-0046](../../dev/adr/0046-chief-of-staff.md) を更新する（「質問と選択肢は画面のとおりに示す」「画面は、実画面のサンプルで確かめた形だけを受け付ける」という決定を変えるため）。
-   **答えを中継する直前の照合は、同じ呼び出し（`tool_use` の ID）がまだ答えを待っているかで行う。送る入力は、今と同じく、選択肢の番号から決まるキー入力に限る。** 送る入力の範囲は変えない。ADR: ADR-0046 を更新する。
-   **権限の確認を、画面ではない情報源で判定できるか確かめ、できれば移す。** ADR: ADR-0046 を更新する（下の「要件定義の際に決めたこと」で移すと決めたため）。
-   **ADR-0046 と、CLAUDE.md の「Declare, don't infer」の例外のうち、この変更で変わる部分を更新する。** ADR: ADR-0046 を更新する。
-   **報告の読み取り（#905）、入力欄に残った文字の判定、OpenCode の pane（#906・#907）は扱わない。** 入力欄に残った文字は、画面でしか読めないためである。ADR: なし（範囲の分け方は、親 issue #902 の中で閉じるため）。

**要件定義の際に決めたこと（2026-11-16）:**

-   **進め方は通常の進め方（`full`）にする。対象外の判断は「対象外」で、上書きはない。** chief は、ほかのエージェントのセッションへキー入力を送る開発用の道具であり、その信頼の境界に当たる（ADR-0046 の背景）。この変更は、人に示す質問と、キーを送る判断を、どの信頼できない情報源に委ねるかを変える。そのため、開発用の道具の信頼の境界に影響するものとして、簡易な進め方の対象外と判断した（[requirements_process.md](../../dev/conventions/requirements_process.md) の「Simple Process」の「Excluded changes」）。人も通常の進め方を選んだ。ADR: なし（進め方の選択はこのタスクの中で閉じるため）。
-   **画面の判定は、送るのを止めるための確かめとして残す。答えを中継する直前に画面を読み、transcript の問いと同じ、1 つを選ぶ問いの形が出ているときだけ送る（F-003）。** transcript は、呼び出しが答えを待っていることを示すが、pane の今の様子は示さない。たとえば人が「Type something.」の選択肢へ移って文字を打ちかけていると、数字のキーが選択肢を選ばず、文字として入るおそれがある（この振る舞いは確かめていない。確かめていないので、送らない側に倒す）。画面の確かめを外し、transcript と Herdr の `blocked` だけで送る案は採らない。親 issue #902 の方針（画面の読み取りは、送るのを止めるための確かめだけに残す）にも合う。ADR: ADR-0046 を更新する。
-   **状況の表で Claude Code の pane が質問で止まっているかは、transcript と Herdr の状態だけで決める。中継の直前の画面が合わないときは、その中継を送らず、理由を示す。表の行を「要確認」にはしない（F-001・F-003）。** 状況を読むたびに画面も比べて、合わなければ「要確認」にする案は採らない。その案では、Claude Code の版が上がって画面の形が変わるたびに表が「要確認」になり、情報源を移す意味が薄れるためである。ADR: ADR-0046 を更新する。
-   **transcript の最後の行が改行で終わっていなければ、書きかけとして読まない。改行で終わっているのに読めない行があれば、その pane を「要確認」にし、何も中継しない（F-004、AC-21）。** 答えを待っている間も、transcript には別の種類の行が書き足されることがある。今の規則（1 行でも読めなければ全体を読めない）のままでは、書き足しの最中に読んだ回が「要確認」になる。手元の transcript はどれも改行で終わっていたので、書き終えた行は改行で終わると見てよい。ADR: なし（transcript の読み方の細部で、このタスクの中で閉じるため）。
-   **権限の確認は、Herdr がエージェントを `blocked` と報告し、かつ transcript に答えのない呼び出しが `AskUserQuestion` 以外でちょうど 1 つあるときと判定する。中身は、その呼び出しの道具の名前と入力で示し、今と同じく中継しない（F-002）。** chief は権限の確認を中継せず、中身を示すだけなので、見分けを誤っても送るものは増えない。権限の確認の判定を画面のまま残し、後の issue に回す案は採らない。Claude Code の Notification フックの `permission_prompt` を使う案も採らない。その案では、各エージェントの設定にフックを足す手間が増えるためである。ADR: ADR-0046 を更新する。
-   **1 回の呼び出しに問いが 2 つ以上あるとき（画面ではタブになる）は、すべての問いと選択肢を示す。今と同じく中継はしない（AC-03）。** 画面には今のタブの問いしか出ないが、transcript にはすべての問いがあるので、人が pane へ移る前に全体を見られる。最初の問いだけを示し、ほかの問いがあることを添える案は採らない。これは、0088 要件定義書の AC-25（質問と選択肢を画面のとおりに示し、タブは画面に出ている問いを示す）を、Claude Code の pane について置き換える（AC-01・AC-03）。OpenCode の pane には AC-25 がそのまま当たる。ADR: ADR-0046 を更新する（「質問と選択肢は画面のとおりに示す」を変える部分に含まれるため）。
-   **transcript で答えを待っている質問の呼び出しがあり、Herdr がエージェントを `working` と報告しているときは、質問として示し、中継は拒む。Herdr が `idle` か `done` と報告しているときは、その pane を「要確認」にし、pane で確かめることを示す（AC-06・AC-07）。** `working` の扱いは、今の画面の場合と同じである（`internal/chief/state.go:392`・`internal/chief/relay.go:226`）。`idle`・`done` で質問として示し続けると、答えのない呼び出しが何かの理由で残ったとき、その pane がいつまでも質問として示され、送信・自動送信・削除が止まり続ける。手元の終わったセッションには答えのない呼び出しは残っていなかったが、起きたときに人が気づけるようにする。どちらも質問として示す案は採らない。ADR: なし（このタスクの中で閉じる表示の細部で、ADR-0046 の「合わないものは要確認」の範囲に収まるため）。
-   **答えを待っている呼び出しが `Agent` の道具（サブエージェント）のときは、権限の確認とせず、その pane を「要確認」にし、サブエージェントが質問か権限の確認で待っているかもしれないことを示す（AC-11）。** サブエージェントが待っていると、親の transcript には答えのない `Agent` の呼び出しが残るだけで、何を待っているかは分からない。そのまま権限の確認として示すと、人を誤らせる。権限の確認として `Agent` の入力を示す案は採らない。ADR: なし（同上）。
-   **Claude Code の pane の transcript を読めないとき（場所が決まらない、上限を超える、形が合わない）は、その pane を「要確認」にし、同じ workspace へのコマンドの送信、自動送信、workspace の削除を止める（AC-19〜AC-24）。** 今は、場所が決まらないときに止まるのは、`/model` を送るときとリセットのときだけである（`internal/chief/send.go`・`internal/chief/reset.go` の transcript の確かめ）。質問の有無が分からないまま送ると、質問で止まっている pane に、人が選んでいない入力が入りうる。止めるのを、その pane への送信だけに限る案は採らない。ADR: なし（ADR-0046 の「合わないものは広く解釈せず、要確認か送らない」の範囲に収まるため）。
-   **transcript を読んで判定する時間は、上限の 64 MiB の transcript 1 つでも 1 秒以内とする（4.1）。** CLAUDE.md の「Performance」は、性能を相対の差ではなく実際の時間の予算で決めることを求める。状況の表は人が見て選ぶものなので、pane ごとに 1 秒を超えると人を待たせる。値は設計で測って確かめ、届かなければ読み方を変える（design_handoff.md の H-01）。ADR: なし（このタスクの中で閉じる値のため）。
-   **書きかけの行の規則（AC-21）は、本書の質問と権限の確認の判定に当てる。モデルの切り替えの記録と、人が最後に入力した行の読み取り（`internal/chief/screen_transcript.go:46`・`:170`）の規則は変えない。** それらは読み直しやリセットの条件として、1 行でも読めなければ送らない側に倒れており、この issue には変える理由がない。transcript の読み取りの規則を 1 つにそろえる案は、#905 で最後の報告を transcript で読むときに合わせて考える。ADR: なし（同上）。
-   **質問の判定のために読む transcript の量の上限は 64 MiB とし、超えたらその pane を「要確認」にして中継しない（AC-22）。** transcript は、長いセッションでは数 MB を超える。リセットの判定がすでに 64 MiB の上限で読んでいる（`internal/chief/transcript.go:30`）ので、それにそろえる。値を設計に任せる案は採らない。ADR: なし（上限の値はこのタスクの中で閉じるため）。

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   Claude Code の版が上がって画面の形が変わっても、Claude Code の pane の質問を、読み違えずに人に示せるようにする。
-   人が選んだ答えだけを、まだ答えを待っている同じ呼び出しへ中継する守りを保つ。

### 2.2. スコープ (In Scope)

-   Claude Code の pane で、答えを待っている `AskUserQuestion` の呼び出しの判定と、その問いと選択肢の示し方（F-001）
-   Claude Code の pane の権限の確認の判定と示し方（F-002）
-   答えを中継する直前の照合（F-003）
-   transcript を読めないとき、書きかけの行、読む量の上限の扱い（F-004）
-   「質問で止まっていない」ことを条件にする、ほかの判断の情報源（F-005）
-   ADR-0046、CLAUDE.md の「Declare, don't infer」の例外、chief 利用ガイドの記述の更新（F-006）

### 2.3. スコープ外 (Out of Scope)

-   Claude Code の最後の報告の読み取り（#905）。
-   入力欄に残った文字の判定。画面でしか読めないので、今のまま画面で読む。
-   OpenCode の pane の質問、コマンドの送信、モデルの切り替え（#906・#907）。
-   使わなくなった画面の読み取りの整理。消す範囲を設計で決め、このタスクで消さない部分は #908 に残す（design_handoff.md の H-07）。
-   中継する質問の種類（1 つを選ぶ問いだけ）と、送る入力の範囲（ADR-0046）。これらは変えない。
-   自由に書く答え、チャットへ移る答え、複数を選ぶ問い、複数の問いがある呼び出し、権限の確認への答えの中継。これらは今と同じく中継しない。

## 3. 機能要件 (Functional Requirements)

本章では、次の言葉を使う。

-   **呼び出し**：transcript の `assistant` の行に書かれた、`type` が `tool_use` の要素。
-   **答え**：transcript の `user` の行に書かれた、`type` が `tool_result` の要素。`tool_use_id` が呼び出しの ID と同じものを、その呼び出しの答えとする。`is_error` の値は問わない。
-   **答えを待っている呼び出し**：transcript の中に答えがない呼び出し。
-   **質問の呼び出し**：道具の名前（`name`）が `AskUserQuestion` の呼び出し。
-   **サブエージェントの呼び出し**：道具の名前が `Agent` の呼び出し。

### 3.1. 機能一覧

#### F-001: 答えを待っている質問の判定と示し方

Claude Code の pane が質問で止まっているかを、transcript の答えを待っている質問の呼び出しと Herdr の状態で判定し、その中身を示す。

**Acceptance Criteria**:
-   **AC-01**: Claude Code の pane の transcript で、答えを待っている呼び出しがちょうど 1 つで、それが質問の呼び出しであり、Herdr がエージェントを `blocked` と報告しているとき、chief はその pane を質問で止まっているものとして、状況の表と人の判断を待つものの一覧に示す。示すものは、workspace の名前、pane、問いごとの見出しと問いの文、すべての選択肢の文（`label` と `description`）である。いずれも transcript のとおりとする（制御文字は見える形に置き換える。0088 要件定義書の AC-25）。選択肢には、transcript の順に 1 から番号を付ける。自由に書く答えとチャットへ移る答えは、その pane で答えるものとして示す。
-   **AC-02**: 答えのある質問の呼び出しは、答えが人の選んだものでも、人が Esc で拒んだもの（`is_error` が `true`）でも、答えを待っているものとしない。transcript に答えを待っている質問の呼び出しがなければ、Herdr の状態にかかわらず、chief はその pane を質問で止まっているものとして示さない（`blocked` のときの扱いは AC-12）。
-   **AC-03**: 1 回の質問の呼び出しに問いが 2 つ以上あるときは、すべての問いと、その選択肢を示し、中継の選択肢は示さず、人がその pane で答えることを示す。
-   **AC-04**: 問いの `multiSelect` が `true` のときは、中身を示し、中継の選択肢は示さず、人がその pane で答えることを示す。
-   **AC-05**: 中継の選択肢を示すのは、呼び出しの問いがちょうど 1 つで、その `multiSelect` が `false` で、選択肢が 1 つ以上 9 つ以下のときだけである。選択肢が 10 以上のときは、中身を示し、中継の選択肢は示さない（選択肢の番号から決まるキー入力は 1 桁であるため。`internal/chief/paneinput/paneinput.go:447`）。
-   **AC-06**: transcript で答えを待っている質問の呼び出しがちょうど 1 つで、Herdr がエージェントを `working` と報告しているときは、AC-01 と同じ中身を質問として示し、エージェントが動いていることを添える。中継のリクエストが来ても送らず、エージェントが質問で止まっていないことを示す。
-   **AC-07**: transcript で答えを待っている質問の呼び出しがあり、Herdr がエージェントを `idle` か `done` と報告しているときは、その pane を「要確認」にし、transcript と Herdr の状態が食い違っているので pane で確かめることを示す。中継の選択肢は示さない。
-   **AC-08**: `/runpr` のマージの確認（`runpr.md` の step 4 の item 3 の問い）は、transcript の問いの文が今と同じ形（`internal/chief/screen.go:113`）であることで見分ける。見分けた結果の扱い（状況の表の「マージの確認」）は変えない。`/runpr` の送り先は今は OpenCode だが、送り先の表（`_context.md` の「Command routing」）を直せば Claude Code にもなるので、この見分けを保つ。
-   **AC-09**: 答えを待っている呼び出しが 2 つ以上あり、その中に質問の呼び出しがあるときは、その pane を「要確認」にし、中継の選択肢を示さない。

#### F-002: 権限の確認の判定と示し方

Claude Code の pane が権限の確認で止まっているかを、Herdr の状態と transcript の答えを待っている呼び出しで判定し、その中身を示す。

**Acceptance Criteria**:
-   **AC-10**: Herdr が Claude Code のエージェントを `blocked` と報告し、transcript で答えを待っている呼び出しがちょうど 1 つで、それが質問の呼び出しでもサブエージェントの呼び出しでもないとき、chief はその pane を権限の確認で止まっているものとして示す。示すものは、workspace の名前、pane、その呼び出しの道具の名前と入力であり、transcript のとおりに示す（制御文字は見える形に置き換える）。入力は、示す量に上限を設け、上限を超えた部分は示さず、切ったことを示す。中継の選択肢は示さず、人がその pane で答えることを示す。
-   **AC-11**: Herdr が Claude Code のエージェントを `blocked` と報告し、transcript で答えを待っている呼び出しがちょうど 1 つで、それがサブエージェントの呼び出しのときは、その pane を「要確認」にし、サブエージェントが質問か権限の確認で待っているかもしれないので pane で確かめることを示す。中継の選択肢は示さない。
-   **AC-12**: Herdr が Claude Code のエージェントを `blocked` と報告し、transcript に答えを待っている呼び出しがないか、質問の呼び出し以外の答えを待っている呼び出しが 2 つ以上あるときは、その pane を「要確認」にし、何を待っているか分からないことを示す。
-   **AC-13**: Herdr が Claude Code のエージェントを `blocked` と報告していないときは、質問の呼び出し以外の答えを待っている呼び出しがあっても、権限の確認として示さず、「要確認」にもしない。

#### F-003: 答えを中継する直前の照合

人が chief の選択肢で選んだ答えを、示したときと同じ、まだ答えを待っている呼び出しにだけ送る。

**Acceptance Criteria**:
-   **AC-14**: 人が中継の選択肢を選んだとき、chief はキーを送る直前に、その pane の transcript を読み直す。人に示したときと同じ ID の質問の呼び出しがまだ答えを待っていて、その問いと選択肢が示したときと同じであり、Herdr がエージェントを `blocked` と報告しているときだけ送る。そうでないとき（答えられた、別の呼び出しに変わった、エージェントが動き出した）は何も送らず、そのことを示す。
-   **AC-15**: AC-14 の条件に加えて、chief はキーを送る直前にその pane の画面を読み、transcript の問いと同じ問いの文と、同じ番号と `label` の選択肢を持つ、1 つを選ぶ問いの形が出ているときだけ送る。画面がその形に合わないとき、問いの文や選択肢が transcript と異なるとき、選択が自由に書く答えにあるか、自由に書く答えに文字が打たれているとき、画面を読めないときは、何も送らず、画面が合わなかったことを示す。その pane の状況の表の行は、このことで「要確認」にしない。
-   **AC-16**: 送る入力は、人が選んだ選択肢の番号から決まるキー入力だけである。選択肢の文を入力の文字列として送らない（0088 要件定義書の AC-29）。
-   **AC-17**: 中継のリクエストに付いた照合値が、chief がその時点の pane の質問について示す照合値と一致しないときは、何も送らず、質問が示したときと変わったことを示す。
-   **AC-18**: 中継のほかの守り（workspace の排他、止まった workspace へ送らないこと、送る前に記録を書くこと、キーを押したかもしれない失敗を送り直さないこと）は変えない（`internal/chief/relay.go:166-176`）。

#### F-004: transcript を読めないときと、書きかけの行

transcript を読めないとき、chief は推し量らずに「要確認」にし、何も中継しない。

**Acceptance Criteria**:
-   **AC-19**: Claude Code の pane の transcript の場所が決まらないとき（Herdr が `agent_session` を報告していない、作業ディレクトリに今の規則が扱わない文字がある、Claude Code の設定のディレクトリが決まらない）は、その pane を「要確認」にし、理由を示す。作業ディレクトリの文字が理由のときは、今の送信の拒否と同じく、人ができることを示す（`internal/chief/transcript.go:75-79`）。
-   **AC-20**: transcript のファイルがまだないとき（人がまだ何も入力していないセッション）は、答えを待っている呼び出しがないものとして扱う。このとき Herdr がエージェントを `blocked` と報告していれば、AC-12 のとおり「要確認」にする。
-   **AC-21**: transcript の最後の行が改行で終わっていなければ、その行は書きかけとして読まず、それより前の行で判定する。改行で終わっている行が 4.2 の受け付ける形に合わなければ、その pane を「要確認」にし、transcript を読めないことを示す。
-   **AC-22**: transcript が 64 MiB を超えるときは、その pane を「要確認」にし、読む量の上限を超えたことを示す。上限を超えた transcript の一部から判定しない。
-   **AC-23**: transcript を読めないとき（AC-19・AC-21・AC-22、ファイルを開けない、通常のファイルでない）は、その pane を「要確認」にし、その pane へ答えを中継しない。中継のリクエストが来ても送らず、transcript を読めないことを示す。

#### F-005: 「質問で止まっていない」ことを条件にする判断

chief がコマンドを送る前、自動送信の前、workspace を消す前に確かめる「エージェントが質問で止まっていない」ことにも、transcript の判定を使う。

**Acceptance Criteria**:
-   **AC-24**: chief がコマンドを送る前の確かめ（0088 要件定義書の F-006）、自動送信の前の確かめ（同 F-007）、workspace を消す前の確かめ（0092 要件定義書の F-007）では、その workspace のいずれかの Claude Code の pane が次のどれかに当たるとき、その workspace のどの pane へも送らず、自動送信せず、消さない。(a) transcript に答えを待っている質問の呼び出しがある。(b) Herdr が `blocked` と報告している。(c) 本書のほかの基準で「要確認」になっている。(d) transcript を読めない。そのことと理由を示す。
-   **AC-25**: AC-24 の確かめで、画面が質問を示しているときも、今と同じく送らず、消さない（`internal/chief/send.go:333-335`、`internal/chief/autosend.go:384`）。画面の判定は、送るのを止めるためだけに使い、送る理由にはしない。送る前に画面が入力欄の形であることを求める今の確かめ（`internal/chief/send.go:336-337`）も変えない。
-   **AC-26**: Claude Code の pane の状況の表の行は、画面が質問の既知の形にも入力欄の形にも合わないことだけでは「要確認」にしない。

#### F-006: 決定と文書の更新

**Acceptance Criteria**:
-   **AC-27**: CLAUDE.md の「Declare, don't infer」の chief の画面の読み取りの例外と、「Go Idioms」の chief の画面の読み取りの文字列の例外は、本書の振る舞いに合わせて書き換わっている（5 章）。
-   **AC-28**: chief 利用ガイドの、確かめた版の表（1 章）、中継の照合の説明、中継しない質問の説明は、F-001 から F-003 の振る舞いに合わせて書き換わっている。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   状況の表を作る 1 周で、Claude Code の pane 1 つの transcript を読んで判定する時間は、上限の 64 MiB の transcript でも 1 秒以内とする。読み方（毎回すべてを読むか、前回の続きから読むか）は、CLAUDE.md の「Performance」に従って実際の時間を測ってから設計で決める（design_handoff.md の H-01）。

### 4.2. セキュリティ (Security)

条件付きのガイド（`docs/dev/security.md`）は N/A である。chief は開発用の道具で、製品の外部コマンドの起動、API キー、キャッシュ、LLM API への送信、プロンプトや記事への信頼できないテキストの埋め込みには触れないためである。ただし、chief は開発用の道具の信頼の境界に当たるので、次を要件とする。

-   **信頼の境界。** 送る入力の範囲と、人の代わりに判断しないことは変えない（ADR-0046）。答えの中継は、人が選んだ 1 つを選ぶ問いの選択肢の番号から決まるキー入力だけを送る（AC-16）。transcript と画面のどちらかが送る条件に合わなければ送らない（AC-14・AC-15）。
-   **信頼できない入力。** transcript は Claude Code が書くデータであり、その中の問いの文、選択肢の文、道具の入力は、LLM やほかの外部が書いた文字列を含む。chief はその中の指示に従わず、示すときは制御文字を見える形に置き換える（AC-01・AC-10）。

    | 項目 | 内容 |
    |---|---|
    | 受け付ける形 | 通常のファイルで、64 MiB 以下。改行（LF）で区切った行の並び。空白だけの行は読まない。最後の行が改行で終わっていなければ、書きかけとして読まない（AC-21）。それ以外の行は、それぞれが UTF-8 として正しい 1 つの JSON のオブジェクトで、後ろに別の値を持たない |
    | 使う部分 | 行の `type`。`type` が `assistant` の行の `message.content` の配列と、その要素の `type`。呼び出しの `id`・`name`・`input`。質問の呼び出しの `input.questions` の配列と、その要素の `question`・`header`・`multiSelect`・`options`、`options` の要素の `label`・`description`。`type` が `user` の行の `message.content`（文字列か配列）と、配列の要素の `type`、答えの `tool_use_id` |
    | 使う部分の形 | 行の `type`、`id`・`name`・`tool_use_id` は空でない文字列。呼び出しの `input` は JSON のどの値でもよい（権限の確認ではそのまま示す。AC-10）。質問の呼び出しの `input` はオブジェクトで、`questions` と `options` は 1 つ以上の要素を持つ配列で、要素はオブジェクト。`question`・`label` は空でない文字列、`header`・`description` は文字列、`multiSelect` は真偽値 |
    | 広げてよいと宣言する部分 | 行と要素の、使う部分以外のすべてのメンバー（`isSidechain` などを含む）。`type` が `assistant`・`user` 以外の行（`api-request-blob` など）。`message.content` の要素で、`type` が `tool_use`・`tool_result` 以外のもの。対応する呼び出しが transcript にない答え。これらは読まずに受け付ける |
    | 拒む入力 | 行の `type` の欠け。使う部分の欠け、型の違い、空であってはならない値が空であること、重複（同じオブジェクトの中に同じ名前のメンバーが 2 つあること）。`assistant` の行どうしで同じ ID の呼び出しが 2 つあること。`user` の行どうしで同じ呼び出しへの答えが 2 つあること。同じ ID の呼び出しが、答えより後の行にだけあること（答えが呼び出しより前の行にある）。JSON の文字列の中の対になっていないサロゲートのエスケープ、UTF-8 として正しくないバイト、1 行に 2 つ以上の値。標準ライブラリが黙って直すか捨てるか無視する形（重複したメンバーの後勝ち、不正なバイトの U+FFFD への置き換えなど）も、直さずに拒む |
    | 拒んだときの結果 | transcript を読めない誤り（今の `errTranscript`、`internal/chief/transcript.go:17`）として扱い、その pane を「要確認」にし、何も中継しない（AC-21・AC-23）。一部だけを読んだ結果は使わない |

-   **残る危険。** 質問の呼び出しの `input` の中の、使う部分以外のメンバーも、広げてよいと宣言した部分に含まれ、chief は読まない。そのため、Claude Code が問いの意味を変えるメンバー（`multiSelect` に代わるものなど）を足すと、chief はそれを読まずに 1 つを選ぶ問いとして示しうる。その場合も、中継の直前の画面の確かめ（AC-15）が、1 つを選ぶ問いの形でない画面への送信を止める。
-   **画面。** 質問と権限の確認の判定では、画面は送るのを止めるための確かめにだけ使う（AC-15・AC-25）。画面から読んだ問いや選択肢を、人に示す中身や送る理由にはしない。残る画面の読み取り（入力欄、中継の直前の確かめ、報告）は、今と同じく実画面のサンプルで確かめた形だけを受け付ける。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   transcript と画面と Herdr の状態のどれかが食い違うときは、推し量らずに、送らないか「要確認」にする（AC-06・AC-07・AC-09・AC-12・AC-15）。
-   送れたかが分からない送信を送り直さないこと、送った結果の示し方（キーが押され、エージェントが質問から離れたこと）は変えない（0088 要件定義書の AC-37、`internal/chief/relay.go:174-176`）。

### 4.4. 互換性 (Compatibility)

-   対象は Claude Code の pane である。受け付ける transcript の形は、手元の Claude Code の版で確かめたもの（1 章の背景）に限る。形が変わって受け付けられないときは、AC-21 のとおり「要確認」になり、何も中継しない。
-   OpenCode の pane の判定は変えない。

### 4.5. 保守性 (Maintainability)

-   transcript の場所の決め方とファイルの開き方は、chief がすでに持つもの（`internal/chief/transcript.go`）を使い、二重に持たない。行の読み方では、書きかけの行の規則（AC-21）と 4.2 の拒む入力が、今の読み取りと異なる。その理由と範囲は「要件定義の際に決めたこと」にある。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   **CLAUDE.md の「Declare, don't infer」の例外の変更。** 方針（[CLAUDE.md](../../../CLAUDE.md)「Key Design Patterns」の「Declare, don't infer」）は、呼び出し側が渡した文字列の中身を調べて振る舞いを選ばず、型で宣言することを求める。今の例外（chief の画面の読み取り）は、pane の画面と transcript の中身を調べることを認め、その範囲に「エージェントが質問を待っているかと問いの形」を画面から読むことを含む。本書の変更の後は、Claude Code の pane について、質問を待っているか、問いの形と文と選択肢、権限の確認、サブエージェントが待っていることを、transcript の答えを待っている呼び出しから読む。`/runpr` のマージの確認は、transcript の問いの文で見分ける（AC-08）。理由は今の例外と同じで、transcript は Claude Code が書く外部の値であり、chief が型で表すことはできないためである。境界も今と同じで、受け付ける形に合わない transcript は広く解釈せず「要確認」か「送らない」にする（AC-21・AC-23）。画面からの判断は、送るのを止めるためだけに使う（AC-25）。CLAUDE.md の例外の文をこれに合わせる（AC-27）。
-   **CLAUDE.md の「Go Idioms」の文字列の例外。** 今の例外は、`internal/chief` の `screen` で始まる名前のファイルに、画面の決まった文字と同じでなければならない日本語の文字列を置くことを認める。`/runpr` のマージの確認の問いの文（AC-08）を transcript の読み取りで使うとき、その文字列を置くファイルがこの範囲の外になるなら、例外の範囲を合わせて書き換える（AC-27）。どのファイルに置くかは設計で決める。
-   **ADR-0046 の更新。** 本書は、ADR-0046 の「質問と選択肢は画面のとおりに示す」「画面は、実画面のサンプルで確かめた形だけを受け付ける。答えを中継するときは、人に示した質問と選択肢から作った照合値を、送る直前に読み直した画面から作った照合値と比べる」という決定を、Claude Code の pane について変える。本書の PR で ADR-0046 の決定と経緯を更新する。
-   **0088 要件定義書の AC-25 の置き換え。** 0088 の AC-25（質問と選択肢を画面のとおりに示し、タブは画面に出ている問いを示す）は、Claude Code の pane について、本書の AC-01・AC-03 に置き換わる。理由は「要件定義の際に決めたこと」にある。
-   中継する質問の種類と、送る入力の範囲（0088 要件定義書の F-005・F-006、ADR-0046）は変えない。

## 6. 用語集 (Glossary)

-   用語は `docs/translation_glossary.md` と統一する。
-   **transcript**：Claude Code がセッションごとに書く記録のファイル（`<config>/projects/<dir>/<session>.jsonl`）。用語集の「文字起こし」（transcript）とは別のものである。
-   **呼び出し・答え・答えを待っている呼び出し・質問の呼び出し・サブエージェントの呼び出し**：3 章の冒頭の定義のとおり。
-   **権限の確認**：Claude Code が道具を使う前に、人に許可を求める確認。
-   **中継**：人が chief の選択肢で選んだ答えを、質問で止まっているエージェントの pane へキー入力で送ること（0088 要件定義書の F-005）。
-   **照合値**：中継の直前に、人に示したときと同じ問いであることを確かめるために chief が作る値（ADR-0046）。
