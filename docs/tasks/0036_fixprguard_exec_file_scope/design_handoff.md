# 設計への申し送り：fixprguard の範囲の規則で、下の階層の指示ファイルと Go のビルドの入力を範囲外にする

要件定義の際に挙がった設計の事項である。`02_architecture.md` は、各項目にどう対応したか、または対応しない理由を記録する。

-   **H-01: `protocol` の番号を上げる手順.** 要件は番号を上げると決めた（AC-16）。上げる対象を決める。`internal/fixprguard` の `Protocol`、`fixpr.md`・`runpr.md` の `--protocol`、ガイドの例とその文書のガードである。今の `--protocol` の番号を文書から読んで確かめる既存の検査も、漏れなく対象に入れる。たとえば `docs/tasks/0032_japanese_pr_title/check_rules.sh:524` は、`fixpr.md` に `--protocol 2` があることを求める。更新から漏れると、番号を上げた時点でその検査が失敗する。タスク 0035 でも、番号を上げたときにこの検査を合わせて直した。番号を固定している箇所をリポジトリ全体から探す手段も決める（AC-16）。ガイド 3 章の手順（`docs/dev/guides/fixprguard_guide.md:52`）に合わせて、マージと入れ直しの順序も決める。範囲の規則だけが変わる変更なので、ガイド 9 章の「番号を変えなくてよい 3 つの条件」（`docs/dev/guides/fixprguard_guide.md:287-292`）との関係も書く。
-   **H-02: 判定の順序.** 今の順序は、実行関連ファイル、`path` との一致、ASCII でない文字、`.go`、同じディレクトリ・タスクのディレクトリである（`internal/fixprguard/scope.go:169-190`）。許可リストをどこに入れるかを決める。`.go` のファイルには許可リストの (b)（`testdata`）を適用しない（AC-06）。
-   **H-03: 定義を持つデータの形と、ガイドへの載せ方.**
    -   `ExecutionFilePatterns` が出力する形（`internal/fixprguard/scope.go:56-75`）では、`.claude/` は最上位のディレクトリを表す。どの階層でも当たる `.` で始まる要素、指示ファイルの名前、拡張子を、ガイドの表にどう表すかを決める。
    -   最上位だけの規則（`/.*`・`/claude.md`・`/agents.md`）と、`.claude/`・`.github/` のディレクトリの規則は、新しい規則に含まれる。これらを表に残すか、まとめるかも決める。
    -   許可リストの項目を一覧に出す関数と、文書のガード（`cmd/fixprguard/docs_test.go:45-62`）がそれを確かめる手段を決める（AC-19）。
-   **H-04: タスク 0034 との実装の順序.** 0034 の要件定義書（PR #429）は、実行関連ファイルの定義を、無視されるファイルの基準値の対象を決めるのに使う。0034 の対象をどうするかは 0034 で決める（本書 1 章）。ただし、0034 の実装が先に入って定義をそのまま使っている場合、本タスクの実装は 0034 の対象も変える。AC-02 の規則では、無視される `extension/node_modules/` の下の `.bin/`・`.package-lock.json` なども対象になる。設計の時点で 0034 の状態を確かめ、本タスクの変更が 0034 の対象に及ぶかと、及ぶならその扱いを記録する。
-   **H-05: テストの作り方.**
    -   AC-12 の各行と、AC-01〜AC-10 の例を、`inScope` の表のテストに入れる。各行について、対応する規則を外すと失敗することを確かめる（`CLAUDE.md`「Testing Strategy」）。
    -   拒否リストと許可リストのどちらでも範囲外になる入力では、どちらの規則を確かめているかが分からない。たとえば `internal/writer/foo.syso`（スレッドの `path` は `writer.go`）は、拒否リストを外しても、許可リストに当たらないので範囲外のままである。
    -   拒否リストを確かめるには、許可リストだけなら範囲に入る入力（`internal/writer/CLAUDE.md` は `.md`）か、規則 1 の入力（AC-13）を使う。片方の規則だけが働く入力を選ぶ（`CLAUDE.md`「A layered path needs inputs only one layer can handle」）。
-   **H-06: 大文字と小文字の扱いの組み合わせ.** 拒否リストは ASCII の大文字小文字を同一視し、許可リストは区別する（AC-09）。たとえば `internal/x/Claude.MD` は拒否リストに当たり、許可リストには当たらない。この組み合わせで、範囲に入るファイルが広がらないことを確かめる。
