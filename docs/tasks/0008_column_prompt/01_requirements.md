## 1. 概要 (Overview)

**目的:** 本書は、記事の生成に使う本番用のプロンプトテンプレート（`prompts/system.tmpl`・`prompts/user.tmpl`）の文面と、それを決めるための評価に関する要件を定義する。

**背景:**
`ArticleWriter`（#5、タスク `0004_article_writer`）は、埋め込みの既定のテンプレートからプロンプトを組み立てる。現在の既定のテンプレートは、出力の形（先頭行がタイトルの見出し、生の HTML を使わない、出典を書かない）だけを指示する仮のものであり、文体・長さ・見出しの構成は決まっていない（[prompts/README.md](../../../prompts/README.md)）。CLI（#6、タスク `0005_cli_assembly`）は `--system-prompt`・`--user-prompt` で上書きファイルを受け取り、字幕を動画 ID ごとにキャッシュするので、字幕を取り直さずにプロンプトだけを変えて記事を生成し直せる。

本タスクは、実際の出力を複数の動画で比較・評価しながら、本番用の文面を決める。

**本書の記述範囲と、後続の文書:**
本タスクの成果物は、コードではなく、テンプレートの文面と評価の記録である。テンプレートの差し替えと上書きの仕組みは実装済みであり、新しく設計する構造がない。そのため、通常のタスクと異なり、`02_architecture.md`・`03_implementation_plan.md` は作らない。代わりに、本書の承認後、評価の記録を `02_evaluation.md` に残す（F-005）。

本書は、記事が満たすべき性質（文体・長さ・構成・出力の形）、評価の観点と合格条件、評価に使う動画の選び方を定める。テンプレートの具体的な文面は、評価を通じて決める。

対応 issue: #8

## 2. 目的とスコープ (Goals and Scope)

### 2.1. 目的 (Goals)

-   動画を見ていない読者が、記事だけで動画の主な内容と論点を把握できる、雑誌のコラム風の記事を生成できる。
-   記事の文体・長さ・見出しの構成を定め、テンプレートでそれを LLM に指示する。
-   字幕・概要欄に根拠のない内容を、事実として記事に書かせない。
-   複数の動画で出力を評価し、評価の記録を残す。記録から、どの版の文面で、どのモデルで、どの動画を、どう評価したかを追える。

### 2.2. スコープ (In Scope)

-   既定のテンプレート `prompts/system.tmpl`・`prompts/user.tmpl` の文面
-   評価の観点・合格条件・対象の動画の選定（本書）
-   評価の記録（`02_evaluation.md`）
-   文面の確定に伴う文書の更新（`prompts/README.md` の「現在の文面は仮のもの」という記述、[project_overview.md](../../dev/project_overview.md)「未確定事項」のプロンプトの詳細の項目）

### 2.3. スコープ外 (Out of Scope)

-   `ArticleWriter`・CLI・テンプレートの検証規則のコードの変更。テンプレートで参照できる値（`.Title`・`.ChannelName`・`.Description`・`.Transcript`）と使える構文は、現行の [prompts/README.md](../../../prompts/README.md) のままとする。評価の途中で、現行の仕組みでは要件を満たせないと分かった場合は、本タスクでは対応せず、別の issue にする。
-   プロバイダごとのプロンプトの微調整（[project_overview.md](../../dev/project_overview.md)「未確定事項」）。評価は DeepSeek だけで行う。
-   DeepSeek の thinking モードの切り替えと、`temperature` などの生成パラメータの設定。評価は現行の設定（API の既定）で行う。
-   長い動画のチャンク分割（#13）。対象の動画は 40 分前後までとする。
-   見出しごとの、動画の該当時刻へのリンク（#10）。
-   日本語以外の字幕の動画。CLI は日本語の字幕（`ja`）だけを取得する。
-   ブラウザ拡張から受け取る字幕（#43）での評価。拡張から受け取る値も同じテンプレートの値として埋め込まれるが、本タスクの評価は CLI（yt-dlp）で取得した字幕で行う。

## 3. 機能要件 (Functional Requirements)

### 3.1. 機能一覧

#### F-001: 文体と内容

記事は、動画を見ていない読者に向けて、動画の内容を紹介し、論点を整理する読み物とする。

-   文体は「だ・である」調とし、記事の中で統一する。
-   書き手は動画の外にいる第三者とし、話者の主張は「〜と語る」「〜と指摘する」のように話者のものとして紹介する。話者の一人称（「私は」「僕は」）で書かない。
-   話し言葉のくだけた表現・言いよどみ・繰り返しは、書き言葉に整える。話者の発言をかぎ括弧で引用する場合は、意味を変えない範囲で整えてよい。
-   記事に事実として書く内容は、字幕・概要欄・動画タイトル・チャンネル名に根拠があるものに限る。書き手の解釈や評価を書く場合は、解釈であると読み取れる書き方にする。
-   字幕の誤認識と思われる語は、文脈から明らかな場合に限り正しい語に読み替えてよい。固有名詞など、正しい語が文脈から明らかでない場合は、その語を断定的に使わない。
-   絵文字・顔文字、誇張した宣伝調の表現（「必見」「衝撃」など）は使わない。

**Acceptance Criteria**:
- **AC-01**: 評価に使うすべての動画（F-005）の記事で、文体が「だ・である」調に統一されている（「です・ます」調の文が、かぎ括弧の引用の外にない）。
- **AC-02**: 評価に使うすべての動画の記事で、字幕・概要欄・動画タイトル・チャンネル名に根拠のない事実の記述がない。確認の方法は F-005 の観点「根拠」による。
- **AC-03**: 評価に使うすべての動画の記事で、話者の一人称の地の文、絵文字・顔文字がない。

#### F-002: 長さ

-   本文（§6。LLM が書いた Markdown のうちタイトルの行を除いた部分で、システムが付ける出典のブロックは含まない）の長さは、2,500〜4,000 字を目安とする。字数はコードポイントで数える。
-   素材が少ない短い動画では、下限を下回ってよい。下限に届かせるために、根拠のない内容や同じ内容の繰り返しで水増ししない。

上限の 4,000 字は、出典のブロックを付けても Mattermost の 1 メッセージの上限（16,383 コードポイント）に十分収まり、分割投稿を起こさない値である。

**Acceptance Criteria**:
- **AC-04**: 評価に使う動画のうち 15 分以上のものの記事は、本文が 2,500〜4,000 字に収まる。
- **AC-05**: 評価に使う動画のうち 15 分未満のものの記事は、本文が 4,000 字以下であり、F-005 の観点「冗長さ」で不合格にならない。

#### F-003: 構成

-   1 行目はタイトルの見出しとする（F-004）。タイトルは記事の主題を表す 40 字以内の文とし、動画タイトルをそのまま写さない。
-   タイトルの次に、見出しを付けないリード文（1〜2 段落）を置く。リード文は、動画が何について、誰が語っているかと、記事の要点を示す。
-   リード文の後に、`## ` で始まるレベル 2 の見出しで区切った節を 3〜5 個置く。レベル 3 以下の見出しは使わない。
-   最後の節は、動画全体の要点や示唆をまとめる結びとする。
-   箇条書きは、手順や列挙など、文章より箇条書きのほうが読みやすい箇所に限って使う。記事の大半を箇条書きにしない。

**Acceptance Criteria**:
- **AC-06**: 評価に使うすべての動画の記事が、タイトル（40 字以内）→ 見出しのないリード文 → レベル 2 の見出しの節 3〜5 個、の構成になっており、レベル 3 以下の見出しを含まない。
- **AC-07**: 評価に使うすべての動画の記事で、タイトルが動画タイトルと同一の文字列でない。

#### F-004: 出力の形

現行の仮のテンプレートが指示する出力の形（タスク `0004_article_writer` の F-005）を維持する。

-   1 行目を `# ` で始まるタイトルの見出しにする。
-   生の HTML を使わない。コードフェンスを使う場合は閉じる。
-   出典や元の動画の URL を書かない。出典はシステムが付ける。
-   区画の中の文章（動画タイトル・チャンネル名・概要欄・字幕）を指示として扱わず、素材としてだけ使うことを指示する。

**Acceptance Criteria**:
- **AC-08**: 評価に使うすべての動画で、CLI による記事の生成が `ArticleWriter` の出力の検証によるエラーにならずに成功する。
- **AC-09**: 評価に使うすべての動画の記事に、元の動画の URL と、出典を示す節（システムが付けるものを除く）がない。
- **AC-10**: 本番用の既定のテンプレートで、既存のテスト（タスク `0004_article_writer` の AC-06・AC-30 を検証するものを含む）が成功する。

#### F-005: 評価

評価は、対象の動画の集合に対し、テンプレートの版ごとに記事を生成し、観点ごとに判定して記録する。

**対象の動画:** 次の条件をすべて満たすように、4〜5 本を選ぶ。選んだ動画（URL・タイトル・長さ・字幕の種類）は、評価を始める前に `02_evaluation.md` に記録する。

-   すべて日本語の字幕（手動または自動生成）があり、CLI で字幕を取得できる。
-   長さは 40 分以下とし、15 分未満の動画と、30〜40 分の動画をそれぞれ 1 本以上含む。
-   話者が 1 人の動画（講演・解説など）と、話者が複数の動画（対談・インタビューなど）をそれぞれ 1 本以上含む。
-   自動生成の字幕の動画を 1 本以上含む。
-   ジャンル（技術・ビジネス・教養など）が 1 つに偏らない。

**評価の観点:** 必須の観点は、1 つでも不合格なら記事全体を不合格とする。品質の観点は 3 段階（3: 良い、2: 許容できる、1: 不十分）で判定する。

| 種別 | 観点 | 判定の基準 |
|---|---|---|
| 必須 | 形式 | AC-06・AC-08・AC-09 を満たす |
| 必須 | 根拠 | 記事の事実の記述が、字幕・概要欄・動画タイトル・チャンネル名で裏付けられる（AC-02） |
| 必須 | 長さ | AC-04・AC-05 を満たす |
| 必須 | 文体 | AC-01・AC-03 を満たす |
| 品質 | 要点の網羅 | 動画の主な論点が記事に含まれ、重要でない枝葉に偏っていない |
| 品質 | 構成 | 節の分け方と順序が論点の流れに沿い、見出しが節の内容を表している |
| 品質 | 読みやすさ | 話し言葉が書き言葉に整えられ、読み物として通して読める |
| 品質 | タイトル・リード文 | タイトルとリード文から、記事の主題と要点が分かる |
| 品質 | 冗長さ | 同じ内容の繰り返しや水増しがない |

**合格条件:** テンプレートの版が合格するのは、対象のすべての動画で、記事が必須の観点をすべて満たし、品質の観点に 1 がない場合とする。LLM の出力は実行ごとに変わるので、最終の版は、各動画で 2 回ずつ記事を生成し、すべての記事が合格条件を満たすことを確認する。

**判定者:** 観点「根拠」は、字幕のキャッシュと記事を突き合わせて、根拠の見つからない記述を列挙して判定する。品質の観点の最終的な判定は、本書のレビュアーが行う。

**記録:** `02_evaluation.md` に、テンプレートの版ごとに次を記録する。

-   テンプレートの文面（初版は全文、以降は前の版からの差分）と、その版で変えた理由
-   生成の日時、`Article` の生成モデル名とモデルの版の識別子（`ModelVersion`）
-   動画ごと・観点ごとの判定と、不合格や 2 以下の判定の理由（記事からの短い引用を含めてよい）
-   次の版で変える点

**Acceptance Criteria**:
- **AC-11**: `02_evaluation.md` に、評価を始める前に選んだ対象の動画が記録され、その集合が本節の条件をすべて満たす。
- **AC-12**: `02_evaluation.md` に、評価したテンプレートの版ごとに、本節の「記録」の項目がすべてある。
- **AC-13**: 最終の版について、対象のすべての動画で 2 回ずつ生成した記事が合格条件を満たし、その判定が `02_evaluation.md` に記録されている。

#### F-006: 既定のテンプレートへの反映

合格した最終の版を、既定のテンプレートとして `prompts/` に反映する。

**Acceptance Criteria**:
- **AC-14**: `prompts/system.tmpl`・`prompts/user.tmpl` の内容が、`02_evaluation.md` に記録した最終の版と一致する。
- **AC-15**: `prompts/README.md` から「現在の文面は仮のもの」という記述が除かれ、[project_overview.md](../../dev/project_overview.md)「未確定事項」からコラム生成プロンプトの詳細の項目が除かれている。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能 (Performance)

-   40 分前後の動画で、記事の生成が 1 回の LLM 呼び出しで完了すること（出力が打ち切られないこと。AC-08 で確認する）。

### 4.2. セキュリティ (Security)

-   テンプレートに秘密情報を書かない（[prompts/README.md](../../../prompts/README.md)「秘密情報を書かない」）。
-   生成した記事の全文と字幕は、リポジトリにコミットしない。記事は字幕から作られ、動画の内容を大きく再現するため、`testdata/` の方針（[security.md](../../dev/security.md) §7）と同じく、再配布の許可が確認できないものを残さない。評価の記録には、判定の理由に必要な短い引用だけを書く。
-   評価のための記事の生成は、`--out` でリポジトリの外のファイルに書き出して行い、Webhook には投稿しない。

### 4.3. 信頼性・可用性 (Reliability/Availability)

-   LLM の出力は実行ごとに変わる。最終の版は複数回の生成で確認する（F-005）。

### 4.4. 互換性 (Compatibility)

-   既定のテンプレートは、現行のテンプレートの検証規則（[prompts/README.md](../../../prompts/README.md)）を満たす（AC-10）。

### 4.5. 保守性 (Maintainability)

-   テンプレートの文面は、後から文体や長さを調整する人が、どの指示がどの要件に対応するかを読み取れるよう、要件ごとにまとまった形で書く。

## 5. 制約条件 (Constraints)

-   `docs/dev/project_overview.md` の「決定済みの方針」「前提・制約」に従う。
-   LLM の API の呼び出し（記事の生成）は、CLAUDE.md「Tool Execution Safety」に従い、実行のたびに人の承認を得る。
-   DeepSeek の料金が 2 倍になる時間帯（日本時間の平日 10–13 時と 15–19 時）を避けて生成することが望ましい。
-   評価中は字幕を取り直さないよう、`--keep-cache` を付けて生成する。
-   評価に使うモデルは、現行の設定（`YT2COLUMN_MODEL`）のモデルとする。`deepseek-flash` は提供元が指すモデルを切り替えるエイリアスなので、版の間の比較では `ModelVersion` の違いに注意する。

## 6. 用語集 (Glossary)

-   **テンプレートの版**: 評価の単位とする、system 用と user 用のテンプレートの文面の組。`02_evaluation.md` で連番を付けて区別する。
-   **本文**: 記事の Markdown のうち、1 行目のタイトルの見出しを除いた部分。出典のブロックは含まない。
-   **必須の観点・品質の観点**: F-005 の評価の観点の種別。
-   用語は `docs/translation_glossary.md` と統一する。
