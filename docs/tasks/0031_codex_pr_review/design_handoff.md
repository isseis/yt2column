# 設計への申し送り（0031 codex_pr_review）

要件の起草とレビューで挙がった、設計（`02_architecture.md`）で決める事項。`02_architecture.md` は、各項目をどう扱ったか（または扱わない理由）を記録する。

## H-01: Codex のレビュー済みを判定する手段

AC-09〜AC-12。候補は、`chatgpt-codex-connector[bot]` の PR レビューの `commit_id` と、依頼したコミットの一致（issue #403）。指摘が 0 件のときの完了の印は、F-001 の観測（AC-01 の 1）で決める。PR レビューのオブジェクトが投稿されない場合（リアクションだけなど）は、依頼のコメントと完了の印をどう対応づけるかを決める。依頼したコミットを、依頼のコメントからどう求めるか（AC-10・AC-15）も含める。

## H-02: 比較の期間かどうかを、コマンドがどこから知るか

F-004・F-005（AC-18）。`_context.md` の値（待つ PR レビュアーと、比較の相手の Bot）にするか、別の値にするかを決める。比較の期間を終える変更（AC-22）が、その値と `.coderabbit.yaml` の変更、それに比較のための手順の削除で済む形にする。

## H-03: REST の名前の作り方

AC-25。#395 の設計（H-02）には、GraphQL の `login` に `[bot]` を付けて REST の名前を作る規則がある。この規則が Codex でも成り立つかを、F-001 の観測（AC-03）で確かめる。成り立たなければ、#405 の設計と合わせて決める。

## H-04: 外部の人が Codex を動かせるかの確かめ方

AC-01 の 8。公式文書、Codex の設定の画面、書き込み権限のない別のアカウントでの試行のうち、どれで確かめるかを決める。別のアカウントで試すなら、そのアカウントの用意と、試行の後の片付け（投稿の削除）を含める。

## H-05: Codex のステータスコンテキスト・チェックラン

AC-01 の 4 の観測の結果に応じて、次のことを決める。レビュー済みの判定に使うか。`gh pr checks --watch` の待ちに影響するか。branch protection の設定を変える必要があるか。

## H-06: 観測と比較の記録の文書

F-001・F-004・F-005。文書の名前と形式（表の列）を決める。観測の記録（設計の入力）と比較の記録（継続の判断の入力）を、同じ文書にするか分けるかも決める。

## H-07: CodeRabbit の重大度と Codex の P0・P1 の対応

AC-20。CodeRabbit のどの重大度（またはどのラベル）を P0・P1 に当たるものとして数えるかを、両者の公式文書の定義をもとに決める。

## H-08: Codex のレビューを待つ時間の上限

AC-13。AC-01 の 7 で観測した所要時間をもとに決める。今の CodeRabbit の約 15 分（`runpr.md:192-196`）をそのまま使うかどうかも含める。

## H-09: 返信の文面から `@codex` のメンションを除く手段

AC-29。`/fixpr` の返信の文面と、ほかのコマンドが投稿する文面に `@codex` が含まれないようにする手段（投稿の前の確認、メンションの無効化など）を決める。#395（タスク 0030）の返信の扱いとの関係も含める。
