## I-01: エラーからステータスコードを取り出す手段

-   **懸念:** 要件 AC-11 は、`200` 以外の応答に対するエラーからステータスコードを取り出す手段として `errors.AsType` を名指ししていた。要件は「エラーからステータスコードを取り出せ、その値が応答のステータスコードと一致する」という観測できる振る舞いだけを定めるようにし、取得手段の名指しは削った。
-   **なぜ重要か:** `errors.AsType` は Go 1.26 で追加された API であり、`go.mod` のバージョンに依存する。また、番兵 `ErrHTTPStatus` がステータスコードをどのような型で運び、それをどう取り出すかは、エラー型の設計（`02_architecture.md`）とその実装（`03_implementation_plan.md`）で決める事項である。要件が 1 つの API を必須にすると、`errors.As`・型アサーション・専用メソッドなどの選択肢と、それを前提にしたテストの書き方が不要に縛られる。
-   **候補:** エラー型（例: `HTTPStatusError`）がステータスコードを保持し、`errors.AsType[*HTTPStatusError]` または `errors.As`（ポインタを対象にする）で取り出せるようにする。carrier 型の名前・公開するフィールド・`Unwrap` する番兵は設計で決め、テストで使う取得 API は実装計画で決める。いずれの手段でも AC-11 を満たす。
-   **関連:** F-003、AC-11。`02_architecture.md` のエラー型の設計、`03_implementation_plan.md` の AC-11 のテスト。

## I-02: 通信の失敗のテストの送信先の作り方

-   **懸念:** 要件 AC-20 は、テストの送信先の作り方（閉じた `httptest` サーバーのアドレス、`Content-Length` ヘッダーで示した長さより前で本文を切る送信先）を名指ししていた。要件は「接続できない送信先」「本文の途中で接続を閉じる送信先」という観測できる条件だけを定めるようにし、作り方は本書へ移した。
-   **候補:** 接続できない送信先は、起動してすぐ閉じた `httptest.Server` のアドレスを使う。本文の途中で閉じる送信先は、`Content-Length` に有効な応答の全長を示し、その一部だけを書いてから接続を乗っ取って（`http.Hijacker`）閉じる。DeepSeek アダプタの AC-19 のテストで使った手段を再利用できるかを最初に確認する。
-   **関連:** F-004、AC-20。

## I-03: 統合テストの分離と Make ターゲットのフラグ

-   **懸念:** 要件 F-007・AC-29 は、ビルドタグ（`//go:build integration`）、`go test` のフラグ（`-count=1`・`-timeout`・`-v`）、スキップの手段（`t.Skip`）を名指ししていた。要件は「既定のテストから分離する」「テスト結果のキャッシュを使わず、実行時間に上限を設ける」「スキップする」という振る舞いだけを定めるようにし、手段は本書へ移した。
-   **候補:** DeepSeek アダプタの統合テストと同じく、`//go:build integration` で分離し、`make test-integration-claude` は `go test -tags integration -count=1 -timeout <値> -v` で実行する。API キーの変数が未設定・空の場合は `t.Skip` する。モデル名と effort の変数が欠けている場合は `t.Fatal` で失敗する（要件書 F-007）。`-timeout` の値は、[design_handoff.md](design_handoff.md) H-04 で測った所要時間から決める。
-   **関連:** F-007、AC-28・AC-29。[design_handoff.md](design_handoff.md) H-04・H-07。

## I-04: 拡張可能なメンバーのテストの入力

-   **懸念:** 要件 AC-38 は、テストの入力を「`02_architecture.md` の作成時に記録した実 API の応答の形を元にした `testdata/` のサンプル」と名指ししていた。要件は「実 API が実際に返す形の応答でも受理される」という振る舞いだけを定めるようにし、入力の作り方は本書へ移した。
-   **候補:** 事前調査（[design_handoff.md](design_handoff.md) H-11）で保存した実応答を `testdata/` に置き、そのままと、テスト用の未知のメンバーを加えたものの両方を入力にする。
-   **関連:** 3.2、AC-38。
