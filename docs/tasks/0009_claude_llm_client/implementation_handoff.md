## I-01: エラーからステータスコードを取り出す手段

-   **懸念:** 要件 AC-11 は、`200` 以外の応答に対するエラーからステータスコードを取り出す手段として `errors.AsType` を名指ししていた。要件は「エラーからステータスコードを取り出せ、その値が応答のステータスコードと一致する」という観測できる振る舞いだけを定めるようにし、取得手段の名指しは削った。
-   **なぜ重要か:** `errors.AsType` は Go 1.26 で追加された API であり、`go.mod` のバージョンに依存する。また、番兵 `ErrHTTPStatus` がステータスコードをどのような型で運び、それをどう取り出すかは、エラー型の設計（`02_architecture.md`）とその実装（`03_implementation_plan.md`）で決める事項である。要件が 1 つの API を必須にすると、`errors.As`・型アサーション・専用メソッドなどの選択肢と、それを前提にしたテストの書き方が不要に縛られる。
-   **候補:** エラー型（例: `HTTPStatusError`）がステータスコードを保持し、`errors.AsType[*HTTPStatusError]` または `errors.As`（ポインタを対象にする）で取り出せるようにする。carrier 型の名前・公開するフィールド・`Unwrap` する番兵は設計で決め、テストで使う取得 API は実装計画で決める。いずれの手段でも AC-11 を満たす。
-   **関連:** F-003、AC-11。`02_architecture.md` のエラー型の設計、`03_implementation_plan.md` の AC-11 のテスト。
